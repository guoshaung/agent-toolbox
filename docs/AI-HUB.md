# 额度中枢

入口：更多工具 → 其他 → 额度中枢。版本：0.46.26。

## 跨设备配置

在额度中枢点「跨设备配置」，选择「提供服务」「使用服务」或「两者都做」。提供服务沿用本页的通道与本地网关，可指定本机端口并复制地址、密钥；使用服务填写对方 Chat Completions Base URL 和网关密钥，工具箱依次检测端口、验证 `GET /v1/models`、保存加密密钥、发送短文本测试，并可接入本机 DSH。选择「两者都做」时，两侧配置互相独立；若 18878 已用于隧道，向导会从 18880 起寻找空闲端口。

向导**检测已有 SSH 隧道，不建立或维护隧道**。使用端密钥保存在本机系统安全存储加密文件中；接入 DSH 时另写入 DSH 自己的当前用户凭据文件，并备份现有 profile。原有通道、密钥、默认模型和页面布局不被替换。DSH 会增加「Toolbox 额度中枢（单轮文本）→ Auto」模型：只转发当前用户纯文本，不转发工具、图片、文件或历史上下文；Windows 网关的 `auto` 仍按通道优先级与指定错误状态切换。此地址只支持 OpenAI Chat Completions，不能直接作为 Responses API 的 Base URL。

这是本机的 OpenAI Chat Completions 兼容网关和额度面板。支持 WorkBuddy 国内版浏览器授权、TRAE 国际版 IDE 本机账号，以及已配置的兼容 HTTP API。豆包工作、千问工作国内版的账号适配尚未完成。

## WorkBuddy 国内版

在服务卡片点击「浏览器登录国内版」，在独立的腾讯云 CodeBuddy 官方页面完成登录授权。工具箱自动保存加密令牌，读取模型列表和个人 credits，随后打开通道编辑框；确认模型并启用后即可通过统一接口调用。无需复制桌面客户端的登录文件或令牌。

支持令牌到期刷新、积分包分页和上游 SSE 到普通 JSON 的转换（含工具调用片段）；不执行签到、积分任务或身份切换。取消或关闭授权窗口会终止本次登录。服务拒绝或流中断时如实失败。

授权窗口使用独立会话直连，避免本机已停止的系统代理导致 `ERR_PROXY_CONNECTION_FAILED`；不修改系统代理、原浏览器会话或工具箱偏好。API 调用使用与工具箱原功能一致的 Node fetch。

2026-10-24 已在本机完成真实账号授权、模型列表及 credits 查询，并通过网关完成一次简短模型调用。此验证只覆盖 WorkBuddy 国内版；不代表其他三家已接通。余额是带更新时间的查询快照，点击「刷新积分和模型」更新。

## 使用

### TRAE 国际版 IDE

点击「连接本机 IDE」只读使用 Windows 当前用户已登录的国际版代码编辑器。读取范围是 `Trae/User/globalStorage/storage.json` 中的账号和设备标识；不会读取国内版、写回登录文件或刷新原软件令牌。工具箱只加密保存账号绑定，令牌在请求时从 IDE 登录文件读取；切换账号后需重新连接，到期后在 IDE 登录再刷新。

获取的是 IDE 模型目录与套餐快照，已过滤自定义 Key 模型和内部代码补全功能。美元额度和 credits 分别显示，不相加。查询失败保留上次快照，未知套餐或字段不会推算为零。

2026-10-24 已在本机 SG 区国际版 IDE 账号验证额度查询、模型目录及 DeepSeek V3.2 的文本调用（回答 OK，报告输入 9、输出 1 Token）。当前支持普通和流式文本对话；工具调用、多模态、JSON Schema 和多候选未接入，明确拒绝这些请求，避免静默丢弃参数。US 区已配置独立域名，但未经本机真实账号验证。

协议事实参考 [trae-local-api](https://github.com/ZedeX/trae-local-api) 和 [cpa-multi-plugins](https://github.com/mmqz/cpa-multi-plugins)，并以本机 IDE 与实际响应校验。模型请求使用 IDE 完成扩展的 schema revision `20260212`，不能拿 UI 版本号代替；旧示例版本会错误返回 `fast_apply`，不足以证明聊天模型接通。未部署参考项目，未复制其流量日志或凭据处理代码。

1. 添加通道，填写名称、完整 Base URL（保留 `/v1`、`/api/v3` 等实际版本路径）、上游模型名和 Key。也可以选择“引用工具箱当前 API”，在请求时只读原设置。
2. 勾选启用。优先级数字小的先使用。
3. 启动网关，复制本机地址与网关密钥。默认地址 `http://127.0.0.1:18878/v1`。
4. 客户端模型填 `auto`，或填某个通道卡片上的模型 ID 来固定通道。
5. 点击“测试调用”可发送一条短请求；会消耗上游额度。正常调用才是接入成功的证据。

支持 `GET /v1/models`、`POST /v1/chat/completions`，含 SSE 流式输出。只监听 IPv4 本机环回地址，所有 HTTP 路径都需要 `Authorization: Bearer <网关密钥>`，不开放浏览器跨域访问。工具箱退出后服务停止，重新打开需要手动启动。

`auto` 遇到 HTTP 429/502/503/504 时尝试下一个通道，并冷却失败通道。连接错误、鉴权错误和已开始输出的流不会自动重发，避免不明确的重复扣费。不同通道的模型能力仍由上游决定，不会自动把工具调用模型变成普通文本模型。

## 额度含义

- **接口查询**：用户提供同一服务下的额度路径和余额字段，例如 `/quota`、`data.remaining`。必须使用服务实际支持的接口，不预设并不存在的查询 URL。失败时保留上次数据和时间。
- **手动记录**：从账户页面抄入数值、单位和重置时间，明确显示为手动快照。不会假装实时扣减。
- **网关用量**：统计经过这个工具箱的成功、失败请求以及上游返回的 Token 用量。未返回 usage 的请求不会被估算成官方 Token 数。
- 未查询到的额度显示“未知”，不显示零或无限额。Credits、请求次数、Token 不混合求和。原软件内消耗不属于网关统计。

### 豆包工作使用与限制

在“你关注的服务”点击“启动豆包连接”，待原客户端登录后点击“连接本机豆包工作”，选择启用通道。如果客户端原本已经运行，需要先从托盘退出，再用此按钮启动。工具箱不终止已有任务、不更改客户端登录目录或系统代理；调试连接仅在 `127.0.0.1:19223`。退出豆包工作即中断这条连接。

每次调用通过原客户端生成请求，再对这一次请求转发，避免本机失效的系统代理。只拦截该次请求的随机唯一标记，不拦截用户在豆包工作中的其他消息。会话 Cookie 只留在内存，不写入工具箱文件；仅加密保存账号绑定，账号变化后须重新连接。

这是工作 Agent 的文本桥接，仍由原客户端处理其权限和确认，不是独立的基础模型 API。多轮历史以带角色标记的文本提交，每次建立新会话；不传入共享文件夹或连接器。只验证自动模型，不冒充菜单中的其他模型。SSE 兼容格式在完整回答后返回，并非逐字实时流；请求期间客户端必须保持运行。上游业务错误、无正文及缺少回答结束标记均记为失败。额度展示原始窗口百分比与查询时间，不相加、不把 `<1%` 算作零。

### QwenWork 国内版

安装并登录 QwenWork 后，点击“连接本机 QwenWork”，默认选择实际目录中的 flash；可在“编辑”中选择目录返回的其他模型。刷新按钮同时查询模型及每日、订阅、长期积分。三项均为同一 credits 单位时显示合计；任一字段缺失则查询失败并保留上次快照，不假定零余额。

适配只读 `%APPDATA%/QwenWorkCN/auth-v2.dat`，使用当前 Windows 用户的系统解密接口；不修改客户端文件、不轮换其 refresh token。令牌仅存在内存中，工具箱只加密保存账号绑定。到期后到原客户端刷新登录，切换账号需重新连接。请求组件从已安装客户端加载，不打包或公开其 WASM 二进制。JavaScript 绑定改编自 Buddy2api／modelwharf，许可位于 `src/main/vendor/QWENWORK-LICENSE.txt`；凭据经子进程 stdin 传递，不放入命令行或临时文件。

首版支持文本与角色历史，暂不支持工具调用、图片、结构化输出；SSE 格式在完整回答后返回。网关仅记录上游真实 usage；外层 HTTP 200 下的业务错误和未完成回答都判为失败。未启用第三方项目的自动签到、活动领取或账号轮换功能。

另发现 [workbuddy2api-hub](https://github.com/ardeyouxipianyi/workbuddy2api-hub) 有 OAuth 和兼容网关实现。已只读检查说明和登录实现（参考提交 `47775c5e4aceb9f977bdebf5dd20175b44b5a78b`），没有运行它、导入账户或启用其中的积分任务功能。维护者 2026-10-23 的公告报告上游收紧非官方客户端拦截；不能把项目宣称视为本机验证结果。CodeBuddy 也有官方 [HTTP API Beta](https://www.codebuddy.cn/docs/cli/http-api)，但其会话接口仍需适配，不能直接填成本页的 Chat Completions 端点。

WorkBuddy 适配按公开协议事实独立实现，参考 [cpa-multi-plugins 协议清单](https://github.com/mmqz/cpa-multi-plugins/blob/main/docs/PROTOCOL.md) 与上述项目的授权、模型和计费请求格式。没有整体部署第三方代理，也没有启用其中的积分奖励功能。

## 配置、隐私与恢复

新设置单独保存到工具箱用户数据目录 `ai-hub/state.json`，不改写原来的字体、API Key、登录或偏好。新通道密钥、WorkBuddy 登录凭据、TRAE 账号绑定及网关密钥使用 Electron safeStorage 加密；系统安全存储不可用时拒绝保存。TRAE 令牌不复制到工具箱文件。渲染页面只接收是否有密钥，不接收上游密钥；网关密钥通过专门按钮复制，并避开工具箱自己的剪贴板历史。

请求记录只保存通道、状态、时间和耗时，不保存提示词、回答、原始上游报错或密钥。额度请求使用相同通道 Key，仅允许同源路径，不跟随重定向。

停止网关即可收回本地监听；删除某个通道不会删除原软件账号或工具箱原 API。更换网关密钥后，已有客户端需要同步新密钥。操作系统剪贴板由用户控制，复制后请粘贴到目标客户端。
