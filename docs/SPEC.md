# Agent 工具箱 — 需求规格 v0.1

> 一句话：把「查文档、打字、进入状态、问 AI」这四件每天都要干、但每次都要切窗口的事，收进同一个壳里。

## 0. 设计原则

1. **常驻不重载** —— 所有工具首次打开后就留在内存里，切换是瞬时的。用户抱怨的「每次都要切到 Edge 然后搜索」，省掉的就是这段时间。
2. **不花钱** —— 不用任何付费 API。AI 能力全部复用用户自己已登录的 DeepSeek 网页会话。
3. **可拆可加** —— 工具是插件。第 5 条「以后还要更多工具」靠注册表实现，加一个工具 = 加一个文件夹 + 注册一行。
4. **坏了要看得见** —— 依赖第三方网页 DOM 的部分（DeepSeek 桥接）一定会随对方改版失效。所以选择器可配置、有自检面板、失败时报错而不是假装成功。

## 1. 需求清单（来自用户口述，已整理）

| # | 用户原话 | 整理后的需求 | 本版状态 |
|---|---|---|---|
| 1 | 「查阅资料，最好是官方文档，内部嵌入 chrome 内核的浏览器打开」 | 内置 Chromium 浏览器 + 官方文档书签库 + 站内搜索 | ✅ v0.1 |
| 2 | 「节省打字，打字经常出错，要读懂中文打字出错的真实意图；偏差太大可以返回请求是什么意思」 | AI 中文输入纠错，输出置信度；置信度低时反问用户而不是硬猜 | ✅ v0.1 |
| 3 | 「进入状态的工具，长时间干活累了或者不知道干什么，提高专注力」 | 番茄钟 + 白噪音 + 呼吸引导 + 「不知道干什么」时 AI 帮你选下一件事 | ✅ v0.1 |
| 4 | 「调用 deepseek，背景可以自己上传，用网页版不用 API」 | 内嵌 DeepSeek 网页版 + 自定义背景图 + 常驻热会话 | ✅ v0.1 |
| 5 | 「可能还需要更多好用的工具，等待开发」 | 插件注册表 + 加工具文档 | ✅ 机制已就绪 |

## 2. 逐条设计

### 2.1 文档浏览器（tools/docs）

- 内嵌 `<webview>`（Chromium 内核，和 Chrome 同源），多标签页。
- 预置官方文档书签库：Python / MDN / TypeScript / React / Vue / Node / Electron / Git / Docker / K8s / PostgreSQL / Redis / Go / Rust / FastAPI / Django / pandas / NumPy / PyTorch / Tailwind / Vite …
- 书签可增删改，存本地 `config.json`。
- **站内搜索**：在当前文档站范围内搜（`site:` 限定），避免搜出一堆二手博客。
- 页内查找（Cmd+F）、前进后退、缩放、复制链接、用系统浏览器打开。

### 2.2 打字纠错（tools/typing）

形态：**应用内面板**（用户选定）。不申请 macOS 辅助功能权限，因此不做全局快捷键与原地替换 —— 以后要升级成全局悬浮窗，是独立的一版。

流程：

```
你打的原文 ──▶ DeepSeek 桥接 ──▶ {corrected, confidence, changes[], question}
                                    │
                    confidence ≥ 阈值 ──▶ 显示修正结果 + 逐条改动说明 + 一键复制
                    confidence <  阈值 ──▶ 「这句我拿不准」+ AI 的反问 + 你补一句说明再来一轮
```

- 阈值默认 0.6，可调。
- `changes[]` 逐条列出「把 X 改成 Y，因为 Z」，让用户能判断 AI 有没有改歪。
- 保留原文，永不静默覆盖。
- 历史记录本地保存，可回看。

### 2.3 专注 / 进入状态（tools/focus）

针对两个不同状态：

**A. 累了 / 静不下来** → 进入状态
- 呼吸引导（4-7-8），跟着圆圈呼吸 1 分钟。
- 白噪音：白噪 / 粉噪 / 棕噪 / 雨声，WebAudio 实时合成，不依赖任何音频文件。
- 番茄钟：默认 25 / 5，可调；专注时进入沉浸模式（界面变暗、只剩计时器）。

**B. 不知道干什么** → 帮你决定
- 本地任务清单（存本地）。
- 「帮我决定」：把任务清单 + 你当前的精力状态丢给 DeepSeek，让它只挑**一件**事，并给出一个 5 分钟就能开始的第一步。
- 输出的是「现在做什么」，不是又一个待办列表 —— 决策疲劳的解药是减少选项，不是增加。

### 2.4 DeepSeek 快问（tools/ask）

- 内嵌 `chat.deepseek.com`，独立持久化 session（`persist:deepseek`），登录一次长期有效。
- **自定义背景**：本地选图 → 自动压缩 → 注入 CSS 作为页面背景；可调暗度遮罩与模糊度，保证文字可读。
- 为让背景注入生效，本 App 对该 session 剥离了 CSP 响应头（只影响我们自己 App 内的这个分区，不影响系统浏览器）。
- 常驻热会话：App 启动即后台加载，点开就能用，省掉「切浏览器 → 等页面加载」。

**关于「速度」的实话**：文件/图片上传慢、AI 吐字慢，是 DeepSeek 服务端决定的，本地壳改不了。这个工具能省掉的是**切换与加载**的时间（每次约 5–15 秒），以及把它放在你手边而不是另一个浏览器里。

### 2.5 DeepSeek 桥接（core/deepseek-bridge）

需求 2 和 3 的 AI 能力都靠它。原理：一个**隐藏的** webview，和「快问」共用同一个登录态，被当作无界面的 LLM 调用：

```
注入文本 → 触发发送 → 轮询最后一条回复 → 文本连续 1.2s 不变且停止生成 → 返回
```

- 每次提问前开新会话，避免上下文污染。
- 未登录时明确报「请先到 DeepSeek 快问里登录」，不静默失败。
- **选择器会失效**：`core/selectors.js` 集中存放所有 DOM 选择器，每个都是候选数组按序尝试；设置页有「桥接自检」，能看到当前哪个选择器命中、哪个没命中，并允许手工覆盖。

## 3. 技术选型

| 选项 | 结论 |
|---|---|
| Electron | ✅ 唯一能同时满足「Chrome 内核 + 请求拦截 + 网页版 DeepSeek」的方案 |
| Tauri | ❌ macOS 上用的是 Safari 的 WKWebView，不是 Chrome 内核 |
| 打包器（Vite/webpack） | ❌ 不用。渲染进程用原生 ESM，改完刷新即生效，个人工具没必要引入构建步骤 |
| 前端框架 | ❌ 不用。工具箱是若干独立面板，原生 DOM 足够，且零依赖好维护 |
| 运行时依赖 | 只有 `electron` 一个 |

安全基线：`contextIsolation: true`、`nodeIntegration: false`、所有 Node 能力经 `preload` 白名单暴露。

## 4. 明确不做

- 绕过登录、破解风控、伪造请求签名 —— 容易封号，且正常登录态已经够用。
- 全局输入法级替换（需要辅助功能权限，本版用户选择了应用内面板）。
- 云同步 —— 所有数据只存本地 `userData/config.json`。

## 5. 目录结构

```
src/
├── main/           主进程：窗口、session、IPC、配置持久化
└── renderer/
    ├── core/       壳与共享能力（工具注册表、DeepSeek 桥接、选择器）
    ├── styles/     主题
    └── tools/      每个子目录 = 一个工具（插件）
        ├── ask/    DeepSeek 快问
        ├── docs/   文档浏览器
        ├── typing/ 打字纠错
        └── focus/  专注模式
```

加新工具见 `docs/ADD-A-TOOL.md`。
