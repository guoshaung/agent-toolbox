# T083：分摊账单结算

## 功能内容与必要性

共同晚餐、旅行和合住的费用往往由不同人支付，逐笔互转容易重复付款或漏掉几分钱。本功能按参与者、费用、付款人和每项权重计算各人的已付款、应承担金额和净额，给出可核对的简化转账建议。支持等分、整数权重和不参与某项费用，完全在本机运行。

这项能力区别于任务清单、饮食推荐和专注计时：它提供确定性的多人费用结算，不记录长期流水、不连接银行、不自动支付或换算汇率。

## 实现方式

金额以十进制字符串输入，最多两位小数，转换成整数分。按各项权重计算份额时用 BigInt 做乘除，避免大金额乘权重的浮点误差；先向下取分，再按最大余数分配剩余分，余数相同按参与者列表顺序。权重 0 不参与该项，所有人权重为 0 时阻止计算。

每人净额是已付减应承担，正值待收、负值待付。按净额绝对值配对付款和收款人，每笔扣掉一方余量，最终建议转账后所有净额归零。建议最多人数减一笔，不承诺全局最少转账笔数。报告保持整数分，不把四舍五入后显示的元金额用于再次计算。

UI 提供参与者姓名、费用说明、金额、付款人和各人权重控件，结果包括每人总额、逐项分摊和转账表。输入变化后旧结果失效，防止导出与当前输入不一致的结果；用户内容只作为文本显示。导出使用公共基础 `copyOnly:true`，已有文件不会被覆盖。

## 如何使用

1. 在“功能工作台 → 工具 → 个人效率与生活计算”打开 T083。
2. 编辑或增加参与者。姓名需要唯一；若某人是付款人，先更换该项付款人才能移除该成员。
3. 逐项填写共同费用、人民币元金额和付款人。每人权重默认 1，表示等分；权重 1:2 表示承担比例 1:2，0 表示不参与这项。
4. 点击“计算结算”，先核对逐项分摊，再看个人净额和转账建议。
5. 点击“导出结算 JSON 副本”，选择未存在的文件名。输入不自动写全局配置，切换功能前先导出。

## 使用后产出

JSON 报告包含格式版本、功能编号、币种 CNY、单位分、总费用、各人已付款／承担／净额、各项权重与份额、转账建议和舍入规则。报告中的所有金额都是整数分，便于审计和继续处理。界面展示元金额，正负和待收待付明确分开。

## 具体例子

点击“载入三人 100 元示例”：甲支付 100.00 元晚餐，甲乙丙各权重 1。最大余数法把不可整分的一分钱给参与者列表中第一位甲：甲承担 33.34 元，乙与丙各 33.33 元，总计恰为 100.00 元。

甲已付 100.00、应承担 33.34，所以待收 66.66；乙和丙分别待付 33.33。建议乙向甲转 33.33 元、丙向甲转 33.33 元，转账后三人净额都为 0。工具只输出建议，用户需自行核对并实际完成转账。

另一例：费用 1.00 元，甲乙丙权重 1、2、0，分摊为甲 0.33 元、乙 0.67 元、丙 0.00 元。余分分给余数较大的乙。

## 验证与限制

运行 `node --test test/feature-T083.test.js`。测试覆盖 100 元三人总额及净额结清、最大余数／同余序顺、零权重、超过安全 Number 乘积的 BigInt 计算、金额精度、多付款人、错误输入和报告序列化。渲染与宿主验证由交付验收记录补充。

首版只支持统一人民币币种、正费用、最多 20 人和 100 项费用、每项最多 50,000,000 元；不处理退款、税费自动生成、支付状态、汇率或全局最少转账优化。整数权重 0–1,000,000，不接受小数权重；可将比例同时放大为整数。舍入余分按照稳定列表顺序，不做随机轮换。没有跨会话草稿或历史账本存储。
