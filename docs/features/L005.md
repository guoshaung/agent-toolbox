# L005 讲解证据链

## 1. 功能内容

用户在自写讲解原文上选定精确片段，人工指定结论、理由、例子、来源片段或角色未知，再添加“陈述→其所依赖依据”的有向边。工具检查当前已确认结论是否能沿用户边到达当前已确认来源片段，输出全部路径、当前无来源结论和旧锚待重标结论。图中金色高亮所选来源路径、粉色边框标当前无来源结论，旧锚/边灰色或虚线。

默认例有两条结论：N1“缓存命中可以减少等待。”通过N2理由、N3例子到N4来源片段；N5“所有请求都会命中。”没有路径。因此**只把N5列为无来源**，不是把两条都列出。新增N5→N4可以只补上第二条结论的路径。所有角色、连边与出处是用户声明，不据此判断讲解语义正确、来源真实或论证充分。

原文显式提交版本，保留每版完整原文和人工来源。标注保留各版本的UTF-16/Unicode码点半开位置、原片段，边记录明确确认的原文版本。提交新版后旧标注/边失效，不重新搜索或悄悄漂移。用户逐片段重确认、逐边确认后才参与新版审计。没有AI必要依赖，离线人工MVP完整，不提供自动句子判真。

## 2. 为什么需要

一段讲解可能读起来流畅，但结论与理由、例子和出处之间没有实际写出的依赖关系。修改段落还可能使旧位置指向另一句话，而原链仍被错误展示成有依据。

L005把自解释中的片段与人工依赖关系画出来，帮助作者定位需要补充的连接或重新确认的位置。它检查的是**自写讲解的结构和当前锚位置**。L036追踪支持文献到用户标记原始来源的外部图并去重可达来源；L005不统计原始实验/独立文献数量，不因三条路径到同一来源片段声称三份独立证据，也不读取网页核真。

## 3. 实现方式与精确规则

`model.mjs`实现严格输入、版本化锚、DAG校验、可达集合与全部来源路径；`index.js`提供原文编辑/选区/手填位置/角色与出处/连边表单、SVG依赖图、全文版本/锚/边历史和报告预览；`meta.json`由生产工作台发现，`style.css`使用项目实际主题变量。用户文字以文本节点或XML转义渲染，无eval/用户代码/网络/语义推断。

- 原文编辑稿独立于最后提交版本。编辑稿文本或出处不同即待提交，不能混用旧锚审计；“提交原文新版”才递增版本，“放弃原文编辑稿”明确恢复已提交原文/出处。完全相同的稿不增加版本。来源变化也属于新版，旧来源保留。
- 锚为0起算UTF-16半开`[startUtf16,endUtf16)`，另保存0起算Unicode码点半开`[startCodePoint,endCodePoint)`、精确原片段和所属原文版本。包括标点/空白，不能切开emoji的代理对；片段≤240码点。恢复逐锚回读对应原文版本验证原片段及两种位置，不仅验证字符串长度。
- textarea会把CRLF/CR变成LF。对已提交原文的只读选区，工具检测与原文的规范化关系，映射回原文UTF-16位置；原文`🙂甲\r\n乙😀。`的可见LF选区`[4,7)`对应原文`[5,8)`、码点`[4,6)`，片段“乙😀”。码点索引把CR和LF各算一码点，不等于行列或用户感知字素簇。通过编辑框输入/编辑文本时使用浏览器返回的LF内容作为**新编辑稿**；先前已提交版本保持原CRLF，不冒称字节级编辑保真或文件导入。
- 提交新版让全部旧锚和边失效，即使文字片段没有变化。重确认一个标注时，新增该版锚；若当前版已确认，再次明确确认会替换该版锚，旧版本锚仍保留。不会自动按相同文字搜索。原边不因两个端点重标而恢复，必须逐条确认该边用于当前原文版本。边确认要求两端当版锚都存在。
- 来源片段是终点，禁止出边；其他角色可依赖任一已知片段，边的语义由用户承担。全体保留边（含旧边）必须DAG，未知端点、自环、重复有向边、循环全部拒绝。跨版本想改变边方向也必须先明确处理旧边，不能保留全局闭环。闭环没有来源不会假通过。
- 当前节点必须有当前版锚，当前边必须明确确认当前版且两端当前。每条当前结论沿当前DAG计算可达来源ID及**全部**来源路径。无来源只指已审当前锚没有来源片段可达；旧结论锚另列“待重标”，不把未审位置冒充已确认断链。用户来源角色缺出处名称/位置单列待补；有路径不证明出处有效。
- 当前区间重叠只提示人工标注一致性待核，不自动改角色/链、不认定论证矛盾。角色未知不会自动成为结论/来源。节点角色、人工说明/来源可编辑，为本台账当前人工声明；不是每个角色修改的不可变历史。完整旧原文/旧版锚/边确认版本保留，直到用户明确删除对象。

最多8原文版本、每版≤8000码点、20标注、每标注≤8版锚、60边、每边≤8确认版本；名称≤160、出处位置≤320、标注/边理由≤600码点。节点/边ID递增不复用，范围1–9999；非法控制字符/孤立代理项、未知schema/字段、错锚/引用拒绝。**全部原文版本、编辑稿、锚和边的JSON UTF8≤64KiB**，任何操作超限整项拒绝、不截断旧记录。

可达先用DAG集合计算，路径枚举只展开能到来源的分支；全部结论累计≤2048条来源路径/≤20000展开。预算超限整份失败，不输出截断的“完整报告”。JSON/Markdown/SVG各≤1MiB，超限整份拒绝。无审计结果仍能导出全量输入归档，保留超路径预算图或未提交编辑稿。配置只存schema1输入，不存派生路径，串行保存采用一在途请求/最新待写值队列；旧回执不冒称最新已保存。编辑、取消、隐藏、切走、销毁隔离迟到结果，恢复不自动审计。

## 4. 使用步骤与可复现例子

1. 打开L005，点击“审计讲解来源路径”。默认结果“结论2、连来源1、无来源1、旧锚待核0”，当前无来源ID**N5**；完整路径`N1→N2→N3→N4`。图中N5粉框、已选来源路径金色，来源角色/片段/出处仅用户声明。
2. 在依赖边表单选择起点N5、终点N4，填写人工理由，提交新增依赖边，主动审计后连来源2/无来源0。在图路径选择器选`N5→N4`只高亮那条路径，不改变全部报告。
3. 尝试N3→N1会形成循环，N4→N5违反来源终点，已有N1→N2是重复边：整项拒绝，没有新增假依据。删除需明确确认；有关联边的片段不能直接删除，先人工删除边，不静默清链。
4. 在原文编辑稿开头加“前缀”，旧报告立即失效但仍属于待提交稿，审计会拒绝混用。点击“提交原文新版”，原文v2保留v1，全部5标注旧锚、2结论待重标。此时当前无来源列表是空，不能将旧位置直接归为当前断链。
5. 逐标注选择ID，手填原始UTF-16起止各＋2（或在已提交只读原文选择对应片段，点击“从选区取位置”），确认当前片段。所有节点重标但旧边未确认时，N1/N5均当前无路径。再逐边点击“确认B1/B2/B3用于当前原文版本”，恢复仅N5无来源。旧版0起点与新版2起点并存，不自动漂移。
6. 选择原文非空选区并取位置，选结论/理由/例子/来源/未知角色，提交新增标注；来源片段出处可在完整标注区填写。清N4出处名称/位置，路径仍表示到用户标来源，但单列待补；把角色改未知，则N1失去来源路径。工具不猜真正来源。
7. 检查全部结论/原片段/来源路径、图、出处待补与重叠提示，预览并导出JSON/Markdown或SVG新副本。完整输入归档包含所有保留原文版本/锚/边及未提交编辑稿。整体替换教学例或删除对象需明确确认；要保留被删除对象请先导出，删除会移除其全部锚/边记录，不承诺撤销恢复。
8. 重载保留完整已提交版本及编辑稿/锚/边，但没有派生报告，主动审计。容量或路径预算满时先归档，再明确另建记录，不截断或部分假成功。

## 5. 产出与保存范围

界面输出结论到用户来源片段的路径/断链表、所有来源路径选择器、依赖箭头图、当前/失效锚与边数量、来源出处缺失项和重叠待核。图中文字为短标签，完整文字保留在每片段原文区、节点SVG title及完整报告；SVG/XML文字安全转义。路径选择/高亮只改变图，JSON/Markdown保留全部路径。

完整JSON/Markdown保留当前与各版全文/人工来源、未提交编辑稿、全部节点当前角色/人工说明/出处/旧新锚、全部边理由/确认版本、全部可达来源和路径、当前无来源/失效结论区分及规则口径。SVG含所有保留节点/边与当前选择的高亮，不是全文数据归档。输入历史归档明确“不是审计结果”，在未提交稿、超路径预算或无报告时仍可导出所有输入。

保存必须具备`files.saveTextSupportsCopyOnly===true`、携带`copyOnly:true`，且回执`ok===true`才显示成功。生产writer用`wx`写新文件，已有目标拒绝覆盖；取消/未知回执不能伪称成功。来源是人工录入，不读取/修改外部文件。预览/副本可能包含用户自写讲解和人工引用片段；没有可信来源或语义认证。已经开始写盘不能撤回，离开/销毁后不补显示迟到成功。
