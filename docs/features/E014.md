# E014 声音切片

## 1. 功能内容与适用范围

导入自己的本地音频，看完整源波形，把最多八段起止区间映射到数字1–8，点按钮或按键触发，一段播一次。每槽可开启/关闭、命名、调±12半音。录制触发和静默时间，也可在真实控件里精确安排触发时刻；回放组合表演、另存WAV、完整JSON工程、Markdown事件清单和源波形PNG。完全离线，无麦克风、摄像头、外链、音频平台或AI。

输入文件1字节至20MiB；由当前浏览器实际解码支持的格式才可用，选择器扩展名不是兼容保证。解码后接受最多60秒、1–2声道，转换44.1kHz单声道PCM16；双声道各取一半相加，会丢失立体声信息。槽区间≤15秒，±12半音同时改变速度/长度（+12减半、−12加倍），不是保音长调音高或高品质抗混叠算法。

最多60秒表演、256触发、8同时采样，完整尾音输出≤90秒、累计生成≤2000万样本；超限整体拒绝，保留旧结果，不截断。数字键仅在采样区域响应，重复keydown不追加。普通按钮支持Tab、Enter/空格；不要求拖动波形精确选区。

## 2. 为什么需要与规则口径

将个人录音切成可重复触发的小片段，组合时留下每次触发的时间和参数，让后来修改槽不改变已经录下的表演。切片只使用所选源帧，不会把整段源音频误写成表演。原文件永不改写。

源区间左闭右开：开始2秒、结束3秒对应88200至132300帧，共44100帧。界面秒数最多6位小数，用整数有理数四舍五入到44.1kHz帧；事件最多3位小数，按毫秒存储并四舍五入至输出帧，等时触发稳定保序。正负半音使用2^(半音/12)线性重采样，最后采样邻点越过区间时取0，防止读取下一段。

每次事件存[触发毫秒、槽0起、源开始帧、源结束帧、半音]。回放/导出重新使用事件快照；当前槽名称或参数修改不会重写快照。总音量是整个表演的现行参数，修改会改变整体回放/导出。混音统一÷8留出并发余量，最后限幅±0.95；一段也保持相同增益，故较源音量低，不假称响度归一化。松键不会截断正在播放的一次性切片。

录制以单调经过毫秒计时，时钟倒拨夹到上次值，60秒自动结束。停止/隐藏/离开会结束当前录制并保留已录事件及最后静默时长，关闭音频并停止计时；返回必须重新启用。撤回删除时间排序的最后一个事件，并把末尾静默缩到剩余最后触发时刻；不是按历史插入顺序撤销。

## 3. 实现方式与边界

model.mjs负责严格schema1、重复JSON键/整数词法/未知字段校验、规范Base64、PCM SHA-256、转换、源帧/音高重采样和RIFF PCM16写入。index.js使用项目原有h()建立完整控件与Canvas。用户手动启用后才创建AudioContext，每次BufferSource只持有选中切片的AudioBuffer；停止会stop/disconnect/释放buffer引用，隐藏/deactivate/destroy关闭AudioContext、清理50ms定时器和监听，没有RAF或后台音频。

浏览器OfflineAudioContext.decodeAudioData读取本地文件并按目标采样率解码，不播放。PCM/float RIFF WAV先校验格式块、数据块、声道、块长度/对齐、声明时长≤60秒再调用解码；其他编码/未知WAV编码依赖浏览器解码成功后再验证时长，**原生解码可能先分配超过60秒的内部缓冲**。20MiB压缩文件上限不等同于解码内存上限；没有编码沙箱/流式解码或取消底层解码的承诺。取消/离开只丢弃异步结果，等待当前底层工作结束前不排第二个导入，避免旧结果覆盖新状态。转换/恢复/组合生成每65536样本让出事件循环并检查取消，单片重采样同步有界。

JSON工程最多8MiB，内嵌完整规范PCM（最多5292000字节，Base64约7056000字节）、八槽、全部256事件及参数；尺寸超限拒绝。原文件名、字节数和原文件SHA是导入时的身份记录，**不嵌入原压缩文件**；另有PCM SHA校验恢复后的真实规范字节，不能将转换后的PCM哈希当原文件哈希。未知版本、重复键、非规范Base64、超界源帧和坏PCM摘要在应用前拒绝。原身份记录不是签名或可信来源认证，手工编辑者也能重算摘要。

大型素材不写公共config。工程只在模块内存：整个工具暂离可保留当前面板内存，但切换具体功能会销毁，重载窗口也从空面板开始。必须显式另存完整JSON再导入；不声称自动草稿恢复。恢复按钮需预览，已有工程再次应用要勾确认；实录替换旧表演同样需勾确认。原生保存待回执期间锁控件，旧异步回执在隐藏/离开后不能报成功或恢复旧资源。

API依据：[W3C Web Audio decodeAudioData](https://www.w3.org/TR/webaudio-1.0/#dom-baseaudiocontext-decodeaudiodata)、[MDN AudioBufferSourceNode](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode)。本功能没有承诺全格式、跨平台或物理声卡时延一致。

## 4. 如何使用与具体例子

1. 选择一个10秒可解码WAV，等校验预览后点“应用采样工程”。当前已有素材时先勾“确认替换当前素材、槽及表演”。
2. 槽1保持开启，把“起秒”改2、“止秒”改3、半音0，点“应用槽1”；总音量可改100。
3. 点“启用采样音频”，点击1号采样键，或聚焦采样区域按数字1；播放长度是1秒。调+12播放0.5秒，调−12播放2秒；改后再点应用槽。
4. 为精确复现设计验收，安排槽1、秒0，点“加入安排触发”；再填秒3，同按钮再点一次。统计显示两次触发、含尾音4秒；触发表的源帧分别都是88200至132300。
5. 点“回放完整采样表演”或另存WAV：0–1秒第一段，1–3秒静默，3–4秒第二段；没有源录音的0–2秒或3–10秒内容。音量100时输出每个样本为所选源PCM/8四舍五入。
6. 想实录则启用音频、勾确认替换旧表演、点开始录制，按键/按钮触发，点结束。真实点击时刻不保证正好0/3秒，可在清单查看记录毫秒；精确安排功能供可控复现。
7. 先另存完整JSON。重载/重新进入后选择此JSON，校验PCM SHA预览后应用，即恢复素材、槽、音量、事件及静默时长。Markdown或WAV不代替完整工程。

## 5. 产出与安全副本

|产物|完整范围|
|---|---|
|JSON|schema1，完整转换后PCM及SHA、原身份记录、全部八槽/参数/事件，可重新导入|
|WAV|44.1kHz单声道16bit LE，仅事件切片、静默与全部尾音，不含整段源，最多90秒|
|Markdown|全部事件参数快照、两个摘要、转换和增益口径；不内嵌素材，不能单独恢复|
|PNG|1000×240完整源波形与启用槽范围，960列精确min/max；不是组合表演时间线或音频|

公共文本能力saveTextSupportsCopyOnly===true、二进制saveBinarySupportsCopyOnly===true才可保存；文本8MiB、二进制10MiB。所有payload明确copyOnly:true，二进制包含规范Base64和SHA-256。只有ok===true报成功，取消/字符串“true”/失败/partialPath均不报成功；部分路径供人工核对。新副本已有目标wx拒绝，既有源或备份不会覆盖。缺桥时按钮禁用并解释升级依赖。本分支基a80e115已包含二进制安全导出基础，不修改公共文件。
