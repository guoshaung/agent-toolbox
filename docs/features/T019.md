# T019 文件时间戳整理副本

## 1. 功能内容

选择普通源文件及新目录父位置，输入统一整数秒偏移，先预览每项原修改时间、预期副本修改时间和完整新目标。明确确认后平铺复制到尚不存在的新目录，只调整副本 mtime，保存原始时间清单。可以另存完整计划或实际结果 JSON/Markdown 新副本。

处理目录复制、修改原件、creation/birth/ctime整理和后台任务不在范围。副本 atime 保持复制前来源值；原件不写，但 OS 读取可能自行更新原 atime，因此不承诺原访问时间不变，不为恢复 atime 回写原件。素材排序的修改时间和源内容由验收确认保持不变。

## 2. 为什么需要

设备时钟偏差可能让素材按修改时间排错。逐个改原件既难追溯，也容易失去对照。本工具把原件路径、旧时间和偏移后的新时间放进可审核计划，用新目录副本供后续排序或交付，原件的内容和修改时间不改写。

偏移是 UTC 绝对秒加减，不是日期换算、时区转换或夏令时修正。选择3600秒表示一小时；用户判断实际设备偏差是否应统一修正，工具不从内容或名称猜拍摄时间。

## 3. 实现方式

`model.mjs` 校验偏移、平铺名称、新目录名和完整报告；`host.cjs` 经既有可信 Host 桥执行受用户文件/目录选择约束的操作；`index.js` 提供选择、预览、独立确认、取消、结果表和完整副本导出。renderer 只提交同窗口 opaque selectionId/parentId/planId，不提交任意复制路径或命令。

一次1–50个普通文件，单个≤32MiB、总量≤128MiB。偏移±315576000整数秒（约10年）；名字1–80 NFC字符，不含路径分隔/控制/设备保留名/尾点空格。同名大小写冲突、清单保留名 timestamp-manifest.json、最终源/父目录链接、UNC/设备路径整体拒绝。选择及预览只读元数据，不读取源正文、不创建目标。先验证最终类型、realpath及dev/ino，预览绑定源size/mtime/ctime，变化要求重新选择。祖先链接会由realpath规范化，其他映射盘/挂载本地性未确认；这不是恶意竞态安全沙箱。

确认后 mkdir 新目录，已有目标不重用、不覆盖；每个文件只读打开来源、核对句柄身份，wx独占创建副本，以64KiB缓冲顺序读写并处理短写。源在复制前后元数据变化时拒绝完成。读取源流计算SHA-256，副本检查大小和实际mtime（允许≤2ms精度误差）；该运行时摘要是源读取流摘要，不声称二次回读副本做端到端哈希验证。仅对副本句柄调用utimes，副本atime沿用源复制前值、mtime加偏移；不调用源写入/chmod/utimes。

自己打开的输入/输出句柄在finally各自关闭，某个close失败不能跳过另一个。最多32窗口状态、128一次性job、全宿主4复制任务，每窗口1项，30秒协作期限。取消/销毁不硬停正等待的文件IO，busy和资源到收尾才释放；预览后新目录变更会拒绝后续路径写入，但检查不锁住文件系统。失败/取消保留当前新目录及部分文件供人工核对，没有自动删除和事务回滚承诺。

全部文件复制/时间调整和timestamp-manifest.json写入、关闭完成才报告complete=true。实际结果同时保留全部原计划和已尝试逐项状态，未尝试项不会悄悄丢失。清单失败时即使已有全部副本也明确未完成；部分目录中的任何残留清单都不能替代当前失败回执。JSON/Markdown各≤2MiB，保存前完整预览，公共text writer copyOnly/wx防覆盖，只有ok===true称成功。资料仅内存，不存自动执行计划；输入改动清旧计划，离开/隐藏/销毁清选择并隔离迟到回调，已开始的原生复制/保存不能撤回。

依据：[Node20 文件句柄读取/写入与utimes](https://nodejs.org/download/release/v20.18.3/docs/api/fs.html#filehandleutimesatime-mtime)、[独占文件打开标志](https://nodejs.org/download/release/v20.18.3/docs/api/fs.html#file-system-flags)。没有新增依赖包、shell或网络请求。

## 4. 如何使用

1. 在工作台打开“工具 / 文件与批处理 / 文件时间戳整理副本”。选择要复制的1–50个普通文件，再选新目录父目录。
2. 输入整数偏移秒，默认3600；输入尚不存在的新目录名，默认timestamp-copy。文件名在新目录平铺，重复名称需要在来源选择阶段解决，不自动编号。
3. 点“预览完整时间副本计划”，核对完整新目录、每个原mtime和预期mtime。可先另存计划备查。
4. 勾选“确认当前完整时间偏移与目标”，点击“确认复制并调整副本时间”。未勾确认不会创建目录；时间或名称改变会废弃旧确认与计划。
5. 完成后检查逐项状态、实际修改时间和目录中的timestamp-manifest.json。取消/失败时人工核对部分目录；重新操作需选择新的目录名和新计划，不能续写已有目录。
6. 预览完整JSON/Markdown，再另存已预览报告。已有目标或源文件拒绝覆盖，取消/错误不算成功。离开不自动恢复或复制。

## 5. 产出与具体例子

计划包含全部来源路径、字节数、原mtime/atime、预期mtime、统一偏移及完整新目录。执行结果包含全部原计划、每个已尝试文件状态、实际副本mtime、源mtime/atime观察、读取流摘要、完整/取消/部分目录状态和清单写入情况；不会将计划冒称已落盘文件。

例子：自有a.bin/empty.txt/unicode.txt，原mtime都是2023-11-14T22:13:20Z（1700000000000ms），输入3600秒并预览。确认后副本mtime为2023-11-14T23:13:20Z（1700003600000ms），二进制/空文件/中文内容保持原字节，三个原mtime仍1700000000000ms。完整新目录有三副本及timestamp-manifest.json。另选negative-copy、偏移−3600时得到1699996400000ms；原件仍不修改。

已有timestamp-copy时重新预览会拒绝，不覆盖上次副本。正在复制时取消会报告complete=false、canceled=true并保留完整原计划；如果已经创建文件，该部分目录不会自动消失，需要用户核对。来源在预览后改动，旧计划拒绝完成，需要重新选择和预览。
