# T017 文件权限差异审计

## 1. 功能内容

从用户选择的有限目录采两份只读权限条件快照，或导入两份完整 JSON，按相对路径比较读取/写入条件和平台模式字段，列出已知变化、未配对、未知和跨平台不兼容。采样不打开文件正文、不写测试探针、不修改权限，导出完整 JSON/Markdown 新副本。

实现 catalog 的两份快照、平台字段、报告预览和只读前后比较。`fs.access` 条件通过不保证实际读写：Windows ACL 没有检查，POSIX mode 也不是当前用户有效访问权。单独的读取/写入错误与未知结果保留，不用“相同”掩盖未知。

## 2. 为什么需要

文件复制或目录迁移后，用户需要核对某个相对路径的只读状态是否变化，并保存可以逐项复核的来源。直接看目录属性无法同时对照两次观察；把访问检查通过当成完整 ACL 检查会误导后续操作。该工具提供有限、可追溯的前后条件报告，不自动修权限或诊断所有访问失败原因。

两份快照可以来自不同目录或计算机，按相对路径对齐不证明同一文件身份。单侧出现只标 first_only/second_only，不宣称文件被添加、删除或已经不可恢复。

## 3. 实现方式

`host.cjs` 通过公共可信 Host 桥调用普通 OS 目录选择，主进程仅保留窗口绑定的 opaque 根 ID。renderer 不能提交任意扫描路径；同一窗口最多一个查询、32 个窗口状态、128 个一次性 job。目录取消不自动选默认目录，不自动扫描。最终根链接、UNC/设备路径拒绝，最终条目链接和特殊文件跳过。

Host 用 `opendir` 顺序枚举、`lstat` 读取元数据，普通文件/目录分别调用 `fs.access(R_OK/W_OK)`。已知 EACCES/EPERM/ENOENT/ENOTDIR 为 condition_fail，其它错误为 unknown，只保留有限原因码，不回显内部错误正文。模式为三位八进制：Windows 普通文件 owner-write 位仅作为只读提示，目录/链接该提示为 null；POSIX mode 保留原位但不计算当前用户 ACL、组、root 特权或执行权。

最多 1000 条子项、128 个排队目录、12 层、256KiB 相对路径、15 秒协作期限；根行额外保留。遇界限、取消、元数据异常或目录身份/mtime变化保留已观察前缀并明确不完整，未运行目录单列。不能硬停正在等待的 OS 元数据调用，busy 到收尾才释放，自己打开的 Dir 在 finally 关闭。普通 identity/realpath/mtime 检查不能锁住路径、抵御恶意竞态或确认所有映射盘/挂载的本地性。

`model.mjs` 严格验证 schema1、字段、UTC 日期、有限条件/模式来源、相对路径、平台内重复路径与体积。Windows 相对路径按大小写折叠对齐；跨平台的 mode 字段列不兼容。未知条件/null 不算相同；已知变更列 before/after。JSON 文件通过真实 File API 读≤2MiB 严格 UTF-8，SHA-256 仅证明导入字节，不认证内容；原 live_host 声明替换为 imported_json。JSON.parse 对重复对象键使用 JavaScript 最后值规则，不声称做重复键检测。

界面每页 40 行，完整报告各≤2MiB，不按分页截断；预览含本机路径。只有 `saveTextSupportsCopyOnly===true` 才保存，公共文本 writer 用 wx 独占新建，已有目标拒绝，只有 ok===true 显示成功。资料仅内存，不存配置或后台任务；编辑来源、重新采第一份、离开/隐藏/销毁按状态清理，epoch 隔离迟到回调，返回需手动选择/导入。已开始的原生保存不能撤回。

平台解释依据：[Node 20.18.3 fs.access 及其 Windows ACL 限制](https://nodejs.org/download/release/v20.18.3/docs/api/fs.html#fsaccesspath-mode-callback)、[Node 文件模式与 Windows write 权限差异](https://nodejs.org/download/release/v20.18.3/docs/api/fs.html#fschmodpath-mode-callback)。本功能没有新增依赖包，不调用 shell、外部程序或网络。

## 4. 如何使用

1. 在工作台打开“工具 / 文件与批处理 / 文件权限差异审计”，点击“选择允许查询的目录”。
2. 点击“采第一份权限条件快照”，查看平台、完整状态、原因与逐项条件。可先预览 JSON 并另存第一份源快照。
3. 用户自行完成需要对照的复制/只读状态变化；本工具不会改文件。点击“采第二份权限条件快照”，再点“比较两份权限条件快照”。重新选根保留第一份、清第二份，便于对照另一目录。
4. 或用两个文件输入导入先前保存的源快照 JSON；比较报告本身不能当作源快照导入。未知、跨平台字段、单侧路径分别核对。
5. 点击完整 JSON/Markdown 预览，再“保存已预览权限报告新副本”，选择新名称。取消/失败保留预览；已有文件拒绝覆盖。离开清除根和两份快照，不会自动恢复或重扫。

## 5. 使用产出与具体例子

快照包含平台、根、live/imported 来源、采样时刻/耗时、所有相对路径、类型、读取/写入条件、mode 及说明、原因和完整状态。比较产出保留完整第一/第二源快照和所有配对行、已知字段 before/after、未知字段、不兼容字段及统计。Markdown 内含同一完整 JSON，不修改任何源文件。

具体 Windows 例子：在自有测试目录放 `a.txt` 和 `b.txt`，采第一份。用户通过系统属性把 a.txt 设为只读，再采第二份并比较。唯一已知变化路径 a.txt：writeCondition 从 condition_pass 到 condition_fail、modeOctal 从 666 到 444、modeWriteHint 从 true 到 false；b.txt 和根的条件无已知变化。这个例子不证明 Windows ACL 完整可写，也不会声称其它未知字段相同。

实际 46 个文件加一个外部 junction 的例子保留根共 48 行：只有 a.txt 的上述三字段变，未配对 0，外部链接保持读取/写入未知，未知路径 1。第二页显示 8 行，JSON/MD 仍包含全部 48 配对行及两份各48行源快照。把第一份 JSON 导回后来源明确为 imported_json，并保留真实文件字节摘要。
