# T013 文件交付校验清单

## 1. 功能内容

用户选择完整源目录，通过本地 File API 读取实际字节并生成 SHA-256 相对路径清单；随后选择完整目标目录，按路径对照实际字节数和哈希，分别列出缺失、修改、额外与一致文件。可把源清单保存为 JSON/Markdown 新副本，JSON 可重新导入；差异报告同样先完整预览，再保存 JSON/Markdown 新副本。

界面按 50 项分页，完整导出包含所有记录。源、目标均只读；不搬移、不改名、不整理、不删除文件，不上传，不用账号/AI/网络或新增包。无全局配置、自动草稿、后台历史或无限任务记录。没有源清单和目标实际读取就不能宣称交付完整。

## 2. 为什么需要

两个文件夹名称可能不同，却应该包含相同相对路径与内容。单看数量不能发现一个文件被另一个文件替代；只比较大小会漏掉等长内容变化。交付清单让收件人无需接收原文件内容，也能用本机实际读取的字节检查遗漏与变化。

清单记录每条相对路径的预期字节数及 SHA-256；报告补充目标的实际值和具体差异原因。路径冲突不自动改名或吞并，避免 Windows 大小写/NFC 表示和文件/目录前缀造成误判。导出到新文件保护来源。哈希用于完整性核对，不是来源签名或发送者认证，导入清单本身仍需用户确认可信来源和完整范围。

## 3. 实现方式

- 元数据沿用“工具 / 文件与批处理”。`index.js` 默认同步 `create(root)` 返回 activate/deactivate/destroy，界面使用共享 `h()` 文本节点，样式局限 `.feature-t013`。独立 `model.mjs` 包含路径/清单校验、文件读取、SHA-256、比较与导出，无其他功能运行时依赖，不修改共享 main/preload/样式。
- 单集合 1–500 个实际所选文件；单文件 ≤8 MiB，总 ≤20 MiB。源清单必须 1–500 条；目标可通过明确的“按空目标集合核对”按钮声明 0 文件，并提示未扫描目录，全部标缺失。空 File API 选择不自动当空目录。零字节文件支持，空目录不枚举。清单 JSON 输入 ≤1 MiB UTF-8，完整清单/报告每输出 ≤2 MiB；超限整次拒绝，不截断或略过。
- 目录输入使用 `multiple + webkitdirectory`。例如 `发出根/sub/C.bin` 和 `收到根/sub/C.bin` 都剥除且只剥除最外层根名，得到 `sub/C.bin`。根名不记录到清单或报告。一次选择必须来自同一个根，不混用有根与平级路径；保留根内子目录和原拼写，不自动 NFC 归一化或改名。目录不兼容时平级 multiple 备用仅用 File.name，未提供的子路径无法推断；同名平级文件明确拒绝。两个输入以该侧最近一次选择为准，必须完整选择交付集合。
- 路径最多 500 字符、每段 120 字符，禁止绝对路径、遍历、反斜杠、空段、Windows 设备保留名、控制及不支持字符、尾点/空格。比较前检查各集合及源/目标路径并集：不区分大小写/NFC 的同名不同拼写和文件/目录前缀冲突均阻止报告；不任意把 `A.txt` 与 `a.txt` 当同文件，也不静默列两份兼容副本。完全相同路径在源/目标各出现一次可正常匹配。
- 文件预检数量、路径、单文件/总大小及 File.slice 后才读取；每 64 KiB 调用 Blob.arrayBuffer，核对返回实际字节数与片段大小，在每次读取后/让出事件循环后检查任务票据。完整实际字节缓冲用 WebCrypto SHA-256，包括任意二进制、NUL、FF 和空文件；digest 返回后再次检查取消。报告 size 来自读取缓冲字节数，不只信任输入清单或文件名。
- SHA-256 是固定算法，清单为 `{format:'T013-manifest',version:1,algorithm:'SHA-256',pathRule:'strip-selected-root-or-flat-name',files:[{path,size,sha256}]}`。严格导入 known keys：顶层和每个文件只允许声明字段，拒绝缺失/未知字段、不支持版本/算法/路径规则。size 是非负安全整数并服从文件与集合限额；sha256 是 64 位小写十六进制。清单导入核验的是声明和结构；只有读取目标内容后才获得实际内容核对。
- 有界 JSON 解析最多 1 MiB、8 层、5000 个值，严格语法、安全整数和 Unicode，重复字段包括 Unicode 转义后同名键一律拒绝，不沿用 JSON.parse 默认后值覆盖。纯文本必须严格 UTF-8；BOM、UTF-16/GBK 或无效编码不自动猜测。导入文件分块读取、字节数核对、取消后丢弃旧回调。有效文件数组统一按原相对路径字符顺序排序，不丢条目。
- 比较完整路径并集：只在源出现为 missing，双方出现且 size 或 sha256 不同为 modified，只在目标出现为 extra，双方字节数/哈希一致为 unchanged。每条报告含 path/status、预期/实际 size+sha256 和原因，不存在的一侧在 JSON 为 null、界面/Markdown 显示 `—`。size 与 hash 的差异分别报告，等长修改也可识别。最多 1000 个并集结果全部保留，分页不会减少输出。
- JSON 及 Markdown 输出只含路径、字节数、SHA-256、规则和差异信息，不含原文件内容。Markdown 转义文件名中的链接/强调等符号，界面使用文本节点不执行路径内容。报告 JSON 格式 `T013-delivery-report` v1，记录源/目标数量与总字节、四类计数及完整 records；报告不作为源清单导入。
- 导出必须先完整预览，再调用生产 `files.saveText({content,extension,defaultName,copyOnly:true})`；检查 `saveTextSupportsCopyOnly===true`。renderer 不指定任意目标路径，保存对话框让用户选择新文件名；生产 writer 使用独占 `wx`，已有源/目标/其他文件均拒绝覆盖。仅 `ok===true` 显示成功，canceled、false、undefined 或异常保留预览且不误报成功，普通异常原文不显示内部路径。
- 来源新选择或清单编辑废弃源清单、报告、预览；目标新选择废弃报告/预览，保留有效源清单。忙状态阻止叠加任务，取消、清除、隐藏、暂停、销毁令旧读取/hash/保存结果失效，不复用部分结果。已完成结果在同面板暂停恢复保留，不自动核对或导出；切换具体功能清空文本、File 引用与监听，需预先保存。原生保存确认后的物理副本写入无法被 UI 票据撤回，仍须用户处理已打开的对话框。
- 本功能没有自有符号链接遍历或系统目录扫描；File API 由宿主决定提供哪些 File，无法识别原对象是不是符号链接，按宿主提供内容读取、不保存链接关系。没有权限/时间戳、隐藏文件遗漏自动发现、空目录枚举、文件锁或应用一致性快照。源可能在读取期间改变，不能把完整所选集合的哈希报告理解为全目录原子快照。JSON 解析和每个 ≤8 MiB digest 内部不可抢占，仅在有界阶段前后取消；不承诺大容量性能或安全内存擦除。

## 4. 如何使用

1. 选择完整源目录；目录接口不兼容时使用源平级备用，并确保无同名文件、完整范围和所需子路径没有丢失。
2. 点击“生成源目录清单”，查看逐文件实际字节数及 SHA-256。分页每 50 项，上一页/下一页查看全部。根名不参与路径匹配。
3. 可“预览源清单 JSON”后保存新副本交付；其他本机读取该 JSON，或粘贴后“核验并导入源清单”。Markdown 供阅读，不支持作为源清单导入。
4. 选择完整目标目录并“核对目标完整目录”。查看四类计数、每条源/目标实际值和差异原因。目标根名可不同，内部相对路径须相同拼写。若明确目标没有文件，可使用空集合按钮；这不是扫描空目录的证明。
5. “预览差异报告 JSON/Markdown”，检查完整内容后“保存已预览的新副本”，在保存对话框选择尚不存在的文件名。当前页之外的记录也导出。取消/失败保留预览可重试，已有文件不能覆盖。
6. 改来源、目标或清单后旧结果失效，需重新核验；读取时可取消。清除/切换功能前保存需要的清单或报告，暂停回来不会自动保存。

## 5. 使用后产出

源 JSON 清单可重新导入，包含完整相对路径/实际字节数/SHA-256 与固定规则；源 Markdown 为完整可读表格。JSON 差异报告包含所有缺失、修改、额外、一致记录及源/目标对照；Markdown 报告有同样完整表格和摘要。没有原文件内容和系统绝对路径。

产出均为显式保存的新文本副本；源/目标文件没有写入、搬移或删除。报告只对实际完整选择的文件集合成立，不保证 File API 未提供的隐藏文件、空目录或外部客户端行为。哈希一致意味着本次读取字节和清单匹配，不证明来源身份或全应用状态一致。

## 6. 具体例子、测试与限制

点击“来源演示 A/B/C”：根 `发出根` 内 A.txt 内容 `A旧内容`，B.txt 内容 `待交付B`，sub/C.bin 字节 `[0,127,255]`。点击“目标演示：改 A / 缺 B / 同 C / 增 D”：不同根 `收到根` 内 A.txt 改为等长 `A新内容`，没有 B，C 字节不变，新增 D.txt `D额外`。应准确显示“缺失 1 / 修改 1 / 额外 1 / 一致 1”；A 的字节数相同但 SHA-256 不同，B 缺失，D 额外，C 一致且实际 3 字节。四条路径根名均剥除。

先导出源 JSON，清除后读取，再选择目标目录核对，四类结果相同。把清单加入重复 version 字段、未知字段、size 改负数或超限、SHA-256 改 63 位、path 改 `../A`，导入明确拒绝，没有目标核对或导出旧结果。源/目标中加入大小写/NFC 同名、文件 `a` 与 `a/b`，阻止核对而不吞文件。平级选两个不同来源但都叫 a.txt 也拒绝。

53 文件样例：读取后第一页 50 条、下一页 3 条，JSON/Markdown 导出仍完整 53 条。模型支持 500 源全缺失 +500 目标全额外的完整 1000 行报告，不静默截断。已有保存目标或原文件被选回时独占 writer 拒绝，其内容和哈希不变。
