# E034 小盆栽

## 1. 功能内容

三种原创程序矢量植物：蕨叶、多肉、小花。显示幼芽、舒展、茂盛、成熟四阶段，当前水分、光照位置和有效成长小时数。用户可以浇水、换位、暂停/继续生长，导出完整 PNG 图片，以及用版本1 JSON 存档恢复植物、照看记录和暂停状态。完全离线，不使用 AI、天气、摄像头或网络素材。

这是明确规则的桌面照看小游戏，不是真实植物模拟。水分归零不会死亡或倒退；成熟后维持阶段。不同植物共用成长规则，形态各不相同：蕨叶逐渐舒展、多肉体积增大，小花从花苞到花瓣。

## 2. 为什么需要

提供一个每日可短暂照看的安静对象。操作结果和成长条件清楚，既能观察时间变化，也可主动暂停。存档是用户选择的新文件副本，换植物或切换功能前可以保存当前记录，不需要账户、外部服务或全局大型配置。

## 3. 实现方式与严格边界

模型 `model.mjs` 只保存版本、植物枚举、水分、光照枚举、成长小时、暂停布尔值、上次结算的本地 Unix 毫秒、最近照看记录以及被滚动移除的记录数。阶段和 SVG 始终重新计算，存档不接受派生阶段/SVG/未知字段。`index.js` 提供实际植物选择、浇水、换位、暂停、草稿编辑、浏览器文件输入、恢复和另存控件。

游戏规则如下：新盆栽水分60，明亮窗边，成长0小时，生长未暂停；浇水加25，最多100。非暂停时，每经过小时水分减2点，最低0；有水期间明亮位置按1倍累计有效成长，散光角落按0.5倍。24/48/72有效小时分别进入舒展/茂盛/成熟，成长最多72小时。

使用闭式运算，不逐小时/tick补算：令 `h=max(0,(当前毫秒-上次结算毫秒)/3600000)`，有效湿润小时 `w=min(h,旧水分/2)`；水分 `max(0,旧水分-2h)`，成长 `min(72,旧成长+w×光照倍率)`。浇水/换位/暂停操作先按原状态结算，再应用操作并记录；这样换位不会把过去整段时间按新倍率计算。

暂停冻结水分和成长，暂停后的结算只更新计时锚点。继续先在暂停状态结算到当前时间，再解除暂停，因此不补算暂停间隔。界面 create 不启动定时器，activate 只建立一个10秒刷新定时器，无 RAF、音频或持续动画。隐藏/deactivate 停止刷新；可见/activate 时只按本地经过时间一次结算，再恢复10秒刷新。**未暂停盆栽会计入离开/关闭后的时间；暂停存档不会。** 切换具体功能销毁未保存状态，重开需自行恢复存档。

使用 `Date.now()` 本地时间。倒拨或导入未来时间时，负经过时间按0处理，并保留较大的时间锚点，直到当前时间追上；界面明确显示提醒，不重复计算已经经过的时间。向前调钟视为经过时间，没有网络校时。时间要求有效非负安全整数且不超过 JavaScript Date 支持的上界，时间差有限；一万天间隔仍然一次运算。

JSON草稿及文件限64KiB UTF-8，文件用严格 UTF-8 解码。恢复先完整校验再替换当前状态：只接受版本1、精确字段集合和枚举、有限数值/安全整数、有效值域、1–100条结构完整且按时间排序的记录、记录时间不晚于状态时间；拒绝重复键（含转义等价键）、未知字段、未来版本、过深结构、损坏JSON和超限内容。未来**时间戳**按倒拨规则处理，未来**版本号**直接拒绝。存档是游戏状态，不带真实性签名。说明信息和导入文字通过文本节点呈现，不执行用户代码。

照看历史只记录新建、浇水、换位、暂停、继续，不为每次刷新添加记录。最多保留最近100条，之后滚动删除最早记录，同时显示旧记录移除数，不声称完整永久历史。记录日期为带 `Z` 的 UTC ISO 格式；同一毫秒操作保留提交顺序。

PNG为本地 SVG→Blob URL→原生 Image→800×600 Canvas→PNG 编码，保留完整花盆、背景窗景与水分图示。图片最大10MiB，规范Base64与SHA-256交给安全二进制接口重新核验；依赖基础提交 `c0c93aa`（公共基础 PR #14）。JSON 使用 `saveText({content,extension:'json',defaultName,copyOnly:true})`，PNG 使用 `saveBinary({copyOnly:true,defaultName,base64,sha256})`；都先检查对应 `SupportsCopyOnly===true`，缺能力禁用。只有 `ok===true` 显示成功，取消/失败/partialPath 明确区分。已有目标独占创建失败，不覆盖原文件。编码和文件读取可取消，失效结果不调用保存；原生另存已提交时须在对话框取消。生成不暂停游戏规则，因此未暂停状态会在生成结束时一次结算经过时间；需要冻结图片和数值时先点击暂停。

destroy/deactivate/隐藏取消刷新调度；销毁移除UI与document监听，撤销Blob URL并清空状态/草稿。异步结果用代次检查，销毁、离开、隐藏或取消后的尚未提交结果不写文件。

## 4. 如何使用

1. 打开“小盆栽”，初始蕨叶水分60、明亮位置、成长0。页面说明所有游戏规则。
2. 点击“浇水（+25，最多100）”；用“光照位置”选择明亮窗边或散光角落。状态和照看历史更新。
3. 要冻结时点击“暂停生长与水分”，回来后点击“继续生长（不补暂停时间）”。“刷新本地经过时间”可主动结算，不需等10秒。
4. 换植物先选“新盆栽种类”，勾选“确认替换当前盆栽”，点击“建立所选新盆栽”。这会明确重置当前记录；建议先保存旧存档。
5. 点击“保存存档JSON副本”另存。恢复时通过“导入存档文件”选择JSON：先严格校验并放入草稿，点击“恢复草稿（替换当前盆栽）”才真正恢复。也可粘贴64KiB以内JSON草稿；“把当前状态放入草稿”供检查/复制，不等于已写磁盘。
6. 点击“保存完整盆栽PNG副本”，选择新的文件名。存档和图片都拒绝覆盖已有目标。切换功能前自行保存存档；没有隐式自动保存。

## 5. 使用产出与可复现例子

建立多肉→浇水→暂停→导出JSON。初始水分60，在同一注入时刻浇水后85，再浇水100，再浇水仍100。恢复这个暂停档后跨一天仍保留多肉、成长阶段、原水分、全部当前保留的照看记录与暂停状态。真实操作之间会经过少量毫秒，因此界面保留一位小数，内部数值可能略小于85/100，不假装真实动作同时发生。

跨日计时例：本地时钟0新建蕨叶，10小时结算后水分40、成长10小时。此时暂停，到34小时仍为水分40、成长10小时、幼芽。34小时继续，到35小时为水分38、成长11小时。24小时暂停间隔没有补算。未暂停档离开24小时后返回则一次结算成水分12、成长24小时、舒展。

光照例：新建60水分的盆栽立即换到散光，24小时后水分12，成长12有效小时，仍幼芽。未照看一万天后水分0、成长30有效小时、舒展，因为初始60水分只支持30小时湿润成长，不能把一万天全部算为成长。

JSON例文件名 `plant-flower-archive-copy.json`；PNG例 `plant-flower-copy.png`。图片800×600包含程序花朵/花苞、完整花盆、窗景、桌面和水分条；成熟小花48小时阶段开始出现花瓣。PNG不拍摄桌面、当前应用窗口或用户其他内容。
