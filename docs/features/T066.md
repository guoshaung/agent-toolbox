# T066 下载地址续传预检

## 1. 功能内容

在功能工作台选择「工具 / 网络诊断与接口验证 / 下载地址续传预检」，输入一个 HTTP/HTTPS 下载地址。先校验并列出标准化目标、主机、端口、HTTP明文/严格HTTPS、两探针固定请求头、次数和期限；用户另行确认才发送最多 HEAD 一次及预先计划的 GET `Range: bytes=0-0` 一次。固定 `Accept-Encoding: identity`，不下载保存文件，不继承浏览器登录状态，不带认证/Cookie/Referer，不使用隐式系统代理，不跳转/重试/修改系统网络设置。

输出本次单字节 Range 判定、HEAD可用资源长度、Content-Range总长度、服务器声明MIME类型及来源、两探针完整审计。HEAD 200 的长度才作为资源长度；HEAD 405/501仍可进行计划中第二探针，不把错误页长度当文件长度，也不是自动改方法重试。其它 HEAD 非2xx状态、跳转或运输失败停止，第二项明确未运行。不存在响应时长度/类型显示未知，不用0假装已测。

## 2. 为什么需要

`Accept-Ranges: bytes` 只是服务器声明，部分下载链接实际忽略 Range、返回200；另有地址须登录、重定向，或 HEAD 和 GET 描述不一致。本工具把声明与实际请求证据分开，帮助用户在长下载前识别当前接口行为。只有完整可靠的206单字节响应才通过，不能将长度不明、失败或返回普通200误报为可续传。现有API请求台用于通用编辑请求，netlog观察流量，本项提供固定探针与判定，不扩展为下载器或抓包台。

结果只证明这次最小区间响应，不能保证将来断点恢复、大偏移请求、对象身份/完整性、权限、稳定性、速度或浏览器下载成功。单字节资源会收到该全部1字节，但不写下载文件；一般资源只计数最小体，不保留字节。MIME来自声明而不是读文件鉴定，未知时明确未知。

## 3. 实现方式与边界

仅自有 `features/T066/host.cjs` 使用Node内置HTTP/HTTPS/TLS/URL/crypto；可信生产 `features.callHost('T066','plan'/'run',payload)` 桥加载已安装固定模块。`plan`纯校验不请求；`run`重新校验 URL/confirmed/jobID，按sender只允许一个任务、每窗口128个已用ID、最多32sender，重复ID拒绝。生命周期取消、窗口destroy、显式取消与期限销毁请求和socket，待运行项保留未运行原因；系统OS DNS不能实际终止，但晚回调无法继续已销毁请求，晚结果票据隔离。没有用户传CA/脚本/请求头/任意方法/文件路径入口。

输入≤2048 UTF-8字节，一个无账号密码的HTTP/HTTPS URL；域名IDNA标准化，允许 localhost 与有效IP，拒绝空白/control/backslash、广播/未指定/组播目标；片段删除，查询保留并发送/进入报告。URL标准化依Node WHATWG语义。最多2个串行请求，HEAD和GET均agent:false / Connection:close，不自动跟Location、不重试、不因HEAD失败回退；HTTPS `rejectUnauthorized:true`、独立hostname/IP匹配、TLS1.2–1.3。HEAD2xx/405/501才发第二探针；HEAD非200的元数据不能作为资源长度或跨请求对象一致性依据。

每请求含 DNS/TCP/TLS/响应头/单字节体至完整结束最多5秒，全批12秒，响应头≤16KiB/128项、信息响应≤3次、观察socket.bytesRead≤64KiB。仅保留 Content-Length整数、规范化MIME（丢弃参数）、Content-Range数值结构、Accept-Ranges bytes/none/absent/other、identity/non_identity编码分类、ETag SHA256指纹。原ETag/任意响应头/文件名/Set-Cookie/正文/内部异常均不导出；长度必须十进制非负安全整数，相关字段重复拒绝。ETag仅比较两次所见指纹是否改变，不是认证/完整性保证，不使用If-Range，也不做条件下载。

Range200无论声明/头错误都判 `unsupported/RANGE_IGNORED_200`，收到头立即销毁，不应用读取正文。Range206须满足：有效 `bytes 0-0/正总长度`；Content-Length若有必须1；identity编码；体计数恰好1且完整end，截断/超量/超时拒；HEAD200若有长度须等于range总长度，HEAD200编码/MIME/ETag（两边均有时）发生冲突即阻止支持。允许chunked206但也必须恰1且完整结束；未知总长度 `bytes 0-0/*` 不在本实现可验证域。Range416 `bytes */0`且HEAD200长度0 => `not_applicable/EMPTY_RESOURCE`，正长度416或其它状态无法确认；Range3xx仅记录状态，不跟随Location。206在读体前拒绝错误区间/长度/编码，chunk超出剩余1字节时仅标bodyOverflow，不缓存chunk或累加超过1。bodyBytesCounted是应用计数，bodyComplete对不读取的HEAD/200等为false，不代表网络从未收到字节。底层初始缓冲/服务器在途发送可超过1字节，socket观察预算不等于整个传输字节保证。

官方主来源：[RFC9110 Range](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)、[Content-Range](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.4)、[Accept-Ranges](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.5)、[206](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7)、[Node20.18.3 HTTP](https://nodejs.org/download/release/v20.18.3/docs/api/http.html)、[HTTPS](https://nodejs.org/download/release/v20.18.3/docs/api/https.html)、[TLS](https://nodejs.org/download/release/v20.18.3/docs/api/tls.html)。本MVP保守验收子集，不声称涵盖多区间、完整HTTP一致性或支持所有RFC合法表示。

## 4. 如何使用

1. 输入原始下载URL。校验输入并展示探针计划，核对实际目标、端口、HEAD+Range方法、最大2次和期限；这一步没有网络请求。本机示例按钮也只填文本。
2. 点击「确认目标，运行有限续传预检」。未验证通过时看两项状态/code，而不是把Accept-Ranges或GET请求中的Range当证据。需要重定向或登录则本工具停止，请自己获取无需登录的最终地址再重新计划；不自动继续。
3. 「取消当前任务」停止当前连接和后续探针，报告保留已测与未测项。隐藏/切走工具停止任务，切回来不会自动重跑或接纳晚结果。编辑/清除输入废弃旧目标、计划、结果与导出预览。切换具体功能销毁面板；输入/结果仅内存，没有feature配置草稿或URL持久化。
4. 完整JSON或MD先预览，确认URL查询是否适合分享，再保存已预览的新副本。依赖生产 `saveTextSupportsCopyOnly=true`；缺能力阻止写出。saveText明确传copyOnly:true，已有目标独占创建拒绝；仅ok===true显示成功，canceled单独提示，false/undefined/throw保留预览并显示失败，不回显内部路径。完整输出≤2MiB，超限拒绝、不截断。

## 6. 具体可重现例子

本机127.0.0.1:8080 `/ignore`：HEAD200 `Content-Length:1000`、`Accept-Ranges:bytes`；GET无视Range仍200并准备完整1000字节。填 `http://127.0.0.1:8080/ignore`→校验（零请求）→另行确认。实际最多HEAD和GET两次，Range status200、bodyBytesCounted0、bodyComplete false，verdict unsupported/RANGE_IGNORED_200；不会因声明或发出的Range误判。收到200头便销毁，服务器可能已将部分数据放入缓冲/网络，不声称实际总接收0字节。

同服务 `/file`：HEAD200长度1000/MIME application/octet-stream/ETag固定；GET206 `Content-Range:bytes 0-0/1000`、`Content-Length:1`，发送一个字节并结束。报告supported/SINGLE_BYTE_RANGE_VERIFIED，headLength/rangeTotal均1000，GET计数1/完整true，但原字节和原ETag未导出。若HEAD长度改1001则inconsistent/RANGE_TOTAL_HEAD_MISMATCH；GET区间改1-1则在头阶段拒绝；合法头但发送chunked两字节则RANGE_BODY_LIMIT且overflow true、计数≤1，不生成伪成功。

`/bodyStall`返回有效206头但不发字节/不结束，约5秒REQUEST_TIMEOUT，bodyComplete false、verdict timed_out并销毁连接。主动取消同样保留HEAD completed与range canceled；若取消待HEAD，range not_run并保留原因。`/empty` HEAD200长度0、GET416 bytes */0，则not_applicable/EMPTY_RESOURCE；不是误报正文件可续传。HEAD405后合法206会按原计划测试，错误页长度不参与总长度比较。HTTPS证书过期或名称不符仅一次HEAD尝试，无GET/HTTP回退。
