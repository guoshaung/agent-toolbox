# T044 音频响度统一

## 1. 功能内容和适用范围

选择一批本机 PCM WAV，设定目标 LUFS 与真峰值上限。先真实测量每个源，显示原 LUFS/真峰值及处理计划，再经明确操作进行第二遍 `loudnorm`、读取成品并重新测量。只有成品响度在目标 ±1LUFS、复测真峰值不超过用户上限，才保留为成功 WAV。原音频和实际成品均有本地手动试听控件；核对全部成功/失败行后，用原生对话框创建完整的新目录，包含所有成功 WAV 和完整 JSON 报告。

首版为 Windows 本机驱动器普通文件路径，明确依赖用户外部安装且自行信任的 **FFmpeg/FFprobe 6.x**（本次验收 6.1）；不下载、不扫描 PATH、不调用音乐平台。固定默认安装目录 `C:\ruanjian\ffmpeg\bin`，也可通过原生目录对话框选择。固定两个名称 `ffmpeg.exe`/`ffprobe.exe`，先显示查询计划，再确认执行固定版本、loudnorm 滤镜和 PCM16 编码器查询。非 Windows、链接/junction/UNC/不规范路径、非 6.x 或能力缺失都明确拒绝，不能据此宣称 macOS/Linux 可用。

一次 1–8 WAV，每文件至 128MiB，总至 256MiB；每段 3–600 秒，累计至 1800 秒，预计输出和实际全部 WAV 至 256MiB、单输出严格低于 128MiB。支持普通 RIFF/WAVE 的有符号 PCM16/24/32 与 IEEE float32，1/2 声道；采样率 8/11.025/12/16/22.05/24/32/44.1/48/88.2/96kHz，允许有限的 PCM/float extensible GUID。只允许一个 fmt 和一个整帧 data 块，RIFF 声明长度必须等于真实长度；RF64、压缩 WAV、8bit、浮点64、多 data、其他声道/率或超限拒绝。文件/时长/编码约束同时生效，例如高采样率双声道 float32 的 10 分钟源可能先超 128MiB，不能绕过体积限制。

目标 -30 至 -9 LUFS，真峰值 -8 至 -1 dBTP，步长 0.1；实际滤镜峰值另留 0.2dB 余量，LRA 目标固定 11，单声道 `dual_mono=false`。输出固定 48kHz PCM16，保留原声道数；会改变采样率/位深并可能使用动态处理，不承诺无损、音质主观提升或所有素材都能同时满足两项目标。

## 2. 为什么需要

录音拼接或连续播放时，不同段的整体响度和峰值可能相差很大。把音量滑块设成相同值，或者只复制第一次滤镜打印的预计输出值，都不能证明最终文件一致。这里保留源测量、第二遍真实参数/实际模式、最终文件重新读取的测量与误差，让用户看到哪些段已经达标，哪些段因静音、格式、峰值或其他原因失败；失败段不生成伪达标副本。

LUFS 衡量这段音频的整体响度，dBTP 是滤镜估计的真峰值，二者并非同一指标。工具对整段处理，不裁切、不去静音、不去噪、不生成朗读或转写；也不是 EBU 设备校准或听觉健康建议。播放音量由用户和系统控制，不自动播放。

## 3. 实现方式和安全边界

已查阅 [FFmpeg 官方 loudnorm 文档](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)：它支持文件双遍、原测参数、目标真峰值和线性/动态模式；线性条件不满足时可以回退动态，动态真峰值处理涉及更高内部采样率，因此输出明确指定 `-ar 48000`。没有把 `linear=true` 写成“实际总是线性”。报告的 `secondPass.normalization_type` 是真实第二遍返回值。第一遍 `output_*` 是该次滤镜的预估/丢弃输出测量，最终验收只使用另一次打开**实际写出的 WAV** 所得 `outputMeasurement.input_i/input_tp`。

`model.mjs` 独立校验有限数值、RIFF/PCM 字段、FFprobe 与结构的一致性、loudnorm 的真实 JSON 和最终标准。RIFF 不将整个源放入 renderer：Host 按块读取有限头，检查总长度、fmt、data/帧数/精确时长；FFprobe 强制 `-f wav`，唯一音轨的编码、声道、采样率和时长须与字节结构相符。全静音的 `-inf`、NaN、不合法/缺失测量或超出 loudnorm 原测参数域都拒绝，不填造数字。

`host.cjs` 的进程/路径/作业基础私有复制自 T043；运行时只引用本 ID 的 model，没有跨功能依赖。通过 a80 公共可信 Feature Host 桥加载本固定模块；renderer 只发来源/计划/结果 token 和有限数值，不传任意路径、命令、argv、滤镜、临时根或输出名称。原生源对话框明确允许本次读取，固定 `shell:false/windowsHide:true`、收紧环境、`-nostdin`、音频处理线程2/滤镜线程1、`-protocol_whitelist file`、强制 wav，不访问网络或外部轨道。源/引擎/输出均校验普通文件及路径祖先，无 symlink/junction。

每个 sender 独立来源/引擎/计划/结果；作业在首个 await 前占位，重复 jobId 拒绝，提前取消意图保留，同一 sender 不能在进程未 close 时重新进入。最多 16 sender、各 512 个已见作业/窗口、32 个提前取消意图、全 Host 至4子进程，串行逐文件处理。版本/能力/FFprobe 单进程最长5秒，原测/复测45秒、第二遍60秒；测量与归一化各有300秒批次 deadline，所有日志累计限128KiB。输出 poll/`-fs` 和最终大小/格式/时长/测值三重校验；被截断或不达标项不作为成功文件。

源在选择、测量、处理和保存关键边界进行 SHA-256 + size/mtime/ctime/dev/ino 核对，按256KiB块读且可取消。处理只写自身 `T044-*` 临时目录中的固定 `normalized-NN.wav`；输出原生选择新目录后 `mkdir` 独占，文件 `COPYFILE_EXCL`、报告 `wx`，再按 SHA 核验拷贝并复核源。该用途由本固定 Host 提供有限大媒体新目录写入，不假定公共 bundle 的2MiB/10MiB预算可以存这批媒体，未修改公共接口。失败时仅清理本次新目录且检查身份/未知条目；不能安全清理则返回 `partialPath`，不假称成功或删陌生文件。临时清理发现未知条目/身份错误返回 `TEMP_CLEANUP_FAILED` 和路径，保留状态供重试；不静默丢掉清理错误。

取消会请求 kill，必须等实际 close 才解除 busy/清理；5秒内未观察到 close 则返回 `PROCESS_TERMINATION_PENDING`，仍不允许新作业，等 close 后完成清理，不声称 kill 请求就是进程已终止。临时结果闲置15分钟后请求清理，忙作业延后、进程未关闭先等待 close；不承诺断电/崩溃事务或安全擦除。源同时被他人修改的检查是前后指纹/身份核对，并非文件系统快照锁。

## 4. 使用方法和可复现例子

1. 点击“查看默认FFmpeg查询计划”或“选择可信FFmpeg目录”。核对真正运行的两个程序路径，再点击“确认运行固定版本与能力查询”；该步未读音频。
2. 点击“选择本机WAV列表”，在原生对话框多选。来源区域列出每个文件名、精确大小和 SHA；原音频控件可手动试听。
3. 保持目标 -16 LUFS、峰值 -1 dBTP，点击“确认测量全部原音频”。此时只做源结构/FFprobe/第一遍测量，不生成输出，表格显示原值、目标、ready/失败原因及完整计划 JSON。
4. 核对原值与处理规则，点击“确认第二遍归一化并复测”。第二遍实际填写第一遍 `measured_I/TP/LRA/thresh` 和 offset，不按目标伪造原测量。结束后逐段试听成功 WAV，核对前后数值、实际模式及所有失败项。预览全部 loadedmetadata 时长一致才能勾核对，再点击“确认全部预览与测量报告”。这个确认是人工核对，不证明每秒都已经听过。
5. 点击“保存完整新目录副本”，在原生对话框核对新目录名/路径（建议 `T044-loudness-copy`），成功后界面显示真实目标。已有源文件、已有文件/目录不能覆盖。可单独另存当前完整 JSON 报告，使用安全文本 copyOnly 接口并只认 `ok===true`。

实际验收例：用本测试原创合成两个20秒 WAV；quiet 是48kHz单声道440Hz、幅度0.025，loud 是48kHz双声道440/660Hz、幅度0.4。第一遍真实得到 **-35.75 / -8.55 LUFS**、**-32.04 / -7.96 dBTP**。目标 -16、上限 -1，第二遍实际均报告 `dynamic`（如实展示），成品复测均 **-15.95 LUFS**，真峰值分别 **-12.23 / -15.31 dBTP**，时长偏差0；符合 ±1 与峰值上限。不是凭 amplitude 推算的假 LUFS。

静音20秒 WAV 与 quiet 混批：静音原测是非有限值，报告 `SILENT_OR_NONFINITE_MEASUREMENT`、输出 null；quiet 实际成功。目录只有 `normalized-02.wav` 与完整报告，仍保留两行、一失败一成功，不静默少交一个文件。另有 float32/44.1kHz双声道和 PCM24/16kHz单声道8秒源实际完成，均输出48kHz PCM16并保持声道。取消例：120秒 WAV 的第二遍进程已启动后，真实鼠标点“取消当前作业”，进程SIGTERM后close，自身临时目录清除，源SHA不变，未生成可保存报告。

输入目标改变会废弃旧计划/结果并停止旧试听，必须重新原测；新源选择、清空、隐藏/离开都停止播放器、移除src/load释放媒体、取消作业并清除本批。返回只恢复操作界面，不自动续播/处理。销毁释放监听器；没有 RAF、配置保存大音频或自动恢复源授权，窗口重载后来源为空。保存报告原生 pending 期间锁输入/清空，不提供虚假的可取消后台 writer；已经开始的原生文件保存可能完成，但晚到回执不会恢复销毁界面。

## 5. 使用后产出

- 完整新目录：每个验收成功的 `normalized-NN.wav`，编号对应输入原顺序；单文件真实48kHz PCM16、保留1/2声道，无压缩编码。源不能覆盖，未通过的输出临时文件删除并保留错误记录。
- `loudness-report.json`：版本1，目标/内部峰值余量/LRA/mono规则、引擎实际版本/能力、精确限额、所有源名/字节/SHA/格式/帧数/时长、第一遍真实测量、第二遍真实测量/模式、输出复测、验证误差/标准、输出大小/SHA、完整成功失败计数、源未变结论、新目录和副本创建口径。单独 JSON 副本保留同样全量计划/结果，不能当 WAV 或工程恢复文件。日志和大音频不塞进配置/公共 JSON请求。

报告≤64KiB；Host请求也受公共64KiB/12层/5000节点限制，所有输出名固定。整个目录WAV总≤256MiB，不通过公共 bundle/Base64大图接口。源名和实际本机目标路径在报告里，分享范围由用户决定。新目录普通失败有身份检查与可见人工核对边界；断电、恶意外部并发替换和 OS/磁盘故障不是跨文件事务保证。
