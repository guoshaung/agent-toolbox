# L045 句法重排沙盘

## 1. 功能内容

学习工作台「语言与表达训练」中的人工句块层级构造练习。用户提供原句/上下文、人工出处、带角色的句块，以及「某块的父节点应当是某块」的目标约束；拖动重排父子关系与同级顺序，查看自己构造的完整树，并主动核对全部已声明约束。

原句、来源名和出处保留独立字段；角色可选主句框架、从句、名词块、动词块、修饰块。它们是用户标注，不由程序自动解析或认证。默认句块ID为M/N/V/C，新增块使用稳定B1…B12 ID；可以编辑文本、角色、实际父节点和约束。M是固定主句框架根，不能拖动或删除。

每个树句块显示ID、人工角色和完整文本。拖动至「挂到某块末尾」会改变父节点，拖到「移到某同级块前」同时明确目标父节点与顺序。移动父块时，其所有子节点随整棵子树保留。另提供父节点下拉、同级前移/后移，以及选择移动块后点击目标区的替代操作，不要求只能用鼠标拖动。

检查结果显示完整树、逐条用户约束的实际/目标父节点、未满足项、人工依据，以及完整JSON/Markdown预览和副本导出。修改任何原句、角色、文本、父节点、排序或约束后旧检查失效，须重新主动检查。

## 2. 为什么需要

读者可能知道从句的含义，却不清楚自己想让它修饰哪一个句块。直接改写原句无法显式呈现层级，也很难区分「父节点挂错」和「词序待讨论」。本功能把用户声明的分析目标与当前构造分开，允许先摆放，再逐项对照；完整原句、出处和人工依据让练习可以复核。

新增能力是显式结构构造和人工约束核对，与AI改写、纠错、翻译或术语问答不同。同级顺序供人工练习，但本版本没有语言学排序评分。只检查声明的父节点约束，不凭字词、角色名或通过数推断句法正确性、语言理解、认知能力或某种语法标准符合程度。

## 3. 实现方式

### 有限树与用户约束

`model.mjs`以稳定ID、人工角色和文本记录句块，单独保存`parents`与`order`。根的父节点为null；每个非根块必须恰有一个已知、非自身的父节点。验证逐节点沿父链走到根，成环、重复、未知节点或缺失记录整份拒绝。排序数组包含每个块恰一次；渲染某父节点的子块时按该数组相对顺序排列，因此移动整棵子树不会隐式重写其内部父关系。

`moveBlock`和`moveSibling`先克隆合法输入，再应用一项移动，重新校验整棵树，成功后才替换当前输入；成环或非法参照会保留之前完整层级。删除有子节点或被用户约束引用的块会明确拒绝，要求先人工移走子块/删除对应约束，避免自动抹除数据。

每条约束是`childId + expectedParentId + basis`，一子块至多一条约束；目标父节点须存在，不能自身、不能为根指定父节点。目标约束本身成环也拒绝，因为不能同时被一棵合法树满足。检查只计算：

```text
satisfied = actualParentId(childId) === expectedParentId
未满足时仅产生kind=parent的一条错误
```

例如用户要求从句C挂在名词块N下，而当前C挂在动词块V下，只报告C的父节点错误；不会再生成词序、角色、语义或未声明的语法错误。角色标签改为动词也不自动判该标签真伪。没有约束时输出`no-declared-constraints`；全部声明满足输出`user-constraints-satisfied`，两者均不证明语法正确。

树使用完整DOM嵌套及连接线，报告另保留全部节点、深度、子ID、边和先序ID。先序展示是人工树的线性阅读顺序，不是自动生成的正确句子；句块也不要求自动覆盖或逐字对齐原句，覆盖是否充分由用户判断。

### 拖放、容量和保存

拖放采用[WHATWG HTML拖放标准](https://html.spec.whatwg.org/multipage/dnd.html#drag-and-drop)的`draggable`、`DragEvent`和`DataTransfer`接口。`dragstart`保存本沙盘专用类型的句块ID，目标在dragenter/dragover取消默认行为，drop取得ID后调用同一纯移动模型。未知ID/根/环均拒绝；不执行用户脚本、外部拖放文件或文本。dragend、输入变更、离开和销毁清除拖动状态/样式。所有用户文本通过文本节点显示，不用innerHTML。

- 1–12个句块，文本非空≤240 Unicode码点；人工角色仅上述5类，根必须标为主句框架。ID为1–12位大写字母/数字/下划线，以字母开头。
- 用户父节点约束最多12条、每子块最多1条；同一目标可被多个子块引用。约束依据≤320码点，空依据明确「未说明」，不伪造来源。
- 原句/上下文≤16000码点，来源名≤160、出处≤320；允许Unicode、原换行和HTML字面字符，拒绝非法控制字符和孤立代理字符。
- 完整输入UTF-8 JSON≤128KiB，完整JSON/Markdown各≤1MiB；任何超限整份拒绝，不部分检查或截断导出。有限12节点树无需长循环、定时器或后台任务。
- 配置只存`schemaVersion:1`完整输入、人工层级、顺序和约束，整个JSON UTF-8≤64KiB。保存前/恢复时重新校验版本、字段、体积和树；不保存派生tree、errors、totals或报告。大型合法输入可检查/导出，但不写配置，关闭只能恢复较早合法输入，UI明确提示。
- 有界配置队列一个在途写和一个最新待写输入，旧回调不能覆盖更新的非法草稿提示。离开后控件/拖放操作忽略；销毁释放当前草稿/报告/DOM，未完成导出响应不能复活界面。没有音频、自动播放、网络、AI或用户代码执行。

导出先检查`saveTextSupportsCopyOnly===true`，传`copyOnly:true`，仅`ok===true`才提示保存成功。生产writer以`wx`拒绝已存在目标；没有副本保护能力则不调用保存。所有产出为新副本，不写回来源，导出内容可能包含用户完整原句及出处，应先预览。

## 4. 使用步骤与可复现例子

1. 打开工作台L045，点击「重置单错误示例」。原句为`The researcher explains the result that we measured.`，出处注明用户自编例句。人工句块：M主句框架、N名词块`the result`、V动词块`explains`、C从句`that we measured`。
2. 当前树是M下有N和V，C在V下。用户K1要求C的父节点为N，依据为「用户声明：从句C修饰名词块N」。点击「检查用户父节点约束」。应恰有一条`kind=parent`错误：C实际V、目标N。树仍完整，无其他自动错误。
3. 拖C树卡片至N的「挂到N末尾」目标；也可直接将「C父节点」下拉改为N，或选择移动块C再点击N目标区。旧报告立即消失。重新检查后未满足0，先序ID为`M → N → C → V`。
4. 拖V到N前的同级前置区，或点「N同级后移」。先序变为`M → V → N → C`，C仍挂在N下；重新检查仍未满足0，同级词序没有被自动评分。移动N到C下应因成环拒绝，原完整树保留。
5. 修改K1目标父节点为V，再检查会只报告C父节点不满足。删除K1后再检查应提示没有声明约束，不称语法正确。添加用户约束时，可编辑子块、目标父节点和人工依据；重复子块或目标约束环应先改正。
6. 完成检查后展开完整JSON/Markdown预览，分别导出到不存在的新文件。刷新窗口应恢复合法输入、树和顺序，报告不恢复，需要重新检查；大于64KiB的完整输入不得声称刷新能恢复。

树形对照：

```text
错误摆放（1条用户父节点错误）   修改后（0条已声明父节点错误）
M                              M
├─ N                           ├─ N
└─ V                           │  └─ C
   └─ C                        └─ V
```

这个示例只验证人工目标关系；它没有完整英语句法分析、句块覆盖证明或专家标注认证。

## 5. 产出

JSON包含schema/model版本、完整输入原句/来源/出处、全部句块文本和角色、原始父关系、完整排序、全部人工约束/依据、完整嵌套树、全部平坦节点/深度/子ID、边、先序ID、逐约束结果、全部父节点错误和口径说明。未声明节点仍在树中，不因缺规则被删除；没有约束的输入保留明确状态。

Markdown给出人工层级先序文本，并嵌入同一完整JSON记录。代码围栏根据原文反引号长度增大，HTML字符转义，避免用户原句成为可执行标签；复核嵌入记录时需要还原实体。JSON/Markdown均包含全部原文及所有12节点，不受屏幕滚动、折叠或当前树焦点影响。

不导出可执行代码或补丁，不读取/改写用户源文件，不把派生报告作为配置草稿回填。输出只证实特定输入下人工父节点约束是否相等；正确语句、恰当词序、真实出处和认知效果仍需人工判断。
