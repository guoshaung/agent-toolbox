# T050 媒体章节标记生成

## 1. 功能内容

选择本地MP4、填写人工标题和整数毫秒起点，严格校验后预览全部章节，再创建真正带章节的媒体副本。使用FFprobe逐条核对标题、起止时间和媒体规格，完整解码；界面提供实际成片逐章跳转和完整章节清单。目标验收：10分钟媒体、0/120/300秒三章实际探测得到三个对应标题和时间。

有限域：MP4、单条H.264/yuv420p 8bit视频、可选单条单/双声道AAC；≤64MiB/600秒、≤1920×1080/60fps、SAR1:1、零开始±1毫秒，无旋转/HDR/章节/字幕/封面/其它数据轨/外部引用。源已有章节整体拒绝，暂不替换或合并。仅Windows本地固定盘普通文件；音频单文件和其它容器暂不支持。产物<65MiB。

1–64章，首章必须0毫秒，其余起点严格递增且小于时长，不重复时间或完全相同标题，不自动排序。标题1–80个Unicode码点且UTF8≤240字节（界面最多80个UTF16单元，更保守）、NFC、无首尾空白/控制/换行/双向控制/未配对代理。正常中文、emoji和#;=、反斜杠安全转义。终点是下一章起点，最后章终点为完整时长。输入、界面及Host计划均拒绝非零首章，避免MP4章节轨把第一点归零的实际时间歧义；不截断媒体，也不擅自调整输入时间。

## 2. 为什么需要

录屏和课程需要可核对的跳转入口。只记录时间或生成标签不能证明媒体章节已写入。本工具先确认清单，再真正写入MP4并探测。固定-c copy只重封装，不为了添加章节重新压缩或缩小视频。播放器章节菜单支持不同，本工具的实际章节按钮提供本机入口，不承诺任意客户端都有章节菜单。

## 3. 实现方式

model纯校验、生成ffmetadata和实际探测对照；私有host通过生产固定Host桥，原生选择可信已装引擎/媒体/新目录，sender绑定opaque token，不接受renderer任意路径、命令、filter或脚本。无跨功能import、新生产依赖、shell、网络或登录态。祖先lstat/realpath拒链接、UNC、设备和特殊路径。安装目录固定ffmpeg.exe/ffprobe.exe，普通文件≤256MiB并保留身份。先展示3次版本/MP4 muxer查询，确认才运行；只接受6.x及实际MP4 muxer。可原生选择自己信任的其它已装目录，示例`C:\ruanjian\ffmpeg\bin`。缺引擎/版本不支持明确拒绝。从[FFmpeg官方下载页](https://ffmpeg.org/download.html)选择Windows构建，本工具不安装。

源只读262KiB分块SHA，确认后ffprobe及有限ISO-BMFF data reference检查，拒外部轨道；固定MOV解码器/file协议、enable_drefs=0/use_absolute_path=0。计划完整列出标题/起止时间、原尺寸音轨、固定argv和期限，不把媒体或章节正文存config。保留报告字段unchapteredPrefixMs，但本支持域只允许其为0。

ffmetadata为UTF8无BOM、TIMEBASE=1/1000、整数START/END。反斜杠/等号/分号/#逐字符转义；标题禁止换行，不会成为新章节指令。格式依据[FFmpeg官方元数据说明](https://ffmpeg.org/ffmpeg-formats.html#Metadata)、[官方map_chapters及stream copy](https://ffmpeg.org/ffmpeg.html#Advanced-options)、[FFprobe官方](https://ffmpeg.org/ffprobe.html)。固定map原视频/可选AAC、-c copy、-map_metadata 0、-map_chapters 1、+faststart及-write_btrt 0，避免重复技术码率盒改变编码配置。标题UTF8预算低于[FFmpeg 6.1官方movenc.c](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n6.1/libavformat/movenc.c)中mov_write_chpl_tag的255字节上限，避免另一种实际章节表示截断标题。音视频不转码，容器布局、muxer技术标签和文件SHA会改变；不承诺任意原元数据或文件字节完全相同。源无其它轨道，不默默丢流。

生成过程固定6个子进程：源probe5秒、重封装30秒、输出probe5秒、FFmpeg -xerror全视频/音轨解码到null60秒、源和输出各一次packet hash15秒；总任务截止130秒，运行前后源SHA/大小/身份/probe核对。输出实际字节/SHA，尺寸、帧率、编码、音轨、时长100毫秒容差，全部实际章节标题和起止时间0.5毫秒容差逐条对照。time_base按分数转换，不把输入直接回写成探测结果。MP4会生成text/bin_data/SubtitleHandler章节数据轨，输出只允许已知生成类型；源仍拒任意数据轨。错误整体失败，不提供假成功可保存产物。

生产运行每次都对源和输出执行固定-c copy framehash，以SHA256核对每个压缩音视频包及DTS/PTS/时长/大小/side-data的有序序列，并对照编码extradata SHA、timebase、视频尺寸/SAR或音频采样/布局。私有packet-proof模块逐块解析并维护每流摘要，不积累全部包数组；每次≤100000包、stdout≤12MiB、未完成行≤1024字节。参数和格式依据[FFmpeg官方framehash说明](https://ffmpeg.org/ffmpeg-formats.html#framehash)，显式-c copy避免其默认原始音视频转换。任何包或配置不一致整体拒绝；这种证据保留原压缩流，不证明容器全部元数据字节不变。

首个await前预留任务/早取消意图，每sender一任务、16sender/4子进程、512调用/窗口、32早取消意图/60秒。源64MiB、临时成片65MiB+ffmetadata32KiB、报告64KiB，普通probe/进程stderr日志128KiB，packet hash stdout另有上述12MiB预算；100毫秒实际文件监控和-fs硬限。kill后观察close才释放槽，5秒未关闭返回pending；晚回调不能恢复旧UI。结果空闲15分钟过期，退出/隐藏/销毁清理。普通读写系统调用不能逐字节硬终止；取消等待有界调用后清理。崩溃/断电可能残留临时文件。

## 4. 如何使用

1. 工作台打开T050，预览默认或原生选择可信引擎目录，核对3条查询后确认运行。
2. 原生选择单个MP4，确认一次只读检查；支持域外明确拒绝。
3. 第一章必须0毫秒，添加行并填写起点/标题。行移动不会自动修正时间，列表须严格递增；非零首章当场提示并禁止计划。预览完整章表与执行计划，再确认生成带章节副本。
4. 实际成片默认静音，可手动取消静音。逐章按钮定位实际探测起点；核对全部标题/时间、画面/声音和报告后勾选确认。
5. 原生保存对话框选择全新目录名称；仅ok===true显示成功，canceled/false/undefined/throw保留预览。已有目录/文件、选回源拒绝。
6. 修改章节即废弃旧结果/跳转按钮/保存资格。取消等待自己的进程close；清除/切换/隐藏/退出停止播放、清除源/草稿/临时成片，返回需重选，不自动恢复。

## 5. 使用后产出

全部人工章节和实际章节（标题、起止毫秒、time_base）、来源/产物SHA与字节、规格、完整解码结果、压缩包与编码配置对照、固定参数与实际成片。每章一按钮，标题按文本渲染，不执行HTML/JS。

新目录两个完整文件：chaptered.mp4、chapter-report.json。报告有输入与实际章表、源/产物SHA、真实尺寸/时长/音轨、限制、argv、预览与copyOnly记录；packetPreservation含实际verified、每流包数/压缩字节/序列SHA与编码配置，报告不包含媒体字节或逐包大数组。标题/媒体未自动做敏感清理，报告包含文件名和实际目标本机路径，分享范围由用户判断。

私有生产Host原生选择新目录，exclusive mkdir、视频COPYFILE_EXCL、报告wx，回读完整SHA/字节并确认源未变。公开bundle每文件2MiB限制不用于冒称能存65MiB媒体。正常失败按创建身份清理；不能确认清理时返回partialPath人工核对，不承诺跨文件崩溃事务。完整验证、Chromium实际metadata/尺寸/时长加载和人工核对通过后才可保存。
