# L002 例题步骤解封

## 功能内容

这是一个无需 AI 的自解释练习工具：把例题拆成若干步骤，每一步先展示提示，让使用者写下自己的推理依据并勾选采用的前提。只有提交非空依据后，才显示该步的参考结果、参考理由和参考前提。

提交时的原始文本会锁定。使用者可以在另一个反思栏补记漏掉的推理、后来理解的条件或自己的其他合理依据。页面提供前提选择差异、完成状态，以及完整练习的 JSON 原始记录和 Markdown 复盘导出。

功能规划对应 `docs/feature-planning/learning.json` 中的 L002；分类为学习，分组为主动学习与理解。

## 为什么需要

阅读答案很容易产生“我知道为什么”的感觉，但这种感觉未必来自完整的推理。把依据写在揭示参考内容之前，可以保留独立思考的证据；把反思另存，可以在复盘时区分“当时知道”与“看完后补上”。

这项功能训练的是步骤依据和条件使用，不是代码默写，也不生成 AI 试题。前提对照仅表示参考选择和使用者选择的差异，不自动断言答案对错。参考解法之外可能存在合理依据。

## 实现方式

组件遵循功能工作台接口：`meta.json` 描述入口，`index.js` 默认导出 `{ id: 'L002', create(root, ctx) }`。同步 `create` 返回生命周期句柄。它通过现有 `h` 工具创建文本节点与表单，不将用户输入写入 HTML。

纯模型在 `model.mjs`，负责例题校验、顺序提交、前提集合比较、不可覆盖的原始记录、独立反思、保存记录恢复和报告生成。界面分为结构化例题编辑器、逐步练习区和结果区；编辑器提供逐字段输入、步骤增删与调整顺序，不要求使用者编写 JSON。

例题包括标题、题目、可选前提池，以及每步的标题、提示、参考结果、参考理由和参考前提。开始练习时复制并校验例题，之后编辑草稿不会改动当前练习的快照。各步参考前提会加入可选池；使用者可以增加其他候选前提。

模型只允许依次提交，不允许跳过未完成步骤或重新提交已完成步骤。非空检查采用 `trim()`，但记录保留原始文本及其首尾空白和换行。反思不会覆盖原始依据。前提选择去重，并生成两种差异：参考中采用而使用者未选的前提，以及使用者另选的前提。

有 `ctx.config` 时，草稿、当前练习、未提交文本和前提选择作为 `schemaVersion: 1` 状态保存在 `features.L002.state`。写入前用 `TextEncoder` 计算完整 JSON 的 UTF-8 字节数，只允许不超过 64KiB（65536 字节）的状态。中文按 UTF-8 字节计量，而不是按字符数估算。

输入保存有 250 毫秒去抖；切走和销毁清理计时器并尝试保存，但仍受同一上限约束。超限不写全局配置，也不覆盖之前的小型记录；界面有独立的持续提示，说明当前内容未保存、关闭后可能恢复旧记录，需完成后导出完整记录或缩减例题。其他进度消息不会覆盖这条提示。完整报告导出不受 64KiB 配置上限限制。

恢复时先检查状态版本和 UTF-8 体积，再解析练习记录。缺少版本号、版本不匹配或超限状态均拒绝恢复并显示原因，不把旧状态自动当成合法的新状态。无配置接口的测试环境仍可在当前页面完成练习。

样式仅作用于 `.feature-l002`，使用既有主题变量和组件容器宽度适配，不修改共享样式、工具注册表或主进程。

## 使用步骤

1. 从功能工作台打开“例题步骤解封”。首次进入可点“开始三步示例”，或“编写自己的例题”。
2. 编写例题时，填写题目和每步的提示、参考结果、参考理由。参考前提每行一条；也可额外填写候选前提。参考前提可为空，步骤至少一条。
3. 点击“开始练习”。练习区只显示题目、当前步骤提示和可选前提，参考结果与理由暂不展示。
4. 写出自己的依据并选择采用的前提。空白文本无法提交；点击“提交依据，解封本步”后，参考内容与原始依据并排显示。
5. 对照未选的参考前提，在反思栏说明漏掉的推理或其他合理依据，随后进入下一步。已经完成的步骤可以通过导航回看。
6. 完成所有步骤后，导出 JSON 或 Markdown。未完成时导出禁用，避免通过报告提前看到后续理由。

“编辑例题”只修改草稿。点击“用此例题开始新练习”会替换当前练习；页面会明确提示先导出需要保留的完整记录。工具只保存最近一次练习，不提供练习历史档案。

## 产出

JSON 报告包含功能标识与报告版本、题目、开始时间、完成步数，以及每一步的原始依据、提交时间、当时采用的前提、参考结果与理由、前提差异和后续反思。反思更新时间与原始提交时间分别记录。

Markdown 报告按步骤列出相同信息，适合放进笔记或交给老师复盘。原始文本逐字保留；其中的 Markdown 语法也按用户文本导出，工具本身不渲染或执行它。

导出调用 `window.toolbox.files.saveText({ content, extension, defaultName, copyOnly: true })`。必须有基础层能力标记 `files.saveTextSupportsCopyOnly`，否则明确提示当前版本缺少防覆盖接口。保存由系统对话框选择位置，防覆盖基础层以新文件写入模式拒绝已有目标；取消或失败均保留练习记录，可再次导出。

## 可复现例子

内置题目是“求解 `2x + 3 = 11` 并验证 x”，共有三步。

| 步骤 | 提交时写的依据 | 建议选择的前提 | 解封后的参考结果 |
|---|---|---|---|
| 消去常数项 | 两边减去 3，保持等式成立。 | 等式两边减去相同的数仍相等 | `2x = 8` |
| 消去系数 | 两边除以 2。 | 等式两边同除非零数仍相等 | `x = 4` |
| 代回检验 | 将 4 代回原式核验。 | 原等式是 `2x + 3 = 11` | `2 × 4 + 3 = 11` |

第二步只选择“同除非零数仍相等”而没有选择“系数 2 不为零”时，页面会列出这一项未选参考前提。随后填写反思“刚才漏掉了除数不能为零”，原始依据仍保持“两边除以 2”，两段文本不会互相覆盖。

完成三步后导出 JSON，`completedSteps` 为 3，`records` 恰有三条，顺序和原始依据与实际提交一致。每一步输入仅空格或换行时，按钮均禁用，参考内容不会揭示。

## 限制

- 仅支持文本例题，1 至 20 步、最多 40 条唯一前提；正文类字段最多 10000 字符，标题最多 200 字符，单条前提最多 300 字符。
- 无 AI、自动判分、公式渲染、图片题、外部题库、多人协作和历史练习档案。使用者应核对自己提供的参考理由。
- 前提差异基于人工定义的字符串集合，不判断推理等价性，也不把未选项直接算作错误。
- 核心练习不需要网络或外部软件；本机配置保存和系统导出依赖应用提供的对应接口。
- 全局配置状态保存上限为 64KiB，包含草稿和练习快照的总量；字段仍合法的大型例题也可能超限。超限练习只在当前页面内保留，切走或关闭不能承诺恢复，需完成后导出完整记录。
- 编辑器可以查看作者输入的参考理由，代码和本机配置也不是保密考试容器；提交门槛用于日常自解释学习。
- 保存的练习恢复失败时会显示错误，当前操作不立即覆盖旧配置；重新开始新练习或编辑后会保存新的状态。
- 已在隐藏的独立 Electron 33.4.11 窗口中，通过生产 preload、功能目录接口和文件写入器跑通三步练习、空白门槛、JSON 导出及 3 条原始记录核对。配置和保存路径使用测试夹具，没有操作原生保存对话框；不构成完整主应用、打包或 macOS 验证。工作台注册及防覆盖接口由基础 PR #14 提供。
