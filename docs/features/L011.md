# L011 指令流水线实验

## 功能内容

在「学习 → 计算机原理交互实验」输入 ADD/LOAD/STORE 序列、寄存器和内存初值，选择是否转发。计算后显示总周期、停顿次数、五级当前占用、当前周期事件与停顿原因、周期末寄存器和内存、完整时序矩阵与最终结果。支持上一/下一周期、点击矩阵周期表头跳转、周期滑块和每700ms自动播放。切走页面自动暂停，返回后可以手动继续。

提供四个会立即计算的示例：LOAD→ADD、独立 ADD、STORE 数据转发、最新生产者。输入编辑会使旧结果失效，防止旧图对应新代码。所有核心计算在本机完成，无AI、编译器、模拟器安装或网络依赖。

## 为什么需要

只看 `LOAD; ADD` 的顺序执行结果无法解释结果在哪个阶段就绪、转发为什么不能消除全部停顿、STORE为何区分基址和数据。这里让学习者把「生产者在哪一级」和「消费者在哪一级需要值」同时放到周期图中，比较同一程序开启/关闭转发的代价，并保留可以复核的规则与轨迹。它补充现有代码练习的微体系结构时序能力。

## 实现方式与时序约定

`model.mjs`负责语法解析、逐周期推进和报告；`index.js`用公共`h`创建界面并处理输入、导出、保存和生命周期；`meta.json`供功能工作台发现；`style.css`仅作用于L011。

模型版本为`five-stage-v1`，导出与保存状态`schemaVersion:1`。

- 固定 IF（取指）、ID（译码/读寄存器）、EX（计算）、MEM（数据访问）、WB（写回）。每周期发射最多一条，顺序执行。IF从C1开始；单条指令5周期，无停顿的N条共N+4周期。STORE也经过WB，但不写寄存器。
- 独立指令/数据存储器，无结构冒险。无分支、缓存、变长延迟、预测、乱序或中断。只模拟寄存器数据冒险；顺序MEM天然使后续LOAD能看到前面的STORE。
- 每周期WB先写回，ID后读，故**WB与ID在同一周期时ID可以读取新值**。关闭转发时全部源（包括STORE数据）在ID等待，任何仍处于EX或MEM的最近生产者都让消费者停顿。
- ADD在EX末生成值，后续周期可MEM→EX或WB→EX转发；LOAD在MEM末生成值，只能从下一周期WB转发，**不能向同周期EX转发**。开启转发时，ID发现其下一周期EX需要的最近生产者为当前EX的LOAD，冻结IF/ID并向EX插入一周期空泡。
- ADD两源、LOAD基址、STORE基址均在EX使用。STORE数据最终在MEM使用：在EX尝试MEM→EX/WB→EX刷新并锁存；若最近值来自当周期MEM的LOAD则等待，下一周期由WB→MEM提供；在MEM也允许WB→MEM刷新。因此紧邻LOAD→STORE**只依赖数据时零停顿**，依赖基址时一次停顿；隔一条指令的LOAD数据必须在STORE EX从WB锁存，不能等生产者退出流水线后再读取旧值。
- 转发和停顿总是选择最近的较早同寄存器生产者。较旧WB值不能越过较新LOAD。R0恒零，写R0的ADD/LOAD仍运行五级，但不写回、不构成寄存器依赖。
- 图表示该周期各级占用；事件、寄存器和内存表示该周期完成WB/MEM后的状态。`ID*`为本周期消费者停顿，IF同时冻结；`.`为空。矩阵重复IF是冻结，不是第二次取指。仅计发生数据冒险的周期，不把流水线填充/排空算作停顿。
- 数据使用JavaScript安全整数，不模拟32位溢出；超出安全整数报错。内存地址是0–255的**字索引**，未定义字为0，不是字节寻址。

语法如下，大小写不敏感，支持空行、`#`或`//`指令注释；内存初值支持`#`注释。

```text
ADD R1, R2, R3       # R1 = R2 + R3
LOAD R4, [R0+3]      # R4 = M[R0 + 3]
STORE R4, [R2-1]     # M[R2 - 1] = R4
```

只有R0–R7，偏移是十进制整数，可省略。内存初值一行一个`地址=整数`，地址不能重复。限制1–40条指令，指令文本10000字符、内存文本5000字符；无隐式截断。执行途中地址越界或整数溢出会拒绝整次计算，提示发生周期/指令或结果类型。

## 使用步骤

1. 打开功能工作台，进入「指令流水线实验」。点击一个示例，或自行输入序列。
2. 设置R1–R7初值和内存初值。R0固定0不可编辑。选择「开启转发」，点击「计算流水线」。
3. 用「下一周期」或点击C3表头，查看当前五级占用、停顿原因和转发来源。滑块可以跳转，自动播放到末周期会停止。
4. 关闭转发，再计算，比较总周期和ID*位置。输入、初值或开关编辑后必须重新计算。
5. 导出完整JSON供程序复核，或导出Markdown供阅读；选用新文件名。导出取消或失败不会清空实验。

## 产出与保存范围

JSON包装含`feature:L011`、`schemaVersion:1`、`modelVersion`、导出时间、当前输入草稿，以及成功计算后完整`result`。结果包含声明规则、初值、解析指令、每周期占用/事件/停顿/寄存器/内存、矩阵、总周期和最终状态。未计算或输入非法时仍可导出JSON草稿，此时`result:null`。Markdown包含模型规则、初值、程序、完整时序表、周期原因和最终状态，只在计算成功后提供。

两种导出调用公共`files.saveText`并强制`copyOnly:true`，能力不足时明确拒绝；主进程以独占新建方式拒绝任何已有目标文件。导出不会覆盖已有文件。JSON可供检查或手动重新输入，本版没有文件导入按钮。

本机配置只保存输入、转发开关、初值、查看位置和是否计算，不保存整条周期轨迹。每次写前用`TextEncoder`计算JSON UTF8字节数，必须不超过64KiB；超限时不写全局配置并提示导出完整JSON，关闭后只能恢复较早保存输入。恢复先验证版本与体积，计算过的实验按当前声明模型重新计算后恢复周期位置。输入保存失败会提示；不承诺磁盘故障时恢复。切走暂停播放并立即保存，销毁清理播放/延迟保存计时器与DOM。

## 可复现的具体例子

### 验收：LOAD→直接ADD消费者只停顿一次

点击「LOAD→ADD 示例」会设置以下输入并计算：R3=2，其他初值0，内存`0=10`，转发默认开。

```text
LOAD R1, [R0]
ADD R2, R1, R3
```

预期总周期7，停顿1，最终R1=10、R2=12。C3为LOAD的EX与消费者的ID*；C4为LOAD的MEM、ADD的ID、EX空泡；C5 LOAD在WB把10转发到ADD的EX。

| 转发开 | C1 | C2 | C3 | C4 | C5 | C6 | C7 |
|---|---|---|---|---|---|---|---|
| I1 LOAD | IF | ID | EX | MEM | WB | . | . |
| I2 ADD | . | IF | ID* | ID | EX | MEM | WB |

取消「开启转发」，点击「计算流水线」。预期8周期、2次停顿：ADD在C3/C4等待，C5 ID读到同周期WB的新值，C6进入EX，C8 WB。

| 转发关 | C1 | C2 | C3 | C4 | C5 | C6 | C7 | C8 |
|---|---|---|---|---|---|---|---|---|
| I1 LOAD | IF | ID | EX | MEM | WB | . | . | . |
| I2 ADD | . | IF | ID* | ID* | ID | EX | MEM | WB |

### 验收：独立ADD无停顿

点击「独立 ADD 示例」：LOAD仍写R1，第二条为`ADD R2,R3,R4`，R3=2、R4=3。开/关转发都6周期、0停顿、R2=5，ADD的矩阵为`. IF ID EX MEM WB`。

### STORE数据与基址的时机差异

开启转发，点击「STORE 数据转发示例」：`LOAD R1,[R0]; STORE R1,[R0+1]; LOAD R2,[R0+1]`，内存0=10。预期7周期、0停顿、内存1=10、R2=10；C5有WB→MEM事件。删去第三条再算，预期6周期0停顿。

把输入改为`LOAD R1,[R0]; STORE R2,[R1]`，R2初值9，内存0=10。预期7周期、1停顿，C3的原因是STORE基址R1要在EX用；最终内存10=9。关闭转发后8周期2停顿。另可输入`LOAD R1,[R0]; ADD R3,R0,R0; STORE R1,[R0+1]`，开启转发时7周期0停顿，C5显示WB→EX刷新STORE数据。

### 最新生产者不能读旧值

点击「最新生产者示例」：`ADD R1,R2,R3; LOAD R1,[R0]; ADD R4,R1,R1`，R2=2、R3=3，内存0=10。开转发8周期1停顿、关转发9周期2停顿；两者最终R4=20，不能采用首条ADD的旧值5算成10。
