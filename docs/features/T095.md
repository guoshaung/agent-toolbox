# T095 浏览器书签整理迁移

## 1. 功能内容

添加1–10份本地浏览器导出的Netscape书签HTML文件，或把HTML粘贴为一个独立来源。生成预览后，按来源保留目录层级，显示输入、保留、去重删除、未迁移数量、目录数和最大目录深度，逐条展示标题、精确URL、原/新目录路径及处理原因。每页最多50条，可按保留/未迁移/去重删除过滤；分页不会缩减导出。

每个来源有自己的根目录，默认`S1 · Chrome.html`、`S2 · Firefox.html`等，原本同名的“收藏”目录不会被合并。通过目录ID选择器明确设置来源根或内部目录重命名，预览显示原/新路径。默认不去重；用户可以选择HTML实体解码后的精确URL字符串去重，保留来源顺序中最先出现的链接，每条被删除链接仍在完整JSON报告中追溯来源、路径和保留链接ID。

保存前需核对报告。导出标准Netscape书签HTML新副本和完整JSON迁移报告新副本；不会修改浏览器配置、原导出文件或任何现有目标。不读取账号/登录态，也不访问书签链接。

## 2. 为什么需要

多个浏览器导出的目录常有相同名称，直接导入容易混淆来源；URL看起来相似也可能具有不同query或fragment语义。本模块用来源根和稳定目录ID保留身份，让重命名、重复处理及丢弃项目都能在保存之前核对。输入链接数始终等于保留数+去重删除数+未迁移数。

书签日期、图标、标签、快捷字和HTML头部标题并不在首版迁移范围。它们逐来源按字段记录不迁移数量，用户明确确认后才允许导出。未知结构不能靠猜测处理：遇到描述标签、资源/脚本标签、嵌套标题或坏层级，整个预览阻止并给出来源编号/名称及错误。

## 3. 实现方式与输入规则

`meta.json`符合工作台发现契约；`index.js`使用既有`h()`渲染文本、文件输入、规则、目录重命名和分页；`model.mjs`实现本功能有限Netscape语法、结构校验、不可变迁移计划和HTML/JSON导出。没有新依赖或运行时跨功能依赖。生产输入解析器直接处理字符串，不创建HTML文档，因此不执行脚本、不触发事件、不加载图片/iframe或外部DTD。用户数据在界面始终作为文本，不用innerHTML，不创建可点击URL。

| 输入/处理 | 规则 |
| --- | --- |
| 来源 | 1–10份，所有来源UTF-8字节总量≤1 MiB。文件必须严格UTF-8，可有BOM；文件集合一批读取成功后才追加，坏文件不会部分追加。粘贴内容点击“添加”后才进入来源集合。来源名1–120码点，不含控制字符/非法Unicode。 |
| 层级和数量 | 合计≤5000链接、≤5000原目录，另有最多10个来源根。迁移目录最多20层，包含来源根，即原输入最多19层内部目录；更深输入拒绝，不自动扁平化。空目录和同名兄弟目录保留，ID不同。单目录标题最多120码点，链接标题最多1000码点；超限拒绝而非截断。 |
| 支持结构 | 可选Netscape DOCTYPE、注释、META/TITLE/H1头部，完整根DL，DT/H3后接DL表示目录，DT/A表示链接，可选p分隔及DT闭合；标签名大小写不敏感，属性可双引号/单引号/无引号。 |
| 未识别结构 | 不支持HTML/HEAD/BODY包装、DD描述、标题内嵌套标签、脚本/图片/iframe等资源标签、外部DTD、缺HREF、重复属性、孤立DL、缺闭合或条目外非空文字；来源整体阻止，不静默丢失。有限语法并不声称兼容所有浏览器扩展字段或任意网页HTML。 |
| 实体 | 支持amp/lt/gt/quot及其HTML标准大写形式、apos、nbsp，有分号的十进制/十六进制Unicode数字实体（x/X）；未知命名实体、坏数字实体、零值/孤立代理项/越界Unicode拒绝。裸`&`按文本保留；不猜测无分号实体语义。 |
| URL | 只输出HTTP/HTTPS绝对URL，其他scheme（javascript/data/file/mailto/ftp等）、相对URL、空白/控制字符或无效URL逐条列为未迁移。以URL对象检查结构，保留原始解码字符串，不用URL对象序列化替换输入。 |
| 重复 | 用户勾选才删除精确URL重复，不修改host大小写、百分号拼写、query顺序、fragment或未知参数。即便同URL标题不同也按明确URL规则处理，原标题/位置保留在报告。默认全部保留并显示重复组。 |
| 重命名 | 明确选目录ID、输入1–120码点非空新名、点击应用，再重新生成预览。名字不去首尾空白，错误输入拒绝；来源根重命名后仍须唯一。内部同名目录不合并，允许保留同名身份。可撤销所选规则。 |
| 有损事项 | 非HTTP(S)等未迁移URL逐条记录原因；仅保留目录/链接标题与URL，所有其他属性和头部TITLE/H1按字段数量报告不迁移。报告有任何这类事项时，默认禁用导出，需核对、勾选确认并重新预览。注释/p/DT只是格式结构，不作为书签内容。 |

JSON报告的`folders`字典包含目录ID、来源ID、parentId、originalTitle与当前title。每条输入链接，无论保留或删除，都有`originalPathIds/outputPathIds`完整ID链，配合字典可重建原/新可读路径；同名目录也可凭ID区分。这比为每条深层链接重复存整段路径文本更有界。报告另含每来源数量/目录数/深度、精确重复URL组、重命名清单、处理规则、原来源文本UTF-16偏移。HTML只包含保留链接，删除后变空的目录仍保留。

导出标题和HREF分别转义`& < > " '`，只输出固定META/TITLE/H1、DL/DT/H3/A/p结构，不复制事件、图标或其它属性。HTML副本≤4 MiB，JSON报告≤8 MiB，超限拒绝不截断。读取、分段token扫描、迁移和序列化有异步检查点并可取消；文件读取只能等待底层返回后忽略取消结果。规则/来源更改废弃旧结果，忙碌时禁用并发输入；原生另存阶段应用内取消禁用，应在对话框取消。

保存检查`files.saveTextSupportsCopyOnly===true`并每次调用`saveText({content,extension:'html'或'json',defaultName,copyOnly:true})`，原生独占创建拒绝已有目标。仅`ok===true`成功；取消、false/字符串ok/空响应和异常均如实反馈。暂停取消当前处理，来源和已生成报告在本模块内存保留；重新进入不自动读取或写文件。销毁移除监听、清空所有来源/规则/文本；没有自动保存或浏览器账号访问。

## 4. 如何使用

1. 先在浏览器自行导出书签HTML。在“工具 → 隐私与数据迁移”打开本功能，用多文件输入追加来源，或填写来源名、粘贴HTML并点“添加粘贴内容为独立来源”。来源队列显示编号和字节量。
2. 默认不去重。点击“生成迁移预览”，核对各来源根、目录深度和数量等式；用状态过滤查看未迁移链接、去重删除链接。展开“各来源数量、所有未迁移元数据字段与重命名规则”，读取完整字段删除说明。
3. 需要重命名时，选稳定目录ID（来源根也可选），填新名，点应用；需要去重时明确勾选“精确URL去重”。每次规则变更旧预览和保存按钮都会失效，必须重新生成。
4. 原生浏览器导出通常带日期/图标/头部标题，所以首版需要明确确认这些元数据不迁移。核对后勾选“我已核对报告……”并重新生成预览；未知标签/结构错误不能靠此确认绕过。
5. 核对输入=保留+去重删除+未迁移和每项路径后，分别点击“保存标准书签HTML副本”和“保存完整JSON迁移报告副本”，在另存对话框核对最终路径，选择尚不存在的新文件。
6. 如需导入目标浏览器，由用户在浏览器中选择导出的HTML副本。本功能不自动打开链接、修改浏览器或执行导入。原数据和JSON报告自行保留。

## 5. 使用后产出与具体例子

直接点“载入两个同名目录示例”。Chrome.html与Firefox.html各有一个“收藏”目录和两条链接：共同URL`https://example.com/?q=1&lang=zh#top`，以及各自`https://example.org/chrome`/`https://example.org/firefox`专属URL。点击生成，预览`输入4 = 保留4 + 去重删除0 + 未迁移0`，目录4个（含来源根）、深度2、重复URL1组。由于输入含头部元数据，先核对并勾选确认，再重新生成。

| 目录身份 | 原/默认新路径 | 保留链接 |
| --- | --- | --- |
| S1-F1 | S1 · Chrome.html / 收藏 | 共同链接、chrome专属 |
| S2-F1 | S2 · Firefox.html / 收藏 | 共同链接、firefox专属 |

将目录S2-F1改名“Firefox收藏”，重新预览，第二条路径变为`S2 · Firefox.html / Firefox收藏`，原路径依然展示和记录。不改来源1。勾选精确URL去重再生成，显示`输入4 = 保留3 + 去重删除1 + 未迁移0`。来源2共同链接记录`status:duplicateRemoved,keptId:S1-L1`及`originalPathIds:[S2,S2-F1]`，来源2专属仍保留。

导出的HTML重解析应得到3条链接，完整JSON报告有4个输入链接记录并满足数量等式。将共同URL的fragment改为`#other`或者query顺序改为`?lang=zh&q=1`就不再是精确重复，不会偷偷忽略参数。`javascript:alert(1)`会成为未迁移条目并要求确认，不进入HTML。源HTML中的`<IMG>`/`<DD>`结构则阻止整个迁移，不输出一个貌似成功的部分文件。
