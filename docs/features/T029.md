# T029 Excel 表格数据验收

## 1. 功能内容

本地选择一个 XLSX、一个工作表与必填列，逐坐标检查文件已保存的单元格错误、公式缺缓存、重复/空/非文本表头以及必填空值。显示完整异常与每条源记录；仅符合这些规则的记录进入 `data.json` 和 `data.csv` 新副本，未通过的记录完整保留在 `report.json`。有合并区域或表头问题时整张选定工作表不开放导入数据副本，仍可保存完整异常报告。没有运行 Excel、联网、公式计算、原文件改写或数据上传。

验收对象是已存储的数据，不是 Excel 当前显示格式或公式正确性。公式结果有缓存时标记 `stored_unverified_freshness`，报告 `recalculated:false`、`cacheFreshness:"unknown"`。没有缓存是 `formula_cache_missing`，不会变成零或空值蒙混通过。错误单元格保留 `#DIV/0!` 等已存错误文本。数值和布尔均以带类型的原始 XML 文本表示，数值不会转换成 JavaScript 浮点值、日期或格式化金额。

## 2. 为什么需要

他人交付的表格可能含计算错误、漏填或合并单元格；只看到一张表或直接批量导入，难以确定失败的源坐标及被排除的行。T029 将必填约定、逐行接受/排除结果、源 SHA-256 和输出摘要放在一个完整报告中，便于向提供者反馈及对照下游导入。这里“就绪”只指满足选定规则、具有可读取的已存结果，不证明业务字段正确、公式新鲜、全工作簿无错误或符合任何数据库类型约束。

## 3. 实现方式和明确范围

使用本 ID 私有 `zip.mjs` 与 `xml.mjs` 读取有限 ZIP/OPC/SpreadsheetML；无第三方运行包、Python、Excel、Node renderer 权限或跨功能依赖。ZIP 预检中央目录/本地头/路径/方法/大小后，再验证 Deflate 结构、实际展开预算与 CRC。只支持 Store/Deflate、非加密、非 ZIP64、UTF-8/有限普通路径；不支持目录条目丢失、链接或危险路径。XML 严格 UTF-8、命名空间、重复属性、配对与实体校验；拒绝 DTD、CDATA、未知实体和非法字符，不执行内容。所有 ZIP 部件保留在内存读入，不生成被修改的 XLSX。

OPC 必须有唯一根 officeDocument 指向 `xl/workbook.xml`，类型是普通 XLSX；内部关系（包含包内 /xl/... 绝对部件地址）必须指向真实部件，工作表关系和内容类型必须相符。拒绝宏、嵌入对象、签名和外部工作簿链接路径/类型，拒绝根和 workbook 外部关系。工作表其他外部关系（如超链接）不会请求，输出仅取本地已存单元格；这不是文档安全扫描或全 OPC/XSD 合规验证。只支持 2006 Transitional SpreadsheetML 工作表，Strict、XLS/XLSM、chartsheet、ISO-date 单元格、数组/data-table 公式等不支持。第一行固定为表头，从 A 列到最后一个真实单元格列；不自动搜索标题行，不猜表范围。隐藏工作表可明确选择，隐藏行也纳入检查；筛选/格式/绘图/打印设置不参与数据判断。

支持 inlineStr、共享字符串、普通/富文本字符串（只连接文本段）、有限 number、0/1 boolean、error 及普通/共享公式的已存值。不展开共享公式表达式，不验证共享公式依赖或公式算法；缓存能读取与否是本功能边界。共享公式必须有合法索引；不支持拼音注释、cell metadata 属性或 `_xHHHH_` SpreadsheetML 转义字符串，遇到它们整张选定工作表明确拒绝，不能把转义编码误当原文。保留 styleIndex 与 1900/1904 日期系统，但不解释样式/日期序号，也不保留显示格式、公式表达式或工作簿布局。空字符串/缺单元格/纯空白文本在必填列视为空；0、false 的原值 `0` 不是空。已存错误不再重复计同坐标的必填空错误。

表头必须是非空、无首尾空白、≤64 字符的非公式文本；重复检测使用 NFC 与小写比较，保守拒绝仅大小写不同的表头。省略的中间行与单元格仍按原坐标补为 blank，再做必填判断，不缩行改坐标。有任何合并区域时报告完整区域并阻止整表数据副本，不擅自扩填或丢行。单元格错误仅排除该行，报告保留全部值与原因；所有行都不合格时只可导出异常报告。

容量：输入 ZIP≤2MiB、实际展开≤2MiB、ZIP≤100文件、压缩比≤1000、工作表≤10、每 XML≤1MiB/30000节点/60层；选定表≤1000数据行（含中间空行）/50列/50000单元格，坐标不超过 AX1001，单格≤4096字符、共享字符串≤10000、重复展开后的单元格文本总量≤1MiB、异常≤2000、合并区域≤200。声明 dimension 超范围也整体拒绝，不截取假成功。每个完整输出文件≤2MiB，三个输出总≤6MiB；报告包含字段元数据，可能比原表大，因此在达到原表上限前就因输出预算拒绝，这是明确失败而非截断。

内存作业有 15 秒协作期限与取消票据；每轮/文件读取后/ZIP展开后/每个摘要后检查，晚回调不能恢复旧结果。不能强制中断已在浏览器执行的短同步 XML/JSON/摘要操作或 FileAPI 读取，期限是检查点停止，不是假称硬实时终止。切换、隐藏或销毁清除源文件引用、所有单元格、规则与报告；监听在 destroy 移除，没有秘密/大数据 config 草稿。已提交主进程的保存不可中途撤销，仍可在保存对话框取消；暂停后如已完成，会准确显示先前请求回执并要求重新选输入。

输出由生产 `files.exportBundle({copyOnly:true,...})` 创建全新目录，完整相对路径/字节/SHA 先预览，再由保存对话框确认目标名称；用户不能指定 renderer 任意路径。独立报告使用 `files.saveText({copyOnly:true,...})`。已有目录、文件或选回源 XLSX 均拒绝，`ok===true` 才成功；false、undefined、异常或取消均不报成功并保留当前结果。桥缺失明确无法写出。正常失败由公共 writer 清理本次新目录，清理失败显示 partialPath 供人工核对；崩溃/断电不承诺事务。

格式依据：[Microsoft 工作表结构](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-sheets)、[公式与已存缓存](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas)、[共享字符串](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-the-shared-string-table)、[CellValue 类型与共享字符串索引](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.cellvalue)。实现仅上述有限子集，不能等同完整 Open XML SDK。

## 4. 如何使用

在功能工作台打开 T029，选择本地 `.xlsx`，点“读取并校验 XLSX（只读）”。选择工作表，核对显示的来源表名/行列范围；从必填列勾选本次约定（默认不选，不能把默认状态当作自动推断）。点“验收选定工作表与必填列”。

先看坐标异常/结构阻止项，再看全部记录（每页 50 行）以及完整 JSON 报告和输出路径摘要。编辑必填规则、工作表或文件会废弃旧结果，必须重新验收。确认接受排除的行后，点“确认创建导入数据副本新目录”，在保存对话框选一个不存在的新目录；这会创建三个完整文件。即使所有行被排除，也可点“保存完整异常报告新副本”选择一个不存在的新 JSON 文件。报告和数据含本次单元格原文，包括被排除行；是用户明确保存的业务数据副本，未经匿名化，不自动写设置或上传。

## 5. 使用后产出

`data.json`：版本化 `T029-ready-stored-data`，来源 SHA、选定表、日期系统、原表头/列坐标，全部合格行的源行号、坐标、kind、text、styleIndex、formula 标记与 cache 状态。number 的 text 是存储文本，接收方须按自身精度/日期规则解释。

`data.csv`：UTF-8、所有字段加引号、引号双写、CRLF，首行为表头，随后全部合格行；扁平文本格式不保留 JSON 类型或样式。字符串/表头以 `=+-@`（允许前置空白）或 Tab/换行开头时加一个单引号，避免被常见表格程序当成公式；report 的 protectedCoordinates 精确记录处理坐标，JSON 保留原文。CSV 保护不能证明所有第三方导入器安全，数值字段不被改写成假文本。

`report.json`：版本化 `T029-xlsx-data-validation`，规则、表头、合并范围/阻止项、逐坐标异常、全部源记录与逐行结果、接受/排除计数、缓存未知说明及两个数据文件摘要。报告自身摘要显示在 UI 的完整输出清单，不在自身内容做循环哈希。单独异常报告内容与预览一致。没有数据时不创建空的“就绪”文件，只有完整报告可保存。

## 6. 具体可重现例子、验证和限制

建立“数据”表，A1/B1/C1 为 name/calc/email。第 2 行 Alice、缓存为 `#DIV/0!` 的 `=1/0`、a@example.org；第 3 行 A3 空、B3=2、C3=b@example.org；第 4 行 Cara、B4=3、C4 空；第 5 行 Dora、缓存为 4 的 `=2+2`、d@example.org。勾必填 A 和 C，结果应只有三处：B2 cached_formula_error（#DIV/0!）、A3 required_blank、C4 required_blank；四条源数据记录中前三条 rejected，仅源行 5 accepted。data.csv 只有表头及 `"Dora","4","d@example.org"`，报告保留源行 2–5 全部值。

给 A1:B1 增加合并，全部 ready 变 0 并完整报告区域；把 B1 改成 NAME 且 A1 为 name，报告 duplicate_header，不产生数据副本。把 B5 公式缓存删除，则额外报告 B5 formula_cache_missing，不能用计算答案 4 补上。61 条合格数据时 UI 第 1–50/51–61 两页，导出仍是全部 61 条（CSV 62 行）。另一个工作表需要手工选择并独立验收，结果不混入当前表。
