# T090 计划工时与容量核算

## 1. 功能内容

为已经分配日期的任务估时核对每日容量。手填每一天可用时长、固定占用和任务估时，产出逐日负荷、缺口、余量、超负荷日期与用户允许延后的候选。所有时长使用整数分钟，避免小数小时含义不清。支持1–31个日期、0–200项任务；不要求日期连续。

## 2. 为什么需要

周总容量20小时、任务总量18小时，看起来还有2小时，却可能在周一只有4小时可用时安排了6小时任务。这种总量核算会掩盖单日2小时缺口。本功能同时展示总量净余和每日缺口/余量，便于人工修改已经制定的计划。它补充事项清单的容量检查；学习顺序规划涉及前置依赖，本项只检查用户已经分配的日期。

## 3. 实现方式

纯模型校验真实公历日期、唯一日期与任务编号、范围内整数分钟和布尔可延后标记。任务日期缺失时明确拒绝，不悄悄排除。以日期分组，负荷=固定占用+任务估时，缺口=max(0,负荷−可用)，余量=max(0,可用−负荷)。总量净余另计算，每日缺口和其他日期余量同时保留。结果持有独立输入快照，原始日程不变。

候选仅列超负荷日期内用户标记可延后的任务；按日期、估时降序和编号排序。每项显示原日期、原估时以及仅从该日移走这一项后的缺口。这是独立假设试算，不为任务选择新日期，多项效果不能直接累加，也不承诺其他日期容纳它。纯模型无网络或自动排程，界面用文本DOM展示。编辑立即清空旧结果和禁用导出。

JSON恢复限64KiB UTF-8，只接受T090版本1的inputs，并重新核算，忽略旧派生结果。数据留在当前面板内存，无后台计时和全局大文件存储。JSON/Markdown报告通过copyOnly接口创建新文件，遇到已存在目标拒绝覆盖；仅ok===true报告成功，取消和保存失败保留当前报告。

## 4. 如何使用与具体例子

在新增功能工作台打开T090，点击“载入周容量20小时示例”。容量表是2026-10-05至10-11，周一至周五各240分钟、周末0分钟、固定占用均0。五项任务分别分配到周一至周五，估时360、180、180、180、180分钟；只有周一任务允许人工延后。

点击“核算每日容量”：总可用1200分钟=20小时，总任务1080分钟=18小时，总量净余120分钟=2小时。周一负荷360分钟、容量240分钟，缺口120分钟=2小时；其余工作日合计余量240分钟=4小时。这两项分开展示，未自动抵消或调配。

候选“撰写报告”保持原日期2026-10-05、原估时360分钟，若仅移走该项，周一缺口变0。你需要自行决定是否拆分、延后或增加当天可用时长；本工具不改日期。可手改“任务1估时分钟”为240再核算，此时周一恰好满额，无超负荷日期。固定占用应填写未列为任务的时间，防止重复计算。

核对预览后点击“导出容量 JSON 副本”或“导出容量 Markdown 副本”，选择不存在的新文件名。需恢复时粘贴本功能JSON，点击“恢复容量草案”，只读取原输入并重新核算。删除日期后若仍有任务引用该日期，会明确提示补齐或人工调整。

## 5. 使用后产出

界面产出总可用/总负荷/总量净余、超负荷日数量、逐日缺口合计、其他日期余量合计，以及日期表和候选表。JSON包含feature/schemaVersion、完整inputs、归一化日期和任务、逐日负荷及缺口余量、totals、overloadedDates、独立候选试算及规则说明。Markdown包含同一汇总、日期表、候选说明与完整原始输入，可用于计划复核或手动调整后对照。

## 6. 验证与限制

定向模型测试验证总量有余但周一超载、固定占用、固定占用独自超载无候选、候选资格和排序、独立移除试算、公历闰年、重复日期和编号、日期未覆盖明确拒绝、整数分钟和数据规模边界、恰好满额、空任务、输入不变、JSON快照/版本/UTF-8边界、忽略伪造派生结果和Markdown。实际Electron组件、导出IPC及集成验证由主代理补充记录。

日期1900–2100年；每日期可用/固定占用0–1440分钟，每任务1–1440分钟，单任务不能跨日。没有依赖拓扑、自动日程调整、跨日搬运、资源冲突、自动日历读取或精准工时预测。结果依赖用户估时，超负荷候选不等于可以延后；本工具不改变原计划。
