# L059 目标证据追踪

## 1. 功能内容

这是跨时间、跨作品版本的人工目标证据台账。用户定义目标接受的证据类型、不同证据数量和有效天数，登记作品各版本的人工片段/出处，再以证据ID绑定目标，追加人工接受、拒绝或撤销记录。用户选择UTC评估日期后，工具计算仍满足条件的不同证据ID数量，并列出每个绑定的作品版本、最新人工判定、有效截止日与排除原因。

目标定义、作品、证据、绑定和判定各有明确ID。目标定义和作品只能追加新版本，证据固定引用某作品版本；旧版本、旧出处、旧片段和旧判定不会被新版本覆盖。重复绑定同一证据不增加覆盖；撤销是“目标ID＋目标定义版本＋证据ID”范围的最新判定，影响该范围全部重复绑定，不能另加绑定绕过撤销。

MVP完整支持catalog的三项验收：两份证据一份过期时只计一份、同ID重复绑定只计一次、新作品版本不继承旧版本接受状态。没有AI依赖。作品及证据均由用户手工录入来源与片段，不自动读取、核真或执行外部文件。

## 2. 为什么需要

复习次数与学习时长不能说明某个长期能力目标具备哪些可追溯证据。即使某份说明曾被人工接受，它可能已超过目标规定的有效期，或者只针对作品旧版本。把同一证据绑定两次也不等于取得两份独立作品。

L059保存这些人工记录的版本与时间关系，帮助用户看到“当前哪个目标，依赖哪份证据、哪个作品版本、哪次人工判定”。覆盖分数仅表示记录数量要求，既不认证证据真实或相互独立，也不证明能力、掌握、效果或未来表现。L058验收一份作业交付的有限文件条件；L059管理长期目标的证据寿命、作品版本和判定变化。

## 3. 实现方式与规则

`model.mjs`是纯本地模型，`index.js`提供真实表单、完整历史、目标覆盖卡片与逐绑定追踪表，`meta.json`供生产功能工作台发现。输入不执行用户JS，不联网、不使用系统时钟来假定评估日期。

- 日期只接受2000–2100年真实日历中的严格`YYYY-MM-DD`，以UTC整日计算，不使用本地时区。有效期N天**包含签发日**：截止日为签发日＋N−1，截止日仍有效，次日过期。证据签发日不得早于对应作品版本；绑定日不得早于目标定义与证据；判定必须已有对应绑定。
- 评估日可以前移、后移。按该日选择已经生效的最新目标定义/作品版本及对应目标定义＋证据的最新人工判定。同日多次追加按数组追加顺序选最新。新的版本日期不得早于同一对象的前版；同判定范围追加日期不能早于其上一条。日期都是用户声明，不是可信外部时间戳或不可篡改注册。
- 每个目标单独维护计入证据ID集合。当前定义、当前作品版本、类型字面匹配、尚在有效期、最新判定接受同时满足，才计入。不同目标不自动共用人工接受；不同目标可以人工接受同一证据，但不由此证明独立性。
- 新作品版本生效后，绑定旧版本的证据保留并标“旧作品版本，待新版复核”。需登记引用新版的新证据、绑定、明确人工接受。修改目标类型/数量/期限也追加新定义；旧定义绑定标“旧目标定义”，当前定义需重新绑定/人工复核。
- 每条绑定显示一个主要排除原因，优先顺序是：尚未生效、旧目标定义、旧作品版本、类型不符、过期、未复核、撤销、拒绝、同ID重复。一个绑定可能还存在其他不满足条件；界面原因不是完整因果诊断。有效截止日按**评估日当前目标定义**的期限计算；旧定义行已排除，原定义的期限保留在完整历史。`expiredEvidenceIds`按主要原因“过期”的行去重，不把旧版本行另计为过期。
- `count`是实际计入的不同ID数量，`covered=min(count,required)`用于覆盖分数，`surplus`单列超额。`quantitySatisfied`只说明数量条件。尚无生效目标定义时要求未知、覆盖“不可估”，不捏造0/0。

schema1草稿包含**所有已提交人工输入和历史**，不包含派生报告或尚未提交表单。配置写入采用单个在途请求、最新待写值队列；旧回执不会显示成最新输入已保存。字段更改立即清旧报告，未提交表单禁止计算，避免把未确认输入误认为已进入结果。切走、隐藏、取消和销毁隔离迟到结果，恢复只显示控件，不自动重算。已经开始的写盘不能撤回，离开后不显示迟到成功提示。

容量是整体拒绝，不截断：最多8目标×8定义、8作品×8版本、40证据、80绑定、160判定，完整JSON输入/版本/历史的UTF8体积≤64KiB；任何新增使其超限则整项不提交，旧台账保留。名称≤160码点，目标描述≤1200，作品片段≤2000，证据/判定说明≤1200；来源名称≤160、位置≤320、判定人≤120；每目标1–5个不重复非空类型，每类型≤40码点，要求1–20份、有效期1–3650天。非法控制字符、孤立代理项、未知schema/字段、无效引用和回退版本/判定日期拒绝。导出JSON/Markdown各≤1MiB，超过整份拒绝，不导出部分结果。

## 4. 使用步骤与可复现例子

1. 在学习功能工作台打开L059，直接点击“重算目标证据覆盖”。默认评估日`2026-10-03`，G001要求2份“分析说明”，期限30天。E001签发`2026-09-01`，截止`2026-09-30`已过期；E002签发`2026-09-20`，截止`2026-10-19`仍有效。两份都曾人工接受，结果恰为**1/2**，只计E002。
2. 把UTC评估日期改为`2026-09-30`，离开日期框提交校验，重算为**2/2**；改`2026-10-01`则**1/2**。`2026-02-30`不存在，整项拒绝。恢复`2026-10-03`再继续。
3. 展开“4 · 绑定与人工判定”，绑定证据选E002，点击“追加证据绑定”，重算仍**1/2**，新增行标同ID重复。在判定证据选E002，选择撤销接受，填写人工理由，追加判定，再重算**0/2**；所有E002重复绑定均受撤销。再追加E002绑定仍不能绕过撤销。同日再追加人工接受可回到1/2，原接受与撤销都保留。
4. 展开“2 · 记录作品或追加作品版本”，选W002，填写新版片段/出处并提交作品版本。既有作品名称不改，新版为v2，旧片段和E002引用的v1保留。重算**0/2**，E002显示旧作品版本待复核，不会继承旧接受。
5. 展开“3”，选W002，版本填2，类型“分析说明”，签发日`2026-10-03`，填写来源/说明，提交生成E003。展开“4”绑定G001/E003，重算仍0/2且E003未复核；明确追加G001/E003人工接受后变为1/2，只计E003。
6. 如修改目标要求，在“1”选择目标、“载入选定当前定义到表单”，修订并提交，产生目标v2。旧定义绑定不自动通过，需要对当前定义重新绑定、人工判定。
7. 查看完整历史与报告预览，导出JSON或Markdown新文件。草稿只保存已提交台账，未提交表单用“放弃未提交表单”撤回；所有当前历史整体替换为示例/空记录需要明确确认，需保留旧台账先导出。

来源名、位置、判定人和理由允许未知空值，界面标未知；未知不会自动编造引文或可信来源。接受仍只表示人工台账中的判定，而非外部认证。当前不提供文件导入或编辑已保存历史：原片段的修正请通过追加作品版本、目标定义或判定说明记录。

## 5. 产出与保存范围

界面包含各目标当前定义、计入ID、不同证据数量、要求与超额，以及每条绑定到证据/作品版本/当前版本/判定的完整追踪表。目标、作品所有版本、证据来源、绑定和判定完整历史可展开浏览。没有分页截断或筛选影响导出。

JSON和Markdown预览及副本都包含：用户UTC评估日、模型版本、完整人工来源和所有目标/作品版本、证据、绑定、判定输入，逐绑定状态及计算口径。Markdown使用安全实体与动态代码围栏，用户文字不注入可执行HTML；JSON保留原人工文本。报告可能含用户手工录入的作品片段和出处，导出前可完整预览。

调用生产`files.saveText`时必须有`saveTextSupportsCopyOnly===true`，携带`copyOnly:true`，且只在回执`ok===true`时报告成功；取消、未知回执或现有目标写入失败都不能伪称保存。生产writer使用`wx`创建新文件，拒绝覆盖已有目标；不修改外部作品或来源。草稿只写schema1输入，不保存派生覆盖；重载后保留完整已提交历史但须主动重算。
