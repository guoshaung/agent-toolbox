# E028 故事接龙

## 1. 功能内容

在一台设备上，由2–8位真人按固定顺序轮流写故事。内置30张原创开头卡，选择1–10轮后建立新局；每轮每人提交一段，最多80段。提供“查看完整上一段”和“盲接末句”两种模式，默认甲、乙、丙三人、两轮、盲接、C01迟到的邮筒。达到计划段数即揭晓，提前结束须先确认并明确标记中断。最后按轮次、段号、作者顺序展示作品，可另存JSON和Markdown副本。

盲接局结束前没有历史全文浏览或导出按钮。首位玩家只看开头卡的末句；后续玩家只看上一段的末句/尾片段，提示最多80个Unicode码点。写作交接页完全不显示提示和输入框；接手玩家点击自己的身份按钮后才建立新的写作节点。

同屏隐私依靠参与者合作和交接约定。身份按钮没有登录验证、授权、加密或安全隔离；有权限操作设备或开发者工具的人可能读取内存。这不是多人远程权限系统。

## 2. 为什么需要

聚会时用聊天窗口编故事容易打乱作者顺序，盲接时也容易看到前人全文。此模块把人数、轮次和交接进度变成明确流程，保留每段作者而不要求创建账号。30个原创开头提供开始素材，参与者自行写作，不调用网络或AI，不使用现有酒馆角色扮演功能。

完整作品和主动中断作品分别标注，避免把只写了几段的作品误称为已经完成。导出的轮次、作者与规则使聚会结束后仍能追溯创作顺序。

## 3. 实现方式与输入规则

`meta.json`采用工作台发现契约；`index.js`用现有`h()`构建实际设置、交接、写作、确认和揭晓界面；`model.mjs`包含卡片、严格设置校验、不可变局状态、末句提取和导出。没有运行时跨功能依赖、第三方库或任意代码执行。

| 输入/状态 | 明确口径 |
| --- | --- |
| 玩家 | 2–8人，玩家名1–40码点；无首尾空白/控制字符，按NFC归一化判断名字重复。作者ID为P1–P8，实际显示保留原名字。 |
| 作品名 | 1–80码点；无首尾空白/控制字符。 |
| 轮数 | 1–10整数；计划段数=人数×轮数，每轮按同一玩家顺序。 |
| 开头和模式 | 只能选择内置C01–C30卡和两种查看模式；本局建立时复制并锁定。改模式/玩家/开头须通过“建立新局”及确认，再重新建立。 |
| 单段 | 提交时先去首尾空白；正文1–1000 Unicode码点，内部换行和制表保留；拒绝非法控制字符及孤立代理项。码点不是视觉字形，组合emoji可能占多个码点。草稿文本框最多2000 UTF-16单位，实际提交还校验1000码点。 |
| 全局限额 | 最多80段、正文80000码点，导出不超过512 KiB；拒绝超限输入，不截断正文。最多1000码点的末句提取和80段的导出均有固定上界。 |
| 未提交草稿 | 不出现在交接、结束确认、新局确认和最终作品中。取消确认回到原玩家并恢复草稿；确认中断/建立新局则舍弃。 |
| 完成/中断 | 正常最后一段提交自动完成。主动结束先显示已提交/计划段数，确认后标记中断；0段中断也明确为0/计划段数。 |

末句提取使用确定规则而非自然语言分析：`。！？!?`是句末符；英文`.`仅后接空白、闭引号/闭括号或文本末尾才算句末，所以`3.14`不会被切断。连续句末符及随后的闭引号/括号合并到同一句。最后若还有未完成片段，显示这个片段。例如`秘密。她说：“公开！？”`显示`她说：“公开！？”`，`第一句。最后未完`显示`最后未完`，`Private. Cost is 3.14.`显示`Cost is 3.14.`。英文缩写不做语义识别，`Mr. Smith arrived.`按规则显示`Smith arrived.`。

没有句末符时显示最多80码点尾片段并说明采用fallback；提取的末句本身超过80码点时也只显示最后80码点，提示“前文已省略”。因此1000码点的一整句不会把前缀全部揭露。长度以Unicode码点切片，不切断单个代理对；一条短的单句可完整显示，因为它本身就是末句。

交接、确认、暂停和销毁会清空旧提示文本及textarea的value、移除旧事件，再替换节点；下一位不复用上一个textarea及其undo状态。模块暂停保留同一玩家未提交草稿于内存，回来用新节点恢复；切换具体功能触发销毁，全部未保存内容清理。状态不写全局配置，不自动落盘，没有恢复导入入口。

导出只接受已经完成或明确中断的局，导出前异步让出一次事件循环，支持取消生成或暂停取消。发送原生另存请求后应用内取消按钮禁用，需在文件对话框取消。仅在`files.saveTextSupportsCopyOnly === true`且接口存在时允许导出，每次携带`copyOnly:true`；原生独占创建拒绝已有目标。仅`ok === true`报告成功，`canceled === true`报告取消，`ok:false`、字符串`"true"`、空响应及异常均报告失败。JSON保留原文；Markdown转义HTML和格式语法，防止故事内容被当作脚本或外部图片链接。

## 4. 如何使用

1. 在功能工作台“娱乐 → 聚会与互动”打开“故事接龙”，填作品名、玩家顺序和轮数，选开头卡及查看模式。
2. 点击“建立本局并开始交接”。设置此时锁定，交接页会显示下一位玩家、轮次、段号和计划总数。
3. 把设备交给指定玩家，点击“我是甲，开始写作”等对应按钮。阅读当前提示，在正文框输入一段，检查长度后点击“提交本段并交接下一位”。非法输入保留当前玩家，不推进段数。
4. 每次提交后进入没有输入/提示的交接页。最后一位最后一轮的按钮为“提交最后一段并揭晓作品”，点击后完整作品出现。
5. 若提前结束，点击“主动结束本局并揭晓”，核对已提交/计划段数再点“确认中断并揭晓已提交作品”。也可点击“继续本局，保留未提交草稿”返回写作。
6. 揭晓页使用“保存完整JSON作品副本”或“保存完整Markdown作品副本”，选择尚不存在的新文件。已有文件不会被覆盖。要重新配置请点“建立新局”并确认清空；原作品先导出。

## 5. 使用后产出与可重现例子

按默认设置三人甲、乙、丙、两轮、盲接、C01建立一局。首位看到`今天，邮筒里第一次传来了敲门声。`。六次交接依次输入以下正文，每次先点击对应身份按钮，前五次提交交接，第六次提交揭晓：

| 段号 | 轮次/作者 | 正文 | 下一位盲接可见提示 |
| --- | --- | --- | --- |
| 1 | 第1轮甲 | 邮筒晃了晃，一张地图落下。地图指向空房子。 | 地图指向空房子。 |
| 2 | 第1轮乙 | 空房子里有一盏灯。灯上写着请等天亮。 | 灯上写着请等天亮。 |
| 3 | 第1轮丙 | 天亮后，灯变成了一只鸟。鸟衔着一枚蓝扣子。 | 鸟衔着一枚蓝扣子。 |
| 4 | 第2轮甲 | 蓝扣子打开了小门。门后是一片海。 | 门后是一片海。 |
| 5 | 第2轮乙 | 海上漂着昨日的信。信封里有一声笑。 | 信封里有一声笑。 |
| 6 | 第2轮丙 | 笑声带大家回到邮筒前。新一天开始了。 | 提交后结束并揭晓完整作品。 |

结束页面显示“完整完成”“已提交6/6段”，按甲、乙、丙、甲、乙、丙展示六段。JSON包含`feature:E028`、`version:1`、`kind:work`、`status:completed`、`complete:true`、`submittedSegments:6`、`plannedSegments:6`，完整开头、玩家列表、规则以及六个带`ordinal/round/playerId/author/text/characters`的段落。Markdown包含开头和每段“第N轮 · 第N段 · 作者”标题。没有重复存储一份拼接全文，单段原文各保留一次。

提前结束例：只提交上述第一段，乙输入尚未提交的`这是草稿`，点击主动结束。确认页不显示第一段全文或该草稿；取消确认会用新输入框恢复`这是草稿`。再次主动结束并确认，作品标记“主动中断”“已提交1/6段”，导出`status:interrupted`、`complete:false`、只有第一段，不包含乙的未提交草稿。

上限提示例：甲写`HIDDENPREFIX`后接900个`x`和`公开尾巴。`并提交，乙提示只有最后80码点并标记省略，当前DOM/输入属性不含`HIDDENPREFIX`。无句末符的长段同样仅给80码点尾片段。
