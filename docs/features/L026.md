# L026 资源生命周期审计

## 1. 功能内容

用户声明1–4个抽象文件句柄资源，编辑1–12节点的无环分支图，明确入口、每节点操作及后继。审计完整枚举入口到叶的全部路径，独立重放Acquire/Use/Release，分别报告操作违规和退出时的泄漏，不扫描用户源代码或接触系统句柄。

界面提供资源/入口输入、节点表格增删、操作/后继编辑、三种可编辑模板、全路径统计、最短首次失败前缀、路径选择和完整前后资源状态。可以筛选失败、泄漏、操作违规路径；筛选不影响完整统计与JSON/Markdown副本。

## 2. 为什么需要

资源忘记释放往往藏在某个退出分支，单看一段直线代码或停止在第一个错误，无法说明每条路径最终还持有什么。重复获取、获得前使用和释放后使用也不是同一种问题。

本功能把各条路径的资源状态明确重放，让用户观察一次非法操作如何影响后续，以及合法Release为什么仍能消除终态泄漏。操作违规与泄漏分开计数：路径即使已释放完所有资源，也可能有历史违规。这新增路径级不变量训练，区别于AI报错解释，结论不外推到真实程序。

## 3. 实现方式与状态语义

`model.mjs` 校验图、枚举路径并进行纯状态机重放，`index.js` 提供表格/筛选/轨迹，`style.css` 用项目已有主题变量。不运行用户JS、真实文件操作或外部依赖。结果中的每条路径和每步状态快照独立。

每个资源只有 `not-acquired`、`held`、`released` 三态：

| 操作 | 当前状态 | 结果 |
| --- | --- | --- |
| Acquire | not-acquired/released | held，首次获得或开始新生命周期 |
| Acquire | held | 重复Acquire违规；保持原held，不额外分配句柄 |
| Use | held | 合法，保持held |
| Use | not-acquired/released | 获得前使用/释放后使用违规，状态不变 |
| Release | held | released |
| Release | not-acquired/released | 获得前释放/重复Release违规，状态不变 |
| Noop/Exit | 任意 | 状态不变；Exit仅为叶末标记 |

**所有异常操作都记录并继续后续重放**，不悄悄释放、不停止后误报持有，也不模拟异常抛出。路径结束统一加入EndPath检查，只有此时仍held才泄漏；从未Acquire不算泄漏。违规发生过就保留失败，即使后续合法Release使终态没有泄漏。此为明确教学规则，不代表真实异常处理或句柄系统。

图和容量规则：资源1–4，节点1–12，边≤32，完整路径预算2048；每节点1–4条区分大小写的 `Acquire 资源`、`Use 资源`、`Release 资源`、`Noop` 或 `Exit`。Exit只允许叶节点最后一条；没有显式Exit的叶也隐式执行统一退出检查，不能在中间节点Exit并忽略后继。

ID为1–12位ASCII字母/数字/_/-且以字母开头，后继/资源ID列表以空格或逗号分隔。操作文本≤512 UTF-8字节，后继≤256，资源列表≤128。重复资源/节点/边、未知入口/资源/后继、循环或任何不可达节点都阻止整个审计，明确提示修正；不可达节点不被静默忽略。改ID、删行后须手动修正引用。

路径按后继输入顺序完全深度优先枚举，无随机抽样。超过路径预算拒绝整个结果，不截断为部分成功；节点/边限制先检查。每路径最多48条操作和一次退出检查。最短失败前缀按到首次操作违规或退出泄漏检查的操作步骤数，在全部路径中取最短，同长选择先枚举者；不是删操作后的全局因果最小反例。查看路径只改变视图，不改变审计数据。

## 4. 使用步骤与具体例子

默认资源fh，入口open：open执行Acquire fh，后继close/use；close执行Release fh，use执行Use fh，两者后继都为exit，exit执行Exit。点击“审计全部路径”：

| 路径 | 状态演进 | 操作违规 | 退出泄漏 |
| --- | --- | --- | --- |
| open → close → exit | not-acquired→held→released | 无 | 无，通过 |
| open → use → exit | not-acquired→held→held | 无 | fh，失败 |

应看到完整2路径、通过1、失败1、泄漏路径1、操作违规路径0。点击“查看最短失败路径”，第二条路径在第4步EndPath才发现泄漏；Acquire/Use中途不能提前报退出泄漏。选择“仅泄漏路径”清单剩1条，但导出仍包含全部2条。

“载入状态违规示例”有一个完整路径：start依次Use/Release/Acquire/Acquire fh，end依次Release/Release/Use fh/Exit。应报告5次违规：获得前使用、获得前释放、重复Acquire、重复Release、释放后使用；首次失败第1步，最终fh仍为released，所以退出泄漏为无。后续合法Release没有被第一个错误跳过。

将start操作改为 `Acquire fh / Release fh / Acquire fh`、end改为 `Release fh / Exit`（每条一行），应通过，证明释放后可开始新周期。“载入多资源示例”中first和second都获取，只释放first，退出只泄漏second。声明但未获取的unused资源不泄漏。

新增节点默认Noop，必须把它连接至入口可达路径后才能审计；没有连接时应提示“不可达，拒绝部分审计”。把open后继改为open应报循环；`close,close`报重复边；删open而不改入口报未知入口。编辑立即清空旧路径和结论。

## 5. 产出与保存

JSON包含feature、schemaVersion、modelVersion、导出时间、完整输入、选中路径索引以及解析图、边数、全部路径统计、各路径操作轨迹/前后状态/违规/终态/泄漏/首次失败前缀、全局最短前缀与定义。Markdown含相同完整草稿和逐路径记录、图元数据与检查规则；路径记录用紧凑JSON避免重复大块数据。没有有效审计时明确没有路径或泄漏结论，可导出草稿。用户内容按文本输出，Markdown中HTML字符转义。

要求 `files.saveTextSupportsCopyOnly===true`，以 `content`、格式和 `copyOnly:true` 调用桥接；仅响应 `ok===true` 才宣告成功。主桥接独占创建拒绝已有文件，取消/失败保留草稿与结果。筛选和当前查看路径不截断报告。当前无报告导入，保存的完整草稿可重算。

配置仅保存 `schemaVersion:1` 输入草稿，整个JSON按UTF-8测量≤64KiB；另有草稿字段上限：资源128字节、入口/节点ID32字符、操作512字节、后继256字节和1–12节点。有界未完成语法可保存，审计时再严格校验。恢复先检查原始存储体积（包括额外字段）、版本、字段类型/数量及容量，随后提取已知字段。超限不写配置，明确提示关闭后只恢复较早草稿，需要完整JSON导出。结果、轨迹和选中位置不保存，重进后重算；切走清保存计时器，销毁释放DOM，异步返回不重建界面。
