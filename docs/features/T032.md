# T032 素材联系表

## 功能内容

选择本地图片文件或目录，按原选择顺序、完整文件名升序或降序生成分组 PNG 联系表。每个来源都有固定槽位、全图缩略图和完整名称；损坏、空文件、超单图预算或不支持的格式保留红色占位，错误原因进入完整报告。可预览每组后另存当前 PNG 或全部 PNG/报告新目录。依赖公共工作台及 binary/bundle/text copyOnly 接口 PR #14；本 PR 仅增加 T032 自有文件，无跨功能导入或共享依赖修改。

## 为什么需要

寻找照片、截图和视觉素材时，逐个打开文件难以同时记住内容和名称。联系表将视觉内容、文件名和顺序放在一起，便于选图、交接和核对；坏文件仍占位可以让接收方发现缺失，避免无声跳过导致列表与文件集合不一致。

## 实现方式

浏览器真实 File API 只读来源，私有有界 PNG/JPEG 结构检查后由 createImageBitmap 解码、Canvas 居中等比绘制并编码 PNG。来源缩略图保持全图、不裁切、不放大；透明像素合成到白/灰背景。Canvas 使用当前浏览器解释色彩/EXIF方向，输出不复制源元信息，不承诺跨浏览器颜色完全一致。结构检查代码为本 ID 私有副本，无 CDN 或运行时下载。

完整选择 1–48 文件、总计最多 30 MiB；目录内不支持格式也保留占位，超过完整集合预算则整份拒绝，不取前48个。单张静态 PNG 或8bit灰度/RGB JPEG为1字节–5MiB、边≤8192、≤2400万像素；动画 PNG、SVG、GIF、WebP等不支持。超单图或无效文件成为明确占位，不是成功图。名称或目录相对路径为1–255个字符，不含控制字符或无效代理对；路径只作为文本，不用作写入路径。

列数/每组行数1–6，格宽180–400px、格高120–300px。原页序从左到右、从上到下；名称排序按 NFC 后 Unicode 码点且区分大小写，同名保持选择序号，明确不是自然数字排序。每个完整名称按14px真实字体测量逐字换行，最多18行，不省略字符；不能完整容纳则整批拒绝。全部分组统一根据最长名称行数计算文字高度，短名称不会预留18行空白。尾组保留用户设置的空槽位，不重复补图。

逐张处理并释放 bitmap、临时 Canvas；生成30秒协作期限、单次解码5秒超时。取消/隐藏/切换使票据失效，迟到解码主动关闭、不复活结果；异步 API 收尾期间仍锁定控件。更改任何设置使旧副本和确认失效；没有自动生成或保存。来源及产物不保存到配置。PNG每文件最多2MiB、完整目录10MiB，超限整批拒绝，不删除某组以凑预算。

全部生成组均完整解码预览且用户确认名称/占位后，才开启 PNG 和目录副本保存。固定序号输出名称避免相对路径和同名覆盖；生产 copyOnly/WX 保存器拒绝已有目标，只有 `ok===true` 才报告成功。完整 JSON 可以单独另存；它不需要图片确认，但包含所有已完成来源及错误项。

## 如何使用

1. 在功能工作台打开“素材联系表”，选择文件，或用“选择联系表图片目录”选目录。查看完整来源列表，设置列、行、缩略格大小和排序。
2. 点击“生成全部素材联系表”，等待所有分组完成。报告列出每个来源的成功或占位原因。
3. 逐组点击“完整预览联系表”，核对名称、内容、顺序和坏图占位，然后勾选确认。
4. 另存当前已预览 PNG 新文件，或导出全部联系表与完整报告到一个不存在的新目录。需要追踪失败来源时可另存完整 JSON 报告。

## 使用后产出

当前组的新 PNG，或新目录内 `contact-01.png`、`contact-02.png` 等全部联系表及 `contact-report.json`。报告包含完整设置、布局、总数/成功/失败、每个来源的完整名称/字节/SHA/选择序号/排版顺序/纸组与槽位/源尺寸/缩略几何/实际名称行和错误、全部 PNG 字节/SHA。过大或空来源没有读取字节，SHA为null且原因明确，不编造校验值。

## 具体使用例子

选择 `asset-01.png` 至 `asset-12.png`，保持选择顺序，4列、每组3行、240×180缩略格。十二张图生成一组1044×812 PNG；每张缩略图下方对应完整文件名，按1–4、5–8、9–12三行排列。加入 `broken.png` 并改成名称降序，得到两组：首槽为红色坏图占位，接着12至1，末组最后剩一张合法图；完整报告是13来源/12成功/1失败。长中文名称按真实测量换成多行且全部字符保留。

## 验证与限制
