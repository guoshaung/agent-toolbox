# T027 Word 模板批量填表

## 1. 功能内容

选择本地 DOCX 文本占位模板和 UTF-8 CSV（也可粘贴CSV），把 `{{field}}` 映射到表头列，逐字段设置必填。生成全部记录的文本结构样稿、逐条目标路径/SHA-256、缺字段报告；核对后显式创建一个全新的目录，包含完整 DOCX 文档与 `report.json`。必填字段为空或仅空白的记录不生成文档；其他完整记录继续生成，报告保留所有记录，不截断也不假称第四条成功。

主文档段落和表格文本支持同一个占位符被 Word 拆成多个 `w:r/w:t`（例如 `{{na` + `me}}`）；同一段落内重复占位也完整替换。占位符名限定 ASCII 字母/下划线起始、随后字母/数字/下划线，最多64字符。所有发现的占位字段都必须明确映射，默认必填，可由用户取消某字段的必填；取消后空值写为空字符串。

## 2. 为什么需要

批量制作成员证明、培训通知或简单登记表时，人工复制粘贴容易把不同记录混在一起或遗漏必填项。该功能把映射、样稿和缺字段作为同一个交付流程：保存之前能检查每条内容和完整目标路径，缺字段的记录有明确位置，原始模板和表格保持只读。此功能处理本地办公文件，不调用AI，不依赖Python或Word安装。

## 3. 实现方式与支持边界

`model.mjs` 实现有界CSV解析、有限XML解析、DOCX/OPC关系检查、占位映射与完整Store ZIP生成；`zip.mjs` 是本 ID 私有的有限ZIP/Deflate/CRC模块，来源于同作者T016实现的源码副本，运行时不导入T016或其他功能。不引入第三方发行包、Python库或共享package/lock修改，因此没有额外vendor许可或机器上的Python依赖。WebCrypto计算SHA-256；浏览器 `DecompressionStream('deflate-raw')` 解压前先用 RFC1951 有界结构扫描器核对实际输出量和流末尾，再验证CRC/实际字节。旧浏览器缺少该能力时Deflate明确拒绝，Store仍可用。

ZIP支持普通单卷Store/Deflate、ASCII或明确UTF-8文件名，中央目录/本地头名称、标志、CRC和尺寸一致，记录连续且无隐藏数据。加密、ZIP64、数据描述符、extra字段、特殊属性/链接、危险路径、重复/NFC/大小写/文件目录前缀冲突整体拒绝；空目录记录也拒绝。保留其他非编辑部件的原始内容字节，但输出ZIP容器重新创建，使用Store和固定时间元数据，不声称ZIP原始压缩方式/注释/权限/目录记录逐字节保留。

DOCX限定过渡版WordprocessingML命名空间，主部件固定为 `word/document.xml`。必须有匹配Content Types和唯一根officeDocument关系；所有关系的源、目标和ID校验，外部关系、宏、嵌入对象、ActiveX、自定义XML、签名、附加模板、altChunk等整体拒绝。支持普通主文档段落/表格纯文本，未编辑样式、媒体和其他部件保留；其他部件（页眉/页脚等）内的占位符，以及属性占位符明确拒绝。域、内容控件、修订/删除文字、文本框、嵌套段落、AlternateContent、tab/br/cr/sym等主文档结构拒绝，避免漏替换或错误跨边界拼接。不能把占位符拆到不同段落。不是完整OOXML XSD验证器，也不是通用Word模板语言，不支持循环表行、条件、图片或样式指令。

XML仅接受UTF-8/XML1.0、ASCII QName、有限命名空间、普通元素/属性/注释与五个预定义及合法数字实体；拒绝DTD、自定义实体、CDATA、其他处理指令、不配对标签、重复/重复展开属性、未声明前缀、非法Unicode。原文XML未编辑区域保持原字符串；替换值按XML文本转义，写 `xml:space="preserve"`，使用占位起点run的格式，跨run的后续占位片段清空。CSV值是字面文本，不执行公式/HTML/JavaScript；此功能不导出CSV。CSV支持逗号、引号内逗号、双引号转义、CRLF/LF和引号内换行，拒绝重复/空/带首尾空白表头、不等列、裸CR或非法引号。引用文本中的换行/制表符作为XML文本字符保留，非Word换行/制表符元素。

容量：模板ZIP≤2MiB，实际展开≤2MiB/50文件，单XML≤1MiB、30,000节点、深度60；CSV≤256KiB、30记录、50列、每格4096字符；占位字段≤100。每份完整DOCX≤2MiB，含报告的新目录总量≤10MiB，超过限额整批不开放保存，无截断/部分成功目录。文件读前后核对字节数。15秒是协作检查期限，不保证同步解析/内核操作硬终止；每条记录与异步SHA后检查取消票据，不使用旧回调覆盖新输入。暂停/隐藏/销毁清除输入、模型和样稿，取消内存处理；已提交的生产保存不能由本功能撤销，仍由主进程完成，可在保存对话框取消。没有自动保存或大字节config草稿。

生产副本依赖公共基础 `files.exportBundleSupportsCopyOnly`/`exportBundle(copyOnly:true)` 和 `saveTextSupportsCopyOnly`/`saveText(copyOnly:true)`（a80e115的祖先包含69f44e8目录副本基础）。renderer不能提供任意目标目录；保存对话框返回的新目录由生产writer独占创建，已有目标拒绝。只有 `ok===true` 算保存成功；取消/false/undefined/抛异常不报成功，正常失败保留样稿。基础writer正常写入失败清理本次目录，清理失败返回partialPath供人工核对；本功能不承诺进程崩溃/断电事务或跨软件导入效果。

格式依据（官方来源）：[Microsoft WordprocessingML结构](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)、[ECMA-376/OPC](https://ecma-international.org/publications-and-standards/standards/ecma-376/)、[PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)、[RFC1951](https://www.rfc-editor.org/rfc/rfc1951)、[XML1.0](https://www.w3.org/TR/xml/)、[RFC4180](https://www.rfc-editor.org/rfc/rfc4180)。实现是上述格式的明确有限子集。

## 4. 如何使用

1. 打开功能工作台→工具→Word模板批量填表；选择 `.docx` 文件，选择UTF-8 `.csv`或粘贴表格。输入只保存在当前内存。
2. 点击“读取并校验模板与表格”。若结构/编码/容量不支持，界面给稳定错误码，旧结果已废弃，不能保存。
3. 核对每个占位字段对应CSV列及必填开关；默认按同名表头选择，否则必须人工选正确列。
4. 点击“生成全部样稿（仅内存）”。核对每条generated/missing_required状态、缺字段及相对路径，切换“样稿记录”查看每份填入文字。样稿不是Word页面渲染，不保证分页/字体/行高；需在办公软件另行查看成品排版。
5. 点击“确认并创建完整新目录副本”，在保存对话框填写尚不存在的目录名称。不会覆盖模板、CSV或已有目录。可单独预览并保存完整JSON缺字段报告。
6. 修改模板/CSV/映射/必填会废弃旧样稿；处理中可取消内存处理。切换/暂停后重新选择输入；保存已提交时不会自动撤销主进程写入。

## 6. 具体可重放例子

在普通Word文档主段落/表格中填写：`成员 {{name}}，职务 {{role}}。`。Word将name拆成 `{{na` 与 `me}}` 两个文字run仍受支持。保存普通 `.docx`，不要使用修订、域、内容控件、外部链接或页眉占位。CSV如下：

~~~csv
name,role
张三,成员
李四,组长
王五,讲师
赵六,
~~~

映射name→name、role→role，两项必填。读取校验→内存生成：记录1/2/3样稿分别为“成员 张三，职务 成员。”“成员 李四，职务 组长。”“成员 王五，职务 讲师。”；记录4物理行5是missing_required，缺role→role，路径null。确认创建新目录后仅有record-001/002/003.docx及完整report.json，没有record-004.docx。将role必填取消后重新生成，第四份填入空职务并在报告保留required:false；若重新选择已有目标目录，保存失败，已有字节不变。
