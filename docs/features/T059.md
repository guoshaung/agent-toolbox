# T059 错误堆栈本地 source map 映射

## 1. 功能内容

将用户粘贴的 V8 `at 函数 (文件:行:列)` / `at 文件:行:列` 堆栈与本地 flat version3 source map 对照，列出全部支持帧的原始项目路径、行列、可选名称及未映射原因。用户明确选择源码项目目录后，可逐条打开对应文件的完整定位行。支持完整 JSON / Markdown 预览和新副本保存，没有自动联网、执行源码或修改原文件。

## 2. 为什么需要

压缩或编译后的错误位置通常在生成文件中，人工查 map 很难核对原始位置。这个功能把映射与原始行查看放在同一页，保留未匹配文件、缺 map、缺片段和未选源文件等不同情况，避免把缺失结果当成功。生成文件与 map 是否属于同一版本仍由用户核对，映射位置不能自动证明错误根因。

## 3. 实现方式

不新增第三方依赖。严格 JSON 解析拒绝重复键、无效 Unicode、非有限/不安全数字；支持 version3 的单一 flat map，不支持 `sections` index map。Base64 VLQ 用有限32位整数解码，包括规范中的 `B` 对应 −2³¹ 特例；generated 列在每行归零，source、original 行列、name 索引在行间累计。每个片段为1、4或5字段；同一行 generated 列必须严格递增，重复列整份拒绝，这比允许重复位置的 map 更严格。

输入和显示行列均为1起，列按 UTF16 code unit；map 内部行列为0起。同一生成行选择不大于输入列的最后一个片段，返回该片段的原始列，不按生成列差插值，不向前一行回退。单字段未映射片段会阻止更早映射继续生效。CRLF / CR / LF 源码换行按一行分隔，源码列允许行尾后一列；越界明确提示。一个 emoji 通常占两个 UTF16列。

用户必须填写 map 与对应生成文件在同一项目中的相对位置，`map.file` 仅作为声明展示，不自动选目标。堆栈生成路径允许 URL 前缀或 Windows 绝对前缀，只做字符串路径匹配，不打开 URL；含百分号编码的 URL 路径不匹配。`sources` 与 `sourceRoot` 相对 map 所在目录解析，`.` / `..` 归一后必须留在项目相对范围。URL、webpack路径、盘符、绝对源路径、编码路径、反斜杠或目录穿越均拒绝整份 map，不选择性跳过不支持 source。源文件名可含普通空格与 Unicode。`sourcesContent` 仅校验结构并标记忽略，永远不拿它充当用户选择的源码；未知扩展字段列名展示并忽略，不解释其语义。

map≤256KiB UTF-8、JSON≤8层/3000节点；堆栈≤16KiB/100行，sources≤200、names≤500、generated行/片段各≤10000。源码目录选择只使用浏览器明确提供的集合，≤500文件；点击定位才读取对应 File，单个≤1MiB，成功读取的缓存正文合计≤4MiB。每次读取严格UTF-8，64KiB分块、长度核对及取消票据，不读取 File 所在目录的其他文件，不查 `sourceMappingURL`，不跟随网络引用。源文件不符、非法UTF-8或容量超限拒绝该定位行，不输出截断正文。

改变堆栈、map、位置或源码集合清空旧报告/定位行/缓存；取消、隐藏、离开、销毁使异步作业失效，旧回调不能重新显示。原生保存期间禁止编辑；取消/失败不报成功。没有输入、源码、map或报告自动配置保存、localStorage或网络请求。报告包括全部映射帧、忽略行编号/原因、map范围、原始路径/名称，但不含源码正文或完整原始堆栈头；帧中的 URL/路径/名称仍可能包含私人信息。

算法参照 [ECMA-426 source map 规范](https://tc39.es/ecma426/)，本文实现的是上述有限 flat 映射及同一行 greatest lower bound 查找，不宣称支持该规范全部扩展、所有堆栈方言、Rust DWARF或C/C++符号化。

## 4. 如何使用

1. 在工具工作台打开 T059，粘贴 V8 堆栈，填写对应生成文件相对路径，如 `dist/bundle.js`。
2. 选择本地 `.map` 或粘贴 JSON，填写它在项目中的位置，如 `dist/bundle.js.map`。文件入口会替换 JSON 内容，UTF-8 BOM在 map 文件入口明确移除；源文件正文 BOM保留参与列定位。
3. 可选“选择源码项目目录集合”，应选同一项目根目录。此时只建立范围，不读取源码正文。
4. 点击“映射完整堆栈”，核对每帧原始位置或原因。只有明确选中的原始文件才有可用“打开所选源码定位行”按钮；未选源码时仍展示映射坐标。
5. 选择 JSON 或 Markdown 完整预览，再“保存已预览报告新副本”，选择新的目标名。`copyOnly:true` 及公共防覆盖能力必须存在；仅 `ok===true` 提示成功，已有目标拒绝，取消/异常/失败保持预览。报告不含刚打开的源码行正文。

## 5. 产出与具体例子

“载入可复现示例”在内存生成三份练习输入，不从磁盘或互联网取得内容：

```text
Error: synthetic example
    at example (dist/bundle.js:2:1)
    at missing (other.js:1:1)
```

```json
{"version":3,"file":"bundle.js","sources":["../src/example.ts"],"names":["example"],"mappings":"AAAAA;AACA"}
```

源码 `src/example.ts` 第2行为 `  throw new Error("示例 🐱");`。map位置为 `dist/bundle.js.map`，生成目标为 `dist/bundle.js`。运行得到支持帧2、mapped1/unmapped1；第一帧→`src/example.ts:2:1`，第二帧原因 `generated_file_not_matching_explicit_selection`；Error头是忽略行1，单独列明而不冒充帧。点击定位显示完整第2行。JSON `source-map-report-copy.json` 和 Markdown `source-map-report-copy.md` 均含全部帧、原因、map范围和解释边界，没有源码正文。

若把 JSON清空，第一帧为 `no_map_provided`；若清空所选源码集合，坐标仍可映射，定位按钮显示“源码未选择”。若将 sources改成 `https://host/source.ts`，整份映射拒绝且旧报告清空。`AAAA,KAAK,K` 的第1行第8列取第6列片段，返回原始第6列而非插值第8列；第11列单字段片段为未映射，不能沿用较早结果。
