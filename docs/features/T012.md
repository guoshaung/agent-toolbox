# T012 文件分片与重组

## 1. 功能内容

本地选择单个文件，按用户选定大小生成有序二进制分片和版本化 manifest.json。分片、清单及原始总文件都有 SHA-256。重组读取清单和全部分片，逐片核对大小/摘要后按索引重组，再核对总摘要；完成后只预览，用户明确保存才写新副本。源文件不修改，无网络或代码执行。

## 2. 为什么需要

传输渠道可能限制单文件大小。只按名称拼接容易漏片、重复片、乱序或混入其他版本。此工具用固定名称、严格清单、逐片摘要与总摘要核对，使用户可以在发送和接收两端检查传输完整性。SHA-256用于完整性比较，不证明发送者身份；清单和分片都被替换时没有签名认证。

## 3. 实现方式

纯model.mjs使用File.arrayBuffer和Web Crypto SHA-256处理真实字节；按清单index顺序重组，不依赖选择文件的先后顺序。index.js通过公共h生成界面并接入生产preload；无新增包或其他功能运行依赖。

输入源文件最多8MiB，包含空文件；可选16KiB、64KiB、256KiB、1MiB、2MiB分片，最多99片。容量或片数超限整次拒绝，不静默截断或读取超限源。空文件用一片0字节part-0001.bin表示。名称仅有效文件名≤120 UTF-16单位，不允许路径、Windows保留名、非法字符、尾点/空格或孤立Unicode。

清单版本1固定包含feature/version/original/chunkSize/parts；原文件记录name/size/sha256，分片记录连续index、固定part-NNNN.bin、size/sha256。UTF-8清单≤32KiB，仅接受本工具生成的JSON缩进与末尾换行格式。按解析值重生成必须与输入逐字符相同，重复字段、未知字段、手改格式/调序/路径均拒绝，避免JSON解析静默覆盖重复键。请直接传递生成的manifest.json，不手动编辑。

重组必须选所有且仅有分片，不选manifest.json。重复/未知/缺失名称、实际读取大小与File.size/清单不符、任何单片或总摘要不符均整次失败，不发布半个文件。当前版不做超8MiB文件流式处理。读取和摘要在内存进行，分片之间让出事件循环并支持取消；底层arrayBuffer/digest不能物理中断，返回后丢弃过期结果。切换/隐藏取消在途处理，隐藏清除预览，切换功能销毁输入及文件引用；无配置草稿或自动磁盘保存。

分片及清单使用公共files.exportBundle(copyOnly:true)在全新目录写出，每片≤2MiB、目录总量≤10MiB。重组使用公共files.saveBinary(copyOnly:true/base64/sha256)保存≤10MiB单文件，主进程再核验SHA-256，独占wx拒绝覆盖已有文件。两个能力标记严格等于true且函数存在才启用保存；只有ok===true显示成功。保存目标在原生对话框核对，renderer不指定绝对路径。常规写入失败清理本次新副本，清理失败返回partialPath供人工核对；不承诺断电/进程崩溃事务。基础依赖PR #14，本功能不修改公共桥。

## 4. 如何使用

1. 打开工具→文件与批处理→文件分片与重组，选择源文件和分片大小，点击“生成分片预览”。
2. 核对原名/大小/总摘要和完整分片清单，点击“保存分片与清单新目录”，在另存对话框输入不存在的新目录名。
3. 将全部part-NNNN.bin和manifest.json交给接收方。接收方读取规范清单文件，再选择所有分片，不要把清单混入分片集合。
4. 点击“核验并重组预览”，确认全部片与总摘要一致。文件选择顺序可任意，重组按清单索引。
5. 点击“保存已核验重组新副本”，选择一个不存在的新文件名。已有源名文件拒绝覆盖，可以另选名称。
6. 错误后修复缺片/损坏片再重新核验；清单格式受改动时应重新获取原始清单。完成后清空。系统另存阶段通过系统对话框取消。

## 5. 产出和具体例子

构造5242880字节source.bin，第i字节为i%256；选择2MiB。预览应为三片：part-0001.bin=2097152字节、part-0002.bin=2097152字节、part-0003.bin=1048576字节。保存目录包含这三片和manifest.json。将三片按3/1/2顺序选入，重组仍为5242880字节，其SHA-256与原始清单相同，逐字节为原内容。选择相同保存目标再次保存拒绝覆盖。

删除第二片，或把第一片任意一个字节翻转，核验失败，重组保存按钮禁用；不会用剩余片假装完整文件。若各片摘要都正确但清单总摘要被修改，最终总摘要检查仍阻止输出。空文件生成一片空文件并可重组保存为空文件。

## 6. 验证与限制

10项专项模型测试覆盖5MiB→2/2/1MiB并独立node:crypto摘要及逐字节比较、空文件、规范清单/重复键/未知字段、索引/名称/大小/摘要篡改、缺片/多片/重复/未知/尺寸错误、同大小损坏及错误总摘要、容量/片数/危险文件名在读取前拒绝、实际File.size不符、读取及片间取消、UTF-8文件名和逆序选片。模型文件API由真实Node File及有限回调测试提供，不等于Electron界面验收；实际DOM/FileAPI/生产bridge证据另记录。

当前实现不支持超8MiB流式分片、压缩/加密、签名认证、断点续传、其他软件的分片格式或原地覆盖。Base64传输给主进程和原生摘要核对存在内存开销，限额不意味着大文件性能证明。原生文件对话框、完整应用与打包需独立验收。

真实 Electron33.4.11 验收：生产工作台/目录发现/preload/IPC、registerBundleIpc及registerBinaryIpc参加；真实File/DataTransfer输入5242880字节原始.bin。实际新目录写出3片（2097152/2097152/1048576）及清单，分别用Node crypto独立摘要核对。读取磁盘清单，按3/2/1逆序选择实际分片，重组并实际保存5242880字节，逐字节与原始向量一致，SHA-256为2e7cab6314e9614b6f2da12630661c3038e5592025f6534ba5823c3b340a1cb6。缺片及同大小损坏片拒绝时二进制目录/文件选择API调用0；重复目录及重组文件目标均拒绝、磁盘原字节未变。清空及HTTP/HTTPS请求0检查通过。证据：隔离集成 work/electron-smoke-1790970737387/result.json及真实产物。配置/目标是测试夹具，未操作系统对话框；全主应用及打包未验证。
