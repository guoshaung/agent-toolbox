# T076 磁盘容量去向诊断

## 1. 功能内容

只读统计用户明确选择的一个目录中普通文件的路径逻辑大小，按子树排序展示目录、直接文件字节、子树文件字节和支持范围状态。每行一个精确相对排除路径，可排除该项及子树；链接、特殊文件、失败和未运行项有完整记录。报告先预览，另存完整 JSON 或 Markdown 新副本，不删除或改写任何源文件。

## 2. 为什么需要

目录变大时，用户需要知道已观察的大文件和子目录在哪里，才能自己回源检查。路径逻辑大小、磁盘分配块和可释放空间是不同量：硬链接会出现多个路径，压缩、共享块、快照及文件系统其它占用也影响磁盘空间。本功能把已知与未知分开，避免把部分统计或文件大小误作清理收益。可用于项目缓存、下载目录和素材目录的人工诊断。

## 3. 实现方式

渲染端通过公共可信 Host 桥调用本功能固定 choose_root / scan 操作。主进程的目录选择器绑定发起窗口，只接受一个普通绝对目录；最终根链接及 Windows UNC/设备路径不支持。选中路径经 lstat/realpath/stat 和身份/mtime检查生成窗口内 opaque token，扫描输入只含该 token、排除规则和独立任务号，不接受渲染端任意绝对路径。选择目录本身不扫描。

Host 逐个目录使用 opendir(bufferSize:32) 与 Dir.read，逐个项只读 lstat 元数据，不读取正文、不执行命令、不调用网络。先检查排除，再读取目标元数据；不跟随最终文件/目录链接，包含外部 junction 和自循环链接。目录前后身份/mtime及 canonical path检测普通变化，有限安全 dev/ino 去重；没有锁目录，不宣称抵御恶意并发换链。普通挂载点或映射驱动器的实际存储本地性未知。

最多10000已读取项、1000已排队目录、24层、1MiB记录路径和30秒协作期限。任何限制到达都明确部分状态，保留所有已观察前缀及未运行目录，不截断后声称完整。达到10000项时为保守限制，不继续读取EOF来证明恰好只有10000项。OS目录调用不能硬中止；取消与销毁标记自己任务，窗口忙状态保持到等待调用结束，所有已打开 Dir 在 finally 请求关闭。关闭失败单列未知。不自动重试。

普通文件逻辑大小按每个路径的 st_size 累计，安全整数溢出整份拒绝；硬链接各路径分别计。目录聚合从子节点回传父节点，子树彼此重叠，不能相加所有表行。Linux 的 st_blocks 按512字节块换算，见 [Linux stat 类型文档](https://man7.org/linux/man-pages/man3/stat.3type.html)；其它平台保留原块字段但不猜单位，不从逻辑字节推算分配字节，见 [Node 20 文件系统 Stats 文档](https://nodejs.org/download/release/v20.18.3/docs/api/fs.html)。分别给出已知每路径块、分配未知文件数及 dev/ino 去重已知子集；身份冲突保留未知。均不包含目录/链接/特殊项、共享 extents、快照及其它文件系统占用，也不是可释放空间。

排除规则完整文本最多4096 UTF8字节、32条，每条≤512字符/16段/每段128字符。以 / 分隔，精确匹配或子树匹配，Windows大小写不敏感；不支持 glob/正则、绝对路径、点段、设备保留名、反斜线或控制字符。空行忽略，重复规则拒绝；其它目录同名子项不会被自动排除。

目录表每页40项，仅显示分页，全部文件/目录/排除/失败仍在完整报告。规则编辑使旧报告失效。离开、隐藏或销毁取消自己任务并清除根选择和报告，返回需重新选择，不自动扫描；不向配置保存目录或报告。异步结果用生命周期票据拒绝迟到回显。Host、复制能力缺失及 false/undefined/canceled/throw 保存回执不冒充成功。

## 4. 如何使用

1. 打开新增功能工作台，搜索 T076，点击“选择允许只读统计的目录”，在系统选择器选择一个目录。
2. 核对根路径。需要排除项目根内 cache 时输入 cache；需要只排除 A/cache 时输入 A/cache。每行一条，不使用通配符。
3. 点击“开始选定范围只读统计”。需要停止时点击“取消当前容量统计”，等当前目录调用结束。
4. 查看已观察逻辑字节、分配未知文件数、目录排序和部分原因；下一页查看更多目录。先核对排除与失败，不把所有子树行相加。
5. 点击“预览完整JSON报告”或“预览完整Markdown报告”，核对全部路径后“保存已预览容量报告新副本”。已有目标文件拒绝覆盖。

没有额外系统修改许可步骤；扫描只读元数据。报告含本地根路径和文件名，分享前可自行检查。

## 5. 使用产出与具体例子

完整 JSON 含根来源、排除规则、平台、任务及起止时间/单调耗时、取消或限制原因、支持域完整状态、所有文件元数据、所有目录聚合、链接/特殊项/排除/失败、已知与未知分配统计和人工诊断建议。Markdown含全部目录表及完整JSON代码块；两种完整报告分别≤8MiB，超限整份拒绝，分页不影响副本。生产文本写入器以 copyOnly:true 独占创建新目标，只有 ok:true 显示保存成功。

自编目录 A/sample.bin=100字节、B/sample.bin=200字节、C/sample.bin=300字节，总逻辑字节600，根与A/B/C共4目录。排除 B 后剩400、2个文件、根与A/C共3目录，B记录 excluded，支持域完整是“排除后的支持域”，不是原全部目录。Windows三文件的 allocatedBytes 均 null，未知文件3；已知子集0不表示磁盘分配为0。

再添加 A/hardlink.bin（A/sample.bin同一文件的另一名字）及45个一字节目录文件，逻辑大小为100+100+200+300+45=745，共49文件/49目录；40项第一页、9项第二页，导出仍含全部49文件及最后的 dir44/one.bin。两个 junction 分别指向根外999字节文件和自身循环，均只记 link_skipped，不增加统计。
