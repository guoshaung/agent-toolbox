# L004 预测观察对账

## 功能内容

这是一份本地的预测账本。先登记数值或枚举预测，提交时自动记录本机时间并锁定该版本；之后把观察绑定到一个明确的预测版本，追加观察值、实际观察时间和说明。界面即时展示偏差和时序关系，并允许导出整个账本。

功能对应 `docs/feature-planning/learning.json` 中 L004，分类为学习，分组为主动学习与理解。核心无需 AI、网络账户或外部运行时。

支持新主题预测、同主题版本修订、多次观察、缺测登记、历史版本对照、JSON 原始报告和 Markdown 复盘。修订只追加版本，已提交的预测和观察都没有覆盖编辑或删除操作。观察填错时可以追加一条附有更正说明的新观察，原记录仍保留。

## 为什么需要

知道结果后，人容易把自己原先的判断记得更接近答案。“我之前就这么想”的感受，不能代替事前留下的预测。把提交前的数值、理由和时间保留下来，再与观察独立对账，可以看见判断在哪些条件下偏高、偏低或完全不同。

这项工具记录认知过程，不是代码运行器，也不根据已知结果倒推预测。实验条件和背景可放进主题与依据，观察说明用于解释测量过程。使用者仍需自行确定实验设计和数据真实性。

## 实现方式

`meta.json` 声明工作台入口，`index.js` 导出 `{ id: 'L004', create(root, ctx) }`。同步 `create` 返回激活、切走与销毁句柄。所有用户字段通过文本节点或表单展示，不将其拼入 HTML。

`model.mjs` 是独立纯模型，负责数值/枚举校验、预测版本追加、观察追加、时间校验、偏差计算、状态恢复和报告生成。界面提供两个结构化登记区与历史对账区，不要求手写 JSON。

每条预测有唯一编号、主题编号、版本号、上一版本编号、类型、原始输入文本、规范化值、单位、预测依据及提交时间。修订只允许从该主题最新版本追加，沿用类型、单位、枚举池和主题，改动预测值与依据。它不会把后来版本的观察挪到旧版本，也不会将旧观察自动重新挂到新版本。

每条观察记录预测编号、原始值、规范化值、单位、缺测状态、说明、实际观察时间和登记时间。实际时间由用户输入，本机登记时间自动生成。报告同时导出两种时间，避免把补记时间当成实验发生时间。

### 偏差口径

| 情形 | 处理 |
|---|---|
| 同单位有限数值 | 差值 = 观察 − 预测；绝对误差 = 差值的绝对值 |
| 非零预测 | 相对偏差百分比 = 差值 ÷ 预测绝对值 × 100 |
| 预测为零 | 仍计算差值和绝对误差；百分比显示不计算，并说明“预测为零” |
| 单位不一致 | 显示不可比较，不自动做单位转换 |
| 枚举预测 | 只比较标签一致与否，不计算数值差或百分比 |
| 尚未观察 | 单列待观察预测，不把观察值补成零 |
| 明确缺测 | 必须填写原因，原始值与规范化值为 null，不计算偏差 |
| 差值或百分比溢出 | 返回 null 并解释超出数值范围，不在 JSON 中写入 Infinity |

数值支持带符号小数与科学计数法，不支持千位逗号、十六进制、NaN 或 Infinity。原始输入文本仍保留。运算采用 JavaScript 双精度浮点数，可能出现小数表示误差，不提供任意精度算术。

枚举在第一次提交时定义 2 至 30 个不同标签；预测和观察必须属于该版本的标签池。若实际结果可能超出预期，应事先加入“其他”等标签，并在说明中保留细节。修订沿用原枚举池，不能悄悄改变历史判定口径。

### 时间界限

- 提交时间是本机自动时间，界面不能填写或改写它。
- 实际观察时间由用户填写当地日期与时间，界面明确标注本机时区，存储统一为带 Z 的 UTC 时间。模型只接受带时区的有效日历时间。
- 实际观察时间晚于本次登记时间时拒绝追加，不能把未来结果当成已发生观察。
- 实际观察时间早于预测提交时允许回补，但显示“不能作为事前预测证据”。数值仍可对账，该时间标记与计算结果分别展示。
- 修订提交时间不得早于前一版本提交时间；发现时钟倒退时提示检查本机时钟，不修改系统时间。
- 某版本提交前已登记同主题观察时，报告标记这一事实，提醒结合实际时间识别事后修订。该指标比较登记与提交时间，不推断尚未登记但实际已发生的观察。
- 本机时间与用户填写时间不是可信时间戳，配置也没有数字签名；这里的“锁定”指应用正常操作下不覆盖原记录，不是防篡改证明。

### 保存与生命周期

状态保存在 `features.L004.state`，包含 `schemaVersion: 1`、账本、选中的版本和未提交草稿。每次保存前用 `TextEncoder` 测量完整 JSON 的 UTF-8 体积，只允许不超过 64KiB，即 65536 字节。恢复时也先校验版本和体积，再检查预测关系与观察内容。

超限后不调用全局配置写接口，不覆盖较早的小型状态。独立提示说明当前内容尚未保存、关闭后可能恢复旧记录，以及应导出整个账本；普通进度或导出成功消息不会覆盖这条提示。完整报告导出不受此配置限额限制。

输入有 250 毫秒保存去抖。切走和销毁清理计时器，并在同一体积规则下尝试保存；销毁同时移除局部页面与样式。页面没有后台采集或轮询。无配置接口时，只能在当前组件实例中保留账本。

## 使用步骤

1. 从功能工作台进入“预测观察对账”，填写预测主题，选择数值或枚举类型。
2. 数值填写预测值及单位；枚举先填写标签列表，再点“刷新标签列表”并选择预测标签。可附上自己的判断依据。
3. 点“提交并锁定预测”。历史区会显示版本编号和本机提交时间，观察区自动选中这个版本。
4. 真正观察后，填写观察值、单位、实际时间和说明。可点击“填入当前本机时间”；缺测时勾选缺测并写原因。
5. 点“追加观察并对账”，核对差值、绝对误差、相对偏差与时序标记。记录不会因下一次观察而覆盖。
6. 想修改预测时，在历史区选择该主题最新版本的“追加修订”，填写新值与新的依据，点“提交新版本，保留旧版”。旧版仍可观察、回看和导出。
7. 用“导出整个账本 JSON”或“导出 Markdown 对账”保留所有版本。需要清空当前账本时，点“导出成功后新建账本”，只有文件成功保存后才创建空账本；取消或失败不清空。

任何预测版本都可以通过观察区下拉框或历史区“对账 pN”选中。当前主题的新版本与旧版本具有独立观察集合，选择时须核对编号。

## 产出

JSON 包含报告标识、计算口径、时间说明、全部预测版本、全部观察、逐观察对账结果和待观察预测编号。预测原始值、版本链、提交时间、观察实际时间与登记时间均保留。Markdown 按预测版本分节，适合笔记或实验复盘。

导出使用基础层的 `files.saveText({ content, extension, defaultName, copyOnly: true })`，先检查 `saveTextSupportsCopyOnly`。系统对话框让使用者选择新文件；基础层以新建方式拒绝已有目标，保存取消或失败会显示原因，账本仍在当前页面中。

## 可复现例子

点击“载入数值示例”，得到主题“纸桥承重示例”、预测 `10`、单位 `g`。提交后，点“填入观察13示例”，再追加观察。

结果为：

- 差值：`13 − 10 = 3 g`。
- 绝对误差：`3 g`。
- 相对偏差：`3 ÷ |10| × 100% = 30%`。

接着点“追加修订 p1”，将预测改为 `12`，提交得到 v2。为 v2 追加 `13 g` 观察，其差值为 `1 g`，而 v1 仍保留预测 `10 g` 和原观察的差值 `3 g`。

导出 JSON 时，`predictions` 中两条值分别是 10 与 12，第二条的 `revisesId` 指向 p1；原来的观察仍绑定 p1，不会变成差值 1。如果将实际观察时间填成早于 v2 提交，则 v2 的这条观察会明确标为回补。

其他边界例子：预测 `0 g`、观察 `3 g`，差值 3、百分比不计算；预测 `10 g`、观察 `13 kg`，单位不一致而不计算差值；缺测并说明“仪器无读数”，值为 null 而不是零。枚举预测“上升”、观察“下降”，结果为标签不一致。

## 限制

- 每账本最多 200 个预测版本、500 条观察；达到上限可导出成功后新建账本。
- 主题最多 200 字符，数值原文及单位最多 100 字符，预测依据及观察说明最多 2000 字符；单枚举标签最多 100 字符。
- 配置总状态上限 64KiB，仍在字段范围内的大型账本也可能超过上限。超过后仅保留在当前页面，不能承诺关闭后恢复；需导出完整账本。
- 不提供 AI 推断、自动测量、联网取数、统计检验或单位换算。多条观察逐条对账，不自动平均或替代旧记录。
- 不提供 JSON 文件重新导入；导出用于独立保存和查看，本机恢复仅针对合法版本的应用配置。
- 用户填写的实际时间和本机时钟可能不准确；仅显示可观察的时序差异，不提供外部可信时间或签名验证。
- 枚举采用明确字符串标签、数值采用双精度浮点，不能自动判断标签同义关系或精确表达所有小数。
