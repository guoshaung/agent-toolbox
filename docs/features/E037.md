# E037 写完放下

## 1. 功能内容

一个离线临时写字页。用户可以写下当下牵挂，核对全文预览，再明确选择保留PNG文字卡或TXT正文副本，或者勾选确认并放下。没有计分、心理分析、AI、网络或自动存档。放下后的收尾只包含12片没有文字的纸片，最多播放1.2秒；手动减少动效或系统 `prefers-reduced-motion: reduce` 时显示静态纸片。

## 2. 为什么需要

临时记录可以有一个明确结束点，不必进入长期笔记系统。保留和放下是两项独立决定：成功保存后正文仍在当前页，需要用户再明确放下；已保存副本不会被自动删除。界面开头明确说明切走功能、隐藏窗口或关闭会清空未保留正文，因此不将临时输入伪装成可恢复日记，也不作治疗或情绪改善承诺。

## 3. 实现方式与容量、清理边界

`model.mjs` 校验原始字符串，不trim、不转HTML；最多8000 Unicode码点、32768 UTF-8字节，拒绝孤立代理字符和不可显示控制字符，仅允许制表符/常规换行。UI在输入时拒绝超限或无效输入，恢复上一份合法正文，不截断。原生textarea按浏览器规则将输入换行规范成LF；TXT保存的是当前textarea的完整值。纯模型接受CRLF、CR、LF、U+2028和U+2029并明确分行，保留空行和末尾换行。

全文预览使用文本节点，长行折行但不删字。PNG依赖浏览器Canvas 2D与 `Intl.Segmenter` 组合字符分割，22px本地微软雅黑/Segoe UI Emoji回退字体，32px行高、1000px宽、896px正文宽。每个逻辑空行也占一行；制表符在卡片中显示为四个空格，TXT仍保留制表符。逐行扩展高度，最后一行和页脚始终有留白，不在固定画布上裁切。单个组合字符宽度超过正文栏时拒绝PNG；本机缺少Segmenter、画布或字体测量失败时明确报错，仍可保留TXT。换行不进行语言学断句或标点禁则排版。

PNG生成前限制高度≤16000px且像素≤1200万（1000px宽时实际高度≤12000px），避免8000空行产生巨型位图；编码后再核验PNG签名、完整字节≤10MiB、SHA-256和规范Base64。不压缩正文、不截断卡片；超预算只拒绝PNG，全文文本预览与TXT仍可使用。8000连续中文字符的全量换行在模型测试覆盖，实际中文和组合emoji字体栅格另有Electron证据。字体实际外观可能随操作系统改变。

正文只存在于当前textarea、模块临时字符串、全文预览、布局行、画布和当前本地编码作业，不调用config、localStorage或sessionStorage，不创建Blob URL、不设置正文标题或属性，没有自有撤销栈。放下/隐藏/deactivate/destroy会：废弃异步代次、清空正文和布局数组、清空预览与旧textarea值、移除旧节点监听并换新textarea，清除画布像素并将尺寸归零，释放作业中的文本/Blob/payload/画布引用，停止收尾RAF。换节点避免在当前输入框通过浏览器撤销重新出现旧正文。没有读取或迁移任何旧正文缓存键，也不擅自清理其他功能数据。

这些措施只承诺本模块引用、DOM和缓存不再包含正文。JavaScript引擎、浏览器内部编码/撤销记录、操作系统内存、剪贴板、截图以及用户已保存文件都不提供安全擦除保证。异步Canvas编码/SHA调用不能中止底层执行；代次检查会忽略旧返回，不再调用写入器或把正文带回当前页面。已开始原生保存时锁住正文、保留及放下，防止回调恢复旧状态；离开/销毁仍会清空并忽略后到结果，但已经写出的副本不自动删除。无RAF常驻动画，create/activate不会自动播放。

## 4. 如何使用

1. 在娱乐工作台打开“写完放下”，输入正文，检查字符数和UTF-8字节数。
2. 滚动“全文文字预览”核对所有段落，点击“生成全文文字卡预览”核对实际字体、折行和最后一行。
3. 若要保留，点击“保留完整PNG副本”或“保留全文TXT副本”，在原生对话框选择新的文件名。需要公共基础 `c0c93aa` 的 `saveBinarySupportsCopyOnly` 和已有文本副本能力；缺少能力时按钮禁用。
4. 成功、失败或取消保存都保留当前正文。另存正在进行时暂时不能编辑或放下。取消原生另存不是清除正文。
5. 要结束当前文字，先勾选“确认放下并清空当前文字”，再点击“放下并清空”。不勾选则提示确认，保留正文。减少动效随时可选，也尊重系统偏好。
6. 切走、隐藏或关闭会清空当前临时文字；返回是新的空白页。要保留内容，应先主动另存并检查成功提示。

## 5. 产出与具体可重现例子

文件名为不包含正文的 `write-and-release-card-N-copy.png` 或 `write-and-release-text-N-copy.txt`；N是当前实例的保存序号。所有写入都要求 `copyOnly:true`，已有目标拒绝；只有 `ok===true` 报成功，取消单独提示，失败/`partialPath`要求人工核对。TXT是完整当前UTF-8正文，不额外加标题、日期或BOM。PNG包含固定标题、全部正文和固定页脚。

在输入框粘贴下面内容（最后保留一个换行），先生成预览再保存两种副本：

```text
今天先记下这件事。

👨‍👩‍👧‍👦 家人　🌿 休息
最后一行 🐱

```

预期空白段落和末尾空行保留，家庭emoji按组合字符换行；TXT原样保存。未勾确认直接放下仍能看到全文；勾选后放下，正文/预览为空，旧卡片消失，仅显示无文字纸片。重新进入或重新加载仍为空。已有PNG/TXT文件保持原样。

边界例子：8000个“长”正常全量预览/模型布局；8001个字符被拒绝且保留上一份合法正文。7999个换行在正文限额内，但全文PNG超过像素预算而拒绝，TXT仍可完整另存。这是明确拒绝，不输出部分文字卡。
