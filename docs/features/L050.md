# L050 长句负担体检

## 1. 功能内容

本地工具接受一份用户粘贴或编辑的文本、人工来源名/出处说明、字符长度与括号深度阈值。按字面中文句号 `。` 和英文句号 `.` 分段，输出完整句长分布、每段最大括号层数、长度/深度超额及原句原位置；可点击定位全文选区。有限中英括号栈另外记录孤立闭括号、错配、全文末未闭合、跨句成功配对。

完整实现 catalog L050 MVP：用户文本和两类阈值、句长分布/层数/超阈原位置、10/25字与阈20验收。无需AI或网络。首版单份文本编辑器，没有文件导入：人工粘贴不修改外部TXT/MD；来源名与出处由用户提供，空项显示未知。摘要为当前字符串UTF8 SHA256，不证明外部原件字节、作者身份或出处真实性。

## 2. 为什么需要

长度和嵌套位置可以帮助用户选择待核片段，再自行判断是否拆句或改写。输入相同且阈值相同，指标可重复核对。阈值只是用户设定；没有未经验证的阅读年级、可读性、语法评分或认知负担评估，不自动纠错、润色，也不判断跨句括号是否错误。

## 3. 实现方式

`model.mjs` 是无DOM的有限扫描器；`index.js` 提供真实文本/数字控件、异步分析/取消、原文定位、分页筛选、完整预览与副本导出。`meta.json` 由生产catalog发现，样式使用实际项目主题变量。

分句和计数口径：只按字面 `。` 和 `.` 分段，不猜缩写、小数、引号、Markdown代码语义。`1.25 Dr.X` 固定为 `1.`、`25 Dr.`、`X` 三段。问叹号和换行不分段。原句raw含分隔句号，长度排除该句号；所有其他标点、空白、BOM、CR、LF均计码点，CRLF在长度中计2。连续句号产生0长段；末尾非空文本（包含纯空白）保留，以句号结束不另加空尾段；空全文为0段，最小/最大/均值/中位数未定义。

长度计Unicode码点，不是UTF16码元或可见字形；emoji `🙂` 长1、占2 UTF16码元，`e`加组合重音长2。阈值相等不超，超额为 `max(0,指标−阈值)`。位置是原全文UTF16半开区间 `[start,end)`，另给内容末端；行/列从1开始，CRLF算一个逻辑换行，列为UTF16而非视觉列。textarea把CRLF/CR转换LF时，定位映射到控件边界，报告和SHA保留未编辑的恢复原文。编辑后以新控件值为来源，旧结果全部失效。

括号只支持 `()`、`（）`、`[]`、`【】`、`{}` 五种严格配对，中英不可混配。全局栈跨句继承，每段记录进入/最大/离开深度。错配闭括号记录所需闭括号、栈顶开位置，不弹栈；无栈闭括号单列，全文末残留开括号分别记未闭合。跨句成功配对只记录事件，不判语法错误。每段最大层数含进入本段时的继承栈，完整报告保留所有问题及成功配对原偏移。

上限：全文20000码点、2000规则段、4000括号字符、128真实层；长度阈0–20000、层数阈0–128均整数，空值无效。完整输入JSON≤256KiB，JSON/MD输出各≤2MiB；任何超限整份拒绝，不截断假完成。扫描每256码点异步让出，摘要完成/检查点和编辑/取消/隐藏/离开/销毁均校验票据，迟到任务不能发布；恢复页面不自动分析。没有音频、摄像头、网络或轮询任务。

草稿schemaVersion1只存来源/全文/阈值，不存派生报告、位置、hash；完整草稿≤64KiB才进入单通道最新值队列，恢复也校验版本/体积/字段。大输入明确提示不保存，关闭只能恢复较早合法草稿。用户文本通过文本节点展示；Markdown转义HTML并动态加长围栏。导出冻结完整报告，要求生产saveText防覆盖能力严格为true、`copyOnly:true`与`ok===true`，不写回来源。

## 4. 使用步骤

功能工作台打开L050，填人工来源/出处（未知可空）、粘贴全文并设阈值，直接点击“分析句长与括号规则”，无需额外确认。核对总段数、超阈ID、固定数值箱、完整精确频数；原句表展示长度超额、层数及原位置。点击“定位Sxxx原句”选中编辑器的实际片段，括号问题也能单独定位。

每页50段，可切页或按长度/深度/括号问题筛选；显示过滤不影响完整导出。展开括号问题/跨句配对及完整JSON/Markdown预览，然后导出副本。保存取消保留报告，防覆盖拒绝不会声称成功。任一来源/阈值改动清旧报告，需要主动重新分析；分析期间可取消，隐藏/离开丢弃迟到任务。整份示例替换有明确保留/确认选项。
