# T048 媒体轨道检查与重封装

## 1. 功能内容

工具工作台 T048 检查一个本地 MP4 的全部音视频和字幕轨道，显示实际 stream.index、编码、语言和标题。用户按源索引选择需要保留的轨道，再确认固定执行计划，生成不重编码的 MP4 新副本和完整 JSON 报告。唯一视频必须保留；音轨和字幕可选择移除或保留。两条语言相同的音轨仍是两条独立轨道，不通过语言猜测它们相同。

支持域：源 1 字节至 64MiB、最长 120 秒；唯一 H.264/yuv420p 视频，2–1920×2–1080、平均帧率大于 0 且不超过 60、方形像素；0–4 条 AAC 单/双声道、8–48kHz；0–1 条 mov_text 字幕，最多 6 轨。要求轨道零起点（容差 1ms）、自包含 MP4。本版整体拒绝其它编码、章节、封面/数据轨、旋转、HDR、外部引用、网络源、UNC 和链接路径。输出必须小于 64MiB，超过则完整失败，没有部分成片成功标志。

## 2. 为什么需要

包含不同语言解说或字幕的文件可能只需要其中一条轨道。重新编码会消耗时间，也可能改变画面和声音。T048 在兼容编码域内直接复制选中轨道，并核对实际输出；例如删除第一条音轨而保留第二条中文音轨，结果由实际源索引和哈希证明，而不是只改扩展名或报告。

“无损复制”指保留轨道的编码包内容和编码配置不变，不表示输出文件所有字节与原件相同。封装结构和轨道索引会改变，丢弃的轨道不会出现在成片；全局元数据和章节不复制，也不提供隐私匿名保证。标题的容器支持可能不同，报告保存原始标题和实际输出标题；语言必须一致，否则不宣告成功。

## 3. 实现方式

本功能私有 model.mjs、host.cjs 和界面，依赖基础 PR #14 的生产 Host 注册器/预加载桥，不引用其它 feature 的运行文件。不新增共享 npm 依赖、全局 CSP 或打包配置。只在 Windows 使用用户自己信任目录内的 ffmpeg.exe、ffprobe.exe。可预览固定默认 C:\\ruanjian\\ffmpeg\\bin 目录计划，也可原生选择安装目录；路径不由 renderer 自由传入。必须先确认三次查询：两个程序各 -version，FFmpeg -muxers；本版接受 6.x 且要求 mp4 和 streamhash 封装器。每次运行检查引擎文件身份，选目录不等于程序安全认证。

选择源后先确认固定 FFprobe 检查。只读 ISO-BMFF 箱遍历验证每个 dref 仅含一个自包含 url 引用，深度最多 8、箱数最多 2048；FFmpeg 参数固定 file 协议、禁外部引用。语言/标题最多 128 Unicode 码点，控制字符和不良 UTF-16 拒绝。源/输出 SHA、大小、文件身份反复检查，旧计划不能用于已改变的来源。

生成前的报告完整列出所有原轨道与 selected；未选中轨道可通过两者对照明确核对。保留轨道按原 stream.index 升序映射为输出 0..n-1。五个固定进程依次源 FFprobe（5秒）、所选源轨道 streamhash（10秒）、复制重封装（60秒）、输出 FFprobe（5秒）、输出 streamhash（10秒）；进程期限合计 90 秒，文件检查另行执行，不宣称整个事务有单一90秒计时器。每进程 stdout+stderr 最多 128KiB，产物每100ms检查大小，另用 -fs 限制。没有用户 shell、任意 argv、滤镜或重新压缩入口。

编码固定 `-map 0:源索引 -c copy`，全局元数据取消后显式映射每条保留轨道的元数据。MP4 固定 +faststart，并使用 `-write_btrt 0`，避免在已有 mov_text 编码配置后再添加重复码率箱；该参数依据 [FFmpeg 官方 MOV/MP4 封装器文档](https://ffmpeg.org/ffmpeg-formats.html)。验证不放宽：实际轨道数量、类型/编码、视频几何/帧率、音频采样率/声道、语言、extradata SHA、每条压缩包拼接 SHA 均必须与所选来源一致；时长容差 100ms。streamhash 是编码包验证，不是解码像素相似度指标。

任务/来源/计划/结果绑定 sender 与随机 token；取消等待自己的子进程 close，未关闭时不释放并发槽。切走、隐藏、销毁清空来源/成片/报告并清理自身临时文件；返回不会自动读取或执行。临时结果闲置约15分钟清理，崩溃或断电不承诺恢复。只有工作台最近使用信息持久化，没有媒体路径、轨道选择或报告自动草稿。

## 4. 如何使用与具体例子

1. 打开 T048，选择自己信任的 FFmpeg6.x 安装目录或预览默认路径。检查两程序路径与查询计划，确认运行版本/封装器查询。
2. 选择本地 MP4，点击确认只读轨道检查，核对原文件 SHA、时长和全部轨道。
3. 勾选保留轨道，预览完整轨道复制计划，再点击“确认无损复制所选轨道”。任何选择改变都会作废旧成片和旧报告。
4. 对照完整实际报告，播放实际成片；默认静音，声音需要自己打开。核对全部所选/丢弃轨道后勾选确认，再点击创建新目录副本。
5. 原生保存对话框填全新目录名称。已有文件/目录和原路径拒绝，不替换原件。

可复现例子：一个2秒、320×180/30fps的 MP4 有源轨道0 H.264 红色画面、源1 AAC 英语440Hz声音（language=eng）、源2 AAC 中文880Hz声音（language=zho）、源3 mov_text 英语字幕 “Track selection example”（0–1.9秒）。只勾选源0与源2后，产物 remuxed.mp4 实际22217字节、2秒/60帧，输出0是原视频，输出1是原源2 AAC，语言 zho；两条编码包 SHA 和配置 SHA 与来源相同。没有源1和源3。JSON mapping 明确 sourceIndex:2 → outputIndex:1。

再保留0/1/2可得到两条AAC的成片；保留0/2/3则保留中文音轨及字幕；只保留0得到没有凭空音轨或字幕的视频。源示例 SHA `b3fc993b178b7a9d4f4d78786392a97a32089ef2704afbbc44ffbc7df10699ee` 始终不变。

## 5. 使用产出

每次成功保存是一个独占新目录，包含完整 remuxed.mp4 和 UTF-8 track-report.json。报告格式 T048-track-report/version1，包含原名称/字节/SHA/全部轨道、selected、原/输出索引 mapping、实际输出媒体属性和每轨编码 SHA、实际时长差、固定执行参数/期限、sourceUnchanged 与 complete。报告不嵌原媒体；分享时自行判断原名称/语言/标题等信息范围。

成片须实际在 Chromium 加载并显示与报告一致时长，用户核对报告后才可保存。Chromium默认只播首音轨，不保证展示 mov_text 或允许切换其它音轨；完整保留情况由实际轨道校验报告验证，需要检查其它轨道时在另存后使用自己的播放器。不会把只看默认音轨称为已听完所有音轨。

保存前再核对源 SHA 与临时产物身份/SHA，原生主进程创建全新目录，视频使用 COPYFILE_EXCL、报告使用 wx；全部文件读回大小/SHA后才返回成功。界面仅接受 `ok===true`、`copyOnly===true` 及完整一致文件回执。取消、失败、false/undefined回执不会显示保存成功；可保留既有预览再次检查。失败后的部分新目录在返回的 partialPath 中明确提示，不承诺跨文件系统原子事务。
