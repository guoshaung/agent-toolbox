# L044 术语一致性检查

## 1. 功能内容

学习工作台「语言与表达训练」中的本地项目术语检查。用户导入1–5份TXT/MD，或粘贴可编辑原稿，再填写规范词、别名及人工依据。工具对原文做大小写敏感的精确子串匹配，列出全部出现次数、文件ID/文件名、原行、UTF-16列及原始区间，生成可审阅的替换预览和逻辑行diff。用户可逐处选中/取消建议，不改写任何来源文件。

每页25个候选；「只看重叠候选」只改变显示，不减少完整报告。术语统计包含零次出现的别名，依据为空显示「未说明」。同一位置或部分交叠的别名完整计数，但整组默认不选择；人工选择出现重叠时，建议报告失效并指出冲突，取消重叠后才能导出。

提供可见的完整原稿只读预览、原行/建议行并列表、完整逻辑行diff、JSON/Markdown报告预览，以及JSON、Markdown、diff新副本导出。编辑原稿或规范表立即清除旧位置和旧报告，需要主动重新检查。

## 2. 为什么需要

同一项目可能规定使用`agent`，而长文中混入`Agent`。人工搜索难以同时跟踪多个规范、多个文稿和重复位置；直接全局替换又可能改变代码、引文或另一个术语的局部子串。保留出处、列出重叠候选、逐处审核和保留原稿，让用户检查建议是否适用于该上下文。

这是用户规范表的可追溯约束检查，与中文纠错、术语问答、翻译或自动语言评分不同。用户填写的依据并未由本工具核验；空依据不是不存在标准。别名出现次数不能证明写作能力、语言认知、文本正确性或项目术语已全部一致。工具不自动猜测同义词，也不将任何词表认证为行业标准。

## 3. 实现方式

### 匹配、索引与建议

`model.mjs`严格UTF-8解码，文件须`.txt`或`.md`扩展名；不猜测GBK/UTF-16。SHA-256覆盖原字节，包括UTF-8 BOM。BOM仅在文本索引中移除，报告明确记录`bomRemovedForIndex`和原字节数；报告中的文本不是保留BOM的磁盘字节镜像。

匹配使用`String.indexOf`，按UTF-16码元索引；找到后将搜索位置推进一个码元，因此同一别名的重叠出现也计入。匹配口径依照[ECMAScript String.prototype.indexOf规范](https://tc39.es/ecma262/multipage/text-processing.html#sec-string.prototype.indexof)：字面子串查找，不解释正则、不做词边界、大小写折叠、词形还原或Unicode规范化。例如`AgentTool`包含一次`Agent`，而`agent`不命中`Agent`别名；`.*`和`$&`都是普通字符。MD中的代码块、链接和引文也按原文本检查，建议是否可采纳由用户判断。

原行按CRLF/LF/CR拆分，保留每行结束符。位置给出1起算行号/UTF-16列和0起算半开区间`[startUtf16,endUtf16)`；emoji等补充平面字符占两个UTF-16码元，因此列不是屏幕字形列或UTF-8字节偏移。末尾换行不额外制造一条没有字符的逻辑行。

每个来源内按照原区间排序，用区间交叠构建传递冲突组；相接但不重叠的两个区间可同时选中。替换预览仅基于原位置拼接一次，既不解释替换模板，也不重新扫描生成的规范词。例如A→B、B→C时，原文`A B`预览为`B C`，不会级联成`C C`。

建议文本保留索引原文的CRLF/LF/CR和末尾换行状态。diff采用`--- original/来源ID`、`+++ suggested/来源ID`、完整逻辑行hunk与`-`/`+`前缀，末行没有换行时给出标记。行级呈现参考[Git diff-format官方说明](https://git-scm.com/docs/diff-format)，但本功能的diff以LF呈现、路径是虚拟来源ID，且不复原BOM；它只是完整审阅文本，不能宣称是可自动应用到磁盘的字节补丁。程序没有执行git、应用补丁、保存建议原稿或写回来源的接口。

### 有界输入、取消和保存

- 文件1–5份，每份≤512KiB，合计≤1MiB；粘贴稿≤1MiB。文件名/人工来源名≤120 Unicode码点。
- 1–20项规范词，每项1–8个别名；规范词/别名为非空单行≤80码点，保留前后空白；规范来源≤160码点。拒绝重复ID、重复规范词、全表重复别名、别名与本项规范相同、非法控制字符和孤立代理字符。规范词可同时是另一项别名，仍只做一次原位置替换。
- 原行≤2048码点，全来源合计≤20000逻辑行，全部命中≤2000。建议文本每份≤2MiB；完整紧凑报告≤6MiB，格式化JSON和Markdown各≤12MiB。超过任一上限整份拒绝，不截断并假称完整。
- 初始/结束以及每4个别名或128个命中异步让出；取消、切走、销毁和输入编辑使票据失效，迟到读取/hash/扫描结果不生效。原生File读取和SHA计算本身不能强制Abort，UI明确等待当前任务释放后才能再次开始。文件组读取成功后才整体替换，读取错误保留此前完整集合。
- 配置只存`schemaVersion:1`规范表、输入模式和粘贴输入，整体UTF-8 JSON≤64KiB；恢复重新校验版本/字段/体积。未导入的原文件内容/名/hash、匹配、人工选择、diff和派生报告不写配置。大型粘贴输入仍可查询，但不保存全局草稿，关闭只能恢复较早合法输入；提示用户保留原文并导出完整报告。
- 配置队列每次仅一个在途和一个最新待写输入，旧回调不能遮盖新输入的校验提示。销毁清空来源/报告/选择和DOM；无自动播放、网络、AI或后台扫描。

导出要求生产桥明确提供`saveTextSupportsCopyOnly===true`，发送`copyOnly:true`，只有`ok===true`才显示保存成功。生产writer使用`wx`拒绝已有目标；没有防覆盖能力时不调用保存。零选择或零命中的diff导出提供非空说明，不伪造修改。报告包含完整原文，保存前应检查预览及目标新副本；导出不等于规范经过人工批准。

## 4. 使用步骤与可复现例子

1. 打开「功能工作台」，选择L044。点击「装入三处Agent示例」。保留规范`agent`、别名`Agent`和人工依据。
2. 点击「检查别名并生成建议」。输入为：

```text
Agent works.
Agent plans.
Agent learns.
```

3. 应报告恰3处，分别第1/2/3行、UTF-16列1，原区间为`[0,5)`、`[13,18)`、`[26,31)`。默认选择3处，建议为：

```text
agent works.
agent plans.
agent learns.
```

4. 取消M2勾选，选择数变为2，中间行仍为`Agent plans.`。原稿输入和来源hash不变。查看原行/建议行表与完整diff，再分别导出JSON、Markdown、diff到不存在的新目标。
5. 测试重叠：粘贴`Agentic Agent`，添加T2，规范`worker`、别名`Agentic`。应出现3个候选；前7个码元的`Agentic`与前5个码元的`Agent`同属一个冲突组，默认都不选，末尾独立`Agent`已选择。只选长候选，预览为`worker agent`；再选短候选时建议失效并取消导出，取消短候选恢复。
6. 测试本地源保护：将下方代码写出的文件导入并检查；应有3处，建议文本保留CRLF，但原文件含BOM的SHA不变。刷新窗口后规范草稿恢复，导入的文件及报告不恢复，需要重新选择原文件并检查。

可在空目录用Node创建只读验证夹具，`wx`防止覆盖已有文件：

```js
const fs = require('node:fs');
const bytes = Buffer.concat([
  Buffer.from([239, 187, 191]),
  Buffer.from('Agent works.\r\nAgent plans.\r\nAgent learns.')
]);
fs.writeFileSync('original.md', bytes, { flag: 'wx' });
```

该夹具SHA-256应为`231c987709a92f1c10fa74e9a68c710bd9efd6d5b64cf3c71515d2f65b41c0ac`。检查前后用独立hash工具复核，原始44字节保持不变。

## 5. 产出

JSON完整记录schema/model版本、人工规范/依据、原来源字节hash/文本/原行索引、全部别名统计、全部出现位置、全部冲突组、人工选中ID和数量、逐来源建议全文、改变行及完整diff。Markdown嵌入同一完整记录，转义HTML字符并使用足够长的代码围栏，避免原文被当成HTML或关闭围栏；读取其中记录时需还原实体。单独diff用于文本审阅，不包含完整规范来源证明，不自动应用。

分页和重叠显示过滤不改变输出范围；相同文件名或相同文本的两份来源保留不同ID并分别计数，不自动去重。人工选择只改变建议内容，不改变原出现次数。大型输入无法保存草稿时，报告仍包含完整原文，可在关闭前导出用于复核，但派生报告不作为配置草稿回填。
