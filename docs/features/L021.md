# L021 失败输入缩减器

## 功能内容

在「学习 → 编程验证与调试训练」输入JSON整数数组，选择内置确定性失败谓词，使用ddmin的删除补集路径缩减。界面显示当前保留数组与原始位置、每次候选、删除位置、失败/通过判定、是否接受删除以及最终逐元素验证证据。

支持自动运行（每次尝试让出80ms）或手动「继续一步」、取消、跟随最新尝试或回看历史、逐条前后查看、次序滑块与25条一页的完整轨迹。所有候选保留元素原值和相对顺序；只删除、不重排或替换。JSON与Markdown可导出全量轨迹，取消后的未完成轨迹也可导出。

首版只接收安全整数数组及以下四个内置谓词，不执行用户代码，无AI/联网/编译器/外部运行时依赖。

| 内置谓词 | 失败条件 | 教学用途 |
|---|---|---|
| 同时包含2和7 | 数值2、7都存在 | 两个不同元素共同触发失败 |
| 存在重复整数 | 任意值至少出现两次 | 区分重复值的不同位置，避免一次删除全部同值 |
| 负数出现在正数之前 | 前方有负数，后方有正数，0不参与 | 保留顺序的约束 |
| 含2和7，或唯一元素是9 | 含2与7，或者数组恰好是[9] | 用具体反例说明1-minimal不是全局最小 |

`fail`表示触发内置条件，`pass`表示不触发；这里没有运行真实用户程序，也没有推断异常或挂起。

## 为什么需要

一个很长的失败样例经常掩盖触发问题的真正组合。只给调试建议无法展示哪些输入可以删除、哪些不能删除以及证据从哪里来。本功能提供可复现的缩减过程，让学习者理解测试判定、删除搜索和最小性证据。它扩展现有practice报错建议，新增确定性的失败样例删除实验。

最终仍失败，而且删除任一剩余位置都通过，称为**1-minimal**。这个证据只覆盖一次删除一个位置，不能证明全局最短或所有子集均通过；特别是非单调条件和不同搜索路径可以得到不同结果。

## 实现方式与范围

`model.mjs`定义固定谓词、输入验证、删除生成器、异步驱动与报告。`index.js`使用公共`h`创建界面、处理手动/自动等待、取消和导出。`meta.json`供功能工作台发现；`style.css`只作用于L021。模型版本`array-ddmin-v1`；保存和JSON导出`schemaVersion:1`。

算法具体约定如下：

1. 初始输入判定必须为`fail`。若为`pass`，记录初始证据并返回`rejected`，不继续缩减。空数组对四个内置谓词都通过，所以明确拒绝；不会虚构失败。
2. 每个元素保留0开始的原始位置。当前数组从分块参数`n=2`开始，块长度为`ceil(当前长度/n)`，按顺序尝试删除每个连续块，判定其补集。
3. 补集仍失败才接受删除，并把分块参数调整为`max(2,n−1)`，重新分块；补集通过则拒绝此候选。整轮未能删除时，增大分块参数至`min(当前长度,2n)`。只有一个元素或单位置粒度整轮都不能删除时结束删除搜索。
4. 搜索结束后**另行逐个删除每个剩余位置**并记录候选与判定。全部通过且当前数组的初始/最近接受候选确实失败，才标`completed`和`minimality.verified:true`。失败证据指向具体尝试序号。
5. 取消、预算耗尽、初始通过、验证失败均不标为1-minimal。达到上限时可以保留已知失败候选，但证据不完整；没有自动将其当作完成结果。`globalMinimumClaimed`始终为false。

每次判定后异步让出事件循环，默认模型让出一个定时任务；界面自动模式等待80ms，手动模式等待「继续一步」。取消立即释放定时器或手动等待，下一检查点停止，不再做下一次谓词判定。切走会取消当前运行；返回不会自动恢复运行。销毁清理等待、延迟保存和DOM。

限制：最多128个元素、8000字符、1–1024次判定（预算包含初始及最后证据检查）。只接受JSON安全整数数组；不接受嵌套、字符串、布尔、null、小数、非有限/超安全范围数或自定义函数。0与-0按相等值处理。谓词是源码中的固定分支，不使用`eval`、`Function`、子进程或用户脚本。元素身份按原始位置处理，两个相等值不会在删除时自动合并。

生成器每次只增加一条判定记录；异步回调收到副本，不能修改内部搜索数组或证据。界面只渲染当前25条轨迹，全部记录仍可分页浏览及导出，避免不断重建1024行表格。

## 使用步骤

1. 打开功能工作台的「失败输入缩减器」，点击「载入同时包含2和7示例」，或输入如`[1,2,3,7,9]`。
2. 查看内置条件，设置尝试上限。想逐步观察时选「手动继续一步」，然后点击「开始缩减」。运行时锁定输入，保证轨迹对应同一次实验。
3. 初始数组先检查是否失败。手动模式每点击「继续一步」推进下一次判定；最后一次证据后再继续一次结束。自动模式按80ms间隔推进，可随时取消。
4. 查看候选卡片和原始位置，区分`fail`后接受删除与`pass`后拒绝删除。点击轨迹序号、滑块或「上一次尝试」回看；取消跟随最新尝试后回看不会被自动跳走。
5. 完成时查看逐元素证据。改输入、谓词、执行方式或预算会使旧结果失效，再开始新实验。取消后可以重跑同一初始数组，没有从中间恢复按钮。
6. 导出完整JSON或Markdown，选新文件名；导出取消或失败不会清空实验。没有成功运行时可以先导出JSON草稿。

## 产出与保存范围

JSON包含功能/状态/模型版本、导出时间、草稿及结果。结果包含内置条件名称/规则、原数组、当前数组及原始位置、初始判定、当前失败证据序号、状态、预算/次数、所有尝试的候选和删除位置、是否接受、分块参数及完整逐元素证据。运行中导出是当时的`running`快照；取消和上限结果分别保留`cancelled`/`limit`，证据标记false。Markdown显示同样的轨迹和证据。结果尚不存在时JSON的`result:null`，不提供Markdown按钮。

导出调用公共`files.saveText`并强制`copyOnly:true`；先检查防覆盖能力，不足时提示升级。基础层用独占新建拒绝任何已存在目标文件。没有新增共享接口或依赖；导出不会覆盖文件。

全局配置仅保存数组输入、内置谓词、执行方式和预算，**不保存尝试轨迹、结果或运行进度**；恢复只恢复草稿，需要重新验证。每次写前以`TextEncoder`测JSON UTF8字节数，超过64KiB拒绝写配置并独立提示导出完整JSON，关闭后只能恢复较早草稿，切走不能保存超限内容。恢复先校验状态版本/体积/字段/谓词，保存失败明确提示。导出文件是完整结果保留方式；本版不提供文件导入。

## 可复现的具体例子

### 验收：[1,2,3,7,9]只保留2和7

选择「同时包含2和7」，载入示例，保留1024预算，点击「开始缩减」。固定搜索顺序产生以下15次判定：

| 尝试 | 阶段 | 候选 | 判定 | 接受删除 |
|---|---|---|---|---|
| 1 | 初始 | [1,2,3,7,9] | fail | 初始证据 |
| 2 | 缩减 | [7,9] | pass | 否 |
| 3 | 缩减 | [1,2,3] | pass | 否 |
| 4 | 缩减 | [3,7,9] | pass | 否 |
| 5 | 缩减 | [1,2,9] | pass | 否 |
| 6 | 缩减 | [1,2,3,7] | fail | 是 |
| 7 | 缩减 | [3,7] | pass | 否 |
| 8 | 缩减 | [1,2] | pass | 否 |
| 9 | 缩减 | [2,3,7] | fail | 是 |
| 10 | 缩减 | [3,7] | pass | 否 |
| 11 | 缩减 | [2,7] | fail | 是 |
| 12 | 缩减 | [7] | pass | 否 |
| 13 | 缩减 | [2] | pass | 否 |
| 14 | 证据 | [7] | pass | 验证删除原位1的2 |
| 15 | 证据 | [2] | pass | 验证删除原位3的7 |

预期最终数组`[2,7]`，保留原始位置`[1,3]`，当前仍失败的证据是尝试11，删除任一位置均通过，显示「1-minimal已验证，未证明全局最小」。证据与前两次搜索重复判定是有意保留的独立最后检查。

把预算设成14再运行：最终仍为`[2,7]`，但只生成第一条逐元素证据，状态`limit`、1-minimal未验证。手动模式在初始检查后点击「取消缩减」：状态`cancelled`、尝试1，导出保留初始失败但不声称最小性。

### 重复值和无需缩减

载入「存在重复整数示例」`[1,2,3,2,9]`，最终`[2,2]`，原位`[1,3]`。删除其中任一位置只剩一个2，判定pass。以`[2,7]`和核心谓词运行，没有任何接受删除，但仍有5次记录：初始、两次删除搜索、两次最终证据。输入`[]`直接返回起始通过，不缩减。

### 1-minimal不是全局最小

载入「含2和7，或唯一元素是9示例」`[2,7,1,9,3]`。固定搜索会接受`[2,7,1]`并删除9，最终`[2,7]`，9次判定、1-minimal证据成立。然而原数组的子序列`[9]`也失败，长度1比最终长度2小。把输入改成`[9]`运行，可复现其失败且删成`[]`后通过，说明工具没有证明全局最小，也不保证结果唯一。
