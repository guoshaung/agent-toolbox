# T063 直连代理路径对照

## 1. 功能内容

给定一个 HTTPS URL、一个显式无认证 HTTP CONNECT 代理和 HEAD/GET 方法，先无网络校验并展示计划，用户另行确认后并行执行两条独立路径。直连记录目标 DNS、TCP、严格 TLS、首字节与 HTTP 状态；代理记录代理 DNS、TCP、CONNECT 状态、目标严格 TLS、首字节。代理内部如何解析目标不可观测，`targetDNS.status=unknown`、`elapsedMs=null`，不会显示为零毫秒或解析成功。

每路径最多一次 TCP 连接、TLS 握手和目标 HTTP 请求，代理另有一次 CONNECT。无重试、地址回退、重定向跟随、隐式系统代理、凭据、Cookie、自定义请求头或系统设置修改。失败路径保留失败阶段和代码，另一条路径的成功不会被覆盖。UI 支持取消、清除、完整 JSON/Markdown 预览和新副本导出。

## 2. 为什么需要

“代理能否连接”和“目标能否返回首字节”是不同检查。代理 TCP 拒绝、代理 CONNECT 拒绝、隧道内目标 TLS 失败不能混成同一个网络错误。两条路径保留阶段观测，便于判断应检查哪个环节，并保留可交付的检查记录。单次耗时受本机解析、网络、代理缓存等影响；本功能不作吞吐、稳定性或网站安全结论。

## 3. 实现与范围

`host.cjs` 使用 Node 内置 DNS/net/tls；只接受固定 `plan/run/cancel` 协议，通过公共可信已安装功能 Host 桥调用。`plan` 不创建 socket 或调用解析。HTTPS URL 使用 WHATWG URL 规范化（国际域名转 ASCII）；代理仅接受 HTTP 根路径，拒绝账号、密码、片段、代理路径/查询、控制字符、未知 payload 字段和无效端口。产品不提供 CA、认证、脚本、请求头或系统代理入口。单标签域名仅允许 localhost，末尾点和 IPv6 zone ID 不在输入范围。

域名使用 `dns.lookup({all:true,verbatim:true})` 每端点一次，按系统返回的首地址连接，不尝试其它地址。IP 字面量 DNS 阶段为 `not_applicable`、耗时 null。系统解析缓存未知，底层 DNS 报文和 NSS/hosts 路径未测；系统 ENOTFOUND 不被表述成精确 DNS NXDOMAIN。系统 lookup 不能实际中止，取消后忽略晚回调并阻止连接。

TCP 先独立建立；代理用限定的 HTTP/1.0/1.1 CONNECT 状态行/响应头读取隧道，记录状态但不保留响应头。非 2xx 为 `CONNECT_REJECTED`；成功后严格 TLS 连接，`rejectUnauthorized:true`、TLS 1.2–1.3，独立按原目标名/IP 调用 `checkServerIdentity`。过期、不可信链、名称不符会阻止 HTTP，不关闭验证或改换协议。GET/HEAD 是最小 HTTP/1.1 请求，仅固定 Host/User-Agent/Accept/Connection 头；首次收到应用字节记录 `firstByteMs`，等待限定状态行后销毁连接。有效最终状态 200–599，1xx/HTTP2 不在响应解析范围，明确失败而不重试。不保存 Location、其它响应头或正文。

阶段耗时仅覆盖该阶段，首字节时间从写请求到首次收到应用字节；首字节阶段总时间还可能等待完整状态行。两条路径并行，总耗时不是各阶段相加，失败阶段的后续步骤为 `not_run`。首字节只证明收到 HTTP 状态，不等于正文下载成功。HTTP 错误状态和 302 也可为路径 `observed`，不表示业务成功。

上限：输入各 2048 字符，请求 8192 字节；每阶段 5 秒，每路径 20 秒；每路径应用层接收 65536 字节、CONNECT 头 16384 字节、目标状态行 1024 字节。接收上限按实际已收到的 chunk 计数，超限拒绝；不是对内核/TLS 缓冲或服务器发送量的承诺。最多 32 个 sender、每 sender 一项在途任务、128 个已用任务 ID；重复 ID 拒绝。任务结束/超时/取消/destroySender 销毁 raw/TLS socket，阶段计时器和监听器清理，晚回调不能改写结果。面板隐藏、deactivate、destroy 取消连接；重新激活不自动运行。输入编辑废弃旧计划与结果，输入/结果不写配置，只有工作台自行保存功能编号最近使用记录。

技术依据（Node 20.18.3 与原生验证运行时对应）：[net.createConnection / net.Socket](https://nodejs.org/download/release/v20.18.3/docs/api/net.html)、[tls.connect / checkServerIdentity](https://nodejs.org/download/release/v20.18.3/docs/api/tls.html)、[HTTP CONNECT 与请求 API 说明](https://nodejs.org/download/release/v20.18.3/docs/api/http.html)、[dns.lookup 的系统解析语义](https://nodejs.org/download/release/v20.18.3/docs/api/dns.html)。本功能手写有限状态行解析，不调用 HTTP 客户端自动重试/重定向逻辑。

## 4. 如何使用

1. 工作台打开“工具 → 网络诊断与接口验证 → T063”。输入 HTTPS URL、显式 HTTP 代理 URL，选 HEAD 或 GET。
2. 点击“校验输入并展示路径计划”。核对规范化后的完整 URL/查询、端口、代理、固定请求头、方法、次数、期限与上限；此时未连接。输入无效时不保留旧确认按钮或报告。
3. 点击“确认目标和请求，运行两条路径”。逐阶段检查 direct/proxy；代理目标 DNS 始终未知。运行期间可取消；取消保留已完成路径和阶段。
4. 完成后先“预览完整 JSON 报告”或 MD，再“保存已预览报告新副本”。生产 `files.saveText(copyOnly:true)` 独占创建；已有目标拒绝。只有 `ok===true` 才报成功，取消/false/undefined/异常均保留预览且不声称成功。

“填入本机示例”只填 `https://127.0.0.1:8443/` 与 `http://127.0.0.1:8080/`，不会启动服务或连接。需自行提供受系统/Node 信任且匹配目标名称的证书和支持无认证 CONNECT 的代理。输入 URL 的查询可能包含敏感信息，会发送并进入完整报告，确认及分享前应核对。

## 6. 具体可重现例子

准备受信任且 SAN 匹配 127.0.0.1 的 TLS 服务 `127.0.0.1:8443`，HEAD `/` 返回 HTTP/1.1 200；代理 `127.0.0.1:8080` 对 CONNECT 返回 403（其自身 TCP 正常）。输入这两个 URL，先校验再确认。结果 direct 为 `observed`，target TLS authorized true、first_byte httpStatus 200；proxy 为 `failed / connect / CONNECT_REJECTED`，CONNECT data.status 403，后续 TLS/首字节 `not_run`；代理侧目标 DNS 未知且 null。预览 JSON/MD 后分别创建新文件，返回相同阶段信息。

将代理换为成功 CONNECT 隧道但转发到 SAN 为 `wrong.fixture.test` 的本机证书服务，保持直连目标不变：direct 仍 observed，proxy CONNECT 为 200，但 failureStage 为 target_tls、code 为 ERR_TLS_CERT_ALTNAME_INVALID，proxy 不发送 HTTP。把正常目标响应改为 302：每路径仅一项请求，httpStatus 302、redirectFollowed false，没有对 Location 目的地的连接。

把代理改为接收 CONNECT 后不回应，直连正常响应：约 5 秒后 proxy 的 connect 阶段 `STAGE_TIMEOUT`，direct 成功保留。到时前点击取消会变为 ECANCELLED，已经完成的直连阶段不改失败。测试命令可重复运行同一固定证书夹具，不需网络、账户、运行依赖或外部代理。
