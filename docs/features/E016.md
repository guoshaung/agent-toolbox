# E016 表情包配字

## 1. 功能与必要性

用自己的静态PNG/JPEG照片裁成方形，写顶部、底部文字，调整字号、描边与颜色，完整预览并另存512×512 PNG/JPEG。关闭AI也能完成全部操作；首版没有AI提供商、文字生成、网络请求、图片上传或设备权限。

聊天表情图常需要短句在小图中清楚可读。这里把原图、裁切和配字放在同一界面，实际自动缩小字号和完整文字可审计，避免只保存被裁掉、被省略的文字。JPEG用于分享，完整JSON用于继续编辑，二者用途明确。

## 2. 实现、规则与资源边界

模块仅依赖本机File API、WebCrypto SHA-256、createImageBitmap、Intl.Segmenter和原生Canvas。没有跨feature运行时依赖或新package。`model.mjs`负责预检查、严格工程、排版和绘制；`index.js`使用现有`h()`创建控件，`create`同步返回生命周期对象。没有RAF、定时器或后台动效。

源图片1字节至5MiB，单边1–8192、总像素≤2400万，接受常见静态≤8bit PNG及8bit单图灰度/RGB JPEG（基线/扩展顺序/渐进帧）。4000×3000普通JPEG在此范围。PNG解码前核对签名、每块界限/CRC、单一首IHDR、IDAT/IEND和尺寸，拒绝APNG。JPEG解码前走完整标记/扫描边界，要求单一SOF/EOI，拒绝DNL延后尺寸、多帧、层级和尾随数据；不按文件扩展名信任尺寸。其后原生解码仍可能拒绝格式损坏，二次核验实际像素与头部，允许EXIF导致的宽高互换。首版不接受SVG/HTML/GIF/WebP、16bit PNG、CMYK JPEG或动画。

格式依据：[W3C PNG Third Edition](https://www.w3.org/TR/png-3/) 的块/IHDR/CRC规则，[ITU-T T.81 JPEG规范](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) 的标记与SOF/SOS/EOI。这是有界预检查加浏览器解码，不能宣称自写验证器覆盖整个标准、所有相机元数据或原生解码器全部内存峰值。

裁切以解码后原图像素为单位，左上原点，`x/y/size`为十进制整数。单一方形完整在原图内，不夹紧越界输入、不静默改变选区；默认居中最大方形。缩放到512×512使用高质量原生采样，不声称非1:1缩放逐像素无损。透明源合成白色底，输出为完整不透明图；JPEG另有60–95质量参数，有损编码不影响工程中的原始图片字节。

每段最多500个Unicode码点；允许换行/TAB，拒绝其他C0控制符及孤立代理项。空段不占高度，显式空行保留。逐字素换行，组合音标和emoji家庭序列不拆开；不做省略号、不删尾部。字体为本机`bold sans-serif`，请求字号12–72px、描边0–8px。自动缩小时从请求字号向下逐整数寻找，最低12px，实际字号明确显示；关闭自动缩小则严格使用请求字号。使用真实Canvas字形进出边界与描边半宽，在四边20px内布局，两段都存在时留16px间隔。字形高度另有2px绘制余量。若完整文字无法放入，界面保留输入、拒绝应用和所有导出；减少文字/描边、修改字号或撤回未应用编辑后再试。500码点是输入限额，不保证每个500码点文本都能在512内完整排版。

schema1工程只含原图身份/完整规范Base64、SHA-256、方形裁切、两段文字、请求字号/自动缩小/描边/颜色/格式/质量。恢复拒绝未知或缺失字段、重复JSON键、非整数数值词法、无效Unicode、不规范Base64、尺寸越界和版本改变；先校验原字节类型/摘要，再解码并核对实际尺寸，再完整排版。JSON≤8MiB、解析深度≤8，5MiB原图加最大文字可完整保存，不丢图片或截断参数。

读取、排版与编解码有上述尺寸/字节/文字上限。取消导入、隐藏或离开使异步结果失效；不能中止底层File读取、WebCrypto或原生解码，旧操作结束前仍锁定新的编辑操作。丢弃的bitmap会close；销毁关闭当前bitmap、清空画布、移除监听和释放工程引用。异步PNG/JPEG编码的过期返回不会调用writer。已经进入原生保存的操作不能撤回已经写出的副本，晚回执也不复活旧面板。

## 3. 操作与恢复

1. 选择“本地表情图片”，查看待导入文件名、尺寸、摘要身份。点“应用图片/工程”。已有工程时必须先勾选“确认替换表情工程”；待导入来源不会自动覆盖当前工程。
2. 设置裁切X/Y/边长，或点“居中最大方形”。输入顶部/底部完整文字，设置字号、自动缩小、描边和颜色。选择PNG或JPEG。
3. 点“应用全部编辑”。确认512全图与“完整文字与字形安全边距审计”中的实际字号、每行原文和字形坐标。修改任何输入都会使旧结果不可导出；“恢复已应用编辑”可撤回未应用输入。
4. 点“另存512表情图”生成分享图片，点“另存完整表情工程JSON”保留可编辑原图与参数，分别选择新文件名。
5. 关闭/切换/重载后，选择已保存的完整JSON，查看身份，再确认应用，可以继续编辑。不需要重新找原照片，JSON中的原图字节经SHA核验。

大型来源不写全局config、不自动持久化；窗口重载为空工程，这是明确的手动完整工程恢复。打开另一个功能会销毁当前模块，**离开前请保存完整JSON**。仅关闭整个工具/隐藏页面但模块仍存活时，已应用工程留在内存；返回没有自动导入/导出，也没有后台播放。键盘可Tab到输入和按钮，使用标准textarea换行与数值控件；没有仅靠鼠标拖动的不可达操作。

## 4. 产出与副本保障

分享产物固定512×512，PNG无损或JPEG有损；自定义文字、原图选区和白底全部在同一幅图中。完整JSON包含原图原文件字节与SHA，不以重新编码的缩略图伪装原图恢复。原图EXIF等元数据保留在JSON原字节中，工程不适合未经检查公开分享。绘制输出由Canvas编码，不承诺保留源元数据、源格式色彩管理或跨平台字体像素一致。

完整JSON调用公共`files.saveText`，PNG/JPEG调用`files.saveBinary`；分别要求`saveTextSupportsCopyOnly===true`与`saveBinarySupportsCopyOnly===true`。JSON8MiB/图片10MiB上限整体拒绝，不做自动缩图或截断。全部`copyOnly:true`，二进制带规范Base64和SHA，主进程生产writer核验后独占`wx`创建。已有目标包括原源文件拒绝覆盖；只有`ok===true`报告成功，取消、失败和`partialPath`均明确显示，保存期间控件锁定避免旧结果换源。能力缺失的旧桥禁用对应按钮。

## 5. 可复现例子

方图512×512导入后直接应用，顶部写“今天开心😀”、底部写“明天继续”，字号32、自动缩小开启、白字黑描边3。点应用，再保存PNG。两行完整位于20px安全边距内，输出512×512。每段是完整文字，emoji也作为字素保留。再次选择同一个保存目标必须失败，原文件SHA不变。

矩形768×640原图可设X=128、Y=64、边长512，得到确定方图；设X=300则超界拒绝，而不是自动夹到合法坐标。上段两行“今天也要认真摸鱼\n给自己一点快乐😀”，下段两行“画面很忙\n心情很好”，在本机32px完整为4行。若上段为“认真生活😀”重复40次，下段为“给今天一点快乐”重复20次，本机自动18px、15行完整保存。字体跨机器可能不同，以实际预览为准。

把“x\n”重复249次（498码点）放顶部，纵向放不下：应用拒绝、保存按钮禁用、输入完整保留；没有提前保存之前的旧配字。点撤回可恢复已应用完整工程。把图片换成4000×3000、≤5MiB的普通JPEG，也能裁切和上下配字，再输出512JPEG；此功能不帮超限照片后台压缩。
