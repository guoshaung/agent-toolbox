# T074 端口占用归属查询

## 1. 功能内容

按用户指定的单一本地端口，只读观察 Windows TCP Listen 和 UDP 绑定端点，列出协议、地址、PID、可见进程名/完整路径/创建时间。查询失败、路径不可见及进程未观察分别保留，不自动提权，也不提供结束占用程序的操作。

完整结果先预览 JSON/Markdown，再保存新副本。创建面板不查询系统，修改端口使旧报告失效；输入和报告不写配置。其它平台明确返回 not_supported，不能把未实现平台当成没有监听。

## 2. 为什么要有

本地服务提示端口被占用时，需要知道当前监听或绑定归属，才能人工判断是否填错端口、已有程序在运行或其他服务冲突。只看到“占用”不能识别进程；本工具把协议、地址与PID证据放在一起，并保留受权限和时点影响的未知。

监听不证明业务正常、网络安全或手机可达；没有观察到端点也不保证可绑定，保留端口、权限和其它绑定条件仍可能影响启动。TCP与UDP互相独立，同一数字端口可能分别有端点。本项没有抓包、远端扫描、连接服务、自动清理或杀进程。

## 3. 实现方式

自有model验证整数端口与严格系统输出，Host经公共可信桥执行固定只读系统查询，renderer展示全部行。只接受1–65535整数，禁止范围、任意脚本、程序路径或附加字段。

Windows系统程序路径由本应用继承的 SystemRoot 加固定 System32/WindowsPowerShell/v1.0/powershell.exe 得到，再realpath/stat核对；不经PATH搜索，不接受renderer指定程序。它信任本地OS安装及应用继承的系统目录，不提供OS完整性认证。使用固定 -NoLogo/-NoProfile/-NonInteractive/-EncodedCommand，无shell，唯一区别是经过验证的十进制整数端口。没有执行策略绕过或系统设置修改。

禁用模块自动加载，显式按该系统PowerShell的PSHOME绝对路径载入系统Utility、CimCmdlets和NetTCPIP manifest，避免从用户PSModulePath自动选择同名模块；不运行用户profile/项目脚本。使用 [Get-NetTCPConnection](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection?view=windowsserver2025-ps) 的TCP监听数据及Get-NetUDPEndpoint本地绑定数据，固定单端口过滤后查询对应 [Win32_Process](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process) 的Name/ExecutablePath/CreationDate。没有读取CommandLine、凭据、环境或远端信息。进程路径可受权限限制，不把空字段判成程序一定不存在。

TCP/UDP各保留observed或query_failed状态及明确count；未成功观察的协议count为null，不能伪造零。最多128总行，超过容量整份拒绝、不截断。结构、数值、所属端口、协议行数、时间、IP格式及路径格式再校验，坏输出不给部分成功。stdout≤256KiB、stderr≤8KiB，均不回显原始系统异常。读取不是原子快照，查询端口后进程可能退出或PID复用，创建时间只是当次可见元数据，没有声称原子关联证明或软件身份认证。

单窗口串行、最多32窗口，每窗口128唯一任务，默认Host最多4个自己创建的查询子进程。12秒计时只限已经启动的查询子进程；取消/隐藏/离开/销毁仅请求终止自己持有的child，绝不按端口PID终止其他程序。只有child close被观察才释放运行槽和窗口任务，不能把kill返回当成OS立即停止，metadata调用也不保证硬12秒返回。销毁与任务票据隔离迟到结果，回到面板不自动查询。

JSON/Markdown各≤1MiB且包含全部端点、协议状态、未知解释、观察UTC、系统程序与退出/取消观测。URI/监听地址分类只有loopback/wildcard/specific_address；没有推断绑定范围等于实际外部可达性。Markdown含完整结构JSON与经过转义的文字表格。

## 4. 如何使用

1. 打开工具工作台→系统与本地环境→端口占用归属查询。
2. 填需要核对的本地端口，例如3000，点击“只读查询指定端口归属”。没有启动服务或联网探测。
3. 核对TCP/UDP观察状态及每行地址、PID、名称和路径。path_not_visible保留未知，query_failed或not_observed不能当作进程不存在。
4. 查询慢时可“取消本工具查询”，等待自己的查询child结束；被观察的服务程序不受这个取消影响。
5. 预览完整JSON或Markdown，再保存新副本。检查桥接能力严格为true；只有ok===true宣布成功，取消/false/undefined/throw保留完整预览。生产saveText(copyOnly:true)/wx拒绝既有目标。

## 5. 使用后产出与具体例子

一个自行启动的本地TCP服务监听127.0.0.1:3000，PID为12345。输入3000查询，预期该行protocol=TCP、endpointKind=listen、addressScope=loopback、pid=12345；可见时显示该进程的实际路径。若同一个数字端口还有UDP端点，它另外显示protocol=UDP、endpointKind=bound_udp，不混为TCP连接。

PID已观察但ExecutablePath不可见时，显示path=null、pathKnown=false、processStatus=path_not_visible，解释权限/保护/其它原因未区分，不说程序损坏，也不自动提升权限。进程查不到时保留端口PID和not_observed，不猜程序名。完整副本format=T074-port-owner-report、version=1，保留原观察时间与全部未知，供人工核对。

实际生产验收例：自有Electron进程PID34764同时持有127.0.0.1:54591的TCP与UDP端点，面板查询准确给出两行及生产Electron完整exe路径；源PID、端口和进程路径由验收进程独立已知，不用查询结果自证。此数值只属于当次夹具，用户应填自己的当前端口。
