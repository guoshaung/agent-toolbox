# L053 学习错误纵向台账

## 1. 功能内容

本地登记历史错误、用户原因说明、知识/策略/执行候选分类及改进行动；只有用户显式确认当前修订标签才计类别次数。输出完整跨任务重复标签、用户日期月频次、未确认/旧确认/未知日期及待验证行动，保留原文、来源位置与全部人工证据。无需AI或网络，采用catalog允许的完整人工MVP，不提供AI语义评分、自动心理诊断或效果结论。

每条记录可有0–4行动，填写人工复验结论/日期/任务/证据，再显式确认绑定当前记录和行动；缺项、旧确认或日期早于错误日期时仍待验证。人工“有效/无效”是用户报告，不是工具验证效果。默认三任务例是自编、预设人工确认的演示台账，新加记录默认未知且无确认。

## 2. 为什么需要

单次练习的错误修复不会展示是否在另一个任务重复同类问题，也容易把“计划改进”误当成已经有效。把错误类别、原因与行动分开记录，再按确认标签聚合，可帮助用户找具体记录复核，以及决定哪些行动需要新的任务证据。

频次只是记录数，没有总练习次数分母，不等于错误率、学习能力、心理状态或改进效果。类别由用户确认，不推断真实原因。同名任务按字面归组，不自动判断任务语义；重复记录可能使次数增大，不自动去重或当作独立事件。

## 3. 实现方式

`model.mjs`实现严格schema、编号/容量、意义修订与分类确认、人工复验绑定、完整聚合；`index.js`提供真实历史/行动编辑、10条分页、分类/复验确认按钮、趋势表及完整预览/导出。`meta.json`由生产catalog发现，CSS使用实际项目主题变量。

记录E001…、每条行动A001…，集合内唯一，删除后可复用空编号。用户填写任务、错误、人工原因和来源名/位置/原句；来源/原因空项明确未知，不伪造引文。候选类别知识/策略/执行/未知；选择候选不等于确认，错误内容非空后才可确认。任务、错误、原因任一改变会增加修订号，分类确认保存原修订，只有修订与当前候选都一致才参与聚合；即使恢复原文字也需重新确认。来源、日期、行动改变不改变分类修订，但清派生报告。

类别次数是当前确认记录数。跨任务模式须该类别至少2记录、至少2个已知任务名；任务名修剪首尾空白后按字面区分。任务未知不制造新的任务身份，类别记录仍保留。每类输出全部记录ID、任务名列表、已知任务数及是否满足跨任务条件，未确认/旧确认单列，不混入三类次数。

日期为用户1900–2100有效YYYY-MM-DD，可空未知；检查真实日历及闰日，不自动采用本机now。趋势按YYYY-MM字面升序，只列有记录月份，提供全部/当前确认/其他数与各类别数；未知日期另列，不因无记录补月为0，也不能凭频次下降判改进有效。

人工复验填写行动、有效/无效结论、日期、任务、证据，再点击确认。确认快照含记录修订号、行动说明及全部复验字段；变更记录上下文、行动或复验字段后旧确认失效，报告恢复待验证。记录日期已知时复验日期不能早于它；错误日期未知可人工确认，但保留时序未知提示。缺少字段/确认时列中文待补原因，输入及JSON保留机器键便于复核。无行动记录显示未安排行动，不伪造待验证条目；空行动单列“行动内容未知”。

限制为最多100错误、每条4行动，正文1000/原因600/任务160码点，来源名120/位置240/原句500，行动400、复验证据500、复验任务160。非法控制、孤立代理字符、未知schema字段/重复ID/未来确认修订/无效日期拒绝；修订号≤1000000。完整输入JSON≤256KiB、生成JSON/MD各≤2MiB；超限整份拒绝不截断。分页只影响编辑显示，完整报告保留100记录/400行动。

schemaVersion1配置只保存人工输入与确认，不存频数/报告，UTF8完整草稿≤64KiB才排队写全局配置；恢复同样验证。大记录可以分析导出，但明确不保存配置，关闭只恢复较早合法草稿。队列串行保留最新合法值，旧回执不掩盖新错误。异步分析先冻结输入、每20记录检查点让出，编辑/取消/隐藏/离开/销毁使用票据隔离迟到结果；恢复页面不自动分析。文本安全渲染，Markdown转义HTML并动态加长围栏；saveText严格能力true/copyOnly:true/ok===true，副本不写回来源。

## 4. 使用步骤

打开L053，在当前页编辑错误日期/任务/内容/用户原因与来源证据。可添加历史错误，页码自动转到新增记录；未知类别不计分类。选择人工候选类别，再点击“确认Exxx当前标签”；修改上下文后观察“旧确认失效”，需重新确认。

添加某条改进行动，填实际计划。未复验默认待验证；做完新的任务后自行登记结论、日期、任务、原句/结果证据，再点击“确认ExxxAxxx复验证据”。资料缺失会拒绝确认并显示待补项；不要将用户“有效”选项当成算法验证。后续改行动或证据，需要新的确认。

直接点击“分析完整纵向台账”，无需额外许可；查看类别表、跨任务条件、月频次、未知/旧确认ID及全部待验证行动。展开完整记录/来源、JSON/MD预览后导出新副本；编辑每页10条不会截断报告。正在分析可取消，隐藏/离开隔离旧结果。删除记录/行动和整体示例替换有明确保留/确认，删除后不在工具内恢复，需要记录先完整导出。保存取消保留报告，失败不声称成功。

## 5. 产出与可复现例子

完整JSON包含模型/schema版本、全部原始人工台账/修订/确认快照、每条当前分类/未知来源/原因/日期状态、全部行动及复验缺项/时序/人工结论、类别计数/全ID/任务名/跨任务模式、完整月份计数与未知日期、待验证行动坐标及统计/规则。Markdown包含摘要及同一完整报告。可能包含用户全部错误/原句/原因与复验证据，保存前检查预览，来源真实性和复验结果仍由用户负责。

默认E001/E002/E003为用户自编三任务：数组边界、区间处理、批次结束，均由示例预设确认“策略”。日期2026-09-30、2026-10-01、2026-10-02。点击分析：策略次数恰3、已知任务3、跨任务重复标签成立；知识/执行0；2026-09全部1/策略1、2026-10全部2/策略2。E001/A001“每次提交前检查首尾/空集合”未复验，恰1待验证；人工已复验0。不是自动诊断三条相同心理原因。

编辑E001错误内容加入“前”，旧确认失效，策略次数降2；点击确认E001当前标签后回3，确认修订变2。给A001填用户报告有效、2026-10-03、任务D及“用户报告：此任务检查首尾及空集合”，只填字段仍待验证；点击确认复验证据后人工已复验1/待验证0。改行动为“改为先写边界测试”，旧复验失效，待验证恢复1，但保留旧快照与证据供核对。

E002候选改知识但不确认时不进知识，原策略确认失效；显式确认后知识1/策略2。E003清日期与来源，未知日期E003单列、10月频次变1，类别仍计策略；原句未知不生成替代引文。100记录每条4行动时全400待验证/全部记录及行动完整导出，编辑每页10；超过容量整份拒绝。18记录其中10篇各1000emoji可完整报告但草稿超64KiB，配置拒存，不保证关闭恢复新大输入。
