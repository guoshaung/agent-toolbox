# L001 概念关系建模

## 1. 功能内容

手动输入1–20个概念、0–60条包含/依赖/对比关系，粘贴一段教材文本并为每条边绑定原文选区。工具生成关系图、逐边引用追溯和循环/重复/自指/引用失效核对清单；支持版本草稿及JSON/SVG新副本。

## 2. 为什么需要

单独记住概念并不能说明哪些概念包含另一个、哪些需要先理解、哪些只是对比。手动明确关系类型和文本依据可以暴露结构问题，同时保留可检查的来源；片段变了不能继续拿旧引用当作有效证据。这个功能用于自己的概念建模，不自动抽取关系，不让AI替代语义判断。

## 3. 实现方式

概念用唯一ID引用。包含/依赖为有向关系，对比为无向关系；使用Tarjan算法仅在依赖子图查强连通分组，每组给一条闭合路径示例，不枚举指数级的全部简单环。包含边不参与依赖循环；重复同类边、自指边作为人工核对项，不能据此推断教材错了。

每次绑定使用当前粘贴文本的UTF-16起止区间、原样引文及全文UTF-8 SHA-256。检查同时比较摘要和实际区间文本；原文任意改动使全文摘要变化，原引用仍保留并标记失效，用户需重新选择绑定。粘贴到浏览器的文本以textarea实际值为准，不宣称保留外部文件的CRLF原始字节。没有文件导入或文本自动纠正。无效Unicode原文拒绝，不以替换字符哈希比较。

SVG在圆周布置概念，颜色/箭头区分关系；深色背景与文本对比，XML转义用户标签。图中概念名称超过12码点省略，完整名称和每边区间/引文在JSON及界面列表保留。20节点/60边的密集图可能重叠，完整列表是核对依据。

UI手动增删概念和关系，源/端点/类型编辑清空旧结果，异步摘要与绑定用世代编号隔离，输入变化/暂停/销毁后旧任务不能更新结果。修改概念ID不会暗改边，引用旧ID的关系需自行修复。草稿只在明确点击保存时写配置；无网络或外部服务。

## 4. 如何使用与具体例子

1. 工作台搜索L001，点击“载入双向依赖示例”，片段是“A需要B。B需要A。”，两条边各绑定一句。
2. 点击检查：A→B和B→A产生一个依赖循环组，示例路径A→B→A，两条引用有效。
3. 将R1/R2关系类型都改为包含，再检查：依赖循环0组，不把包含边算成依赖问题。
4. 在片段后追加说明，检查会保留原引文并把两条标记失效。选中第一句，点击“绑定当前原文选区 R1”，再选第二句绑定R2，重新检查恢复有效。
5. 另存JSON/SVG完整副本。可显式保存版本草稿；重开时恢复输入，再重新检查。使用恢复面板粘贴报告JSON时，只取输入与旧锚点，重新计算结论，不信任旧结果。

## 5. 使用产出

JSON包括feature/version、完整源片段及SHA-256、概念、三类边、每边原文区间/引文/绑定摘要/有效标志、依赖循环分组、示例路径和全部核对项。SVG为可分享的关系图，图中包含边编号，完整引用看JSON。

没有或失效的引用不阻止画图，图及列表明确标识，不能把存在引用等同于关系有充分依据。依赖循环报告只说明该手填有向图的结构；修订模型仍需人判断。

保存草稿/JSON恢复限制64KiB UTF-8，超限明确阻止而不截断。结果副本使用copyOnly=true，明确ok=true才显示成功；选择已有文件拒绝，取消保留输入。配置只保存版本1输入及锚点，不保存结论。最终路径由另存对话框选择。

## 6. 验证与限制

9项模型测试涵盖默认单循环、包含/对比排除、原文变动和保留旧引文、emoji/CRLF UTF-16定位、三个独立循环组、自指和重复、无环菱形、非法/超限输入、恢复不信任派生结论、图箭头与XML转义；与6项基础测试一起通过。入口按ESM模式语法检查通过。

真实Electron选区、图像显示与副本导出在交付前验证，证据追加在下方。当前功能不读取用户源文件，不自动提取概念，不证明关系语义正确，也不是教材校对或自动学习效果评价。
