# T023 扫描文档可搜索化

## 1. 功能内容

从本地扫描 PDF 中选择语言、DPI 和页范围，逐页离线 OCR。每页显示原扫描图、原识别字词、置信数、像素框及可编辑校对词；用户检查后生成保留原页面的 PDF 新副本，添加 Tr=3 不可见文字层。生成后使用 PDF.js 实际重新打开副本、提取选页文字和渲染第一页，提供完整预览。TXT、JSON、Markdown 同时保留完整选页结果；JSON/Markdown 记录原词与校对词，不把人工修改伪称原识别。

随功能提供可直接载入的纯图片标准打印示例，源 PDF 没有可提取正文。支持英语、简体中文、简中+英语；无 AI、云端、外部可执行命令或全局 tesseract 安装。只在选定纯扫描页加文字，原图、页数、非选页、原页面旋转和 CropBox 保留。已有文字的选页被拒绝，避免重复文字层。不是 PDF 阅读器、PPT 制作器、论文问答或正文改写器。

## 2. 为什么需要

扫描件保留文字图像但缺少文字对象，无法直接检索或复制。只导出 OCR 文本不能使原 PDF 可搜索；本功能将识别结果写回新副本中同一页面的不可见文字对象，让图片依旧可见、文字可提取。识别可能出错，用户可对照原图和每词位置校对；置信数不是准确率、语义判断或证据真实性认证。

## 3. 实现方式与安装

`model.mjs` 提供页范围解析、像素预算、严格设置、字词校验、仿射逆变换及完整报告。PDF.js 使用项目现有 pdfjs-dist 4.10.38 本地 worker、字体和 CMap，禁用 eval 和字体注入；处理源字节副本，避免原字节被 PDF.js 的 Transfer 转移。OCR 采用规范0°页面视图，副本保留原 `/Rotate`；图像框通过该视口逆矩阵回到 PDF 点坐标，兼容非零 CropBox。字词字体宽度缩放到原 OCR 框；基线用框底向上15%近似，不声称精确逐字形排版。

`host.cjs` 仅提供固定操作，使用生产 feature-host IPC 的本地顶层 sender。单块最多24000字节（Base64最多32000字符，整体请求不超过64KiB），任务绑定 sender 与随机 ID，严格顺序/总长/规范编码/SHA；PDF 完整核验后才解析。页面 PNG 另核验签名、IHDR 与声明像素尺寸、页顺序、SHA；未完整上传不能识别、生成或保存。PDF 与 PNG 只留内存，无源路径、用户命令、任意 JS 或 OCR 临时文件。每个窗口仅一个任务；取消/离开/窗口销毁清理自己的源、上传、报告与目标票据，并终止拥有 Tesseract 子线程的 OCR worker 及 PDF worker。

本地引擎为 [Tesseract.js 6.0.1](https://github.com/naptha/tesseract.js/blob/v6.0.1/docs/api.md)、tesseract.js-core 6.0.0，固定 OEM=1。Node worker 的本地 langPath、gzip=false、cacheMethod=none，且自己的识别线程 fetch 明确禁止网络下载；缺失或 hash 不符不联网修复。完整私有包/模型/字体约43.9MB，顶层 package/lock 未变。英文/简中模型来自 [tessdata_fast 固定提交](https://github.com/tesseract-ocr/tessdata_fast/tree/87416418657359cb625c412a48b6e1d6d41c29bd)；字体来自 [Noto CJK Sans2.004](https://github.com/notofonts/noto-cjk/tree/523d033d6cb47f4a80c58a35753646f5c3608a78)。vendor/manifest.json 保留 registry 固定版本、SHA-512 integrity、URL、许可和实际随附每个文件的大小/SHA-256，vendor/NOTICE.md 说明许可及原包分发范围。无需用户安装程序或编写适配器；损坏时从同一功能提交完整恢复 vendor 即可。清单用于复现与损坏检查，不是可信签名。

生成用 pdf-lib 1.17.1、fontkit 1.1.1 自包含 UMD 原字节私有副本，嵌入 Noto CJK 字体子集及 ToUnicode。使用 [Invisible 文字渲染模式](https://pdf-lib.js.org/docs/api/enums/textrenderingmode)，不是涂白、透明图片或仅正文 sidecar。不改原图内容流，写后重新提取。字形不在字体字符集时整份拒绝，不能用缺字符号假成功。全空校对/空页仅保留原 PDF 内容，不嵌入空字体子集，不假称可搜到不存在的文字。

设置草稿 schemaVersion=1，仅存语言/DPI/页范围，UTF-8不超过64KiB，保存排队；不存源字节、文字、校对、报告、目标路径或派生数据。不兼容草稿保留原值，只有明确点击覆盖后替换。源/设置变更作废旧任务，校对变更作废报告和目标；异步请求、File 读取、解码、绘制和写入回执受生命周期票据隔离。离开不自动续识别，所有文件和结果需重新载入/生成。

## 4. 使用步骤与可复现例子

1. 在功能工作台打开 T023，点击“载入标准打印扫描示例”，或主动选择本地扫描 PDF。核对来源名、字节数、页数、SHA。默认英语、200DPI、页1；多页可用 `1-3,5`，重复/倒序/越界拒绝。
2. 点击“逐页离线OCR”。标准例应识别 `The quick brown fox jumps over the lazy dog.`，第二行 `OCR 2026`。原文件是纯图片 PDF。逐词检查文字、原图、置信数及框；直接在校对输入修改错误词，原词仍留在完整报告。
3. 点击“生成并预览可搜索副本”。检查真实 PDF 提取文字、完整报告、实际副本页面；原扫描图依旧可见。
4. 点击 PDF/TXT/JSON/MD 相应“选择…新副本路径”，在原生对话框选一个尚不存在的文件。返回界面后看到绝对路径、格式、字节数和 SHA，此时尚未写入。核对后点击“确认写入该新路径”。生产副本 writer 用 `wx`；选原文件或任何已有文件都会拒绝。
5. 打开保存的 PDF，在阅读器搜索完整英语句；例图应可见。实际中文样例 `中文扫描文档可以搜索文字` 的原识别把“描”错为“摘”，在词3将“摘”人工改为“描”后生成；报告保留原词“摘”/校对“描”，PDF 可搜索“文字”，提取正文去空白后含完整中文句。不能据此宣称 OCR 自动全部正确。
6. 保存完整报告再离开。窗口重载只恢复设置，不恢复 PDF、OCR 或校对字节。重新识别前须重新载入来源，不能把空白界面当作已恢复媒体。

## 5. 产出与边界

PDF 为全部原页面的新副本，仅选页附加不可见字层；TXT 为全部选页校对正文；JSON/Markdown 含完整来源名/SHA/原字节数/页数、设置、引擎版本、每页 PNG SHA/尺寸/坐标矩阵、每词原值/校对值/置信数/框/行及副本 SHA/大小。界面附加实际提取预览，报告原始字段仍完整，不回填草稿。文字/来源可能含用户内容，请自行核对目标和分享范围。

输入6MiB、1–20页；每次1–10选页；150/200/300DPI；单页600万像素、累计2400万；PNG4MiB；每页2000词、累计10000；单词128 Unicode码点且拒绝控制字符/孤立代理；PNG/PDF字节均有严格完整校验。PDF输出10MiB，JSON/MD/TXT各1MiB，超限整份拒绝，不截断。设置页范围最多120字符。PDF解码/绘制/后端处理各30秒，单页OCR60秒超时终止；页数限制给出有限总工作，计时是取消通知预算，不宣称任意恶意文件在每个平台都有硬实时上界。

拒绝加密、表单、签名/权限字典及不支持的尺寸/旋转；不保证保留数字签名效力，不执行 PDF JavaScript。字体子集覆盖常用简中/英语，不支持的字形明确拒绝。复杂表格、多栏、竖排、倾斜或手写识别/阅读顺序与检索效果没有保证；字框到基线只是定位近似，复制排版/空白可能因阅读器而异。简中跨词可能有空白，可检索已核对词；不宣称全文语义正确。阅读器/引擎报告置信数不能验证引文或作者身份。

## 6. 验证、证据与限制

专项命令 `node --test test/feature-T023.test.js test/feature-foundation.test.js test/feature-host.test.js test/feature-binary.test.js`：25项本功能 +17项基础，共42/42通过。覆盖独立 affine/72点-DPI 公式、范围/像素/Unicode边界、原始/校对记录、固定资源SHA、sender/分块顺序/长度/hash、未完整不能识别、真实私有引擎打印句、真实PDF搜索文字、校对及改回原值、空字层、字形拒绝、多页非选页、真正OCR执行中取消、DOM真实组件事件/容量预检/迟到文件/设置排队与坏草稿保留。

实际 Electron 验收使用隔离 hidden BrowserWindow、生产 catalog/workbench/preload/feature-host/同 CSP 和生产 binary wx writer。受控 HTML File 注入与固定保存对话框返回是夹具；没有声称操作物理鼠标或系统文件选择对话框，也未启动完整主程序所有服务。检查源 `getTextContent` 空；输出 PDF.js PDFFindController 英语完整句0→1命中、中文“文字”1命中、90°旋转+非零 CropBox 完整英语句1命中；英文/中文文字对象位置由独立72/DPI公式核对。三份输出每页全部RGBA像素SHA与源严格相等、来源文件SHA不变，12个PDF/TXT/JSON/MD新副本写盘并回读、原文件目标wx拒绝。中文人工校对单独注明。实际重载只恢复设置、识别中取消无迟到词、离开释放任务；界面和实际输出/目标预览截图均通过 view_image 查看。

还将整个私有 feature 打进测试 ASAR，用真实 Electron Worker 从 ASAR 直接运行本地 OCR 和 PDF 字层生成成功，未依赖额外全局引擎或 renderer WASM CSP 放宽。该测试不是完整 electron-builder 安装包验收；集成/发布还需确保私有 vendor/node_modules、模型等被打包（顶层 .gitignore 会忽略它们，本功能明确强制加入自有路径），没有改公共打包配置。PDF.js 对 Noto CFF 子集出现 `getFontFileType` 警告，验证中没有 renderer错误；文字提取、真实检索、子集PDF及像素对照都通过，不能据此保证所有第三方阅读器相同行为。未重跑缺依赖的全量 check。
