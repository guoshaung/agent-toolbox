# L016 TCP 丢包时序

## 1. 功能内容

在“学习 → 计算机原理交互实验”中，通过有限离散tick教学模型观察单连接的固定发送窗口、数据丢包、累计ACK、越序缓冲与超时重传。输入包含数据包数量、窗口包数、单向传输延迟、初始超时和首次发送丢包列表；默认三包、窗口1、延迟1、初始超时4、首次丢弃包2。

运行后提供发送端/通道/接收端时间线、全部发送/ACK/重传列表，能够单步查看每个tick（包括没有事件的等待），核对前后收发状态、在途包、逐包确认/接收/缓冲状态和RTO。另有越序缓冲与过早超时两个示例。完整JSON/Markdown副本导出，无AI、登录、网络或新增外部运行时依赖；不会建立真实连接、抓包或模拟完整TCP栈。

## 2. 为什么需要

只看“丢包就重传”的图，容易把接收和发送端确认混为一谈，认为收到包3就能跳过缺失包2，或者误以为超时需要把整个窗口一起重发。本功能让每次发送、接收、累计确认和超时都出现在可复现的时间线上，并把越序缓冲、重复包及计时器状态直接展示出来。

新增能力是可控的本地故障时序实验，区别于网页抓取、Requests练习、真实网络连接或AI讲解。计算的是所声明抽象规则，不测量网络性能。

## 3. 实现方式、协议参考与简化

`model.mjs`校验参数，顺序推进tick0～2048，处理有限在途队列，生成独立的前后快照和事件。`index.js`使用现有`h`构建实际输入、tick选择/前后步进、分栏时间线及状态表；仅修改本ID目录、独立测试和文档。用户输入通过表单值与文本节点展示，不执行脚本或HTML。

协议事实核对官方来源：

- [RFC 9293 §3.4](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.4)定义按字节的序号和累计确认：ACK给出下一期待序号；之前的数据已连续收到。本模型将每个包抽象成一个序号单位，包号从1开始，ACK n表示包1～n−1已连续收到。
- [RFC 9293 §3.10.7.4](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.10.7.4)讨论重复段处理、保留越序段及排队段的ACK聚合。本模型选定保留所有越序包，缺口补齐后一次释放连续缓冲；重复包不重复交付。但为了教学逐包展示，每到一包立即生成一个ACK，不实现真实TCP的批量ACK聚合或延迟ACK。
- [RFC 6298 §5](https://www.rfc-editor.org/rfc/rfc6298.html#section-5)作为单重传定时器规则的依据：发送时未运行则启动，全部确认则关闭，新数据确认重启，超时重传最早未确认段并退避。这里使用用户指定的初始RTO和整数tick，超时翻倍，教学上限1024tick；不做RFC §2的RTT/SRTT/RTTVAR估计、秒制下界或后续RTO收敛，不是标准符合性实现。

模型的其他确定规则：

- 1～30包，固定窗口1～8包（可以大于总包数），单向延迟1～20tick，初始RTO1～64tick。两个方向相同恒定延迟，每个包一个抽象序号单位，不模拟TCP字节序号/回绕、分段、MSS或握手。
- 丢包列表是≤256 UTF-8字节的十进制包号，用逗号、中文逗号或空格分隔；空白表示无丢包。拒绝重复号、超出包数、非法字符、小数或脚本。指定包仅首次发送时被丢弃，任何重传均不再被此故障注入丢弃。ACK不丢失、不延迟聚合，不额外注入乱序/抖动；越序可由缺包自然产生。
- 数据按序到达时推进接收端下一期待值，再释放连续越序缓冲；越序到达仅进入缓冲，不推进缺口上的累计ACK；重复或已缓冲的同包不会再次交付，但仍发当前ACK。缓冲最多覆盖这30个包，不模拟接收端窗口动态变化或内存压力。
- 同tick先处理全部数据到达，再处理全部ACK到达，再判断定时器，最后填充可用发送窗口。同类到达按入网顺序，不依赖对象或Set遍历偶然次序。延迟≥1，当前tick生成的传输不会当前tick再次到达。ACK恰在超时tick到达时先更新/关闭计时器，因此不会错误地触发旧超时。
- 发送端保存下一未发送包、累计ACK和未确认集合。只有新累计ACK推进窗口并清除确认包；重复/旧ACK既不推进窗口、不重启定时器，也不触发快速重传。窗口以`下一待发包 < 累计ACK + 固定窗口包数`限制新包。
- 只有一个定时器；超时只重传最早未确认包，不整窗重传。超时翻倍RTO至最多1024；收到新确认且仍有未确认包则以当前RTO重启，不因ACK重置回初始RTO。没有拥塞控制、SACK、快速重传或真实RTT估计。过早超时可能重传尚在途的包，接收端需去重。
- 全部确认时记录`completedAt`并关闭计时器，但继续处理已有在途重复包及其ACK，直到通道排空记录`endedAt`；因此两者可以不同。只有全部包累计确认并排空后才返回completed结果。
- 最晚tick2048（含tick0，共最多2049份快照）、最多512条事件（发送、首次丢弃、接收、ACK发出、ACK到达、超时）。超限整轮报错，不返回截断轨迹、不宣称全部完成。内部测试可降低上限核对精确边界，UI始终使用固定硬上限。时间线只展示有事件tick，但单步选择器与导出保留无事件tick。
- 输入修改立即清空旧结果。配置只保存`schemaVersion:1`参数字符串草稿，不保存收发状态/轨迹；写入前测JSON UTF-8大小≤64KiB，恢复校验整个对象版本、体积和字段类型，运行时再校验参数。超限明确不写配置，关闭只能恢复较早草稿，需导出完整JSON保存当前输入。
- 草稿保存延迟250ms，切走/销毁清除定时器并尝试保存；模型有界同步完成，不留后台网络或模拟。异步保存/导出不更新已销毁界面。所有DOM替换过滤null及嵌套数组。
- 导出检查`files.saveTextSupportsCopyOnly`并传递`content`与`copyOnly:true`，创建新文件，拒绝覆盖已有目标；Markdown草稿转义HTML/表格分隔符。

## 4. 使用步骤与可复现例子

打开功能，保留默认三包、窗口1、单向延迟1、初始超时4、丢包列表2，点击“模拟时序”。全程摘要显示全部确认tick10、排空tick10、重传1次，当前查看tick0。通过“下一tick”、选择器或时间线“查看tick6”核对：

|tick|手算事件|关键状态|
|---|---|---|
|0|首次发送包1|未确认1，超时到期4|
|1|收到包1，发ACK2|接收连续交付1|
|2|ACK2到达，首次发送包2被丢弃|未确认2，超时到期6|
|3～5|无事件等待|包2仍缺失，定时器不变|
|6|超时，只重传包2|RTO4→8，下次到期14|
|7|收到包2，发ACK3|连续交付1、2|
|8|ACK3到达，发送包3|未确认3，超时到期16|
|9|收到包3，发ACK4|连续交付1、2、3|
|10|ACK4到达|三包全部确认、计时器关闭、在途排空|

展开“完整发送 / 确认 / 重传列表”，应仅有包2的一次重传（tick6，第2次发送）。当前tick状态与全程摘要分别标明，不将提前算出的全程结果伪称为tick0已确认。

点击“载入越序缓冲示例”，窗口变3，其余同默认。tick0发1、2、3并丢2；tick1收1和3，3进入缓冲，发两次ACK2；tick2第一个ACK2确认1并重启超时至6，第二个重复ACK2不重启。tick6只重传2，tick7补2后一次交付2、3并发ACK4；tick8确认完成。查看tick1应显示越序缓冲3、连续交付1，查看tick7应显示按序交付2、3。

点击“载入过早超时示例”：单包、窗口1、延迟2、初始RTO1、不丢包。tick1与3两次重传包1；原包tick2到达，重传副本tick3、5重复到达，不重复交付。全部确认tick4，但最后重复ACK要到tick7才排空；两时刻不同不是缺包或未完成。此例没有故障丢包，只有不合适超时导致的重复发送。

自定义时修改全部五项输入，旧轨迹立即清空，再模拟。非法参数给出错误；若2048tick/512事件内不能排空，整轮拒绝，减小丢包/包数或调整参数后重新计算。导出选择不存在的新文件名；取消不改变当前草稿或结果。

## 5. 产出

界面产出三泳道方向时序、逐tick事件、发送端未确认/累计ACK/下一待发、接收端下一期待/连续交付/越序缓冲、当前RTO/到期时刻、在途事件表、逐包状态以及全部发送、ACK到达和重传列表。所有确认时刻与排空时刻分列。

JSON包含feature、schemaVersion、modelVersion、导出时间、原始草稿、规范化参数/规则/硬上限、全部tick前后状态（含无事件tick）、事件及独立发送/重传/确认列表、completedAt、endedAt和最终状态。Markdown包含完整输入、模型规则、事件表、每tick快照和官方RFC链接。未运行/编辑后/模拟失败时导出只有当前草稿，明确没有完成报告。当前不支持报告导入；配置草稿恢复后需重新模拟。

组件测试导入真实`index.js`，操作实际输入与事件，覆盖默认例单步、等待tick、超时6、确认10、越序缓冲、过早超时、五参数编辑清旧结果、上限失败无假完成、草稿恢复、JSON/Markdown副本导出/能力检查/取消及销毁。DOM由Node stub提供，不代表原生Electron窗口验收；主代理另做界面视觉、工作台集成和原生文件对话框验证。未安装依赖、未启动应用、未跑缺依赖全量check。

模型不实现完整TCP或RFC一致性验证，不建立socket、不抓包、不测真实网络。它省略握手/关闭、字节序号回绕、RTT估计、拥塞控制、接收窗口变化、ACK丢失/聚合/延迟ACK、快速重传和SACK；初始超时和RTO上限是教学tick参数，不可当真实网络调参建议。协议来源支持的是相关概念及定时器参考规则，具体简化以本文声明为准。
