# T015 文件夹骨架模板

## 1. 功能内容

用一个有限文本模板创建全新的项目目录骨架。支持显式空目录、显式UTF-8文本样板和 `{{变量}}`，完整预演列出目标绝对路径、全部自动父目录、文件内容及字节数。用户核对并勾选确认后，另一步创建新目录；已有同名文件/目录立即停止，不合并或覆盖。

创建后输出完整清单：目录相对路径、文本文件字节数和回读后的SHA-256。JSON/Markdown可先预览，再另存新副本。失败或取消可能保留部分新目录，结果明确 `complete:false`、partialPath和已完成条目，供人工核对；不把部分树宣称为完整成功。

## 2. 为什么需要

项目的src/components、docs/drafts、assets/empty等结构经常重复建立，手工创建容易漏空目录或把样板写到旧项目。变量和完整预演让同一个结构可以用于不同项目名，而独占创建避免修改已存在项目。空目录是真正空目录，不通过额外.keep文件冒充。

本功能只建立明确写出的目录和文本，样板可以包含代码字样但不会被运行。不是已有文件归位、去重、运行脚手架命令或安装依赖。

## 3. 实现方式

### 模板格式

每个非空、非 `#` 开头的行是一个条目：

```text
D {{project}}/src/components
D {{project}}/docs/drafts
D {{project}}/assets/empty
F {{project}}/README.md<TAB>"# {{project}}\n\n这是显式文本样板。\n"
F {{project}}/src/index.txt<TAB>"项目：{{project}}\n"
```

`<TAB>`表示真正一个制表符，非字面文字；“载入三级目录示例”已经填入真实TAB。F行TAB后必须是一个合法JSON字符串，`\n`表示文本换行，JSON中的引号/反斜杠按JSON规则转义。不是JSON对象、脚本表达式或任意模板引擎。变量框每行 `name=value`，例 `project=demo-project`；只替换严格 `{{name}}`，缺失、不完整、嵌套占位符、重复变量均拒绝，值中的等号保留。

`model.mjs`验证整个模板后生成计划，所有父目录纳入预演。路径按 `/` 分段，禁止绝对路径、..、空段、反斜杠、Windows保留名、控制字符、尾点/空格，最多12层/路径500 UTF-16码元、每段80码点/240 UTF-8字节。显式重复路径、文件/父目录冲突按NFC+不区分大小写拒绝，父目录不同大小写/NFC表示也拒绝，不在不同平台默默建立不同结构。有效Unicode文字/Emoji保留，拒绝NUL与孤立代理码元。

上限：模板24KiB、变量4KiB/20项/名称32字符、100显式条目、包括自动父目录最多200目录、单文本8KiB/总文本32KiB。任一超限整份拒绝，未截断为“完整”骨架。路径和内容的全部变量展开后再验证；变量不执行代码、命令、条件或递归模板。

`host.cjs`通过基础PR #14的可信固定Host接口接受choose_target/plan/create。选择使用主进程保存位置对话框，只返回本窗口的随机targetId和canonical父目录下的新目录路径，不创建。plan只接收该targetId与模板/变量，重新按同一个模型验证并生成随机planId，主进程保存已验证不可变计划；create只接收本窗口planId、jobId和confirmed=true，renderer不能另传路径或替换内容。每sender最多一个选择/预演/创建操作，最多32个sender，销毁清理状态并取消作业。

创建根与所有子目录使用非recursive mkdir；文件用wx独占创建、UTF-8写出并完整回读核对，SHA-256使用Node crypto独立计算。逐步检查本次目录的dev/ino、非symlink及realpath，检查父目录未换身份。存在同名目标时停止，预演之后才出现目标也不覆盖。没有对已有目录进行递归清理或删除。普通失败保留本次部分树，清单只记录真正完成并核验的条目；失败文件可能存在但未计为完成，应人工查看partialPath。

创建最多10秒合作式期限，检查发生在底层文件调用之间，不能强制中断已进行的fs调用。取消/隐藏/离开/窗口销毁请求Abort，在下一步检查生效；已经写出的部分不会自动删掉。文件身份检查降低普通目录变更风险，不是对抗外部进程恶意竞态的文件系统隔离，也不保证断电、崩溃、慢/网络文件系统调用的硬时限。

renderer用文本节点显示所有内容，编辑模板/变量使旧计划和清单失效，确认勾选清空；完整导出包含预演文本，JSON中的代码不会执行。没有自动草稿、后台创建、命令执行、依赖安装或网络访问。清空/离开只撤去面板结果，不删除已经创建的目录。保存清单使用生产 `files.saveText(copyOnly:true)`，只有ok===true才成功，wx拒绝已有目标。

## 4. 如何使用

1. 在“工具 → 文件与批处理”打开T015，载入三级目录示例；或按D/F格式自行输入，并填写变量。
2. 点击“选择新建骨架目录位置”，在已有父目录下给一个尚不存在的新目录名。选择位置尚未创建任何内容。
3. 点击“生成完整骨架预演”，逐项核对完整目标路径、全部空目录、自动父目录、文件全文及字节数。
4. 勾选“确认完整预演与目标后新建目录”，再点击确认创建。检查complete和全部清单；失败/取消时人工核对partialPath，不能当作完整项目使用。
5. 预览完整JSON/Markdown创建清单后另存新文件。清单包含本机目标路径及文本样板，分享前核对。重复保存到已存在目标被拒绝。

## 6. 具体使用例子

载入示例，变量为 `project=demo-project`，选择一个不存在的新目录 `D:\projects\new-skeleton`（其父目录须已存在）。完整预演包含demo-project、assets/docs/src三父目录、assets/empty、docs/drafts、src/components三叶目录，以及README.md和src/index.txt两个显式样板。全部是新根下的相对路径，不写入已有D:\projects其他文件。

确认创建后清单为7目录/2文件/66 UTF-8字节，README内容为 `# demo-project`、空行及 `这是显式文本样板。`；index.txt为 `项目：demo-project` 加换行。assets/empty仍无文件。预览并保存两种清单副本，保留每文件字节数和SHA用于交付。

再次选择同一个new-skeleton目标会拒绝，原README保持相同。把模板改为 `D ../escape`，生成预演直接失败，确认按钮不可用，目标外没有新文件。要生成另一项目，换变量并选择另一个全新根，重新核对完整预演再确认。
