# L020 浮点误差显微镜

## 1. 功能内容

输入有限算术表达式，以相同语法树并行计算两条链：JavaScript Number 的 IEEE 754 binary64 加减乘除，以及将原十进制字符串解析为 BigInt 有理数的精确加减乘除。每个数值输入转换、一元运算和二元操作分别保留步骤。

界面显示完整表达式结果、当前步骤的 Number 最短显示、DataView 位模式、符号位/指数域/52位尾数域、正常数/次正规数/零分类、实际 double 的精确分数、原十进制精确链、局部表示或操作误差、累计总误差。步骤选择、前后切换和全部步骤速览可定位误差。预设 0.1+0.2、消去误差、1/3、负零、次正规数、下溢零六个可编辑例子。

## 2. 为什么需要

直接运行数学代码只能看到结果，很难分清误差来自字面量转换、已经不准确的操作数，还是本次算术舍入。“Number 显示 0.1”也不等于实际二进制值精确等于十分之一。

本功能把原输入精确值和实际 double 值都保留为分数，逐步展示误差来源，补充已有直接运行数学代码的工具。保留负零的符号位、允许次正规数和下溢至零，并明确循环小数的十进制近似，避免用一串看似精确的小数掩盖真实误差。

## 3. 实现方式、误差定义与范围

`model.mjs` 使用独立 tokenizer 和递归下降解析器，不调用 eval、Function、用户代码或外部运行时。乘除高于加减，同优先级左结合；括号和一元正负号允许。只允许十进制数字与可选科学计数法，不能输入变量、函数、隐式乘法、指数运算、数组或十六进制。BigInt 只在内部计算；产出中的有理数分子/分母都是十进制字符串，可直接 JSON 序列化。

十进制转换先去除小数点，按十进制指数构造整数及 10 的幂分母，再约分；不经过 Number 构造精确链。double 则由 DataView 按大端写入 Float64/读取 Uint64，拆成 1/11/52 位。正常数采用 `(−1)^s × (2^52+f) × 2^(e−1023−52)`，次正规数采用 `(−1)^s × f × 2^−1074`，因此可直接还原实际值的精确有理数。

所有误差均为**有符号差值**，不是绝对值或百分比：

- 输入表示误差 = 输入转换后的实际 double 精确值 − 原十进制字面量精确值。
- 本次操作误差 = 输出 double 精确值 − 对实际 double 操作数做同一个运算的精确值；包括一元正负号步骤。
- 本步骤累计总误差 = 当前实际 double 精确值 − 原十进制精确链的当前值。由于误差会被后续运算放大、缩小或消去，局部误差不能简单相加代替总误差。

Number 的文本使用最短显示，仅便于识读；`-0` 用 Object.is 明确保留。JSON 不依赖原始 Number 负零，而保留 `numberText`、符号与完整位模式；有理数零是 `0/1`，没有正负零之分。double 下溢零允许并显示误差；精确分母或 Number 分母为零（包含下溢零和负零）则拒绝，非有限输入/中间结果也拒绝整个结果，不显示部分成功报告。

容量：表达式≤2048 UTF-8 字节、128 token、括号/一元深度24、计算64步骤；单个数值最多64个十进制数字（含前导零、小数部分，不含符号/指数），指数绝对值≤324且指数部分最多3位数字。每个有理数约分后分子/分母各≤4096二进制位，运算前已有操作数受该限制，临时乘积/和≤8193位；约分后仍越界即拒绝。所有表达式解析和计算都在这些固定上限内完成，不截断为假结果。

精确分数完整保留。十进制最多展示小数点后24位，若已终止则标为精确；否则判断约分分母是否只含2/5因子，分别标为“有限十进制超过24位”或“非终止十进制”，统一明确为截断近似、不是舍入。极小非零数截断后也可能显示0.000…，必须以分数为准。

概念来源：[ECMAScript Number 类型及四则运算规范](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-ecmascript-language-types-number-type)；符号/指数/尾数布局及正常/次正规/带符号零的公式核对 [Oracle Numerical Computation Guide：IEEE Arithmetic](https://docs.oracle.com/cd/E19957-01/806-3568/ncg_math.html)。这只演示 binary64 有限四则运算，不实现其他浮点格式、可配置舍入模式或完整 IEEE 异常环境。

## 4. 使用步骤与具体例子

打开学习工作台“浮点误差显微镜”，默认表达式 `0.1 + 0.2`，点击“计算对照”。完整结果应为精确 `0.3`（分数 `3/10`）与 Number `0.30000000000000004`。初始选择步骤1：Number文本虽然为0.1，实际值分数为 `3602879701896397/36028797018963968`，输入表示误差为 `1/180143985094819840`。

点击“查看最终步骤”，应看到位模式 `0x3fd3333333333334`、正常数、实际结果分数 `1351079888211149/4503599627370496`；本次加法操作误差是 `1/36028797018963968`，累计总误差是 `1/22517998136852480`。两者不同，因为输入转换已经产生误差。展开相应分数可查看完整值，步骤选择仅改变查看位置，不重新求值。

其他可复现例子：

| 输入/模板 | 应观察到的结果 |
| --- | --- |
| `1/3` | 精确分数1/3，24位截断近似0.333…明确标为非终止；Number为0.3333333333333333 |
| `(1e16+1)-1e16` | 精确1，Number0，累计误差−1；最后一次减法自身操作误差0 |
| `-0*2` | Number文本−0、符号1、零分类、位模式8000000000000000，有理数值0 |
| `5e-324` | 次正规数，指数域全0、尾数最低位1，实际分数1/2^1074 |
| `1e-324` | Number正零，原十进制精确值非零，表示误差为−1/10^324 |
| `1+2*3` 与 `(1+2)*3` | 分别7和9，证明优先级与括号 |
| `1e308*10`、`1/0`、`1/1e-324` | 分别溢出或除零，整个结果拒绝并清空旧结果 |

编辑任何输入会清空旧步骤并提示重新计算。65位数字、25层括号、超过64步骤或约分后超过4096位的有理数同样报容量错误；不可将容量拒绝理解为该数学表达式不存在精确值。

## 5. 产出与保存

JSON 副本包含 feature、schemaVersion、modelVersion、导出时间、完整输入、选步索引和完整计算结果；每个步骤保存依赖、Number文本、分类、位字段/十六进制、实际 double 分数、精确链分数、局部误差与总误差，分数都包含完整分子/分母及十进制是否精确的标注。Markdown 包含同样全部步骤和完整模型记录、误差定义及来源。没有有效结果时仍可导出草稿，报告明确尚未计算；用户内容以文本输出，Markdown 的 HTML 字符转义。

导出能力 `files.saveTextSupportsCopyOnly` 必须严格为 true，调用参数 `copyOnly:true`、`content`、格式及文件名；只有响应 `ok===true` 才宣告成功。主桥接独占创建拒绝已有路径，取消或失败保留输入和结果。当前没有报告导入；导出草稿可用于重新计算。

配置仅保存 `schemaVersion:1` 的输入草稿。保存前测整个 JSON 的 UTF-8 字节数≤64KiB，表达式另受更严的2048字节限制；恢复先检查整个原始存储体积（含额外字段），再检查版本、字段类型和容量。超限不会写配置，明确提示关闭后只能恢复较早草稿，需导出完整JSON。语法错误可作为有界草稿保存；结果、位信息、选步不保存，重进后重新计算。切走立即保存有界草稿并清计时器，销毁释放计时器/DOM；没有自动播放或后台计算。
