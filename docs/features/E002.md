# E002 扫雷

E002 是离线可玩的一套扫雷游戏，属于“娱乐 → 独立休闲游戏”。它提供初级、中级和自定义棋盘，完整支持开局、推理开格、插旗、连开、暂停、胜负结算、成绩保存、成绩导出与同局重放。

## 功能与必要性

项目现有醒脑区包含舒尔特方格、流光记忆和第三方网页游戏入口，没有本机扫雷。扫雷增加的是风险判断与邻域逻辑排除玩法；不依赖 AI、网页站点、网络、摄像头或额外运行时，也不重复顺序记忆游戏。

游戏的目标是打开全部无雷格。数字表示周围八格内的雷数；旗标只代表玩家判断，游戏不会提前验证旗下面是否有雷。首点及周围八格必定安全，首点会展开一个空区，减少第一次点击就结束的挫败感。

## 可使用的界面

- 初级：9×9，10 个雷；中级：16×16，40 个雷。
- 自定义：宽度 5–30、高度 5–24，雷数为 1 至 `floor(宽 × 高 × 35 / 100)` 的整数。最多 720 格，最高密度 35%，所有合法棋盘都能容纳首点安全区。
- “指定局号”留空时新局使用新的随机局号；输入局号可以复现局面。参数修改后点击“新局”生效。非法参数不会替换当前游戏。
- 用时从第一次开格开始，显示到十分之一秒。计时按经过时间计算，不依赖定时器调用次数。
- 棋盘提供数字、空格、旗标、雷和错误旗的文字/符号状态。未开格在界面文字、ARIA 标签和数字属性中不暴露雷位或邻雷数字。
- 空格自动展开相连空区及边缘数字；旗标挡住自动展开，取消旗标后可重新开格。
- 插旗最多使用本局雷数的数量，旗标用完会提示先取消一面。获胜只要求打开全部安全格，不要求插齐旗。
- 双击已开数字，或聚焦数字按 Enter，可以在周围旗标数与该数字相同时展开其他邻格。旗插错位置也可能导致踩雷，界面有明确说明。
- 暂停时移除棋盘格显示并停止计时。继续后恢复棋盘和焦点位置。
- 踩雷显示所有雷位；错误旗显示 `×`。赢局或输局之后棋盘不可继续操作，结果只记录一次。

## 使用步骤

1. 从公共功能工作台打开“扫雷”，选择难度。需要指定局面时填局号，需要自定义时设置宽、高和雷数。
2. 点击“新局”。点任意格开始，数字出现后推断周围雷位，逐步开格与插旗。
3. 鼠标右键插旗或取消旗标；触屏先打开“旗模式”，再点击格子。关闭旗模式后点击恢复开格。
4. 需要休息时点“暂停”，回来点“继续”。切走工作台或隐藏窗口也会暂停，切回不会自动继续计时。
5. 打开全部安全格得到赢局；点到雷得到输局。两者都会形成一条完整成绩记录。
6. 使用“重玩本局”重新开始相同规格、相同局号与相同首点。最近成绩的“重放”也会自动开原首点，得到相同棋盘。
7. 点击“导出成绩”将近期记录与历史最佳保存成 JSON 文件。

中途重开或离开后销毁当前游戏不会计为输局。当前局不做跨进程存档；关闭功能后重新打开会开始新局，已完成成绩仍保留。

## 键盘与触屏

棋盘采用单一 Tab 入口，方向键移动焦点；Home / End 到当前行首尾，Ctrl+Home / Ctrl+End 到棋盘首尾。

| 操作 | 行为 |
| --- | --- |
| Enter | 开格；已开的数字尝试连开 |
| F | 插旗 / 取消旗标 |
| 空格 | 当前模式下开格或插旗 |
| Esc | 暂停，并把焦点移到继续按钮 |
| Tab | 在参数、操作按钮、棋盘入口和成绩操作之间移动 |
| 鼠标右键 | 插旗 / 取消旗标，不弹浏览器菜单 |
| 触屏旗模式 | 点击切换旗标，避免依赖长按和右键 |

每格具有行列、未开/旗标/已开数字的可访问名称；状态信息使用礼貌播报，计时不连续播报。触屏设备的格子放大到 44×44；大棋盘支持横向和纵向滚动。样式限制在 `.feature-e002` 内，尊重减少动态效果设置。

## 产出与存储

每条成绩记录含：棋盘宽、高、雷数、局号 `seed`、首点零基索引 `firstIndex`、胜负 `outcome`、排除暂停时间的 `elapsedMs`、有效操作次数 `moves` 及结束时间 `finishedAt`。

`moves` 计入有效开格、插旗/取消及连开请求；空区自动展开不逐格累计。首点与局号用于棋盘重放，不用于复现原玩家的每步操作。

- 配置键为 `features.E002.scores`，保存 `version: 1`、最近 20 局 `recent`、最近更新的 100 种棋盘规格的最快赢局 `best`。
- 最佳按宽、高、雷数完全相同的规格比较，仅赢局参与；最佳不会随最近 20 局列表滚动而丢失，但超出 100 种规格时移除最久未更新项，避免全局配置无限增长。局号与重玩不限最佳，成绩用于个人休息记录，不提供竞技防作弊。
- 配置服务不可用时使用本机 `localStorage` 键 `agent-toolbox:E002:scores:v1`。保存失败会提示仅当前打开期间保留，并仍可导出。
- 写入顺序串行化，避免短时间内完成多局的后发写入被前一局覆盖。读取时过滤非法记录，不把损坏记录变成重放按钮。
- 在支持新文件保护的应用中，导出调用 `files.saveText` 并设置 `copyOnly: true`，保存至用户选取的新文件；较旧宿主使用浏览器 JSON 下载。
- 导出示例顶层字段：`feature: "E002"`、`version: 1`、`exportedAt`、`recent`、`best`。不会输出进行中游戏的隐藏雷表。

## 具体可重放例子

使用初级 9×9、10 雷，局号填写 `E002-demo`，点击“新局”，首点选择**第 5 行、第 5 列**（零基索引 40）。该格及周围八格均无雷，空区自动展开。

这是一份固定测试局。其雷位为：

| 行 | 列 |
| --- | --- |
| 1 | 1 |
| 1 | 7 |
| 2 | 6 |
| 3 | 1 |
| 3 | 9 |
| 4 | 8 |
| 5 | 2 |
| 5 | 9 |
| 6 | 7 |
| 9 | 3 |

以上坐标是文档测试样例，正常游戏界面在结算前不会显示它们。

完整输局重放：首点开第 5 行第 5 列后，点击第 1 行第 1 列，即得到输局、显示全部雷位并增加一条成绩。点击该成绩的“重放”，首点会自动重开；再点第 1 行第 1 列仍会输局。

完整赢局重放：重玩该局，在上表十处插旗，再逐个打开其余未开格；安全格计数到 **71 / 71** 时判胜，保存赢局和此规格最佳。等待、暂停与继续会改变记录用时，不会改变雷表。

纯逻辑测试使用可控时钟：在 1000 ms 开首点、到 6500 ms 打开全部安全格时，结果为 `won`、`elapsedMs: 5500`。暂停例子：开局后游玩 2500 ms，暂停 90000 ms，再继续 1200 ms 后踩雷，结果为 `lost`、`elapsedMs: 3700`。

## 实现

- `src/renderer/features/E002/meta.json`：供公共工作台发现的分类、标题、用途。
- `index.js`：同步 `create(root, ctx)`；创建完整 DOM 界面，统一鼠标/键盘/触屏操作入口，保存和导出成绩，返回 `activate`、`deactivate`、`destroy`。
- `model.mjs`：纯 JavaScript 游戏状态机、输入约束、种子随机布雷、邻格计数、空区展开、连开、计时及成绩验证。内部雷表与已开/旗标集合采用私有字段；UI 只读取经过遮蔽的 `getView()`。
- `style.css`：独立作用域样式，34px 常规格/44px 触屏格、滚动棋盘、可见焦点与数字对比度。
- `test/feature-E002.test.js`：纯逻辑与实际渲染函数的事件 DOM 适配器测试，不新增依赖。

布雷延迟到第一次合法开格；从候选位置剔除首点及邻格，再使用局号、宽高、雷数和首点派生的确定性随机数做 Fisher–Yates 洗牌。首点不同可能得到不同雷表，所以重放同时保存首点。

生命周期：`deactivate` 暂停游戏并取消唯一计时器；`activate` 保持暂停，等待用户继续；`destroy` 暂停、取消计时器、移除窗口可见性监听、销毁棋盘和样式链接，并回收下载对象 URL。已结算且排队中的成绩写入仍会完成，异步回调不会更新已销毁界面。

测试覆盖尺寸与密度边界、初级/中级/最高规格及四角安全、固定布局、隐藏信息、空区边界、旗标配额、连开正确/错误旗、完整赢输、结果锁定、暂停排除时长、最佳成绩比较、键盘和触屏旗模式、页面退出与窗口隐藏、重复重开、成绩只记录一次、存储失败、损坏记录过滤和副本导出请求。

这里的 UI 测试运行实际 `index.js` 和项目 `h()`，使用事件 DOM 适配器验证交互与生命周期；它不构成真实 Electron 窗口、浏览器截图、触屏硬件或辅助技术验证。平台可见性事件和下载保存流程仍需宿主集成烟测。游戏没有 AI 解题、联网排行、无猜测棋盘保证或跨设备同步，也不会自动恢复中断的对局。
