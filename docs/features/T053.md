# T053 接口类型离线生成

## 1. 功能内容

从用户粘贴或主动选择的本地 UTF-8 JSON Schema 生成三个完整文件：`types.d.ts` TypeScript 静态类型声明、`validation-mapping.json` 说明性的校验规则映射、`generation-manifest.json` 生成清单。全部文件在 UI 中完整预览后，点击确认导出，通过生产 `files.exportBundle(copyOnly:true)` 创建全新副本目录。源文件不改写。

本 MVP 明确支持 **JSON Schema 2020-12 的有限静态投影**，不读取 OpenAPI 文档、不生成运行时验证器、不调用真实接口。清单和映射固定标注 `runtimeValidation:false`；无法表达的约束逐 JSON Pointer 列出。生成成功不等于源已通过完整元 Schema 验证、不等于生成类型与完整 Schema 等价、不等于任何接口实例已验收。

## 2. 为什么需要

接口字段变动后手工维护类型容易把必需字段变成可选，或丢失数组元素类型。离线生成让小型 Schema 与类型副本之间有可核对的关系，同时明确区分静态类型能力和额外约束。用户能先看完整类型、规则映射和省略说明，再选择新目录保存，无须服务端、账号、网络或大模型。

## 3. 实现方式与支持范围

`model.mjs` 的独立递归 JSON 解析器拒绝普通/转义后重复键、非法/非有限数字和不安全整数、尾随文本、不配对 Unicode、原始控制字符。数字使用 JavaScript IEEE-754 有限数值；不安全整数拒绝，避免大整数枚举静默取整，不提供任意精度十进制。对象采用无原型字典，不执行 eval、Schema、正则 pattern 或生成代码。预算：源最多64 KiB UTF-8，JSON深度最多8（根0），**所有 JSON 节点合计最多200**（含容器、Schema关键字值、注释、required/enum元素），三文件合计最多2 MiB UTF-8。超限明确阻止，无截断/部分产物。SHA-256 用 WebCrypto，固定三个安全相对文件名，与生产目录接口的每文件2 MiB预算兼容。

规范依据为官方 [JSON Schema 2020-12 Core](https://json-schema.org/draft/2020-12/json-schema-core)、[Validation](https://json-schema.org/draft/2020-12/json-schema-validation) 及 [TypeScript Object Types](https://www.typescriptlang.org/docs/handbook/2/objects.html)。本实现不是这些规范的完整实现。

- 顶层/子 Schema 可以为对象或 boolean。true→unknown，false→never。只有 `$schema:"https://json-schema.org/draft/2020-12/schema"` 是支持的显式方言；省略时明确按有限2020-12域处理，清单 `draftDeclared:false` 并增加信息项。其他方言/子 Schema重新声明阻止生成，不联网取元 Schema。空 Schema `{}`→unknown。
- type 支持 string/number/integer/boolean/null/object/array 及这些类型的非空、无重复数组。可空用 `["string","null"]` 等表达；不同类型分支生成 union。integer 静态映射 number，逐路径标记无整数运行时检查。OpenAPI 的 nullable 不属于支持类型语法，作为未知关键词警告省略，不能当作可空保证。
- properties 必须为对象，其每个值是支持 Schema。properties/required 必须配合显式含 object 的 type；required 必须为无重复字符串数组，且每个必需名称在 properties 里声明。缺 required 表示全部可选；必需属性不带 `?`，可选属性带 `?`。空 object 使用 `{ [key: string]: unknown }`，避免 TS空 `{}` 接受非null原始类型的问题。非空 object 生成列出属性的结构类型；TypeScript新鲜字面量的额外属性检查和 JSON Schema 默认允许额外键并非完全同一语义，仍属于有限投影。
- array 必须明确 items（支持对象或boolean）；生成 `Array<元素类型>`，支持元素 union、本地引用和对象。缺 items、旧草案 tuple items数组、prefixItems 都阻止，不擅自推断元素或固定长度。
- enum 为非空、无重复的原始 JSON 字面量数组，只允许 string/finite number/boolean/null；每个值必须符合显式 type（若有），类型冲突阻止。对象/数组枚举拒绝。生成 TS literal union；不支持 const。
- 只支持根 `$defs` 字典和精确 `#/$defs/<一个JSON Pointer段>` 的 `$ref`，包括 `~1`、`~0` 转义。不支持百分号片段编码、任意根路径引用、嵌套defs、锚点、外部 URL、file、缺失引用。不会读文件或发网络请求。定义按名称代码单元排序，别名固定 Def1/Def2…，不内联反复展开。所有定义（含未引用者）都检查；自/互循环引用在有限依赖图中拒绝，错误给引用路径，无部分声明。ref 的 type/properties/required/items/enum 结构兄弟字段不能安全交集时明确阻止；annotation和被明确省略的约束不静默合并。
- allOf/anyOf/oneOf/not/if/then/else、contains、additionalProperties/patternProperties/propertyNames、dependent*/unevaluated*、$id/$anchor/$dynamic*、$vocabulary、definitions、const 等结构/引用语义超范围，逐路径 error 阻止整个输出。OpenAPI/swagger根文档明确报 openapi_not_supported。不存在“当作普通 Schema 忽略 paths”行为。
- minimum/maximum/minLength/maxLength/pattern/format/uniqueItems 等剩余约束与未知关键词，在各 Schema 层按关键词 JSON Pointer 报 `constraint_or_unknown_keyword_omitted` warning；从静态投影省略，不执行其值，也不声称它们有效或已验证。未知关键词的内部数据不当作支持子 Schema解释；这一整块省略由该关键词路径说明。支持 title/description/$comment 字符串注解，但 description/comment不注入代码或复制到产物。
- 根 title 只允许大写英文字母开头、随后字母数字下划线、总长≤64的名称，并排除 Def数字名和 Array。其他 title 回退 Root 并提示；Array避免遮蔽生成代码中的内建泛型。属性名和枚举字符串用 JSON字符串转义，额外转义 Unicode行分隔符；注释仅固定文本，不拼接用户文字。恶意引号、换行、注释结束符保留在字符串属性/字面量中，不变为代码。所有 UI 内容用 h()/text/textarea渲染，不作为 HTML执行。

`validation-mapping.json` 是 Schema路径、投影表达式、sourceType、required、原始enum、ref别名及defs对照的**说明性映射**，不是可执行验证器或完整校验配置。生成清单包含方言/根类型、源UTF8字节SHA-256、所有省略/阻止范围提示，前两个文件的bytes/hash；清单不嵌入自己的hash以避免循环。UI/传输对三个文件（包括清单）均显示/携带独立hash，由主进程重算核对。

用户选择文件通过真实 HTML File API 只读读取，核对实际字节数，用 fatal UTF-8解码，不猜编码；UTF-8 BOM可由解码器去除。不记录源文件名或任意系统路径。粘贴的源和生成类型可包含字段名/enum值，不做敏感脱敏，分享前自行检查。内容仅当前面板内存，不调用ctx.config自动持久化。

生成后只出现完整预览及显式确认导出按钮。缺 `exportBundleSupportsCopyOnly===true` 阻止调用。生产桥接重验路径、规范Base64、SHA，再由保存对话框确认新的目录名，已有目标拒绝。仅 `ok===true` 提示成功；取消单独提示，false/undefined/throw保留预览并提示失败，不显示内部error；partialPath提示新目录清理未完成，不回显该内部路径。目录写入承认正常错误清理边界，不提供崩溃/断电事务保证。

异步任务票据在读取之后、解析后的yield、每个摘要之后核对；取消、清除、源编辑、隐藏、暂停、销毁使旧任务失效。同步解析/字符串生成受小输入预算控制，不声称随时即时中断。暂停不自动恢复生成、不自动导出；切换具体功能销毁所有源/结果。已经完成的原生导出不能因UI取消撤回，但旧回调不能恢复预览或提示成功。

## 4. 如何使用

1. 在工作台打开 T053。默认就是必填 name字符串、可选 tags字符串数组示例；可改成自己的有限 Schema，或读取本地UTF-8 JSON。
2. 点击“生成并预览全部文件”。先看逐路径提示，检查是否省略了业务必须依赖的约束。结构 error 会阻止全部文件，需修改源后重新生成。
3. 逐个看完整 types.d.ts、validation-mapping.json、generation-manifest.json。检查字段必需性、数组元素、引用别名和不支持项；不要把映射当成执行过的校验。
4. 点击“确认导出已预览文件到全新目录”，在保存对话框选择新的目录名。导出目录含固定3文件，不能覆盖源或已有目录。取消/失败保留预览可重试。
5. 编辑源就废弃旧预览，须重新生成。需要保留产物时先导出再切换功能；可随时清除源与所有预览。

## 5. 使用后产出

每次完整生成并确认得到一个新目录，包含静态声明、规则映射和生成清单。无网络请求记录或运行时实例验收结果；不是OpenAPI全工程生成器，不产生npm包、可执行JS或API调用代码。Schema里的enum字面量会成为静态声明和映射的一部分，源文本整体不会复制到清单，源摘要不代替人工分享检查。

## 6. 可重现例子、测试与限制

点击默认“生成并预览全部文件”，types.d.ts 关键内容精确为：

```ts
export type User = {
  "name": string;
  "tags"?: Array<string>;
};
```

其源为 `{"$schema":"https://json-schema.org/draft/2020-12/schema","title":"User","type":"object","properties":{"name":{"type":"string"},"tags":{"type":"array","items":{"type":"string"}}},"required":["name"]}`。`{name:"小明"}` 合类型，缺 name 或 tags含number 不合类型。清单issues为空，runtimeValidation仍false。

给 name Schema加 `"pattern":"^[A-Z]"` 和 `"minLength":3`，类型仍string；提示出现 `#/properties/name/pattern`、`#/properties/name/minLength` 省略项，不能声称匹配或长度已检验。`{"type":["string","null"]}`→`string | null`；`{"type":"array","items":{"enum":["A","B"]}}`→`Array<"A" | "B">`。

`{"$defs":{"A":{"type":"string"}},"$ref":"#/$defs/A"}` 生成 Def1=string 与 Root=Def1；改为 A引用自身会报具体 `$ref` 路径 ref_cycle_not_supported，无导出按钮。外部 URL `$ref` 同样阻止且不联网。
