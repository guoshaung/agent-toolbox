# L031 论断原文绑定

## 功能内容

在本地TXT或Markdown原文中选择一段，填写自己的论断，建立引文卡。每张卡包含论断、原文文件名、实际原始引文、UTF-16范围及完整原文的SHA-256。修改或重新导入源文件后重新校验；全文版本不一致使绑定失效，旧引文保留供人工比对，不自动迁移位置。

## 为什么需要

阅读笔记常只有结论，回头难以确认哪段文字支撑了论断，源文件被修改后旧位置也可能指错。本功能保留当时引用和来源版本，使“能定位到原文”可被核对。它不判断论断真假或因果关系，引文是否支持结论仍由使用者判断；不会替代引用许可、文献审查或学术查证。

## 实现方式

独立模块由功能工作台发现，纯模型和同步create界面仅引用自身文件及公共h。Web Crypto SHA-256针对完整原始UTF-8字节编码，保留BOM及CRLF/CR。文件使用fatal UTF-8解码，拒绝非法字节；界面textarea统一LF，通过边界数组映射回原始UTF-16索引，左闭右开，不切开emoji代理对。源文件编辑后采用编辑框实际文本及LF，因而重新计算得到新源版本。

每张卡必须有非空完整选区及论断。哈希不同标sourceMismatch；哈希一致但源长度、引用位置或内容不一致标anchorMismatch；全部一致才bound。文件改名而内容相同仍有效，并提示名称差异。恢复报告严格核对版本与50张卡结构，重新计算当前原文哈希及所有状态，拒绝重复编号和损坏范围，不相信导入的旧validCount或status。

限制为原文1MiB UTF-8、500000 UTF-16单位、50卡、每引文10000单位、每论断2000单位；恢复JSON文件最多4MiB。界面在摘要计算、文件读取和导出期间禁用操作，销毁后丢弃异步回调。材料只留本功能当前内存，不写全局配置，不读取输入文字所称的路径或链接，不执行Markdown、脚本或联网。

## 如何使用

1. 从工作台打开L031，填写来源名称，粘贴原文，或导入UTF-8 TXT/MD。
2. 填写自己的论断，用鼠标选择原文，或聚焦原文并以Shift和方向键选择完整文字。
3. 点击“将选中原文绑定论断”，查看引文卡、原始范围、源哈希及绑定状态。
4. 修改或导入新版源文件，点击“重新校验全部绑定”，核对失效卡。旧引文不会被新版本覆盖；需要新版引用时添加新卡，旧卡可单独删除。
5. 导出JSON或Markdown副本，切换功能前保存。JSON可经“恢复JSON报告”重新导入，恢复后重算所有绑定。

## 使用后的产出

JSON版本1报告包含完整当前原文、名称、UTF-8字节数、UTF-16长度及哈希；全部引文卡原始来源/哈希/范围/文本、论断和重新校验状态/原因；有效与失效数量、明确的偏移定义。它包含完整材料，分享前需要自行确认范围。Markdown包含当前来源哈希与逐卡论断、来源版本、定位、状态及原始引文，不包含整篇当前原文；用户文字会转义，引用使用缩进文本。

两种文件通过生产saveText安全副本能力保存，copyOnly=true防覆盖；不支持能力时提示更新，取消与失败保留输入。配置不存原文或卡，切换具体功能会丢失未导出的材料。报告恢复失败保留当前原文与卡。

## 具体使用例子

点击“载入原文示例”，来源为“实验摘录.md”，原始内容含CRLF：第一行“本地实验”，第二行“样本量为20。”，第三行“平均结果为10。”。示例已经选中第二行并填入论断“这个本地实验使用了20个样本。”。点击绑定，C1保存引文“样本量为20。”，原始UTF-16范围[6,13)，显示绑定有效。

将原文的20改为21并重新校验：当前全文哈希变动，C1绑定失效，原始引文仍为20，不被自动更新为21。导出JSON可看到currentSource.text含21，C1.quote含20及旧哈希，validCount=0、invalidCount=1。恢复这个JSON报告后重算仍失效，不能通过伪造导入状态使旧卡有效。

## 验证与边界

8项Node专项测试通过，独立使用node:crypto计算预期哈希，覆盖绑定、源变化、CRLF偏移、UTF-8 BOM、emoji边界、文件改名、损坏锚点、重复卡编号、文本/引文限额及报告定位。不含PDF解析、网页下载、OCR、多个文件同时管理、跨版本自动迁移或AI判定证据。

主代理在隔离隐藏Electron 33.4.11窗口中使用生产preload、功能目录和实际文件写入器：载入CRLF示例并使用真实textarea选区绑定，卡显示[6,13)且有效1；修改20为21，重校验失效1，旧引文仍为20。实际写入1032字节JSON并解析，确认currentSource含21、卡含旧哈希/原始20和sourceMismatch。通过实际File/DataTransfer和change事件导入故意把旧status改成bound的报告，恢复后重新计算仍显示失效1。
