# L024 蜕变关系验真

## 1. 功能内容

选择四个内置纯函数之一，编辑安全整数 JSON 数组和固定输入变换，先预测适用关系通过或失败，再观察实际结果。内置升序排序、错误去重排序、整数求和、错误常量偏差求和；只执行本功能定义的实现，不运行任意用户 JavaScript。

四类关系为排序置换不变、长度保持、幂等、线性缩放。界面明确适用矩阵，完整显示原输入/结果、变换输入/结果、每条检查的关系预期及实际值、事前预测和观察对照。失败保留全部可复现样例，并随完整 JSON/Markdown 副本导出。

## 2. 为什么需要

没有每个输入的标准答案时，仍可以先声明函数应满足的性质，再比较变换前后的行为。错误排序去重可能同时通过置换不变和幂等，却违反长度保持；常量偏差求和在缩放因子1时可能通过，因子2时则失败。用这些明确例子训练用户检查关系前提与样例区分力，避免把“某关系通过”当作“函数全部正确”。

这新增的是性质验证、反例复现与预测复盘，区别于既有答案比对、模板默写或直接运行代码。关系由本功能明确提供，不自动创造标准答案预言机或自动推导任意函数的性质。

## 3. 实现方式与适用前提

`model.mjs` 包含纯函数、输入校验、固定变换与关系检查，`index.js` 提供表单和观察卡片，`style.css` 使用真实主题变量 `--bg-raised`、`--bg-sunken`、`--line`、`--text` 等。不增加依赖或外部运行时。

| 内置函数 | 行为 | 适用关系 |
| --- | --- | --- |
| sort | 复制输入、按数值升序排序，保留重复 | 置换不变、长度保持、幂等 |
| sort-dedupe | 先排序后去重；刻意错误 | 同上，用长度检查揭示错误 |
| sum | 精确整数和 | 线性缩放 |
| sum-offset | 精确整数和+1；刻意错误 | 线性缩放 |

排序函数的置换 `P` 固定为反转或左轮转一位（首项移至末尾），保持全部输入元素及重数。检查 `f(P(A))=f(A)`，数组按值/位置比较。长度关系独立检查 `len(f(A))=len(A)` 和 `len(f(P(A)))=len(P(A))`，不能只比较两个错误输出是否一样长。幂等把第一次输出作为第二次输入，检查 `f(f(A))=f(A)`。

求和只检查 `f(kA)=k×f(A)`；其中预期来自第一次函数输出，不是额外标准答案。排序不做线性检查，求和不做排序三关系；模型入口也明确拒绝不兼容关系和未知函数。`k=1` 显示退化提示；置换未改变输入时显示区分力有限提示。

输入为0–32项 JSON 数组，元素必须为 Number 安全整数（±9007199254740991）；小数、布尔、字符串、对象、代码和不安全整数拒绝。输入中的−0归一为整数0，重复元素保留，空数组允许。缩放为−10至10整数，数组文本≤2048 UTF-8字节。求和和整数乘法内部用 BigInt 得到精确值，再核对输出、变换输入和关系预期的安全整数范围；越界拒绝整个观察，不拿舍入结果作真假结论。排序比较用大小关系，不依赖大整数相减精度。

每个函数至多三项关系、每数组至多32项，运行次数固定且有界，无后台任务或自动播放。函数/输入/变换改变后清空预测与旧观察；预测改变也清空旧观察，必须重新验证，不能在观察记录里事后改写预测。未预测可以直接观察，不计预测对错。

## 4. 使用步骤与可复现例子

默认错误去重排序输入 `[2,2,1]`、反转置换。先在“长度保持事前预测”选择“预测通过”，再点击“验证适用关系”，应该观察到：

| 关系 | 原输入/结果 | 变换输入/结果 | 结论 |
| --- | --- | --- | --- |
| 置换不变 | [2,2,1] → [1,2] | [1,2,2] → [1,2] | 通过，两个输出相同 |
| 长度保持 | 输入长3、结果长2 | 输入长3、结果长2 | 两项长度检查均失败，预测错误 |
| 幂等 | [2,2,1] → [1,2] | [1,2] → [1,2] | 通过，仍不能证明排序正确 |

点击“载入正确排序示例”并验证，输出 `[1,2,2]`，三关系全通过。将置换改为左轮转，默认变换输入应为 `[2,1,2]`；完整元素重数仍为两个2、一个1。

点击“载入常量偏差示例”，函数sum-offset、输入 `[1,2,3]`、因子2。可先预测线性失败，再验证：原结果7，变换输入 `[2,4,6]`，变换结果13，关系预期 `2×7=14`，失败且预测正确。因子改1则通过但有退化提示；改0时预期0、实际1，仍失败。切换为sum、因子−2，原结果6、变换结果−12，关系成立。

空数组、单项、重复负数也可测试。输入 `[9007199254740991]` 缩放2必须因变换输入越界拒绝；`[1.5]` 或33项输入必须拒绝。编辑后旧观察消失，需要重新预测与验证。

## 5. 产出与保存

JSON 副本包含 feature、schemaVersion、modelVersion、导出时间、完整输入及事前预测、适用关系观察、全部原/变换输入与结果、检查预期/实际、通过标志、警告、关系违反样例和预测错误ID。Markdown 含同样完整记录、适用前提与“通过不证明全部正确”的范围说明。没有有效观察时也可导出草稿，但明确没有反例或关系结论。用户文本按文本输出，Markdown的HTML字符转义。

导出要求 `files.saveTextSupportsCopyOnly===true`，调用 `content`、格式、文件名和 `copyOnly:true`；只有响应 `ok===true` 才宣告成功。主桥接独占创建，拒绝覆盖已有文件。取消/失败不清空草稿和观察。当前没有文件导入，导出草稿可用于重算。

全局配置只存 `schemaVersion:1` 输入/预测草稿，不存观察和反例。保存前测JSON UTF-8总大小≤64KiB；数组文本另限2048字节，选项字符串各≤64字符。恢复先检查整个原始存储体积（含额外字段）、版本、字段类型和容量，再提取已知字段。超限不写配置，明确提示关闭后只能恢复较早草稿，需导出完整JSON。语法错误可作为有界草稿保存，验证时再校验。切走保存并清计时器，销毁释放DOM，异步导出提示不会重建已销毁界面。
