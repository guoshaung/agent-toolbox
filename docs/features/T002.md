# T002 · 表格脏数据清洗

所属分组：工具 / 文本与结构化数据。规格对应 `docs/feature-planning/tools.json` 的 T002。

## 功能与必要性

导出表格常见首尾空白、全角字符、大小写不统一或空字段。直接在电子表格里批量替换容易漏列、误删行，也难说明改变了什么。本功能在本机处理 CSV / TSV，允许按列选择规则，先检查结果与逐格变化，再保存新副本。

默认只去除数据字段的首尾空白，保留全部数据行和表头。每个输出数据行、变化单元格和移除记录都可追溯到输入的原始物理行号。处理一个表格的多行数据；本版本不合并多个文件。

## 实现与接入

- `src/renderer/features/T002/meta.json` 提供工作台发现元数据。
- `index.js` 通过 `../../core/ui.js` 的 `h` 创建原始内容、文件输入、列选择、清洗规则、统计、分页预览及副本导出界面。`create(root, ctx)` 同步返回 `activate / deactivate / destroy`。切走会取消尚未完成的解析或清洗，销毁会清空内存数据。
- `model.mjs` 提供 `parseDelimited / cleanTable / serializeTable / serializeReport`。使用有限状态解析器处理 CSV 引号与换行，无新增包依赖；纯模型可独立测试。
- 浏览器文件输入使用 `FileReader` 读取，严格 UTF-8 解码。文本及文件内容均不上传、不写入配置或历史记录。
- 输出调用现有 `window.toolbox.files.saveText`，payload 为 `{ content, extension, defaultName, copyOnly: true }`。调用前要求 `files.saveTextSupportsCopyOnly === true`。基础层须使用独占创建 `wx` 拒绝已存在目标；缺少此能力时允许预览但禁止导出。单靠新文件名不能保证不会覆盖，保护在主进程落实。

输入解析约每 32,768 字符让出事件循环；清洗和导出约每 128 行让出事件循环。取消通过 AbortSignal 检查。结果和审计表每页最多显示 25 条，避免一次创建全部表格 DOM。保存对话框阶段由其取消按钮停止保存，已经发出的文件保存 IPC 不支持 AbortSignal 撤回。

## 使用方式

1. 粘贴 CSV / TSV 文本，或选择一个本地 UTF-8 文件。`.csv` 和 `.tsv` 文件扩展名自动选择分隔符；粘贴时自行选择。需要时取消“首行为表头”。
2. 点击“解析并选择列”。解析错误显示物理行号；成功后勾选需要清洗的列，可全选或清空选择。
3. 设置规则，点击“生成清洗预览”。表头保持原样，蓝色单元格表示值变化。使用分页检查结果、原值、新值和移除原因。
4. 核对统计，设置副本文件名、是否附加源行号列、是否输出 BOM。点击“保存结果副本”，在保存对话框检查最终路径并保存。已有目标会被拒绝，请选择新的名称或目录。
5. 可另存 JSON 变更清单。输入或清洗规则变化会使旧预览失效，必须重新生成预览才能保存。

界面提供五行示例，可直接验证默认去空白规则。文件导入失败不会替换之前有效的原始内容。

## 输入及清洗规则

- 仅支持逗号 CSV 或制表符 TSV，UTF-8 文本；允许一个文件开头的 BOM。GBK 等编码明确报错，请先另存 UTF-8。不自动猜测编码或分隔符。
- 双引号字段可包含分隔符和换行，字段内双引号写为 `""`。CRLF、LF 和单独 CR 均可作为记录分隔符；引号内的原始换行保持。
- 双引号必须从字段首字符开始，闭引号后只能接分隔符或记录换行。`1,"abc" extra` 和未闭合双引号均报错。
- 除完全空的物理行之外，每条记录必须与首条记录列数一致。完全空的物理行作为整行空字段保留。短的非空行不自动补齐，长行不截断。两列空行可写为 `,`；单个尾部换行不会制造额外数据行。
- 默认首行为表头。空表头显示“第 N 列”，重复表头通过列序号区分，原表头值保持不变。
- 清洗只应用于选中列。执行顺序为：首尾空白 → 连续空白 → NFKC 字符规范化 → 大小写 → 空值替换。``trim`` 和连续空白规则涵盖 JavaScript Unicode 空白；连续空白会将字段中的多次空格、制表符、换行合并成一个普通空格，须主动启用。
- 空值仅指当前规则处理后的空字符串；字面量 `NULL`、`null`、`0` 不当空值。空值替换默认关闭，最多 1,000 字符。
- 整行空值和完全重复行默认保留。主动选择移除后，按清洗后的全部列判断；先移除整行空值，再检查完全重复。重复行保留首次出现者，并记录其源行号。若先填充空值为非空文本，相应行不再是空行。
- 变化统计包含被移除行中的单元格变化；保留行数与移除行数另行列出。规则不会修改输入记录。

### 五行验收示例

```csv
姓名,城市
 张三,北京
李四 ,上海
王五,广州
赵六,深圳
钱七,杭州
```

选择表头、两列、默认去首尾空白：原始 5 条数据，保留 5 条，变化 2 个单元格和 2 行。变化清单为物理第 2 行 `" 张三" → "张三"`、第 3 行 `"李四 " → "李四"`。其它字段值不变。导出附加行号时输出：

```csv
_source_line,姓名,城市
2,张三,北京
3,李四,上海
4,王五,广州
5,赵六,深圳
6,钱七,杭州
```

### 引号、多行与空值示例

```csv
id,note,status
1,"coffee, tea",NULL
2,"line one
line two",
3,"said ""yes""",0
```

不开启连续空白规则时第二条 note 保留换行。三条数据的源物理行号为 2、3、5。启用空值替换为“未填写”仅替换第二条 status；`NULL` 和 `0` 保持。第四物理行属于第二条记录，不被计作独立数据行。

### 空行、重复与错位示例

```csv
a,b
,
x,y
 x ,y
```

默认输出 3 条数据。主动移除空行及重复后输出一条 `x,y`，保留源物理行 3；源行 2 记录为空行移除，源行 4 记录为清洗后重复并指向源行 3。改成非空短行 `x` 时解析报“第 N 行有 1 列，预期 2 列”，不能静默猜测缺少哪一列。

## 产出与容量限制

- 清洗副本：UTF-8 CSV / TSV，记录分隔符为 CRLF，可选 BOM。字段分隔符、双引号、换行或首尾空白会按 CSV 规则引用。没有公式计算、类型转换或电子表格重算；内容以原始字符串保存，电子表格应用可能将公式形态文本解释为公式，分享时应检查相应字段。
- 默认添加 `_source_line` 列；若源表头已有该名称，增加后缀 `_` 直到不重名。无表头时行号位于每条记录第一个字段，可关闭此选项。
- JSON 变更清单：功能 ID、源名称、规则、统计、原值/新值及移除原因。它含原始内容，应按输入文件同等私密程度保管。
- 输入最多 5 MiB UTF-8 字节、10,000 条数据、100 列、100,000 单元格（含表头及扩展空行）、每字段 50,000 字符。结果或变更清单最多 12 MiB，扩大的替换文本同样受限。
- 所有数据行移除且无表头时，结果文件导出禁用，仍可保存移除清单。
