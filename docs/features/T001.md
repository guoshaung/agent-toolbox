# T001 JSON 数据验收台

## 1. 功能内容

粘贴完整 JSON，或读取本地 JSON 数据和可选 JSON Schema 文件，查看格式化原文、字段树、类型统计及逐条验收结果。顶层数组逐条模式最多200条，每条明确有效／无效／未验收；关闭该模式时 Schema 检查整个 JSON 文档。无效记录列出序号、JSON Pointer 错误路径、规则、原因与参数，每条只报告第一个错误。

完整 JSON 与 Markdown 报告保留数据原文、Schema原文、解析结果、全部字段树、所有记录及原文 SHA-256。界面字段树每页40节点，导出不按当前页截断。文件只读，不回写来源；结果不自动写入配置，不调用 AI 或联网。

## 2. 为什么需要

JSON 能解析不等于满足交付要求。例如记录缺姓名或年龄误写成字符串，格式化工具仍会显示正常 JSON。将结构检查和明确 Schema 分开，用户可以定位到具体记录和字段，同时区分空 Schema、无法编译的 Schema、有效及无效数据，避免把“没有运行校验”显示成通过。

Schema 仅定义此次结构及规则条件。通过不证明来源真实、业务正确或作者身份；原文摘要只是字节核对，不是可信签名。没有对未知字段业务意义作自动推断。

## 3. 实现方式与支持边界

model.mjs 负责有界解析、RFC6901路径、六类JSON值计数、格式化、记录划分与报告。可信 Host 启动一次性 Node worker，在独立线程中运行静态捆绑的 Ajv 8.20.0。支持同步 draft-07，本地 $ref 可用；显式 $schema 仅接受 draft-07 的标准HTTP标识。不加载远程 Schema，没有格式插件、自定义JS或异步Schema。严格模式拒绝未知关键字／未知格式；关闭数据类型转换、默认值填入、删除额外字段，原值不会为校验而改写。allErrors=false，每记录只取首个错误。required／additionalProperties错误进一步附上实际字段名，键中 ~ 与 / 分别编码为 ~0 和 ~1。

数据原文≤24KiB、Schema≤16KiB、编码请求≤64000字节；数据≤24层／3000节点，Schema≤12层／500节点，记录≤200，完整报告≤2MiB。全部容量超限整体拒绝，不截断。原文件UTF-8严格解码；BOM不被默默剥离，不能按JSON解析时会明确失败。JSON.parse重复对象键按最后值，本功能不检测重复键；数字采用JavaScript有限Number，超大整数可能舍入、负零格式化为0、不保留数字词法或任意精度。完整原文仍保留。非有限数拒绝。

每线程自启动到完成限2秒，V8旧生代预算96MiB、新生代16MiB、栈4MiB；全局最多4个线程，每窗口单任务，取消／窗口销毁／超时均终止自身线程，直到实际exit才释放槽。报告只有收到完整结果且正常exit后才返回；异常exit撤销已发送的成功结果。超时或取消不提供部分通过报告。内存参数限制V8相应区域，不是完整进程RSS硬限或进程安全沙箱；同步正则在worker内可能耗时，截止后终止线程。可信固定worker代码用eval加载，用户数据仅作为workerData，renderer CSP不增加unsafe-eval。

worker-bundle.cjs为Node20 IIFE静态包，独立携带模型及Ajv，运行不依赖项目开发依赖。vendor/manifest.json固定Ajv与4个依赖版本、包字节及SHA；五份原始许可证和NOTICE随功能提交。用esbuild0.25.10按NOTICE分别构建Ajv CJS和worker IIFE，不修改共享package或lockfile。官方依据：[Ajv安全说明](https://ajv.js.org/security.html)、[Ajv JSON Schema](https://ajv.js.org/json-schema.html)。

## 4. 如何使用

打开工作台T001，输入完整JSON数据及可选Schema。默认顶层数组逐条模式把同一Schema应用于每条记录；要校验数组本身，取消“顶层数组逐条验收”，并提供type=array及items规则。点击“解析统计并验收JSON”。检查记录表和字段树，翻页查看节点，完整格式化框可选择全部文本。

数据或Schema编辑会清除旧报告，必须重新运行。空Schema只分析结构，所有记录未验收；Schema编译失败时仅保留结构与编译错误，所有记录未验收，没有通过结论。JSON解析失败、容量限制、线程失败／超时／取消不产生可导出的完整验收报告。文件读取显示原始字节哈希，人工编辑后旧文件摘要不再代表当前文本。

点击完整JSON或Markdown预览，核对其中所有原文，再“保存已预览JSON验收报告新副本”（按钮保存当前所选格式）。调用既有生产saveText，只在防覆盖能力明确且回执ok===true时显示成功，始终copyOnly:true；已有目标以wx拒绝。失败或取消保留预览。隐藏／离开会取消本工具任务并丢弃报告；返回不自启。切换具体功能或重载会从默认示例开始，输入没有自动草稿恢复。

## 5. 产出与具体使用例子

输入三条记录：第一条name='记录一', age=20；第二条只有age=21；第三条name='记录三', age='22'。Schema要求对象、必需name与age、name为非空字符串、age为≥0整数且不允许额外字段。逐条模式结果为 **1有效、2无效**：第二条路径 **/1/name**，规则required；第三条路径 **/2/age**，规则type。第三条年龄仍为字符串'22'，不会替用户转换成22。

修正第二条姓名及第三条年龄为数字后，重新运行可得到3有效。清空Schema则3条都未验收；把Schema改成无效JSON则编译错误、0有效／3未验收。把整份数据切换到whole模式，Schema改为数组items对象规则，首条缺姓名时错误路径仍是/0/name，但记录表只有1条整体结果。

JSON副本包括source、sourceSHA256、parsedData、formatted、fieldTree、parsedSchema、schemaStatus／schemaError、records、counts及规则边界；Markdown包含同一完整JSON。200条各有name和age的数据产生601树节点，16页显示，但报告保留全部200记录／601节点及最后一条n199。副本包含全部用户原文，不是脱敏摘要。
