# E030 吹牛骰子

## 1. 功能内容

3至6位玩家在同一设备玩完整吹牛骰子。每人开局5颗六面骰，每轮重新掷剩余骰子，逐人遮挡查看，然后依次递增叫价或质疑。质疑亮出本轮所有骰子并精确计数，失败方扣1颗，零骰退出；只剩一位即获胜。默认1不万能，可在开局设置开启万能1，建立本局后规则及玩家锁定。无联网、AI、下注或付款。

数量1至本轮总骰数、点数1至6，按数量优先、点数其次的词典顺序严格增加。例如3个4→3个5、3个6、4个1均合法，3个4→2个6非法。已到总骰数个6时只能质疑。开启万能1后，叫2至6统计该点数加上所有1，叫1只统计1；没有数量翻倍或换规则的隐含特例，词典顺序保持一致。实际数量低于叫价，叫价者失败；实际数量达到或超过叫价，质疑者失败，恰好相等也算质疑失败。

## 2. 为什么需要

聚会时省去实物骰杯和手动记分，通过明确叫价规则、自动扣骰及退出跳过减少争议。同屏交接配合参与者背过屏幕，让当前玩家自行看骰；这是合作隐私，不是账户授权隔离，不能抵御旁观、屏幕录制、开发者工具或设备访问。

## 3. 实现方式与安全边界

纯本地model.mjs使用WeakMap保存本局私密状态。公用view仅返回玩家剩余骰、当前交接者、公开叫价和已结算轮次；未亮骰数组不放到返回的公用view、config或报告。私密查看只返回当前玩家复制数组。质疑结算后当前私密数组移除，历史只保存已亮骰本轮。最多6人、每人5骰，最多29次扣骰即终局；每輪最多总骰数×6种叫价，严格递增保证调用历史有界，报告限2MiB且超限拒绝，不截断。

生产骰子调用crypto.getRandomValues(Uint8Array)，不降级Math.random。每次读取32字节，取第一个小于252的字节，点数为byte%6+1；0至251中每个余数恰好42次，因此避免256直接取模的偏差。持续128批拒绝则报错，无静默替代。模型测试可注入roll函数，生产界面不提供指定骰点或种子。随机源依据：[MDN Crypto.getRandomValues](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues)。它提供适合密码学用途的伪随机值；本功能未作硬件熵认证或联网防作弊承诺。

每轮先按起手玩家开始的顺时针顺序逐一看骰，再回到起手玩家叫价。确认叫价或完成看骰均遮盖并交接，下位玩家必须再次点击本人查看。render前清空旧私密节点文本、清空输入、移除旧监听并替换节点，不用CSS隐藏骰子，不把私密骰写入标题或数据属性。暂停遮盖，恢复不会自动显示；destroy清空本局与监听，旧按钮不能继续操作。切换具体功能会销毁本局，暂无私密存档或恢复。

下一轮失败方起手；若扣至零骰，顺时针下一存活玩家起手。只掷存活者剩余骰，已退出者既不参与看骰也不被叫价轮到。一次完整重掷成功后才提交新状态；随机源异常保留上一轮结算，不留下半局。终局后禁止看骰、叫价、质疑及继续下一轮，仍可另存已亮骰历史或确认新局。

## 4. 如何使用

1. 设置3至6位唯一玩家名称，每名1至20个Unicode字符，无首尾空格/控制字符，默认甲、乙、丙。可添加或移除最后一位。选择万能1规则，然后“建立本局并开始看骰”。
2. 把设备交给提示的玩家，其他人背过屏幕。本人点击“我是某某，私密查看自己的骰子”，记住后点“记住骰子，遮盖并交接”。全部看完回到起手者。
3. 当前玩家本人查看骰子后填写数量和点数，点“确认叫价并遮盖交接”；下位玩家可增加叫价，或“质疑上一叫价并亮全部骰”。第一次叫价前质疑禁用。输入非法不推进玩家，显示规则错误。随时可“立即遮盖自己的骰子”。
4. 结算页显示每人本轮骰点、实际数量、成功/失败、扣骰者、剩余骰及下一起手者。非终局点“下一轮重新掷骰并遮盖”；退出者跳过直到胜者产生。
5. 已有结算轮次后可保存JSON或Markdown副本。按钮只导出已亮骰轮次；即使下一轮正在私密查看，保存动作先遮盖，只导出上一批已揭示历史。生成阶段可取消；进入原生另存后在对话框取消。建立新局需确认清空当前局及未保存历史；取消确认返回时保持遮盖。

## 5. 产出与具体可复现例子

UI展示每轮公开叫价、亮骰计数、质疑结算、每人剩余骰、退出和最终胜者。JSON包含feature/version、锁定规则、玩家、完整/进行中标记、胜者、已揭示轮次数，以及每轮起手者、亮骰、顺序叫价、质疑者、实际值、成功与否、失败方、扣骰前后、退出和下一起手者。进行中导出标记currentUnrevealedRoundExcluded，整段当前私密轮次不进入报告。Markdown保留同样的已揭示顺序和结算并转义玩家名称；副本文件默认liars-dice-revealed-copy.json/md，仅copyOnly能力存在时允许调用saveText，只有ok===true报成功，已有目标拒绝覆盖。

确定性验收例在测试注入roll序列（生产界面随机，不允许固定骰点）：甲=[4,4,2,2,2]，乙与丙各=[2,2,2,2,2]，关闭万能1。逐人看骰后甲叫3个4，乙质疑。亮骰实际2，challengeSucceeded=true、loser=甲，剩余[4,5,5]，下一轮甲起手；JSON第1轮actual=2、before=[5,5,5]、after=[4,5,5]。同一例也经生产组件事件路径的Node DOM fixture验证，不冒充随机Electron固定结果。

普通窗口精确操作：保持甲/乙/丙和1不万能→逐人查看并交接→甲本人查看→数量1/点数1→叫价→乙查看→质疑。用亮骰中所有1的数量A核对界面实际值：A=0甲扣1、[4,5,5]；A≥1乙扣1、[5,4,5]。无论随机点数怎样，本轮总剩余骰必为14，导出仅1轮。继续下一轮后保存报告，rounds仍只有上一已亮骰轮次。

本次真实Electron随机验收恰为A=2，甲叫1个1、乙质疑失败，乙扣1，JSON/MD通过生产写入器实际保存。固定边界例另含：实际等于叫价质疑失败；开启万能1，2个4+3个1叫6个4时实际5；叫1时仍只计3个1；甲扣第五颗后退出，下一轮乙起手且看骰者仅乙、丙；3人10轮特定序列后丙胜，所有游戏操作禁止；6人最长29轮、29次扣骰后恰一胜者。
