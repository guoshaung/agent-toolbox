# T069 接口响应稳定性采样

## 1. 功能内容

对用户明确授权的一个固定 HTTP/HTTPS URL 串行发送有限次 GET 或 HEAD，完整保留每次状态、HTTP 状态码、请求错误码、原始耗时与阶段事件。先校验并展示全部样本计划，再点击确认才连接。默认 10 次、完成后间隔 250ms，允许 1–20 次、0–2000ms 间隔。每请求固定 2 秒，全批固定 60 秒；不重试、不跟重定向、不登录、不读取应用或系统代理配置，不更改网络设置。

成功定义是：严格 TLS 验证通过（HTTPS）且有限 HTTP 200–299 响应头接受成功，不代表业务成功或完整正文下载成功。HTTP 其他状态记 `http_error`，2 秒/批次截止记 `timed_out`，网络、证书或预算错误记 `request_error`，主动停止记 `canceled`，尚未发起记 `not_run`。

## 2. 为什么需要

单次成功可能掩盖间歇性超时。有限采样保留全部原始记录，能说明成功分母、少量异常以及本次观察到的阶段边界。它不是负载测试、抓包工具或持续监控；不推断服务器业务根因，也不保证一次短批次代表长期可靠性。

## 3. 实现方式与支持边界

生产主进程通过固定 `feature-host` 桥加载本功能 `host.cjs`；宿主 `invoke(plan)` 只解析，`invoke(run)` 检查确认字段、固定输入与任务限额。任务在首个 await 前预留；更早到达的取消先登记意图，稍后的同 ID 运行零请求并输出未运行记录。每 sender 同时一个任务，最多 128 个历史任务/取消意图；最多 32 个 sender，销毁窗口释放该 sender。输入只接受固定键，URL ≤2048 UTF-8 字节、HTTP/HTTPS、明确 1–65535 端口，拒绝用户密码、控制字符和歧义主机名。localhost、常规 IDNA 域名及单播 IP 可用。默认未启用 family 自动重试；不承诺 DNS 多地址回退。

`agent:false`、`Connection:close`，不复用连接。固定 Host/Accept/User-Agent，不读取浏览器 Cookie、认证、Referer 或环境代理。HTTPS 使用 `rejectUnauthorized:true`、原始目标主机名检查、TLS 1.2–1.3、HTTP/1.1，不关闭验证。失败不会换 DNS、换代理或降级协议。系统 DNS 查询不可保证硬中止；取消实际销毁 request/socket、清除间隔/截止定时器并隔离晚回调，不能声称操作系统查询本身终止。

响应头 ≤16KiB/128 项，最多三个信息响应，socket 在完成时及数据事件观察的已读字节预算 64KiB；不读取应用正文，收到响应头立即销毁。Node 初始缓冲可能已经含正文或超过预算后才观测，64KiB 不是网络逐字节硬防火墙。报告不保留正文或任意响应头，只有状态码、事件、观察到的字节数等固定元数据。

`totalMs` 是单调时钟从启动请求到完成/错误/截止的未舍入差值；不含下一次等待。UTC 仅辅助关联，墙钟调整不会改变单调耗时。`events` 是相对本请求起点的 socket 分配、lookup、connect、secureConnect、请求写完、首应用数据、响应头事件。DNS 段=lookup−socketAssigned，TCP 段=connect−lookup；字面 IP 无 lookup 时 TCP 使用 socketAssigned。TLS 段=secureConnect−connect；首字节等待=firstByte−连接 ready（HTTPS secureConnect，HTTP connect），包含本地写请求开销，不是纯服务器时间。缺边界为 null 并写原因；IP DNS、HTTP TLS 不适用，不能当作 0。系统缓存来源未知。请求/响应头事件是 Node 本机观察边界，不是网络线上的精确物理阶段。

统计分母只含 `success/http_error/timed_out/request_error`；取消及未运行排除，零分母结果 null。报告分别列成功总耗时、全部已评估总耗时（含超时），及成功样本每个已知阶段的 n/未知/不适用数量。分位数使用 nearest-rank：排序后第 `ceil(p*n)` 项，无插值；P50/P90/P95 的每组 n 独立。错误样本不混进成功阶段统计。10 次中 2 超时是 8/10=80%；1 成功后取消其余，不应写 1/10=10%。

## 4. 如何使用

打开功能工作台 T069，输入自己的已授权 URL、固定方法、次数和完成后间隔。点击“校验输入并展示完整采样计划”，逐条核对目标、请求方法、固定头、最多请求数、截止和最坏时长；这一步不联网。最坏计划可能超过 60 秒，界面明确说明批次会截断。点击“确认授权目标，启动有限采样”开始；取消会停止当前连接/间隔和后续样本，不自动重跑。隐藏、切走或销毁面板取消并忽略晚结果。编辑输入清除旧计划/结果/预览；清除按钮释放输入及报告内存。

URL 查询是实际请求的一部分，显示和报告保留原始规范 URL，分享前自行核对；片段去除。URL 中的认证信息拒绝并不回显错误原文，但用户源输入框仍可见输入内容。结果中不回显错误异常路径、响应凭据或任意头。设置、源与报告不写全局 config，功能无持久任务历史；切换面板可能丢失未保存结果。

## 5. 使用后产出

界面显示全部 ≤20 个样本及统计，没有只展示成功样本的截断。选择“预览完整 JSON/MD 报告”，先看完整文本与副本名，再保存。JSON 保留完整计划、全部原始样本和统计；MD 包含完整表格及完整 JSON，≤2MiB，超限阻止而不截断。生产 `files.saveText` 强制 `copyOnly:true`，已有目标用独占创建拒绝覆盖。只有 `ok===true` 提示成功，取消、false、undefined、异常均保留原预览并准确提示。旧宿主缺副本能力时阻止导出。报告不是服务器故障证明或业务 SLA 验收证明。

## 6. 具体可重现例子与验证

在受控本机 HTTPS 服务建立 `/mix`：总共十次 HEAD，第三和第八次不返回响应头，其余返回 200。输入 `https://localhost:<服务端口>/mix`、10 次、50ms 间隔。校验阶段服务收到 0 请求；确认后按顺序只收 10 次，第三/第八次约 2 秒超时，8 次成功，分母 10，成功率 80%。保存 JSON 后按 success 行原始 totalMs 独立计算 nearest-rank 并和 P50/P90/P95 核对。输入 IP HTTP 服务时 DNS/TLS 为不适用 null；输入 localhost HTTPS 服务则按实际 lookup/connect/secureConnect 事件形成已知或明确未知阶段。

专项测试：`node --test test/feature-T069.test.js test/feature-host.test.js` 共 31 项通过（本功能 25 项、公共 Host 6 项）。包含真实本机 HTTP 十次两超时、GET/HEAD/302/503不跳转、严格 HTTPS 证书有效/不信任/过期/域名错、有限响应头、等待后取消、lookup 晚回调、早期取消零请求、独立固定时钟事件差值、独立分位数 oracle、批次在间隔期间截止、sender 隔离以及真实组件事件/完整预览/保存 false/undefined/throw/canceled。组件测试使用真实模块和简化 DOM，不能替代 Electron 验证。另验证 MD 零分母写 null 而不伪造百分比。
