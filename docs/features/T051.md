# T051 配置文件一致性核对

## 1. 功能内容

在功能工作台打开 T051，读取或编辑 2–5 份 JSON/YAML 配置。配置1固定为基准，其余按路径核对必需缺键、类型差异、额外项、可选缺项，并列出所有配置共同存在且类型一致的路径。支持有限必需/忽略路径规则，逐页看结果，先完整预览再保存 JSON/Markdown 新副本。

本项只检查结构和类型。相同类型的两个值可以完全不同；`accepted:true` 只代表必需存在和类型检查通过，不证明值相等、配置能运行、配置已去敏或部署正确。公共清单包含容器与叶子路径；两个空对象是公共 object 路径，两个空数组是公共 array 路径，null 单独分类。空基准对象没有路径，公共清单为空；对照新增路径仍报告 extra。

## 2. 为什么需要

开发、测试和生产配置经常缺少同一字段，或将布尔值写成字符串。按完整源文本比对容易把密钥带进截图或分享文件。本项只保留固定来源别名、键路径和类型元数据，使结构核对和无值报告可在本机完成，不读取环境变量、不执行程序、不连接配置服务或上传文件。

## 3. 实现方式与边界

- `model.mjs` 使用独立 JSON 递归解析器，拒绝普通/转义后重复键、尾随文本、非法数字、非有限数、控制字符和不配对 Unicode。对象用无原型字典创建；不采用后者覆盖重复项。
- YAML 复用仓库已安装 js-yaml **4.3.2** 的原始浏览器 ESM 分发，保留 MIT LICENSE。版本、模块 SHA-256 和官方来源见 [vendor/README.md](../../src/renderer/features/T051/vendor/README.md)。没有新增包、Node require、CDN 或运行时联网。官方 [load API](https://github.com/nodeca/js-yaml/blob/4.3.2/README.md) 说明单文档、JSON_SCHEMA、重复键及深度选项；本项使用 `JSON_SCHEMA/json:false/maxDepth:8/maxTotalMergeKeys:0`，并拒绝警告。
- **YAML 有限范围**：只接受单文档块式映射/块式序列及 JSON_SCHEMA 标量。解析前保守拒绝正文任意 `& * ! ? { } [ ] <<` 候选，甚至引号/注释里的这些字符也拒绝；拒绝指令和显式复杂键。因此不支持锚点、别名、自引用、merge、显式标签、流式结构，空对象/空数组请改用 JSON。此限制在库解析前执行，避免先构造别名图再判断容量。JSON_SCHEMA 的 YAML 数值语法由 js-yaml 定义，允许部分非 JSON 写法；不是严格 JSON 数字语法。日期样式在该 schema 中作为字符串。非有限数值拒绝。
- 两格式都要求顶层对象，深度最多8（根为0），每份最多2000节点（含根、容器、叶子），键最多128个 UTF-16 code unit，完整路径最多512个；每份配置及规则输入最多64 KiB UTF-8，最多5份配置，总配置正文最多320 KiB。JSON Pointer `/a~1b/~0x` 表示 `a/b` 下的 `~x`。数组固定按索引 `/items/0`、`/items/1` 核对，不按值排序/对齐；增删首项会影响后续索引类型。number 不进一步区分整数/小数。
- 解析返回 `Map<path,type>`，不把对象/值放入报告。固定别名配置1–配置5，不使用源文件名、路径或用户提供的名称。所有容器也生成路径，以区分 null/object/array、空容器和容器缺失。祖先类型变化可能同时导致子路径 missingRequired；每项准确列出，没有隐藏或去重掉子项。
- 规则为 `{"format":"T051-rules","version":1,"ignore":[]}`。允许字段只有 format/version/required/ignore，重复/未知字段拒绝。省略 required 时所有未忽略的基准路径必需；显式 required 为最多100个基准路径的数组，`[]` 表示均可选。ignore 最多100个精确 JSON Pointer 路径，忽略自身和整个子树；必需路径必须存在于基准且不能落入忽略子树。路径列表重复、非法 `~` 转义、非字符串、未知版本全部拒绝。ignore 可针对对照额外路径，不使用通配符，不实现 JSON Schema。
- 缺必需项和类型差异使 accepted=false。extra、optionalMissing 只提示，不使其失败；ignored 数量不进入逐项/公共列表。路径排序，结果/公共列表每页50；完整导出不随当前页截断。最多4个对照×每对3998个联合路径，理论15992条逐项记录；完整输出最多4 MiB，超出就阻止，不截断。
- 文件通过 HTML File API 只读用户主动选择的文件；限制实际 File.size 与读得字节完全一致，用 fatal UTF-8 解码，不猜 GBK/二进制/其他编码。UTF-8 BOM 可由解码器去除。没有任意系统路径读取、目录递归或源文件写入。
- 正文默认只在当前面板闭包内存，textarea.value为空且 readonly；点击显露才主动进入 DOM 编辑。核对、读文件、数量变更、隐藏、暂停/恢复再次遮蔽。显露编辑与本机调试器可访问内存属于准确边界：遮蔽不是加密或沙箱。解析异常只输出固定错误码和固定说明，不显示原解析异常、片段、值、文件名或内部保存错误。**键名/路径本身仍可能敏感**，不承诺路径去敏，分享前自行检查。
- 不调用 ctx.config，不自动保存源/报告/设置或秘密草稿；切换具体功能销毁源和结果。异步 File 读取、每份解析后、每50条核对后检查任务票据，可取消；编辑清除、隐藏、暂停、销毁让旧回调失效。同步解析期间不声称即时中断，容量/深度限制先行。暂停不自动写文件。
- 先完整预览后 `files.saveText({copyOnly:true})`；缺 `saveTextSupportsCopyOnly===true` 阻止保存。生产写入器独占创建新目标；仅 `ok===true` 提示成功，canceled单独提示，false/undefined/throw 保留预览并提示失败，不输出宿主 error 内容。取消/销毁不能撤回已经完成的原生写入，旧返回不会再更新面板。

## 4. 如何使用

1. 选择含基准的配置数量。每份明确选择 JSON 或 YAML 格式，读取 UTF-8 文件；正文保持遮蔽。或点“显露并编辑配置N”，粘贴完后遮蔽。
2. 默认规则已经准备好但同样遮蔽。需要可选/忽略项时显露规则，编辑有限 v1 JSON；也可读取规则文件。只检查用户选中的前 N 份，其他未选份仍留内存，清除按钮一次清除全部。
3. 点“核对路径与类型（遮蔽源值）”。语法或规则失败时没有部分/旧报告；结果会明确必需缺项、类型差异、额外/可选项及公共项。
4. 翻页看全部类型记录，再预览完整 JSON 或 Markdown。确认没有敏感键名后保存新副本；对话框里选新的文件名。选已有文件会失败而不覆盖。
5. 输入/格式/数量/规则编辑后旧预览废弃，须重新核对。取消后等当前读取结束再重试。退出或切换功能前导出需要保留的报告。

## 5. 使用后产出

报告格式 `T051-report v1`，含固定来源别名、基准别名、accepted、规则路径、分类计数、完整逐项 records 和完整 common 列表。逐项只含 `source/path/expected/actual/required/status`；公共项只含 `path/type`，没有值、值摘要/长度、完整配置、源文件名、映射、原异常上下文。状态为 pass/typeMismatch/missingRequired/optionalMissing/extra。JSON 适合后续人工或脚本核对，Markdown 可分享结构检查；无配置转换或修改产物。

## 6. 可重现例子、测试与限制

直接点击“演示：布尔与字符串差异”可得到 `/enabled` boolean→string 的 typeMismatch、`/nested/port` missingRequired 和 `/extra` extra；`/TOKEN` 为共同 string 路径但其演示值不会输出，`/empty` object、`/items` array 为公共路径。

实际文件例子，基准 JSON：

```json
{"enabled":true,"TOKEN":"只保留当前内存的值","items":[1],"empty":{}}
```

对照 JSON：

```json
{"enabled":"true","TOKEN":"另一个值","items":["1"],"empty":null}
```

默认规则下 `/enabled`、`/items/0`、`/empty` 三项类型差异；`/items` 为公共 array，`/TOKEN` 为公共 string，公共并不表示 TOKEN 值相同。完整预览里没有两个值。修改规则为 `{"format":"T051-rules","version":1,"required":["/enabled"],"ignore":["/TOKEN"]}`，TOKEN 整项被忽略，但其他已存在路径的类型差异仍报告失败。

YAML 对照可用 `enabled: "true"` 换行 `TOKEN: 本机值`，选择 YAML 再核对；`a: 1` 换行 `a: 2` 报 yaml_syntax；`a: &ref 1` 或 `a: "*literal"` 在解析前报 yaml_unsupported_token。保守拒绝的字符出现在真实密码中时也会阻止 YAML，可改用 JSON，不会偷偷解析别名。
