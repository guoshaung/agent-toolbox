# E007 猜颜色密码

## 功能和验收

这是本地完整可玩的颜色密码推理游戏。六种颜色用 A–F 字母标记，密码有四位，颜色允许重复。玩家最多提交十轮四位猜测，每轮反馈“位置命中”和“仅颜色命中”；四位位置全部命中即通关，十轮未解会显示答案。

位置命中表示颜色与位置都对；仅颜色命中表示颜色对但位置错，排除已计入位置命中的密码位。每个密码位最多计一次。例如密码 `AABC`、猜测 `ADAA` 的反馈为位置命中 1、仅颜色命中 1。反馈不告诉玩家具体哪一位或哪种颜色命中。

## 必要性和功能边界

这项游戏用有限次数的反馈训练排除和组合推理，适合短时休息。与已有流光记忆不同，玩家不需要记住曾显示的序列，而是推断从未显示的隐藏组合。

游戏离线运行，无需 AI、账号、网络、摄像头、音频或新增依赖。元数据和默认导出遵循独立功能工作台契约，由工作台发现 `features/E007/meta.json` 并加载同步 `create(root, ctx)`；仅使用现有 `h` 和配置接口，不改共享注册表、主进程或预加载代码。

## 实现和状态

- `model.mjs` 使用固定版本的局号生成器：FNV-1a 将局号转换成 32 位状态，mulberry32 生成四次 A–F 取值。局号大小写敏感，限定为 1–32 位字母、数字、下划线或短横线，相同局号始终产生同一密码。生成器版本 1 的局号 `2293` 产生 `AABC`，`demo` 产生 `FAAC`。
- 反馈先移除位置相同的命中，再分别统计剩余密码和猜测的颜色频数，逐色取两者较小值。重复猜中同一颜色不会超过密码的剩余颜色个数。
- 密码由模型私有字段保存。未结束的 `getView()` 不提供答案；界面不会创建隐藏答案节点、答案属性或答案数据标记。只有通关或十轮失败才渲染答案。历史成绩不保存答案或猜测内容，重玩相同局号不会从历史条目提前暴露本局答案。
- 阶段为待开始、运行、暂停、通关、失败。首次合法提交完整四位开始计时，未填满输入不消耗轮数或启动计时。结束后冻结成绩，禁止继续猜测；每局只保存一次结果。第十轮猜对优先判为通关。
- 暂停遮住已提交猜测与当前输入，冻结计时，输入仍保留。功能切出、工作台退出、页面隐藏会自动暂停，返回后手动继续。销毁移除节点、样式、事件监听器、计时器与尚未回收的下载 URL。
- `index.js` 创建四个输入位、六色字母按钮、逐轮反馈和完成记录。所有猜测都经过模型校验。`style.css` 使用 `.feature-e007` 限定作用范围，由本模块样式链接加载。

## 使用方法

1. 打开功能即可获得随机局号；点“随机新局”另开一局。“重玩本局”清空猜测和当前输入，以同一密码重新开始。
2. 复现指定局面时，在“复现局号”中输入局号并点“按局号开局”。无效局号会显示说明，保留当前游戏。
3. 点击需要编辑的输入位，再点击 A–F 的颜色按钮。填入后自动选择下一位，第四位后回到第一位；可重复选择同一颜色。输入位和颜色按钮都有可见字母和辅助说明，判断不依赖色彩。
4. 填满四位后点“提交猜测”。反馈追加到逐轮记录，当前输入清空，开始下一轮。通过位置和颜色计数排除组合；两种计数互不重复。
5. “清空输入”只清本轮草稿，不影响轮数和已提交猜测。“暂停”停止交互和计时，点“继续”恢复。猜中或十轮未解后显示答案与成绩，可从记录“重玩此局”。

键盘操作：Tab 到输入位，按 A–F（大小写均可）填写颜色；左右箭头选前后位置，Home/End 选首末位，Backspace/Delete 清当前位，Enter 提交，Esc 暂停。暂停后 Tab 到“继续”恢复。鼠标和触屏使用相同的输入位与颜色按钮。

## 产出和本地保存

每轮产出猜测与两类反馈。完整结束的一局产出局号 `seed`、胜负 `outcome`、使用轮数 `rounds`、有效游玩时间 `elapsedMs`、结束时间 `finishedAt`。界面保留最近 20 局完成摘要，包括失败局；不建立跨不同密码的“最佳成绩”，可按局号重玩比较同一谜题。

配置键为 `features.E007.records`，数据结构为 `{version: 1, recent: [...]}`；没有配置接口的独立环境退回本机 localStorage。读取时验证盘面无关的成绩字段并剔除额外字段，每条摘要只有固定字段，列表最多 20 条。中途重开、退出或销毁不生成成绩，未完成棋盘不持久化。保存失败仍能游玩，内存成绩可导出。

“导出成绩”输出 JSON，包含功能 ID、数据版本、生成器版本 1、导出时间和最近记录。支持副本保存的原生接口使用 `copyOnly: true`；没有该能力时使用浏览器下载。取消保存明确显示已取消，失败显示错误，不声称成功。

示例：局号 `2293` 第一轮 `ADAA`、第二轮 `AABC`，两次提交之间有效游玩 2.5 秒，可产出：

```json
{
  "seed": "2293",
  "outcome": "won",
  "rounds": 2,
  "elapsedMs": 2500,
  "finishedAt": "2026-10-02T00:00:00.000Z"
}
```

时间与日期仅为说明，真实游玩按有效时间记录；测试使用可控时钟验证 2.5 秒。记录不会包含 `answer`、`secret` 或历史猜测数组。

## 可重放例子、验证与限制

验收样例：

1. 输入局号 `2293`，点“按局号开局”。此时答案不显示。
2. 按顺序点颜色按钮 A、D、A、A，再点“提交猜测”。第一轮应显示“位置命中 1 · 仅颜色命中 1”，剩余 9 轮，答案仍不显示。
3. 按顺序点 A、A、B、C，再提交。应显示“第 2 轮通关”“答案：AABC”，第二轮反馈为位置 4、仅颜色 0，并新增一次成绩。
4. 点“重玩本局”，答案与旧逐轮记录应消失；最近成绩只显示局号和摘要。

失败例子：重新打开局号 `2293`，连续十轮提交 `DDDD`。每轮位置和仅颜色命中均为 0；前九轮不显示答案，第十轮显示“十轮已用完”“答案：AABC”，记录为 `lost`、10 轮。若前九轮提交 `DDDD`、第十轮提交 `AABC`，则应通关。

暂停例子：第一轮提交 `ADAA` 后填写下一轮首位 F，游玩 2.5 秒并暂停 90 秒，再继续。F 和第一轮反馈都应恢复；清空输入，再用时 1.2 秒提交 `AABC`，有效完成时间为 3.7 秒，不包含暂停时间。

运行 `node --test test/feature-E007.test.js`，20 项测试覆盖输入边界、局号稳定性、重复颜色反馈、1,296 种密码与独立频数算法的核对、隐私视图、十轮输赢、暂停时间、记录上限和导出。组件测试通过事件 DOM 适配器加载实际 `index.js` 与现有 `h`，触发真实事件处理函数，验证调色板、键盘编辑、重复颜色样例、胜负、隐藏答案、暂停恢复、生命周期、取消保存与下载清理。

这些测试验证模型与组件事件逻辑，不等同于真实 Electron 布局和设备交互验收；真实客户端验证由集成环节完成。当前仅支持四位、六色和十轮，不支持线上对战、自动解题、改变规则、成绩导入或未完成局恢复。局号用于复现娱乐局面；已经看过答案后重玩同一局当然可凭记忆猜中，成绩不会标记为新谜题。
