# L028 测试污染定位

## 1. 功能内容

“学习 → 编程验证与调试训练”的有限 key/value DSL 沙盘。用户编辑 2–6 项测试及共享运行顺序，工具完整比较所有测试独立运行、指定共享顺序和全部两两有向测试对，展示断言差异、完整状态轨迹和修改来源。

默认 A 执行 `set x 1`，B 执行 `assertMissing x`：A/B 独跑均通过，A→B 的 B 失败，定位 x 与 A 第1步。可以手动把顺序改为 B A 查看差异，也可以逐格查看 A→B/B→A 的独立矩阵模拟。纯本地，无 AI、新依赖、真实测试框架或代码执行。

## 2. 为什么需要

单项测试通过、整套失败时，常见教学问题是测试意外共享状态。只看最终失败信息看不到前序留下了什么，也容易把测试本来就有的错误全部归为污染。本工具保留独跑基线，并逐操作比较共享实际状态，标出断言读取的键及来源。

工具同时展示另外两种情况：测试独跑已失败，不能直接怪前序；前序状态使原本失败的测试通过，可能掩盖了测试自身问题。状态差异与修改来源是有限模型内的关联证据，工具不自动证明真实程序的因果关系，也不提供真实 pytest/Jest/进程隔离验证。

## 3. 实现方式与明确边界

`meta.json` 供公共工作台发现；`index.js` 提供同步 `create(root,ctx)` 和生命周期；`model.mjs` 提供纯 DSL 解析、独跑/共享/有向对模拟、比较、保存及报告；`style.css` 使用项目实际主题变量。用户文本通过 h/textContent/value 呈现，不用 eval、Function 或 innerHTML 执行代码。

### 输入与 DSL

测试ID/key为 1–12 位 ASCII 字母开头，其后只允许字母、数字或下划线。拒绝重复测试ID，以及 `__proto__`、`prototype`、`constructor`。操作名区分大小写，不接受注释、空行、分号、表达式或任意 JavaScript。

| 操作 | 明确语义 |
| --- | --- |
| `set key value` | 写入或覆盖一个键，记录本测试/步骤来源 |
| `delete key` | 删除键；不存在时状态不变，仍记录删除来源 |
| `assertMissing key` | 仅当键不存在时通过，false/0/空字符串均不是缺失 |
| `assertEqual key value` | 键必须存在且类型和值均相同；例如字符串"1"不等于整数1 |
| `reset` | 清空全部现存键，记录各被清除键的修改来源 |

值只允许整数（绝对值≤10亿）、true/false、有效 JSON 双引号字符串（≤64 Unicode码点、拒绝孤立代理项）。字符串可包含标准JSON转义，例如 `set name "a\n☺"`；不允许null/数组/对象/小数/指数/代码。-0按普通整数0处理，不区分浮点符号零。每测试1–8操作、脚本文本≤2048 UTF-8字节；2–6测试，最多48操作和48个现存键；共享顺序≤128字节，以空白/逗号分隔，所有测试必须恰好一次，重复、未知、遗漏均拒绝，不部分运行。

断言失败只记录失败，不改变状态，后续指令继续，包含 delete/reset。这是固定教学语义，不模拟某个真实框架的异常中止规则。因而失败后清理确实能影响后序结果，不能默认第一条失败就跳过 cleanup。

### 三组执行与矩阵

每项独跑建立 fresh `{}`。指定共享顺序只在该顺序内共享状态；所有测试恰好执行一次，断言失败仍继续下一个操作和测试。每个有向对另建 fresh `{}`，先执行行测试，再以其最终状态执行列测试；不同矩阵格不互相共享，前序失败后仍执行完后续清理。矩阵包含 n(n−1) 格，最多30格，对角线标“不测自身”；全部n个独跑基线独立展示。

它不是枚举全部测试排列：6项只分析指定顺序及30个有向对，不宣称验证720个完整排列。两两对也不能替代长顺序；多项前序的组合效果由用户给定共享顺序展示。

上限同时界定工作量：独跑最多48操作，指定共享最多48，30对各最多16，共576操作步骤。所有有效轨迹完整计算，超限输入直接拒绝，不截断。结果面板选择仅切换详情，导出始终保留全部基线、共享运行和全部有向对。

### 差异与来源口径

每操作保存完整状态前/后与实际修改 diff。共享/有向对的后序逐步与相同测试的独跑轨迹对齐，记录独跑状态、断言结果、全状态差异与断言读取的键差异。不存在用 `{exists:false}` 表示，存在用 `{exists:true,value}`，不会把 undefined/null或数组拼接文本当成缺失值。

一个断言仅在“该断言独跑通过、共享失败，且读取状态不同”时计为差异新失败断言。测试级“新增失败测试”要求整项独跑通过而共享失败。因此测试可同时有自身bug与另外新增的差异断言，此时两个计数不会被混为一谈。独跑失败→共享通过单独标为“失败被掩盖”。

最早差异失败按用户共享顺序、再按测试操作步骤选择。来源显示两项：键自最近缺失后首次set的测试/步，以及最近一次set/delete/reset。覆盖不同值仍保留首次set；删除或reset后重新set产生新的首次来源。例如 A写1、C覆盖2、B查缺失，首次A#1、最近C#1。当前值2是C的写入，A只是这段持续存在状态的首次写入；首次来源不是当前值的唯一作者或因果最小源。删除缺失键仍可显示最后删除者，但没有读取差异就不会据此称污染。工具不穷举删除前序以证明最小原因。

### 生命周期、持久化与副本

编辑脚本、ID、顺序或载入示例后清空旧矩阵/轨迹。配置键 `features.L028.state` 仅保存 `schemaVersion:1` 输入草稿；结果不写配置，重开后需重算。保存前通过 TextEncoder 检查整个JSON≤64KiB UTF-8，再检查每字段容量；恢复先检查完整原始对象体积和版本，未知大字段不能绕过总限额。草稿允许暂时语法未完成，但必须满足结构与字段容量。

编辑250ms合并保存，切走/销毁清计时器并尝试保存；无后台测试/网络。超限不写配置并提示导出，关闭只能恢复较早草稿。导出完成后不会向已销毁组件更新DOM。

导出检查 `saveTextSupportsCopyOnly===true` 并发送 `copyOnly:true`，主进程用 wx 创建副本，已有目标拒绝覆盖。仅响应 `ok===true` 宣告成功；取消、未确认成功和错误均明确反馈。JSON包含完整输入和所有结果；Markdown包含同等完整数据，转义HTML并使用适应用户反引号长度的围栏，避免字符串破坏报告结构。

## 4. 使用步骤与具体例子

### 核心示例

1. 打开“功能工作台 → L028 测试污染定位”，保持默认A/B脚本和顺序 A B。
2. 点击“分析隔离与共享”。独跑失败0/2、共享失败1/2、新增失败测试1、差异新失败断言1、有向对2。
3. 最早差异显示“测试B#1，键x：独跑不存在 → 共享1”；首次来源与最近修改均为A#1。
4. 点击“查看 A→B”。前序A状态 {}→x=1；后序B继承x=1，期望不存在/实际1，失败；“查看独跑B”显示空状态下通过。
5. 将共享运行顺序改为 B A。旧结果清空，再分析，共享失败0/2；矩阵A→B仍失败，因为每格独立运行，不跟随选定顺序更改定义。
6. 导出完整JSON/Markdown。更换详情不会减少导出的矩阵格或独跑基线。

### 失败后cleanup

点击“载入失败后清理示例”：A为 `set x 1 / assertEqual x 2 / delete x`，B查缺失。分析后A失败，但第3步delete仍执行，A最终{}，B通过。查看A→B可同时看前序失败和后序通过，不会因为A失败就把x留在状态里。

### 自身bug、掩盖与覆盖来源

“载入独跑失败示例”中B执行 `assertEqual x 2`，B独跑失败，共享得到1也失败。结果显示独跑已有失败及读取差异，不计新增失败测试。把B期望改成1，共享会通过但独跑仍失败，显示失败被掩盖，不能当成修复证明。

“载入来源覆盖示例”：A写x=1、C写x=2、B查缺失，顺序A C B。最早失败读取2，首次来源A#1、最近C#1。把C改为 `delete x / set x 2`，首次来源变成C#2。

可以“增加测试”至6行，新增ID与顺序会自动追加，默认新增 `assertMissing x`；删除测试自动从顺序移除该ID。手动改ID须同步修改顺序。全部6行默认顺序分析有30有向格，5个读取测试共享失败，独跑均通过。

## 5. 产出

界面包含全部独跑基线、共享顺序逐测试结果、n(n−1)有向运行矩阵、初始/最终状态、每操作前后状态与实际diff、断言期望/实际/独跑对照、读取差异及首次/最近修改来源、最早差异新失败。

JSON为 `{feature,schemaVersion,modelVersion,exportedAt,draft,result}`，result含解析程序、isolated/shared/pairs、最终状态、统计及来源口径；有向对同时保留source和target完整执行，清理不会被隐藏。没有有效分析时可导出草稿，此时result=null，不附旧矩阵。首版无导入、真实测试框架运行、源码扫描或真实进程隔离。
