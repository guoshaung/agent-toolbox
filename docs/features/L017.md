# L017 HTTP 缓存决策台

## 1. 功能内容

在“学习 → 计算机原理交互实验”中，从一条已经存在、可存储的本地GET缓存开始，逐步判断新鲜度、是否需要请求、ETag条件验证，以及304/200后实际使用的body和缓存元数据。输入包括当前时间、已计算的缓存年龄、模拟响应耗时、本地/服务端Cache-Control、ETag和body；用户可真实编辑全部字段。

提供新鲜、304、200、no-cache、弱ETag五个示例。决策链可上一步/下一步、直接选择，展示每步前后缓存、模拟请求头和响应；完整JSON/Markdown副本导出。完全本地，无AI、登录、网络或新增运行时依赖，没有真实HTTP请求。

## 2. 为什么需要

知道缓存头的名字，并不等于知道下一次访问会直接复用、条件请求还是重新取内容。常见误解包括把no-cache当禁止存储、把304当带新body的响应、把ETag比较当永远强比较，以及把年龄正好等于max-age仍当新鲜。本功能让规则、请求链和前后body同时可见，使这些区别能用确定输入复核。

新增能力是已有缓存的可编辑本地决策模型，区别于请求代码样例、AI解释、抓包或实际访问站点；它不验证服务器实现的HTTP符合性。

## 3. 实现方式、官方依据与范围

`model.mjs`解析有限响应指令/ETag，计算一个GET访问的3或5步决策，返回独立的前后快照。`index.js`使用现有`h`建立输入、步骤按钮、请求/响应展示、缓存body文本及全程比较。每轮重新从输入草稿计算，历史选择只查看，不回滚或更新输入；用户内容不通过HTML插入，不执行脚本。

相关协议事实核对官方来源：

- [RFC 9111 §4.2](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2)的新鲜度比较是新鲜期严格大于当前年龄，因此age==max-age不能直接当新鲜；[§5.2.2.4](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.4)的无参数响应no-cache要求复用前成功验证，不是删除已存储响应。
- [RFC 9110 §8.8.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.3)定义强/弱ETag；[§13.1.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2)的If-None-Match采用弱比较，GET标签匹配可返回304。比较opaque内容，不因W/标记而不同，但内容大小写仍敏感。
- [RFC 9110 §15.4.5](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.4.5)规定304无内容；[RFC 9111 §4.3.3–4.3.4](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.3.3)说明验证后复用或更新缓存。本模型假定已知唯一表示，弱匹配即304并直接更新该条元数据；未实现完整候选表示/强验证器识别和筛选算法，不能当一般缓存符合性实现。

模型的确定规则：

- 固定GET `/lesson`、私有本地已有一条缓存，表示可存储；没有URL输入或真实连接、首次缓存缺失、共享缓存/多个表示/Vary或其它请求方法。
- Cache-Control只接受`max-age=非负整数`、无参数`no-cache`及两者组合，指令名称不分大小写。max-age最多604800秒，原输入最多128字符；允许赋值旁空格、数字前导零，规范化显示；拒绝重复指令、空字段、引号参数、带字段名no-cache、no-store和其他未支持指令。没有no-store行为，不会把它误当no-cache执行。
- 用户提供的age是已经计算好的年龄，范围0～1000000秒；now为抽象当前秒0～1000000000，且now≥age；响应耗时0～60秒，now+耗时不能超过1000000000。初始上次存储/验证参考时间简化为now−age。不读取Date/Age、不实现HTTP完整年龄公式或启发式新鲜度。
- max-age存在且age严格小于它时年龄新鲜；没有max-age时本模型不猜测新鲜期。只有新鲜且无no-cache才直接复用，0请求；此时不检查服务端版本，也不改变缓存年龄或上次参考时间。max-age=0即使age0也需要验证。
- no-cache允许保留body，但每次访问都须先验证；即使年龄新鲜、验证后age0，下一次访问仍须验证（前提是服务端更新后的策略仍含no-cache）。本模型没有不可用源站或允许服务过期副本的路径。
- ETag为空白表示无验证器；`""`是有效的空opaque标签。只支持单个双引号包围的ASCII可见字符，内容最多64字符（不含双引号和空白），外层字段最多70字符；可带大小写敏感的大写`W/`。背斜杠作为字面字符，不支持引号转义；不支持obs-text、多标签列表或`*`。
- 有本地ETag则构造GET `If-None-Match: 原标签`；弱比较只比较引号内opaque字符。相同标签返回模拟304，无响应body；W/强弱混合也匹配。不匹配、服务端没有ETag、或本地无验证器均返回200；本地无标签时不构造If-None-Match，也不改用Last-Modified。
- 服务端始终成功返回200/304，版本以用户ETag为准，不从body生成hash或验证强标签与body的一致性。服务端body只用于200；304保留原缓存body，即使输入的服务端body字段不同，也不会借304取新内容。
- 200替换body及ETag；服务端无ETag则清除旧标签。304保留body，更新当前已知单条缓存的服务端Cache-Control/ETag。两个响应都把验证时间设为now+耗时，简化age为0：假定响应在该时刻生成且初始Age=0，不等于真实Date/Age计算。响应到达而尚未应用元数据的中间步骤显示旧age+耗时。
- 原/服务端body各≤4096 UTF-8字节，允许空body、Unicode和多行文本。传输body字节数304/直接复用为0，200按服务端body的UTF-8字节数；不是包含头部/压缩的真实网络流量。
- 配置只保存`schemaVersion:1`输入草稿，不保存模拟更新后的缓存/决策链。写入前按TextEncoder测完整JSON大小≤64KiB，并校验body容量；恢复校验完整存储对象版本、体积、字段类型和body上限。未完成语法可恢复为草稿，判断时再次校验。超限明确不保存，关闭只能恢复较早草稿，须导出完整JSON保存当前输入。
- 输入修改立即清空旧结果，250ms延迟保存草稿；切走/销毁清除定时器并尝试保存，不留后台模拟。异步保存/导出不更新已销毁界面。DOM替换过滤null及嵌套数组，body文本不会当作HTML执行。
- JSON/Markdown通过主桥接`content`和`copyOnly:true`创建新文件，检查防覆盖能力并拒绝覆盖已有路径；Markdown草稿及body转义HTML和分隔字符。

## 4. 使用步骤与具体复现

打开功能，默认now100、age30、响应耗时2，本地/服务端均`max-age=60`和ETag `"v1"`。点击“判断缓存”：全程结论直接复用本地缓存、请求0次、无响应状态码。查看步骤2显示`30 < 60`为真；缓存body保留，参考时间70、年龄30均不改变。

将“本地缓存年龄秒”改为90，旧结果立即清空，重新判断：请求1次、304、body传输0字节。选择步骤3看`GET /lesson`及`If-None-Match: "v1"`；步骤4服务端弱比较相同，响应时间102、没有body；步骤5保留本地body，缓存age90→0、参考时间10→102，更新服务端响应元数据。点“载入304示例”可以直接重现同一输入。

临界与分支示例：

|输入|预期行为|
|---|---|
|max-age60、age59，无no-cache|直接复用，0请求|
|max-age60、age60，标签相同|不新鲜，条件GET，304|
|max-age0、age0，标签相同|不新鲜，条件GET，304|
|max-age60/no-cache、age10，标签相同|年龄新鲜仍验证，304；缓存保持已存储|
|age90、本地`"v1"`、服务端`"v2"`|200，新body和ETag覆盖旧内容|
|age90、本地`W/"v1"`、服务端`"v1"`|GET弱比较匹配，教学304路径|
|age90、本地无ETag|普通GET，没有If-None-Match，200|

点击“载入200示例”再判断，服务端ETag `"v2"`、body为“版本2：更新后的课程内容”，最后缓存和最终使用body都变成版本2；步骤5显示替换关系。点击“载入no-cache示例”再判断，age10虽然新鲜仍发条件请求，成功后缓存已存储且继续含no-cache。点击“载入弱ETag示例”可编辑本地/服务端W/标记核对弱比较，opaque大小写变化如`"V1"`则不匹配。

自定义时编辑两个Cache-Control、两侧ETag/body及三项时间，修改后重新判断。no-store、标签无双引号或越界时间都会明确报错，没有旧报告残留。所有body只显示文本。导出时选择不存在的新文件名，取消保留当前输入和结果；导出未判断草稿时明确没有有效决策。

## 5. 产出

界面产出新鲜/验证/200替换结论、请求次数、模拟响应状态、body传输字节数、3或5步完整决策链、每步缓存前后状态及请求/响应头。最终前后表比较Cache-Control、ETag、年龄、验证参考时间与body来源；正文为可读文本。

JSON包含feature、schemaVersion、modelVersion、导出时间、全部原始输入、规范化指令/ETag、freshness判定、初始缓存、各步独立前后快照、最终缓存/request/response/body、状态及传输字节数。Markdown包含完整输入和body、摘要、初始/最终缓存、每步理由与快照、RFC来源及范围。报告不导入，也不自动把最终缓存回写输入或全局配置；恢复输入草稿后重新判断。
