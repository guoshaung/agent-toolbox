# L040 预注册偏离对账

## 1. 功能内容与需要解决的问题

工具按样本`sample`、指标`metrics`、排除`exclusions`、分析`analysis`四类记录项目，每项有人工ID和完整描述。左侧/上方的计划、实际编辑草稿与下方只读历史分开。初始计划冻结后无法在界面中编辑、删除或重写，后续计划修订和实际记录均只能追加完整版本，每次保留原时间、原hash、原项目和完整人工理由。

研究分析改动后，只看当前文稿难区分原计划、后加指标、改写口径或删除项目。本功能按类别和ID对账，把“未变/改写/新增/删除”显示为`unchanged/modified/added/removed`；可以切换基准计划，核对当时实际记录或当前尚未登记草稿，而不把当前值回填覆盖原计划。

这是本机教学档案，不等于OSF等外部预注册，不证明计划是在分析前产生，也不证明作者、时间或内容真实。无登录、网络、AI、文献核查或可信外部时间服务。初始示例文字明确为人工练习，使用时须替换为自己的记录，不应将示例当真实研究证据。

## 2. 实现方式与精确口径

`model.mjs`保存schemaVersion=1的完整输入档案：两个编辑草稿、两类理由、人工时序声明、实际草稿所选基准计划、全部冻结/实际版本。每个历史版本包含追加序号、`plan/actual`种类、本机ISO UTC时间、时源`local-device-clock`、人工时序声明、原理由、基准计划序号、前版hash、完整四类快照及自身hash。计划修订继承上一冻结计划；实际记录可选择任一此前已冻结计划，不只能参考最新版。实际版本也不可覆盖，能保留多轮分析对账。

对账键是**类别+大小写敏感ID**。同一类别的ID相同且描述字符串严格相同为unchanged；ID相同、描述任意字符不同为modified（空白改动也计）；只在实际/新修订中存在为added，只在基准计划中存在为removed。更换ID为removed+added，不猜测两项语义相同，也不推断改动是否合理。四类之间相同ID独立匹配，不互相吞并。对账保留两端完整描述，空字符串不用于假装已删除；删除靠移除该ID。

hash采用WebCrypto `crypto.subtle.digest('SHA-256', ...)`，[W3C Web Cryptography API](https://www.w3.org/TR/webcrypto/)为API依据。被hash的内容为该版本除hash外的全部字段：对象键递归按JS字符串排序、数组保持顺序，canonical JSON转UTF-8；前版hash也在新版本内容中。初始前hash为null。恢复时先严格schema、引用和容量验证，再顺序重算每个hash，整份一致才开放编辑器。快照在模型内深冻结；UI只读表不含input/textarea。导出数据仍可人工改写并重算整链，**没有私钥签名、防恶意篡改或身份验证**，不能把hash一致当真实性证明。

本机`new Date().toISOString()`产生冻结/登记时间；不是外部见证时间。时间线按追加序号展示，不按可变时钟重排。比前一记录时间早显示“时钟回拨/早于前记录”，相同毫秒显示保留序号，两者都不拒绝、不改写原时间。分析前/后/未知是用户对真实分析时序的声明，工具不持有真实分析时点，不能由本机早晚自动断言事前或事后。

## 3. 使用步骤、保存与生命周期

1. 打开L040，编辑四类计划草稿的ID/描述和计划理由；填写本次记录相对分析的人工声明。不需要的类别可无项目，但初始冻结至少需一项。
2. 点击“冻结初始计划”。下方出现版本1，只读展示完整快照、人工理由、本机时间、hash。上方计划编辑器仍是独立草稿，之后修改不会改写版本1。
3. 在实际草稿添加或改写项目，选择实际草稿的基准计划版本。实时对账标记“未登记草稿”，没有自动生成历史。填写实际理由，点击“登记实际记录”，追加不可覆盖的实际版本。
4. 修改计划草稿或“复制选定冻结计划到修订草稿”，填写修订理由，点击“追加冻结计划修订”。旧版本保留，新计划引用前一计划并进入时间线；实际记录可以继续按旧版对账。成功追加会清空该类**下次**理由草稿，已经冻结的原理由保持完整，促使下次重新填写。
5. 从“查看历史版本”选择只读快照和该版本当时的对账；从“实际草稿对账计划版本”改变当前实际草稿基准，两种选择用途不同，不改变历史版本引用。
6. 查看完整JSON/Markdown预览，再导出新副本。完整档案/所有版本均在报告中，不只导出选中版本；当前草稿不完整时对账错误单独标记，不将它写成合法结果。没有有效冻结时报告明确尚未冻结，不伪称预注册完成。

边界：冻结/实际合计≤20版本，每类每份快照/草稿≤40项；ID字母起始、1–40位ASCII字母/数字/下划线/连字符，同类冻结ID唯一；描述非空且≤300 Unicode码点；人工理由每新增版本必须非空且≤600码点。草稿允许暂留未填行或重复ID以便编辑，冻结/登记和实时对账时拒绝这些不完整输入。非法类型、额外schema字段、孤立代理码和非法控制字符均拒绝，普通换行可留在描述/理由中，所有用户文字经文本节点/Markdown编码输出。

整个草稿+**全部历史**按TextEncoder测JSON UTF-8字节，≤64KiB。新增版本导致超限会整份拒绝，原冻结快照/时间/hash一个不丢；21版本、41项也不截断。没有自动删旧、清空历史或覆盖旧版本功能。可以缩短尚未冻结的草稿并导出全部档案；已经冻结的描述不能用改短来腾容量。导出同时保留草稿，若草稿自身超过字段或总容量则不能假称已保存/完整导出，须缩短未冻结输入或自行复制保留。

本机配置`features.L040.state`存完整输入/历史，**不回填派生report、timeline或对账行**。恢复重算全部hash链；版本/容量/hash失败时整份拒绝显示编辑器，不自动将示例写入覆盖坏档案。需要先人工备份检查原配置；没有绕过校验的自动重置按钮。

保存通道按实际共享config对象维护：至多一个进行中的写入和一个最新待写快照，待写输入合并，顺序await写入，防止旧写入最后覆盖新值。同一通道快速重新打开时承接最新待写输入；新面板获得owner后，旧面板销毁不再追加旧写入。队列完成后重新打开读取当前配置并重验链，不借旧缓存跳过检查。没有跨进程锁或跨应用存储仲裁。

编辑、切走或销毁使未完成冻结/登记票据失效，不提交过时快照。切走/销毁排队保存当前合法档案；已发出的写入无法取消，会串行完成，但销毁后不回写DOM。异步保存失败明确未确认保存，不保证关闭能恢复最新输入；待写草稿还在队列时不将它称为已落盘。恢复hash运算和导出回调也检查生命周期，销毁清空DOM，无定时器、网络或后台轮询。

## 4. 产出与可复现具体时间线

JSON包含原始archive和根据该archive复算的report。report有当前草稿对账或明确错误，以及**全部版本**按追加序号的时间线、完整hash和理由、每次修订/实际相对其基准计划的对账。Markdown保留相同完整内容，用户HTML字符作编码，代码围栏长度避开原文本反引号。两者须基础层防覆盖能力为true，以`copyOnly:true`独占创建新文件，仅响应`ok===true`才称成功；取消或拒覆盖不丢历史。报告展示选中版本不会导致导出删减其他版本。

### accuracy→F1验收例

默认计划metrics仅`accuracy`，描述“使用准确率作为主要指标（人工练习）”。填写理由后冻结为版本1，得到本机`t1`和`h1`。实际草稿保持accuracy，再添加`F1`、描述“宏F1指标（人工实际记录）”，填写实际理由并登记版本2：accuracy为unchanged，F1精确added；counts为`{unchanged:1,modified:0,added:1,removed:0}`。版本1仍只有accuracy，`t1`和`h1`不变；版本2引用计划1，前hash为h1。

将实际accuracy描述改为“更改accuracy计算口径（人工声明）”，填写新理由后登记版本3：modified=1、added=1。然后删除实际accuracy，只保留F1，填写理由后登记版本4：removed=1（accuracy）、added=1（F1），未变和改写均0。此前版本2/3的实际描述和原理由仍完整保留，不会被第四轮覆盖。

计划修订草稿加入F1，人工声明分析后，填写“分析后声明新增F1到修订计划；未覆盖初始计划”，追加计划版本5。它基于计划1，保留全部1–4记录。当前实际对计划5的F1可为unchanged，对计划1仍是added；选择版本1只读视图仍能见原accuracy和原t1/h1。这并不证明第5版实际分析后或第1版分析前，只记录声明和本机时间。

### 时钟及容量例

模型测试输入本机时间`2026-10-03T00:00:00.000Z`冻结计划，再于00:00:10登记实际，随后00:00:05追加实际：序号1/2/3保持，第三条明确earlier/回拨；另一条同00:00:05显示equal，原记录不重排。真实UI没有手填过去时间入口；隔离验证通过替换fixture Date模拟回拨，不能把该fixture时间当真实本机事件证明。

已有5版本后，将**尚未冻结**计划metrics填为40项，每项描述300个“汉”，完整当前档案仍≤64KiB，但再追加一份同样快照会超64KiB：追加拒绝，仍5版本，原t1/h1不动。当前40项草稿和全部5版本仍可完整导出，无M40丢失；超过字段限制到301码点则整份草稿保存拒绝，旧已保存档案保留。达到20版本后第21次拒绝，不删最早记录。

## 6. 限制与解释边界

所有项、理由、分析时序声明均是人工记录，不自动判断改动科学合理、排除是否选择性、指标是否适当或研究是否存在偏差。对账是ID和字符串变化，不是科研诚信判断、因果证明或论文审计认证。相同内容也可以在现实中有不同实施，未变状态不能证明真正遵循计划。

哈希重算检测未配套更新hash的意外修改，拥有档案的人可改记录并重算整链；本机时间可调整，文件可替换。记录没有外部服务器见证、不可撤销发布、身份签名或第三方注册证明。它不等于OSF预注册，不能用“已冻结”字样宣称已获得可信事前注册。需要外部预注册者须另用相应服务，本功能不代办或核验。

只支持固定四类有限项目，不读取真实分析日志、版本仓库、实验数据或注册平台；没有任意代码执行、自动统计分析、附件上传或人工时间编辑。总历史64KiB/20版本是明确练习边界，不能靠删除旧冻结内容无声扩容。导出完整包含全部人工描述、理由和历史，保存位置由用户选择。
