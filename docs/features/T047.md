# T047 字幕排版与烧录

## 1. 功能内容

T047 在工具工作台提供完整本地字幕烧录流程：选择本次 MP4 和 UTF-8 SRT/简单 VTT，选择固定可信字体、像素字号、四边安全边距及上/中/下位置，计算全部字幕的换行和位置，生成代表性长句的真实 FFmpeg 样帧。每张样帧加载成功、尺寸吻合并经用户明确核对后，才允许生成烧录副本。成片附带同一请求时刻的真实提取样帧和完整来源/布局报告。原视频和原字幕始终只读。

界面显示全部字幕原文、整数毫秒区间、每行实际文本、宽度预算、垂直位置和完整计划。代表句取换行最多者优先，再按原文码点数和原顺序选择，最多三条；所有条目均参与最终烧录。样帧显示请求时刻、实际源 PTS 和偏差，蓝色叠框仅表示安全区，不烧录到产物。成片可以主动播放/定位，默认不自动播放。

固定 Noto Sans CJK SC Regular 支持本功能有限中文/Latin 纯文本范围，不允许用户上传任意字体、自由滤镜命令或 ASS 样式程序。SRT/简单 VTT 的文本如 `{\pos(1,1)}`、`%{metadata:filename}` 和 `<b>literal</b>` 会逐字画在帧中，不解释位置、表达式或标签。原文件不改，新增换行只存在于烧录排版和报告。

## 2. 为什么需要

平台不支持外挂字幕时，字幕必须成为视频像素的一部分。仅检查文本行长无法证明实际字体渲染后没有裁切；T047 先用所选字号和同一固定过滤图生成真实长句样帧，让用户在烧录前核对，再提取成片相同时间的画面比较。明确人工确认保留了质量审核边界，不将字符计数或预算包装为自动质量认证。

T046 校验字幕时间轴并导出文本，T041 做片段编辑，T043 抽取视频样帧；T047 的新增能力是按固定字体排版与真正把字幕编码到视频。此功能的解析、可信主进程路线和字体均为独立文件，运行没有对其它 feature 的路径依赖，也没有修改共享桥、CSP、package 或锁文件。

## 3. 实现方式、依赖与范围

外部依赖为用户明确选择并信任的 **FFmpeg/FFprobe 6.x Windows 安装**。界面预览默认目录 `C:\ruanjian\ffmpeg\bin`，也可选择自己的普通本地 bin 目录；存在 `ffmpeg.exe`/`ffprobe.exe` 才给出查询计划，点击确认才运行四次固定只读查询：两次版本、编码器、过滤器。需要 libx264/png/aac 和 drawtext。当前真实验收使用 `6.1-full_build-www.gyan.dev`。安装来源可从 [FFmpeg 官方下载页](https://ffmpeg.org/download.html) 查找 Windows 构建或 [官方 n6.1 源码](https://github.com/FFmpeg/FFmpeg/tree/n6.1)；本功能没有安装/升级引擎，也不保证任意新主版本兼容。不从 PATH 猜程序，不下载或执行任意用户命令；所选本地程序的可信性由用户决定，不声称官方签名验证。

字幕使用自有有限解析器：SRT 唯一正整数编号、HH:MM:SS,mmm；简单 VTT 仅标准头 `WEBVTT` 加空行、可选唯一 ID、HH:MM:SS.mmm 或 MM:SS.mmm。LF/CRLF 和 UTF-8 BOM 支持，保留原字幕字节副本；正文不解释样式。拒绝 NOTE/STYLE/REGION、VTT 行位置设置、内嵌时间戳、重复编号、无效时间和其它高级语法。原序时间必须不重叠，每条至少100ms，均在视频内；越界或无法排版时整份拒绝，不截断或自动移走字幕。

字号16–64px、边距16–96px；固定字体的逐码点 advance 按 unitsPerEm 缩放并向上取整，安全宽度再内缩8px。优先已有换行和空格边界，长词/无空格文本可按码点拆行；换行段拼接保留原文字符和空格。每行独立生成固定名称的 UTF-8 文本文件，行步长 `ceil(fontSize×1.5)+8`，最多四行，高度超过安全区拒绝。字体缺字、组合附加符、控制/双向格式字符或未实现塑形的书写系统拒绝，不偷偷换字体。字形预算不是可见性证明，实际代表样帧须人工核对。

渲染依据 [FFmpeg drawtext 官方文档](https://ffmpeg.org/ffmpeg-filters.html#drawtext)：固定 `fontfile=font.otf`、`textfile=cue-NNN-line-NN.txt`、`expansion=none`、`text_shaping=0`、白字黑色2px边；水平按 `text_w` 居中，垂直值来自有界布局。过滤字符串不插入用户正文、路径或命令；每条启用条件为 `start≤t<end`。样帧从源或成片顺序解码，`select` 选请求之后首帧，`showinfo` 的整数 PTS 与 time_base 独立计算实际时刻；若已经落在该字幕外，拒绝样帧，不假称请求时刻精确存在。

每个子进程 `shell:false`、隐藏窗口、精简环境，协议只允许 file；MP4 普通文件/路径逐级检查，ISO-BMFF dref 必须自包含，拒绝外部轨道引用、UNC/符号链接/目录跳转。允许单 H264 yuv420p 视频、零或一个 AAC 单/双声道8–48kHz音轨，拒绝章节、附图、非零起始时间、旋转/其它 side data、HDR及非1:1像素宽高。范围：视频64MiB、60秒、偶数160×120至1280×720、平均帧率0–60；字幕32KiB、最多24条、每条300 Unicode码点/4行。输出 H264 30fps、CRF20、1.5Mbps上限，音轨若有则重编码 AAC96kbps/48kHz；有损重编码不能保证像素或声音完全等同源。成片尺寸/音轨/帧率/时长及完整大小核验，时长允许100ms编码量化差，达到20MiB上限拒绝。每张 PNG 最多1MiB，CRC/结构/尺寸/实际时间均核验。进程输出131072字节限、最多4个并发；查询/探测5秒、每张样帧15秒、烧录60秒；超时或取消先杀子进程，观察 close 后再释放槽位和自己的临时字体、文本、PNG/MP4。

私有资源为固定 [Noto CJK 提交523d033…](https://github.com/notofonts/noto-cjk/tree/523d033d6cb47f4a80c58a35753646f5c3608a78)的 `NotoSansCJKsc-Regular.otf`，16,437,364字节，SHA-256 `2c76254f6fc379fddfce0a7e84fb5385bb135d3e399294f6eeb6680d0365b74b`，原 SIL OFL1.1 LICENSE 保留；@pdf-lib/fontkit **1.1.1** 的成熟 UMD bundle仅用于字形测量，固定 npm URL/SHA-512 integrity、原package/README和MIT声明均保留。上游 npm 包未附LICENSE，私有 `fontkit-LICENSE.txt` 是依据其声明添加的标准MIT文本和来源说明，不冒称原npm文件。七项资源大小/SHA及来源在 `vendor/manifest.json`，`.gitattributes` 禁止换行改变原字节，第一次使用核验全部资源；复制 OTF 时再次核对固定 SHA。外部 FFmpeg 读取主进程写入自身真实临时目录的字体，永远不接收 ASAR 虚拟字体路径。

## 4. 使用步骤与具体例子

1. 打开 T047，预览默认目录或选择可信 FFmpeg6.x 安装目录，核对程序路径后确认四次固定查询。
2. 选择自己的支持范围内 MP4 和 UTF-8 SRT/简单 VTT。只读检查后界面展示视频参数、大小/SHA与完整字幕原文。
3. 选择固定字体，填字号32、安全边距32、底部位置，计算全字幕排版。确认没有超行/越界或重叠提示。
4. 生成真实长句样帧，逐张检查原文末尾和所有行、是否完整在蓝框内；加载失败不能确认。勾选“我已逐张核对”，记录人工确认，再点击烧录。
5. 查看实际副本回放及对应时刻样帧，展开完整报告；选择不存在的新目录，先核对路径与所有文件列表，再点击确认创建。

随附 `fixtures/long-lines.srt` 是314字节、SHA `92e169c7a84cd698fdecc67bb1732ac4fe97d1cf5f5554b5d38466f93a14aed7` 的确定长句例：中文在500–2500ms，英文在3000–5000ms，视频需至少5秒。本机可用可信引擎创建受控6秒640×360/30fps黑底、440Hz音轨夹具：

```text
ffmpeg -v error -nostdin -n -f lavfi -i color=c=black:s=640x360:r=30:d=6 -f lavfi -i sine=frequency=440:sample_rate=48000:duration=6 -c:v libx264 -pix_fmt yuv420p -c:a aac -shortest black-6.mp4
```

这是维护者复现命令，不是应用允许用户提交的命令接口。字号32/边距32下安全区为 `(32,32)–(608,328)`，中文实际三行：

```text
这是用于字幕安全区验收的中文长句，
换行之后每一个文字都应清楚可见，不
能被画面边缘裁掉。
```

英文实际四行（前三行结尾空格仍在排版报告，画面不可见空白不算丢字）：

```text
This long English sentence must
wrap within the safe rectangle and
every word must remain visible in
the burned video.
```

实际样帧请求1500ms/4000ms，固定30fps夹具的实际PTS正好相等。烧录后两张对应帧完整可见；实际MP4容器时长6016ms，比源6000ms多16ms（AAC编码量化），不会虚称每种媒体精确6000ms。改成顶部位置会立即废弃旧样帧/人工确认/成片和目标，必须重新生成与核对。

## 5. 产出、保存与生命周期

新目录包含 `burned.mp4`、原字幕完整字节副本 `original-subtitles.srt/vtt`、1–3张烧录前 `sample-NN.png`、对应的 `after-NN.png`、`burn-report.json` 和 `.md`。两条示例共八文件。JSON 保存视频/字幕/字体 SHA、原字幕全文、所有原区间/原文/换行、每行位置和宽度、安全区、真实样帧PTS/大小/SHA、编码规则及输出核验；导出的样帧记录只引用完整相对文件名，不保留会失效的临时URL。Markdown 保留全部字幕和排版，HTML符号转义。PNG为完整原尺寸画面，蓝色安全框只在界面 SVG 叠层，不写入图像。

先预览完整来源/排版/真实样帧/报告，再选择目标并显示绝对目录与全文件列表；此时尚未写入。主进程独占创建新目录，媒体/样帧用 `COPYFILE_EXCL`、原字幕和报告用 `wx`，所有媒体复制回读 SHA，原视频/字幕前后也重新核验。已有目录、源文件路径或更改的来源拒绝，不能覆盖。只有严格成功、`copyOnly:true`、相同目录和完整唯一文件回执才显示完成。报告最多1MiB，超限整份失败；普通中途失败只清理本次创建、身份仍吻合且只有预期文件的新目录，否则返回需要人工复核的 partialPath。跨多文件导出不是断电原子事务。

草稿只存 `schemaVersion:1` 的字体/字号/边距/位置，UTF-8 JSON≤64KiB，保存队列保序。没有视频路径、字幕内容、派生结果或人工已观看状态；不可读版本不自动覆盖。编辑参数或切换来源立即清旧确认/结果/目标；取消及切走停止媒体、发固定后端取消，序列化 Host 清理等待正在运行调用结束，票据隔离迟到结果；恢复页面不自动播放或重新启动程序。临时产物常规15分钟清理，切走/窗口销毁正常释放；进程崩溃或系统断电可能留下临时文件，不声称崩溃清理保证。
