# L035 研究设计混杂检查

## 1. 功能内容

本地填写一个研究的暴露、结局、候选混杂、选择机制四项要素。每项都有描述、记录性质、对应作者证据位置、作者原句和用户待核问题；另有研究名称、设计描述与整体待核疑问。生成填写/证据缺口表和完整 JSON、Markdown 预览，支持安全新副本导出。

描述为空或只有空白时显示“未知”。作者证据位置与原句任一缺失，独立显示“证据待补”，不会自动生成引文。描述与证据的状态分别判断：有引用却没有描述仍未知，有描述却没有引文仍待补。候选混杂由用户记录，不自动确定真实因果角色，四项填满也不自动标为无偏差。

## 2. 为什么需要

阅读相关性研究时，可以先列出变量角色、样本如何进入研究，以及作者在哪里交代这些信息。没有找到信息与已经证明不存在问题是两件不同的事。本功能让这些缺口显式留下，便于返回材料核查，也避免把用户猜测或作者声称当作已核实事实。

三种记录性质是“用户记录（未验证）”“作者声称（待核）”“待核假设/疑问”，由用户选择，不通过关键词推断。即使输入“没有混杂”，也只显示文本已填写，不能据此宣布真实没有混杂。填完表只完成记录，不代表证据充分、排除选择偏差或证明因果效应。

## 3. 实现方式与保存范围

`model.mjs` 校验有界输入并生成四行派生表；`index.js` 提供实际表单、记录性质选择、示例/空白、结果与导出事件；`meta.json` 供生产功能工作台发现。每项的 unknown 只由 `description.trim()` 是否为空计算；unknownCount 为四个布尔值之和。证据缺失列表分别检查 location 和 quote，evidencePendingCount 是证据待补的行数，不是缺失字段总数。证据文本存在只显示“已填写（未核真）”，不验证真实性。

界面按字段编辑，不需要大 JSON 输入框；报告全文可预览。用户内容通过 h 文本节点/textContent 渲染，不执行 HTML、JS 或外部请求。Markdown 为动态文本设置足够长的代码围栏并转义 HTML；完整 JSON 保留原始文本。

- 单个研究记录，固定四项，没有额外案例、历史或事件列表。研究名称最多160个UTF-16代码单元；设计描述、整体疑问各2000；每项描述/作者原句各2000、证据位置300、待核问题1000。正常换行、回车与 tab 可用；拒绝其他 ASCII 控制符及孤立代理项。UTF-16 长度与 UTF-8 字节容量是独立限制，例如一个 emoji 通常占两个UTF-16代码单元。
- 整个输入对象先用 TextEncoder 测 JSON 的 UTF-8 体积，最多64KiB；版本化对象也再校验64KiB。超限或字段类型/容量不符时整份生成、配置写入及导出拒绝，不截断文本，不生成部分表，不沿用旧结论。界面显示错误且保留当前输入供缩短或自行复制保存；不会宣称关闭后能恢复超限输入。
- 配置键 `features.L035.state`，`schemaVersion:1`，仅保存研究信息与四项原始输入。恢复校验版本、原始对象体积与字段类型，忽略合规体积内的派生属性，派生核对表不回填配置。恢复后重新生成报告；所有编辑清空旧报告及预览。
- 输入改变立即尝试保存，切走再次保存；配置失败有提示。销毁清空结果/DOM，异步导出完成后不会重新填充已经销毁的界面。没有AI依赖、网络、计时器、源文档扫描或自动证据检索。

## 4. 使用步骤与具体例子

1. 在功能工作台打开“研究设计混杂检查”，点击“生成待核表”。默认是**虚构教学案例**：暴露为每周运动次数，结局为睡眠质量自评分，候选混杂与选择机制留空。示例两条原句均明确标“教学自造句”，设计说明也声明并非真实论文或已核对引文。
2. 预期“未知2/4 · 作者证据待补2/4”，未知项恰为候选混杂与选择机制；暴露/结局已有位置和原句，显示已填写、未验证。结论明确不判定无偏差、因果效应或可信程度。
3. 在“候选混杂描述”填“年龄（用户候选，未核）”，记录性质选“待核假设/疑问”。旧报告清空；重新生成后未知1/4，证据待补仍2/4。新增描述没有自动制造证据或确定真实混杂。
4. 只填写“候选混杂作者证据位置”如“第4页表2”，重新生成仍证据待补2/4，并明确该行缺作者原句。再填写实际查到的原句后，证据待补降为1/4，但证据仍未自动核真。默认教学材料不是实证依据，应自行替换为真实材料。
5. 点“新建空白记录”，仅给暴露填位置与原句，不填描述，生成应为未知4/4、证据待补3/4；这说明引文存在不替代要素描述。也可在所有描述填文本验证未知0/4，报告仍不会宣布无偏差。
6. 展开完整 Markdown/JSON 预览，导出副本；修改任一输入后旧报告失效。切走、返回或重载后恢复的是输入，需重新生成。打开空白记录或载入示例会替换当前草稿，不保存额外历史，需要留存旧案例时先导出。

## 5. 产出与导出

JSON 包含 feature、schemaVersion、modelVersion、导出时间、完整 draft 和 result；结果有四行完整描述、原句、位置、记录性质、待核疑问、未知状态、证据缺失列表及统计、设计说明和解释边界。Markdown 按四项展开全文，再附完整记录，包括空缺和作者证据位置；不会根据预览或页面滚动位置省略内容。合法输入未生成报告时也可导出草稿，result 为 null。

导出检查生产能力 `saveTextSupportsCopyOnly===true`，调用 `files.saveText` 时 `copyOnly:true`，仅 `ok===true` 认定成功，取消及写入失败分别提示。生产写入器使用 `wx`，已存在目标拒绝覆盖原文件。超出记录容量的内容整体拒绝导出，不生成截断报告；请缩短后重试或自行复制文本保留。自动配置不保存派生报告，文件是完整独立新副本。
