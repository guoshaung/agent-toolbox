# T003 两份数据集对账

## 1. 功能与交付范围

将两次导出的JSON对象数组、CSV或TSV按业务主键对账，分别报告新增、移除、修改、未变及主键冲突。输入可以粘贴或从本地UTF-8文件读取，两侧可使用不同格式。解析完成后提供来源与字段预览、候选字段选择和手动填写单个顶层主键。

结果提供分页字段差异表、完整前后值详情、单独的主键冲突分页及JSON/CSV副本导出。保留来源名称、记录序号、记录起始物理行、字段路径、前后值和字段存在状态。功能不修改输入文件，不自动解决冲突、不合并记录、不忽略选定列、不提供复合或嵌套主键。

## 2. 必要性及现有能力关系

两次业务导出经常改变记录顺序，纯文本比较会产生大量无关差异；按主键定位同一记录能够直接区分增删和字段修改。遇到重复主键时，随意保留第一条或最后一条会产生不可信的结论，因此需要将该键的两侧全部记录隔离并报告出处。

现有webtools以网页嵌入为主。本功能提供完整离线原生对账闭环。它与T002清洗功能不同：本功能保留原始字段类型及值，不修剪、填补或去重输入。catalog中的待选表格依赖在首版由本功能自带的严格解析器实现，无新增npm依赖。

## 3. 实现方式与数据保护

`meta.json` 提供工作台元数据；`index.js` 使用现有DOM工具实现同步create与activate/deactivate/destroy；`model.mjs` 实现解析、索引、比较、预览行和导出。未改公共registry、main、preload或package文件。

CSV/TSV状态机在本功能内移植并调整自T002 `model.mjs` 的必要纯解析片段（来源提交`ba92a386`），没有运行时import其他功能。保留引用字段内逗号、制表符、换行、双引号转义和物理行；要求首行为非空且唯一的字段名，不自动改名、修剪或猜测错列。

JSON采用有界异步递归解析器，严格验证语法、保留顶层记录起始物理行，并拒绝重复对象属性，避免`JSON.parse`常见的重复属性覆盖结果。不接受非有限数字或超出JavaScript安全整数范围的整数；大业务编号应作为字符串输入。数字按JavaScript有限Number比较（小数为IEEE 754精度，1.0等于1，-0等于0）；不提供任意精度数值对账。

建立两侧类型明确的Map索引。缺失或无效主键逐行形成冲突；任一侧重复的主键，其两侧全部记录形成一个重复键冲突，不参与正常增删改。其余键按匹配记录逐字段比较，对象键集合排序使属性顺序无关，数组按索引比较。字段路径使用JSON Pointer转义：`/`→`~1`，`~`→`~0`，空路径代表整条新增/移除记录或整体类型替换。JSON属性`__proto__`等作为自有数据字段处理，不写原型。

解析、建索引、字段递归和导出定期让出事件循环并检查AbortSignal。取消、切走或销毁中止后续处理，不生成可导出的半成品；输入或主键改变立即清除旧报告。每侧解析必须完成，才可执行对账。文件读取采用可中止的FileReader和fatal UTF-8解码，非法编码不替换当前输入。文件导入的原始换行独立保存，避免textarea显示时的换行规范化改变比较数据；用户编辑后使用文本框返回的值。

JSON/CSV副本调用实际`window.toolbox.files.saveText({content,extension,defaultName,copyOnly:true})`。必须确认`saveTextSupportsCopyOnly===true`，否则禁用导出，不调用可能忽略保护字段的旧接口。基础层以排他写入拒绝覆盖已有目标。用户先核对结果预览，再在原生保存对话框确认新路径/文件名。数据不联网、不上传、不执行用户代码。

## 4. 使用步骤与输入比较规则

1. 载入内置增删改示例，或分别粘贴/导入旧、新数据，核对两侧名称与明确格式。
2. 点击“解析两侧数据”，查看记录数、字段及前3条来源预览。语法错误时按状态消息修正输入。
3. 从候选字段选择主键，也可手动输入字段名；首版支持一个顶层字段，默认id。字段名和字符串值大小写敏感。
4. 点击“按主键对账”，核对新增/移除/修改、字段差异、未变统计以及独立冲突列表。点击完整详情检查未截断的原始值。
5. 核对结果后保存JSON或CSV报告副本。保存对话框打开后通过系统取消按钮关闭；面板取消中止解析、对账和副本生成阶段。

| 输入/比较项 | 首版规则 |
|---|---|
| JSON | 顶层数组，每项为对象记录；允许空数组；属性不重复；不接受注释、尾逗号、undefined、NaN、Infinity或不安全整数 |
| CSV/TSV | 明确逗号/制表符，首行为标题；每格均是字符串；双引号字段内`""`代表一个引号；闭引号后仅分隔符/换行；数据列数必须匹配 |
| 空表行 | 终止换行不生成虚构记录；实际空物理行保留为全空单元格并产生无效主键冲突 |
| 字符串 | 不自动trim、改大小写、解析日期或推断数字；`"01"`、`"1"`、`" 1 "`是不同键 |
| 主键 | 非空字符串、有限安全数字或布尔值；数字1、字符串"1"、布尔true各自不同；缺失、null、空字符串、纯空白、数组或对象为无效键冲突 |
| 混合格式 | CSV的主键"1"与JSON数字1会分别移除/新增；需要一致身份时请将JSON主键明确保存为字符串 |
| 对象/数组 | 对象属性顺序无关，数组顺序和长度均参与比较；对象与数组不同 |
| 缺失/null | `{present:false}`表示字段不存在；`{present:true,value:null}`表示存在且为null；空字符串也单独区分 |

字段名不做隐式转换：CSV标题` id `与`id`不同。JSON/表格开头可含一个UTF-8 BOM，解析时去除格式标记；后续BOM视为普通文本内容或JSON语法错误。记录序号从1开始（CSV不包含标题），物理行从1开始，引用字段内换行会推进物理行。

## 5. 产出与输入输出示例

点击“载入增删改示例”得到旧侧old.json：

```json
[
  {"id":1,"name":"旧记录"},
  {"id":2,"name":"原名称","meta":{"active":true}}
]
```

新侧new.json：

```json
[
  {"id":2,"name":"新名称","meta":{"active":true}},
  {"id":3,"name":"新增记录"}
]
```

主键id，结果为“新增1 · 移除1 · 修改1 · 未变0 · 冲突0组”。移除数字键1；新增数字键3；修改数字键2的`/name`，从`"原名称"`到`"新名称"`。该修改保留旧侧记录2/物理行3和新侧记录1/物理行2。仅重新排列记录或meta对象属性，不会产生修改。

冲突例：旧侧`[{"id":1,"v":"a"},{"id":1,"v":"b"},{}]`，新侧`[{"id":1,"v":"c"}]`。输出0项正常变化、2个冲突组：重复键1的旧2行/新1行，以及旧侧缺失主键1行。没有从重复键中选择任何一条来计算修改。

JSON报告包含`feature=T003`、`version=1`、规则、主键、来源、统计、changes和conflicts。正常变更保留完整两侧记录和字段差异，冲突保留涉及的全部原始记录。未变记录计数但不重复导出。

CSV包含每个字段差异和每条冲突记录；旧、新来源均带记录序号/物理行。字段存在状态为单独的before_present/after_present列。字符串及对象单元格先以JSON字面量编码，再按CSV引号转义，保留null/空字符串/换行和数据类型，并避免字符串被表格软件作为公式解释；读取这些列时先CSV解码，再JSON解码。整个CSV含UTF-8 BOM。结果表每页25个字段差异；冲突每页10组，每侧预览最多20行，完整详情与导出始终保留全部冲突行。

## 6. 验证、限额与集成边界

```powershell
node --test --test-reporter=spec test/feature-T003.test.js
Get-Content src/renderer/features/T003/index.js -Raw -Encoding UTF8 | node --input-type=module --check
node --check src/renderer/features/T003/model.mjs

```

23项定向测试通过（20项独立模型测试、3项DOM契约测试）。覆盖验收增删改及两侧物理行；记录/对象换序；数组次序/长度；字段缺失、null、空字符串和类型；数字/字符串/布尔主键；双侧重复隔离；无效键；每侧统计守恒；严格CSV/TSV引号、BOM、多行、空物理行、表头错误；JSON重复属性、错误语法、不安全整数、物理行、特殊属性名；空数据；字符/字节/行/列/节点/深度/差异限额；解析/对账/导出取消；副本API实际载荷及旧写入接口阻断。

限额：每侧2 MiB、5000条记录；每字符串50000个UTF-16单位；CSV/TSV每行100列、总100000单元格（含标题/空行）；JSON嵌套深度32、节点100000、每对象100属性及顶层字段并集100；整个报告10000个字段差异；导出12 MiB。超过限额整批失败，不自动裁剪记录。JSON小数沿用JavaScript Number精度，超出安全整数的大编号应使用字符串。

本提交没有启动Electron，DOM契约不等于真实客户端操作验证。待集成确认真实文件选择/文本框编辑、长表分页与取消响应、系统保存对话框及已有目标拒绝。Node因现有package未声明renderer `.js` ESM类型产生提示，未修改package消除提示。需要批量更大数据、复合主键、嵌套主键、忽略列或自定义类型转换时，属于后续明确扩展，首版界面不会静默猜测。
