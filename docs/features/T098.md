# T098 版本化备份恢复演练

## 1. 功能内容

读取用户主动选择的本地目录文件，建立带 SHA-256 的基础版本 v1；以后将另一份完整目录状态与最新版本比较，产生新增、替换、删除增量。完整版本链导出为包含二进制 Base64 的 JSON 新副本，可重新导入并逐版本重算文件内容、历史快照、canonical 清单和父链哈希。用户选择任意历史版本，核验整条链后完整预览相对路径、字节数和 SHA-256，再明确创建一个不存在的全新恢复目录。

本功能读取文件内容，不扫描任意系统路径，不改源文件、当前目录或已有目标，不用网络、AI、账号和新增包。它是有限文件集合的迁移演练，不是系统备份服务；只保存相对路径与内容，不保存空目录、ACL/权限、时间戳、符号链接、硬链接关系或运行中应用的一致性快照。

## 2. 为什么需要

复制成功不等于历史版本能恢复。增量可能缺基础，替换指向不存在的文件，删除项失配，包被截断，或两个路径在 Windows 大小写/NFC 规则下实际冲突。仅确认导出文件存在会遗漏这些问题。

将每个历史状态重放并核验，再恢复到新目录，可以检查“新增/替换/删除后应当只剩哪些内容”。预览中的删除是版本重放动作，不是对源目录执行删除。原目录继续使用，新目录只是隔离副本，用户可进一步自行比对。SHA-256 检测完整性，不提供签名、可信来源或密码认证；拥有包的人也能改内容并重算哈希，不能据此证明包来源可信。

## 3. 实现方式

- `meta.json` 沿用“工具 / 隐私与数据迁移”。`index.js` 默认同步 `create(root)` 返回生命周期，真实界面使用公共 `h()`；样式局限 `.feature-t098`。独立 `model.mjs` 不引用其他功能、Node 文件系统或共享业务模块；不修改 main/preload。没有全局配置写入、草稿历史或无限备份记录。
- File API 的 `webkitdirectory` 输入接收一个根目录下 1–100 个文件，剥除选中根名称，只保存剩下相对路径。若不兼容，平级 multiple 输入可选择完整平级文件集合；它不代替递归目录读取。两种模式以最后一次选择为准。每次用户必须选择完整目标集合；没选择的旧路径在增量中将被视为删除。浏览器/Electron 可能不提供隐藏文件或空目录；本工具仅声称捕获实际选中的 File 对象集合。根外文件、混合根和根/平级混用拒绝。
- 限额：每状态 1–100 文件、单文件 ≤2 MiB、总字节 ≤10 MiB；1–10 版本，整个规范 JSON 包 ≤20 MiB UTF-8，包含 Base64、旧版本和清单开销。不是每版本各给 20 MiB；容量耗尽必须另建基础链。输入/生成超限整次失败，不截断、不丢文件。空目录或全删除变成零文件状态不支持，明确拒绝；零字节文件支持。
- File.slice 每 64 KiB 读取并核对实际字节数；二进制不作文本解码，SHA-256 用本地 WebCrypto。Base64 编码每 49152 字节（3 的整数倍）分段，解码每 64 KiB 让出事件循环并检查取消，保证任意二进制及段边界往返。文件内容哈希和清单哈希异步结束后也检查票据。JSON 解析、canonical 序列化、atob/btoa 和单次 WebCrypto digest 的内部步骤不能中途抢占，只能在有界阶段前后取消；大包没有性能承诺，也没有独立 Worker。
- 包格式为 `T098-backup` / `schema:1` / `versions`。基础版本 `kind:base,index:1,parentHash:null`，后续 `kind:delta,index:n,parentHash:<上一版本hash>`。每版包含严格按原字符升序排列的 `changes`、`snapshotHash` 和 `hash`。`add` 含 path/size/sha256/base64；`replace` 再含 previousHash；`delete` 只含 path/previousHash。完整相同状态产生合法空增量，不重复装入内容。
- 文件 SHA-256 覆盖实际解码字节。快照哈希覆盖 canonical `{format:'T098-snapshot',schema:1,files:[{path,size,sha256}]}`；文件按原路径字符升序排序。版本哈希覆盖 canonical `{format:'T098-version',schema:1,...版本全部字段但不含hash}`，包含完整变更内容、父哈希及快照哈希。canonical 对象键按原字符升序、数组顺序保持、无空白、字符串按 JSON 转义、安全整数按 JSON 规范化。基础和增量是同一个导出包内的连续链，不支持分别导入任意独立增量。
- 解析器最多 20 MiB、12 层、10000 个值，严格 JSON 语法、Unicode、安全整数，拒绝重复键（包括 Unicode 转义后的同名键）、未知或缺失 schema 字段和不支持版本。仅 UTF-8 JSON；版本包不是 CSV、文本备份、压缩或加密格式。路径最多 500 字符、每段 120 字符；禁止绝对路径、遍历、反斜杠、Windows 设备名、非法字符、尾点/空格、大小写/NFC 同名和文件/目录前缀冲突。原路径本身不自动归一化或改名；Windows 非 NFC 文件名可能在实际客户端另有约束。
- 每版逐条验证：新增必须不存在；替换/删除必须存在且 previousHash 符合当前旧内容；替换必须确实改变内容；基础只能新增。所有内容重新解码及重算哈希，每版完整状态核对文件/总字节限额和路径冲突，重新计算 snapshotHash 与 version hash，连续 index/父链必须完全相符。所选历史版之后的版本也完整验证；后续损坏不能作为“只恢复旧版”绕过。重复操作、内容失配或未知字段没有部分成功报告。为保守避免大小写或文件/目录转换歧义，单个增量变更集合本身也执行路径冲突规则；case-only 重命名或文件→目录转换请另建基础链。
- 恢复先 `prepareRestore` 重放整链，展示所有文件完整清单。仅明确确认按钮再重验整链，核对预览的快照哈希，才调用生产 `files.exportBundle({copyOnly:true,defaultName,files:[{path,base64,sha256}]})`。需 `exportBundleSupportsCopyOnly===true`；renderer 不传任意目标路径。生产接口再次验证全部数据，经保存对话框选新目录名称，独占创建且拒绝已有目录，然后独占写文件。正常失败清理新创建目录；若返回 partialPath，界面用文本显示供人工核对。进程崩溃/断电不保证全目录事务原子性。
- JSON 包及报告先完整预览，再调用 `files.saveText` 且 `copyOnly:true`，需能力标记；只 `ok===true` 宣告成功。恢复/文本导出的 canceled、false、undefined、异常均保留已完成预览，不误报成功。普通异常原文不直接展示内部路径，明确的 partialPath 为必要恢复信息。版本包含原文件 Base64；完整性报告只含路径/字节/哈希/操作/父链，无源字节及 Base64。
- 异步任务有票据与忙状态；取消、清除、编辑、隐藏、暂停、销毁令旧读取/核验/保存回调失效，不自动恢复或写文件。输入变化废弃旧链/预览；所选文件变化和历史版本变化废弃恢复与导出预览。已完成链在同面板暂停恢复保留，切换具体功能销毁源文本/File 引用/结果并移除监听。原生保存对话框确认后的写入不能由取消票据撤回；提示不能把 UI 取消理解为物理写入回滚或安全内存擦除。

## 4. 如何使用

1. 选择一个完整目录。检查实际文件数量和限额；目录输入不兼容时可选择完整平级集合，注意不会递归获取未选子目录。
2. 没有当前版本链时点击“生成基础版本 v1”。已有链不能直接替换基础，需先导出或清除。
3. 选择下一次完整目录状态，点击“比较并新增版本”。展开每版“完整变更清单”，核对新增/替换/删除路径及旧、新哈希。此时只读来源，没有写任何文件。
4. 点击“预览版本包 JSON”并保存新副本。该包是完整基础+增量链，包含文件内容，需自行选择保管及分享范围。另一台本机可读取/粘贴包，再“核验并导入完整版本链”。错误包整次阻止，不进入恢复接口。
5. 选择“恢复历史版本”，点击“核验并预览所选版本”。核对所有最终路径/字节/SHA-256，而不是只看增量文件。改历史版本或输入后需重新预览。
6. 点击“确认创建全新恢复副本目录”，在原生保存对话框提供尚不存在的新目录名称。已存在目标拒绝覆盖；取消不算成功。若发生清理失败，按显示路径人工核对新目录。
7. “预览完整性报告 JSON”可输出完整父链、各版变更和所选状态清单；报告不含原内容。清除或切换前先保存包，没有自动草稿。暂停/隐藏后手动重试，不自动恢复。

## 5. 使用后产出

完整 JSON 版本包包含所有基础与增量内容，1–10 个连续版本及 canonical 父链/快照/内容哈希；单个包可重放其中任何历史状态。JSON 完整性报告记录所选历史版本、各版类型/hash/parentHash/snapshotHash、变更动作/path/字节/新旧哈希、最终文件清单/总字节及验证边界，不导出原字节、映射或隐藏数据。

恢复产出一个全新的真实目录，内容只来自所选历史快照，不在源/当前目录做覆盖或删除；正常生产写入返回成功才显示恢复演练完成。恢复目录可自行交给目标应用进一步验证。没有自动导入应用、启动恢复文件、全盘恢复或后台定时备份。

## 6. 具体可重现例子、测试和限制

点击“演示 v1：A/B”：A.txt 为 UTF-8 `A旧版`（7 字节），B.txt 为 UTF-8 `B保留到v1`（12 字节）。再点击“演示 v2：替换/删除/新增”：A.txt 为 `A新版`（7 字节），B.txt 删除，新增 sub/C.bin 三字节 `[0,1,255]`。v2 变更按路径列出替换 A / 删除 B / 新增 sub/C.bin，最终只有 A.txt 与 sub/C.bin 共 10 字节。选 v2、核验预览、确认创建新目录；核对 A 新内容和 C 二进制，B 不存在。选 v1 再预览则恢复 A 旧内容和 B，C 不存在。不会向来源目录删除 B。

导出版本包，清除当前链，读取包后恢复 v2，得到同样快照哈希及文件字节。将 versions 删除第一个基础、调换两版、改 parentHash、改 A 的 Base64 或加入未知字段，再导入，应明确拒绝且没有恢复确认按钮或原生目录 API 调用；所选旧历史版本也不能绕过后续坏版本。删除目标已不存在、add 覆盖已有路径、replace 旧哈希失配即使重算版本 hash 也拒绝。已有目标目录含 keep.txt 时选择同一名称，生产 writer 拒绝且 keep.txt 哈希不变。

限制：不支持空目录、零文件状态、文件属性/链接、单增量分包合并、跨链拼接、超过限额的完整目录、压缩/加密/签名、多盘事务或系统应用一致性快照。目录 File API 与原生目录保存兼容性依赖 Electron/浏览器；缺生产能力明确阻止写入。20 MiB 是包的字节预算，不是运行时内存上限；处理需要同时保留有界原文本、对象、Base64 及缓冲区，没有大容量性能或全目录原子性承诺。
