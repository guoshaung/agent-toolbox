# L036 引用来源独立性检查

## 1. 功能内容

人工填写论断、选定支持文献及指向上游来源的有向无环图。按每条论断的支持集合，显示支持文献数、去重的用户标记可达原始来源数、未知终点数、共享上游分组，以及每个支持的完整可达ID集合与到各终点的一条见证路径。节点与邻接关系完整列出，标题不挤在难辨的图形上。

来源是否原始必须由用户明确勾选 original，原始节点不能再有上游边；未标原始的终点显示未知，不自动计作独立来源。支持本身就是显式原始时计入自身；同一支持ID重复输入按集合去重并报告重复数量。JSON/Markdown全文可预览与导出，草稿恢复后需重算。

## 2. 为什么需要

三篇文献可能各自转述同一个实验。支持篇数3不能直接当作三个独立原始来源。本功能把人工记录的引用链展开，突出共享上游，帮助用户返回文献检查是否重复引用同一证据。

“用户标记可达原始来源数”是图上的去重计数，并不证明统计独立性、来源真实或论断可信度。不同来源可能有其他未记录联系；未知终点也不能自动视为原始来源或无证据。工具不会检索网页、辨认真正原始论文或自动判断因果。

## 3. 实现方式、规则与容量

`model.mjs` 处理有界输入校验、全图DFS循环检测与各支持BFS可达分析；`index.js` 是来源表、论断卡片、增删/编辑、勾选原始、结果列表和导出。`meta.json` 供生产工作台发现，样式使用真实主题变量。用户文本只经 h 文本节点/textContent 渲染，不执行HTML或JS。

- 边方向为支持/二手文献 → 上游来源。1–40来源、1–10论断、整个图最多100条边。每来源上游列表最多40个ID，重复边拒绝。每论断支持列表最多20个输入ID，包含重复条目，去重后统计独立支持集合。所有ID为字母起始、1–12位ASCII字母/数字/下划线/连字符，英文逗号分隔列表、周围空白trim；空条目/未知ID拒绝，来源ID及论断ID各自不得重复。
- 核对时验证**整个图**，包括未选为支持或不可达的分支：标题/论断缺失、未知边、循环、自环、原始节点有上游、重复边均整份拒绝，不沿用旧结果。来源ID改名或删除不会自动重写引用，便于发现悬空边。未完成图可作为输入草稿保存/导出，但没有成功核对结果，不作为有效来源数。
- 原始集合是从各支持出发可达的 explicit original 节点并集。original自身作为支持包含自身路径；同源经多条路径到达只计一次。未标原始且无上游的终点另存 unknownTerminalIds，不加入原始计数。多条论断分别分析，不把支持集合串到另一论断。
- 每支持BFS访问每节点一次，存完整reachableIds（含支持自身），给到每个原始/未知终点的一条最短见证，等长路径按上游输入顺序选择。可达集合按节点输入顺序显示。不会枚举指数数量的全部路径；全图nodes/edges保留，所以未展示的其他路径没有被丢弃。共享分组按同一终点可达的不同支持归组，支持数>1的组另列；原始与未知共享终点类型明确区分。
- 图最多40节点/100边，最多10×20次有界BFS，不执行用户程序或后台任务。标题200、来源位置/备注300、上游文本1300、论断1000、支持文本260、ID12，长度按UTF-16代码单元；允许正常换行/回车/tab，拒绝其他ASCII控制符及孤立代理项。整份输入JSON与版本化草稿均≤64KiB UTF-8，超过整份拒绝、不截断文本或输出部分结果。
- 配置 `features.L036.state` 使用schemaVersion=1，仅保存节点原字段和论断支持文本，派生edges/可达集合/报告不回填。写入/恢复先验证原始JSON体积和版本，再校验字段类型与容量。语义未完成的图可暂存，核对仍须完整验证。每次编辑清空旧输出，尝试保存；保存失败提示关闭只能恢复较早草稿，建议缩短或自行复制文本保留。切走保存、销毁清空结果及DOM，异步导出完成后不重建已销毁界面；无网络、AI或计时器。

## 4. 使用步骤与可复现例子

1. 在功能工作台打开“引用来源独立性检查”，默认加载虚构教学示例。节点A/B/C是支持文献，三者上游均填E；E明确勾选原始且上游为空。论断Q1的支持填写 `A,B,C`。
2. 点击“核对来源”，应显示支持文献3、用户标记可达原始来源1、未知终点0；共享分组 `E ← A,B,C`，三条见证分别为A→E、B→E、C→E。所有示例来源注明教学虚构，不是真实文献核验。
3. 取消E的原始勾选会清空旧结果，重新核对应显示支持3、原始0、未知终点1；E仍是三篇共同上游，但属于未知终点。将支持改为 `A,B,C,A`，重复支持去除1，支持总数仍3。
4. 再勾选E原始，支持改为 `A,E,A`。结果支持2、原始1、重复去除1，E自身的见证为 `[E]`。原始来源如填上游A会拒绝，不能同时声称终点与继续追溯。
5. 点击“添加来源”，新节点S1填标题“未选支”，上游填 `S1`，即使论断只选A/B/C，整个图循环也必须拒绝；填 `Missing` 则未知边拒绝。删除该节点后可继续核对。删除/改名已有E但未改引用，也会提示未知来源E。
6. 多上游例：A→B,C，B→D，C→D,E，D/E均原始无上游，支持A。应得到原始D/E共2、完整可达A/B/C/D/E，以及最短见证A→B→D、A→C→E；D经两条链到达仍只算一次。
7. 可添加论断并选择同一图的其他支持，查看各自计数；展开完整预览或导出。输入改动需重新核对；切走/重载恢复输入，不恢复成功输出。加载示例或空白会替换当前草稿，需要保留旧图时先导出。

## 5. 产出与副本导出

JSON含feature、schemaVersion、modelVersion、导出时间、完整draft/result。结果保存全部节点（包括未选支）、全部有向边、每条论断原始支持文本和请求ID/去重支持、重复数量、原始与未知终点集合、每支持完整可达集合和见证路径、全部上游终点分组及共享分组、解释边界。Markdown先给论断计数和路径，再附完整JSON记录，动态长围栏和HTML转义避免用户内容脱离文本。页面采用完整文本列表/邻接表，没有过滤导致导出省略。

草稿导出可能没有有效result，明确不能作为完成核对的报告；没有伪造计数。字段容量或整体64KiB超限时整份导出拒绝，不输出截断图。导出前检查 `saveTextSupportsCopyOnly===true`，调用生产 `files.saveText` 并设置 `copyOnly:true`，只有 `ok===true` 才提示成功。取消与失败有独立提示；写入器使用wx拒绝覆盖已存在文件。
