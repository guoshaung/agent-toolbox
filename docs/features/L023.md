# L023 分支覆盖探索

## 功能内容

在「学习 → 编程验证与调试训练」选择内置条件程序，编辑整数/布尔测试输入集合，查看每条if决策的true/false边命中次数、命中输入编号、未覆盖边提示和分支覆盖率。每个输入保留实际执行路径、返回结果、执行或未执行的决策，以及原子条件的求值/短路跳过理由。

提供四个内置程序：简单x>0、嵌套x/y三条决策、复合`(x>0 && enabled) || override`、用于解释不可达边的嵌套矛盾程序。支持载入单/多输入示例、真实添加/编辑/删除输入、逐输入路径切换和完整JSON/Markdown导出。没有用户程序编辑或运行入口，不需要AI、联网、登录或外部软件。

## 为什么需要

测试数量多不等于走过了重要决策，重复输入常常只重复命中同一条边。本功能把输入、执行路径和固定分母对应起来，直接指出需要补充的输入区域。它新增practice运行结果之外的路径覆盖反馈。

复合布尔条件尤其容易误解：if的真假都走过，并不说明每个原子都分别取过真/假；短路未执行也不能视为false。工具保留这些区别，并用一个明确不可达例子说明为什么不能擅自把没命中的边删出分母。

## 实现方式与覆盖定义

`model.mjs`保存固定AST程序、有限条件解释器、输入验证、每次执行轨迹和边统计；`index.js`用公共`h`创建输入表、决策计数、边表和路径明细；`meta.json`供工作台发现；`style.css`仅作用于L023。模型版本`finite-branches-v1`；草稿和JSON导出`schemaVersion:1`。

解释器只处理以下受限节点：整数变量与常量比较（`>`、`>=`、`<`、`<=`、`===`、`!==`），布尔变量、逻辑AND/OR/NOT，以及固定if/return语句。没有通用语言解析，没有eval/Function、函数调用、用户脚本、循环、数组或算术表达式执行。界面的伪代码为只读文本，实际运行由内置AST解释。

覆盖统计采用本训练的**高层if决策边定义**，不声称与所有编译器或覆盖工具的低层控制流边定义相同：

- 每条静态if条件有true和false两条边。分母=if决策数×2，不取决于运行次数或已访问节点数量。
- 某边至少命中一次计入分子；重复输入只增加次数，不增加分子或分母。
- if条件没有执行时标`executed:false`、`outcome:null`，两边都不命中，另统计未执行次数。
- 复合if的整条条件仍是一条决策、两条边。内部原子求值只用于解释路径，不计入分支分母，也不生成条件覆盖百分比。这里不是条件覆盖、MC/DC或所有路径组合覆盖。
- `&&`左侧false跳过右侧；`||`左侧true跳过右侧。跳过原子标`status:skipped`、`value:null`和理由，不能虚构false或true结果。
- 所有静态决策边均保留。只有内置矛盾示例的D2真边带直接不可达证明，**仍计入分母**；一般未覆盖边不自动标不可达，也不自动排除。未覆盖提示仅是受控程序的输入建议，没有通用求解器。
- 没有输入时保留静态边列表和分母，但状态`empty`、百分比为null，显示「覆盖率未生成」。

整数范围为±1000000，字符串输入须为十进制整数；不接受空字段、小数、NaN、Infinity、布尔冒充数字或代码。布尔输入只接受true/false，0/1或字符串不是布尔。每次最多64输入，单条件AST深度至多8、节点至多32（包括短路跳过的子树），单次程序执行至多16语句。计算有界且同步，没有常驻计算任务。

## 使用步骤

1. 打开工作台「分支覆盖探索」，选择一个程序，查看只读伪代码中D1/D2/D3决策编号。
2. 点击「载入单输入示例」，或添加输入后填写当前程序声明的变量；整数用数字字段，布尔用true/false选择框。
3. 点击「运行分支探索」。先看覆盖率分数和全部边表，再看每条决策的真/假/未执行次数及未覆盖边提示。
4. 在执行表点击「查看Tn」，或选择「查看输入路径」、上个/下个输入，检查实际走过的决策与原子短路理由。
5. 添加未覆盖边所需输入后重新运行，或载入多输入示例。编辑会使旧结果失效；切换程序保留输入变量草稿，只使用当前声明字段，示例按钮会替换集合。
6. 导出完整JSON或Markdown到新文件名。没有输入或尚未运行也可导出草稿/空结果；无结果时不提供Markdown按钮。

## 产出与保存范围

JSON包装包含功能/状态/模型版本、导出时间、输入草稿和结果。结果保存程序名称/伪代码、覆盖定义、每次输入的规范化值、返回结果、执行路径、全部决策与原子求值/跳过记录、每条true/false边的次数和输入编号、未覆盖提示及不可达证明、固定分母/分子、真/假/未执行总次数。未运行或输入非法时`result:null`；空输入结果保留`status:empty`和百分比null。

Markdown包含同样的程序、规则、边计数和全部路径/短路明细及未覆盖提示。复合条件表格中的`|`字符已转义，保证逻辑OR文本不会破坏表格。界面节点数组展开并过滤空项，用户值均按文本/表单值渲染，没有null杂字、对象字符串或HTML注入。

两种导出调用公共`files.saveText`，强制`copyOnly:true`并检查能力。基础层以独占新建拒绝已有目标文件；不足时提示升级。取消/失败不清空输入或结果，没有新增共享接口或依赖。

全局配置只保存程序选择和输入集合，不保存轨迹/得分，恢复后需要重新运行。写前用`TextEncoder`测量JSON UTF8字节数，超过64KiB拒写并独立提示导出完整JSON；关闭后只能恢复较早草稿，切走不能强存超限内容。恢复先校验版本/体积、内置程序和草稿字段，保存失败明确提示。切走立即保存草稿，销毁清理延迟保存计时器与DOM；没有后台执行要恢复或暂停。本版没有文件导入按钮。

## 可复现的具体例子

### 核心验收：一条输入50%，加−1后100%

默认「简单：x>0」，输入T1 x=1，点击「运行分支探索」。

| 输入 | 路径 | 返回 | 真边次数 | 假边次数 |
|---|---|---|---|---|
| T1 x=1 | D1:true | 正数 | 1 | 0 |

分母2，覆盖1条，**1/2（50%）**。点击「添加输入」，T2 x=−1，再运行：T2走D1:false返回非正数，两边各1次，**2/2（100%）**。x=0同样走假边；重复加入x=1只增加真边次数，分母不变。

### 嵌套程序必须保留没走到的if

选择「嵌套：x与y的三条决策」，载入单输入示例(x=1,y=1)并运行：路径D1:true→D2:true返回双正数，D3未执行、两边次数均0。分母为3条if×2=6，覆盖2/6（33.33%），不能因没到D3而减分母。

多输入示例如下，覆盖6/6：

| 输入(x,y) | 路径 | 返回 |
|---|---|---|
| (1,1) | D1:true→D2:true | 双正数 |
| (1,−1) | D1:true→D2:false | x正、y非正 |
| (−1,0) | D1:false→D3:true | x非正、y为零 |
| (−1,1) | D1:false→D3:false | x非正、y非零 |

D1真/假各2次，D2和D3真/假各1次、各未执行2次。点击查看T3，D2明确标「未执行，没有命中任一边」。

### 复合条件：分支100%不代表条件100%

选择「复合：(x>0 && enabled) || override」，载入多输入示例：

| 输入 | A1 x>0 | A2 enabled | A3 override | D1结果 |
|---|---|---|---|---|
| x=1, enabled=true, override=false | true | true | 未执行（OR左侧true） | true |
| x=−1, enabled=true, override=false | false | 未执行（AND左侧false） | false | false |

分母是整条if的2条边，覆盖2/2（100%）。然而A2从未实际取false，A3从未实际取true；工具没有将它们视为条件覆盖完成，也不会把未执行当成false。把第二条override改true再运行，两条路径均D1:true，覆盖退回1/2，证明真实输入编辑会改变路径结果。

### 不可达边的规则

选择「不可达：正数中的x<0」，载入多输入示例x=1、−1运行：D1真/假、D2假都命中，D2真不命中。进入D2已要求x>0，D2真又要求x<0，声明整数域中矛盾；因此标注已证明不可达，但仍保留在4条分母中，**3/4（75%）**。一般未命中边没有这种证明，不自动认为不可达或移出分母。

## 验证及限制

运行`node --test test/feature-L023.test.js test/feature-foundation.test.js`：L023 15项、基础层6项，共21项。测试断言简单例分母/真假路径、零和重复计数、嵌套未执行不假命中和全部四路径、复合短路的精确原子轨迹、AND/OR/NOT、不可达边保留分母、六种比较边界、AST深度/节点及未知代码拒绝、空输入/整数/布尔/64条上限、确定性与输入不变、UTF8保存及Markdown。

组件事件测试实际添加−1使50%变100%，切换嵌套和复合程序、修改布尔输入、查看各条路径、验证不可达75%、空输入与非法文本、容量禁添、完整导出/取消/能力检查、仅草稿恢复及生命周期；同时断言没有null或对象字符串。

这些是纯模型和轻量DOM事件验证，没有启动Electron或确认实际保存对话框；主代理负责真实窗口集成。工具只解释固定受限程序，不分析用户源码、不计算条件覆盖/MC/DC、不证明所有路径组合或程序正确性，不自动求解不可达性，也不以已证明不可达为理由自动排除分母。
