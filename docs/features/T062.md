# T062 TLS 证书体检

## 1. 功能内容

输入主机名或 IP、独立端口，先展示规范化目标、SNI、名称检查对象、一次连接尝试/最多一次握手、TLS 1.2–1.3、五秒等待期限和明确的证书观察模式。计划不连接；必须另行点击确认才运行。只观察 TLS 证书，不发 HTTP、应用数据、API 凭据或客户端证书，不自动切换地址/端口/协议，不修改系统网络或信任设置。

为了读取过期、名称错误或不受信任的证书，**固定诊断握手使用 `rejectUnauthorized:false`**。这是明确显示的观察模式，不是修复、信任或验证成功。报告保留实际 Node `authorized / authorizationError`；独立检查主机名以及每张可获取证书的日期，避免 Node 的首个授权错误遮蔽其他问题。结果可完整预览，导出 JSON/Markdown 新副本。

## 2. 为什么需要

HTTPS 报错有时只显示一个授权错误；过期、不受信任和名称不匹配可能同时发生。仅看到握手完成也不能判断证书可信或网站可用。本工具把连接观察、Node 当前授权结果、日期和名称检查分开，使评审者能获得失败证书的可核对信息，同时保留验证边界，不把关闭拒绝作为解决方案。

## 3. 实现方式、协议与限制

纯输入/导出模型在 `model.mjs`，固定可信 Node 后端在 `host.cjs`，界面在 `index.js`。生产公共 Host 桥提供 `features.callHostSupported/callHost('T062',operation,payload)/cancelHost('T062',jobId)`，只加载安装目录有效 meta 对应的固定 host，绑定本地 file: 顶层 live sender。后端只允许 `plan/run`，run 必须 `confirmed:true` 和 12–64 字符唯一 ID，拒绝额外 CA、key、凭据、脚本或动态 TLS 选项。没有新增运行依赖。

目标最多 512 输入字符。域名经过 Node `domainToASCII` 并小写，规范化 DNS 名去掉可选末尾根点后最多 253 字符；标签 1–63 字符，仅字母/数字/点/连字符，首尾不为连字符，单标签只允许 localhost。接受规范 IPv4、IPv6（可方括号），IPv6 规范化；拒绝 URL、路径、内嵌端口、命令语法、控制字符、zone ID、未指定 IP、有限广播 255.255.255.255 和多播。端口为 1–65535。保留连接域名的末尾根点，SNI 与名称检查去掉末尾点；域名发送 SNI，IP 不发 SNI。工具不提供自定义 SNI/主机名替换或客户端身份。

每任务仅一次 `tls.connect`，固定 `minVersion:TLSv1.2/maxVersion:TLSv1.3/autoSelectFamily:false/requestOCSP:false/rejectUnauthorized:false`；不开启 HTTP ALPN、重协商、会话重用、自定义 CA 或回退。正常版本协商并非第二次连接。域名连接可能先经过系统名称解析，其内部报文和实际缓存未知；五秒期限会销毁 socket 并停止本应用等待，但不能保证已经进入操作系统的 DNS 查询立即终止。计时器依赖事件循环，不是操作系统实时调度保证。

`secureConnect` 后，在连接仍打开时读取 `getPeerCertificate(true)`，从每个 DER 建立 `X509Certificate` 并保留 subject/issuer/SAN、序号、CA 标记、密钥类型、UTC 日期、期限状态、剩余天数、SHA256 和完整 DER Base64；重复证书指纹终止环，完整性始终标 `unknown`，不可用 issuer 标 `issuer_not_available`。这仅是 Node 当时可提供的链，不证明全部服务器报文证书、完整可信路径或根已被信任。最多 16 张证书、每张 64 KiB DER、总 256 KiB、单名称字段 16,384 字符，超过范围整份链拒绝而非截断。没有证书或读取失败时，不能声称日期/名称正常。

名称检查用叶证书 DER 的 `X509Certificate.toLegacyObject()` **独立调用 `tls.checkServerIdentity(identityName,cert)`**，不依赖 Node 仅在其他检查通过后才调用默认名称检查的行为。因此过期/链不受信任仍可报告 `hostname_mismatch` 与 `ERR_TLS_CERT_ALTNAME_INVALID`。每证书日期分别按握手观察时本机时钟检查 `expired/not_yet_valid/within_dates`；日期范围内与名称匹配都不代表可信。Node 授权值依据当前运行时默认信任配置，不是浏览器或全部系统应用的结论；工具 `trustGrantedByTool` 永远为 false。

报告状态有 observed/certificate_error/connection_error/connection_closed/timed_out/canceled。`observed` 仅表示取得一次握手观察，授权 false 不伪装 true；连接或证书不可用时相应字段 null/not_checked，不从缺失信息猜结论。报告不包含原始异常堆栈/系统路径，只保留有限错误 code；证书自身公共名称/DER 可能含个人或组织信息，分享前核对。每份输出最多 2 MiB，禁止截断。

单 sender 同时一个任务，各最多 128 个不复用 ID，最多 32 sender；达到次数上限需关闭重新打开窗口。取消/隐藏/暂停/销毁均请求后端结束，后端清理期限计时器并 `socket.destroy()`；UI 用票据忽略晚回调，恢复不自动连接。公共桥在 webContents destroyed 调用 `disposeSender` 释放该发送者记录。没有持续扫描/配置秘密/自动草稿。

官方依据以实际验收 Node 20.18.3 为准：[tls.connect 与 rejectUnauthorized](https://nodejs.org/download/release/v20.18.3/docs/api/tls.html#tlsconnectoptions-callback)、[authorized / authorizationError](https://nodejs.org/download/release/v20.18.3/docs/api/tls.html#tlssocketauthorized)、[getPeerCertificate(true)](https://nodejs.org/download/release/v20.18.3/docs/api/tls.html#tlssocketgetpeercertificatedetailed)、[checkServerIdentity](https://nodejs.org/download/release/v20.18.3/docs/api/tls.html#tlscheckserveridentityhostname-cert)、[X509Certificate](https://nodejs.org/download/release/v20.18.3/docs/api/crypto.html#class-x509certificate)。没有验证 OCSP/CRL 吊销、浏览器信任、全协议强度、HTTP/TLS 以外网络层或站点可用性；不抓包、不改变证书信任、不自动修复。

## 4. 如何使用

1. 打开 **T062 TLS 证书体检**，填写目标主机名/IP 与端口（默认 443）。示例按钮只填写 `127.0.0.1:8443`，不启动服务或连接。
2. 点击 **校验输入并展示握手计划**，核对目标、名称检查对象、SNI、一次握手、五秒期限和 `rejectUnauthorized:false` 观察说明。
3. 明确点击 **确认观察模式和目标，运行一次握手**。运行中输入禁用，重复点击不重复连接。
4. 阅读 Node 授权、独立名称结果、每张证书日期和 issues，不能把 `observed` 当作可信。可手动取消，返回后报告记录 canceled 及没有获得证书的状态。隐藏/暂停则取消当前任务并忽略晚结果。
5. 分别 **预览完整 JSON 报告 / MD 报告**，检查全文、目标文件名和共享信息，再 **保存已预览报告新副本**，在宿主对话框选择全新文件名。

输入改变会废弃旧计划、报告和预览；清除/切换功能销毁未保存数据，不保存在全局配置。保存取消/失败不会显示成功，预览保留；无法撤回已经实际写完的副本。宿主缺少 Host 或副本保护能力时阻止连接/写入，不退回其他网络方式。

## 5. 使用后产出

得到 `T062-tls-certificate-report v1`，含确认计划、测量 UTC/耗时、连接状态/代码、Node 授权与观察模式、独立名称检查、可获取链/完整 DER/指纹/期限、问题清单及未测边界。可分别保存 `T062-tls-certificate-report.json/.md` 两个完整新副本；MD 包含摘要及完整 JSON/DER，没有遗漏证书。输出没有私钥、客户端凭据或系统信任修改。

生产文本副本要求 `files.saveTextSupportsCopyOnly===true`，传 `copyOnly:true`，只有 `ok===true` 显示成功；已有源/报告目标拒绝覆盖，false/undefined/canceled/异常均保留预览。实际路径由保存对话框确认。原始用户输入、证书和报告只在当前面板/任务内存，不自动存配置或服务器日志正文。

## 6. 具体例子、验证结果与边界

固定开发者 TLS 夹具在 `127.0.0.1:8443` 监听，叶证书有效期 `2010-01-01 → 2011-01-01 UTC`、SAN 仅 `wrong.fixture.test`，附中间/根证书。输入本机 IP 和端口，检查计划时连接数应为 0；确认后一次观察握手。报告应为 observed，但 Node authorized=false 且保留实际 authorizationError；独立 identity=mismatch/code ERR_TLS_CERT_ALTNAME_INVALID，同时 issues 含 `leaf_expired` 与 `hostname_mismatch`，链可获取 3 张。若 Node 首先报告 SELF_SIGNED_CERT_IN_CHAIN，也不能漏报过期或名称问题。JSON/MD 均保留 DER/指纹及观察模式，不能写成证书可信。换仅过期且 SAN 包括本机 IP 的夹具，应 expired 且 identity=matched；换期限正常但 SAN 不匹配的夹具，应名称错误。静默 TCP 夹具不完成握手，取消或五秒期限必须销毁连接而不是自动探测其他端口。

`node --test test/feature-T062.test.js`：24 项（16 Host/模型，8 实际模块 DOM 事件）；公共 Host 桥另 6 项，此树合计 30 项通过。固定证书/开发者私钥常量仅在专项 test 文件，生成一次后提交，不在产品 feature 目录；日期固定到 2050，过期叶证书固定 2011，future 固定 2040。Python cryptography 只用于 ignored 开发夹具生成，不是产品/测试运行依赖。测试执行真实 TLS 仅在 127.0.0.1 临时端口，覆盖过期、名称错误、两者并存、good/future、三证书 DER/指纹、连接销毁/超时/取消，TLS 服务端收到应用明文字节数 0。测试专用 CA 在隔离 tls.connect 适配器里证明实际 Node authorized=true 分支，不安装根到系统、不属于生产默认信任验收；生产默认测试保留不信任错误。有界/ID/晚回调/错误上下文使用受控 Host 单测，UI 用轻量 DOM 适配器，不冒称真实原生窗口。
