# E008 黑白棋

## 1. 功能内容

标准8×8黑白棋，用户执黑先行，本机执白。提供当前合法点提示、八方向同时翻子、短翻子动画、无合法棋自动跳过、双方都不能落子时按棋子数结算及平局。简单/进阶两档离线规则算法，鼠标和方向键/空格/Enter可下完整一局。没有网络、账号、计分排行或设备授权。

每次真实落子自动保存完整源步迹，重载保持暂停；支持撤销至上次黑方落子前、确认放弃当前局后按所选难度重开、完整JSON恢复及JSON/Markdown/PNG新副本。只保存当前一局，历史局需先另存，不声称长期累计战绩。

## 2. 为什么需要

给想与本机对手玩策略棋、无需联网的用户提供另一种规则。它不是现有围棋/国际象棋的改名入口。合法点和翻子记录帮助新手理解夹子规则，两个算法难度提供不同决策；暂停与撤销允许从容尝试，完整步迹便于续玩和复查胜负。

## 3. 实现方式、规则与限制

`model.mjs`负责规则、自动跳过、计数、AI、合法源步迹重放及记录；`index.js`提供真实按钮棋盘、键盘、CSS翻子和副本接口；`worker.mjs`在独立模块Worker计算两档本机落子。没有依赖包、外部AI或用户JS执行。

规则核对来源：[World Othello Federation 官方规则](https://www.worldothello.org/about/about-othello/othello-rules/official-rules/english)。采用固定标准开局，黑先；合法落子必须在空格沿直线夹住至少一枚连续对方棋，不能跨空格或己方棋。所有被此次直接夹住的方向同时翻转。当前方不能下则跳过，能下不能主动跳过；双方都不能下时按已有黑白棋数判胜，允许棋盘未填满便结束。平局两方数量相同。这里为休闲玩法，不实现比赛钟、触子必须下及正式赛事判罚。

坐标A–H向右，1–8向下。初始白D4/E5、黑E4/D5，黑合法D3/C4/F5/E6。生产判定从空格向八方向扫描连续对手，再寻找自己的端点；必须有至少一枚对手。边界按x/y检查，不允许一行末尾绕到下一行。每次落子后推导下一方：对方可下则换方；对方不可下且己方可下则记自动跳过后由己方继续；两方都不能下立刻结束。重复白方回合会重新启用Worker，最多60次标准落子保证有限，跳过不占落子数。

简单档挑即时翻转枚数最多的位置，同分取行列靠前。进阶档使用最多3层迭代加深negamax/alpha-beta，最多20000处理节点，评估位置权重、行动力差及棋数；终局用实际棋数大权重。位置权重偏好角、谨慎角边邻格；深度耗尽用启发式，不声称最优/最强/竞赛公平随机。预算不足保留上一完整搜索层结果；若连第一层未完成，使用合法即时翻子候选，不能把未完成层称为完整。两档没有随机数；当前棋盘与难度相同会给相同选择。合法规则对人机一致。

AI在Worker隔离，最多5秒超时则终止、暂停且不落子，用户继续可重试；失败/非法回复也不改棋盘。请求ID、当前活跃/可见/暂停状态核对，迟到回复无效。暂停/隐藏/离开/销毁终止Worker和清超时，返回需明确开始，不暗自续下。创建不启动Worker；无RAF/interval。翻子动画0.32秒，减少动效偏好关闭动画；暂停/离开将棋子动画暂停，恢复对局才允许继续。它是UI提示，不改变真实规则或棋盘。

schema1源存档只含版本、难度、0–63整数落子步迹，最多60步，JSON≤64KiB。重放从标准开局核对每步合法性，重新推导全棋盘、回合、翻子、自动跳过、计数和胜负，不信任外带棋盘/winner/turn字段。拒绝未知字段/版本/难度、重复键、非整数词法、越界/占用/非法/终局后步骤、坏UTF-8和超限文件，不截断。不提供任意残局编辑；合法文件也不是AI真实性/防篡改认证，用户可以构造其他合法双方走法。旧坏档须明确确认清空或导入，不静默覆盖。

撤销移除上次黑方落子以及它之后所有白方落子，包括自动跳过造成的连续白方回合，回到该黑方落子之前并暂停。已结束局冻结落子/继续/撤销，需确认新局；难度选择只影响确认的新局，不能中途悄悄改变。一个标准局的60步自然上限全部可保存、显示与导出，没有几百点击的人工限制。

## 4. 使用方法与可重现例子

进入娱乐→独立休闲游戏→黑白棋，点击“开始 / 继续对局”。你执黑，点浅色小点位置；选非法位置给解释，不改棋盘。键盘聚焦棋盘后方向键移动（包括空白非法格，便于导航），空格或Enter提交当前格，按住不会重复落子。本机执白时棋盘操作冻结，暂停/撤销仍可取消计算。

确定开局例：简单档在D3（index19）落黑，翻D4，立即黑4/白1/空59。本机选择C3（index18），翻D4为白，随后黑3/白3/空58，轮到黑。完整记录显示各步翻转坐标与计数。可点暂停，再离开返回/重载：同样两步和棋盘保留，保持暂停；点击继续才再下。撤销回到上次黑落子前，包含它之后的白棋。

改新局难度为进阶后，仅选择不会改变当前简单局；勾“确认放弃当前黑白棋重开”并“按所选难度开启新局”才清当前棋局并使用进阶。新局仍须开始。两档都可完整下至双方不能落子；有棋可下的一方不能手动跳过。

先另存JSON，在另一新局选择本地文件，预览显示难度/步数/棋数/结束状态；未勾确认不能替换。勾“确认替换黑白棋续玩”再应用，完整恢复并暂停。可用JSON `{"schema":1,"difficulty":"easy","trace":[19,18]}`恢复上述两步例；`trace:[0]`必须被拒绝，因为A1不是开局合法点。独立测试另有59步留1空格终局和60步32:32平局源迹，全部重放通过；不要求一定填满64格才结算。

## 5. 使用后的产出与安全保存

- 自动配置 `featureLab.E008.progress`：当前一局完整源步迹与难度，重载重新推导而且暂停。每步、撤销、新局及应用导入保存；失败标明当前仅临时保留，可重试或另存。进程异常退出不保证未完成保存落盘。
- JSON副本：schema1全部当前步迹，可完整恢复标准开局到当前/终局；不截短到最近几步。
- Markdown：每步双方、坐标、所有翻子坐标、自动跳过及黑/白/空计数；完整64格棋盘、当前回合/胜负和规则。完成局保留完整局，而非只记录最后计分。
- PNG：900×850全棋盘，A–H/1–8坐标、双方数量/空格/步数/回合或胜负、合法点、最近落子边框及底部规则。独立Canvas按源状态绘制，不截窗口滚动范围或未结束动画中间帧。

导出主动暂停并终止AI，使作品冻结。JSON/Markdown通过saveText(copyOnly:true)，PNG通过saveBinary(copyOnly:true)，规范Base64和SHA256，≤10MiB。检查生产capability，旧基础缺能力禁用。严格ok===true才报保存；取消不报成功；已有目标WX拒绝、partialPath提示人工核对。导出锁交互，生命周期使迟到回调失效；Canvas与临时图像字节引用在结束/失效后释放。已保存文件不随重开自动删除。
