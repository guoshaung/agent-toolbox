# L014 调度策略对照

## 1. 功能内容

在“学习 → 计算机原理交互实验”中，用同一组任务对照FCFS、非抢占SJF和RR。用户逐行输入任务名称、到达时间、运行时长及RR时间片，能够添加、删除和编辑真实任务行。运行后并列显示三策略的比例甘特图、统一统计与逐任务首次运行、完成、等待、周转、响应时间；点击甘特片段或步骤选择器，查看候选队列和调度原因，点击任务查看全部运行与等待区间及公式。

内置基础、边界入队、空闲三套可编辑示例，支持完整JSON/Markdown副本导出。核心完全本地，无AI、登录、网络或外部运行时依赖，无新增共享依赖。仅包含本ID的元数据、UI、模型、样式、测试和文档，不修改公共注册表。

## 2. 为什么需要

调度算法会改变不同任务的等待与首次响应。只背FCFS/SJF/RR名称，或者只看平均等待数，难以看清一个任务为何晚运行、是否被抢占，以及RR响应时间为何与总等待不同。本功能将同输入时间线、逐任务指标和区间公式连起来，使平局、边界与空闲的影响都能手算复核。

新增能力是可编辑、可验证的单CPU调度模型和统一指标，区别于并发模板背诵或AI解释；它不运行真实并发任务、不影响系统进程。

## 3. 实现方式和统一口径

`model.mjs`使用事件推进模拟，在运行结束或时间片结束时处理候选队列，没有按巨大时间域逐tick循环。三策略接收同一份经过校验的任务副本，输入行索引用于稳定排序。UI使用现有`h`构建输入表、实际事件控件、DOM甘特图及结果表；用户字符串仅进入文本节点和表单值，不能执行代码或HTML。独立测试另用逐tick oracle核对模型，未与事件模型共用调度代码。

本模型规则如下：

- 单CPU、无I/O、无优先级、无依赖，切换成本0。任务到达时间是非负整数，运行时长与量子是正整数；时间单位统一为tick。任务名1～24字符且去首尾空格后唯一。1～50任务，到达范围0～99999，时长及量子范围1～100000，禁止小数、科学计数、脚本和非数值对象。
- FCFS非抢占，按到达时间排序；同到达按输入行顺序，不按任务名称字母排序。
- SJF非抢占，只在当前已到达候选中选择运行时长最短者；同burst按到达时间，再按输入行顺序。运行中到达的短任务不会抢占正在执行的任务。
- RR按到达时间/输入行顺序入队。当前任务运行期间及时间片结束边界到达的新任务，先进入队尾，再重新排队当前尚未完成任务。任务恰在边界完成则不重新排队。即使没有竞争任务，相邻同任务时间片仍分开保留，显示量子边界。
- 区间采用`[开始,结束)`；时间轴从0开始，初始无任务或任务间断档均显示CPU空闲片段。到达前的空闲不算该任务等待。
- 完成时间为最后一次运行的结束时刻；周转=完成−到达；等待=周转−运行时长；响应=首次运行−到达。RR响应只算第一次运行前的等待，不等于总等待。平均数分别由全部任务的等待、周转、响应求和除以任务总数，精确值保存在JSON中，界面显示两位小数。
- 总完成时间makespan定义为从0到最后一个任务完成，包含初始空闲；CPU忙时长为所有burst之和，空闲=makespan−忙时长，利用率=忙时长/makespan。
- 模拟终点最多100000，每个策略最多1000个甘特片段，空闲也计片段。总burst超过100000提前报错；其他时间或片段超限整轮拒绝，不截断、不展示其他策略的部分成功报告。增大量子可减少RR片段，但不保证满足时间上限。
- 甘特条宽度为片段时长/makespan，无人为最小条宽；窄片段可用选择器、键盘或标题查看。时间轴最小800px，可横向滚动；前后片段选取只切换解释，不重新执行模拟。
- 配置只保存`schemaVersion:1`输入草稿，不保存结果；写入前测JSON的UTF-8大小，≤64KiB才保存，恢复检查整个存储对象的体积、版本、字段类型与容量。草稿可保留空行或未完成输入，运行时再做数值校验。超过64KiB明确提示导出完整JSON；关闭只能恢复较早草稿，不能恢复当前超限内容。
- 编辑清空旧时间轴和指标；保存延迟250ms，切走/销毁释放定时器并尝试保存。模拟有界同步完成，不留后台工作；已销毁组件不响应异步保存/导出消息。
- JSON/Markdown通过基础层`saveText`的`content`、扩展名和`copyOnly:true`导出，检查防覆盖能力；创建新文件，拒绝覆盖已有路径。Markdown转义HTML字符及表格分隔符。

## 4. 使用步骤与可复现例子

打开功能后默认量子1，任务A/B到达均0，时长分别3/2。点击“运行三策略对照”，FCFS时间线为`A[0,3)、B[3,5)`，总完成5。点击“FCFS查看任务B”，显示等待`5−0−2=3`、周转5、响应3，满足规格验收。

同输入的全部手算结果为：

|策略|时间线|A完成/等待/周转/响应|B完成/等待/周转/响应|平均等待/周转/响应|
|---|---|---|---|---|
|FCFS|A 0–3，B 3–5|3 / 0 / 3 / 0|5 / 3 / 5 / 3|1.5 / 4 / 1.5|
|SJF非抢占|B 0–2，A 2–5|5 / 2 / 5 / 2|2 / 0 / 2 / 0|1 / 3.5 / 1|
|RR，量子1|A 0–1，B 1–2，A 2–3，B 3–4，A 4–5|5 / 2 / 5 / 0|4 / 2 / 4 / 1|2 / 4.5 / 0.5|

点击“载入边界入队示例”再运行：量子2，A到达0时长4，B/C到达2时长1，输入顺序A、B、C。RR时间线为`A[0,2)、B[2,3)、C[3,4)、A[4,6)`；第一个片段结束后候选顺序必须显示`B → C → A`，证明边界到达先于当前任务重新排队。用“RR查看时间片段”选择第4段，核对A剩余2后完成。

点击“载入空闲示例”再运行：A到达2时长2，B到达7时长1，C到达7时长3，量子1。FCFS与SJF均为`空闲[0,2)、A[2,4)、空闲[4,7)、B[7,8)、C[8,11)`。总完成11、忙6、空闲5；A等待及响应均0。RR运行A时保留两个时间片，随后B一次、C三次，总完成仍11。

自定义时逐行修改名称、arrival、burst，添加或删除任务，再选择RR时间片。输入变化立即清空旧结果，需重新运行。运行后看三策略摘要，再点击各策略任务详情和甘特片段，核对运行、等待区间。导出时选择不存在的新文件名；取消文件对话框保留当前草稿与结果。

## 5. 产出

界面同时输出三条比例甘特图（包括idle）、每个策略的逐任务指标表、平均数、总完成时间、忙/空闲时长，以及可选择的任务公式/区间与片段队列/原因。不会以平均值替代逐任务结果。

JSON包含feature、schemaVersion、modelVersion、导出时间、原始字符串草稿、规范化任务与量子、三策略完整时间线及逐任务运行/等待区间、队列快照和统计。Markdown包含完整输入表、三策略规则、所有片段表、逐任务指标和区间公式。未运行或编辑后导出只包含当前草稿，明确未生成结果。当前不支持报告导入，配置草稿可恢复后重新运行。
