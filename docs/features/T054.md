# T054 可复现模拟数据生成

## 1. 功能内容

用户输入有限多表 `T054-schema v1`、每表记录数和固定种子，生成 `synthetic-data.json`、每表一个 `tables/<表名>.csv`、`generation-manifest.json` 完整参数清单。每表有唯一顺序数字主键，外键指向目标表实际存在的主键。支持闭区间整数、定点小数、布尔、原始枚举和带明显 SYNTHETIC 标记的合成文本。

固定种子、规范化 Schema 和固定生成顺序使重复生成的**全部文件字节和SHA-256一致**，清单也没有当前时间、随机文件名、保存路径或源文件名。可选边界模式将每表前两行选为各字段域首/末，其他行按明确的 uniform 离散伪随机规则抽样。不是实际人物或交易记录，也不是统计分布证明或匿名化工具。

## 2. 为什么需要

开发、演示和错误复现需要稳定的小数据集，真实记录可能包含个人信息且不便分享。本项用明确规则自行合成，复现时只需同一Schema与种子；主外键关系保持有效，边界样本帮助测试最小/最大值，完整参数清单便于核对。无需数据库连接、账户、网络、AI或第三方伪造人名库。用户手填的枚举或前缀会复制，不应把真实敏感记录当作生成参数，本工具不替这些文字去敏。

## 3. 实现方式与范围

独立 `model.mjs` 严格解析JSON，拒绝普通/转义重复键、尾随文本、非法数字、非有限/不安全整数、控制字符与不配对Unicode。根/表/字段都只接受固定必填关键词，未知词直接阻止，不静默忽略，不执行JavaScript、表达式或正则。输入最多64 KiB UTF-8、深度8（根0）、**全部JSON节点3000**（含容器、关键字值、枚举元素）。1–10表，每表1–20个用户字段，每表0–1000行，**全部表合计≤1000行**，产物全部合计≤2 MiB；任何超限不截断、不导出部分表。

根必填 `format:"T054-schema"`、`version:1`、`distribution:"uniform"`、`boundaryRows:boolean`、`tables:[]`。不是JSON Schema/OpenAPI方言，不接受任意约束、normal分布、权重、时间、函数或nullable。

每表必填 `name/rows/primaryKey/fields`；表/字段名为ASCII英文字母开头、后续字母数字下划线、最长32，禁止Windows保留名CON/PRN/AUX/NUL/COM1–9/LPT1–9；表名/字段名不区分大小写重复即拒绝。由此生成路径无遍历、NFC/大小写歧义、系统保留路径或前缀碰撞。外键名称区分大小写精确匹配，错误大小写不自动修正。每表必须恰有一个 id 字段且是声明的 primaryKey；不支持复合主键或其他唯一列。

字段参数固定：

|type|必填参数（所有字段另有name/type）|生成含义|
|---|---|---|
|id|无|行序号1…N，表内唯一，种子不改变ID|
|integer|min/max|安全整数闭区间，各界限±1000000，min≤max|
|decimal|minUnits/maxUnits/scale|整数最小单位闭区间，各单位±1000000；scale0–3，值=单位/10^scale，CSV固定scale位|
|boolean|无|false/true两值离散抽样|
|enum|values|1–50个不同string/boolean/±1000000整数；不接受null/对象/数组/小数；字符串最长120个UTF-16单元|
|text|prefix|最长80个UTF-16单元的人工前缀；产出 SYNTHETIC_表_字段_四位行号_前缀_六位伪随机数|
|foreignKey|table|只指向目标表primaryKey，目标必须存在且至少1行|

枚举/前缀允许引号、逗号、TAB/CR/LF和Unicode，禁止其他低控制字符及无配对代理。数字域采用安全整数单位，小数JSON值是有限JavaScript number，不是任意精度十进制；CSV用已声明scale表示，例如单位-101/scale2→JSON -1.01、CSV `-1.01`。没有真实地址/姓名/电话/邮箱生成器。

关系图在生成前完整验证。缺表、空目标（即使引用源表也0行）、自引用或多表循环全部拒绝，无部分结果。依赖目标先生成，再从目标已存在行的主键取值，不能凭空造外键。孤立0行表可生成空JSON数组和仅CSV表头；不虚构数据。表/字段以代码单元字典序排序，依赖按该固定字段/表顺序做后序生成；JSON/CSV输出表依然按表名排序，行按ID递增。原Schema键顺序、表/字段数组顺序和输入空白不进入产物，清单嵌入**完整规范化Schema**及其摘要；enum数组顺序保留（关系到域首/末含义）。

种子为1–64个UTF-16单元字符串，严格Unicode；不做隐式trim或Unicode归一。对UTF8字节自写FNV-1a32（offset2166136261，prime16777619，模2^32），零状态替换固定0x6d2b79f5，再用xorshift32移位13/17/5。技术依据：[FNV作者IETF草案](https://www.ietf.org/archive/id/draft-eastlake-fnv-25.html)；本项是自有实现，不复制库或源码。整数/单位/枚举索引/布尔/外键用范围拒绝采样后取模，域宽≤2000001，最多64次拒绝，超过明确失败。uniform含义是**离散伪均匀抽样映射**，不是独立真随机、密码安全或有限样本统计保证；不支持正态/泊松/加权等分布，种子32位散列可能碰撞，不能保证任意不同seed数据都不同。

boundaryRows=true时，**每表**第1行选择数值最小/false/enum首项/目标首行，第2行选择最大/true/enum末项/目标末行。若只有1行只提供首边界；0行无边界。第3行起离散伪均匀；text仍正常生成SYNTHETIC文本，id始终顺序，不称文字/ID强制随机边界。min=max/单元素枚举自然重复，但主键仍唯一。boundaryRows=false时所有被抽样字段都用伪随机，ID仍顺序。固定/退化域或仅id表可能在不同seed下数据相同；同seed复现保证覆盖全部产物。

JSON顶部显式 `synthetic:true` 和非真实记录notice，每CSV额外首列 `_synthetic=SYNTHETIC_T054`（20个用户字段外再加1标记列），合成文本也以SYNTHETIC开头。CSV为UTF-8无BOM、逗号分隔、CRLF记录结束、全部单元双引号包围，内部双引号加倍，内部CR/LF保留；依据 [RFC4180](https://www.rfc-editor.org/rfc/rfc4180)。按 [OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection) 说明，只有字符串单元若空白后以 `= + - @` 开始、或初始TAB/CR/LF，前加apostrophe；JSON原值不改，清单记录每表保护格数量。浏览器textarea预览/复制会把CRLF规范为LF，正式副本仍保留清单声明的CRLF和SHA；从预览复制的CSV文本不能代替字节一致的导出副本。负数/小数等真正数值不加apostrophe；例string `"-3"` 会保护而numeric -3不会。保护后CSV字符串可能与JSON不同；不保证所有表格导入器处理完全一致，未验证Excel应用实际导入，按UTF-8/文本列导入时自行核对。

清单含完整规范化Schema、seed、算法版本文字、排序/依赖顺序、边界/分布定义、全部行数、Schema SHA、CSV范围与保护统计、数据/CSV每文件bytes/SHA。避免清单自我循环，不嵌入自己hash；UI和传输对**每个文件包括清单**都计算并提供WebCrypto SHA-256。没有时间字段或源正文拷贝。

界面使用h()/text/textarea，不把用户文字执行为HTML。真实File API只读用户选择文件，核对实际size与读到字节，fatal UTF-8，不猜编码，不访问任意路径；源文件名不持久化，UTF8 BOM由解码器去除。seed/源/结果只在当前面板内存，不调用ctx.config保存；切换功能销毁。每50行/每表/每摘要后核对任务票据，读取后核对；取消、隐藏、暂停、清除令旧回调失效。受控同步解析/序列化不能即时打断，但有容量限；暂停不自动导出，恢复不自动生成。

全部文件完整预览后才显示确认按钮，`exportBundleSupportsCopyOnly===true`才调用 `files.exportBundle({copyOnly:true,...})`。主进程重验规范Base64/路径/SHA，经保存对话框选全新目录，已有目标拒绝。只有ok===true提示成功；canceled单独提示，false/undefined/throw保留预览不假成功，内部错误/路径不回显；partialPath提示新目录清理未完成。写入的正常失败清理不等于崩溃/断电事务保证，UI取消不能撤回已完成原生写入。

## 4. 如何使用

1. 工作台打开T054，默认用户/订单两表例子、seed-42。可直接修改有限Schema中的rows和字段，或只读加载UTF8 JSON。
2. 明确保留distribution uniform，选择boundaryRows true/false；外键table必须是非空目标表，主键为唯一id类型。种子保留或改成需记录的固定文字。
3. 点“生成并预览全部文件”。语法/容量/关系错误显示明确原因码，无部分CSV或旧导出按钮；修正后重新生成。
4. 逐个核对完整JSON、所有表CSV与完整清单，再点“确认导出已预览文件到全新目录”。实际新目录由保存对话框确认，已有目录不能覆盖。
5. 同Schema同seed重新点生成再导出到另一新目录，可以比较全部文件字节或清单摘要。源/seed编辑废弃旧预览；切换功能前先导出，清除按钮移除全部当前源/seed/预览。

## 5. 使用后产出

新目录含1个synthetic-data.json、1–10个CSV和1个generation-manifest.json，共3–12文件。JSON含各表name、primaryKey及全部rows；CSV可用于支持本项输出范围的测试/演示导入；清单提供复现所需的完整参数及摘要，不仅是统计概要。所有记录明确合成，主键表内唯一，外键属于实际目标主键集合。无SQL、执行脚本、真实记录抓取、数据库写入或自动上传产物。

## 6. 可重现例子、测试与验证边界

默认点击生成：users 3行、orders 5行，共8行、4文件。users.id=1/2/3；users第1/2行level=1/9、active=false/true。orders第1/2行amount=1.00/99.99（JSON number显示1/99.99，CSV固定两位）、user_id=1/3、state=待处理/完成；其他外键仍属于1/2/3。再用seed-42生成，JSON、两个CSV、清单字节和hash都一致。改seed为next-seed，例子的伪随机合成文本/后续采样改变，ID和强制边界仍相同。

最小输入：

```json
{"format":"T054-schema","version":1,"distribution":"uniform","boundaryRows":true,"tables":[{"name":"items","rows":2,"primaryKey":"id","fields":[{"name":"id","type":"id"},{"name":"count","type":"integer","min":-2,"max":4}]}]}
```

生成两行count=-2/4，CSV负数不加文本保护。给枚举values设 `["=SUM(1,2)","第二项"]` 时JSON第1行保持公式候选原字符串，CSV对应格变为`'=SUM(1,2)`并双引号转义，清单formulaProtectedCells计数≥1；真实表格如何显示不属于本机纯生成证明。把外键目标rows改0或删目标、产生循环、distribution改normal、增加未知字段、复制重复JSON key都明确阻止。
