# L006 类比角色映射

## 1. 功能内容

L006 为用户的源系统和目标系统建立两个有限结构图：人工选取原文片段为实体、填写直接有向类型关系，再将源实体逐项配对到目标实体。执行后输出完整角色映射表、每条源关系的检查状态、结构不保持清单及双系统箭头图。它实现 catalog 中“手动配对实体；检查关系在两侧是否保持，不自动评价类比真实性”，完全本地可用，无AI、网络或外部运行时要求。

默认源图是 **S1=A —依赖→ S2=B**，配对 **M1:S1→T1=X、M2:S2→T2=Y**，目标图没有T1—依赖→T2。主动执行得到源关系1、保持0、不保持1，只列 **SR1** 不保持。用户录入目标同向同类型直接关系后得到保持1、不保持0。不同名实体不会自动配对、同名实体也不会自动合并；实体、配对、类型与来源都是人工记录。

界面提供两侧原文编辑稿、出处名/位置、已提交原文的选区取位置、实体增删/改名/说明/出处、关系增删/类型/依据、配对增删/依据/新版确认、完整版本记录、源关系高亮选择及JSON/Markdown报告预览。图展示全部保留实体、关系和映射；JSON/Markdown保存全部输入和逐关系结果，不依赖图中文字截断来保存信息。

## 2. 为什么需要

类比常只记录“某物像某物”，而忽略相同关系是否在两侧都被明确提出。例如A依赖B并不意味着人工对应的X也依赖Y；反向Y依赖X、X和Y的其他联系、或X经过Z才关联Y也不能充当同一条直接关系。逐关系对账将用户的结构声明与缺口分开，方便修改类比或保留待核问题。

本功能检查输入图的字面结构。它不抽取语义、不核验作者引文、不判断实体真正扮演同一角色、不证明类比真实，也不把“保持几条”包装成迁移效果或学习成绩。原文、人工图和出处之间是否一致仍需用户核对；目标用户图未录入某关系不等于目标真实系统不存在它。

## 3. 实现方式与规则

纯模型位于`model.mjs`；`index.js`以生产feature工作台接口创建控件、处理编辑、异步票据、串行配置保存和副本导出；`style.css`使用项目实际主题变量。无`eval`、`Function`或用户代码执行，无系统文件修改、网络请求、计时播放。

**关系口径。** 每侧关系是`(from实体ID,to实体ID,人工类型)`。类型只做`trim()`和Unicode NFC规范化，保留用户输入的原类型；相同NFC有向三元组只能录入一次。大小写、语言、同义词或不同类型不自动等同；反向边和传递路径不替代直接边。允许环和自环：这是有限结构图，不要求因果DAG，存在闭环也不自动评估合理性。源/目标实体ID分别S/T，关系ID分别SR/TR，映射ID为M；ID1–9999递增，删除不复用。

映射首版限定**部分一一对应**：每个源实体最多配一个目标实体，每个目标实体也最多使用一次；不支持合并多个角色到同一目标，超出范围明确拒绝。源关系两端均有当前映射时，按映射得到目标三元组，逐条检查目标录入图中的同类型同方向直接关系。检查不依赖实体显示名称，未知名称/出处单独列出，不填补用户未知证据。

全部源关系都输出一行，按下列顺序区分状态，而不是将未审记录都称为“不保持”：

1. 源关系缺当前确认或源端点缺当前锚：`source-stale`，源旧版待核。
2. 任一源端点尚无人工配对：`unmapped-endpoint`，端点未配对。
3. 配对缺当前双侧确认或目标端点缺当前锚：`mapping-stale`，配对旧版待核。
4. 目标图无对应直接三元组：`not-preserved`，本轮不保持。
5. 目标图有对应三元组但缺当前确认/锚：`target-relation-stale`，目标旧版待核。
6. 对应目标直接关系当前有效：`preserved`，输入图保持该关系。

**原文与位置。** 两侧分别保存全文和出处版本；修改编辑稿不会覆盖已提交原文，执行必须先提交新版或明确放弃。改全文或出处提交新版后，旧实体锚、本侧关系确认和跨侧映射不会自动移到新位置。先人工重锚两端，再明确确认本侧关系和双侧映射。每个锚保留当时原文版本、原片段、0起算UTF-16半开区间和Unicode码点半开区间，恢复时逐字段重算校验，拒绝切开emoji代理对/非法字符/伪造位置。原文不搜索自动重定位。

同版纠正某实体锚为明确人工操作，更新该版锚、不追加同版锚；它不会自动撤销同版已录入关系或配对，用户需审阅这些当前人工记录。实体名称/说明/出处、关系类型/依据、映射依据以及系统名称是当前人工台账值，编辑后废弃结果，但不是每次改字的不可变审计历史。保留的是各版全文/原文出处、锚历史及关系/映射确认版本；没有可信时间戳、安全签名或语义认证。

HTML textarea会将CRLF/CR规范化为LF。已提交只读原文的选区会映射回保存的原始UTF-16位置；本台粘贴编辑稿得到的是浏览器实际文本，不声称任意外部文本原字节导入保真。没有外部文件导入/扫描功能。

**容量与异步。** 每侧≤8实体、24关系、8原文版本，每版/编辑稿≤4000码点，片段≤240码点；≤8配对，每个配对≤16双侧版本确认组合。实体名称≤80、说明/关系/映射依据≤600、出处名≤160、出处位置≤320、关系类型≤40码点。完整schema1输入，包括两侧全部保留原文、编辑稿、锚/关系/映射历史，JSON UTF8≤65536字节。超限整项拒绝，旧输入不变，不截断、丢旧版本或写入超预算配置。

派生报告不写草稿。配置保存为一在途/最新待写队列，旧回执不宣布最新输入已保存。每四条源关系异步让出并校验取消票据；输入编辑、取消、隐藏、切走、销毁均使迟到结果失效。恢复只恢复输入，不自动执行。未知schema、字段、引用、重复关系、非一一映射、错误锚、版本回退、容量超限均拒绝，不能部分假成功。

## 4. 使用步骤与可复现例子

1. 在功能工作台打开L006，点击“检查人工类比关系”。默认显示**源关系1、保持0、不保持1、其余待核0**，仅SR1不保持；源A→B依赖箭头粉色，两条跨侧虚线分别指向X/Y，目标无对应直接边。
2. 目标关系表单默认T1→T2、类型“依赖”，点击“新增目标系统直接关系”，旧结果立即失效；再执行，显示保持1，不保持0。关系是用户新声明，工具不自动改目标原文或判断声明与原文是否一致；需更新描述时走原文新版流程。
3. 先尝试T2→T1“依赖”或T1→T2“depends”，都不会替代源“依赖”关系。正确同向同类型录入后，只匹配它，额外目标关系另列。将源类型改为` é `（e+组合重音）、对应目标类型改为`é`，trim+NFC后保持；再次录入规范化同一三元组拒绝重复。`É`与`é`仍不同。
4. 删除M1需要明确确认，SR1进入“源端点未人工配对”；源/目标实体保留。重新配S1/T1得到M3，ID不复用。重复使用已配源/目标实体拒绝，不自动替换另一映射。有关系/配对引用的实体不能直接删除，先人工删除引用对象。
5. 在源系统编辑稿开头加“前缀”，检查拒绝未提交稿。点击“提交源系统原文新版”，v1保留，SR1为源旧版待核，不列不保持。选S1/S2，手填原UTF-16起止各+2，或从只读原文取对应非空选区，再确认当前实体锚。两锚重标后仍须确认SR1当前原文关系，此时映射旧版待核；再确认M1/M2两侧当前映射，才能恢复直接关系保持。
6. 修改目标原文开头加“前”，提交目标新版，两目标锚位置各+1重标、确认M1/M2后仍显示“目标相同关系旧版待核”；明确确认目标TR1当前原文关系才恢复保持。窗口重载两侧各v1/v2、锚历史和配对确认仍在，但结果为空，主动执行复算。
7. 添加未知实体可从原文选区取位置，填写名称/来源名/位置与人工说明，录入关系和跨系统配对。未知出处或名称单列待补，工具不猜角色。调整图高亮只改变图，不筛掉其他源关系的报告结果。
8. 查看完整映射和逐关系表、旧版/未配对状态、出处待补、完整JSON/Markdown预览，导出报告或SVG新副本。无报告/未提交稿也可展开输入归档导出全部合法输入。超容量的候选改动未进入合法台账，先归档旧记录再明确另建；整体替换教学例或删除对象会移除其输入历史，不承诺撤销，需保留先导出。替换教学例同时复位未提交关系/配对表单。

独立Unicode例：保存原文`🙂甲\r\n乙😀。`，原始UTF-16选区`[5,8)`为“乙😀”，码点`[4,6)`。浏览器只读框中的LF选区`[4,7)`映射回原始`[5,8)`。`[6,7)`切开😀代理对，整项拒绝。不会因为同一文字重复出现而自动选择另一个位置。

## 5. 产出与保存范围

完整JSON/Markdown包含modelVersion、schema、两侧每版全文/来源、编辑稿、所有实体当前人工名称/说明/出处/旧新锚、全部关系类型/依据/确认版本、配对依据/双侧版本确认、每条源关系映射目标三元组、匹配目标关系ID、六类状态计数、不保持列表、未配对源实体、额外目标关系、未知名称/出处和完整口径。没有学习效果/类比真实性分数。未使用目标关系表示额外人工记录，不自动认定错误。

SVG包含全部保留实体/关系/配对及当前选中源关系的高亮。短标签节点名称最多8码点、选中关系类型最多12码点；完整名称/类型/依据保留在SVG title、人工台账和JSON/Markdown表。实体ID和两侧箭头明确，配对标签靠源侧固定行，避免不同目标顺序在中央重叠；稠密多关系曲线可重合，应逐条选择并核对完整表。SVG是结构图副本，不代替全文归档。JSON/Markdown/SVG各≤1MiB，超限整份拒绝。

输入归档含全部合法输入和未提交编辑稿，明确不是检查结果。临时选区数字、尚未提交的新关系/配对表单及图选择只为操作控件，不持久化；提交后的对象、当前原文编辑稿才属于草稿输入。所有派生检查都需重算。

导出必须具备`files.saveTextSupportsCopyOnly===true`、携带`copyOnly:true`并收到`ok===true`，才显示已保存。取消、未知/字符串ok或失败回执不冒称成功。生产writer以`wx`写新文件，已有目标拒绝覆盖。已开始写盘不能撤回；编辑/离开/销毁后迟到回执不能补显示旧结果成功。预览和副本会含用户两侧原文、来源和人工备注，应由用户决定保存位置；本台不读取或修改外部来源文件。
