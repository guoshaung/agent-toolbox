# L022 变异测试训练场

## 功能内容

在「学习 → 编程验证与调试训练」选择内置max、sum或product纯函数，只填写测试参数a、b及期望输出。可添加、编辑、删除最多64条测试，载入最小或强化示例；先验证原函数，通过后逐个执行固定的比较/算术运算符变异，显示杀死/存活/等价排除列表、具体输入与结果、测试×变异矩阵和口径明确的得分。

每个变异卡片同时显示原实现、变异实现、改动说明、所有测试的观察结果及杀死它的测试。测试或函数变化会使旧结果失效；切换函数保留现有用例，明确要求确认当前函数的期望值。示例按钮会替换当前测试。

核心在本机运行，没有用户代码输入或执行，不需要AI、登录、网络、外部运行时或安装依赖。

## 为什么需要

测试通过只说明当前用例与实现一致，不说明它能发现一个常见错误。例如`sum(2,2)=4`会放过把加法写成乘法的变异。本功能量化当前测试能区分哪些固定错误，并给出可复核的杀死证据，帮助学习者主动补充参数顺序、相等、零和负数边界。

这补充现有pytest练习与AI出题的能力：新增受控变异和测试有效性观察，不靠测试数量或成功提示推断覆盖。得分衡量本工具的有限变异集合，不代表代码覆盖率，也不证明真实程序正确。

## 实现方式与数值规则

`model.mjs`包含固定函数/变异元数据、对应纯函数求值器、输入验证、基准和变异判定、报告。`index.js`用公共`h`创建表格输入、矩阵和证据卡片，处理保存/导出；`meta.json`供工作台发现；`style.css`仅影响L022。模型版本`operator-mutation-v1`，草稿和JSON导出`schemaVersion:1`。

输入与判定有明确边界：

- a、b只能是−1000000至1000000的十进制整数，期望只能是±1000000000000内整数；空字段、小数、布尔、null、NaN、Infinity、代码字符串和越界数均拒绝。字段可用正负号和首尾空格，不接受科学计数法字符串。
- 原函数的max、加法和乘法在此范围内都得到有限、精确的安全整数。期望用精确数值比较，不使用近似容差；0与−0相等并规范化为0。
- 除法变异按JavaScript Number求值，有限小数也参与精确比较。零除得到NaN/±Infinity时视为可观察失败，可杀死变异；JSON存`kind:non-finite`及文字显示，不把非法数值序列化成null。
- 最多64测试，最多4变异，计算有界且同步完成，不运行任意代码、不启动后台进程。退出清理延迟保存计时器与DOM，没有持续运行任务。

内置实现及运算符变异：

| 函数 | 原实现 | 变异 | 参与计分 |
|---|---|---|---|
| max(a,b) | `a > b ? a : b` | `>`→`<`、`===`、`!==` | 各计1项，共3项 |
| max(a,b) | 同上 | `>`→`>=` | 已证明等价，排除 |
| sum(a,b) | `a + b` | `+`→`-`、`*`、`/` | 各计1项，共3项 |
| product(a,b) | `a * b` | `*`→`+`、`-`、`/` | 各计1项，共3项 |

只有固定比较/算术运算符变异，没有改变量名、常量、控制流或用户可编辑代码。屏幕中的实现文本只用于说明，不经eval或Function编译。

## 基准、存活和分母口径

1. 每条测试先在原函数上运行。任何一条与期望不同，状态为`baseline-failed`，显示实际与期望、返回`score:null`和空变异执行列表，不生成正常变异得分。不能把错误期望杀死很多变异当作好测试。
2. 空测试状态`empty`，得分未生成；不能标成合格的0%。有有效测试且都通过时，0/3则是有效但未杀死任何计分变异的结果。
3. 非等价排除项执行全部测试；任一实际值与期望不同或出现非有限结果，标`killed`。记录全部杀死证据，一个变异即使被多条测试杀死也只计1次。
4. 没有发现差异的项标`survived`，明确不能据此断言等价，仍计入分母。工具不通过“所有测试都过了”推断等价。
5. max中`>=`变异的排除来自声明数值域的直接证明：a≠b时与`>`判断一致；a=b时分支虽然选择不同参数，输出数值相同。NaN不在输入域，0和−0按相等处理，所以该项与原函数等价。排除理由随报告保存，不作为“存活”计入分母。
6. 得分=杀死的参与计分变异数/所有参与计分变异数。max生成4项、排除1项、分母3；sum/product生成3项、排除0项、分母3。显示生成、排除、杀死、存活数量与百分比。满分只覆盖这些变异和测试，不是正确性证明。

## 使用步骤

1. 打开工作台「变异测试训练场」，选择内置纯函数，查看原实现和数值范围。
2. 点击「载入最小示例」，或「添加测试」后填写a、b及期望。每个字段有测试编号；可删除单行或载入强化示例替换当前用例。
3. 点击「运行变异训练」。先查看原函数基准表；若失败，修正期望或参数后重新运行。
4. 查看每个变异的具体实现与输入/期望/实际值，在矩阵中观察哪个测试杀死哪些错误，分辨存活和等价排除。
5. 补充相反参数顺序、相等、零、负数用例，再运行并比较得分。输入编辑后不会继续显示旧得分。
6. 导出完整JSON或Markdown到新文件名。切换函数保留测试，需要确认期望；本版不导入测试文件，也不运行用户项目。

## 产出与保存范围

JSON包装含功能/状态/模型版本、导出时间、测试草稿及结果。结果保存原函数实现、数值/计分规则、全部测试的参数/期望/原函数结果、基准判定、每个变异的原/新实现、改动、状态、等价排除原因、全部测试观察和杀死测试编号，以及生成/排除/分母/分子/存活数量。基准失败和空测试也可导出，保留其状态及`score:null`；未运行或输入非法时JSON的`result:null`。Markdown包含相同判定及证据，存在结果时才提供。

所有导出调用公共`files.saveText`并强制`copyOnly:true`，先检查能力标识，不足则提示升级；主进程以独占新建拒绝已存在目标文件。取消或失败不会清空测试。没有共享接口或依赖改动。

全局配置只保存函数选择和测试草稿，不保存得分/执行结果。恢复后必须重新运行。写前以`TextEncoder`检查JSON UTF8体积，超过64KiB拒写并独立提示导出完整JSON，关闭后只能恢复较早草稿，切走不能强存超限内容。恢复先验证状态版本/体积、内置函数和字段结构；保存失败明确提示。完整结果通过导出保留，本版没有文件导入按钮。

## 可复现的具体例子

### 验收：max(2,1)→2杀死反向比较

默认选择max，测试T1为a=2、b=1、期望2。点击「运行变异训练」。原函数结果2，基准通过。

| 变异 | 结果 | 状态 | 分母 |
|---|---|---|---|
| max.reverse：`a < b ? a : b` | 1，与期望2不同 | 被T1杀死 | 计入 |
| max.inclusive：`a >= b ? a : b` | 不执行测试，按证明排除 | 等价排除 | 不计入 |
| max.equal：`a === b ? a : b` | 1，与期望2不同 | 被T1杀死 | 计入 |
| max.unequal：`a !== b ? a : b` | 2 | 存活，不能断言等价 | 计入 |

预期得分**2/3（66.67%）**，生成4、等价排除1、存活1。点击「添加测试」，T2填a=1、b=2、期望2，再运行：`max.unequal`实际1被T2杀死，得分**3/3（100%）**。也可载入强化示例，同时包含(0,0)→0。

把T1期望改成1再运行，预期「测试基准失败 · 变异得分未生成」，原函数仍为2，变异列表不执行。删除全部测试后运行，预期「无测试 · 变异得分未生成」。仅测试(0,0)→0则基准通过，三个非排除变异都存活，得到有效的0/3。

### 算术边界补充

选择sum并载入最小示例(2,2)→4：减法实际0、除法实际1被杀死，乘法实际4存活，得分2/3。添加(0,3)→3，乘法变异实际0被杀死，得分3/3。强化示例还包含(−2,1)→−1。

选择product并载入最小示例(2,2)→4：加法变异4存活，减法0、除法1被杀死，2/3。强化示例包含(0,3)→0和(−1,3)→−3，杀死加法变异，3/3。

sum测试(0,0)→0时原函数通过；除法变异0/0报告「非有限结果 NaN」并被杀死，加法改减法或乘法则仍为0而存活。它说明运行错误也是可观察证据，而不是被隐藏为空JSON数值。

组件渲染用本功能局部辅助展开节点数组并过滤空节点；事件测试验证原/新实现、具体杀死证据和存活标签在界面存在，没有对象字符串或null杂字。

上述是模型和轻量DOM事件验证，没有启动Electron或确认实际保存对话框；主代理负责真实窗口集成。局限为三个固定二元整数纯函数与比较/算术运算符变异，不编辑代码、不分析真实项目、不生成覆盖率、不自动证明其他变异等价，也不承诺满分意味着完整测试。
