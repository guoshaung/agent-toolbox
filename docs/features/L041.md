# L041 ABX听辨训练

## 1. 功能内容与需要解决的问题

用户选取本地参考A/B音频及1–8份X音频，**人工**为每份X指定A/B答案，固定种子安排四轮。每轮完整试听A和B，再听X、提交A/B判断，产生混淆矩阵、已作答准确率/混淆率、四题反应时、全部播放/暂停/失败/中断记录及人工耳机/环境声明。答案不由语音识别、文件hash匹配或音频内容猜测；标签真实性由材料提供者负责。

相近发音或声音的区别仅靠回忆容易混淆，本工具让用户用同一组已标材料和同一种子复现有限对照，保留每轮响应与试听状态。它是训练记录，不是听力诊断、音频设备测量、语言能力认证或科学盲测。用户自己上传/标素材，可能事先知道答案；工具不声称安全隐藏本地运行时答案。

首版仅PCM16 WAV，单/双声道、8–48kHz，不进行语音合成、转写、音量归一化或音频文件转换。只读源文件，不生成修改后的录音、不上传文件，不依赖AI或网络。验证中的合成正弦波是本机**测试夹具**，没有为用户合成语音的功能。

## 2. 实现方式、随机化与计时定义

`model.mjs`先检查RIFF/WAVE声明长度、chunk边界/数量、单一16字节PCM fmt、format=1/bits=16、1/2声道、采样率、byteRate/blockAlign、单一非空data及完整帧，再用原始文件ArrayBuffer计算SHA-256。全文件hash包含头和其他chunk，不是声学相似度。Browser AudioContext固定48kHz，用**复制**的ArrayBuffer调用真实decodeAudioData，检查输出声道/帧数/时长，再关闭临时Context。未成功检查和解码的文件不能进入训练；每次仅一个加载/解码过程，异步票据防止切走后迟到结果产生URL。

API依据：[W3C Web Audio decodeAudioData](https://www.w3.org/TR/webaudio/#dom-baseaudiocontext-decodeaudiodata)、[WHATWG HTML媒体播放](https://html.spec.whatwg.org/multipage/media.html#dom-media-play)。实际播放采用HTMLAudioElement和本地Blob URL，手动按钮调用play，观察playing/ended/error；没有autoplay属性、定时播放、音频队列自播或远程URL。每次新尝试使用新媒体元素/票据，旧元素迟到事件不会污染当前题。

种子为0–4294967295。PRNG是`state=(1664525*state+1013904223) mod 2^32`（Math.imul保证32位乘法），Fisher–Yates洗牌X池ID，每批取到四题为止；不足四份时重新洗下一批，超过四份只选该批前四份。种子、**有序X池**相同才有相同顺序，人工标签不参与猜测。默认seed41、池顺序X1/X2，安排为X2、X1、X1、X2。单份/单类X允许练习，但没有另一类的观察，不能推断双类辨别能力；A/B字节相同或标签错误也不会自动被“纠正”。

本轮A/B都需收到实际playing，再正常ended且currentTime/媒体duration与已验证时长一致，才记已完整试听。失败、未知时长、未playing的ended、中途停止或跳题都不新计“听过”；之前本轮已成功完成的参考试听仍保留。X按钮在A/B成功后可用。界面不提供进度拖动；发现seeking会拒绝该尝试。暂停可从当前位置继续，完整正常结束后才计完成，不因按过播放就计听过。

**反应时精确定义**：当前题最后一次X正常ended处理时的`performance.now()`记为`readyAtMs`并启用作答，提交按钮处理时记`respondedAtMs`，`reactionTimeMs=respondedAtMs-readyAtMs`。重听任意通道、暂停、切走均使**未作答题**旧起点失效；重新完整听X才重新开始。已经提交题的两个原始时间点/差值不可改写，切题不清它们。此值包含允许作答后的用户响应和UI事件调度，排除前面播放长度；不是“从开始播放X算起”，也不是硬件声学延迟或实际听见的测量。performance是本页面单调时间基准，ISO壁钟仅标开始/结束/导出，不能拿不同重载页面的原始performance值直接比较。

## 3. 使用步骤、容量与保存范围

1. 打开L041。填写固定种子、耳机/扬声器/未知声明、可选设备环境说明及0–1音量，先将设备音量调低；默认播放音量0.35。耳机使用无法自动核验，声明不作硬件证据，音量0也不能凭软件事件证明听见。
2. 为参考A/B和至少一份X分别选择本地PCM16 WAV，等待“已检查并解码成功”。每个位置选择一个文件；每个X明确选择人工答案A/B。没有自动带声音的示例，也不根据文件名推断标签。加载/解码没有播放。
3. 点击“开始固定种子四轮”。本训练的素材、标签、种子、音量和设备声明锁定，当前X不会显示文件名/标签，进行中不预览或导出答案安排。设置和素材之后的编辑不会回写本次已经开始的快照。
4. 手动播放本轮A和B（两者先后不限），可暂停后继续。完整结束后播放X，X正常结束才启用“判断X是A/B”。可重听，重听会重置作答起点。提交一次后记录冻结并显示正确/错误和反应时，不能回改。
5. 点击“下一题（不播放）”进入下一题，没有自播。可显式跳过，记录未作答并停止正在播放；“结束当前训练并生成未完成报告”保留已发生的响应/播放事件，余题仍pending，不伪称全部完成。四题处理完或显式结束后才显示完整报告，包含全部人工素材标签。
6. 预览、导出JSON/Markdown新副本。完成后可修改素材/设置并明确“开始新的四轮（替换上一报告）”；新开始会替换当前内存报告，请先导出要保留的记录。关闭前未导出的报告不会自动恢复。

输入容量明确：文件名≤120 Unicode码点；每文件44字节至6MiB、>0且≤30秒；A/B+全部X≤12MiB且≤120秒，≤8个X/10文件。RIFF长度必须匹配实际长度，最多64个chunk，不支持压缩/float/extensible WAV、MP3或多data块。单次解码≤144万帧/最多双声道、48k输出（Float32 PCM约11.52MiB）；临时解码Context关闭且不长期存解码PCM。当前编码素材总量和临时单文件读取均有上限，浏览器内部媒体开销不宣称精确内存占用。替换失败保留先前已验证素材并显示其完整文件名，不把失败文件当可用。

整次训练≤32播放尝试，每次≤4暂停；超限明确拒绝新增，不截断旧记录，可以结束生成未完成报告。原速媒体播放长度理论≤32×30=960秒，人工暂停/等待的墙钟时间未设倒计时，也不声称总会话在960秒内结束。种子格式有限；设备说明≤120码点；设置JSON整体≤64KiB。用户文本使用textContent/安全Markdown编码，文件名不会作为脚本、HTML或保存路径执行。

配置`features.L041.settings`严格schemaVersion=1，只含`seed/headphones/device/volume`，没有音频字节/base64/Blob URL、文件名/hash、X标签、题目或报告。恢复只恢复设置，必须重新选文件和标答案，不自播。保存同一config对象通道至多一进行中写入和一最新待写，按序完成并对旧回调票据检查；非法新设置的提示不会被旧写入完成抹掉。失败提示未确认保存，字段/64KiB超限不写部分设置。

切走停播、卸载媒体src并清未答起点，训练暂停；返回及“恢复训练（不播放）”都不播放，之后须手动重新听X。正在解码的票据失效、Context关闭；销毁卸载播放器、关闭Context、撤销全部Blob URL并清DOM。迟到playing/ended/decode/导出回调不复活界面。无轮询定时器、自动下一段、麦克风、音频捕获或网络请求。

## 4. 产出与可复现具体例子

完整JSON包括设置快照和人工设备声明、开始/结束时间、原素材名称/大小/采样率/声道/帧数/原字节hash/解码验证、全部X人工标签、有序四题、response/readyAtMs/respondedAtMs/reactionTimeMs、每题状态/正确性、全部播放尝试和暂停/中断原因、混淆矩阵/准确率/混淆率及解释边界。Markdown含相同完整对象，用户HTML作编码、代码围栏安全。报告不带音频字节、路径或Blob URL，但包含原始文件名和人工标签，应选择合适保存位置。

混淆矩阵行是真实**人工标签**A/B，列是用户回答A/B；混淆率=错误/已作答，准确率=正确/已作答。跳过/未答不入分母，反应时为null；零作答时准确率/混淆率/平均反应时是null（未定义），不是0%或合格。四题都答且都正确另有`completeFourAllCorrect`，不能用3/3的100%称四题全部正确。平均反应时仅用已作答。四题样本不作置信区间或推广能力判断。

### 固定四轮可控素材

可用自己的两类短录音，分别导出PCM16 WAV，将已标类别A/B的X逐个指定。为复现工程验证而不依赖发音，可以在新文件夹生成0.18秒、8kHz单声道的低幅正弦波A440Hz、B660Hz，并复制A为X1、B为X2。下面脚本使用Node内置模块；只用于生成测试夹具，不是本工具的语音合成能力：

```js
const fs=require('node:fs');
const folder='L041-fixture-'+Date.now();fs.mkdirSync(folder);
function wave(freq){
  const rate=8000,frames=1440,b=Buffer.alloc(44+frames*2);
  b.write('RIFF');b.writeUInt32LE(b.length-8,4);b.write('WAVE',8);
  b.write('fmt ',12);b.writeUInt32LE(16,16);b.writeUInt16LE(1,20);
  b.writeUInt16LE(1,22);b.writeUInt32LE(rate,24);b.writeUInt32LE(rate*2,28);
  b.writeUInt16LE(2,32);b.writeUInt16LE(16,34);b.write('data',36);
  b.writeUInt32LE(frames*2,40);
  for(let i=0;i<frames;i++)b.writeInt16LE(Math.round(900*Math.sin(2*Math.PI*freq*i/rate)),44+i*2);
  return b;
}
for(const [id,freq] of [['A',440],['B',660],['X1',440],['X2',660]])
  fs.writeFileSync(folder+'/'+id+'.wav',wave(freq),{flag:'wx'});
console.log(folder);
```

选择这4文件，人工X1=A、X2=B，seed=41，耳机/设备声明如实填写。四题顺序X2/X1/X1/X2；每题A/B/X完整结束后，按B/A/A/B提交。得到准确率100%、混淆率0%、4条非负反应时、矩阵真A→答A2、真B→答B2，其余0。暂停/继续A仍属一次播放尝试；重听X增加一次尝试并以新ended重新计时。hash在整次训练前后与原文件一致，不把X和参考同hash当作自动答案来源。

模型手算计时：A尝试t0、playing=1、ended=41；B在100/101/141；X在200/201/241，350提交，RT=109ms。重听A在300/301/341会清掉旧readyAt，350不能作答；再听X在400/401/441，550提交，仍为109ms。切到下一题后，已提交题保留241/350或441/550原点和值。若仅跳过一题后结束，已答0、跳过1、准确率null、completeFourAllCorrect=false，不会伪称100%。

## 6. 限制与适用边界

仅验证材料的有限WAV结构、解码和软件播放过程，不能确认人是否认真听、耳机是否连接、设备音量是否足够、真实声学延迟或标签是否正确。相同字节A/B、错误X标签、单类X或事先知道答案都可能令训练缺乏感知区分意义；工具保留人工标签并按它计分，不用hash猜标签或声称识别了语音内容。

四题是短练习，准确率/混淆率不证明稳定辨音能力，没有信号检测指标、统计显著性/置信区间、双盲安排、临床听力分析或自动评分纠正。反应时依赖UI调度及浏览器performance精度，不做跨设备校准，后台切走会中断起点，无法当硬件延迟比较。音量固定训练快照，不动态增益或校准。

不支持MP3、压缩WAV、float/extensible WAV、网络音频、实时录制、语音合成或转写；需要相应格式者应准备明确PCM16输入。没有音频永久存储或训练历史数据库，报告要手动导出，关闭需重选材料。导出包含全部原名称/标签/错误/中断记录，未完成状态和null指标不会被删成“全对”。所有反馈依据提供材料与软件观察范围，不推断真实语言/听觉能力。
