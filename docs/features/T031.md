# T031 图片批量交付规格

## 1. 功能内容与必要性

本地一次选择1–20个静态PNG/JPEG/WebP，设置统一宽高、居中裁切或整图留白、底色、格式和单图体积上限。顺序处理并有限尝试质量；完整展示成功副本和失败原因，逐张预览成功项后交付一个新目录，附完整JSON报告。原图只读，关闭网络也能完成，没有AI或外部运行时。

多个平台要求不同尺寸/体积，逐张操作容易混入错误尺寸、暗降分辨率或漏掉失败图。此功能保留固定目标尺寸，失败不冒充成功；报告把源文件、摘要、转换选区、每次尝试和实际副本关联起来。同名源图不互相覆盖，完整交付预算与单图体积约束分别判断。

## 2. 实现方式与明确规则

`model.mjs`使用File API、createImageBitmap、Canvas、WebCrypto，`raster.mjs`进行有界预检查，`index.js`用现有`h()`实现实际控件。PNG/JPEG有限预检查源于本作者E016的本地片段，代码复制在T031内，不引用E016运行时。目录规格原列“图像处理与编码库（待选型）”，首版选用内置浏览器解码/Canvas编码能力，未新增package或共享接口。

选择集合最多20项、声明总字节≤30MiB，整体超限在读取前拒绝。单图1字节至5MiB、单边≤8192、≤2400万像素；集合内单图超限作为失败，不读取字节、源SHA为null并注明“未读取”。有效读入后计算原字节SHA，即使格式损坏也可留下已读摘要。读取失败、字节与File.size不符、预检查失败、原生解码失败均逐项记录，后续图继续；取消是整批废弃，不把未处理项目说成失败或保存部分结果。

PNG检查签名、全部块长度/CRC、单一首IHDR、数据/结束和尺寸，拒APNG及16bit；JPEG检查完整标记边界、单SOF/单EOI、8bit灰度/RGB基线或渐进帧，拒多帧、DNL延后尺寸和CMYK。WebP检查RIFF总长/块界限/零填充、VP8关键帧或VP8L版本尺寸、VP8X保留位/画布一致性，拒动画、多帧或矛盾尺寸。先预检查再解码；二次实际尺寸必须匹配头部像素总量，可宽高互换以允许EXIF旋转。拒SVG/HTML/GIF和外链，不执行文件正文、不访问任何网络资源。未知压缩损坏仍由原生decoder拒绝，有限预检查不声称覆盖整个格式标准或原生decoder全部内存峰值。

格式来源：[W3C PNG Third Edition](https://www.w3.org/TR/png-3/)、[ITU-T T.81 JPEG](https://www.w3.org/Graphics/JPEG/itu-t81.pdf)、[Google WebP Container Specification](https://developers.google.com/speed/webp/docs/riff_container)。WebP尺寸来自对应帧头，不能只信VP8X声称的小尺寸。

目标宽高为1–4096整数、最多16777216像素（包含3840×2160标准4K与4096方形，绝不后台改成较小尺寸）。可选PNG/JPEG/WebP，单图体积1–2097152字节。底色不透明`#rrggbb`，原图透明区域合成此底色；首版不输出透明留白。

留白：按最小宽高缩放比保留整图，目标内区宽高floor且至少1像素，居中整数放置；奇数剩余留白右/下多1px。整数像素量化可能带来不足1px的理想尺寸差，极细图保证至少1px，不声称完全连续几何等比例。裁切：按最大缩放比，在原图中心取浮点矩形裁切，铺满目标；边缘可能被切掉，报告保留sx/sy/sw/sh及dx/dy/dw/dh。无手动任意选区首版，没有用体积约束改变裁切策略、目标宽高或自动压缩源文件。

PNG只编码一次，无质量参数。JPEG/WebP最小/最大质量0–100，候选为`max-round((max-min)*i/5)`（i=0…5）降序去重，至多6次，两者相等只有1次。首次实际编码大小≤上限才成功；不假定质量与字节数单调，不宣称最低文件体积、最优编码或搜索全部质量。所有候选都超上限则明确失败，分辨率不变。Canvas回退成其他格式、空Blob或输出帧头尺寸不符也失败，不改扩展名掩盖格式。PNG无损，JPEG/WebP为Canvas对应有损编码；不保留EXIF/ICC等源元数据，不承诺跨浏览器颜色或编码字节一致。

每次只有一个源bitmap和处理canvas；处理完close/归零。最多缓存20个成功输出、每个≤2MiB，源集合≤30MiB。精确内存峰值和浏览器decoder内部不在此承诺。处理间和质量尝试间短yield，File读取/解码/编码异步；取消、隐藏、deactivate使代数失效，旧bitmap晚到会close，晚结果不绘制、不写出。底层原生调用不能强制终止，旧操作结束前控件继续锁定。无常驻RAF/定时器；destroy移除事件、清Canvas和模块引用。已有原生保存操作不可撤回已写出的副本，但旧回执不会复活旧界面。

## 3. 如何使用

1. 在“本地批量图片”多选来源，核对源文件列表与顺序。文件名同名也可，实际帧头决定类型，扩展名不作为唯一判断。
2. 设置目标宽高、整图留白或居中裁切、PNG/JPEG/WebP、背景色及字节上限。默认512方形留白、白底、PNG、204800字节（200KiB）；JPEG/WebP默认质量50–90，PNG时质量控件禁用。
3. 点“开始批量处理”，查看进度。点“取消整批处理”将废弃整个未完成结果；等待底层操作结束后可重新处理。
4. 核对全部成功/失败结果；每个成功项点“完整预览001/002…”看实际已编码交付字节。完整画布保留实际目标分辨率，CSS按比例显示整张，不只显示顶部。旁边显示副本路径、尺寸、实际字节数、SHA和源名。展开完整报告核对全部尝试及失败。
5. 勾选已核对完整报告与全部成功图片，点“交付完整新目录”，在原生保存对话框输入一个尚不存在的目录名称。

未逐张预览成功图、未确认或桥缺安全能力，交付按钮禁用。任意输入或来源变化都会清空整批旧结果、画布与确认，必须重新处理；不会偷偷导出旧规格。隐藏/离开返回不会自动处理、自动写目录，已完成结果仍需重新预览确认。所有输入和按钮可用标准Tab/键盘操作。

大图片、输出和完整报告不进config，也不自动存工程。切换到其他功能会销毁未交付内存，返回需重新选择原图与规格；已交付目录和report.json可保留规格与审核记录，首版没有报告导入重建源图的承诺。

## 4. 产出与副本保障

新目录包含`images/001.png`或`.jpg/.webp`等全部成功副本及`report.json`。编号对应原来源顺序，失败编号留空，不重新排号错配。原文件名只在报告中，目录使用固定安全ASCII相对路径，避免同名、路径字符、大小写/NFC等冲突。没有原图副本，也没有失败图片的空文件。

完整报告schema1记录全部来源原名/字节/已读SHA、识别和实际解码尺寸、status/error、全部尝试质量与字节数、成功输出路径/类型/尺寸/大小/SHA/选用质量/几何选区；含统一设置、限额、口径及精确成功/失败计数。全失败时仍能明确确认后交付仅report.json的新目录。

公共`files.exportBundleSupportsCopyOnly===true`是硬条件。交付前重新核验成功字节SHA、实际格式/尺寸、单图上限和报告计数。`copyOnly:true`包带每文件规范Base64/SHA，调用生产`exportBundle`，writer再次核验后仅创建新目录；已存在文件或目录拒绝。只有`ok===true`报告成功；取消、错误和partialPath分别显示。原图不调用写入器、不改字节。源只读不等于源文件被锁定，若别的应用同时改源不在此保证。

每个文件（含report）≤2MiB，全部成功图+完整UTF8报告≤10MiB、最多21个文件。报告大小计入预算；任何完整预算超限整批禁止交付，成功项仍完整显示，不能默默丢掉一些成功项以凑预算。可以明确减少来源数量/单图体积上限或更改格式后重新处理，不会后台降低目标分辨率。断电/进程崩溃不提供事务恢复保证，公共writer正常失败会清理本次新目录，清理异常会返回partialPath。

## 5. 具体可复现例子

选横图1024×512 PNG、竖图512×1024 JPEG、方图768×768 WebP，512×512留白、白底、PNG、200KiB上限。横图目标图像占x=0…511、y=128…383，上下各128px白边；竖图占x=128…383、y=0…511，左右各128px；方图铺满512。全部成功图片分别完整预览，确认后得到3张512PNG和完整报告，每张≤204800字节，源SHA不变。

原坐标色块768×512，选512方形“居中裁切”，选区为sx128/sy0/sw512/sh512，原坐标(x+128,y)映射至目标(x,y)。裁切用同样512分辨率，不为图像过大而改成256。

将单图上限改为1字节、格式JPEG、质量50–90，候选90/82/74/66/58/50全部无法达标：三项失败，共18次尝试，报告保留全部原因及尺寸512。可确认只保存report.json的新目录，无images文件和假成功。

14个512×512真实噪点PNG，PNG单图上限2MiB，每张成功约900KiB，合计超过10MiB。所有14项完整显示，逐张预览并确认后仍禁止交付，不会悄悄只交付前11张。界面给出实际总字节数；显式减少源数或改用有限质量的JPEG/WebP后重新处理即可。
