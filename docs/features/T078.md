# T078 字体与字符显示诊断

## 1. 功能内容

输入所需字体登记显示名称（每行一个，最多5个，可空）和字符样本，读取 Windows 当前用户及机器的 Fonts 注册记录，明确选择1–5个主字体/替代候选，检查这些字体文件的 Unicode 字符到字形映射。也可直接选择自己已有的本地 TTF/OTF 字体文件，读取前须点击检查按钮。结果含登记标识/允许路径、文件存在/可读状态、字节及 SHA、cmap 版本、每码点字形索引/缺字、已选替代字体的覆盖证据。

证据层次分开：登记存在不证明 CSS family、可用路径不证明文件有效，映射到非零字形不证明轮廓可渲染、复杂塑形或原文档排版正确。本功能不解析轮廓、不绘制字形，不把缺少验证说成字体渲染失败。glyphIndex 0 按 cmap 规范标记缺字；未支持字体格式为 unsupported，没有逐码点伪造“全缺字”。

## 2. 为什么需要

换电脑后文档可能选不到原字体，或指定字体缺少某些字符。把系统登记、原文件和字符映射证据放在一起，可以识别需要在目标文档软件进一步核对的字体和码点。替代建议只来自本次实际选中并成功解析的其他字体，不按字体名称、相似外观或所谓“中文字体”猜覆盖。

不下载、安装、注册或删除字体，不执行字体脚本、用户命令或外部应用，不修改字体配置、不结束进程。字体授权、浏览器/办公软件实际回退、字距、连字、双向排版和性能均不在诊断范围。

## 3. 实现方式与严格范围

登记查询经既有生产 Host 桥调用自己固定 host.cjs，Windows 支持域为 C:\Windows 系统 PowerShell。使用绝对系统可执行文件、-NoProfile/-NonInteractive、shell:false、隐藏进程，关闭模块自动加载，只导入绝对系统 Utility 模块；环境只有4个系统定位变量。固定脚本读取 HKCU/HKLM Registry64 的 Software\Microsoft\Windows NT\CurrentVersion\Fonts，OpenSubKey false，无写键 API。最多1000条登记、stdout+stderr共256KiB，超限/权限失败整份拒绝，不截断冒称完整。没有枚举Registry32、临时应用字体、其它系统或全部字体机制。非字符串注册值保留为不支持路径记录。

允许根仅 C:\Windows\Fonts 和系统查询的当前用户 LocalAppData\Microsoft\Windows\Fonts；允许本机确认的 DriveType.Fixed 盘。HKLM 的单文件名相对值解析到系统 Fonts 根，HKCU 相对值语义不确认，保留 unsupported。绝对值必须在允许根内；拒绝 UNC、网络盘、路径遍历、设备/ADS/保留名称、非NFC、路径前缀冒充、超过32段/1024字符。列表返回随机 opaque ID，选项只绑定同 sender、本次清单；不能从 renderer 提交任意路径，重新查询立即废弃旧 ID，取消或失败的刷新不能恢复旧选项。

读取前逐级 lstat 拒绝祖先/目标链接，打开只读句柄后比对 dev/ino/size/mtimeNs/ctimeNs；每64KiB一块，读满预期大小后重新比对句柄、路径和祖先。大小/身份变化拒绝输出覆盖。此为有界竞态检测，不是文件系统安全沙箱或原子快照：检查与打开之间仍可能被外部程序改动，不能声称 Windows 路径操作天然无 TOCTOU。

每文件最多8MiB，每批最多5个/累计预留16MiB；记录实际已读字节。预算15秒，固定子进程到期终止；FS调用/文件关闭不能硬中断，返回后检查取消和期限。每 sender 一项任务、全宿主最多4项活动任务和4个尚未close查询子进程，32 sender、128 jobID；在首个模型 import await 前登记任务/配额，提前取消意图不会丢失。文件句柄在 finally 关闭；取消/隐藏/暂停/销毁使晚结果失效，恢复不自动检查。没有在配置持久化源、字体字节或报告；清单只保存有限宿主选项，刷新/window销毁释放。

模型是本 ID 自研的有限解析器，取代设计中的“待选字形解析库”，没有新增运行时包。接受单 sfnt 的 0x00010000 TrueType 或 OTTO 容器；校验≤128张表的目录、唯一标签、4字节对齐、范围和重叠，maxp字形数量，Unicode cmap4/12结构。format4检查分段顺序、FFFF哨兵、idRangeOffset相对本字段的地址、idDelta和零字形语义；format12检查≤65536个有序不重叠组、Unicode范围和字形索引界限，优先采用12再4。遇到未支持 Unicode 映射、坏偏移/重叠/字形越界明确拒绝该字体。TTC/WOFF/WOFF2、Symbol/非Unicode、format13/14变体序列、GSUB/GPOS、glyf/loca/CFF轮廓、色彩字体、hinting、完整校验和/所有字体有效性均未解析或验证；报告明确 partial_table_validation_only / outlineEvidence not_parsed / renderEvidence not_tested。

样本≤128个不同Unicode标量、≤256 UTF-16码元/1024 UTF-8字节，不接受空样本、控制字符或不配对代理；逐码点检查，不把emoji序列/组合字素拆分结果当实际组合渲染证明。所需名称最多5行/256字符，登记显示名仅去除 TrueType/OpenType后忽略大小写精确匹配；“未在支持登记范围观察到”不证明系统一定没安装。FileAPI来源安装状态 not_queried。

官方格式依据：[OpenType sfnt](https://learn.microsoft.com/en-us/typography/opentype/spec/otff)、[cmap](https://learn.microsoft.com/en-us/typography/opentype/spec/cmap)、[maxp](https://learn.microsoft.com/en-us/typography/opentype/spec/maxp)。独立验收使用本机已存在的 Python/fontTools，仅开发测试工具，不导入产品、不新增依赖。

## 4. 如何使用

1. 填入登记名称，例如 Arial，样本 AB中😀。点击“读取 Windows 字体登记清单”；此时只查登记和允许路径，不读字体正文。
2. 在多选框明确选主字体和替代候选（Ctrl/Command多选），再点击“检查所选登记字体字符覆盖”。查看实际可用路径、文件状态、逐码点和未验证项。
3. 或在本地文件区选自己的TTF/OTF，不安装，点击“检查所选本地字体文件”。TTC等不支持文件会显示未知格式，而不是缺字列表。
4. 缺字旁的替代候选均有本次被选文件的非零cmap映射证据；没有候选即没有本次证据，不泛化到未选字体。到实际文档软件复核排版/字形。
5. 预览全部 JSON 或 MD 后保存新副本。依赖 saveTextSupportsCopyOnly，只有 ok===true 才成功；已有源/目标文件拒绝覆盖，取消/失败保留预览。修改样本、名称或选择使旧报告失效。清除/切换会丢失未保存输入和报告。

## 5. 使用后的产出

T078-font-diagnostic version1：字符样本及去重码点数量、所需登记匹配、所有所选字体的来源/路径/只读文件状态/字节/SHA/有限解析证据、每个缺字的已选替代候选、限制和实际读取统计。JSON和含相同完整JSON证据的MD，上限2MiB，不能截断。没有字体二进制、轮廓、系统配置正文或安装操作。

报告包含用户样本和本机字体路径，分享前核对。名字不是字体内部name表/family映射；覆盖并非文档可用性证明。源文件和系统配置不回写，登记路径不存在或不可读时保留 fileState/code，不自动修复。

## 6. 具体例子、验证和限制

已有 Windows Arial 登记时，输入 Arial、AB中😀，读取后选 Arial (TrueType)，再检查。该机器实测 Arial 文件 A/B 分别映射 glyph36/37，中和😀为0：这两码点标缺字，renderEvidence仍not_tested。其他Arial版本可能有不同覆盖，必须以本次文件SHA/索引为准，不能把本机结果当所有Arial的事实。

可重放开发例：自己的 ignored work/font-fixtures/fixture-A.ttf 只有A映射，fixture-B.ttf只有B映射。通过真实FileAPI同时选两文件、样本AB：A字体对B标缺字；B字体对B有glyph1证据，因此仅B文件被列为A字体的B替代。只选A文件时没有替代证据。两个文件都未安装，安装状态明确not_queried；真实原字体字节保持不变。
