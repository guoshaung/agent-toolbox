# E003 数字填图

## 1. 功能内容

20张自制像素谜题：10张5×5、10张10×10，包括爱心、松树、小屋、杯子、帆船、鱼、箭头、旗、钥匙、花、猫、伞、苹果、火箭、盆栽、城堡、山湖、星星等不同图案。按行列数字推理，涂格、标空、清除、撤销，必要时主动检查。正确填完当前图才结算完成进度；提供本地续玩、全部关卡进度表、JSON备份、Markdown记录和全幅PNG副本。

20张全部可选，不要求先解前题。支持鼠标左键、右键，以及键盘选格/操作。游戏全程离线，不随机生成新题，不读取设备，无计时器或动画循环。

## 2. 为什么需要

数字填图只需理解连续分组长度和组间留空即可开始，让用户用几分钟推理出一张小图。5×5便于入门，10×10提供多组提示和更多空间；格子、提示和工具都在同一棋盘旁，不要求粘贴JSON才能玩。

主动检查避免每次尝试都立即泄露答案，也避免把尚未填写的格子误算错误。撤销、当前局源步迹恢复和明确的副本保护便于暂停、修正或迁移进度。每局允许10000次改格，显著高于25/100格普通操作量，不以几十次的低上限打断游玩。

## 3. 实现方式与精确规则

`puzzles.mjs` 保存固定20张原始图案；`model.mjs` 计算行列提示、合法改格、胜利、冲突、撤销、版本化源步迹和完整记录；`index.js` 用现有h实现静态DOM网格与控件，PNG由本地Canvas绘制当前用户标记。没有用户HTML、外链资源、运行时代码输入或第三方依赖。

规则及口径：

- 数字表示连续涂格块的长度，按从左到右/从上到下排序，组间至少一个空格；提示0表示整行/列为空白。
- 状态0未定、1涂格、2标空。左键按当前工具切换涂格/标空（再次点击同状态回到0）；清除工具直接回到0。右键切换标空，不改变其他格。
- 胜利必须全部答案目标为涂格，同时没有额外涂错空白格。答案为空白的格可以保持0，也可标2，不要求全标叉。统计“未定”是尚未手动标记数量，即使通关也可以非零，不代表图案未解完。
- 只有“主动检查”标记错误：已涂了答案空白，或把答案目标标空。未定格不标错误，不将“无冲突”称为完成。下一次实际改格、撤销、重开、切关废弃旧检查；工具选择本身不改图案。检查结果不作为源数据持久化，重新打开需重新检查。
- 成功改变一个格计一次改格，清除本来空白等无变化操作不计。撤销恢复前一个单格状态，源迹和操作数一起回退。全部目标正确后本局冻结填涂和撤销，完成记录仅按不同关卡计一次；重开/切关继续玩，不重复增加已完成数。
- 棋盘焦点内方向键选格，左右不会跨行，边界停留；空格/Enter按当前工具操作，F/X/C选工具，按住重复涂格事件忽略。自动保存完成后恢复当前格焦点，可连续纯键盘玩，不要求每次重新鼠标点击。

进度保存于ctx.config的 `featureLab.E003.progress`，schema1仅含 puzzleId、源trace、completed。trace每次改格为“两位小写base36格索引+0/1/2状态”，最多10000条/30000字符；恢复从空棋盘按序重放，不直接信任用户提供的格子数组、胜利标记或图像。拒绝未知关卡、未来版本、未知/缺失字段、索引越界、非规范源迹、无变化记录、完成后的追加记录、重复/未知完成编号、完成图却无对应完成记录。完成编号是本机进度，不是成绩认证或防作弊记录。

自动档和导入/导出JSON最多65536 UTF-8字节，10000条源迹完整往返仍在限内。导入严格UTF-8，JSON深度≤6，每对象≤8字段，数组≤20；重复键（包括转义后的重复）、不安全整数、小数/指数、尾随垃圾拒绝。不截断。无效自动档保持原值，只有勾选确认重新建立进度或明确确认有效备份才覆盖；保存失败提示当前临时保留、另存JSON或重试，不把公共Config的内存缓存当作成功落盘证明。

每次改格/撤销/切关/重开自动保存当前一个局及20张完成记录；切关重开所选图，不保留20个同时进行的草稿，界面明确说明。保存/导出期间锁定改格。异步读取取消或离开只使旧结果失效，不声称终止底层读取；暂停/隐藏禁止操作，返回保持图案不自动涂，销毁释放全部监听与PNG画布。PNG源变化、离开/销毁后旧编码/保存回调不能重建界面；临时Canvas清零宽高并移除引用。

“唯一解”的独立oracle：枚举长度5/10所有二进制行候选（最多1024），按独立连续段计数筛行/列候选，逐行搜索并约束每列前缀，完整搜索确认恰好1个解。该搜索不调用生产runs/compile/paint/matches；同时以已知2×2双解题证明能识别第二解，以及全空2×2单解校准。所有20题唯一解与原图逐格一致，行列提示也与独立计算一致。运行时不求解、不统计估计唯一性，不主张“最少操作次数”。

## 4. 使用步骤与具体例子

1. 打开“娱乐 → 独立休闲游戏 → 数字填图”，选择N01小爱心。按行/列提示涂格；想确定空白，可用“标空”或右键。清除回到未定。
2. 对N01故意涂第1行第1列，再右键标空第1行第2列；点击“主动检查当前标记”，只红框这两格，显示2个明确冲突。其余23个未定格没有红框。
3. 点击“撤销一次改格”，第1行第2列回到未定，只保留第1格已涂；旧检查废弃。退出/重新打开恢复同一局，可以继续。
4. 改正第1格，按下图涂所有#，其他格不必全标空：正确填16个目标即完成N01；再次点击已冻结格不会重复结算。可重开或下一张。
5. 另存PNG保留当前可见图案和全部提示；JSON可恢复当前局及完成记录，Markdown记录完整20关进度。导入JSON先预览关卡/操作数，再勾选确认替换后应用。

N01唯一解（#涂格，.空白）：

```text
.#.#.
#####
#####
.###.
..#..
```

行提示为 `1 1 / 5 / 5 / 3 / 1`，列提示为 `2 / 4 / 4 / 4 / 2`。任何额外涂格阻止通关；把任意目标标叉也阻止通关。

可导入的两次错误尝试源数据：

```json
{"schema":1,"puzzleId":"N01","trace":"001012","completed":[]}
```

恢复第1行第1列涂格、第1行第2列标空，2次改格，尚未主动检查；点击检查精确得到这两格冲突。trace为 `000`（初始无变化清除）、`zz1`（索引越界）或未知schema2会拒绝。

## 5. 使用后产出

自动档和 `nonogram-progress-copy.json` 保存完整源迹及所有完成编号，恢复会重新计算各格、操作数和胜利。Markdown `nonogram-records-copy.md` 包含当前可见标记全文网格、行列提示、主动检查状态/坐标及全部20关记录；不会另附尚未涂出的答案。

PNG为 `nonogram-Nxx-draft-copy.png` 或 `nonogram-Nxx-complete-copy.png`，包括完整5×5/10×10当前网格、全部行列数字、标题、操作数和标记说明，主动检查的红框可随当前草稿导出。自适应有限尺寸小于900×900，按PNG实际字节预算≤10MiB，超过拒绝，不裁掉底部或截断提示。程序Canvas绘图，无远程素材。

文本先检查saveTextSupportsCopyOnly，PNG先检查saveBinarySupportsCopyOnly；都用copyOnly:true并严格ok===true。PNG提交规范Base64及浏览器SHA-256，生产二进制桥重新核验摘要/容量并wx独占写新文件。已有目标拒绝，取消/失败/partialPath如实显示，导入来源和旧副本不覆盖。旧基础缺能力禁用对应导出，PNG依赖a80e115已包含的二进制副本基础接口。
