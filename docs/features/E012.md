# E012 鼓点编排

## 1. 功能内容与必要性

从空小节开始，用四行16个开关编出自己的鼓点，试听循环后保存一小节WAV、完整节奏工程和可读节奏图。底鼓、军鼓、踩镲、拍手全部由本项目程序合成，既不下载音色，也不调用AI、TTS、麦克风或网络。适合短节奏练习和分享；现有语音/白噪音页面不能编辑鼓点序列。

对应 `entertainment.json` E012：四轨16步、速度/音量、WebAudio合成循环、摆动、一小节WAV与工程。120 BPM导出2秒，静音轨不进入音频。增加完整PNG和Markdown便于查看/记录，但不增加音频格式、音色插件或多小节编辑。

## 2. 实现方式与规则

`model.mjs` 纯本地合成与工程校验，`index.js` 通过现有 `h()` 创建64个真实按钮和参数控件。4/4小节，四个四分拍，每拍四个十六分步。BPM为40–240整数，四轨/总音量0–100整数，摆动0–50整数百分比；全范围均可操作，没有按开启格数量截断。

步编号界面1起，源码0起。源码偶数步起点固定；奇数步延迟 `60/BPM/4 × swing/100`。50%摆动使相邻两步间隔3:1，0%等距；小节总时长不变。采样起点用安全整数分子 `15×44100×(100×step+oddSwing)/(100×BPM)` 四舍五入，避免浮点半帧差异。帧数 `round(240×44100/BPM)`，120 BPM为88,200帧，96 BPM为110,250帧；其他BPM相对理想时长最多半个采样帧误差。

底鼓是下降频率正弦及衰减包络，军鼓是180Hz正弦与高频噪声，踩镲是短高频噪声，拍手是三个间隔12ms的噪声包络。命中时长分别420/240/75/220ms，有短攻击/结束淡化。噪声为确定性xorshift32，工程固定保存种子（默认27358）；不主张密码学随机或采样器真实鼓录音。每次相同工程重算相同音频，导出不依赖音频设备。

先累加 `单轨volume/100 × 总volume/100 ÷ 4` 的合成样本，静音/零轨音量/零总音量完全不参与混合，不按剩余轨重新归一化；最终硬限幅±0.95并量化PCM16。接近小节结尾的尾音按采样帧取模叠到开头，导出表示循环稳定状态，不是带额外衰减尾巴的单次录音。WAV固定44.1kHz单声道、16位小端PCM、RIFF fmt/data块，最大40 BPM=264,600帧=529,244字节。

用户点击播放才创建/恢复 `AudioContext`，PCM除32768写入 `AudioBuffer`，一个 `AudioBufferSourceNode` 通过 `loop` 重复整个小节。音频由WebAudio播放，60ms计时器只更新步高亮，绝不依赖JS定时器触发每个鼓点。修改开关或参数立即停播，点击播放听新版本；停止后再次开始从头。停止/隐藏/离开/销毁立即停节点、断连接、清音频缓冲引用、关闭上下文、清计时器；返回/重载不自动发声。尚未完成的resume返回也不能重启旧节点。

实现依据：[W3C Web Audio Recommendation 的 AudioBufferSourceNode/循环章节](https://www.w3.org/TR/2021/REC-webaudio-20210617/#AudioBufferSourceNode)、[MDN AudioContext.resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume)、[Microsoft RIFF格式说明](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-)。未使用新的依赖包、音色资源或其他feature运行时实现。

## 3. 如何使用与恢复

1. 在功能工作台选择“娱乐 / 创作与音乐玩具 / 鼓点编排”，初始为空小节且不播放。
2. 点击任一音轨的1–16步开关。每四格为一拍，彩色格是开启。每行可设置音量并勾静音，静音保留步骤，试听/导出不发该轨声音。
3. 可Tab聚焦步骤按钮、空格/Enter开关；方向键在四轨/16步之间移动，边界不绕行。数字输入可键盘改变BPM/摆动/音量，失焦/change确认，非法/空值显示原因且保留旧参数。绘图只是完整预览，编辑使用上述控件。
4. 点击“播放循环鼓点”；音频不可用/启动失败会显示原因，可继续编辑及导出WAV。先用低音量；“停止播放”会从头重置试听。编辑任何参数停播，需要再点播放。
5. 每次提交编辑自动通过 `featureLab.E012.project` 保存完整工程，成功状态明确显示；配置失败显示临时保留，可“重试本地保存”或导出备份。离开不会改变工程，没有后台音频。新建空节奏需确认勾选，清空全部步骤/参数并重置种子。
6. 工程JSON用File API读取，≤64KiB、严格UTF-8，拒绝重复JSON键、未知/不完整字段、未来版本、非布尔步骤、非安全整数及非法参数。文件先校验显示四轨/BPM/摆动预览，必须勾确认再替换全部工程；无效旧档不会默默覆盖，只能确认清空或导入。重载恢复全部64格及参数，始终处于停止状态。

schema1源字段只包含 `schema,bpm,swing,volume,seed,tracks`；tracks固定四项，每项只有16个布尔steps、0–100整数volume与布尔mute。不保存音频上下文、已混合PCM、计时器、图片或DOM；无播放历史/撤销栈，不声称恢复试听位置。正常最大项目远低于64KiB，超限整体拒绝不截断。

## 4. 产出与安全副本

- JSON：完整可恢复源工程，所有64步和参数齐全。
- Markdown：全部64步的开启/静音/音量/采样起点表、时长和摆动/尾音/混音规则，附完整源JSON。
- WAV：当前四轨静音/音量生效的一小节混音，固定44.1kHz单声道PCM16。空工程/全静音/总音量0合法导出静音小节。
- PNG：原生Canvas绘制960×420完整节奏图，四轨64格、各轨音量/静音、BPM/摆动/总音量/时长和图例；不是音频波形或可恢复工程。开启静音格灰色，关闭格浅色。没有AI生成位图或外链图片。

保存前检查安全能力，文本 `saveTextSupportsCopyOnly===true`，二进制 `saveBinarySupportsCopyOnly===true`；均使用copyOnly。PNG/WAV计算规范Base64/SHA-256，二进制≤10MiB，原生独占wx新建，已有目标拒绝且不覆盖。取消不报成功，`ok===true` 才成功，partialPath会要求人工核对。老应用缺能力时禁用相关按钮并解释。

导出冻结一个完整版本并停止试听；准备PNG/摘要期间离开/隐藏会使旧结果失效，未调用保存桥就不再写入。原生保存已开始不能撤回，返回页面后保持锁定直到完成，旧回调不会声称新版本已保存，完成后控件恢复可用。销毁释放界面/事件/计时器；不承诺终止浏览器底层PNG编码或撤销已写副本。

## 5. 可重现例子

**两秒及静音验收**：新建空工程（确认），保持120 BPM、摆动0、总音量65、底鼓80。点“底鼓第1步”；点“军鼓第5步”再勾“军鼓静音”。点击播放可以看步高亮，停止后另存一小节WAV。该文件176,444字节，头44字节，88,200个16位样本，时长正好2秒，内容与只有底鼓第1步的版本完全相同；取消军鼓静音再另存新名称后音频会变化。重载后这两格和静音设置仍保留，不会自动播放。

**完整节奏图**：底鼓1/5/9/13、军鼓5/13（保持静音）、踩镲1/3/5/7/9/11/13/15、拍手5/13，共16格开启。设96 BPM、摆动30%、总音量70、踩镲音量55，其他轨80。PNG完整四行，底鼓四个红格、军鼓两个灰格、踩镲八个绿格、拍手两个黄格；标题显示2.50000秒小节。JSON恢复以上所有设置；Markdown包含完整64行与源JSON。

**摆动例**：120 BPM、摆动50，前四步0起采样帧 `[0,8269,11025,19294]`；只启底鼓第2步时，0–8268帧全零，8269是攻击起点零样本，随后非零；其16步小节仍2秒。最后一步底鼓的尾音可在小节起头听见/观察到，这是明确的循环尾音策略。
