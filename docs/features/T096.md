# T096 日历事件迁移校验

## 1. 功能内容

本地读取单个严格 UTF-8 ICS 或粘贴日历文本，解析一个 VCALENDAR 中的 VEVENT，区分 UTC、带 TZID 的当地时间、floating 无时区时间和 DATE 全天日期。保留 UID、重复/例外属性、完整 VTIMEZONE、参数、未知属性及嵌套组件，核对 UID 重复和内容冲突，输出完整 ICS 新副本与 JSON 校验报告。没有云日历、账号、网络请求、AI 或第三方新增依赖。

默认“保留原时间语义”不推断偏移、不展开重复排期，只规范内容行折行和 CRLF。完全相同整条 VEVENT 的重复需要用户选择保留 ID、明确确认；同 UID 不同内容全部保留，含 RECURRENCE-ID 时提示可能为合法系列实例或更新，不能简单当成多余记录。未知或复杂规则的原样副本不承诺目标日历导入效果。

额外提供有限、可验证的单次时区转换：2000–2035 年内 UTC ↔ Asia/Shanghai / Asia/Tokyo，要求匹配的固定偏移 VTIMEZONE 和当前 Intl 数据一致。DATE、floating、RRULE/RDATE/EXDATE/RECURRENCE-ID、提醒、DURATION、METHOD、其他 TZID 或 DST 时间不在转换范围，明确阻止整次改写，不静默补时区或删除规则。

## 2. 为什么需要

迁移时常见的问题是 UID 重复、同 UID 内容更新，以及把无时区时间错误当成 UTC/当地时间。重复事件还可能依赖 EXDATE、RDATE 和时区观测规则；只复制标题/开始时间会丢失系列语义。

完整保留加上有限校验能在迁移前看见差异，而无需伪造一套完整调度器。确认去重只删除完全相同的物理事件记录；它与重复规则产生的实例去重不同。明确的时间类型和转换范围避免给 DATE 或 floating 强配地区。完整预览和独占副本写入保护原文件，供用户在自己的日历客户端另行核对导入结果。

## 3. 实现方式

- 元数据沿用“工具 / 隐私与数据迁移”，`index.js` 默认同步 `create(root)` 返回 `activate/deactivate/destroy`。真实交互使用公共 `h()`；样式只匹配 `.feature-t096`。`model.mjs` 为独立有限解析/生成/校验模型，`examples.mjs` 保存可复现夹具；未引用其他未合并功能，也未改 main/preload 或共享样式。
- 官方依据为 [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545)：§3.1 内容行/折叠、§3.2.19 TZID、§3.3.4–5 DATE/DATE-TIME、§3.3.10–11 RECUR/TEXT、§3.6.1 VEVENT、§3.6.5 VTIMEZONE。只实现本文声明的校验范围，不宣称完整 RFC 验证。TZID 不适用于 DATE 或 UTC；无 TZID 的当地时间保持 floating；DTEND 是不包含的结束边界，全天日期不自动改成当天 23:59。
- 输入按物理行展开空格/制表符折叠，记录起止行。参数解析识别引号中的冒号/分号，保存完整原参数及值；已知 TEXT 只做安全展示解码，生成时使用原始属性，不重新编码重复规则或未知值。Unicode 生成按最多 75 UTF-8 字节折行，使用 CRLF。输入 LF 会记录规范化审计。原属性顺序保留，BEGIN/END 组件名规范大写；空内容行（末尾一个换行除外）和不完整语法明确拒绝，不悄悄丢掉。
- 用组件树检查一个 VCALENDAR 根、匹配 BEGIN/END、VEVENT/VTIMEZONE 的直接父组件、VALARM 和 STANDARD/DAYLIGHT 的父组件关系。VERSION 须唯一为 2.0，PRODID 须唯一非空；范围外组件及属性原样保留并报告，不自动删除 VTODO、VALARM 或时区规则。UID、DTSTART、DTSTAMP 缺失/重复或日期参数错误进入审计，只保留原值，阻止转换。缺少 UID 不参与重复判定。
- UTC 带 Z，TZID 引用保留原 ID 且要求匹配唯一 VTIMEZONE；floating 不转换为具体瞬间；DATE 按日期验证，保留结束日期不包含的语义。内部墙钟校验标量不会作为 UTC 瞬间写进报告。日期不支持的闰秒/数值偏移/分数秒、无效日及 UTC 搭配 TZID 均审计并阻止改写；原样副本仍保留错误属性，不能据此声称原文件合规。
- 以完整展开组件内容比较“完全相同”，包括 UID、DTSTAMP、属性顺序、参数和嵌套组件。仅折叠形式不同可判同组；属性顺序或参数不同保守判不同内容。UID 相同但内容不同生成冲突/系列组，没有覆盖或删除按钮。确认相同组时保留用户指定的组成员，移除其余完整副本；判定须当前组/当前 ID，重复判定或任意 ID 明确拒绝。新输入废弃旧判定。
- RRULE、RDATE、EXDATE、RECURRENCE-ID 均完整保存并在报告中列出，包含本 MVP 不理解的规则也不会被改写/删除。不会验证全部 RECUR 组合、展开次数、实例日期、DST 例外或判断真实空闲时间。完全相同整条记录的显式去重不修改其内部重复规则，复查仍具有相同 UID 和规则。
- 转换仅检查并改写单次 DTSTART/DTEND。日期在 2000–2035，源类型限 UTC 或两种支持的 TZID；TZID 必须有唯一同名 VTIMEZONE，内含一个 STANDARD，无 RRULE/RDATE/DAYLIGHT 等复杂观测，固定 FROM/TO 与上海 +0800 或东京 +0900 一致，观测开始不晚于事件。使用当前 Intl.formatToParts 核对具体事件瞬间的偏移，不一致或缺支持立即失败。UTC 转 IANA 时新增合法固定 VTIMEZONE；已有及源 VTIMEZONE 从不移除。TZID→不同 TZID 不直接转换，可先审阅 UTC 副本再另行转换。DST、纽约/伦敦等其他时区以及歧义/不存在的当地时间都明确不支持，不选择“较早/较晚”偏移。时区法规和数据库不由本功能更新；范围外时间保留原语义。
- 任何保留事件含重复/例外、提醒、DURATION、校验问题或范围外时间参数时，整次转换失败，不输出部分已改写副本；METHOD 或非事件组件也阻止转换。复制模式完整保留它们。未知属性继续保留原语义，转换报告逐项给出已修改 DTSTART/DTEND 的前后原行；未实际改变的属性不虚报修改数。
- 限额为输入 1 MiB、20000 物理行、1000 事件、3000 组件、8 层嵌套、每组件 200 属性、展开行 65536 字符，ICS 和报告每种最多 4 MiB。超限明确失败，无静默截断；可以拆成独立批次。没有无限历史或全局配置存储。
- 异步 UID 分组每 50 事件让出事件循环，可取消；任务结束前不允许另一个任务叠加。编辑、清除、隐藏、暂停和销毁都令旧回调失效；File 读取或保存返回不能恢复旧源文本/结果。已完成结果在同一面板暂停恢复时保留；切换具体功能会销毁源文本及状态、移除监听。取消底层 File 读取会丢弃其返回值，不承诺物理内存擦除。
- 保存先检查 `saveTextSupportsCopyOnly === true`，只调用文本接口 `saveText({ content, extension, defaultName, copyOnly: true })`。预览后在原生对话框确认路径，已有目标拒绝覆盖；只在 `ok === true` 成功。`canceled`、false、undefined、异常保留预览，错误原文不直接暴露路径。所有输入用文本节点显示，不执行标题/描述中的 HTML。

## 4. 如何使用

1. 读取一个 UTF-8 `.ics` 或粘贴单个 VCALENDAR。文件读取不保存路径，不猜测 GBK/UTF-16 等编码。
2. 点击“校验并核对 UID”，查看每页 20 个事件的类型、原时间、重复属性及物理行。完整审计保存在后续 JSON 报告，包括不解释的属性及缺失时区定义。
3. 默认保留全部。完全相同组中选择保留事件 ID，再点击“确认去重 Dxxx”；确认只影响生成副本，不改源输入。冲突/系列组只能查看，不能自动覆盖。“撤销去重”恢复该组全部记录并废弃旧副本。
4. 默认目标是“保留原时间语义”。仅在符合单次固定时区范围时选择 UTC/上海/东京；不满足时整次拒绝，应回到保留原语义检查副本，而不是跳过问题事件。
5. 点击“生成当前规则副本”，查看输入/输出数量、移除 ID 和每条时间改写的前后原行。目标或判定改变后必须重新生成，源输入改变后必须重新校验。
6. 点击“预览完整 ICS 副本”或“预览完整校验报告”，检查完整只读文本后保存新副本。实际路径在原生保存对话框确认，不覆盖已存在文件。
7. “清除源文本和结果”清空当前内存与判定。暂停/隐藏取消在途任务，恢复需手动重新校验；已完成结果在同面板暂停恢复时保留。切换功能销毁未保存内容，需事先导出。已经打开的原生保存对话框仍由用户取消或完成。

## 5. 使用后产出

ICS 新副本保留完整 VCALENDAR 元数据、事件 UID、原重复属性、VTIMEZONE 和其他组件；只有明确确认的完全相同记录移除，或通过严格范围校验的 DTSTART/DTEND 转换。生成物重新解析可验证 UID/RRULE/EXDATE/VTIMEZONE 保持一致，不等于日历客户端已成功导入。

JSON 报告包含输入/输出事件数、原始事件 ID/物理行、输入时间类型、重复属性、完全相同组、UID 冲突/系列组、用户判定、移除 ID、完整审计和时间变更前后行。`events`、重复组和冲突组描述原输入对照，最终时间改写见 `changes` 和 ICS 正文，移除记录见 `removedIds`，不会把旧 UID 组误称为输出端已解决的身份关系。报告可能包含原事件信息，需核对分享范围。

## 6. 可重現例子、验证与限制

“每周重复演示”包含 `UID:weekly-demo@example.test`、`RRULE:FREQ=WEEKLY;BYDAY=MO;COUNT=4`、`EXDATE:20261012T010000Z` 和 `X-ORIGIN`。校验后使用默认保留，生成 ICS 并再解析：UID、RRULE、EXDATE、未知属性与完整事件内容相同。选择上海改写时必须整次拒绝，重复规则不会被删掉以凑成单次事件。

“重复与冲突演示”有 3 个同 UID 事件：前两条完整相同，第 3 条标题不同。未确认生成输出 3 条；`D001` 选 `E0002` 后确认、再生成输出 2 条，移除 ID 仅 `E0001`；标题不同事件继续保留，UID 冲突仍报告。撤销后输出恢复 3 条。折叠形式不同但展开内容完全相同也判同组；属性顺序不同则保守不去重。

“单次时区演示”的 DTSTART/DTEND 为 `20261005T010000Z` / `20261005T020000Z`。校验后选择上海、生成，改为 `DTSTART;TZID=Asia/Shanghai:20261005T090000` / `DTEND;TZID=Asia/Shanghai:20261005T100000` 并新增固定 VTIMEZONE。导出副本重新作为输入选择 UTC，应恢复两个原 UTC 值且原 VTIMEZONE 保留。东京对应 `100000` / `110000`。纽约 `20261101T013000` 歧义时间和 `20260308T023000` 不存在时间均不进行转换，不猜偏移；它们只可原样保留审计。

DATE 例 `DTSTART;VALUE=DATE:20261005`、`DTEND;VALUE=DATE:20261006` 保持全天 10 月 5 日，不能分配上海 TZID；floating `DTSTART:20261005T090000` 没有 UTC 瞬间，保持无时区值。缺 UID、非法日期或缺 VTIMEZONE 等问题在报告中显示，原样副本不修复或认证这些源问题。
