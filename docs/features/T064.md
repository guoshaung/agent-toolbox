# T064 TCP 服务可达性矩阵

## 1. 功能内容

输入 1–6 个明确主机（每行一个）和 1–8 个明确十进制端口，总组合最多 24 个。点击校验后展示规范化目标、完整主机×端口清单、一次尝试规则、DNS/TCP 次数、并发和期限，此时无网络。用户另行确认后，逐端点进行无数据 TCP 连接，展示成功、拒绝、超时、DNS 失败、其它网络错误、已取消或未运行矩阵，并保留逐端点 UTC 测试时间与单调耗时。

只连接填写并确认的目标。不接受/推断网段、通配符、端口段、URL、凭据或代理，不扩展目标，不重试。每主机最多一次系统解析，每端点最多一次 TCP 尝试，不发送 HTTP/TLS/应用数据，不修改网络配置。完整 JSON/Markdown 报告先预览，再安全创建新副本。

## 2. 为什么需要

多台设备的几个明确服务端口，手工逐个建立连接容易遗漏并混淆错误。矩阵保留每个端点的观测、时间和失败阶段，便于交付核对清单。TCP 建立成功只证明本次握手可完成，不证明该端口的应用健康、身份、TLS、认证或业务能力；ECONNREFUSED 也不证明一定由具体应用拒绝。系统解析失败和连接拒绝必须分开，未运行项不能显示成零毫秒成功或无故障。

## 3. 实现方式与范围

`host.cjs` 使用 Node 内置 net/dns/url 和单调时钟，无新增运行依赖。产品入口仅 `plan/run/cancel`，经公共可信已安装 Host 桥；严格拒绝未知 payload 字段，用户不能提供脚本、计时器、解析器、socket 或文件路径。Node 官方语义依据：[TCP Socket/connect/destroy](https://nodejs.org/download/release/v20.18.3/docs/api/net.html)、[dns.lookup 的系统解析语义](https://nodejs.org/download/release/v20.18.3/docs/api/dns.html)、[domainToASCII](https://nodejs.org/download/release/v20.18.3/docs/api/url.html#urldomaintoascii-domain)。

主机允许 IPv4、原始或带方括号 IPv6、标准域名（国际域名转 ASCII）和 localhost。IPv6 规范化后和大小写/IDNA 域名重复目标拒绝；域名末尾点、IPv6 zone ID、其它单标签域名、未指定/广播/多播 IP 不在范围。端口 1–65535，重复拒绝，按输入顺序产生确定的完整交叉清单。端口逗号/空白分隔，严格十进制，不支持范围表达式。

先解析所有主机，再进行 TCP 队列。IP 字面量解析为 `not_applicable`、耗时 null；域名每主机一次 `lookup({all:true,verbatim:true})`，保留最多 64 个合法返回地址，仅选系统首地址用于全部端口，无地址回退。来源 system_lookup、缓存 unknown；系统 lookup 可能使用 hosts/NSS/系统缓存，不能由 ENOTFOUND 判定精确 DNS NXDOMAIN，底层 DNS 报文数量不可观测。DNS 失败/超时分别为 `dns_error/dns_timed_out`，所有对应端口不连接，TCP 时间 null、attempted false。

限额：主机文本 4096 字节、端口文本 512 字节；1–6 主机、1–8 端口、≤24 组合。DNS 逻辑队列和 TCP 队列各最多 3 个在途阶段；DNS 阶段 3000 ms，TCP 尝试 3000 ms，整批 30000 ms。系统 lookup 不可实际中止：逻辑阶段超时/取消后忽略晚回调，原 OS 查询可能仍在后台完成；同批最多 6 次系统 lookup，不声称底层查询并发/报文总数严格等于逻辑队列。TCP 通过已解析字面 IP 且 `autoSelectFamily:false` 建立，仅一项地址/连接尝试，connect 后立即销毁；不等待应用回复。并发上限指在途连接尝试，不对内核 FIN/关闭缓冲瞬间作额外保证。整体/阶段截止由事件循环定时器实现，不承诺阻塞时精确毫秒返回。

TCP statuses：`connected` 为 connect 事件；`refused` 为 ECONNREFUSED；`timed_out` 为阶段 STAGE_TIMEOUT、整批 BATCH_TIMEOUT 或 OS ETIMEDOUT；其它 EHOSTUNREACH/ENETUNREACH 等为 network_error，保留有限代码，不保留内部异常内容。人工取消在途为 canceled/ECANCELLED，尚未尝试为 not_run、reason ECANCELLED；整批超时尚未尝试为 not_run/BATCH_TIMEOUT。已完成行保持原结果。解析时间独立在 resolutions；逐端点 startedAtUTC/tcpElapsedMs 只在真正 TCP 尝试时设置，没有测量就是 null。

每 sender 同时一项任务，32 sender 上限，每 sender 最多 128 个已用随机任务 ID，重复拒绝；cancel 和 destroySender 隔离 sender。成功/失败/取消/期限结束清理 socket、阶段监听器与计时器，晚回调不得覆写报告或启动后续连接。隐藏、deactivate/destroy 取消并停止队列，重新激活不自动连接；编辑清除旧确认/报告/预览。输入与结果只存面板内存，不写 ctx.config；工作台独立记录最近功能编号。UTC 采用本机墙钟，耗时采用单调时钟；主机时钟修改会影响时间标签，不影响单调阶段计时。

## 4. 如何使用

1. 工作台打开“工具 → 网络诊断与接口验证 → T064”。主机每行一个，不附带端口；填写明确端口清单。
2. 点击“校验输入并展示端点计划”，核对所有组合、一次尝试/不扩展规则、并发与期限。输入不合法时显示错误，没有旧确认按钮或旧结果。
3. 点击“确认全部端点，运行一次矩阵”。读取主机×端口矩阵和逐端点时间；DNS 的独立表展示所选 IP、缓存未知或失败。运行期间可以取消，完成状态保留，未运行项明确显示。
4. 先“预览完整 JSON 报告”或 MD，再“保存已预览报告新副本”。生产 saveText(copyOnly:true) 独占创建；已有目标拒绝。只有 ok===true 才成功，取消/false/undefined/异常保留完整预览，不回显内部错误。

“填入本机示例”仅填写 `127.0.0.1` 和 `8080, 8443`，不启动服务、不连接。这些端口是否开放取决于你的本机服务。清除会删除当前内存输入、批准计划与矩阵；切换功能销毁面板，不自动持久化未保存结果。

## 5. 使用产出与验证

专项 `node --test test/feature-T064.test.js` 22 项（14 host/report、8 组件事件），公共 Host 6 项另计，组合 28/28 通过。真实 Node 本机开放/已关闭端口 connected/refused、时间/0 数据、接受但沉默服务仍为 connected；DNS 首地址共享涉及真实 TCP 和受控 lookup seam。可控 socket/计时器测试 3 并发、完成/取消/未运行队列、3000/30000 ms 截止、DNS 失败/超时/晚回调、OS 错误、sender、有限历史。组件使用真实 h()/production feature 事件，DOM 适配与部分报告 fixture 属渲染层证据。

原生实际通过：隔离隐藏 Electron 33.4.11 / Node 20.18.3，生产 catalog/workbench/preload/registerHostIpc/**原样 singleton Host** 与生产文本 writer，15 组；冻结源 `0b3ffc11789fc5b61f2c684a8b70fc835346f92e`，证据 `work/electron-T064-1790991543709/result.json`。真实 127.0.0.1 / ::1 / localhost ×开放/关闭两个端口，6 行结果为 3 connected / 3 refused，每行 UTC 时间和 TCP 耗时；actual localhost lookup 一次，系统首地址 ::1、缓存 unknown，随后端口共用该 IP。完整 24 组合验证 3 connected / 21 refused、24 次单次 TCP、峰值并发≤3，最后一行亦保留。

TCP 连接超时不能用已接受但不回应的 loopback 服务伪造，超时仍为受控 socket/计时器逻辑验证，不声称已测真实 TCP 黑洞。没有为验收修改防火墙/系统设置；保存路径由测试夹具控制，未驱动系统对话框、未验证部署安装包。stderr 的 PRIVATE_TEST_PATH 是刻意抛出的保存失败夹具日志，结果 UI/报告不回显。

## 6. 具体可重现例子

在受控本机启动 TCP 服务监听 127.0.0.1:8080，确保 8443 当前没有监听。输入主机 `127.0.0.1`、端口 `8080,8443`，校验显示 2 端点、最多 2 TCP、0 DNS、并发≤3、阶段 3000 ms/整批 30000 ms，再确认。8080 行 connected，8443 行 refused/ECONNREFUSED；二者都有本次 UTC 开始/完成时间和 TCP 耗时，解析为 IP literal/not_applicable/null；服务收到 0 应用字节。预览并导出 JSON/MD 的两个新文件，重选同一已有目标会拒绝且原文件字节保持。

把主机改 localhost：系统仅解析一次，显示首地址及 unknown 缓存；全部端口共用该地址。若首地址是 ::1 而仅 IPv4 127.0.0.1 服务在监听，可能拒绝，工具不会擅自回退 IPv4，因此 localhost 和 IP 的结果可以不同。要验证两者相同，可同时在 ::1 与 127.0.0.1 对同一端口监听，均仅 loopback。

输入 `10.0.0.0/24`、`80-90`、重复端口或规范化后重复主机均拒绝，网络次数 0。为队列取消例填写最多 24 个明确本机端点；运行后立即取消，已完成行保持原状态，在途行 canceled、未启动行 not_run，未启动项没有 TCP 时间。具体状态数量取决于取消时机，不保证真实快速 loopback 必然产生超时或某个固定未运行数量；固定队列/期限逻辑可重复由专项受控计时器用例验证。
