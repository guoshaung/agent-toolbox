# T011 批量文件改名预演

## 1. 功能内容

明确选择同目录的普通文件，按前缀、选择顺序序号和字面替换生成完整旧路径→新路径映射；显示所有目标路径、SHA、冲突和恢复日志目录。只有预演通过且用户明确点击“确认原地改名（不是副本）”才修改原文件名称。记录每项已改名、不变、未执行、失败或未知；可预演撤销，重新确认后恢复原名。任何撤销原名占用先整批报告并阻止，不覆盖占用者。

这是原地改名，不是副本处理。单文件移动不覆盖且绑定源句柄，整批没有原子事务；中途失败或停止可以留下部分已完成文件。没有自动“尽力回滚”、重试、跨目录移动、覆盖、用户命令或任意脚本入口。

## 2. 为什么需要

一批照片、导出文件或资料命名不统一时，直接执行替换可能生成同名目标，之后又忘记原名。完整预演让人先看到每个目标和冲突；保存原名、文件身份及逐项结果，才能判断哪些项目实际改过。撤销还要重新检查，不能把后来新建的同名文件当成可以删除或覆盖的目标。

在 Node fs.rename 的默认目标替换语义之外，本实现采用明确不覆盖的 Windows 文件句柄移动。程序退出或回执丢失时承认未知状态，把人工核对所需的路径、身份和哈希保留下来。

## 3. 实现方式、资源和支持边界

仅支持 Windows 固定本地 NTFS，同一目录1–50个普通且单硬链接文件。每文件≤32MiB、合计≤64MiB，逐流哈希而不把正文放入 Node/renderer 报告；完整源/目标路径≤240字符、每段名称≤120字符、目录祖先≤32层。拒绝 UNC、设备路径、相对路径、遍历、非NFC、控制字符、Windows保留名、尾点/空格、符号链接/目录junction、多硬链接和文件夹。互换、目标占另一被选源、仅大小写变化明确拒绝，不创建临时名称绕过冲突。非 Windows 或系统能力不可用时明确失败/unsupported，不降级为覆盖式移动。

固定 host.cjs 使用生产 features.callHost('T011',固定operation,payload)；文件由原生 openFile/multiSelections 对话框选择，renderer 只能拿到本 sender 的 opaque selection/plan/record token，不接受任意磁盘路径、命令、工作目录或代码请求。已选择路径在 host 中校验；规则仅有限精确字段，查找/替换是文件名主体的全部字面匹配，保留最后一个点后的扩展名。前缀最多60字符，序号起点0–999999、最小位数1–6，按选择顺序添加，后接下划线。空查找表示不替换；无变化计划不能执行。

worker.ps1 是自有固定普通文件，host 拒绝链接或超过64KiB脚本。固定系统路径 PowerShell 使用 NoProfile/NonInteractive/EncodedCommand，固定 PSModulePath 和官方 Utility 模块；仅从 stdin 接收有限结构化数据，不把文件名拼进脚本、命令或表达式。固定 C# P/Invoke 锁住目录祖先并拒绝 reparse point；源文件以读+删除访问、仅允许其它读共享的句柄打开，拒绝外部写/替换/删除，比较卷/文件ID、创建/写入时间、长度和完整 SHA。执行/撤销前所有源和所有目标整批检查后才进入移动阶段。

单文件用 SetFileInformationByHandle / FileRenameInfo，ReplaceIfExists=false；UTF-16变长名称包含终止零，32/64位布局按进程指针大小处理。成功后以目标句柄复核文件ID；不能复核则标未知。kernel 拒绝后来才出现的占名；整个批次不能锁住所有未来目录项，因此仍可能部分完成。Windows文件系统大小写/短名等额外语义若在执行中产生冲突，也会停止后续，不承诺穷尽未来竞态。

每个 sender 同时一个任务，全宿主最多4个固定PowerShell进程（系统 Add-Type 可能短暂启动Microsoft编译器），16个 sender、128个有限任务编号。30秒请求期限加5秒收尾等待；系统I/O或关闭回调不保证硬时限；停止按逐文件 GO/结果握手阻止后续移动，不能撤销已发起的当前单文件操作。只在真实 child close 后释放槽和源句柄；杀进程/断电/丢回执可能留下未知状态，不能说“取消=没有改名”。早期取消意图在首个 await 前登记。隐藏、暂停、销毁请求停止；暂停后最终部分结果仍保留并在回到面板时展示。

确认前显示应用数据中的 feature-T011-recovery 目录。执行前独占 wx 创建 JSONL 初始完整映射，操作意图和回执逐条追加并 fsync；不把记录塞入 config。每 sender 最多10份原地改名批次记录；撤销更新原批次状态而不占新的批次槽；磁盘最多100份本功能日志，每份≤1MiB，达到界限停止新操作，不自动删除旧日志。日志包括完整本地路径和哈希，应按私人资料保管。它提供恢复证据，非通用事务日志或跨会话自动恢复框架；当前会话可在下拉选择已改名批次后预演撤销。未知状态要求人工核对原/目标路径及身份，禁止自动撤销。

文本 JSON/MD 报告只保存新副本，生产 saveText copyOnly=true、ok===true 才显示成功；取消、false、undefined或异常保留结果并明确失败。实际改名不使用文件副本writer，避免混淆原地操作。依赖系统 Windows PowerShell/.NET/Win32 固定能力和已交付生产 Host；不新增 npm 包或修改共享基础。

官方参考：[Node fs.rename](https://nodejs.org/api/fs.html#fspromisesrenameoldpath-newpath)、[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)、[FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)、[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)。系统能力按本机 Windows/.NET 实际验证；未承诺所有跨平台或32位环境已验证。

## 4. 如何使用

打开 T011，点击“明确选择本次原地改名文件”，选择同目录普通文件。选择过程读取完整哈希及身份，不改名。设置前缀，决定是否加序号，设置起点/位数与字面替换；“预演完整改名映射”显示所有原/目标路径和冲突。规则编辑会废弃界面旧计划，源改变会在确认后的再次整批预检中阻止操作。

核对完整表格和恢复目录，点击“确认原地改名（不是副本）”。等待最终状态，不能只因发起了请求就判断成功。停止按钮请求不再执行后续文件；最终表格说明已完成了哪些。需要撤销时，选择本会话记录批次，点击“预演撤销原名”，整批核对原名空闲和当前文件身份，再点“确认按完整计划撤销”。原名被占时先解决占名问题，再重新预演；程序不会移除占名者。

点击 JSON/MD 完整报告预览，然后保存新副本。切换整个工具会请求停止、保留实际最终结果；切换具体功能会销毁界面，仍可在应用数据 JSONL 中按记录人工核对。跨会话不能直接导入任意 JSON 让程序改名，没有冒称自动恢复能力。

## 6. 具体可复现例子

新建同目录 a.txt='alpha'、b.txt='beta'。明确选择二者，前缀设“整理_”，加序号，起点1、位数3、查找留空，预演应显示 a.txt→整理_001_a.txt、b.txt→整理_002_b.txt。确认后原路径消失，新路径正文/独立 SHA/文件ID一致；选择该批次预演撤销，确认后回到原名。

同目录 a.txt、aa.txt，前缀留空、不加序号、查找a、替换留空：两者都映射到 .txt，预演给 DUPLICATE_TARGET，执行按钮禁用，源文件不变。a.txt→A.txt 只有大小写变化也拒绝。

合法执行后，外部在 b.txt 原位置新建“occupant”，预演撤销给 TARGET_OCCUPIED 并显示完整原名路径，整批撤销0移动，包括原名仍空闲的 a.txt 也不恢复；占用者保持原字节。去掉自己创建的占用夹具后重新预演再撤销。

开发夹具在整批预检后、第二个 GO 前创建第二目标名。真实 Win32 返回占名，第一项 moved、第二项 failed，批次 partial；只对已完成第一项预演撤销，第二原文件及占用者均保持。若第一文件已经移动而回执前 worker 被终止，该项 unknown，日志操作意图留存，禁止自动撤销并要求逐路径核对。
