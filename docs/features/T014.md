# T014 按清单收集文件副本

## 1. 功能内容

明确选择1–5个允许的源目录，给每个目录固定别名A–E。输入每行一项的“别名/精确相对路径”，预演找到/缺失状态、源到目标映射及同名策略，再读取所选文件并核对SHA-256。用户确认后在全新目录写出收集副本及完整collection-report.json；不移动原件或写回来源。

## 2. 为什么需要

项目交付常从多个目录挑选少量文件。逐项手动复制容易漏文件或让不同来源的同名文件相互覆盖。预演把来源范围、缺失及最终名字放在同一张完整映射里，用户能先确认再收集。明确目录选择也避免把文本路径清单当成访问任意磁盘的授权。

## 3. 实现方式与规则

model.mjs提供纯路径范围/策略规划及File.arrayBuffer、Web Crypto SHA-256、Base64内容准备；index.js用公共h生成实际File API目录控件、完整预览和生命周期；没有eval、网络请求、新依赖或其他功能调用。

每个来源必须来自同一个File API选中根，保留webkitRelativePath并移除第一段根目录名。例如选择资料库时得到资料库/docs/a.txt，清单使用A/docs/a.txt。不同根用不同别名。别名1–12位ASCII标识符、唯一；相对路径按大小写精确匹配，不猜测路径，也不尝试读取未列出的文件。全部来源最多1000文件，清单1–99行/≤64KiB UTF-8；空行、重复请求、未知别名及非法路径整次拒绝。空目录没有可枚举文件，不支持空目录来源。

路径≤500 UTF-16单位、每部分≤120；拒绝绝对路径、遍历、反斜杠、非法字符/Unicode、Windows保留名称、尾点/空格，以及大小写/NFC重复和文件/目录前缀冲突。目录File API不提供符号链接和权限保真的承诺，本模块不自行遍历链接或使用源绝对路径。源集合已被用户选中，但只对清单找到的文件调用arrayBuffer；不匹配的文件只参加路径范围核对。

三种同名策略：默认保留别名和目录（files/A/docs/a.txt）；平铺同名阻止（任何同名组禁止准备）；平铺同名加序号（按清单顺序，n.txt、n_2.txt、n_3.txt，跳过已经使用的后缀名）。命名不截断，超限拒绝。完整冲突组和每条最终映射都显示，永远没有覆盖同名策略。输出files/内文件与根collection-report.json不会互相占名。

缺失项完整保留。只要有缺失，必须勾选“确认只收集找到的文件，缺失项完整写入报告”才能准备；全部缺失则阻止。准备对找到的文件先核对单文件≤2MiB、总≤8MiB及读取能力，再逐个核对实际大小并计算SHA-256。任一读取失败或大小不符整次拒绝，不发布半份内容。输入或确认条件改变立即清除旧结果；分片读取间让出事件循环，取消/暂停后过期回调不发布结果。底层arrayBuffer/digest不能物理中断，返回后忽略。切换功能销毁文件引用和输入，没有配置草稿或自动保存。

副本使用公共files.exportBundle({copyOnly:true,defaultName,files:[path,base64,sha256]})，能力标记严格true及函数存在才写。主进程再次核对全部内容/路径/摘要，在原生对话框确认全新目录名，独占创建，已有目标拒绝。普通失败清理本次新目录，清理失败显示partialPath供人工核对；不提供断电事务保证。只有ok===true成功，取消/未确认响应/异常不会报成功。本功能依赖公共基础PR #14，不修改共享桥。

## 4. 如何使用

1. 在工具→文件与批处理→按清单收集文件副本里选择允许源目录A，必要时再选B–E。
2. 每行写一项，例如A/a.txt、A/sub/b.bin、B/c.txt、A/no.txt。目录根名被移除，大小写精确。
3. 选择保留目录或平铺策略，点击“预演完整收集清单”。核对每条找到/缺失和最终路径；冲突时修改策略再预演。
4. 有缺失时明确勾选只收集找到的文件。点击“读取并核验副本预览”，检查完整SHA-256/字节/缺失报告。
5. 点击“确认创建收集新副本目录”，在原生另存对话框提供不存在的新目录名。保存过程中只能通过系统对话框取消。
6. 核对新目录内files/及collection-report.json。已有目标拒绝时换一个新目录名，来源不改动。离开前保存，否则切换功能会清除输入。

## 5. 使用产出和具体例子

源A有a.txt=UTF-8 alpha（5字节）、sub/b.bin=[0,128,255]（3字节）；源B有c.txt为空（0字节）。清单四行A/a.txt、A/sub/b.bin、B/c.txt、A/no.txt。默认保留目录策略预演4项：找到3、缺失1。确认缺失并核验后，报告copied=3、totalBytes=8、missing唯一为A/no.txt。

实际副本应含files/A/a.txt、files/A/sub/b.bin、files/B/c.txt及collection-report.json。每份内容与来源相同，报告包含请求、映射、字节、摘要、全部缺失、同名组、策略及明确缺失确认。报告本身也经主进程SHA-256核对；SHA-256核对完整性，不认证文件来源。

源B另有a.txt时，清单A/a.txt、B/a.txt选择平铺同名阻止会禁用准备；改加序号后目标是files/a.txt、files/a_2.txt。若A原先还有a_2.txt且请求顺序为A/a.txt、A/a_2.txt、B/a.txt，则最后一份为a_3.txt，保留前面两份名字，不覆盖。

## 6. 验证与限制

10项专项模型测试核对三找到一缺失/字节及独立Node摘要、缺失明确确认/全部缺失、三种冲突策略与已占后缀、非法/未选择路径、别名/根/大小写/NFC/前缀拒绝、预演零读取及未选择文件不读取、预算在读取前拒绝/实际大小不符、冲突禁止准备、精确大小写/根移除、读取和进度边界取消。测试使用真实Node File及有限回调，不能替代Electron组件操作；原生界面及生产目录接口另记录。

不支持空目录、空来源、跨未选择目录访问、相对路径模糊匹配、权限/时间戳/链接保真、文件原地改名/移动或覆盖、超过限额的全盘备份。限制是实现容量边界，不承诺大目录性能。原生目录选择器/保存对话框、完整主应用和安装包未在模型测试验证。

真实Electron33.4.11验收采用生产工作台/catalog/preload/IPC与registerBundleIpc/writeNewBundle。实际File/DataTransfer选择A/B两个目录，四请求找到三/缺失一；未确认缺失时准备禁用。明确确认后实际新目录含三份副本与完整报告：alpha5字节、二进制3字节、空文件0字节，共8字节，逐字节及独立NodeSHA-256核对。平铺同名阻止准备，加序号后实际第二目录含a.txt=alpha、a_2.txt=beta。重复目标拒绝，所有来源夹具及原输出字节未变，未选择的B/a.txt未混入第一副本，HTTP/HTTPS请求0，清空通过。证据为隔离集成work/electron-smoke-1790971463195/result.json及两个真实目录。来源由真实File对象提供webkitRelativePath夹具，保存路径由对话框测试响应指定，未操作系统选择器/保存框，完整主应用与打包未验证。
