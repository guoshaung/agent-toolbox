# T075 进程资源快照比较

## 1. 功能内容

手动查询当前权限可见的进程列表，选择一个进程后分别采两份有限资源快照。比较工作集字节、累计CPU计数与关联子进程，显示真实查询时间窗口、差值和未知。可分别查看第一份、第二份或比较报告，完整预览后保存 JSON/Markdown 新副本。不会暂停、结束或改变用户进程。

## 2. 为什么需要

程序变慢时，单个瞬时数字难以说明变化。两份源快照及时间窗口能帮助人工复核工作集上涨或CPU累计消耗，同时避免把PID复用当作同一程序、把权限失败当作零用量、把未观察到的子进程说成已经退出。它是有限诊断证据，不自动判定内存泄漏、性能根因或处理建议的效果。

## 3. 实现方式

公共可信Host调用本功能固定 list/sample 操作。固定 Windows System32 PowerShell -NoLogo -NoProfile -NonInteractive -EncodedCommand，shell:false/windowsHide:true；固定cwd和最小系统环境，禁止模块自动加载，只导入固定系统 Utility/CimCmdlets manifest。固定 Get-CimInstance Win32_Process 仅查询 ProcessId、ParentProcessId、Name、CreationDate、WorkingSetSize、KernelModeTime、UserModeTime，不拼接用户命令、读取命令行、路径、用户名、环境值或调用任何进程控制方法。父PID、创建时间及计数含义见 [Microsoft Win32_Process 属性文档](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-process)。

完整查询最多512条，管道最多读取513验证超限；stdout+stderr共256KiB、15秒，每Host至多四个未close的自建查询子进程，每窗口同时一个，最多32窗口/128独立任务号。OS枚举本身开销不承诺在第513行之前停止；超限整组未知，不取部分列表声称完整。数据严格UTF8和结构校验，计数按规范十进制uint64字符串/BigInt，不经浮点损失；重复PID、非法日期/字段/容量拒绝。异常仅固定码，不回显内部异常。非Windows/固定程序缺失明确未支持或未知，不退到用户PATH/其它命令。

列表每条返回窗口内opaque选择token。sample只接受该token及独立任务号；PID+原始七位小数UTC创建时间确认同一选择身份，缺创建时间为identity_unknown，不匹配为pid_reused，找不到仅not_observed。不把PID相同视作身份一致。列表刷新重置所有选择token。结果只保留所选进程、子进程及关联未知项，其它进程资源和名称不混入快照报告。

工作集 WorkingSetSize 是字节，不是私有内存或虚拟内存。前后差以BigInt精确有符号十进制给出，MB=1000000字节/MiB=1048576字节。CPU采用官方属性的100ns Units计数，用户+内核累计差值除10000为毫秒；二者之和为0时WMI不能区分不可用与真0，本功能保留未知；缺字段、下降或身份不一致也未知。极大CPU差仍保留精确100ns字符串，安全数值换算不足时毫秒/百分比未知。

每次报告包含查询开始/结束UTC及同一主进程单调时钟。资源字段实际读取在非原子窗口内，比较给出两窗口中点间隔估计、最小间隙和最大跨度；CPU毫秒/中点间隔×100是单逻辑处理器等价估计，可大于100%，不是任务管理器全机CPU百分比或精确瞬时值。系统查询会短暂创建自己的观察进程；若观察应用自身，它可能进入子进程证据，这是观察开销，不能忽略后声称完全无进程影响。

子进程按当前 ParentProcessId和创建先后关系有限遍历，父创建更晚/日期未知/循环单列unassessed。这是快照关联证据，PID复用及已消失父进程不能由当前表完整证明历史关系。比较按PID+创建时间分同两份/仅第一份/仅第二份，不称“退出”或“刚启动”。表40项分页，完整报告仍含全部支持的512条域内数据。

首个await之前占任务，早期取消可预记意图；仅终止自己固定查询子进程。取消/超时回执后，窗口和全局名额仍占到真实close，销毁窗口也不提前释放全局子进程名额。离开/隐藏/销毁清除列表与快照并忽略晚结果；返回手动查询，不自动采样，不保存进程信息到配置。

## 4. 如何使用

1. 工作台搜索T075，点击“读取当前可见进程列表”，从列表按PID、名称和创建时间选择目标。
2. 点击“采第一份进程快照”。自己执行要观察的常规操作，随后点击“采第二份进程快照”。
3. 点击“比较两份资源快照”，查看工作集字节差、CPU累计差及查询窗口。也可单独查看两份源快照。
4. 核对子进程来源和未知项；需要停止仅点“取消本工具查询”，它不结束目标用户程序。
5. 预览完整JSON或Markdown，再保存已预览新副本。切换选择或重读列表会清除旧结果；离开后需重新采样。

## 5. 使用产出与具体例子

完整JSON比较报告内含两份源快照、选择身份、字段来源状态、子进程/未知关联、查询窗口、精确差值及定义；Markdown嵌同一完整JSON。可单独输出一份源快照。每份≤1MiB，超限整份拒绝，不由分页截断。只用生产 copyOnly:true 新文件写入，已有文件拒绝；仅ok:true显示成功，取消/false/undefined/throw保留预览。

可复现模型例：同PID/创建时间，第一份工作集100000000字节、第二份150000000，精确增加50000000字节即50MB；第一查询窗口[0,100]ms、第二[1000,1100]ms，中点间隔1000ms，最小间隙900/跨度1100ms。若累计CPU差50000000个100ns，则5000ms/单处理器等价500%，不声称全机CPU达500%。若第二份PID创建时间改变，资源差值未知，不能把新进程与旧进程相减。

真实开发夹具申请额外50000000字节并做约120ms CPU工作。最终两次Windows快照工作集81219584→135319552，实际差54099968字节；不把分配请求50MB说成实际工作集恰好增50MB，因为运行时/OS也有变化。累计CPU差1406250个100ns即140.625ms，中点间隔约1895.3921ms，等价估计约7.4193%；窗口间隙187.1994ms、跨度3603.5848ms。真实grandchild两份均观察到，创建身份保持一致。
