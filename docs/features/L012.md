# L012 缓存命中实验

## 功能内容

在「学习 → 计算机原理交互实验」输入读取地址序列，选择块大小、组数、直接映射或两路组相联。计算后显示命中/未命中轨迹、逐次地址拆解、缓存访问前后状态、具体填充或替换原因、LRU/MRU标识和命中率。提供上一次/下一次访问、次序滑块、轨迹行跳转及每700ms自动播放。修改输入会使旧结果失效。

可比较同一地址序列在**相同块大小、相同总行数和容量**下的直接映射和两路LRU结果。界面提供同块三次、直接映射冲突、LRU替换、相同容量比较四个会立即计算的示例。核心功能本地运行，不需要AI、登录、联网或外部软件。

## 为什么需要

只记忆「缓存命中快」「组相联减少冲突」难以解释哪两个地址映射到同一组、命中怎样改变LRU、下次究竟替换哪一行。本功能把地址、组和有效行在每次访问中连接起来，保留可重放的前后状态。相同容量比较避免把多一倍缓存空间带来的改善错误归因于相联策略，且明确命中率差异依赖当前序列。

这扩展现有学习工具的系统实验能力：不是AI解释术语或代码练习，而是确定性的地址映射和替换模拟。

## 实现方式与模型边界

`model.mjs`负责解析地址、参数验证、单级缓存推进、同容量对照及Markdown报告；`index.js`用公共`h`创建参数表单、缓存状态表、轨迹、播放和导出；`meta.json`供工作台发现；`style.css`仅影响L012。模型版本`read-cache-lru-v1`，保存和JSON导出均为`schemaVersion:1`。

- 地址是0至4294967295的无符号**字节地址**，接受十进制和`0x`十六进制；不使用有符号位运算截断高地址。一次读取访问所在的一个缓存块。
- 块大小为1–256字节的2的幂，组数为1–64的2的幂。路数仅1或2，总行数至多64；两路时至多32组。容量=块字节数×组数×路数，界面和导出均明确显示。
- 块号=`floor(地址/块字节数)`，组号=`块号 mod 组数`，标签=`floor(块号/组数)`，偏移=`地址 mod 块字节数`。块字节范围为`块号×块大小`到`(块号+1)×块大小−1`。
- 每次计算都从**冷缓存**开始，所有行无效。标签相同且有效时命中，并更新该路的上次访问序号。未命中则装入整个块；本组优先使用最低编号空路，满组时替换上次访问最早的路。序号逐次递增，LRU不存在平局。
- 直接映射只有一路，满组未命中会覆盖该路。两路LRU只在对应组内决定替换，不受其他组访问影响。访问前/后快照为独立拷贝，不会被后续访问回改。
- 只模拟**读取**、未命中装块和替换。不提供WRITE指令、dirty位、写回/直写、写分配选择；不会把读取未命中装块称为某种写策略。无多级缓存、访问耗时、预取、相干性或真实硬件性能预测。
- 总命中率为`命中次数/读取次数`，界面保留精确计数分数并显示两位百分比。当前步骤还显示累计命中和未命中次数。尚无有效输入时不生成空序列百分比。
- 同容量比较保持总行数不变：直接映射使用`总行数`组×1路，两路LRU使用`总行数/2`组×2路，二者同块大小且各自冷启动。只有1行时拒绝比較并解释无法构成两路；比较不改变当前实验参数或轨迹。

地址可用空白、换行或中英文逗号分隔，连续分隔符可合并，`#`或`//`后的内容为注释。输入1–256次访问，最多10000字符；非法地址、非2的幂参数、超限行数均报错，不截断或静默取模。

```text
0, 1, 3       #同一个4字节块
0x8 0x10     //十六进制地址
```

## 使用步骤

1. 打开功能工作台的「缓存命中实验」，点击一个示例，或编辑「读取地址序列」。
2. 选择块大小、组数与映射方式，点击「从冷缓存计算」。块大小和地址使用字节单位。
3. 用「下一次访问」、滑块或点击轨迹表的次序，查看地址拆成块/组/标签/偏移后的访问目标、命中或替换原因。
4. 默认查看访问后全缓存。勾选「显示访问前缓存」比较同一次访问之前的有效位、标签和LRU顺序。描边指示本次选中路。
5. 点击「比较相同容量的两种映射」，查看两者容量与命中次数。若只配置1行，先把行数增加到至少2行。
6. 导出完整JSON或Markdown，选择新文件名。修改地址或参数后重新计算；播放切走会暂停，返回后手动继续。

## 产出与保存范围

完整JSON包含功能/状态/模型版本、导出时间、当前输入草稿、计算结果和可选同容量比较结果。结果含声明规则、解析地址、缓存容量参数、总命中率、每次访问的块/组/标签/偏移/路、命中和被替换行、具体原因、累计计数、访问前后全缓存及最终状态。比较结果同时保留两种策略的完整轨迹，可以逐项复核。

未成功计算时仍能导出JSON草稿，此时`result:null`；只有成功计算才提供Markdown，包含输入参数、规范化地址、命中率、逐次轨迹、每次访问后缓存状态与同容量比较。未提供文件导入按钮，可以按导出中的地址和参数重新输入计算。

导出调用公共`files.saveText`，强制`copyOnly:true`并检查能力标识。基础层通过独占新建拒绝任何已有目标文件；取消/失败不会清空输入，能力不足会提示升级后再导出。无需新增共享依赖或文件接口。

全局配置只保存输入、参数、查看位置、访问前/后开关以及是否已计算/比较，不保存大轨迹。写前用`TextEncoder`测量JSON UTF8字节数，超过64KiB不写配置，并独立显示「只能恢复较早输入，请导出完整JSON」提示；切走也不会强行保存超限内容。恢复先校验版本和体积，再按声明模型重新计算成功记录。保存失败明确提示，不承诺磁盘故障恢复。退出暂停播放，销毁清理播放与延迟保存计时器和DOM。

## 可复现的具体例子

### 核心验收：同块三次，命中率2/3

点击「同块三次示例」自动设置：地址`0,1,3`、块4B、2组、直接映射，容量8B。

| 次序 | 字节地址 | 块号 | 组号 | 标签 | 偏移 | 结果 | 动作 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 0 | 0 | 0 | 0 | miss | 组0路0装块0 |
| 2 | 1 | 0 | 0 | 0 | 1 | hit | 更新上次访问为2 |
| 3 | 3 | 0 | 0 | 0 | 3 | hit | 更新上次访问为3 |

预期命中2、未命中1、命中率**2/3（66.67%）**，第一步所有访问前行无效。更改为两路并重新计算，结果仍是miss/hit/hit。

### 直接映射冲突

点击「直接映射冲突示例」：地址`0,8,0`、块4B、2组×1路。块0和块2都映射到组0，标签分别0和1。结果三次均miss；第二次替换块0，第三次替换块2。组1始终为空，说明总缓存仍有空行也不能解决该组冲突。

### 命中刷新LRU，替换不能用装入时间

点击「LRU 替换示例」：地址`0,8,0,16,8`、块4B、2组×2路，容量16B。这些块都在组0。

| 次序 | 块号 | 结果 | 选中路 | 被替换块 | 访问后路0/路1 |
|---|---|---|---|---|---|
| 1 | 0 | miss | 0 | 无 | 块0@1 / 空 |
| 2 | 2 | miss | 1 | 无 | 块0@1 / 块2@2 |
| 3 | 0 | hit | 0 | 无 | 块0@3 / 块2@2 |
| 4 | 4 | miss | 1 | 2 | 块0@3 / 块4@4 |
| 5 | 2 | miss | 0 | 0 | 块2@5 / 块4@4 |

`@`表示上次访问序号。预期命中1/5（20%）。点击第4次，看到路1的块2上次访问2早于路0的3，所以替换块2；第5次再替换块0。

### 同容量比较

点击「相同容量比较示例」：地址`0,16,0,32,16`、块4B、2组×2路、容量16B，同时生成比較。直接映射改用4组×1路，容量仍16B；这几个块仍冲突到组0，直接映射0/5，两路LRU1/5。这里没有增加缓存容量；界面也明确此优势不保证在所有序列成立。

上述验证是纯模型及轻量DOM事件测试，没有启动Electron或确认实际保存对话框；主代理负责真实窗口集成。教学模拟不代表真实CPU缓存周期、吞吐或性能。没有跨实验累计热缓存、读写数据内容、文件导入或多级缓存。
