# T016 压缩包安全检视

## 1. 功能内容

本地 ZIP 先得到完整条目清单、相对路径、压缩字节、声明展开字节、单文件压缩比和风险代码。通过元数据预检以后，再单独校验全部文件的实际展开长度、ZIP CRC-32 和 SHA-256。所有文件完整通过后，用户明确点击确认，通过生产多文件副本接口创建一个全新目录。源 ZIP 从不改写，损坏或危险包不产生部分解压结果。

支持普通单卷、非加密 ZIP 的 Store（0）与 Deflate（8）方法；文件名支持 ASCII（未设 UTF-8 标记时）或严格 UTF-8（已设标记时）。不调用外部解压程序，不执行包中脚本，不使用 AI、网络、账号或系统 ZIP 文件关联。

## 2. 为什么需要

未知 ZIP 中的 ../、绝对路径、Windows 保留名称、大小写别名、文件与父目录冲突和特殊链接可能让通用解压流程产生危险目标。只相信中央目录的大小还不能发现伪造展开长度或损坏内容。本功能把风险预检、实际内容完整性校验、用户确认和独占写入分开，便于在交付前核对完整清单。

“安全解压”指本功能有限范围内的路径、容量、CRC 和新目录写入检查；不等于文件无恶意软件。CRC/SHA 不能证明作者可信或内容适合执行。展开后的文件需要用户自行决定如何使用。

## 3. 实现方式与支持边界

model.mjs 对 ZIP 二进制逐字段检查 EOCD、中央目录及每个本地头。名称原始字节、版本、方法、标记、时间、CRC 和大小必须一致；本地记录须从偏移0连续覆盖至中央目录，不接受自解压前缀、间隙、重叠、隐藏本地记录、分卷或尾随归档数据。ZIP64、数据描述符、所有额外字段、未知标记、非 DOS/Unix 创建平台、链接和特殊文件属性整体拒绝。条目注释、归档注释、时间、权限不写入副本；这不是逐元数据保真迁移。

路径必须已经为 NFC，不静默规范化；拒绝绝对路径、反斜杠、空段、点段、冒号、控制字符、尾点/空格、Windows 保留名、大小写重复和目录大小写别名。每段≤120字符、完整路径≤500字符。显式目录必须至少有一个实际输出子文件，由文件路径创建必要父目录；仅有目录记录或任何空目录都整体拒绝，不能声称完整解压后丢掉它。

ZIP≤8MiB、记录≤200、实际文件1–100、每文件≤2MiB、展开总量≤10MiB。用户允许总量1–10485760字节，单文件最大压缩比1–1000，默认100。大小与比率在解码前以声明值检查。RFC1951 帧扫描不分配输出，检查块、Huffman 树、长度/距离、流结束、尾随数据和累积实际长度，首先阻止声明小而实际大的 Deflate。随后浏览器 DecompressionStream('deflate-raw') 解码，按块再次检查实际预算；完整 CRC 和 SHA 通过才保存准备结果。输出保留有界，浏览器解码器内部临时内存不能承诺精确上限。缺少该浏览器能力时，Deflate 整包失败；Store 仍可校验。

每次读取/内容校验期限15秒，流写入按1KiB压缩块推进；取消使用 AbortController 并释放流锁，摘要与已发起 FileAPI 读取只能忽略晚回调。同步解析/帧扫描中检查时钟，不能保证硬中断浏览器主线程。隐藏、切走、销毁会废弃结果，旧回调不恢复状态；没有秘密或源内容配置草稿。

依赖已有生产 files.exportBundleSupportsCopyOnly / exportBundle 与 saveTextSupportsCopyOnly / saveText。多文件接口先核验 Base64、路径及 SHA，然后由原生保存对话框选择全新目录名；目录和文件独占创建，已有目标拒绝，正常失败清理本次新目录。renderer 不指定任意目标路径，不写源目录。断电/进程崩溃不提供目录事务保证；清理失败提示需人工核对。确认写入后不能取消已经交给生产接口的保存操作。只接受 ok===true 的成功回执，canceled、false、undefined、异常均不显示成功。

格式参考：[PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)、[RFC1951](https://www.rfc-editor.org/rfc/rfc1951)、[WHATWG Compression Standard](https://compression.spec.whatwg.org/)。未引入 ZIP npm 包或运行时 Node/shell 依赖；Node zlib 仅用于开发独立夹具和 oracle，产品使用自有有限解析器及浏览器解码器。

## 4. 如何使用

打开工作台 T016，选择一个本地 ZIP，设置允许总字节和最大压缩比。点击“预检 ZIP 元数据”，核对所有条目和风险。拒绝状态下不能解压；支持范围失败显示具体代码，可以导出拒绝报告。

元数据通过后点击“校验全部内容（仅内存）”。待全部 CRC、实际长度与 SHA 通过，核对表格中每个相对路径及摘要。点击“确认并创建新目录安全解压副本”，在保存对话框为目录选择一个不存在的名称，例如 ZIP安全解压副本-交付1；默认建议名称和完整相对路径在确认前显示，最终绝对目标由对话框确定。

点击 JSON 或 MD 完整报告预览，再保存报告新副本。报告可能包含私密文件名，分享前应核对。修改预算或换文件会废弃旧结果；清除按钮释放所选文件及内存内容。没有浏览器/生产桥支持时提示缺少能力，不假称保存成功。

## 6. 具体可复现例子

用 Python 标准库 zipfile 创建包含 a.txt='hello'、nested/中文.txt='中文hello' 和 bytes.bin=[0,255,7] 的普通 ZIP，选默认预算后预检、内容校验、确认输出新目录。三份副本内容应逐字节相同，SHA-256 可由独立 hashlib/Node crypto 复算。显式 nested/ 目录可保留为文件父目录，空目录 empty/ 则整包拒绝。

用 zipfile.writestr('../escape.txt','x') 创建穿越样例；点击预检后出现 unsafe_path，校验和确认按钮禁用，不能调用生产目录保存接口，目标目录外不出现 escape.txt。即使包内另有正常文件也拒绝整个包。

将 Deflate 文件的本地头及中央目录声明展开长度同时改成1，保留真实压缩数据（实际100000字节）。元数据可能通过，但内容校验返回 actual_output_budget，不能保存任何文件。完整流末尾加一个字节并同步调整 ZIP 压缩大小时返回 deflate_trailing_data，避免不同浏览器忽略尾随数据。另将同一 CRC 字段同时改错，可复现 crc_mismatch。

选择已存在的目标目录时生产接口拒绝，原目录文件 SHA 不变。取消保存保留校验结果供再次选择；隐藏面板会清除内存结果，再次进入需要重新预检。
