# T065 网址跳转链验收

## 1. 功能内容

输入最多 4 个起始 HTTP/HTTPS URL、最多 8 个精确允许主机/IP、0–5 次最大重定向和固定 HEAD/GET。先无网络校验，展示标准化 URL、端口、允许集合、明文 HTTP 提醒、固定请求头、次数/期限；用户另行确认后逐条串行检查服务器 Location 跳转链。

仅跟随 301/302/303/307/308；每链记录逐次请求 URL/方法/UTC 时间/单调耗时/HTTP 状态、下一 URL、跨主机/跨 origin/降级/循环/允许范围/是否跟随。未允许的下一主机及 HTTPS→HTTP 降级都在下一请求前停止。A→B→A 只请求 A/B 两次，记录 loop，不重复请求 A。最后已请求 URL、收到终点响应的 URL、未请求停止目标分别保存，不能把越界目标当终点。

无登录状态、凭据、Cookie、Referer、代理、自动重试或 HEAD 失败改 GET；严格 TLS，不关闭验证。完整 JSON/Markdown 先预览，再创建安全新副本。

## 2. 为什么需要

分享链接可以经过多个服务器重定向。循环、未授权跳到其它主机、HTTPS 降级和超长链会影响交付，人工只看浏览器最后地址往往丢失中间环节。有限链报告保留每个决策和实际请求数量，便于核对分享目标，而不把页面加载、登录后的业务成功或浏览器跳转行为混作服务器 Location 验收。

## 3. 实现方式与边界

`host.cjs` 仅使用 Node 内置 http/https/tls/net/url。生产 `plan/run/cancel` 经可信已安装公共 Host 桥调用，payload 严格已知字段，外部不能提供脚本、认证、请求头、Cookie、CA、代理或文件路径。`plan` 无 socket/解析/请求。WHATWG URL 标准化国际域名、默认端口、相对路径；片段删除不发服务器，查询保留。拒绝账号密码、控制字符、非 HTTP/HTTPS、URL 超长、重复标准化起点；精确允许主机规范化大小写/IDNA/IPv6，拒绝重复、URL/端口/通配符/网段，不隐式包含子域。单标签只允许 localhost，域名末尾点、IPv6 zone ID、未指定/广播/多播 IP 不在范围。

允许集合按 hostname/IP，不按注册域或 origin：`example.test` 不自动允许 `sub.example.test`，同一允许主机其它端口仍可访问，跨端口/协议记录 crossOrigin，换主机记录 crossHost，两者分开；确认计划明确这一范围。每条输入链独立 visited 集合，以标准化完整 URL（含查询、不含片段）判断循环，不把不同查询假定为同资源。最多 N 次重定向意味着最多 N+1 次请求，初始请求另算一次。禁止目标/降级/已访问目标/超过上限均不请求，记录候选与 followed false。循环在最终允许次数的响应里仍会被识别。

http/https.request 不自动跟随，`agent:false` 每次新连接、`autoSelectFamily:false` 不做其它地址回退，串行最多一项请求，固定 Host（每跳 URL.host）、User-Agent、Accept、Connection:close，无正文。相对 Location 按当前 URL 解析，GET/HEAD 全程保持，不按 303 改成其它方法，也不把 HEAD405 变 GET。只支持列明五种状态；其它 3xx 不跟随，终点状态仍记录 warning。401/403/404/405 等收到最终响应不等于业务成功，不登录。响应 Set-Cookie/其它头/正文不进入报告，也不会发给后续请求。Location 缺失/多条拒绝，不静默取第一条；无效协议或内嵌凭据拒绝且不回显原始 Location/凭据。

HTTPS 始终 `rejectUnauthorized:true`、TLS1.2–1.3、HTTP/1.1 ALPN，并用原目标主机/IP checkServerIdentity；不可信/过期/名称错误拒绝，无修复或降级。授权成功仅表示此次 Node 信任验证成功，不等于浏览器/所有客户端信任、不测 OCSP/CRL。HTTP 起始 URL 是明确计划内的明文；HTTPS→HTTP 永远停止，即使目标主机已允许。

限额：URL 各≤2048 UTF-8 字节、列表≤8192 字节；允许文本≤2048 字节，≤8 项；4 起点×最多 6 请求=最多 24 次 API 请求。每请求含 DNS/TCP/TLS/响应头等待≤5000 ms，整批≤30000 ms，事件循环定时器不保证阻塞时精确毫秒。Node maxHeaderSize 16384、完整头数≤128（关闭 Node 自动头数截断后自行拒绝超限），最多 3 个信息性响应，升级协议拒绝；socket.bytesRead 在读头过程中/完成时观察上限65536。头收到就销毁 IncomingMessage/ClientRequest/socket，不读取或保留正文。GET 可能在初始缓冲/内核中已经收到正文，socket 字节属性不是完整下载量或服务器总发送量承诺，超限拒绝但不能撤回已传输字节。输出≤2 MiB，完整拒绝超限，不截断。

每 sender 一项任务、最多 32 sender / 每 sender128个已用 ID，重复 ID拒绝；cancel/disposeSender隔离。成功/失败/取消/阶段或整批期限清理计时器、请求、socket/响应监听；晚回调不改报告、不继续队列。Node 系统 DNS 路径/缓存/底层报文未知，OS lookup 不可实际终止；销毁请求/socket并忽略晚结果。面板隐藏/deactivate/destroy 取消，不自动恢复请求；编辑清除旧允许计划和报告。UTC 使用本机墙钟，耗时单调时钟；输入、查询、结果不写配置，仅工作台保存最近功能编号。

官方依据：[Node HTTP ClientRequest/response/rawHeaders/maxHeaderSize](https://nodejs.org/download/release/v20.18.3/docs/api/http.html)、[HTTPS request TLS选项](https://nodejs.org/download/release/v20.18.3/docs/api/https.html)、[TLS验证/checkServerIdentity](https://nodejs.org/download/release/v20.18.3/docs/api/tls.html)、[RFC9110 Location与重定向语义](https://www.rfc-editor.org/rfc/rfc9110.html)。不处理 HTML meta refresh/JavaScript 跳转、HTTP2、浏览器会话、站点完整加载或页面内容验收。

## 4. 如何使用

1. 打开“工具 → 网络诊断与接口验证 → T065”。起始 URL 每行一个；允许主机/IP每行一个，必须明确包含所有起始主机。
2. 选择 HEAD/GET 和最多重定向次数0–5，点击“校验输入并展示跳转计划”，逐条核对规范化 URL、端口、精确域名范围/同主机其它端口、明文/严格 HTTPS、固定头、N+1请求规则和期限。此时未发请求。
3. 点击“确认允许范围，运行有限跳转链”。查看每链的最后已请求 URL、终点/HTTP状态、未请求停止目标和逐次记录。终点为空表示没取得最终响应，不能读成已访问候选。可取消；已经完成的链保留，后续未开始链为 not_run。
4. 先预览完整 JSON 或 MD，再“保存已预览报告新副本”。检查 saveTextSupportsCopyOnly 后以copyOnly:true独占创建，已有目标拒绝；只有ok===true报成功，取消/false/undefined/异常保留完整预览。

示例按钮仅填写 `https://127.0.0.1:8443/start`、允许 `127.0.0.1`、HEAD、3次跳转；不会启动服务或请求。需要自备信任且名称匹配的证书和对应路径。分享前核对报告URL查询：本工具不自动识别查询参数里的秘密，完整查询会发送并导出。清除/切换功能删除未保存面板内存结果，不自动持久化。

## 6. 具体可重现例子

在本机HTTP服务127.0.0.1:8080配置 `/a` 返回302 Location `/b`，`/b` 返回302 Location `/a`。填URL `http://127.0.0.1:8080/a`、允许主机`127.0.0.1`、HEAD、最大3次；校验显示每链最多4请求，确认后实际仅2请求。结果loop/REDIRECT_LOOP，逐次状态302/302，followed true/false，最后已请求 `/b`，未请求停止目标 `/a`，terminalURL null。导出JSON/MD完整保留；不会再次请求 `/a`。

将 `/a` Location改`http://other.example.test/end`而允许集合仍仅127.0.0.1：只请求一次，domain_blocked/HOST_NOT_ALLOWED、crossHost/crossOrigin true、targetAllowed false、next URL作为未请求候选；不解析或访问other主机。若自有第二主机明确加入允许集合，才会跟随，并保留跨域记录。同主机从8080到8081属于跨origin，允许范围仍按主机，不因端口变化默认阻止。

配置已受信任/匹配127.0.0.1的HTTPS服务8443，其 `/start` Location返回 `http://127.0.0.1:8080/end`。确认HTTPS起点后只请求HTTPS一次，downgrade_blocked/HTTPS_DOWNGRADE_BLOCKED、降级/跨origin警告；即使目标主机允许也不发HTTP。HTTPS证书过期或名称不符则当前请求失败，不改HTTP再试。

配置 `/n/0`→`/n/1`→`/n/2`→…，最大重定向2，则只请求0/1/2三次，在候选3之前limit/MAX_REDIRECTS，terminalURL为空。配置 `/stall`建立连接后不返回HTTP头，约5秒 REQUEST_TIMEOUT销毁连接；这是真实等待响应头超时，不是声称TCP没连上。HEAD405只记录终点405及terminal_http_error，不自动改GET。每项可以用本机夹具或专项固定路由重复核对，无账户或浏览器登录依赖。
