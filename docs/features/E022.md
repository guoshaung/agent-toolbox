# E022 谁是卧底

## 1. 功能内容与必要性

按 `entertainment.json` E022 的精确范围提供同设备4–10人、80组相近词、逐人私密看词与自动遮挡、发言轮次、逐人投票/平票加赛、淘汰/胜负/揭晓、公开JSON/Markdown记录和手动完整存档恢复。省去准备纸卡，由同桌真实玩家描述和猜测。没有联网房间、AI角色、录音、摄像头、账户或下注。

姓名1–24码点、无首尾空格/控制字符，NFC意义下唯一；一行一人且无空行。卧底1至 `floor((人数−1)/2)`，其余平民，初始卧底必须少于平民，不设白板。配置建立后锁定；重设要求明确确认丢弃当前局。姓名按输入顺序发词/发言/投票，已出局者不再投票。

80词对是为本项目人工整理的独立日常概念组合，不摘录歌词、诗歌或外部题库，不宣称独占这些普通词语。固定库在 `model.mjs` 的 `PAIRS`（basis `e022-pairs-v1`），正文界面不展示当前词对库或候选答案，避免看词阶段提前揭示。完整词对如下，每行8组：

## 2. 完整规则与实现方式

随机均匀选择一组词、平民/卧底词方向，再从剩余玩家中无替换抽取指定卧底数。使用 `crypto.getRandomValues(Uint32Array)`，拒绝不属于整倍数区间的值再取模，无Math.random降级；连续128次拒绝明确失败，不无限循环。纯模型可注入索引源做独立样例，生产界面没有指定身份、固定结果或seed入口。

每个玩家只看自己的词，不直接告诉其“平民/卧底”。同组玩家拿相同词；有多个卧底时所有卧底共享另一词。全部看完进入口头发言，每位存活玩家按姓名列表顺序描述但不直接读原词；工具只记录玩家点击“发言完毕”，不录音、不判断描述质量，不声称实际所有人都发过言。

每轮每位存活玩家投一票给另一存活者，禁止自己；只有全部投完后才公布完整票数/票单。唯一最高票者出局。最高票平票时不淘汰，进行一次限定为最高票候选的加赛，所有存活者仍各投一次且不能投自己；加赛还平票则本发言轮无人淘汰，进入下一发言轮。没有随机出局、主持人随意选人或暗中多轮加赛规则。

出局只公布姓名，所有身份和两组词直到终局才揭示。结算后全部卧底出局则平民胜；否则卧底存活数达到或超过平民数则卧底胜，包含相等边界。每次淘汰只判断一次；终局后禁止看词/投票/追加轮次，只能保存、恢复或明确新建。最多30发言轮（每轮最多2次投票），达到仍无胜者标“中断”，保留完整60次投票，不能将上限当通关。主动结束也需要勾选确认揭晓全部秘密，标中断/无胜者。

`model.mjs` 在WeakMap内持有私密source/派生状态，公开快照不含未揭晓词、身份或未完成票单；结束后才提供reveal。source只保存固定版本、姓名、卧底数量、两词、卧底ID及完整操作事件，恢复先严格校验再逐事件回放，拒绝非法顺序、候选/投自己、结束后事件、重复键/ID、未知版本/词库/字段、非规范安全整数和超限。每次动作先在副本上验证，失败不污染当前局。有效source最多700事件/64KiB，固定规则至多约670事件，不截断历史。

## 3. 如何使用与秘密交接

输入4–10人姓名和卧底数量，点击“建立本局并逐人看词”。把设备交给标题所示当前玩家，其他人背过屏幕，然后本人点击“我是…，查看自己的词”。只显示一个词，没有另一个词、身份提示或其他人词卡。8秒后自动清空旧词节点并回遮挡页；也可随时“遮挡自己的词”或“记住词，遮挡并交接”。未本人查看不能直接交接。超时后仍需手动确认已记住，避免自动把设备交给下一个人。

每次重新渲染/隐藏/离开/交接/销毁都会清空旧私密节点textContent、移除旧事件、清除私密计时器并新建遮挡DOM；没有隐藏在title、data属性、textarea/undo或折叠面板中的其他词。暂停/hidden返回仍在原玩家遮挡页，需要重新本人查看，不自动恢复秘密。不做账户授权隔离：旁观、屏幕录制、开发者工具、应用源码或本机存档访问无法靠此交接流程阻止。

看完所有人后口头发言，点击发言完毕进入投票。每次把设备交给当前投票者，选一个候选并确认，旧选择控件被清空、下一人看到空选择。每轮或加赛完整结束才公开票单；有人出局后其投票阶段自动跳过。平票页面明确候选，点击开始一次加赛。无需计时发言，也不会隐藏/返回时自动投票或推进。

功能不自动写config/localStorage/sessionStorage。要继续上次，需要**显式保存含秘密的完整存档**。选择UTF8 schema1存档（1字节至64KiB）后只预览姓名/阶段/轮次，不把秘密/未完成票单放到DOM；勾选替换并应用，原局才改变，发词途中恢复仍保持遮挡、投票途中恢复到下位投票者且控件空选。恢复终局可直接查看已公开的最终揭晓。公开记录不能恢复秘密本局。

## 4. 产出与安全副本边界

公开JSON/Markdown记录包含规则、姓名、初始卧底数、轮次/阶段、存活名单、已经完成的全部票单/票数/淘汰、未完成投票数量、完整或中断标记、胜者/理由。终局前不包含两词/卧底身份或当前未完成选择；終局/主动揭晓后附每位玩家身份与词。Markdown对用户姓名进行转义，不执行HTML，JSON不添加伪造认证信息。

完整存档为了恢复必须含两词、所有身份与未完成票单，是**未加密**JSON，打开者可以读出全部秘密；独立勾选“我理解完整存档包含全部秘密，明确另存”才启用保存，保存尝试后勾选重置。存档不适合在游戏中发送给其他玩家。事件回放验证结构与规则，不是防篡改签名或反作弊认证，合法内容仍可被有本机访问的人改写。

三种输出通过生产 `files.saveText({copyOnly:true,...})` 新副本保存，须有 `saveTextSupportsCopyOnly===true`，只认 `ok===true`。取消、字符串“true”、失败或partialPath不报成功，partialPath提示人工核对；已有目标WX独占创建拒绝并保留原SHA。原生pending期间锁定修改/新建/恢复，隐藏/离开/销毁version使晚到结果失效，不复活旧词卡或旧面板。保存前先遮挡本人卡；不承诺安全擦除JS/操作系统内存、剪贴板或已保存副本。

本功能无用户PNG/音频输出；原生截图只用于可见界面证据，不当作完整报告或诗卡导出。产物的完整性由实际JSON/Markdown解析与完整事件/票单核对，不能只凭截图顶部宣称所有历史可见。

## 5. 具体可重现例子

六人甲、乙、丙、丁、戊、己，一名卧底。依次本人查看并遮挡，统计应是五人同词、一人另一词，且没有“当前玩家是卧底”的明示。生产本局身份随机，不保证哪人不同。单测固定档案/原生恢复边界使用甲拿“梨”、其他人“苹果”，这种固定输入仅为复现规则，不是生产界面的身份选择功能。

甲卧底的固定六人局，完成发言后按玩家顺序投目标 `[乙,甲,甲,甲,甲,甲]`，甲得5票、乙1票，甲出局且平民立即胜；直到最后一票前，DOM与公开报告都没有苹果/梨或甲的身份。若依次淘汰平民乙、丙、丁、戊，剩甲和己各1人，卧底达到人数相等时胜，已出局者不会再投票。

平票独立例：六人按顺序投 `[乙,甲,甲,甲,乙,乙]`，甲/乙各3票，其他0票；进入只含甲/乙的加赛，甲不能投甲、乙不能投乙，其余可投其中任意一人。加赛同样3/3则无人淘汰，第2发言轮开始。保存加赛/部分票单存档并恢复，要回到同一阶段/下一投票者，不丢票、不给前一玩家重复投票。

发完甲但还没交接乙时，显式保存完整档案并重载窗口；选择该档、勾选替换后，应显示“请交给乙”的遮挡页，甲旧词节点不可回看。第一位投完票后保存/重载，会从乙继续，选择框为空；全部后再另存公开记录能完整核对六张票单。主动结束须明确勾选，输出complete=false/winner=null，而不是假胜利。
