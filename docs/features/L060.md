# L060 学习方法个人对照

## 1. 功能内容

围绕四对、共八份人工匹配材料，用户指定两种学习方法、固定种子、共同量规和成果测量的延迟小时数。工具在每对内分配A/B各一份，全组各四份，记录种子和逐对伪随机状态。用户编辑每份材料的来源、实际量规、实际延迟与人工成果分数，得到逐对A−B分差、四份方法A/方法B均分、四对分差均值和材料混杂提醒。

默认自编教学例两方法均分8/6，四对分差都是2，均差也是2。量规或延迟与共同计划不同/未知时醒目标“不可直接比较”，保留标注的原始数值算术差。缺分数保留未知，不当0，不用三对结果伪称完整四对均值。来源和材料匹配依据由用户声明，不自动认定其真实、相同难度或相互独立。

输入编辑递增本地修订号并废弃当前报告。已完成修订保留当时的完整输入快照，可以查看当时种子、方法、来源与分差；重载后须主动复算。只有整体替换当前输入/历史需要明确确认，离线分析直接点击执行，没有AI依赖。

## 2. 为什么需要

把今天某种方法的分数与昨天另一份材料的分数直接相比，可能混入题目难度、延迟、评分口径或学习順序的差异。个人记录也常丢失当时的方法分配，改完种子后错误地把旧分数当作新方法取得的分数。

L060使每份材料有固定ID、每对有匹配说明、每次完成修订有完整输入快照，帮助用户检查“比较用了哪些材料、什么量规、多久后测量”。它记录随机分配与描述性配对算术，不执行真实学习实验，不证明某方法造成效果，也不计算显著性、置信区间或自动评分。与复习算法、题库生成和能力认证不同，其核心产出是个人对照的可复现人工台账及口径不一致提醒。

## 3. 实现方式与规则

`model.mjs`提供纯有限分配与整数分差计算，`index.js`提供共同计划、四对材料表单、分配预览、配对结果表、完整历史和副本预览；`meta.json`由生产功能工作台发现，`style.css`使用项目实际深色主题变量。所有用户文字通过文本节点渲染，没有用户代码执行、联网、自动计时或AI推断。

- 固定P001–P004，每对固定两个材料M001–M008的输入顺序；不能交换ID或改变材料数。分配算法公开为`state=(state×1664525+1013904223) mod 2^32`，用BigInt精确计算，种子为0–4294967295的无前导零十进制整数。每对更新一次状态，最高位为1则第一材料A、第二B，为0则相反。因此每对各一方法、全组各四份，同种子输入次序必重复。报告记录算法名、常量、规则、每对state前后及每份材料所属方法。
- 算法是教学用确定性伪随机分配，不是安全随机。它只随机**材料的方法标签分配**，不随机真实学习顺序；没有声称固定种子在真实实验中不可预测或具有随机化因果保证。
- 分数始终绑定材料ID。修改种子或方法名称代表新的人工声明，不自动把分数挪到另一份材料，也不自动证明修改后的方法真实取得过该分数。原快照的名称/种子/分数/分配保留；用户须核实本轮填写是否对应实际过程。
- 原始分数范围0–100、最多3位小数；较高仅代表用户量规的原始分较高，不做归一化或质量判断。以整数千分单位记录求和、相减：每对差为A分−B分，A均分为四个A整数单位之和/4000，B均分同理，配对均差为四个整数分差之和/4000。不先对浮点数相减；符号可以为负、零、正。输出Number仅用于有限整数除法展示，无测量精度或有效位数保证。
- 计划/实际延迟均为人工声明的小时数，0–8760、最多3位小数，以整数千分小时比较；0明确代表用户声明即时测量。不是计时器，不验证实际等待。`24`和`24.000`同值，空值未知，负值/科学记数法/超范围整次拒绝。
- 实际量规描述经trim后须与共同计划量规字面完全相同，实际延迟须与共同计划数值相同。任一材料量规/延迟不同或未知，整组状态为不可直接比较；报告保留原始数学差并说明没有调整口径差异。字面一致**不证明真实执行/评分一致**，也不验证量规尺度或测量有效性。
- 任一配对缺分数则该配对差未知，四对均差未知；某方法四份中任一缺分数，该方法均分未知，不从子集替代。已知分数0是有效记录。材料出处/名称/匹配理由空项单独标未知，不伪造来源；口径字面一致仍不能排除材料混杂或形成因果结论。

schema1只保存当前输入和已完成输入快照，不存派生报告。编辑递增`revision`（1–1000000），旧完成快照不修改；同一修订反复执行不追加历史。成功分析才原子追加快照，容量/数值/取消失败不追加。历史模型版本固定，恢复检查结构、顺序、ID、历史可计算性以及当前修订是否静默改写既有快照；不是签名或防伪保护。配置串行保存采用一个在途请求、最新待写值队列，旧回执不能冒称最新值已保存。

最多12个完成修订快照；当前输入加全部历史UTF8 JSON体积≤64KiB，新增超限整项拒绝、不丢旧记录。方法名≤80码点，量规描述≤320，材料名≤160，材料说明/匹配理由≤1200，来源名≤160、位置≤320，数值文本≤32、种子文本≤10码点；非法控制字符/孤立代理项拒绝。输入允许尚未完成的数值字符串，分析时严格校验。报告JSON/Markdown各≤1MiB，超限整份拒绝。无报告时也能完整导出当前输入/历史归档，便于容量满后保留再另建记录。

## 4. 使用步骤与可复现例子

1. 在学习工作台打开L060，点击“执行个人配对对照”。默认种子`20261003`、方法A“主动回忆”、方法B“重读”、共同量规“用户同一10分量规v1”、共同延迟24小时，八份教学材料的实际口径相同。
2. 默认分配为：P001的M002→A/M001→B；P002的M003→A/M004→B；P003的M006→A/M005→B；P004的M008→A/M007→B。每份A教学分8、每份B教学分6，故四对差2，均分8/6、配对均差2。重复执行同修订结果/分组相同，仅一条完成快照。
3. 编辑M001成果分数为`6.001`（本种子M001属B），重算：P001差1.999、B均分6.00025、四对均差1.99975。旧版8/6快照仍保留。此值只是人工分数算术，没有测量精度或有效性结论。
4. 把M001实际量规改为“另一20分量规”，再执行，醒目标“不可直接比较：量规或延迟不同/未知”，原始分差仍标为算术。把M001实际延迟改48也标不一致。明确点击“将共同量规与延迟填入全部材料”后，记录口径可以恢复字面一致，但这个操作不证明实际等待/评分真的一致。
5. 修改种子为0，分配预览/重算可重复、仍每对A/B各一份。材料ID及原分数不改变，当前分差可能随标签分配变化；须核实分数是否对应真实过程。旧快照保留原种子/分配，不被覆盖。
6. 把M001分数清空、来源名/匹配依据清空，执行显示分数缺失、四对均差未知、来源/匹配未知提醒。输入`-1`、`1e2`、`100.001`或无效种子，分析整次拒绝；当前已提交输入仍可导出完整输入历史归档。
7. 查看当前配对表、逐材料算法状态/来源与完整报告，展开旧快照核对。导出完整JSON/Markdown报告；重载后已提交输入与快照恢复，报告不自动恢复，要主动执行。
8. 达到12次历史或64KiB时，不截断/覆盖旧快照；导出输入历史归档后，可明确确认整体替换为教学例并开始另一记录。整体替换先可取消，不自动清旧记录。

## 5. 产出与保存范围

界面提供当前输入修订、历史数量/总字节、八材料分配预览、四对结果表、各方法完整四份均分、逐对差值、原始配对均差、量规/延迟不一致项以及材料混杂提醒。原始数值差始终带描述性边界，工具不输出“某方法有效”的因果结论。

完整报告含当前与每个完成修订的全部来源/匹配理由/材料说明/方法/种子/公开算法与状态、score口径、原始分数、实际/计划量规与延迟、逐材料记录、配对差和未知项。输入历史归档不含结果计算，明确标记“不是结果”，但保留尚未分析的当前输入和全部旧快照；表单数值尚不合法时也可归档，不丢原字符串。

JSON保持原文，Markdown转义用户HTML、使用动态代码围栏，避免把用户文字当可执行HTML。预览/副本可能含人工材料片段和出处，请按用户实际需要选择保存。必须检测`files.saveTextSupportsCopyOnly===true`、携带`copyOnly:true`，仅回执`ok===true`报告成功；取消、未知回执或错误不伪称成功。生产writer的`wx`新文件写入拒绝覆盖已有目标。

配置只包含schema1人工输入/快照，没有派生分差、文件字节或可信时间戳。隐藏/取消/切走/销毁隔离迟到分析/保存回执，恢复不自动执行。已经开始写盘无法撤回，离开后不会补显示成功。没有外部文件读取/扫描/编辑，来源都是人工记录。
