# T010 层级数据扁平化映射

## 1. 功能内容

将一个嵌套 JSON 中显式选择的对象记录数组映射为扁平表。用户填写父记录 JSON Pointer、父内一个数组的相对 Pointer，逐列编辑输出名称、父记录/当前元素范围及字段路径。支持单数组展开和数组保留；先精确预测行数及丢弃风险，再执行预览。输入为本地 UTF-8 文件或粘贴，数据不上传、不写全局配置、不修改原文件。

每个结果行包含来源名称、1 基父记录序号、原文父记录物理行、1 基数组元素序号、元素物理行、数组状态、元素存在标记。预览每页 25 行，每格显示最多 200 UTF-16 单位；可查看完整行，完整副本不会按预览截断。输入或任何映射配置改变，旧预测与结果立即废弃。切换具体功能会销毁未保存内容；离开工具会取消正在执行的操作。

## 2. 为什么需要

嵌套接口记录、订单明细与导出 JSON 很难直接按表格查看。简单逐数组展开容易产生笛卡尔积，把平行数组按位置绑定又可能错误关联。静默删除父字段或忽略空数组也会改变业务记录数。此功能要求显式选择一个数组，重复保留用户选择的父字段，并完整列出未选数据路径；让表格的行数与丢失范围在执行前可以审查。

## 3. 实现方式与输入规则

- `json.mjs` 独立严格异步 tokenizer 来源于 T008 的纯解析实现，扩展到任意根 JSON，并通过 WeakMap 保存对象和数组元素的原文物理行；没有运行时跨功能依赖。重复属性名、尾逗号、非法语法、不安全整数、非有限数与 Number 最短十进制表示改变原值的输入会拒绝。`0.1`、`1.2300`、`1e2` 可往返；`9007199254740993`、`1.00000000000000001`、`1e-999` 会拒绝，请把精确大数写为字符串。不是任意精度数值处理器。
- 父路径必须指向存在的对象数组，各父记录必须是非 null、非数组的对象。根就是对象数组时，父路径留空；嵌套为 `{"records":[...]}` 时填写 `/records`。其他根结构可解析但不能选为父记录。空父数组输出 0 行。
- 路径仅使用原生 JSON Pointer，空映射路径表示范围根值，属性名中的 `/` 写为 `~1`，`~` 写为 `~0`。例如属性 `a/b~c` 用 `/a~1b~0c`。不接受点语法或 `#/` URI 片段。数组索引只允许固定 0 基整数；`01`、`-`、`*` 遇到数组会拒绝，普通对象的字面 `*` 属性仍可读取。
- 每列名称唯一、无首尾空白、最多 80 单位，不能使用 CSV 的 9 个保留来源列名；至少有一列来自父记录，建议明确映射业务主键。没有自动主键猜测。存在的 null 是 null；缺失字段不出现在 `values` 中，并进入 `missingColumns`。空字符串是有效字符串。
- **展开**：仅所选一个数组一元素一行。父字段重复到每一行；元素可对象、标量、数组或 null。映射其他数组为父 JSON 列，或用固定 `/tags/0` 索引读取；不会 zip、笛卡尔积或递归展开，固定索引不随元素序号联动。
- **保留**：每父记录一行，额外把所选数组保存为用户命名的 JSON 字面量列。必须手动删除元素范围映射或将其改为父范围；程序不静默删配置。数组 null 的额外列是字符串 `"null"` 并标记 JSON 字面量，数组缺失则该列缺失。
- 所选数组缺失、null 或空数组，各保留一条父行，分别记录 `missing-array`、`null-array`、`empty-array`，`arrayIndex=null`、`elementPresent=false`，元素范围各列缺失。真正 `[null]` 产生 1 个存在的元素，`arrayIndex=1`、`elementPresent=true`，元素根映射为原生 null。非数组/非 null 的所选值直接拒绝。
- 对象与数组映射成 JSON 字面量字符串，并进入 `jsonLiteralColumns`；普通 JSON 类型保持类型。审计列出父路径外的未保留叶路径、逐父的未映射叶路径、逐展开元素的未映射叶路径及映射配置、政策和来源。空对象/空数组也是叶；被整体映射的子树不会误报为丢失。父映射 `/items/0/a` 仅覆盖第一个元素的 `/a`，不会假设后续元素也被保留。丢弃数量按来源叶路径计数，不是重复输出单元格数。

预测和执行分开。模型按约定精确计算 `sum(max(数组长度,1))`，保留策略为父记录数；不生成试探性截断结果。解析/审计/执行/导出定期让出事件循环并检查 AbortSignal。取消或超限不产生可导出的半成品。预测行数不是输出字节大小保证，大字段重复后可能在执行阶段触发字节限额。

## 4. 如何使用

1. 打开工具工作台中的 **T010 层级数据扁平化映射**，导入 UTF-8 `.json`/`.txt` 文件或粘贴 JSON。非法 UTF-8 或过大文件不会替换当前输入、预测或报告。
2. 填写父记录路径、单数组路径，选择展开或保留。根对象数组父路径留空。保留策略填写额外数组列名，并清除元素范围映射。
3. 编辑每个映射的列名、范围与相对 Pointer。需要更多列时点击 **添加映射列**，删除用 **移除映射N**。空映射路径代表整个父对象/当前元素。
4. 点击 **预测输出与风险**，核对预计行数、数组状态、丢弃路径；**查看完整预测审计** 可展开全部审计。只有成功预测后 **按预测执行扁平化** 才可用。
5. 点击执行，查看分页表或 **查看输出行N**。用 **取消当前操作** 停止解析/预测/执行/导出并重试。
6. 保存完整 JSON，或保存扁平 CSV 并同时保存完整审计 JSON。所有保存调用 `files.saveText({content,extension,defaultName,copyOnly:true})`，且必须有 `saveTextSupportsCopyOnly===true`。旧基础层没有能力时导出按钮禁用；既有目标由基础层独占创建拒绝覆盖，选回输入文件也不覆盖。对话框取消不报告成功。

## 5. 产出与可复现例子

最短验收输入：

```json
[
  {"id":"P1","items":[{"sku":"A"},{"sku":"B"}]},
  {"id":"P2","items":[{"sku":"C"}]}
]
```

父路径留空，数组路径 `/items`，展开策略。映射 1：列名 `parent_id`、父记录、`/id`；映射 2：列名 `sku`、当前数组元素、`/sku`。预测为 **2 父记录 → 3 输出行**，结果按来源顺序为：

| parent_id | sku | 父序号 | 原文父行 | 数组序号 | 元素原文行 |
| --- | --- | --- | --- | --- | --- |
| P1 | A | 1 | 2 | 1 | 2 |
| P1 | B | 1 | 2 | 2 | 2 |
| P2 | C | 2 | 3 | 1 | 3 |

UI 自带 **载入两父记录三元素示例**，直接点击预测、执行即可复现。该示例外包 `/records`，多一个父范围 `/tags` 映射到 `tags_json`；结果依然 3 行，P1 两行的该列均为 `["x","y"]` JSON 字面量。两条 `/note` 和根外 `/metadata/version` 共 3 个未映射叶路径完整进入审计。不会把 tags 按元素位置配对。将策略改为保留、手动移除 `sku` 元素映射后，预测/输出为 2 行，额外 `items_json` 列保留各父完整数组。

边界输入：

```json
[{"id":1},{"id":2,"items":null},{"id":3,"items":[]},{"id":4,"items":[null]}]
```

默认根父路径、`/items`、展开、父 `/id` 与元素空路径映射，输出 4 行。前 3 行元素缺失，后 1 行是真正存在的 null；审计和 `missingColumns` 明确区分。

完整 JSON 为版本 1 的 `{feature,version,columns,rowCount,audit,rows}`，每行有 `{source,values,missingColumns,jsonLiteralColumns}`。单独审计 JSON 包含版本、源名称、配置、政策、逐父/元素丢弃路径和预测数，无数据表。

CSV 为 BOM/CRLF 的扁平表，9 个系统列分别是 `__source_name_json`、`__parent_row`、`__parent_line`、`__array_index`、`__element_line`、`__array_state`、`__element_present`、`__missing_columns_json`、`__json_literal_columns_json`，其后为映射列。每个单元格是 JSON 编码后的内容，再按 CSV 双引号规则转义：数值 `1` 和字符串 `"1"` 区分，缺失单元格是 `{"present":false}`，null 是 `null`；普通字符串 `"{\"present\":false}"` 仍可区别。JSON 字面量对象/数组单元格是字符串，须配合标记列理解。该格式有意保留类型及缺失信息，不是未经编码的普通文字表格；字符串公式开头被 JSON 双引号包住。CSV 本体不放风险审计，请配套保存审计 JSON，或直接用包含二者的完整 JSON。
