# T007 XML 数据查询台

## 1. 功能内容

粘贴或选择本机UTF-8 XML，先解析并查看元素/属性/节点数量与层级，再执行XPath 1.0。支持命名空间别名、元素/属性/文本节点列表以及数字/字符串/布尔标量结果，输出节点描述路径、序列化内容及完整查询报告。

## 2. 为什么需要

嵌套XML用普通文本搜索难以表达“价格大于10的商品”等结构条件，在线查询台还需要上传数据。此功能在本机解析和查询，统一保留表达式、别名与节点路径方便复核；超限或不支持的输入明确拒绝，不把一部分结果当成完整结果。

## 3. 实现方式

在任何XML解析器调用前拒绝DOCTYPE/DTD/ENTITY声明及除开头XML声明以外的处理指令；这是保守文本检查，注释或CDATA中出现这些字样也会拒绝。拒绝DTD包含内外实体，不依赖解析器对外部实体的默认行为。

生产渲染器以DOMParser application/xml构造离屏源文档，再用Document.evaluate ANY_TYPE执行宿主XPath 1.0。源DOM从不插入活动页面；匹配项以公共h()的文本节点/pre显示，源SVG/HTML标签、事件属性不成为可执行页面。不会解析/应用XSLT或XInclude，不解引用XML中的资源URL。XPath没有网络函数或任意JS执行入口。名称空间字典只查询自有键，xml前缀固定标准URI。

节点路径使用`/{namespaceURI}localName[n]/@{namespaceURI}attr`之类的DOM描述，区分同名兄弟及命名空间；不是可直接粘贴执行的XPath。DOM统计含文档、属性和空白文本节点，CDATA独立按DOM节点统计，可能与XPath文本节点合并模型不同。

输入≤1MiB、5000 DOM节点、32层、单元素100属性/名字128字符；XPath≤1024 UTF-8字节，别名最多20个/4096字节。结果最多500匹配，每匹配文本/序列化各≤64KiB，结果合计2MiB，完整JSON报告≤8MiB，超限阻止整个查询，无部分结果。树预览前100项明确标示，完整路径树在JSON里。数字用字符串保存XPath双精度结果，包括NaN/Infinity，不提供十进制精确算术。

XML解析/XPath原生同步执行，不能中途取消，复杂表达式可能耗时；输入/节点/表达式限制控制规模，不承诺执行时间上限。文件读取异步结果以世代编号隔离，源编辑、暂停或销毁后旧读取不会回填。输入/文档仅当前面板，不写全局配置。

## 4. 如何使用与具体例子

1. 搜索T007，点击“载入三条商品示例”，工具解析catalog内A价格8、B价格20、C价格12。
2. XPath默认`//item[@price > 10]`，点击运行，匹配B和C两节点；展示路径和完整item序列化内容。
3. 改为`count(//item)`返回number文本3；`sum(//item/@price)`返回40；`//item/@id`返回三个属性节点。
4. 有默认命名空间`urn:catalog`时，配置`{"c":"urn:catalog"}`并用`//c:item`；不把空前缀默认映射成XPath的无命名空间名测试。
5. 核对后另存JSON/Markdown新报告。源文本变动需重新解析，表达式/别名变动仅重跑查询。清空按钮移除源及结果，切换功能释放当前文档。

若输入`<!DOCTYPE r SYSTEM "https://example.com/a.dtd"><r/>`，在DOMParser之前拒绝；不请求该地址。读取文件使用严格UTF-8，其他编码明确失败不猜测；XML声明中的编码不会改变File字节解码方式。输入字节统计为当前解码后文本的UTF-8大小，非原文件字节承诺，XML解析也会按规范处理换行和实体。

## 5. 使用产出

JSON包含功能版本、源文本大小/查询/别名、完整节点树与统计、结果种类、全部匹配节点的DOM类型/名称/描述路径/文本/序列化内容，或带种类的标量值；不自动把整个原XML放入报告。Markdown含完整结果和统计记录，输入标签按文本转义。

报告可能包含用户查询到的个人字段值，分享前自行核对。副本保存明确copyOnly=true，已有目标拒绝覆盖；只有ok=true显示成功，取消保留报告。最终路径由原生另存选择，本功能不改写源文件或导出源DOM到活动页面。完整报告限制按JSON验证，Markdown有额外转义开销但在宿主文本上限内。

## 6. 验证与限制

10项模型/适配器测试涵盖DTD/实体在解析器构造前拒绝、处理指令/大小/零字节、别名字典、描述路径/兄弟序号/属性归属、5000节点与32层限制、标量特殊数字、完整迭代与超500拒绝、语法错误及文本转义；另有6基础接口检查。Node测试中的DOM/XPath适配器是模型证据，不冒充真实XML/XPath引擎；真实Electron引擎查询与零网络请求已另验，证据如下。

仅XPath 1.0，不支持2.0/3.1、XQuery、DTD/自定义实体、XSLT、外部schema校验或非UTF-8文件。规范依据：[W3C XPath 1.0](https://www.w3.org/TR/xpath-10/)、[MDN Document.evaluate](https://developer.mozilla.org/en-US/docs/Web/API/Document/evaluate)、[MDN DOMParser](https://developer.mozilla.org/en-US/docs/Web/API/DOMParser/parseFromString)。

浏览器错误检测同时覆盖 Firefox 专用 parsererror 命名空间及 Chromium 嵌入部分文档的 XHTML parsererror。为避免将解析器的部分文档当作完整 XML，本模块保守拒绝这两个命名空间下的 parsererror 元素，即使用户有意在合法 XML 中使用该名称；其它命名空间的同名元素允许。

真实验收使用 Electron 33.4.11、生产工作台/目录发现/preload/IPC/独占文本写入器。DTD 外部地址在解析前拒绝；`<broken>`被 Chromium 部分错误文档识别并拒绝。实际 DOMParser、Document.evaluate 和 XMLSerializer 核对商品 B/C、count=3、sum=40、boolean=true、三项 id 属性、默认命名空间别名、真实 File/DataTransfer UTF-8 中文。SVG image/script 源仅按文本展示，不插入活动 DOM；HTTP/HTTPS 请求监控为 0。实际新 JSON 副本 2840 字节，elements=4、attributes=6、匹配书/笔、B 的描述路径 `/{}catalog[1]/{}item[2]`。证据：隔离集成工作树 `work/electron-smoke-1790969753738/result.json` 和对应文件。配置/保存目标由测试夹具提供，未操作系统对话框或验证打包。
