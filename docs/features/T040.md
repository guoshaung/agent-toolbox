# T040 图片局部标注脱敏

## 1. 功能内容

本地选择PNG/JPEG，在完整原图上拖选实色矩形或编号箭头，也可精确编辑完整坐标JSON。明确生成后，显示真实单层PNG；核对全部区域后另存新目录。矩形采用不透明实色逐像素替换，最后覆盖箭头和编号，不保留遮盖区原像素、可逆模糊或原图层。只有手选区域被处理，不自动检测手机号/邮箱/地址或判断遗漏。

单图8字节–2MiB、边≤4096/≤4194304像素；最多32矩形和20编号箭头。支持常见≤8bit静态PNG、8bit单图灰度/RGB JPEG（SOF0/1/2）；APNG、多图/CMYK/16bit等拒绝。实际ImageBitmap与头几何不一致（例如方向旋转）明确拒绝。原透明图白底合成，输出不保留Alpha透明度。

## 2. 为什么需要

工单、操作说明常要指出多个问题，同时遮住联系方式。编号箭头方便正文引用位置；实色单层输出让用户能检查遮盖确实发生在最终像素上。不能靠降低模糊强度判断是否还能还原内容，也不能把仅隐藏编辑图层当作可分享的成片。

## 3. 实现方式

私有`raster.mjs`有界检查PNG签名/CRC/几何与JPEG段/扫描结构，实际ImageBitmap解码再核对几何。`model.mjs`严格校验完整masks/arrows/color字段、图内整数坐标、数量和#RRGGBB颜色；矩形为[x,x+width)×[y,y+height)，重叠计数采用逐像素并集。

固定独立module Worker使用OffscreenCanvas白底合成源，按列表绘制红箭头与1..n白色编号，然后将每个矩形内RGBA设为指定RGB/Alpha255。实色矩形优先级最高，若与箭头/数字相交，遮住它们也是预期行为。生成新PNG后真实重新解码，检查整个输出RGBA与渲染缓冲完全相同，并逐像素验证每个遮盖矩形。无原图层/来源元数据迁移；新编码器可能写自己的色彩块，不承诺彻底消除所有生成文件元数据。

线程最长15秒、每次实际图像预览5秒，PNG≤2MiB，任何处理/完整回读/预览失败没有可导出的部分结果。不请求网络、不存配置、不运行系统命令或自动写图。取消终止自己的Worker并废弃迟到结果，保留源供手工重试；离开清除源字节/画布/产物，返回不自动处理。源码FileAPI读取有生命周期票据，离开期间迟到读取不恢复原图。

目录保存经生产exportBundle、copyOnly、新目录独占/wx、全字节SHA核验；PNG及报告各≤2MiB。JSON也可独立生产文本副本桥另存。只认ok===true；既有文件/目录/来源拒绝覆盖，取消/失败保留完整预览。打包SHA等待期间离开不继续发写入IPC；不声称已开始的磁盘动作可物理撤销。图片里的其他隐私及报告原文件名仍需自行检查。

## 4. 如何使用

1. 打开T040，选择一张截图。查看完整原图及实际几何，没有自动生成或导出。
2. 选择“实色遮盖矩形”，从区域一个角拖到另一个角；两个终点都包含。选择“编号箭头”，从编号起点拖向目标；箭头按列表编号。
3. 核对/修改完整JSON。示例：`{"masks":[{"x":110,"y":50,"width":180,"height":38}],"arrows":[{"x1":30,"y1":40,"x2":90,"y2":40}],"color":"#111111"}`。坐标为实际图像像素，不是显示缩放后的屏幕像素。至少一个遮盖或箭头；删除数组项可撤销该规则。
4. 明确点击“生成并预览完整标注遮盖PNG”。查看实际新PNG；修改JSON立即废弃旧结果，需要重新生成。
5. 勾选已核对实际PNG全部区域与遗漏，另存完整PNG和清单到全新目录；也可只存完整JSON报告。分享时使用输出PNG，原图预览和原文件仍含原内容。

很小的图或靠边标注可能裁到编号/箭头，先检查完整预览并调整坐标；本版没有自动排版避免重叠。矩形遮盖会覆盖与它相交的编号，要移动箭头保持可读。

## 5. 使用后产出

新目录含`annotated-redacted.png`与`annotation-report.json`。PNG保持源宽高，白底不透明单层，实色区不含原像素。报告含源名称/大小/SHA/几何/格式、全部矩形与箭头编号/坐标、颜色/绘制样式/顺序、遮盖并集像素数、输出大小/PNG SHA/RGBA SHA及有限作用范围，不复制原手机号文本或元数据正文。源文件不变。单独JSON没有图片，不能作为已分享图片被遮盖的证明。
