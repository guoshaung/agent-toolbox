# T072 PATH 命令冲突诊断

## 1. 功能内容

输入命令名、完整 PATH 和 PATHEXT 快照，逐项检查同名文件，保持目录顺序和 Windows 扩展名顺序，列出不同路径匹配、规范目录重复、未解决项和首个观察到的匹配。可主动读取本应用进程继承的 PATH/PATHEXT，读取快照本身不扫描文件。分析直接执行只读元数据检查，不执行命令，不修改系统设置。

所有候选明确标记“未认证可执行性”。空项、相对项、Windows UNC/设备路径等未支持项原样保留；前置未知会影响首项结论。零字节文件和 WindowsApps 位置只提示疑似占位或执行别名，真实别名开关及文件可用性仍未知。

## 2. 为什么需要

多个 Python/Node 安装、重复目录和旧环境快照会让同名命令出现多个候选。单独看到某个版本无法解释搜索顺序；本工具把给定快照的全部候选和未知并列，便于人工核对预期安装路径。

这份文件观察不能证明终端实际选择。[PowerShell 命令优先级](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_command_precedence?view=powershell-7.5)还包括别名、函数和 cmdlet；本项不连接用户 Shell，也不读取 Shell 缓存、文件关联或执行策略。应用继承环境不等于另一终端或当前注册表值。报告据此限定优先项结论的范围。

## 3. 实现方式

`model.mjs`验证固定快照格式并生成 JSON/Markdown；`host.cjs`由公共可信 Host 加载，仅支持 `snapshot`/`analyze`，使用 Node `realpath`、`stat` 和 `lstat`；`index.js`在工作台展示完整表格与预览。没有 child_process、网络请求、目录 readdir、递归扫描、文件内容读取或文件写入。元数据语义参考 [Node 20 文件系统文档](https://nodejs.org/download/release/v20.18.3/docs/api/fs.html)。

命令名1–80位 ASCII 字母数字/点/下划线/连字符，禁止路径、参数、通配符和空白。Windows 无点命令按明确提供的 PATHEXT 查名字，有点命令只检查精确名字；此规则是本项支持域，不复刻全部 Shell/SearchPath/where 解析。PATHEXT≤512字节，最多16个唯一扩展名，无空项或空白；非 Windows 必须留空，仅查精确命令名。

PATH≤24KiB UTF-8、最多128项，每项≤4096字符，Windows分号、其它平台冒号拆分。完整成对 Windows 引号剥除且保留原项。目录必须明确绝对路径；不展开环境变量、波浪号或隐含 cwd。Windows只接受驱动器绝对路径；显式 UNC/设备路径不访问，映射驱动器的实际存储本地性未知。Unix绝对路径中的特殊字符按字面处理，不进行 Shell 展开。

规范化后检查目录身份，规范目录按 Windows 大小写无关/Unix大小写有关去重，重复项保留原顺序并指出首次项。只对固定候选名逐个 lstat，最多2048次文件检查。最终候选符号链接只记录存在、不跟随，目标与可执行性未知；目录链接经 realpath 规范化后访问。Unix执行位只是元数据，不验证 ACL、挂载选项或脚本解释器。目录前后 realpath/dev/ino/mtime 普通变化检测会标记不确定；不是文件锁或恶意竞态防护。

每窗口串行，最多32窗口、每窗口128个唯一任务ID。首个 await 前占用任务，取消只作用于所属窗口任务；销毁使任务停止继续。10秒协作期限在文件 await 之间核对，不能强制中止 OS 文件调用或保证硬10秒返回。当前 OS 调用未返回时保留忙槽，后续任务不能无限叠加。中断报告保留已观察前缀、当前取消/期限项及全部后续 not_run 项。

完整 JSON/Markdown 各≤2MiB，超限整份拒绝、不截断；包含全部原快照、条目、检查、匹配、重复、未知、来源类型、开始结束UTC与建议。来源字段是快照说明，不是外部来源认证或可信时间。输入与报告仅内存保留，不写配置。编辑废弃旧报告，隐藏/离开请求取消并清报告，返回不自动分析；迟到回调不能恢复旧界面。

## 4. 如何使用

1. 打开工具工作台中的 PATH 命令冲突诊断。
2. 填命令名，例如 `python`；主动读取本应用环境，或粘贴自己核对的 PATH/PATHEXT。手动编辑后来源标为用户快照。
3. 点击“分析完整PATH快照”。核对全部路径、重复来源、首个观察匹配与前置未知。只输出建议，需要调整环境时自行复核。
4. 有较慢文件调用时可取消；等待当前 OS 调用结束，不能把请求取消当作立即中止证明。
5. 预览完整JSON或Markdown，再“保存已预览PATH报告新副本”。只有生产能力严格为true才允许保存，只有 `ok===true`宣布成功。`copyOnly:true`和生产writer的 `wx`拒绝既有文件；失败/取消保留预览。

## 5. 使用后产出与具体例子

Windows准备两个目录 `C:\Demo\A`、`C:\Demo\B`，各有 `demo.EXE`。输入命令 `demo`、PATH `C:\Demo\A;C:\Demo\B;C:\Demo\A`、PATHEXT `.EXE;.CMD`。报告列两条不同路径匹配，首个是A中的文件，第3项为重复规范目录并引用第1项；不执行这两个文件。

把 PATH 改成 `C:\Demo\B;C:\Demo\A`重新分析，首个观察匹配变成B。改成 `;C:\Demo\B;C:\Demo\A`，首项空目录保持未解决，前置未知为true，不能保证B为完整搜索优先项。

若增加零字节 `C:\Demo\WindowsApps\demo.EXE`，只输出 `zero_byte_possible_placeholder` 与 `possible_app_execution_alias_location`，不判定执行别名一定启用、禁用或不可用。导出 `T072-path-command-report` v1 JSON及含完整JSON的Markdown，全部候选均 `executableVerified:false`。报告含本地路径，分享前应按源资料范围查看。
