# E038 拉伸休息卡

## 1. 功能内容

纯本地的2至5分钟休息安排：选择坐姿或站姿，查看项目原创SVG插图，主动开始、暂停、继续、跳过或中断。每次包含肩部放松、手腕轻动、椅上换姿（坐姿）或起身走动（站姿）三张卡。三张卡各分配相等时段，3分钟就是60+60+60=180秒；每卡可以轻动几次后安静休息，不要求持续拉伸60秒。

界面同时显示当前卡剩余时间、全计划剩余时间、每卡实际计时和状态，以及完成/跳过数量。计时到期只标“计时完成”；不检测身体动作，不声称用户实际完成活动。跳过单独记录，永不计完成。支持完整JSON和Markdown新副本，没有摄像头、音频、AI、积分、网络请求或定期自动提醒。

## 2. 为什么需要与活动范围来源

给工作间隙一个能自主停止和调整的简单安排，减少为选择活动而继续盯屏的时间。所有动作采用舒适范围内的轻柔小幅活动，不加入负重、强拉、手压头、单脚平衡或康复处方。不适可以暂停或跳过；已有伤病或不确定是否适合时先询问专业人员。界面只保留这两句简短提示，不制造长篇警告，也不许诺疗效、诊断姿势或评价体能。

2026-10-03 已核对权威主来源：[NHS Sitting exercises](https://www.nhs.uk/live-well/exercise/sitting-exercises/)说明温和坐姿活动、稳固无轮椅子、脚落地和舒适活动范围；[NHS Wrist pain](https://www.nhs.uk/symptoms/hand-pain/wrist-pain/)支持轻柔手腕活动，并明确不要自行诊断或进行引起疼痛的活动；[HSE Work routine and breaks](https://www.hse.gov.uk/msd/dse/work-routine.htm)支持离开工作站、走动或改变姿势。这里将这些原则简化为日常休息卡，插图和措辞为项目自制，未复制官方图片或把医学诊疗动作转成通用处方。2至5分钟是用户选择的程序安排，来源没有规定这组时长对所有人都合适。

## 3. 实现方式与精确计时、容量边界

`model.mjs` 的独立session状态机使用可注入单调clock，生产默认为 `performance.now()`；以毫秒差值累计运行时间，不以200ms界面刷新次数扣时间。模型拒绝非法时钟，并对时钟倒拨取已见最大值，不产生负计时。暂停记录当前差值并停止运行基准，继续重新设置基准，暂停期间完全不扣卡片时间。所有状态都是当前实例的有限源数据，不从壁钟或时区字符串猜测时间。

纯模型每次推进最多遍历三张卡，跨多个期限或极大前台时间差也有界，不逐秒补tick。到期自动切到下一卡，最后一张结束停止定时器。展示秒数向上取整，实际累计保留完整毫秒；总时长和结束判断不受显示取整影响。前台若事件循环长时间阻塞，下一次采样按真实单调时间补算，可跨卡；结果仍只表示计时到期，不能证明各活动已经看见或做过。隐藏窗口和deactivate在事件收到时暂停并清interval；返回或activate不自动开始。destroy停止interval、移除按钮和visibility监听、清空UI与当前实例记录，无RAF。

跳过保留该卡已经计时的毫秒，并单列未用时长。已跳过卡不再占后续倒计时，因此实际休息可短于计划总时长。若点击跳过恰好发生在上张到期时，模型核对界面所示卡序号；已经切卡则拒绝误跳下一张，并提示核对。中断保留当前卡partial计时，后续未开始的卡保持pending，绝不改成完成。对任意结束记录：`activeMs + skippedUnusedMs + interruptedUnusedMs = plannedMs`；运行/暂停记录还含 `remainingMs`，四项合计为原计划。

状态字段 `pending/active/completed/skipped/interrupted`分别对应未开始、进行中、计时完成、跳过、中断；session的 `ready/running/paused/finished/interrupted`单独表示流程。`pausedMs`和`pauseCount`独立记录暂停，completed只代表期限满足。每次结束只进入缓存一次，缓存最多10次，达到上限时拒绝生成下一次，提示先导出或勾选清空；不默默删旧记录。报告的 `current` 是当前计划快照，`history`只包含此前结束记录，去掉当前结尾在缓存中的重复快照，不把一次休息报告成两次。

记录和设置仅在当前模块内，不写config/localStorage/sessionStorage。重新加载或销毁不恢复，请先导出；deactivate仅暂停并保留当前实例。设置控件更改不会修改当前计划，必须显式“生成新计划”。未开始的原始计划可直接替换；已经开始/跳过的计划需要勾选确认，中断结尾也会保留。没有JSON导入或用户代码执行。最多三张卡、10个有限结束快照加当前计划，输出不截断。

## 4. 使用步骤

1. 在娱乐工作台打开“拉伸休息卡”，选择坐姿/站姿、2/3/4/5分钟，点击“生成新计划”。默认已有坐姿3分钟预览，没有自动计时。
2. 看清插图和短说明，再点击“开始 / 继续”。按自己的节奏轻动几次，其余时间可休息；不必重复到耗尽整张卡。
3. 点击“暂停”可停住倒计时；“开始 / 继续”只累计继续后的时间。切走工具或隐藏窗口也暂停，返回后主动继续。
4. 不想做某张卡，点击“跳过当前卡（不算完成）”。记录中出现skipped和已花时间，完成数量不增加。第三张跳过后仍可以结束流程，结果为finished-with-skips。
5. 提前结束或替换已经进行的计划，先勾选确认，再点击对应按钮。仅结束流程，不把未到时活动当完成。结束的10次记录容量用完时，先导出，勾确认后“清空结束记录”；当前计划仍保留。
6. 点击“导出完整JSON记录”或“导出完整Markdown记录”。另存前暂停，原生保存期间锁住流程/设置，保存成功、失败或取消都不会自动继续。选择一个新文件名，已有目标拒绝。若离开/销毁时保存仍在等待，后到结果忽略，已经写出的副本不自动删除。

## 5. 产出和可复现例子

`stretch-break-record-copy.json`包含schema1、当前session、此前history、全部三张卡的说明/计划毫秒/实际毫秒/状态、计时完成/跳过/中断/未开始计数、暂停时长和次数、剩余与未用预算、口径和官方来源。`stretch-break-record-copy.md`包含完整当前/此前卡表与相同时间口径，易于阅读。只调用 `files.saveText`，预先检查 `saveTextSupportsCopyOnly===true` 并要求 `copyOnly:true`；只有 `ok===true`报告成功，取消独立提示，失败和partialPath供人工核对。

例一：选站姿3分钟生成，三张各60秒，共180秒。开始后20秒暂停，等10秒再继续：暂停期间仍剩160秒，计时完成的墙上时点在开始后190秒（180秒运行+10秒暂停）。最终plannedMs=180000、activeMs=180000、pausedMs=10000、完成3、跳过0。这组精确数值由独立模型/组件clock oracle验证，不能把测试注入时钟说成真人已经活动三分钟。

例二：站姿3分钟，第一张60秒计时结束；立即跳过第二张手腕卡；第三张60秒到期。报告状态 `[completed, skipped, completed]`，计划180秒、实际计时120秒、跳过未用60秒，完成2、跳过1，outcome=finished-with-skips。JSON的三行与Markdown三行都必须一致。若途中只用了第一张15秒就跳过，它保留elapsedMs=15000和剩余45秒未用，仍不算完成。

例三：开始后主动离开，再返回，不应看到时间继续扣减；必须点继续。全跳过也能结束，但完成数量0/3、跳过3/3、实际计时0，不能显示“全部动作已完成”。
