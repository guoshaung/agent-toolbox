# L058 综合作业验收包

## 1. 功能内容

对一次用户真实作业，人工设置文件存在、JSON字段、字数、人工证据提交四类有限量规；用户选择本地产物和证据附件，执行后逐条给出通过、失败、解析错误、未知／待补。报告保存完整任务、人工来源、量规版本及摘要、原文件字节大小与SHA-256、逐条原因、失败ID和附件清单。

完整验收包导出到新的目录，包含原字节产物、原字节证据附件及完整JSON／Markdown报告。另可单独导出报告；报告副本不含文件字节，不能冒称包含附件的整包。结果只陈述四类条件，没有总能力分数、自动认定能力、AI语义评分或任意脚本执行。

## 2. 为什么需要

完整作业通常包含写作、结构化数据和人工证据。如果一个数据字段遗漏，报告文件的存在、字数条件和已提交证据应继续显示各自结果，而不是整份结果都被覆盖为失败。保存量规快照和原字节摘要，让用户能把本次检查与实际交付的副本一同复核。

量规由用户提供，来源空项明确未知；本地版本号与摘要不是可信外部注册、不可篡改签名或作者身份认证。人工证据通过只表示说明及指定附件已提交，不证明其内容正确、来源真实或学习能力已达成。文件存在仅指本次选定集合，不能据未选文件推断其在电脑上不存在。

## 3. 实现方式与范围

`model.mjs` 提供严格schemaVersion1输入、量规修订、原字节摘要、四类独立判断及完整包生成。`index.js` 提供真实任务与来源表单、可编辑量规卡片、两类多文件选择控件、教学例、结果矩阵、筛选／分页、完整报告预览及整包导出。`style.css` 使用项目实际主题变量。文字均用文本节点，Markdown转义HTML并调整代码围栏，不执行输入代码。

四类规则固定如下：

- 文件存在：按文件名NFC规范化及不区分大小写匹配用户选定产物，只验集合中存在，不扫描目录或访问任意路径。
- JSON字段：严格UTF-8解码，再解析顶层JSON对象，只检查顶层自有字段是否存在，null／false／0／空字符串也算存在，不检查值。数组或标量顶层拒绝；字段名不支持路径语义，点号是字面字符。禁止原型保留字段名。重复JSON键按JSON.parse后项覆盖并在细节中说明；只验字段存在。解析后深度≤32、值节点≤20,000，非有限数拒绝。文本／JSON解析失败只该规则为error，不抹掉其它通过项。
- 字数：严格UTF-8文本，按Unicode码点统计，剔除ECMAScript正则`\s`空白。CR/LF、空格、制表符不计，标点和完整emoji各计1；不是UTF-16单位数，也不是自然语言分词或写作质量。上下界包含边界，须明确0–262,144整数；超界为fail，UTF-8／非法控制字符等解码问题为error。
- 人工证据提交：要求非空人工说明、至少一个指定附件且附件都在选定集合。满足时pass仅表示提交条件齐全；缺说明／附件为unknown并列待补，不能推断内容正确或能力不合格。附件可为任意有限二进制，不自动打开、播放或执行。

本地量规版本1–1,000,000，规则编辑／增删递增；任务和来源编辑清旧报告，报告保存量规快照、版本和SHA-256。不保存长期历史，旧版本需要用户导出新副本保留。本次最多40规则，说明最多200码点、人工说明最多1,800，任务2,000，来源名160／位置320。文件名是安全单段、最多120UTF-16单位，禁止路径遍历、保留名、不安全字符及角色内NFC／大小写重名。

产物最多8份、每份≤256KiB；附件最多8份、每份≤128KiB；原字节总量≤3MiB。读取前检查文件声明大小，读取后核对实际长度，原字节再次摘要校验；同一批有错整批拒绝并保留前次成功集合，不部分载入。每个完整报告≤2MiB，整个输入≤256KiB；容量超限整份拒绝，不截断。

## 4. 使用步骤与恢复

1. 填写真实任务和人工量规来源，为规则选择四类之一。文件条件填目标单段文件名；JSON填顶层字段；字数填界限；人工证据填写说明和每行一个附件名。
2. 通过「选择产物文件」与「选择证据附件文件」选定本次集合。新选择替换该角色集合，原文件只读。清除选择只释放本次载入，不删除磁盘文件。用户也可点击「载入教学产物（缺result）」使用明确标记为自编教学的内存字节。
3. 点击「执行四类验收」，逐条查看pass／fail／error／unknown。量规、任务、来源或文件改变后旧报告失效，必须主动重验。
4. 翻页或筛选只改变显示，每页10条；完整预览及副本始终保留全部规则与附件清单。
5. 「导出报告JSON／Markdown」只保存完整报告；「导出完整验收包（新目录）」保存所有原字节产物／附件及两个报告。生产桥必须分别声明严格防覆盖能力，始终传copyOnly:true，只有ok===true宣告成功。新目录已存在则拒绝，取消不算成功。

整包目录结构是`products/<原文件名>`、`attachments/<原文件名>`、`report.json`、`report.md`，角色目录分开避免报告名冲突。使用现有生产exportBundle writer，对每个文件验证规范Base64及SHA-256，创建全新目录并以wx写入；不覆盖已有目录。产物和附件不转码、不压缩、不改写。

全局配置只保存schema1任务、人工来源及量规，不存原文件字节或派生报告。完整UTF-8草稿≤64KiB，超限不写配置并提示导出；关闭只能恢复较早合法输入。恢复检查版本和容量，必须重新选择产物和附件，不自动验收。保存队列合并最新输入且隔离旧回执。读取、摘要和验收可取消；编辑、隐藏、离开、销毁废弃迟到结果，销毁释放原字节。浏览器已开始的arrayBuffer读取无法物理中止，只丢弃其返回值；已开始的副本写盘不能撤回，不把迟到成功写回新界面。

## 5. 产出与可复现例子

默认四类量规要求：R001存在report.md，R002在data.json中有顶层result，R003报告字数10–100，R004有人工说明和proof.txt附件。点击「载入教学产物（缺result）」再执行：

```text
report.md：# 综合作业\n学习笔记与数据解释。
data.json：{"value":1}
proof.txt：用户声明已核对产物出处；不是能力证明。
```

报告字数是15。结果恰为 **R001通过、R002失败、R003通过、R004通过**，合计通过3／失败1／错误0／未知0，失败ID仅R002。数据字段失败不影响其它通过项。把R002字段改value后量规版本递增、摘要改变，重新执行四条都通过；不是能力认证。

将data.json变成`{bad`，仅R002为解析错误，文件存在和其它项继续通过。`{"result":null}`通过字段存在条件。人工说明清空后R004为未知，不伪造证据。二进制附件proof.bin仍可作为指定附件，完整包保存其原字节；这不表明其内容支持人工说明。

Unicode例`🙂甲\r\n乙\t。　丙`剔除换行、制表符和全角空白后计5，最小／最大都为5时通过。该计数没有分词或阅读质量含义。

JSON／Markdown报告包含完整量规、人工输入、版本、摘要、文件元数据和逐条结果；整包另含全部产物及附件的原字节。导出可能含用户原始作品和证据，不是脱敏摘要，不根据筛选删除失败项、附件或其它记录。
