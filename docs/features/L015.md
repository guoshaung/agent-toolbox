# L015 锁与竞态重放

## 1. 功能内容

在“学习 → 计算机原理交互实验”中，用两个固定线程T1/T2、一个共享计数器、每线程一个本地寄存器R和一个非重入互斥锁构建有限教学模型。用户编辑两个逐行指令脚本和初始计数器，人工选择下一个线程执行一条指令，查看共享值、寄存器、PC、锁所有者和每一步前后状态。

只支持READ/WRITE/LOCK/UNLOCK，提供无锁及互斥两个可编辑模板。界面记录执行、阻塞与失效原因，识别未保护读写冲突和陈旧写入，完成后与同脚本串行基准比较。支持重置、历史步骤查看、完整JSON/Markdown副本导出。全部本地、无AI、登录、网络或外部运行时；不执行用户JS，不创建真实线程，不新增共享依赖。

## 2. 为什么需要

共享计数器“加一”通常包含读值、计算和写回；两个线程都读到旧值后分别写回，会把两次预期增量合成一次。直接运行线程程序难以稳定复现调度，也容易把“有锁变量”误解为任何读写都自动受保护。本功能让用户指定确切交错，并查看锁是否真正由当前线程持有，复现丢失更新及其修复。

新增能力是抽象共享内存状态的确定性单步重放与冲突证据，区别于practice执行真实代码或AI解释。历史选择只查看证据，不回滚当前执行状态。

## 3. 实现方式与明确规则

`model.mjs`解析有限四指令，并通过不可变状态转移返回每次尝试的前后快照。`index.js`用现有`h`创建真实脚本输入、线程操作按钮、当前PC高亮、寄存器/锁展示与轨迹表；`style.css`只作用于本功能。没有eval、动态函数构造或任意脚本执行，字符串只通过表单值或文本节点呈现。

- 每行一条独立指令，不分大小写、忽略空行；不支持参数、表达式、注释、分号或其他操作。每线程1～16条指令，脚本最多4096 UTF-8字节；初始计数器是±1000000内的十进制整数。固定两线程，每次选择执行一条原子指令，不模拟真实硬件内存模型。
- READ：共享值读入当前线程R，并记录共享写版本。WRITE：共享值写为当前线程R+1，R保持原读值；必须先READ初始化。没有通用ADD指令或其他算术。重复WRITE同一个R可能写回同值，不能用成功WRITE次数直接虚构串行理想值。
- LOCK：锁空闲时获得所有权；由另一线程持有时阻塞，PC、R和共享值均不变，可在解锁后人工重试。锁非重入：持有者重复LOCK为失效指令。
- UNLOCK：只有所有者能执行；无人持锁或非所有者解锁均失效。失效会记录原因、停在原PC并将该线程标为fault，需重置或编辑脚本；不能跳过错误继续执行。已完成/失效线程不可继续步进。
- 锁仅约束LOCK竞争，不会自动阻挡未持锁线程直接READ/WRITE。脚本必须把共享操作放在LOCK/UNLOCK之间。完成或失效不会自动释放锁；所有者停下但锁仍占用时显示警告。单个锁没有一般性多锁死锁检测，仅指出当前无可推进线程或锁未释放，不自动恢复。
- 全部尝试最多128步，包含成功、阻塞、失效；上限后禁用步进，保留完整轨迹用于导出或重置，不截断旧记录。有效指令总数最多32，额外步数只用于有限阻塞重试。
- 未保护冲突按已经发生的轨迹配对：跨线程访问同一共享值、至少一个WRITE、至少一次未持有该互斥锁。每对记录两个具体步骤/线程/指令。它是保护缺失提示，不是对真实语言happens-before或数据竞态的判断；无锁串行也会提示冲突，但可能没有丢失更新。
- 陈旧写入指WRITE引用的READ版本已落后于当前共享写版本。记录读步骤/读值/读版本、当前版本、覆盖前值、实际写值、相对当前值加一的增量缺口。自身重复WRITE也可陈旧，陈旧提示与最后的串行差值分开，不等同于丢失更新结论。
- 串行基准固定T1整段执行后T2整段执行，使用实际同脚本语义、初始值和锁规则。若该基准存在失效指令、阻塞或未释放锁则不生成理想值。只有两线程均执行完且串行基准有效，才计算串行值−当前值；差>0显示“丢失更新差”，其他结果显示实际差。它是一个具体基准，不证明任意自定义脚本的所有串行顺序等价。
- 配置只保存`schemaVersion:1`脚本及初始值草稿；不保存寄存器、调度、轨迹或锁状态。写入及恢复都检查脚本容量/类型，并按`TextEncoder`测完整JSON UTF-8大小，≤64KiB才保存；恢复先检查整个存储对象的版本和体积。空行或不合法语法可以作为草稿恢复，开始时再做解析。超限明确不保存，关闭只能恢复较早草稿，须导出完整JSON保存当前内容。
- 修改初始值/脚本立即清空旧状态，250ms延迟保存草稿；切走/销毁清除定时器并尝试保存。没有自动重放定时器或后台线程；已销毁组件不响应异步保存/导出消息。开始/重置回到当前草稿的初始状态，不保留旧轨迹。
- JSON/Markdown检查基础层`files.saveTextSupportsCopyOnly`，通过`content`和`copyOnly:true`创建新副本，拒绝覆盖已存在目标。Markdown转义HTML与分隔字符；所有DOM替换均过滤null和嵌套数组。

## 4. 使用步骤与可复现例子

默认无锁模板初始0，两个脚本均为`READ`、`WRITE`。点击“开始 / 重置重放”，再严格按T1、T2、T1、T2点击“执行下一条”：

|步骤|操作|T1的R|T2的R|共享值|说明|
|---|---|---|---|---|---|
|1|T1 READ|0|未初始化|0|T1缓存读值0|
|2|T2 READ|0|0|0|T2也缓存读值0|
|3|T1 WRITE|0|0|1|写R+1=1|
|4|T2 WRITE|0|0|1|陈旧读版本0覆盖版本1，仍写1|

此时两线程完成，最终1、串行理想2、丢失更新差1。第4步陈旧记录引用步骤2读0；未保护冲突有3对，分别步骤2↔3、1↔4、3↔4。用“查看步骤1”看到当时共享0的快照，但顶部当前共享仍1，证明历史查看没有回滚。

点击“载入互斥模板”，脚本均为`LOCK → READ → WRITE → UNLOCK`，再开始。选择线程顺序`T1、T2、T1、T1、T1、T2、T2、T2、T2`：第1步T1拿锁；第2步T2的LOCK阻塞，PC仍在LOCK；T1随后读0、写1、释放；T2重试拿锁，读1、写2、释放。最终2、串行理想2、未保护冲突0、陈旧写入0。

再重置无锁模板并按`T1、T1、T2、T2`执行，最终也为2，但未保护冲突仍3对，界面不宣称丢失更新。这是“未保护冲突提示”和“实际丢失更新”之间的可复现区别。

要检查失效指令，把T2脚本改为`UNLOCK`，T1保留互斥模板。修改会清空旧状态；开始后先选T1 LOCK，再选T2 UNLOCK，出现无权解锁、T2停在原PC，锁仍由T1持有。将T1脚本改为仅`LOCK`，T2改为`LOCK/UNLOCK`则能看到完成不自动释放锁及T2持续阻塞警告。

用户可以编辑有限脚本、选择初始值，自行重复或改变交错。若语法无效，开始时指出具体线程和源行；运行失效则在轨迹中显示原因。导出选择不存在的新文件名，取消不改变状态；重置会清除当前轨迹，重要记录应先导出。

## 5. 产出

界面显示当前共享计数器/写版本/锁所有者、线程R和PC、下一指令、可执行/阻塞/失效/完成状态、串行基准和完成后的差值、未保护冲突及陈旧写入统计。每次人工调度都有前后状态、结果、原因、具体冲突步骤和陈旧写入证据。

JSON包含feature、schemaVersion、modelVersion、导出时间、完整原始草稿、规范化指令和源行、当前状态、固定串行基准、全部调度尝试及前后快照、冲突对和陈旧写入记录。Markdown包含完整脚本、模型规则、结果摘要、轨迹表和每步证据。未开始或编辑后只导出当前草稿，明确无状态轨迹。当前没有报告导入/从历史步骤继续执行；恢复配置草稿后重新开始。
