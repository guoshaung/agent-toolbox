# L009 概念分类重构

## 1. 功能内容

对应 `docs/feature-planning/learning.json` 的 L009：输入用户知识卡和自定义分类规则，输出旧新分类对照、无法归类卡片，支持多标签、交叉集合和规则版本。全部本地完成，无 AI 必要依赖。功能位于学习功能工作台，不读取或整理文献库文件，不生成知识内容。

每张知识卡包含固定 ID、用户标题/原文、逐行标签、逐行手工旧分类、人工来源名和位置。分类草稿包含名称、全部/任一包含条件、排除标签、人工说明和来源。用户冻结草稿得到新规则版本；旧版本只读保留，可复制到草稿再修订。旧侧可以选择当前手工旧分类或任一冻结规则版本，新侧选择冻结版本。

结果并排显示两侧所有类别及成员、未归类卡、完整两两交集和逐卡旧新分类表。总唯一卡数按卡 ID 计算；一张卡可在多个类别出现，成员出现次数单独计算。默认 C1 同时匹配“机制”“实作”，两侧新类别中均出现；三张卡的唯一总数仍为 3，分类成员数是 4。

## 2. 为什么需要与解释边界

教材目录通常只给一个组织方式，用户可能需要按“机制”“实作”等自己的标签重新查看同一材料。L009 保留卡片原文，并允许多重归属，让交叉材料和规则未涵盖的材料都可见。规则版本对照说明改变组织规则后的成员变化，避免把多处出现误算成新增知识卡。

标签、规则、手工旧分类和来源均由用户提供。精确命中不证明概念理解、分类合理、知识正确或学习效果；未归类只表示当前规则未命中。工具不判断正文语义、不推断同义词、不认证来源、不补造出处、不运行用户代码。名称/出处缺失保持未知；报告的 `metadataUnknown` 明确列当前卡及新侧所选规则的缺项，其余问题/版本/规则来源仍原样包含于完整 `input`。

## 3. 实现方式、版本与容量

纯模型在 `model.mjs`，UI 在 `index.js`，样式使用项目真实 `--bg-raised`、`--bg-sunken`、`--line`、`--text`。`meta.json` 由生产 catalog 发现，工作台动态加载。模型版本为 `L009-exact-tag-multilabel-v1`。

标签和手工旧分类一行一项：按 CRLF/CR/LF 分行，`trim()` 后 NFC 规范化，忽略空行、区分大小写。每项最多 40 个 Unicode 码点，重复项整项拒绝，不自动去重或做子串匹配。原文不参与匹配；标签 `机制学` 不会命中 `机制`。包含集合 `I`、排除集合 `E` 和卡标签 `T` 的规则为：全部方式要求 `I ⊆ T`，任一方式要求 `I ∩ T ≠ ∅`，两者都要求 `E ∩ T = ∅`。每类冻结时必须至少有一个包含标签，空条件不会匹配全部；同一规则包含与排除标签相交时拒绝。

每类别成员按当前卡输入顺序列出。全部两两交集保留，包括空交集；一张卡属于三类时，分别出现在三个二元交集中，不将三个交集当作三张唯一卡。手工旧分类按当前卡中首次出现顺序生成组，最多 8 个不同旧分类名。

冻结只追加完整规则快照，ID/顺序号递增，不修改既有版本。版本含人工版本名、说明、问题来源快照和每规则来源；没有可信外部时间戳/签名，不是防篡改证据。卡、规则 ID 删除后不复用；复制旧版本只替换规则草稿，已有版本和当前对照选择保留。删除卡、删除草稿规则、复制覆盖草稿、整体替换教学例需要明确确认；普通分析直接执行。

**版本只冻结规则，不冻结卡片历史。** 两个版本总是对同一份当前卡内容复算。编辑卡片后，两侧都会变化；报告保存分析当时的完整当前输入与全部规则版本，不声称恢复某历史日期的卡。当前卡片、手工旧分类、问题信息和规则草稿仅保存当前修订号，不是不可变编辑日志。版本名/说明的新增表单值属于未冻结临时输入，不随重载恢复。

最多 30 卡、8 条草稿分类、12 冻结版本；每卡标签/旧分类及规则包含/排除各最多 16 项；标题 80 码点、卡原文 1200、分类名 60、规则/版本说明 300、背景 900、来源名 120/位置 240。拒绝非法控制字符和孤立 UTF16 代理项。原文保留用户字符串，浏览器 textarea 依标准将 CRLF/CR 规范化为 LF，不宣称字节级文件导入保真。本功能没有原文片段锚点，不计算或猜测句子/字符范围；真实编辑“甲😀”时 caret 为 UTF16 偏移 3，模型长度预算按码点。

`schemaVersion:1` 的**全部当前输入及所有冻结版本** UTF8 JSON 预算为 64KiB，修改/新增/恢复均完整校验；超限整项拒绝，旧输入和历史不截断。完整 JSON/Markdown 各 1MiB，超限整份失败。派生分类和交集不写配置，恢复后主动重算。

逐行标签控件保留当前原始输入以便连续键入换行，有效内容即时存为规范标签数组。重复/超限等无效逐行文本只保留在当前控件，最后有效数组仍可保存；该无效输入未修正前，分析、冻结和导出都会阻止，避免拿旧数组假作当前结果。窗口重载只恢复最后有效输入，未提交的无效控件文本不恢复。复制/删除/整体替换确认后清理相应临时控件文本。

配置保存使用单通道串行队列和最新待保存值；旧回执不覆盖当前提示。不可恢复旧草稿（含未来 schema 或布尔值）保留，编辑/离开/销毁都不会自动覆盖；明确“替换不可恢复旧草稿”后才恢复保存。分析先取完整快照，每 5 卡让出一次，编辑、取消、隐藏、离开、销毁使任务票据失效；迟到结果/IPC 回执不复活输出。不自动运行分析，无计时器、网络、摄像头/麦克风、文件扫描或媒体资源。

## 4. 使用步骤与可复现例子

1. 在功能工作台打开 L009，展开“知识卡原文、标签与手工旧分类”，编辑自己的标题/原文、标签、旧分类和来源。标签一行一项，正文不代替标签。
2. 展开“自定义规则草稿与新增版本”，为每个分类设全部/任一包含条件和排除项，补充人工说明与来源；填写新增版本名，点击“冻结新增规则版本”。冻结不覆盖旧版，新侧自动选新版本。
3. 选择旧侧手工分类或冻结版本、新侧冻结版本，直接点击“重组并对照分类”。查看唯一数、成员数、并排类别、未归类、展开两两交集和逐卡表。
4. 编辑后结果立即失效，需再次主动重组。要重用旧规则，选旧版本并点击“复制旧版本替换规则草稿…”，确认后改草稿再冻结新版本。需要保留被删除/替换工作先导出输入归档。
5. 预览完整 JSON/Markdown，导出新副本。规则或卡片尚不完整时，可导出最后合法输入归档；无效逐行控件文本须先修正，不能归档为已提交输入。

默认教学例：C1 标签 `[机制,实作]`，旧分类“教材第一章”；C2 标签 `[机制]`，旧分类“教材第二章”；C3 标签 `[实作]`，旧分类“教材第二章”。V1：R1“机制”全部包含 `机制`，R2“实作”全部包含 `实作`。新 R1={C1,C2}，R2={C1,C3}，交集={C1}，唯一总卡=3、已归类唯一卡=3、成员数=4、多标签卡=1、未归类=0。

把 C1 标签改成 `外部` 并重组：R1={C2}、R2={C3}、交集为空，未归类只列 C1；唯一总卡仍 3，成员数 2。它仍完整出现在逐卡表和报告，未丢弃。

重置教学例后，将 R1 草稿包含标签改成 `实作`，冻结 V2，旧侧选 V1、新侧 V2：V1 R1={C1,C2}，V2 R1={C1,C3}；V2 R2={C1,C3}、交集={C1,C3}，未归类 C2。V1 的规则仍为 `机制`。再改 C1 标签时，V1/V2 均用当前卡复算，不能把 V1 输出称为历史卡片状态。

另一个手算：卡标签 `[a,b,x]`，包含 `[a,c]`。全部方式不命中；任一方式命中；任一且排除 `[x]` 不命中。原文包含 `c` 不会替代缺失标签。三个分类均包含相同 `common` 标签时，每张卡可同时进入三类，但唯一卡数仍按卡 ID 一次计数。

## 5. 产出与副本保护

完整 JSON 包含 schema/model 版本、当前输入修订、全部卡原文/标签/旧分类/来源、草稿规则、**所有冻结版本**、旧/新选择、两侧类别成员/每卡成员表/全部两两交集/未归类、逐卡对照、唯一与成员数、缺项和规则口径。Markdown 用安全 JSON 围栏给出同样完整内容，HTML 字符转义、围栏长于用户反引号序列。输入归档包含全部合法当前输入和冻结版本，不假作分析结果。

产物会包含用户卡片原文及人工出处，请按实际分享范围使用。报告预览、界面折叠、选定对照不删除历史版本或隐藏成员的导出。界面没有 SVG/图片生成或自动内容生成，视觉产物是实际 DOM 并排集合和表格。

导出使用生产 `files.saveText({content,extension,defaultName,copyOnly:true})`，要求 `saveTextSupportsCopyOnly===true`；缺能力就明确失败，只有 `ok===true` 才提示成功。生产 writer 使用 `wx`，已有目标拒绝且原文件不改。取消/失败/不明确回执不得报成功；已发起的写盘不能因切走撤回，只隔离迟到提示。
