# T034 截图表格转结构数据

## 1. 功能内容

工具工作台中的 T034 将本地 PNG 表格截图转换为经过人工校对的二维字符串表格。用户先在原图拖动矩形表区，本地检测完整暗色横竖分隔线，再编辑原图像素坐标的行列边界。叠图同时显示候选网格与每格的 R1C1 等编号；必须明确确认没有合并格才允许逐格 OCR。用户可输入边界而不使用自动检测。

每格同时显示原识别、原图矩形、词置信最小值、可编辑的校对值和人工状态。低于用户阈值的格标记低置信；没有词结果的格标记未识别、置信未知。所有格一开始均待核对。完整 OCR 完成后，用户必须分别确认值或明确未知。用户声明已核对后可批量确认未被低置信或未识别标记的格；它不会确认低置信格、未知格或无效值。

输出包括全表 CSV/TSV 和完整来源、边界、词位置、原识别与人工值的 JSON/Markdown。每种格式先预览，再选择新目标路径，显示绝对路径、字节数和 SHA-256，最后点击写入。原图只读；所有写入为新副本。首行始终属于数据，不自动变成表头，不将 `003`、`2.50`、公式样式文本或布尔样式文本转成数字、公式或布尔值。

## 2. 为什么需要

截图中的表格常需要进入数据分析或表格软件，普通 OCR 给出的长文本会丢失行列关系。本功能把文字识别与矩形分格绑定，并允许逐格修订，同时保留来源与原识别，便于检查误读和结构错位。T034 的核心是结构和校对；T023 处理扫描文档的可搜索文字层，两者产出不同。

识别不是准确性认证。置信最小值来自引擎，不是准确率；人工确认仅记录操作者的判断。未识别格可能是真空白，也可能读不清，工具不会自行决定。合并格、无边框、透视或旋转表格不在首版自动推断范围；完整暗线检测只给候选分隔，不理解表意。

## 3. 实现方式与固定资源

`model.mjs` 用像素投影检测分隔线：透明像素先合成白底，亮度不高于 160 的像素算暗色，横/竖投影覆盖选区长度至少 65% 才算候选，间隔不超过两像素的暗线带合并为整数中心。候选至少两条横线与两条竖线；不满足则要求人工边界。边界严格递增、包含外缘，以绝对原图像素为单位。每格内缩用户指定像素以排除边框，原图 canvas 与 SVG 叠图分离，绘制叠图不修改来源像素。

OCR 使用本功能私有的 Tesseract.js **6.0.1** / tesseract.js-core **6.0.0**，OEM1、PSM6，固定 `eng`、`chi_sim` 或组合语言；不依赖 PATH 中的可执行程序。Node 所有者线程内启动成熟引擎的子线程，完整 PNG 只传入一次，每格传固定矩形。使用本地 `langPath`、`gzip:false`、`cacheMethod:none`；所有者线程禁止 fetch，固定资源齐全时上游实际走本地文件路径。首次后端使用逐项检查私有资源大小和 SHA；缺失或不符就报错，不下载或运行任意命令。矩形识别和缓存参数依据 [Tesseract.js 6.0.1 官方 API](https://github.com/naptha/tesseract.js/blob/v6.0.1/docs/api.md)。

资源独立随本功能提供，运行时没有其他 feature 路径引用。`vendor/manifest.json` 保存 209 个资源文件的大小/SHA-256、固定 npm 包版本/下载 URL/SHA-512 integrity 和许可，合计 26,138,974 字节，不含 manifest 自身。原 npm LICENSE、包元数据和模型 LICENSE 保留；OCR 引擎/core/模型为 Apache-2.0，传递依赖许可见 manifest 和各包 LICENSE。npm 初次获取固定版本并禁止安装脚本；维护恢复应检出本功能完整 `vendor`，无需用户安装模型或写适配器。`.gitattributes` 对 vendor 和 PNG fixture 禁止文本换行转换。没有引入顶层依赖、字体或 PDF 写出库；上游包原带例子不代表本功能支持 PDF。

两个模型来自 [tessdata_fast 固定提交](https://github.com/tesseract-ocr/tessdata_fast/tree/87416418657359cb625c412a48b6e1d6d41c29bd)：

|模型|字节数|SHA-256|
|---|---:|---|
|eng.traineddata|4,113,088|7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2|
|chi_sim.traineddata|2,469,156|a5fcb6f0db1e1d6d8522f39db4e848f05984669172e584e8d76b6b3141e1f730|

生产 Host 单请求上限 64KiB，图像按最多 24,000 字节的 canonical base64 分块上传。任务绑定窗口 sender 与随机 job ID，验证序号、总长度、完整 SHA 和 PNG 头尺寸，未 seal 不允许 OCR。行优先识别，不允许跳格、重复或并发。每格最多 64 词，全部位置必须位于当前原图矩形；没有将坐标误当成裁剪图坐标。

输入边界为 PNG 33 字节至 8MiB、单边最多 8192、源最多 1200 万像素；选区 16×16 至 600 万像素；最多 8 列、12 行、96 格；内缩 0–12 像素，每格内缩后至少 8×8。引擎逐格重新解码源图，因此还限制源像素数 × 格数 ≤ 1.28 亿。解码 30 秒、单格 OCR 15 秒、整次识别 120 秒上限；OCR 超时终止线程，未完成不提供截断表。图像解码 API 不能中断已开始的内部工作，迟到结果会关闭并禁止写入 UI。检测每 64 行让出事件循环并检查取消。每格文本最多 512 Unicode 码点，词最多 128 码点，拒绝孤立 UTF-16 代理和不支持的控制字符；允许 Tab/换行。每种完整输出最多 1MiB，超限整份拒绝。

来源、识别、校对与目标只在内存，取消释放线程及结果；切走/销毁还关闭 bitmap、清空 canvas 和来源字节，不自恢复或自动识别。所有异步结果以票据隔离，改变来源、网格、参数会作废旧结果；改变人工值/状态会作废旧预览与目标。只持久化 `schemaVersion:1` 的语言、阈值、内缩，UTF-8 JSON ≤64KiB，排队保存保留顺序。草稿不含图像、文字表格或派生报告；不可读版本不默默覆盖，需要明确操作。

## 4. 使用步骤与可复现例子

1. 打开工具工作台 T034，点击“载入三列四行截图示例”，或选择自己的 PNG。来源名、字节数、尺寸和 SHA 会显示。
2. 拖动选择表区，点击“检测完整横竖边线”。示例是 1200×560，候选列边界 `20,400,790,1180`，行边界 `20,150,280,410,540`，正好 3 列×4 行。对照叠图核对，也可手工修订完整边界列表。
3. 明确勾选矩形网格没有合并格，选择英语，内缩 4，点击逐格离线 OCR。示例每格只有一个词，实际原识别为下面 12 个字符串。
4. 将低置信阈值设为 98 重跑，可以观察全部 12 格被标记低置信（本机固定夹具置信为 92–96）；逐格检查原图，选择“人工确认值”，或读不清时选择“明确未知”。阈值 90 下未标记格可在自己核对后按批量确认按钮。没确认全部格时预览会报错。
5. 点击校验并预览，检查所有行列和 CSV/TSV；展开完整 JSON/Markdown，再选择格式的新路径，核对路径/字节数/SHA，点击确认写入。

标准预期 CSV（实际文件 UTF-8、CRLF 行尾，末尾有 CRLF）：

```csv
Item,Count,Cost
Apple,12,2.50
Pear,7,1.20
Plum,3,0.80
```

进一步将 R2C1 改为含逗号、引号和换行的 `逗号,引号"` 加下一行 `下一行`，CSV 会将整个字段放在双引号内并双写内引号；原识别 `Apple` 仍在报告。将 R4C3 状态改未知，它的 CSV/TSV 字段为空，但 JSON 保留原识别 `0.80`、当前人工值和 `unknown` 状态。若白底擦掉示例 R4C3 的内容，引擎实际返回无词/置信未知，批量确认不处理它，必须人工决定确认空白或未知。

示例原 PNG SHA-256 为 `e871bc86f5abc8cb5d9e8dc26fe0e92ee422aa404b46496ee196eb1285c8f4b8`，38187 字节。改变边界为乱序 `20,790,400,1180` 会清旧 OCR 并禁止运行，纠正边界后也必须重新勾选网格和识别。

## 5. 产出与保存范围

CSV 是二维字符串，按 [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180) 描述的逗号/换行/引号转义与 CRLF 行尾；该 RFC 为信息性说明，不承诺所有导入器行为。TSV 使用相同双引号规则但分隔符为 Tab，含换行/Tab 的字段需要支持带引号 TSV 的导入器。工具不执行 CSV 文字中的公式；在其他表格程序打开时该程序可能自行解释内容。

JSON 保存全部源 SHA/尺寸、语言与置信设置、网格/检测口径、全格原文/人工值/状态、词置信与原图 bbox，以及完整 values、低置信 ID 和未知 ID。Markdown 逐格列全内容并转义 HTML。未知与人工确认空白在 CSV 都是空字段，只能用 JSON 区分。JSON 不嵌原 PNG，应自行保留原截图；窗口重载只恢复三个设置，不能声称恢复已释放的校对记录。

选择路径不会写文件；生产主进程提供的 `wx` 新副本 writer 只有目标不存在才写，严格要求成功回执 `ok===true`、`copyOnly===true` 以及相同目标、大小和 SHA。目标已经存在，包括原截图路径时明确拒绝；写入失败不报告成功。源截图从未交给任何写回接口。
