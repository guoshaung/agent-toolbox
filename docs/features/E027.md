# E027 估价竞猜

## 功能内容

提供 30 道原创固定参考值估算题：物品数量、体积、长度、面积、时长，以及题面明确标注“本题假定”的虚构价格。每道题都包含单位、参考值和可复算说明，使用题目给定数字计算，不查询实时商品价，不把假定价格当作市场报价。

2–8 位玩家在同一台电脑逐人交接、私下输入并密封提交，所有人提交后才显示“统一揭晓”。揭晓后按绝对误差升序排名，并显示本轮积分；多题局另给累计积分排名。支持手填参考值自建题、整库 JSON 导入、下一局题库删除与题库/报告安全副本导出。

## 为什么需要

普通知识抢答比的是谁先按键；估算游戏需要每个人先独立给出一个数，再公平比较距离。此功能把共同屏幕的交接、密封、揭晓和误差比较分开，方便朋友用固定可核对的生活数量题开展短局竞猜。价格不随联网或市场变化，今天和下次可以按同一题复现结果。

## 实现方式

纯 `model.mjs` 验证题库、数值和玩家设置，流程为 ready → handoff → input → sealed → revealed；本轮揭晓后进入下一题或完成局。每轮第一位输入者按名单循环轮换，其他人依次接力。提交校验题号、当前玩家和输入状态；旧按钮、重复提交、重复揭晓或下一题不会加分两次。模型视图在揭晓前只给出提交人数/玩家，不返回参考值、解释或已提交猜测；已完成旧轮的完整数据也不放进下一轮的普通视图。

数值为 0–1000000，最多两位小数，严格十进制文本；拒绝 NaN、Infinity、指数、负数、千位分隔符、多余小数和前导零。`0.1` 转为整数 10，`0.30` 转为整数 30，所有误差都由缩放整数相减、取绝对值，避免浮点尾差导致本来相等的误差失去并列。显示和 JSON 数值文本统一两位小数，同时保留缩放整数与 scale 100、precision 2。

单轮名次采用并列占位：误差 10、10、30 的名次是 1、1、3。每轮积分 = 玩家人数 − 单轮名次 + 1；例如三人分别获得 3、3、1 分。累计只相加积分并从高到低排名，相同积分并列，绝不相加“米”“元”“个”等不同单位的误差。最接近可并列，没有按输入先后破同分。

UI 使用已有 `h()` 渲染用户文本和独立样式。当前玩家点独处确认后才创建数值输入框；密封提交后清空原输入，再移除该节点。主持人参考题库仅在明确私密编辑区生成，关闭编辑、隐藏、失焦后清空参考输入、JSON 草稿和参考列表，普通局内 DOM 不藏参考值。暂停保留已密封猜测，但丢弃当前未提交输入并退回交接确认。没有网络、AI、音视频、账号或定时资源；destroy 清理事件、局和题库内存。

## 如何使用

1. 玩家框每行一个名字，2–8 人，每个名字 1–20 字且规范化后不同；设置题数，范围为 1–当前题库长度，内置最多 30 题、自定义最多 100 题。点击“建立新局”，题目按题库顺序使用，新局快照不受后续编辑影响。
2. 点“开始本题”。轮到的玩家接过电脑，其他人转身后点击“我是某某，独处输入”，按显示单位输入十进制猜测，点“密封提交，交给下一位”或 Enter。输入错误会保留当前输入并提示，修正即可；重复 Enter 不会重复提交。
3. 最后一人提交后仍不显示答案，点击“统一揭晓”才展示固定参考、说明、每位猜测、绝对误差、本轮名次和积分。点击“下一题”继续，最后“结算本局”显示累计积分和逐轮误差表。
4. “暂停”可暂停任何未结束局；工作台切走、窗口失焦、页面隐藏也会暂停并清空未提交数值，恢复需手动继续并重新交接。提前结束只保留已经统一揭晓的轮次；未揭晓轮的猜测和参考不进入报告，累计积分也不改变。
5. 主持人独处时可编辑题库：填题面、单位、参考值和可复算说明添加自建题，也可删除或整库导入；全部修改只在下一局生效，正在进行的局保持原快照。私密编辑结束要点“隐藏参考值，关闭编辑”，未提交草稿会被清空。

导入只接受 version 数字 1、questions 数组；每题字段严格为 id/prompt/unit/reference/explanation。题号 1–32 位字母、数字、_ 或 -，唯一；题面 1–240 字，规范化去空白后不重复；单位 1–20 字；说明 1–400 字，均为非空单行文本。reference 必须是合规十进制**字符串**，不接受 JSON 数字以免隐式精度或指数转换。JSON 草稿最多 65536 字符，题库 1–100 题。

```json
{"version":1,"questions":[{"id":"MY001","prompt":"本题假定一个托盘装100颗珠子，估计共有多少颗？","unit":"颗","reference":"100.00","explanation":"本题给定参考100颗，不涉及实时商品报价。"}]}
```

自建参考值由主持人确定；结构校验不会验证事实真伪。共享电脑采用共同合作约定，没有账号或权限隔离，不能阻止别人偷看当前输入、查看源码或点击主持人编辑按钮。

## 使用后产出

单轮显示按绝对误差排序的比较表，单位贯穿参考、猜测和误差；累计排行榜显示积分，明确区别于误差。完整 JSON 包括玩家设置、固定精度、计分规则、每道已揭晓题的题面/参考/说明、按误差排序的玩家猜测/误差/名次/积分、题后累计积分及最终累计排名。提前结束的未揭晓轮仅记题号、题面、单位和已提交玩家，不导出对应数值。题库 JSON 可以再次导入。

题库和报告都先检查 `files.saveTextSupportsCopyOnly === true`，再调用 `saveText({copyOnly:true})` 创建新副本；已有文件不被覆盖。仅 `result.ok === true` 显示保存成功；`canceled` 提示取消，已解决 Promise 返回 `ok:false/error`、缺失成功标记或抛错均提示失败。异步保存结束时若局已切换或模块销毁，不更新旧界面。

全局配置只保存最近 10 局小摘要（玩家设置、时间、已揭晓轮数、积分），不保存大题库、参考值、猜测或报告。保存失败不阻止内存报告导出。题库、当前局和完整报告只保存在模块内存，切换具体功能、新建一局或退出应用会丢失，需先导出。

## 具体可重现例子、验证与限制

使用完整内置题库，小明、小红、小蓝三位玩家，题数 1，建立新局，点“开始本题”。第一题 Q001：“一个托盘摆了 10 行小积木，每行 10 个，估计共有多少个？”单位“个”，固定参考由题目计算为 100。

小明独处输入 `80` 并密封提交；交给小红输入 `110`；交给小蓝输入 `140`。每次提交后前一人的输入清空，统一揭晓前既不展示任何猜测，也不把参考 100.00 放进隐藏 DOM。点击“统一揭晓”：小红误差 10.00 第 1 得 3 分；小明误差 20.00 第 2 得 2 分；小蓝误差 40.00 第 3 得 1 分。结算累计顺序相同；报告误差缩放整数为 1000、2000、4000。

并列小数例：手填参考 `0.30`、单位“米”，三个猜测 `0.20`、`0.40`、`0.60`。前两者误差都是整数 10（显示 0.10 米），并列第 1 各 3 分；第三名误差 0.30 米，名次 3 得 1 分，不会因为浮点相减出现假差异。两题局可以分别用“颗”和“米”；累计只把得到的积分相加，不产生混合单位误差总和。

验证：`node --test test/feature-E027.test.js`，覆盖 30 题原创数据、题库/数值/玩家边界、指定 100/80/110/140 验收、小数并列、公开视图无数值、逐人交接、重复及旧题号操作、暂停保留密封/清空未提交、异单位累计积分、提前结束抑制未揭晓数据、有界摘要，以及实际 DOM 按钮/Enter 处理、参考隐藏节点清理、导入文本安全和副本保存所有结果类型。另运行模块导入、语法和暂存差异检查，以及提交后自有模块/样式引用检查。

27项专项测试通过。组件测试使用轻量DOM和文件桥适配器，属于纯模型与渲染事件验证。程序不检测参与者是否偷看，也不提供实时价格、自动估价或金融建议。

主代理在隔离隐藏Electron33.4.11窗口，以生产preload/目录/实际文本写入器完成三人一题：逐人独处输入80/110/140、密封提交后输入节点移除，统一揭晓前没有猜测表。明确揭晓及结算后实际写入1771字节JSON并解析确认scoresAfter[2,3,1]、排名小红/小明/小蓝及errorScaled[1000,2000,4000]，即误差10/20/40。配置及保存目标为夹具，未操作原生保存对话框，未验证防偷看硬件、macOS或打包。
