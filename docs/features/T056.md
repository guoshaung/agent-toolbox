# T056 数据库结构差异草案

## 1. 功能内容

在本机对比两份有限 SQLite DDL，输出表、列、主键和显式索引的变化，以及潜在破坏标记。输入支持文本编辑和本地 UTF-8 文件，只读文件正文；空白输入明确表示空结构。输出完整 JSON、Markdown 和全注释 SQL 草案，保存前必须预览内容和拟创建文件名，生产副本接口拒绝覆盖已有目标。功能没有数据库连接、SQL 执行、网络、账号或运行时解析库依赖。

报告涵盖 `add_table/drop_table/add_column/drop_column/change_type/change_nullability/change_default/change_primary_key/reorder_columns/add_index/drop_index/change_index`。每项都有 `requiresReview: true`；`destructive: true` 表示可能破坏数据或约束，不表示其他变更自动安全。删表、删列、类型和主键变化、收紧 NOT NULL、删除唯一索引以及涉及唯一性的索引修改都会标记危险。新增 UNIQUE 索引仍需要人工检查历史重复值，即使未标记数据删除风险。

## 2. 为什么需要

交付建表脚本或评审迁移时，纯文本 diff 很难区分格式变化、真正删列与新增索引。本工具在明确的小语法范围内先恢复结构，再提示风险和核对事项，避免直接把删列当作可运行迁移。它适合离线评审声明，不替代查询计划、数据质量、真实外键引用、迁移备份或 SQLite 客户端的导入验证。

## 3. 实现方式与方言边界

`model.mjs` 用逐字符词法分析器区分字符串、引号标识符、标点与注释，随后按有限语法解析，绝不按逗号/分号正则拆 SQL。`index.js` 用独立任务代号隔离读取、分析和保存，异步读取结束后再次检查取消状态；输入变化立即废弃报告/预览。局部 CSS、纯模型与 UI 事件测试均在 T056 自有目录；不引用其他功能。没有用户提供正则、动态代码或查询执行。

支持语法如下：

```sql
CREATE TABLE name (
  col INTEGER|REAL|TEXT|BLOB|NUMERIC
    [NULL|NOT NULL] [DEFAULT literal] [PRIMARY KEY],
  ...,
  [PRIMARY KEY (col, ...)]
);
CREATE [UNIQUE] INDEX name ON table (col [ASC|DESC], ...);
```

约束可在列定义中调整顺序；NULL/DEFAULT/PRIMARY KEY 各最多一次，每表最多一个主键。表级主键须放末尾，引用必须存在；同一主键/索引列不能重复。表/索引共享名称空间，列在所属表内唯一，比较使用 SQLite 的 ASCII 大小写折叠；非 ASCII 名称不会擅自折叠。支持 ASCII 未引号普通名称、双引号、反引号与方括号名称，双引号/反引号可通过重复引号转义；名称 1–128 字符且拒绝控制字符。拒绝 `sqlite_` 内部前缀。列引用和索引所属表会核对并使用定义中的名称；两份输入都须包含本份索引引用的全部表。输入作为完整声明集合比较，索引可以先出现，工具并未执行原文件顺序。

DEFAULT 仅接受 NULL、单引号字符串（重复单引号转义）和有符号普通十进制数字（最多 100 字符、有限值，不支持指数或省略小数点前后的数字）。文本默认值按解码字符串比较；数字保守按去除前导 `+` 的字面量比较，`1` 与 `1.0` 仍报告默认值变化。没有 DEFAULT 与 DEFAULT NULL 不当作同一声明。显式 NULL 与未声明 NOT NULL 相同；主键单独记录列顺序，**不会把所有主键错误推断成 NOT NULL**。单列 INTEGER PRIMARY KEY 可能有 rowid 别名语义；工具不验证行标识、运行时数据类型或真实行内容。

支持 `--` 行注释及 `/*...*/` 块注释，末尾分号可省略，多个语句之间必须有分号。CHECK、REFERENCES/FOREIGN KEY、列 UNIQUE、COLLATE、AUTOINCREMENT、命名约束、DEFAULT 表达式/时间函数/Blob、其他声明类型、IF NOT EXISTS、CREATE TABLE AS、TEMP、附属库名、STRICT、WITHOUT ROWID、表达式/部分索引、TRIGGER、VIEW、ALTER、PRAGMA、数据 SQL 和 JSON 结构快照等整份拒绝，错误只显示固定说明与词元行列，不返回源上下文。拒绝未知输入后不保留上一份成功报告。当前 MVP 接受两份 SQL DDL，未实现 catalog 可选的结构快照输入。

每份输入最多 64 KiB UTF-8、40,000 词元、50 表、每表 50 列、100 显式索引、每索引 50 列；严格 UTF-8、不成对 Unicode/危险控制字符拒绝，不猜测编码。文件分 16 KiB 读取；最长一个解析阶段是有界同步处理，取消会在解析前后及每次读取后检查，不能承诺逐词元中断。完整输出每份最多 2 MiB，超过上限拒绝而非截断。表格每页 50 项，JSON/MD 导出所有声明与差异。不会枚举真实数据库自动索引、外键、触发器或隐藏列。

SQLite 官方依据：[CREATE TABLE](https://www.sqlite.org/lang_createtable.html)、[CREATE INDEX](https://www.sqlite.org/lang_createindex.html)、[关键字与引用](https://www.sqlite.org/lang_keywords.html)、[PRAGMA table_info / index_xinfo](https://www.sqlite.org/pragma.html)。SQLite 是动态类型，声明类型表示亲和性；此工具的五类型比较是声明比较。没有检测目标 SQLite 版本；未声称完整实现 RFC、通用 SQL 或全部 SQLite DDL。原样 SQL 草案也不保证目标版本/应用能够导入。

## 4. 如何使用

1. 在功能工作台打开 **T056 数据库结构差异草案**，分别粘贴旧、新 DDL，或读取两个 UTF-8 `.sql/.ddl/.txt` 文件。
2. 点击 **比较结构并标记风险**。不支持语法会明确失败，此时没有可导出的旧结果；应按支持范围准备完整声明，不要依赖工具忽略未知约束。
3. 查看风险清单并翻页，结合真实数据、业务引用和迁移备份人工决定方案。无变化仅表示支持范围内声明相同。
4. 分别点击 **预览完整 JSON 副本 / MD 副本 / SQL 副本**。预览显示完整文本、拟创建文件名和保护方式，确认后点击 **保存已预览新副本**，在保存对话框选择全新文件名。
5. 文件冲突、取消、返回失败、undefined 或异常都不会显示成功，预览保留。取消任务或隐藏/暂停面板会阻止晚到回调恢复旧结果；操作输入会废弃现有预览。切换功能销毁源文本与结果，不保存秘密/源文本/结果到配置。

源码编辑框确实显示用户输入；JSON/MD 及 SQL 草案可能包含名称与 DEFAULT 字面量。工具不是敏感信息遮蔽器，分享前自行检查。取消保存发生在宿主返回后，无法撤回已完成的真实文件写入；不会自动再次导出。

## 5. 使用后产出

得到完整结构差异与风险清单，以及 `T056-structure-review.json/.md/.sql` 三个可选新副本。JSON 包含版本、有限方言、完整 before/after 表和索引、逐项前后值及复核说明；Markdown 含清单与完整 JSON；SQL **所有非空行都以 `-- ` 开头**，只给新增表/新增索引的注释候选 SQL，危险变更列事项而不生成可执行 DROP/ALTER。名称和多行字符串都经过转义/逐行注释，源内分号不能变成草案中的执行语句。

副本保护依赖基础 `files.saveTextSupportsCopyOnly === true`，每次使用 `copyOnly: true`，只有返回 `ok === true` 才报告成功。实际目标路径由宿主对话框确认，不覆盖源文件、已有报告或其他现有文件；JSON/MD/SQL 均走同一生产文本 writer。工具不会检查或承诺整个迁移事务安全性。

## 6. 可重现例子、验证与限制

点击 **载入删列与新增索引示例**，自动比较：

```sql
-- 旧
CREATE TABLE people (id INTEGER PRIMARY KEY, name TEXT NOT NULL, note TEXT DEFAULT 'a,b;()');
-- 新
CREATE TABLE people (id INTEGER PRIMARY KEY, name TEXT NOT NULL);
CREATE INDEX people_name ON people (name);
```

预期准确 2 项：`drop_column / people / note / destructive=true` 与 `add_index / people / people_name / destructive=false`，危险计数 1，全部 requiresReview。三种预览分别保存新副本，JSON 保留两项及默认值 `a,b;()`；SQL 包含注释 `CREATE INDEX "people_name" ON "people" ("name" ASC);`，没有执行任何语句。随后把新文本改成带 `CREATE TRIGGER` 的 DDL，重新比较必须报 unsupported，旧预览与保存按钮消失。
