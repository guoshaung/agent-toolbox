# T067 接口契约版本兼容性对比

## 1. 功能内容

在「工具 / 网络诊断与接口验证 / 接口契约版本兼容性对比」导入旧、新响应 JSON Schema 和带版本历史响应样例，或显露正文后编辑，再点击「比较契约并重验历史样例」。完整离线，没有网络Host、登录状态、请求、重试、外部ref解析或执行脚本，也无需额外确认许可流程。

本项对比“旧契约允许的响应是否仍被新规则接纳”的有限规则方向，并把每条历史样例分别交给旧、新校验器；新增必填、类型收紧、枚举缩减、数值闭开界限收紧逐路径标记。旧有效新失效记录 upgrade_rejected，原本不符合旧契约的样例记录 invalid_old_sample，不能把原本错误算成升级导致。整数属于number、number不整体属于integer；枚举原始值按typed集合核对，兼容扩充不标破坏。新增可选属性对其存在时增加约束，标 potential_breaking 并要求回源复核。

## 2. 为什么需要

接口升级前，单独确认新响应符合新Schema无法知道哪些历史响应已经失效。本工具把变更规则方向和历史样例证据并列，便于定位 price 类型变化、coupon 新必填等具体问题。T001是单份契约校验，L027是反例教学训练，API工具发送请求；本项是离线升级对照，不重复它们。

规则变更及有限历史样例不是全部旧消费者兼容性证明，也不覆盖实际服务器返回字段、完整OpenAPI、请求参数、HTTP状态码、权限或语义业务变化。新契约撤掉属性声明只放宽其值约束，不证明响应仍返回它；旧样例全通过也不能推出所有将来响应/调用方兼容。报告明确保留方向、分类、数量、来源路径及源SHA，用户能回源核对；省略原值不能当作已经证明普遍兼容。

## 3. 实现方式与支持域

自有纯 model.mjs 严格解析 JSON、编译有限Schema、比较规则、校验历史与生成完整报告；index.js 使用生产h()与工作台生命周期。设计中的校验库原为待选；目前仓库不存在T001可复用实现，因此本项采用内置、显式有限、独立测试的校验器，不声称运行时复用未存在T001，不添加包或依赖其它功能。不是完整JSON Schema校验库。

根必须object。支持单一type七种（object/array/string/number/integer/boolean/null）、对象properties与required、数组items、primitive enum、minimum/maximum/exclusiveMinimum/exclusiveMaximum；可使用根 `$schema: https://json-schema.org/draft/2020-12/schema`，省略时明确按2020-12子集假定。title/description/$comment仅字符串注释，记录忽略路径，不作为校验规则。未知keyword整份拒绝，包括additionalProperties（即使true）、$ref/$defs/外部网络/文件引用、组合/条件/union/nullable/OpenAPI、格式/正则、长度与其它约束，不静默投影成功。额外未声明object属性按默认语义允许；required必须唯一且对应声明properties，这是本实现比完整标准更窄的输入域。array items必须存在；object/array enum不支持。

每份Schema≤64KiB UTF-8、最多200 schema节点、嵌套schema层≤6、每对象≤50属性、属性名1–64字符且无control、每enum≤50原始值。enum非空、typed重复拒绝（0/-0等值）、所有成员须符合本节点type和数值范围，矛盾/空数值域（含整数无可取整点）拒绝。数值界限绝对值≤10^12；数据遵循有限JavaScript IEEE754数值，整数必须safe integer，不支持任意精度数。重复JSON键含转义同名、非有限数、unsafe integer、未配对Unicode、语法尾内容拒绝，不回显异常源片段。

比较保留object/array结构路径，数组规则路径使用 `/*`，样例错误使用真实index；字段名JSON Pointer转义 `/→~1`、`~→~0`。数值闭开界限按更严格有效界限归一化；整数的取整边界、有限旧enum/boolean/null/小整数域参与包含核对，避免旧enum本就都是整数时把number→integer误报破坏，或把不同小数界限但相同整数域误报收紧。枚举兼容扩充/移除约束、类型integer→number、撤必填分类compatible_in_domain或relaxed；该分类仅针对所述规则及本支持域，不是整份API证明。

历史格式严格 `{ "format":"T067-history", "version":1, "samples":[{"id":"sample-1","contractVersion":"v1","response":{"price":10}}] }`；≤256KiB、1–50条，id唯一，id/contractVersion为1–32字符 `A-Za-z0-9._-` 且首字符字母数字，未知字段/版本拒绝。response保留合法有限JSON值供校验；样例顶层非object会产生type错误而不是截断或丢弃。每JSON结构≤18层/10000节点，验证≤100000步/次，全报告≤10000错误，规则≤2000；超限拒绝整份、不截断。所有数据error输出path/schemaPath/keyword/code与实际类型，绝不附实际值。

报告不包含源正文、历史值、enum原值、数值界限或注释正文。旧/新来源alias、schema节点、UTF-8字节数、原文SHA256、规则type/required数量/enum数量/界限存在与闭开、方向和错误保留。原文SHA只帮助匹配源，不是匿名化或不可猜测保证；属性名、样例别名和版本可能由用户放入敏感文字，分享前核对。源默认不放进textarea.value，显露后正文进入可访问DOM，隐藏/比较/切走清空DOM正文值，内存仍保留直到清除/销毁；不声称当前内存已加密。比较和FileAPI读取在首个await之前同步登记busy与ticket，取消/编辑/隐藏/切走后旧异步回调不接纳；File.arrayBuffer/crypto.digest本身不能中途终止，有限读取完成后丢弃结果。每5样例让出事件循环检查取消。源/结果不写config。

官方主来源：[JSON Schema2020-12 validation type/enum/numeric/required](https://json-schema.org/draft/2020-12/json-schema-validation)、[JSON Schema2020-12 core properties/items](https://json-schema.org/draft/2020-12/json-schema-core)。本MVP显式子集及更窄输入域，不是完整标准符合性或OpenAPI兼容证明。

## 4. 如何使用

1. 三个本地JSON选择框分别读取旧契约、新契约、历史样例，原件只读。严格UTF-8，文件1字节起、上限分别64/64/256KiB，实际读取字节须等于File.size；未知编码、坏UTF-8、BOM拒绝。不会扫描目录或任意路径。界面显示内存字节数，不默认显露正文。
2. 如需粘贴或修改，点击相应「显露 / 编辑」，在正文输入；再次隐藏会从DOM清掉正文值但保留当前内存。编辑立即废弃旧结果/预览。价格/优惠券示例按钮仅填三个内存源，不自动比较。
3. 点击「比较契约并重验历史样例」。观察变更分类与每条样例oldValid/newValid及旧、新完整错误；规则20项/页，样例10条/页，可翻页查看。未知规则、坏格式或容量错误不产生部分报告。取消当前处理、清除或切走会使旧ticket失效；切回来不自动比较。清除全部源和报告或销毁会释放内存源。
4. 完整JSON/MD先预览再保存新副本，预览/导出全部规则和全部样例错误，不只当前页。依赖生产saveTextSupportsCopyOnly；缺能力阻止保存。saveText copyOnly:true，已有目标拒绝，包括选回源文件；只有ok===true显示成功，canceled提示取消，false/undefined/throw均失败并保留完整预览，不回显内部路径。完整输出≤2MiB，超限拒绝无截断。没有自动源草稿/秘密配置。

## 6. 具体可重现例子

点击价格/优惠券示例：旧 `type:object, properties:{price:{type:number},coupon:{type:string}}, required:[price]`，新只把price改string并required改[price,coupon]，历史v1响应 `{price:10}`。点击比较，恰两变更：/coupon required_added、/price type_narrowed；旧有效新失效一条，新错误恰/coupon missing_required、/price type_mismatch（actualType integer），不导出10或源正文。预览JSON/MD，再保存副本。

旧price number enum[1,2]，新integer enum[1,2]：只报告type_domain_covered，不是破坏，因为有限旧枚举均整数；旧number无enum→integer则type_narrowed，样例price1.5新type失效。旧string enum[A,B]→enum[A]，旧B样例升级失效，报告枚举数量2→1和enum_narrowed，不输出A/B实际值。反向扩充为compatible_in_domain，不误报收紧。

旧数值minimum0/maximum10，新exclusiveMinimum0/exclusiveMaximum10：两条lower/upper tightened；历史0与10新失效，5两边通过。旧integer minimum0.5→0.9，实际允许整数都从1起，domain_covered不误报破坏。带版本旧样例本就字符串price而旧number时，单列invalid_old_sample，即使新允许string也不归升级导致。给新Schema添`$ref:https://example.invalid/secret`或additionalProperties，整份unsupported_keyword不跟网络ref，不留旧报告。
