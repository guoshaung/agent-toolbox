# T058 国际化文案完整性校验

## 1. 功能内容

本地输入一份基准JSON和1–4份目标语言JSON，递归核对缺键、冗余键、类型变化、命名插值变量缺失/新增。支持明确选择{name}或{{name}}有限方言；默认按变量集合比较，同变量次数差异单列，勾选严格次数时计为差异。完整报告预览后另存JSON或Markdown新副本，不翻译、不修改原资源文件。

每份最多64KiB UTF-8、500节点（含对象与叶值）、16层；字符串最多8192 UTF-16码元，键最多160码元。根须对象，不支持数组。报告最多4MiB，超限整份拒绝，不截断。输入不自动保存草稿。

## 2. 为什么需要这个功能

界面增加文案后，译文容易漏键或删掉插值参数。字符串仍可成功加载，不代表运行时能替换正确。把每个路径和变量差异列出，可在发布前修补资源，而不把“缺翻译”和“翻译语义有误”混为同一类。

工具核对结构与声明变量，不判断翻译质量、语言回退规则、实际运行时模板引擎或文案是否已人工审核。空字符串合法，也不代表已经完成翻译。

## 3. 实现方式

model.mjs有限严格JSON解析器拒绝重复键（含Unicode转义后同名）、非有限数、截断、控制字符键和孤立代理项；对象使用null原型，不允许__proto__等键污染原型。JSON对象递归成路径Map，根是空字符串，~与/按[JSON Pointer RFC6901](https://www.rfc-editor.org/rfc/rfc6901)编码为~0/~1，不按点拆键或归一化Unicode。

比较全部根/对象/叶路径，父节点类型变化及其缺失子路径分别记录；空对象参与类型核对。基准叶值须字符串，其他叶类型作为基准问题并标不可核验，不能得到accepted:true。目标少路径报missing_key，多路径报extra_key，同路径异类型报type_mismatch。

占位符变量为ASCII字母/下划线起始，后续字母数字下划线，可用同类点分段，最长64字符。解析对应单或双花括号，拒绝字面/转义花括号、ICU复数、格式器、嵌套、错误闭合及空变量，标unsupported而不悄悄判通过。双花括号来自常见[i18next插值方式](https://www.i18next.com/translation-function/interpolation)，这里只支持明确命名变量子集，不宣称实现所有i18next选项。每条报告含完整变量次数、集合缺失/新增与次数差异，不含文案正文；键名、变量名和语言别名仍由用户核对分享范围。

每50个路径让出事件循环并检查取消；取消/隐藏/离开不发布半份报告。输入、方言、次数或启用目标变化使旧结果和预览失效。真实File API只读严格UTF-8，读取失败清除旧对应文本，不能误用上次文件。

UI通过value/textContent显示源文本和报告，标签不执行。报告JSON全文可预览；Markdown采用比报告内最长反引号更长的代码围栏。保存要求生产saveTextSupportsCopyOnly===true，请求copyOnly:true，writer用wx拒绝任何已有目标，ok===true才显示成功。取消/失败保留预览，原生另存等待时禁改输入。

## 4. 如何使用

1. 在新增功能工作台打开T058，粘贴基准JSON或读取文件。
2. 勾选需要核对的目标B–E，为每个填唯一语言别名及完整JSON。未勾选的目标不参加本次范围。
3. 选择{name}或{{name}}方言。需要严格检查重复变量次数时勾选；默认只要求变量集合相同。
4. 点击“核对完整语言集合”，阅读全部路径记录和基准问题。unsupported表示不适合当前有限方言，不能当作已通过。
5. 预览JSON/Markdown，检查完整报告及分享范围，再保存到新文件。修改来源后重新核对，不覆盖源语言文件。

## 5. 使用后产出与具体例子

输出T058-i18n-report.json或.md，含输入范围、方言/次数规则、基准节点/文案数、基准问题、每目标所有路径的预期/实际类型、缺失/新增变量、全部次数及差异、总体accepted和计数。文案正文不进入结果，但源编辑框明确包含用户输入，并不声称私密内存保护。

“载入缺键与变量示例”：基准/greeting含“你好，{name}”，目标en为“Hello”，应在/greeting报告missingVariables=[name]、placeholder_mismatch；基准/help有而en没有，报missing_key；目标/extra只在en存在，报extra_key。/cart/count两边都有{count}，报告match。总体缺键1、冗余1、变量差异1，未通过。

重复例：基准“{name} {name}”、目标“{name}”。默认集合相同可通过，但countDifferences明确expected2/actual1；严格次数开启后该路径placeholder_mismatch。双括号例选{{name}}方言，基准{{user.name}}、目标无此变量，准确报user.name缺失；ICU“{count, plural, ...}”明确不可核验。
