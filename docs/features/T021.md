# T021 · PDF 页面装订台

## 1. 功能内容

在本地选择 1–4 份未加密且不含 AcroForm 交互表单的 PDF，显示全部来源页，以缩略图、拖动以及“上移/下移/排除此页”按钮安排输出页序。将选中的页合并为一个 PDF，或按每份最多页数拆成多个 PDF。生成后必须成功渲染全部输出页，才允许另存文件。完整逐页来源表包含输入和输出 SHA-256、来源页、输出页、MediaBox、CropBox、旋转角与注释存在标记。

每份来源不超过 2 MiB，合计不超过 8 MiB，来源页和输出页均不超过 80 页。单份合并输出最多 10 MiB；目录包每个文件最多 2 MiB、包括 PDF 与两份来源报告在内合计最多 10 MiB。超限整体拒绝，不截取前几页或输出残缺目录。来源报告另有 1 MiB 上限。

## 2. 为什么需要这个功能

讲义、申请附件、票据与扫描文件经常需要重新排序、删除不需要的页，或者拆成便于提交的小文件。手工判断“合并后的第几页来自哪份资料”容易出错。本功能把整理结果和逐页来源一起交付，用户能逐页核对并再次定位原件；所有文件从本地读入，不需要上传材料。

## 3. 实现方式

`model.mjs` 检查完整字节、来源标识、容量、页几何和严格输出计划。独立模块 Worker 运行固定的 `inspect/build` 操作，使用本功能私有、固定版本的 pdf-lib 1.17.1 原始 ESM 发行包复制 PDF 页。[上游 API 文档](https://pdf-lib.js.org/docs/api/classes/pdfdocument)说明页面复制接口；实现使用 `ignoreEncryption:false`，不绕过加密。原包下载完整性和落盘 SHA-256 均固定于 `vendor/manifest.json`，六项上游依赖版本及原始许可证随功能保存，无共享依赖或全局配置修改。

浏览器端使用项目已有的 PDF.js 4.10.38 渲染来源和全部输出页，`isEvalSupported:false`，Worker 与字体资源均来自应用自身；真实 Electron 的 `self` CSP 已验收。读取、解析、生成、渲染均可取消；取消会终止本次 Worker，取消渲染并废弃旧回调。Worker 15 秒期限和输入容量不等于 PDF 解压/渲染进程的内存硬限，本工具不是隔离不可信 PDF 的安全沙箱。

单份 PDF 调用公共二进制新副本写入器，目录包调用公共目录导出器，报告调用文本新副本写入器，均传递 `copyOnly:true`，并只把严格 `ok===true` 视为保存成功。现有文件或目录拒绝覆盖。保存请求提交后不能用本功能取消按钮撤销已开始的文件写入。PDF 原字节、大文件和来源表不写配置；离开或隐藏时清除来源字节与全部预览，返回后需重新选择。

复制的是普通页面内容、尺寸、裁切和旋转。新文档不保证迁移文档级书签、附件、签名、元数据以及交互链接/注释关系。注释存在标记用于提醒核对，不意味着已清理其中的数据。本功能不做敏感内容遮盖或脱敏，不能把删页/重排当成安全清理。缩略图也不等同于印刷质量证明。

## 4. 如何使用

1. 在功能工作台打开 T021，点击“选择PDF来源文件”，明确选择本地原件。
2. 点击“渲染当前源页缩略图”，核对页内容；拖动页面卡片，或使用上移/下移调整顺序，排除不需要的页。
3. 选择“合并为一份PDF”或“每组页数拆分PDF”，拆分页数填写 1–80 的整数。
4. 点击“生成并预览全部输出PDF页”。检查每个输出页和完整来源表；调整页序或输出方式会立即作废旧结果，必须重新生成。
5. 另存单份 PDF，或将全部 PDF 与 JSON/Markdown 来源报告导出到新的目录。也可单独预览、另存 JSON 或 Markdown 来源报告。若保存取消或失败，完整预览仍保留，可以换一个新目标再保存。

加密、表单、容量或解析错误会拒绝新输入并保留之前成功载入的来源，但旧输出结果会失效。任何输出页渲染失败都会废弃整个生成结果，不能保存其中已经渲染的部分页。

## 5. 使用后的产出与验证

合并产物为 `assembled.pdf`。拆分产物为 `part-01.pdf` 等；目录包同时包含 `page-sources.json` 和 `page-sources.md`。来源表逐页列出输出文件/页码、稳定页面 ID、来源文件 ID/文件名/SHA、来源页、页几何、旋转和注释标记，完整记录所有来源与输出的字节数及 SHA。来源表没有嵌入 PDF 原字节。

17 项专项测试通过：使用独立手写 PDF 固定内容标记检查复制页顺序与实际 Page 对象，核对全部 80 页来源表；覆盖严格计划、容量、交互表单、完整拆分包、真实二进制 SHA；组件验证实际拖动事件、全部页预览门槛、各类失败/取消/undefined 保存回执、缺少新副本能力、渲染失败、15 秒期限回调、晚到线程回执和离开后不得自动恢复。

真实隔离 Electron 33.4.11 / Node 20.18.3 验收使用生产功能工作台、预加载、PDF.js、真实模块 Worker 和生产文件写入器。系统选文件通过真实 FileAPI；保存对话框目标与配置接口为夹具，不声称人工操作系统保存窗口、安装包或跨系统验证。验收涵盖 11 组检查：两份真实磁盘 PDF 的四页、全部来源/输出缩略图、DragEvent/DataTransfer 重排、单份新文件、完整六文件拆分目录、JSON/Markdown 回读、现有目标拒覆盖、独立加密输入拒绝、线程取消、离开清除、零网络和原件 SHA 不变。

另用独立 pypdf 6.10.0 解析输出，核对四页完整文本、MediaBox、CropBox、旋转和各拆分文件。Poppler 独立渲染每个裁切页并与对应来源页逐像素比较，共 1,075,800 像素完全一致；四张完整输出页均已实际查看，顺序、方向、裁切与文字无遗漏。以上为所述夹具的证据，不代表所有 PDF 结构兼容。

## 6. 具体使用例子

`A.pdf` 有红色 A1 和旋转 90°、带裁切的绿色 A2；`B.pdf` 有蓝色 B1 和旋转 180° 的金色 B2。选择两份文件，拖动 P002 到 P001 前面，再将 P004 上移到第三位，页序变为 A2、A1、B2、B1。选择合并并生成，四页预览按此排列；来源表对应 `A.pdf:2、A.pdf:1、B.pdf:2、B.pdf:1`，新 PDF 保留各页尺寸、裁切与旋转，原件 SHA 不变。

将输出方式改为拆分、每份页数为 1，重新生成并预览，得到四个单页 PDF 和两份来源报告的新目录。再次选择已有目录时拒绝覆盖，各文件 SHA 保持不变。如果来源为加密 PDF，载入会拒绝，也不会留下可保存的旧输出。
