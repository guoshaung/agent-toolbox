# E024 你画我猜

## 功能内容与验收

2–4 名玩家在同一设备上轮流作画和猜词。画者先独自看屏幕，从三个候选词中私密选一个，再明确点击“隐藏词题，开始作画”；词题节点被移除，进入不显示答案的 640×400 Canvas 画布。其他玩家选择自己的名字并提交文本猜测，匹配标准词或预设别名即可得分并结束该轮，系统自动换下一位画者。

本模块手写 40 个常见绘画词题，每词最多两个明确别名。归一化后每个标准词和别名只属于一个词题，不使用模糊语义匹配。例如“自行车”接受“单车、脚踏车”，“手机”接受“移动电话”，“冰箱”接受“电冰箱”；“汤圆”不会把制作方式不同的“元宵”当作别名。

验收局为两个玩家、每人作画一轮：完成两轮后，两人各作画一次，作画界面不显示当前答案；第一轮用别名猜中，第二轮用标准答案猜中，并保存两张不同的绘画 PNG、输出比分和完整画册。

## 为什么需要与功能边界

它把共享屏幕变成轮流创作、猜测和计分的聚会工具，与普通绘图模块不同：有私密题目、作画倒计时、玩家角色、文本猜测、别名规则和局后画册。参与者可以通过动作和图形交流，无需图片识别、摄像头、麦克风、AI、账号或网络。

隐私流程需要本机参与者配合：选词时其他人转身，画者确认隐藏后再给猜词者看画布。暂停和页面隐藏也会遮住私密选词；重新查看须再次经过“画者已独处，查看选词”。只提供本机轮流玩法，不建立联网房间。

元数据沿用“娱乐 / 聚会与互动”，独立模块由工作台发现，默认导出同步 `create(root, ctx)`。它只引用自己的词表、纯模型、画笔模型及现有 `h`，不运行时引用其他待合并功能，不修改主进程、预加载或共享样式。

## 实现与规则

- `words.mjs` 维护不可变词表，构建标准词/别名唯一索引。猜测须为 1–32 字符，不含控制字符；NFKC 归一化、去空白和转小写只处理书写格式，然后精确匹配，不接受任意同义词、部分匹配或附加后缀。
- `model.mjs` 限定 2–4 个不同的 1–20 字符玩家名、每人 1–2 次作画、30–180 整数秒/轮，以及 1–32 位字母、数字、下划线或短横线局号。总轮数最多 8。固定种子洗牌让相同局号有同样候选词序；每轮取三个候选并全部消耗，候选词和已作画词本局均不重复。
- 游戏阶段为交接、私密选择、作画、暂停和完成。所选词用模型私有字段保存，只有私密选择阶段返回候选与选择 ID；作画阶段不返回所选词或别名，也不在隐藏 DOM、属性、数据标记中放答案。第一位提交正确答案的非画者 +1，画者 +1，其他人不加分；到时和主持人提前结束均 0 分。相同分数并列排名。
- 每轮最多 100 次有效猜测，相邻猜测至少间隔 300 毫秒，非法玩家、空值或过长输入不写入记录。旧轮的提交不能作用于新轮，操作先检查时限，到时后正确答案也不能补分。猜中立即结束并自动轮换画者，但下一轮仍需私密选词和明确确认才计时。
- `drawing.mjs` 独立保存可验证笔画：固定 640×400，颜色为六种墨色加白色橡皮，粗细 2/5/10/18 px；最多 200 笔、每笔 400 点、整幅 10000 点，撤销保留最近 20 次操作，包括清空。完成的笔画与点不可变，Undo 按笔画状态重绘，并非仅更改计数。
- UI 使用原生 Pointer 事件和指针捕获，按 Canvas 的实际显示矩形换算坐标，支持鼠标、触屏和触控笔，超出画布的坐标被夹紧。暂停、隐藏或退出提交当前已画部分并停止接收新画笔点。切回工作台仍暂停，手动继续才恢复；切换具体功能会销毁中间局。
- 每轮结束把当前矢量笔画重新画到独立离屏 Canvas，再收集 `image/png` 快照；下一轮新建画笔状态，不覆盖前轮图像。整局最多八张 640×400 PNG，图片和详细猜测只保留在当前打开期间，不能写入全局配置。PNG 生成异常时保留受限笔画快照，画册导出可重试生成。
- PNG 画册在本机另建双列 Canvas，逐轮解码已收集图片，再拼接题目、画者、猜中者和比分。两轮为 1340×570，八轮最大 1340×2010（约 269 万像素）；图中的题目只在结束后的画册揭晓，不会画进游戏中的作画 Canvas。
- `create` 准备界面，`activate` 才可开始资源和计时；`deactivate` 暂停和取消未完成的画册拼接；`destroy` 移除监听器、计时器、图片缓存、下载 URL、节点和样式。样式只作用于 `.feature-e024`。

## 如何使用

1. 设置玩家人数和不同名字，选择每人作画轮数、时长和局号，点“建立新局”。默认小明/小红、每人一轮、每轮 60 秒。错误输入明确提示并保留原局。
2. 系统提示本轮画者。其他玩家避开屏幕后，点“画者已独处，查看选词”，选择一个词。此时不计时，可“暂时隐藏选词”。
3. 画者点“隐藏词题，开始作画”。答案从画布界面移除，倒计时启动；选择颜色和粗细，用鼠标、触屏或触控笔画图。白色可擦除，“清空”可通过“撤销”恢复；达到画笔上限时按说明撤销或清空。
4. 猜词者在“猜词玩家”中选自己的名字，输入猜测，按 Enter 或“提交猜测”。画者不能猜自己的题；错误猜测只显示尚未猜中，不显示答案。第一位猜中结束本轮并给猜中者和画者各一分。
5. 到时停止作画和猜测，或点“结束本轮”提前结束。本轮答案在交接界面揭晓，下一位画者自动轮换。暂停期间画布与猜测隐藏，继续后恢复同一幅图和剩余时间。
6. 全部轮次结束后查看排名、各轮绘画与题目，下载 PNG 画册副本，并按需导出完整 JSON 报告。

所有设置、颜色、撤销和猜测按钮可通过 Tab 操作，文本猜测可用 Enter 提交；画笔本身需要鼠标、触屏或触控笔。关闭工作台是暂停，切换具体功能或建立新局会丢失未导出的图片和详细报告，界面在开始前明确说明；切换前先导出。

## 使用后的产出与保存

完整局 JSON 元数据包含功能、数据和词表版本，玩家/时长/局号设置，预设计分，比分与并列排名，以及全部轮次。每轮有画者、揭晓标准词和别名、结束原因、猜中者、有效毫秒数及受限猜测记录；猜测包含玩家、文本、是否正确与有效时间。绘画元数据记录 Canvas 大小、PNG 是否已收集、画册列数和尺寸，不把 PNG base64 嵌入文本报告，不引用虚构图像文件路径。

小配置键 `features.E024.summaries` 只保存最近 10 局的玩家/设置、比分和结束时间；不存绘画、词题或猜测明细。载入时验证人数、名称、时间、轮数及比分边界和双人得分一致性，剔除损坏数据；没有配置接口时使用本机 localStorage。摘要保存失败仍能导出本次内存中的画册和报告，未完成局不会恢复。

**PNG 导出**使用浏览器标准 Canvas `toBlob('image/png')`、Object URL 和带唯一文件名的下载链接，提交一个新的下载副本。名字包含局号、时间戳和递增编号，不使用不存在的 `saveImage`，也不调用文本保存接口。下载后按浏览器命名策略放入下载目录；UI 只确认“已提交下载请求”，不冒称已验证磁盘保存。Object URL 延后回收，销毁时也会清理；离开功能会取消仍在解码或编码中的下载任务。

**JSON 导出**先检查 `saveTextSupportsCopyOnly === true`，再调用 `saveText({content, extension: 'json', defaultName, copyOnly: true})`。缺少安全副本能力时阻止 JSON 导出并提示更新；PNG 的浏览器下载仍可独立使用。取消 JSON 保存不报成功，错误显示原因。两种导出路径和状态明确分开。

## 具体例子、验证与限制

设 2 人“小明 / 小红”、每人作画 1 轮、每轮 60 秒、局号 `demo`，点“建立新局”。

1. 小明独处查看第一轮候选“冰淇淋 / 手机 / 面包”，选择“手机”，点击“隐藏词题，开始作画”。此时界面不应出现“手机”“移动电话”或该词的 ID。
2. 在画布内画一个手机外框，例如沿逻辑坐标 `(160,80) → (480,80) → (480,320) → (160,320) → (160,80)` 连续拖画。猜词玩家选“小红”，输入别名“移动电话”并提交。
3. 第一轮结束，自动轮换小红为画者；两人当前各一分，并保存小明的 PNG。小红独处查看第二轮“菠萝 / 西瓜 / 星星”，选“菠萝”并明确隐藏开始。
4. 画一幅不同图，例如菠萝的果身及顶部叶片。猜词玩家选“小明”，提交标准词“菠萝”。最终两人各 **2 分、并列第一**，恰好两轮、每人各画一次，画廊有两张不同图。
5. 点“下载 PNG 画册副本”，应得到一张 1340×570 的两列画册，包含两轮独立绘画及揭晓题目、画者/猜中者。点“导出 JSON 报告副本”，应有两轮记录，第一轮猜测为“移动电话”、第二轮为“菠萝”，画者索引分别 0、1，比分 `[2,2]`。

到时例子：第一轮选手机、隐藏后不提交有效猜中，满 60 个有效秒后旧提交按钮即使迟到提交“移动电话”也不计分，画布锁定并轮换小红，首轮 PNG 仍收集。之后第二轮猜中只产生该轮两分，最终 `[1,1]`。

暂停例子：作画 2.5 秒后暂停 90 秒，再继续 1.2 秒并猜中。旧 Canvas 的指针事件不能写入，恢复后笔画不丢失，本轮有效时间为 3.7 秒。精确时间由注入时钟测试验证，不要求手动操作到毫秒精度。

运行 `node --test test/feature-E024.test.js`，25 项测试覆盖标准词/别名唯一、设置边界、私密选词与 DOM 无答案、两人两轮及四人八轮、轮换/计分、100 猜上限、60 秒期限、暂停时间、画笔/点/撤销上限、Pointer 缩放、清空与恢复、两轮独立 PNG 收集、画册拼接 API、PNG/JSON 分路、存储失败和下载取消清理。组件测试加载实际 `index.js` 和已有 `h`，使用事件 DOM 与 Canvas/图片 API 适配器；适配器核对画笔点、绘图和编码调用，不是真实 PNG 像素或原生文件对话框验证。

本项不支持联网、自由新增词题、模糊 AI 判分、猜测撤销、历史绘画恢复或单轮单独图像下载；PNG 画册和完整 JSON 应在切换具体功能前导出。

## 主代理集成验收

在隔离隐藏的 Electron 33.4.11 窗口中运行生产 preload、功能目录服务和文本写入器。按上面的局号 demo 流程，向实际 Canvas 派发 Pointer 事件画两张不同图，分别检查超过1000个非白像素，确认作画 DOM 不显示当前词；第一轮暂停后画布遮住，恢复笔画仍在。两人完成轮换，第一轮别名“移动电话”、第二轮标准词“菠萝”猜中，JSON 报告比分 [2,2]、画者索引 [0,1]、两幅 PNG 均已收集，实际写入1941字节副本。

下载流程实际执行 Canvas 重新绘制、PNG 解码、toBlob 编码和 Electron 下载：测试将下载目标指向全新夹具目录，收到 completed，检查磁盘 PNG 文件头和1340×570尺寸，并打开图像确认两列各有独立图形、题目和比分。这里使用真实 Canvas 像素与文件下载；Pointer 事件由测试派发，未验证触屏硬件，保存目标与配置为夹具，未操作系统保存对话框，未完成打包验收。

含33个功能的隔离集成分支执行项目 CI 模式全量检查：994项，984通过、10跳过、0失败；跳过的既有平台用例不算本功能的真实硬件验证。
