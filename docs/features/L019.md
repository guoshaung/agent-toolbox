# L019 B树分裂演示

## 1. 功能内容

固定阶数为 2-3 树，只接受无重复整数键的插入序列。编辑输入后生成完整演示，逐帧查看叶内插入、三键溢出、中间键提升、父节点递归分裂及新根建立。树形 DOM 使用节点、键分隔和父子连接线展示实际结构，每个孩子有明确序号。高亮本帧涉及节点，橙色标识三键溢出。

支持上一帧、下一帧、完成下一次插入、首帧、末帧、直接选择帧、播放/暂停以及每次插入的完成帧快捷查看。每帧展示排序、键唯一性、子树范围、孩子数量与所有叶同深检查；临时三键帧明确不是有效 2-3 树。完整输入、全部帧和最终结果可导出 JSON/Markdown 副本。

## 2. 为什么需要

索引结构的难点在于一个叶节点溢出后，为什么要把中间键交给父节点，以及父节点也满时如何递归传播。只看最终树或算法代码模板，很容易忽略分裂过程中哪些结构仍然正确、哪些暂时违反容量限制。

本功能新增可操作的结构变更实验；用图形对照分裂前、溢出时、提升后和最终检查，让用户直接观察树高为何增加、叶子深度为何仍一致。它采用明确的 2-3 树模型，不演示真实数据库索引、磁盘页、B+ 树或删除算法。

## 3. 实现方式与边界

`model.mjs` 是确定性纯模型。节点有稳定整数 ID、排序键数组及有序孩子数组；`index.js` 负责编辑、帧选择、DOM 树和保存，`style.css` 仅用现有主题变量 `--bg-raised`、`--bg-sunken`、`--line`、`--text` 等，无额外依赖。

- 有效节点包含 1 或 2 键，内部节点孩子数为键数+1；叶节点没有孩子，所有叶必须同深。子树中的键必须严格位于父分隔键限定的范围内；键值及节点 ID 不重复。
- 输入 1–64 个十进制整数，范围 −1000000 至 1000000。空格、换行、英文/中文逗号分隔；不接受 JSON 数组、表达式、代码、小数或指数格式。重复值直接拒绝，不自动去重，`01` 与 `1`、`0` 与 `-0` 也属于重复。序列文本最多 4096 UTF-8 字节。
- 按分隔键选择孩子，下降至叶后有序插入。叶形成 3 键时取中间键提升；原节点 ID 留给左节点，右节点取得新 ID，各保留一个键。内部节点分裂时，原来的四个孩子按顺序分成左右各两个。父节点新形成 3 键则继续分裂；根分裂建立新根，树高增加 1。
- 每帧执行不变量检查。暂态允许最多一个三键溢出节点，但仍强制排序、唯一性、孩子数量、范围与叶同深。完成帧再次用严格的 1–2 键容量规则检查，并核对已插入键总数；检查失败拒绝产生成功结果。
- 最多 1024 帧；超过容量直接报错，不截断、丢失输入或假称完成。每棵树/每帧快照独立，回看不会修改其他帧。全序列结果一次预计算，播放只是显示快照，不是后台继续插入。摘要区明确区别“完整计算结果”与“当前展示帧已完成的插入次数”。
- 播放每 700ms 前进一帧，到末帧自动暂停。编辑、重新生成、手动选帧、切走和销毁都清除播放计时器；返回不自动续播。销毁也清除草稿保存计时器和 DOM。

## 4. 使用步骤与具体例子

打开学习工作台的“B树分裂演示”，使用默认 `10, 20, 30`，点击“生成 / 重置演示”。首帧显示空树，点击“完成下一次插入”两次后，根节点为 `[10 | 20]`，当前已完成 2 次插入。

继续点击“下一帧”四次，依次看到：

| 帧 | 阶段 | 根/结构 | 检查结论 |
| --- | --- | --- | --- |
| 6 | 插入 30 前 | 根 `[10 | 20]` | 有效 2-3 树 |
| 7 | 溢出 | 根 `[10 | 20 | 30]` | 三键暂态，容量未通过；排序/范围/孩子数/叶深通过 |
| 8 | 根分裂与提升 | 新根 `[20]`，左叶 `[10]`、右叶 `[30]` | 有效结构，提升中间键 20 |
| 9 | 插入完成 | 同上 | 3 个键、叶深度 1、树高 2，全部严格检查通过 |

点击“查看末帧”也应得到根 20 与左右叶 10/30；该按钮不会跳过计算，完整结果在生成时已计算。选帧仅改变查看位置。生成后立即导出的报告也包含完整结果，并附当前查看位置。

递归例：点击“载入父递归分裂示例”，序列为 `1,2,3,4,5,6,7`，生成并查看末帧。插入 7 时叶分裂提升 6，父暂态形成 `[2 | 4 | 6]`，再提升 4 建立新根；最终根为 `[4]`，孩子为 `[2]`/`[6]`，四个叶依次 `[1]`/`[3]`/`[5]`/`[7]`，叶深度 2。可在帧列表查看两次分裂及中间父溢出帧。

拒绝例：把输入改为 `10,20,10` 后生成，应显示“重复键10”，没有旧结果；`1000001` 或 65 个键也必须拒绝。可以自行修改混合顺序示例，比较不同形状，但排序键集合应与输入完全一致。

## 5. 产出与保存

JSON 副本包含 feature、schemaVersion、modelVersion、导出时间、完整输入草稿、当前选帧索引，以及预计算结果：全部键、全部帧、帧原因/焦点/提升信息/树/检查、每次完成树、最终树、最终检查与中序键集合。Markdown 逐帧列出相同结构和完整模型记录，区分有效帧与溢出暂态；用户文本按文本渲染，Markdown 中 HTML 字符转义。没有有效结果时可以导出当前草稿，报告明确尚未生成结果。导出 JSON 的草稿可重新计算，当前版本不提供文件导入。

调用主桥接 `files.saveText`，能力 `saveTextSupportsCopyOnly` 必须严格为 `true`，参数含 `content`、`copyOnly:true`；只有返回 `ok===true` 才宣告保存成功。基础层以独占创建拒绝已有文件，取消/失败不清空输入和结果。

全局配置仅保存 `schemaVersion:1` 输入草稿，不存树、帧、结果或播放位置。写入前测量整个 JSON 的 UTF-8 大小，最多 64KiB；序列另限 4096 字节，属于更严格上限。恢复先检查原始存储体积（含额外字段）、版本、字段类型与容量，然后提取已知字段。超限明确提示当前输入未保存，关闭后只能恢复较早草稿，应导出完整 JSON；输入语法错误也可作为有界草稿保存，生成时再校验。

## 6. 验证与限制

运行 `node --test test/feature-L019.test.js test/feature-foundation.test.js`：本功能 20 项测试，基础 6 项测试。包含核心三键手算树、1..7 递归手算树、每帧暂态/严格检查、故障树检查器、重复/语法/数值/容量边界、64 键升降序、快照独立性及完整报告重算。20 个确定性随机排列的每次完成树另用独立遍历校验范围、孩子数、叶同深和输入键集合。

组件测试实际触发注册的编辑、帧选择、插入跳转、播放/暂停、导出事件。用可控计时器验证暂停、切走、编辑、到末帧和销毁不泄漏播放资源，核对严格成功判断、防覆盖参数、草稿恢复和超限不覆盖旧草稿。另运行 ESM 模块导入与 `git diff --check`。

这些是模型与 DOM stub 组件证据，不等于实际 Electron 窗口验收；主代理负责 native 界面、全库集成与 PR。没有安装依赖、启动应用、推送或创建 PR，也不运行已知缺依赖的全库 check。仅实现无重复整数插入的 2-3 树；不含删除、查询训练、数据库页、并发修改或真实存储索引。
