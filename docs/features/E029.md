# E029 默契测试

## 1. 功能内容

内置60道原创、没有标准答案的二选一生活偏好题。2–8名玩家在同一设备上逐人选择，每人连续回答本局的全部题；所有玩家密封完成后统一揭晓逐题选择、同选人数与每两人一致率，并生成可另存的SVG分享卡。

## 2. 为什么需要

朋友常想比较生活偏好的相同与不同，逐题随口回答容易受到先前答案影响。密封交接和最后统一揭晓让每人先独立选择，完整记录使7/10之类的一致率可以核对。统计只描述本局题目，不评价人格、亲密度或关系质量，也不代替事务投票决策。

## 3. 实现方式

60题固定原创题库；随机开始用Fisher–Yates洗牌后选择1–60题，不重复，随机源Math.random仅供娱乐抽题，不提供密码学随机承诺。两人十题验收局固定Q01–Q10。名字1–40字符，按NFKC/小写防重复，题目/玩家/顺序在建立本局时锁定。

有限纯模型只接受A/B，每次密封返回独立新状态。每人最后一题转到下一人的交接页，最后一人的最后一题转到完成状态。所有人完成前报告接口拒绝，UI无导出入口。旧作答节点递归清空文本和值后移除，交接页不保留上一个玩家的输入、自己的选择标签或结果表。暂停遮住当前作答节点，返回恢复当前自己的未提交选择；切换具体功能销毁本局内存。

一致率=同选题数/本局题数×100，最多保留两位小数；逐题A/B计数之和等于玩家数，最多同选人数=max(A人数,B人数)。最多480个选择、28组配对。SVG结果卡为800像素宽，按配对数量增加高度，所有姓名按XML转义；卡内文字压缩适应宽度，JSON与Markdown保留完整姓名和逐题选择。

同屏隐私是合作交接约定，不是登录、授权或加密隔离；不能防止浏览器开发工具读取当前游戏内存。没有网络、AI或账号访问，游戏不自动持久化。

## 4. 如何使用与具体例子

1. 功能工作台搜索E029，填入每行一名玩家和题数，点击“开始密封测试”；也可直接“载入两人十题验收局”。
2. 交接给小明，本人点击“我是小明，开始选择”。每题点A或B，再点密封；密封后不能回改。
3. 小明十题全部选择A并密封，交接页不显示他的选项。小红本人进入，前七题选A、后三题选B。
4. 小红最后一题密封后统一揭晓：小明↔小红同选7/10，70%；前三题中的每题A2人、B0人，后三题A1人、B1人。
5. 查看分享卡和展开的完整题目记录，再另存JSON、Markdown或SVG新副本。需要改玩家/题数时点“建立新局”，明确确认后清空；未确认时可返回原局。

## 5. 使用产出

JSON包含feature/version、完成标记、玩家、题数、全部两人配对同选次数/分母/百分比、每题完整内容、各人A/B选择、A/B计数和最多同选人数。Markdown含同样可读统计和完整选择，SVG是一张已揭晓的配对一致率分享卡。

三个格式只使用支持copyOnly的新副本接口，明确ok=true才显示成功，已有目标拒绝覆盖，取消和失败保留结果。用户通过原生另存对话框选择最终目标。切换功能前需自行导出，本功能不提供存盘恢复或游戏中途导出。

## 6. 验证与限制

6项模型测试涵盖60题唯一性、7/10=70%、同选人数与选择核对、未完成报告拒绝、独立状态、非法选项/名字/容量、最大480选择/28配对及SVG转义。6项基础接口检查一起通过。渲染入口按ESM模式语法检查通过。

真实Electron交接、暂停、统一揭晓及实际文件导出在交付前另验，并在下方记录证据。模型不推断玩家关系质量；同屏身份按钮只供本人自觉交接，不是权限认证。

交付前已使用隐藏隔离 Electron 33.4.11 的生产工作台/preload/catalog/text-writer完成20次实际DOM选择及密封：小明十次A，小红七次A三次B；交接没有自己的选择节点或结果，揭晓前没有分享卡。暂停遮住选择、返回恢复A。最后7/10=70%，首题A2/B0、末题A1/B1；实际JSON4736字节和SVG副本落盘，均copyOnly=true/ok=true。SVG由浏览器解码成800像素宽图并渲染PNG，图像检查发现文字被拉伸，已改为自然比例和按长姓名缩字号，再完整重验并查看结果卡通过。
