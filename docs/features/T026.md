# T026 PDF 体积压缩预演

## 1. 功能内容

选择本地 PDF、目标大小与高/中/低 JPEG 档位，压缩能明确识别的图像 XObject 流。文字、向量绘图、页内容流与页序保留，不把整页转成图片。完整报告每个图像的原尺寸、原流大小/SHA、支持或保留原因、真实候选尺寸/流大小、实际应用状态，以及原件/候选/最终文件大小、节省比例与是否达到目标。原件及输出所有页实际预览完成后才允许确认新目录副本。

压缩只执行一轮固定档位，不为追求目标大小反复降低质量。未达到目标明确显示“未达到”。某图像编码后反而变大则保留原流；候选 PDF 整体变大或无变化时输出原 PDF 字节的新副本，并标明 `original-copy-no-gain`，不能把序列化开销、跳过项或未处理当成压缩成功。

## 2. 为什么需要

邮件体积限制常由高分辨率照片造成，全页栅格化容易失去可搜索文字和向量清晰度。T026 优先调整可解释的照片图像流，用户先对照原件/输出，再决定质量和目标之间的取舍。PDF 容器大小减少不等于所有图片无损、文件安全或目标一定可达；本功能给出实际产物和完整证据，而不是仅估计“预计能缩小”。

## 3. 实现方式和支持边界

本 ID 私有原始 pdf-lib 1.17.1 npm ESM 发行包（523417 字节，SHA-256 `72c052d97b4d5d9fa6cdbdcb7ad709f03d4ddb1122390cb3afeba4d88651d969`）。固定 npm tarball integrity、版本、全依赖原始许可证/版权声明位于 vendor/manifest.json；`.gitattributes` 的 `-text` 保证原发行字节。没有 CDN、运行时下载、新安装包或 shared package/lock 修改。PDF.js 使用项目既有 4.10.38 本地 worker/标准字体/cmap。Python/PIL/pypdf/Poppler仅供开发独立验证，不进入应用运行依赖。

模块 worker 解析 PDF 与编码图像，30 秒到期实际 terminate 该线程，用户取消或切换亦 terminate，并用票据阻止晚回调。单个 PDF 8字节–2MiB、开头 `%PDF-`、1–16页、≤3000间接对象/64图像，页资源及 Form 递归≤8层/512节点、每资源≤128 XObject、每图≤256使用位置。拒绝加密（不旁路权限）、已检测表单/签名结构；这不是完整 PDF 合规或恶意内容扫描。PDF 解析器、JPEG解码器是本地可信库/浏览器能力；字节/像素/线程期限是有界工作约定，不是假称 PDF 解压内存沙箱。

只重编码间接、被页资源或有限 Form 资源引用的 Image XObject：单一 DCTDecode（可为单元素 filter 数组）、8bit、DeviceRGB、无 Mask/SMask/Decode/DecodeParms/额外色彩/未知字典语义；允许普通 Type/Subtype/Width/Height/Length/Name/Interpolate 与明确 false ImageMask。要求 JPEG 有 JFIF 标记、单扫描 baseline SOF0、三分量索引1/2/3、原 JPEG 与 PDF 字典尺寸相同；拒绝 EXIF 方向、ICC、Adobe APP14 色彩变换与 progressive/未知标记语义。JPEG 最大边4096/单图4194304像素、实际解码累计16777216像素；超过预算的后续图像保留并报告，不隐式缩额或猜编码。

所有未支持图像（包括 CMYK/Gray/Indexed、Flate、透明、mask、复杂过滤器、色彩映射、direct stream、不在页资源中引用）保持原流并逐项报告。PDF 内联图像不是此处枚举的 Image XObject，随页内容流原样保留，不声称已列出/压缩它们。JPEG编码失败、输出非法/尺寸不符也保留源流并标出原因。资源损坏、循环、容量超限或文件解析失败整体拒绝，没有可保存部分产物。

高档最大边1600/quality0.85，中档1000/0.65，低档600/0.45；不放大，尺寸按等比例缩放并四舍五入（报告实际尺寸，可能产生≤1像素的纵横比舍入）。worker 内使用浏览器 createImageBitmap/OffscreenCanvas 真实解码/绘制/JPEG编码，显式sRGB画布；只移除本功能画布编码器刚生成JPEG中的冗余ICC APP2标记（不修改编码熵流），使DeviceRGB标记保持一致，输入未知ICC依然拒绝重编码。关闭 bitmap并释放 canvas。quality 是编码器参数，不是画质分数/PSNR，JPEG属于有损；纹理、细小字、线条可能变化。保留图像原引用与其他允许的字典键，仅替换 JPEG 流、Width/Height。PDFDocument.load updateMetadata:false，同一文档 save，无页面重排或重建；前后每页 MediaBox/CropBox/旋转/原页内容流压缩字节SHA必须完全相同。对象容器/xref序列化可能变化，不承诺整个输出PDF字节一致或数字签名有效。

全部原页+全部输出页通过 PDF.js 白底72DPI真实渲染（isEvalSupported:false/disableFontFace:true），页数与模型必须一致；每页边4096/4194304像素，源+输出累计16777216像素，完整预览30秒协作期限。某页失败/超限/缺依赖则清除全部结果，禁止保存，不只展示成功页当完整预览。渲染任务成功只证明任务完成；用户仍须查看JPEG细节、字体替代与文字可读性。所有canvas及源字节引用在隐藏/切换/销毁时清除；worker/渲染/加载器释放，事件destroy移除。参数编辑立即废弃旧产物；不写来源、PDF字节、报告或秘密到config，不上传。

输出PDF≤2MiB、完整报告≤2MiB，总目录≤4MiB；任何输出超限整体拒绝，无截断。完整预览相对路径/SHA后使用生产 files.exportBundle({copyOnly:true})，由保存对话框选择一个不存在的新目录。已有目录/文件或选回源PDF拒绝，不覆盖。ok===true才成功；取消/false/undefined/异常不报成功，当前结果保留。缺生产能力可预览但不能写盘。已提交主进程写入不可中途取消，可在保存对话框取消；生命周期清除内存后仍准确显示先前回执。公共writer正常失败清理本次新目录；partialPath提示人工核对，不保证崩溃/断电事务。

格式依据：[HTML Canvas明确sRGB与编码语义](https://html.spec.whatwg.org/multipage/canvas.html)、[ISO32000-1 图像XObject/DCTDecode](https://developer.adobe.com/document-services/docs/assets/35e4369068f86065372c18787171a17e/PDF_ISO_32000-1.pdf)、[pdf-lib PDFDocument load/save](https://pdf-lib.js.org/docs/api/classes/pdfdocument)、[PDF.js官方渲染API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)。实现是明确有限域，不等同通用 PDF 优化器、无损压缩或 PDF/A 认证。

## 4. 如何使用

打开 T026，选择一份本地 PDF。源文件只读进内存，没有自动压缩。设置目标1–2048整数KiB及高/中/低档位；点“压缩图像并预览全部源页与输出页”。查看实际大小/目标状态/每图保留原因和所有页对照，必要时改变档位并重新主动预演。

所有原件和输出页均按页序列出，完整JSON报告含每页/每图，没有摘要截断。确认接受有损图片差异后点“确认创建完整PDF及报告新目录”，在保存对话框填写一个不存在的新目录名称。先前预演有缺页或渲染失败时不可保存。取消内存任务终止worker并丢弃结果；隐藏或切换功能清除来源，返回须重新选文件。

## 5. 使用后产出

新目录固定 `compressed.pdf` 与 `report.json`。PDF 是全部页，普通文字/向量页内容原流保持，支持JPEG真正压缩；没有收益时是原PDF完整字节副本且报告明确说明。报告为版本化 T026-pdf-image-compression，包含来源文件名/大小/SHA、目标/档位、最终输出大小/SHA/节省率/目标状态/候选大小、全部页面和内容流摘要、每图全部位置与支持/实际应用状态、原件及输出每页实际渲染尺寸和待人工确认标记。报告本身会包含来源名称/哈希/资源路径，不是匿名化产物；不带完整源字节或图像原字节。
