# E004 管道接通

## 功能

“管道接通”是离线旋转管件谜题，包含 20 个固定、可重放、具有可验证解的关卡。点击直管或弯管旋转 90°，将左侧入口的水接到右侧指定出口，且水流必须经过全部黄色 `◇` 节点。

提供关卡选择、上一关/下一关、顺逆时针旋转、路径预览、断口定位、必经节点计数、旋转步数、暂停、重置、通关记录、本关最少步数及 JSON 导出。所有关卡直接可选，不需要先解锁，不依赖网络或 AI。

## 必要性与现有功能区别

项目现有醒脑游戏侧重顺序注意力、记忆或网页游戏。该功能新增的是图连通与两接口管件旋转规则：需要将各管件的方向相向连接，并同时满足出口与节点约束。它不复用方块消除或六边形消除，也不是现有小游戏换主题。

短时休息可以只完成一关；没有倒计时压力，玩家可以任意次试接并定位断口。完成后留下可检查的实际水流路径和通关步数，不以“点击过”或“连到任意边缘”充当完成。

### 关卡与规则

关卡局号从 `E004-L01` 到 `E004-L20`，由固定种子生成，重复打开同一关得到同样的管件和初始方向。

- 第 1–5 关为 4×3、1 个必经节点。
- 第 6–10 关为 5×3、2 个必经节点。
- 第 11–14 关为 6×5、2 个必经节点；第 15 关为 6×5、3 个节点。
- 第 16–20 关为 7×5、3 个必经节点。

生成器先构造逐列前进、列内单向移动且不重复格子的解路径，将路径上的格子设成所需的直管/弯管，再打乱方向并填入其他管件。首个入口管件总是以未接通方向开始，避免初始局已经通关。全部 20 关有解；不承诺唯一解或最少步数的唯一性。

每块管件只有两个接口；直管连接上下或左右，弯管连接相邻两个方向。入口在左边固定格子的左口，出口在右边固定格子的右口。管件可以转，入口/出口位置保持不动。

水流从入口逐格追踪：当前出口方向与相邻格的反向接口必须同时存在，才进入相邻格。接口不匹配时停在当前格，下一格不着色；流出其他边缘会标为错误断口。仅当从指定出口流出且经过全部必经节点才判胜。已经接到出口但漏过节点时仍可继续旋转。

`PipeGame` 持有管件和方向的独立副本。渲染层仅读取 `getView()` 中的当前方向与实际水流，不读取生成器的 `solution` 或 `solutionPath`；通关之前没有一键显示答案。算法有重复访问保护，输入尺寸、节点与管件类型也有验证。

### 生命周期

`deactivate` 暂停并遮住棋盘；`activate` 保持暂停，等待点击“继续”；`destroy` 移除棋盘、独立样式链接、窗口可见性监听及下载对象 URL。窗口隐藏也会暂停。该游戏不用计时器，不存在离开后继续运行动画或倒计时的后台任务。

已完成并排队的成绩写入可以在销毁后结束，异步回调不会操作已销毁界面。通关后的旋转被模型阻止，同一局只保存一次；重置后可形成新的通关记录。

## 使用

1. 在功能工作台选择“管道接通”。默认第 1 关，可用下拉菜单或上一关/下一关导航。
2. 先看左边进水箭头和右边指定出水箭头。黄色 `◇1`、`◇2`、`◇3` 是水必须经过的节点。
3. 点击格子顺时针转 90°；右键逆时针转 90°。触屏可点击“点击：顺时针”切换为逆时针模式，再点格子。
4. “路径预览”默认打开：蓝色标出水已经流到的管件，红色标出断口，状态文字给出断口行列和方向。可关闭预览独立推理，重新开启不增加步数。
5. 连接到出口且经过所有节点后显示通关、水流坐标路径和步数，同时保存本关成绩。
6. “重置本关”恢复固定初始布局并归零步数。切到另一关也会重置新关，中断的局不计成绩。
7. “暂停”隐藏棋盘；“继续”保留当前方向和步数。关闭功能再打开会从新局开始，不跨进程恢复中断的局。
8. 成绩列表的“重玩”打开同一固定关卡；“导出通关记录”保存 JSON。

键盘的棋盘只有一个 Tab 入口；方向键移动，Home/End 到行首尾，Ctrl+Home/Ctrl+End 到棋盘首尾。Enter 或空格按当前顺逆模式旋转；R 或 Shift+Enter 强制逆时针旋转；Esc 暂停并将焦点移到继续按钮。

每格的可访问名称包括行列、直管/弯管、接口方向、入口/出口、必经节点和当前水流状态。节点编号和管口形状不依赖颜色辨识。格子常规尺寸 56×56，窄屏为 48×48，支持滚动；减少动态效果设置会关闭按钮过渡。

## 产出与保存

一次完整通关产生以下记录：

```json
{
  "level": 1,
  "seed": "E004-L01",
  "moves": 14,
  "path": [0, 4, 5, 1, 2, 6, 10, 11, 7],
  "checkpoints": [2],
  "finishedAt": "实际通关时的 ISO 时间"
}
```

`path` 是本次有效连通的水流路线，`checkpoints` 是已经过的必经节点；二者的格子索引均从零开始，`行 = floor(index / width) + 1`，`列 = index % width + 1`。`moves` 每次顺时针或逆时针 90°操作计一，预览、导航、暂停不计步。点击无效位置或已通关棋盘也不计步。

存储在配置键 `features.E004.scores`，包含 `version: 1`、最近 20 次 `recent` 和每关最少步数 `best`。`best` 按关卡去重，最多 20 项；即使某条最快成绩滚出近期列表，仍保留在本关最佳中。比较只针对同一固定关卡，不混用不同规格和布局。

配置服务缺失时使用 `localStorage` 键 `agent-toolbox:E004:scores:v1`。保存失败会显示提示并允许从当前内存导出。损坏或不满足关卡、局号、路径邻接、管件类型及必经节点约束的记录会被过滤。

JSON 导出顶层包含 `feature: "E004"`、`version: 1`、`exportedAt`、`recent`、`best`。宿主提供 `files.saveTextSupportsCopyOnly` 时使用 `copyOnly: true`，由用户选择新文件；宿主未提供时使用浏览器下载。取消保存按宿主 `canceled` 字段识别。记录用于个人对局回看，不提供竞技防作弊或云同步。

## 具体可重放例子

打开**第 1 关，局号 `E004-L01`**，点击“重置本关”，保持“点击：顺时针”。入口位于 `(1,1)`，出口位于 `(2,4)`，必经节点位于 `(1,3)`。

按顺序执行以下操作，坐标从 1 开始；“点击次数”代表每次顺时针 90°：

| 顺序 | 行 | 列 | 点击次数 |
| --- | --- | --- | --- |
| 1 | 1 | 1 | 2 |
| 2 | 1 | 2 | 2 |
| 3 | 1 | 3 | 3 |
| 4 | 2 | 1 | 1 |
| 5 | 2 | 2 | 1 |
| 6 | 2 | 3 | 1 |
| 7 | 3 | 3 | 2 |
| 8 | 3 | 4 | 2 |

预期结果：**14 步通关，经过 1/1 个节点，水流路径 9 格**：

`(1,1) → (2,1) → (2,2) → (1,2) → (1,3) → (2,3) → (3,3) → (3,4) → (2,4)`。

最近成绩增加一条第 1 关 14 步记录；本关最佳若原来更快则仍保留更快值。再次点击通关棋盘不改变步数，也不会重复保存；重置并重复上述操作可以再得到相同有效路径。这个例子给出完整可验证的一局，不声称是最短解。

独立规则例子：3×2 棋盘上第一行三块水平直管，从 `(1,1)` 流到 `(1,3)`，却把 `(2,2)` 设为必经节点时，`reachedExit` 为真而 `won` 为假。将中间直管改成垂直后，水只到 `(1,1)`，断口是它的右侧，不能把 `(1,2)` 标成已通水。
