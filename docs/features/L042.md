# L042 跟读节奏对齐

## 1. 功能内容

本功能在学习工作台的「语言与表达训练」中提供本地示范录音与本地跟读录音的时间结构对照。用户选择两份已有 PCM16 WAV，人工设置 1–10 个对应段的起止秒数，查看两份真实来源的波形包络、每段时长、时长比与差、段前停顿与差。编辑秒数或拖动边界滑块时同步重算；越界、重叠或无效输入使旧报告立即失效。

对应段是用户自己的标注。工具不录麦克风、不执行语音识别、不生成声音，不自动判断发音正确性，也不将「更接近示范节奏」自动判为更好的发音。

首版完整支持以下产出：

- 两张上下排列的 SVG 波形图，使用各自绝对时间横轴和统一的原始幅值范围 −1 到 1；绘制来源采样的 min/max 包络与人工边界。
- 每段的示范/跟读时长、跟读÷示范时长比、跟读−示范时长差、两份段前停顿、停顿差和可定义的停顿比。
- 末段后的未标尾部、全部来源元数据与原字节 SHA-256、完整输入快照与解释。
- 完整 JSON/Markdown 预览与新副本导出，以及分别导出示范/跟读波形 SVG。不会写入或覆盖来源录音。

## 2. 为什么需要

回听跟读录音可以发现「听起来拖长了」，却难以区分某个句段的持续时间、段间间隔和整份录音的长度。人工时间对照把这些差异转换为可检查数字，同时保留原始波形与标注供复核。例如相同对应段的示范为 2 秒、跟读为 3 秒时，显示时长比 1.5，而不是给出没有依据的发音总分。

本功能增加了已有 voice 语音输入之外的训练能力：比较两个用户提供的声音文件的人工时间标注；不会把语音输入或自动转写当作发音评估。

## 3. 实现方式

### 输入与资源预算

| 项目 | 首版范围和拒绝规则 |
| --- | --- |
| 录音数量 | 恰好示范、跟读两份，未成功载入两份时没有比较报告 |
| 文件格式 | RIFF/WAVE、单一 16 字节 PCM fmt、format=1、16 位整数、单/双声道、8–48kHz、单一非空且帧完整的 data chunk |
| 文件/时长 | 每份 44 字节至 6MiB、>0 至 30 秒；两份合计 ≤12MiB/60 秒；最多64个 chunk，越界、错误声明长度、压缩/扩展WAV全部拒绝 |
| 真实解码 | AudioContext 48kHz解码副本，校验声道、时长、帧数；每份解码最多1,440,000帧；Context随后关闭 |
| 人工段 | 1–10 个对应段，两份都必须按时间顺序、无重叠且起点<终点；可邻接，不可超出各自音频 |
| 时间精度 | 文本0–30秒，最多6小数位，不接受指数、负数、Infinity；滑块步长0.001秒；使用JavaScript有限Number，表格显示9位有效数字，JSON保留计算值 |
| 字符 | 段名≤60、备注≤500、文件名≤120 Unicode码点，拒绝非法控制/孤立代理字符 |
| 持久化 | schemaVersion=1的分段/备注/音量输入草稿，JSON UTF-8体积≤64KiB；校验版本、字段和体积，不接受派生报告回填 |

`model.mjs` 解析WAV边界和元数据，计算时间公式，生成完整报告、Markdown及XML转义的SVG。包络直接读取原文件PCM采样，以采样整数÷32768作为幅值；每箱取所有声道的 min/max，避免双声道正负相抵造成假静音。每份最多600箱，箱边界完整覆盖全部采样帧，每16,384帧异步让出并检查取消。不是逐采样无损图、响度、音素边界或发音评分。

`index.js` 以真实 File/arrayBuffer 获取来源字节，SHA-256校验原字节，`decodeAudioData`读取**副本**，创建来源File的Blob URL供HTMLAudio播放。只保留两份Blob URL及有界包络；临时原字节与解码AudioBuffer不作为长期配置保存。创建组件返回同步生命周期对象，工作台通过meta发现并动态加载。

文件读取、hash与原生解码没有可用的逐字节Abort接口。取消/切走通过票据使迟到结果无效、关闭当前Context，包络循环合作式取消；界面等当前任务释放后允许重新选文件，不能声称底层读取已被强制中断。一次仅一个读取/解码流程。成功更换来源才释放旧URL；失败或取消保留先前成功验证的来源。旧来源在卡片显示完整文件名/hash。

### 时间定义

每个段为各自录音绝对秒数区间 `[start,end)`；录音不会移位、拉伸、裁剪或被新写入。

```
示范时长 = 示范end - 示范start
跟读时长 = 跟读end - 跟读start
时长比   = 跟读时长 / 示范时长
时长差   = 跟读时长 - 示范时长
首段段前停顿 = start - 0
后续段前停顿 = 当前start - 上一段end
停顿差 = 跟读段前停顿 - 示范段前停顿
停顿比 = 跟读段前停顿 / 示范段前停顿（示范为0时null/未定义）
末段未标尾部 = 文件时长 - 最后end
```

「停顿」是人工区间间隙的名称，未标区间可能包含声音；不会自动检测静音。末段后的未标尾部单独列出，不虚构下一段。两图横轴分别覆盖各自全长，所以等比例视觉位置不代表同一秒数，应看刻度和表格。

「将整份录音对应为一段」将起点设0，并将来源终点向下取到6位小数，避免最后一帧时长不能用6位小数精确表达时越界；最多不足1微秒的尾部仍如实单列。无效输入不截断为合法值。SVG逐行列出所有段边界，长段名仅图上显示前26码点与省略号，完整名称保留在SVG title/metadata、界面表格和JSON/Markdown。

### 播放、草稿和导出

播放只有用户按钮发起；支持暂停、手动继续和停止。读取、解码、重置分段、换来源、窗口恢复都不自播。输入改变停止当前播放；播放失败明确显示，不将失败称为听过。切走停播并取消在途解码；销毁额外释放所有Blob URL和DOM。真实HTML媒体事件不证明用户听见、设备发声或耳机正常。

配置仅保存结构合法的分段、备注、音量，不含音频内容、来源名字/hash、波形或结果。重新打开只恢复分段，须重选原文件后复算。保存队列最多一个进行中和一个最新待保存快照；旧完成回调不能掩盖较新输入错误。非法草稿不保存，关闭会恢复先前合法草稿，不能声称最新非法/大型输入已保存。

导出时复制当时完整有效报告，调用生产 `files.saveText({content,extension,defaultName,copyOnly:true})`，要求 `saveTextSupportsCopyOnly===true`且结果`ok===true`才显示成功；取消/失败保留报告。生产writer用`wx`拒绝任何已存在目标，不覆盖来源或已有报告。音频字节不在导出中，但文件名、hash、备注和波形包络是来源派生信息，保存前可检查预览。

媒体API概念来源：[W3C decodeAudioData](https://www.w3.org/TR/webaudio/#dom-baseaudiocontext-decodeaudiodata)、[WHATWG HTMLMediaElement.play](https://html.spec.whatwg.org/multipage/media.html#dom-media-play)。时间公式和包络口径是本工具显式定义，不代表自动声学评分标准。

## 4. 使用步骤与可复现例子

1. 打开「功能工作台」，在学习→语言与表达训练中选择L042。
2. 选择示范与跟读PCM16 WAV，成功后卡片显示完整文件名、时长、格式和SHA-256；此时尚未播放。若是MP3、压缩WAV或太长，先用用户自己的音频工具准备符合范围的文件。
3. 编辑每个对应段的名称、两份起止秒数，或拖动「移动段…起点/终点」滑块。按同一个语言单位人工对应；两份起点无需一样。增加或删除段，最多10段。
4. 查看上下波形、每段表格与未标尾部。检查声音来源和标段是否合理；需要时主动播放整份录音，可暂停/继续。不依据波形自动断言静音或发音错误。
5. 预览完整JSON/Markdown，选择新目标导出；也可分别导出两张波形SVG。关闭后需重选音频，分段草稿才复算为报告。

### 验收例：2秒与3秒

准备任意可播放的2秒示范和3秒跟读PCM16 WAV。保留默认唯一对应段：示范0–2、跟读0–3，显示两段时长2/3、比1.5、差+1秒，段前停顿0/0、差0、比未定义。拖动「移动段1跟读终点」到2.5，文本终点同步为2.5，时长比立即变1.25、差+0.5秒、跟读未标尾部0.5秒。把跟读终点改4，报告和导出按钮失效并提示越界；改回3恢复有效输出。

### 两段停顿例

| 段 | 示范区间 | 跟读区间 | 时长比 | 示范段前停顿 | 跟读段前停顿 | 停顿差 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0–0.8 | 0–1.2 | 1.5 | 0 | 0 | 0 |
| 2 | 1–2 | 1.5–3 | 1.5 | 0.2 | 0.3 | +0.1 |

把第二段跟读起点改1.4：时长比变1.6，跟读段前停顿0.2，停顿差0。旧报告在导出文件中保留，当前界面只显示最新有效比较。

下面的独立Node脚本生成确定的2秒/3秒PCM16 WAV夹具，含上述人工段间静音；请在临时目录保存脚本运行，**仅创建不存在的新文件**，不执行用户音频或联网：

```js
const fs=require('node:fs');
function sample(seconds,hz,rest){
  const rate=8000,frames=seconds*rate,b=Buffer.alloc(44+frames*2);
  b.write('RIFF');b.writeUInt32LE(b.length-8,4);b.write('WAVE',8);
  b.write('fmt ',12);b.writeUInt32LE(16,16);b.writeUInt16LE(1,20);
  b.writeUInt16LE(1,22);b.writeUInt32LE(rate,24);b.writeUInt32LE(rate*2,28);
  b.writeUInt16LE(2,32);b.writeUInt16LE(16,34);b.write('data',36);
  b.writeUInt32LE(frames*2,40);
  for(let i=0;i<frames;i++){
    const t=i/rate,v=t>=rest[0]&&t<rest[1]?0:Math.round(12000*Math.sin(2*Math.PI*hz*t));
    b.writeInt16LE(v,44+i*2);
  }
  return b;
}
fs.writeFileSync('示范.wav',sample(2,440,[.8,1]),{flag:'wx'});
fs.writeFileSync('跟读.wav',sample(3,660,[1.2,1.5]),{flag:'wx'});
```

人工段不要求夹具必须静音；本模型不会从夹具频率/静音自动建立段。

## 5. 产出内容

JSON顶层包含feature/schemaVersion/modelVersion、完整input、两份sources、两个完整waveforms、每个segments全部中间时间与指标、trailingUnmarkedSeconds、definitions。JSON和Markdown均保留全部1–10段与每份最多600箱；没有只导出当前屏幕页或视觉截短名称。Markdown含简洁指标与完整JSON安全围栏，可检查所有精确计算值和来源hash。

SVG包含真实幅值图、刻度、人工边界与逐段区间；metadata包含该来源完整元数据/hash、所有段名与边界、完整波形包络。两份各自导出，导出内容不包括PCM音频，不能用其替代原录音。JSON/Markdown报告只是本地人工标注后的时间对照记录，没有发音总分、识别文本、硬件或人耳验证结论。
