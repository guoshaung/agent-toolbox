# L027 数据契约反例训练

## 1. 功能内容

在“学习 → 编程验证与调试训练”中，用有限 JSON 字段契约训练“先判断、再看反例、再修正规则”。可以编辑规则表、选择或手填 JSON 样例、预测通过/失败；提交后锁定该轮规则、样例与预测，再揭示全部违反路径，统计误判，并记录新的规则修订。

首版包含五类约束：类型、必填、数值范围、字符串长度、数组长度。支持 `number/string/array/boolean` 四种字段类型，规则仅作用于 JSON 顶层字段；不实现完整 JSON Schema。最多 8 条规则、24 个修订、24 轮训练，完整会话另受 64KiB UTF-8 限制。没有 AI、网络、额外运行时或新增依赖。

## 2. 为什么需要

接口文档里“age 是数字”容易被当成完整契约，却遗漏缺字段、null、错类型和上下界。直接运行校验器只能看到结果，无法保存学员看答案之前的理解。本工具把预测先锁定，再与确定性规则判定对照，区分“我的预测错了”与“规则可能不符合业务意图”。

例如上限 120 时 age=130 是契约反例；把上限修到 150 后可以产生新的通过轮次，但旧轮误判仍保留。工具不会根据“修后通过”自动宣布业务规则正确，修订的合理性必须由人判断。这是有限反例教学闭环，不是生产批量校验器、源代码扫描器或自动生成业务预言机。

## 3. 实现方式与精确规则

`meta.json` 供公共工作台发现，`index.js` 提供同步 `create(root, ctx)` 与生命周期，`model.mjs` 实现纯解析、判定、修订、提交/揭示及存储校验，`style.css` 使用项目现有主题变量。用户文本通过 `h`/`textContent`/`value` 呈现，未使用 `eval`、`Function` 或用户代码执行。

### 契约与违反项

规则字段名须以英文字母开头，长度 1–20，后续只能为字母、数字或下划线；重复规则字段拒绝。`__proto__`、`prototype`、`constructor` 禁用。

| 约束 | 判定口径 |
| --- | --- |
| 必填 | 以 own property 是否存在为准，缺必填报 `required`；缺可选字段通过 |
| 类型 | present 的 null 是 `null`，不是缺字段，且不符合四种允许类型；错类型报 `type` |
| 数值范围 | number 使用含端点的闭区间，空上下界表示不限制；超界报 `range` |
| 字符串长度 | 按 Unicode 码点计数，不按 UTF-16 代码单元或 grapheme；报 `stringLength` |
| 数组长度 | 仅计元素数，不检查元素类型；报 `arrayLength` |

缺必填/错类型后不追加该字段的范围或长度错误，其余字段继续判定。未配置的额外字段忽略。一个轮次即使有多条违反项，只记一次误判：预测通过与真实通过不一致即 `misjudged=true`。预测失败且真实失败算判断正确，但不代表学员已经准确指出每个违反项。

上下界输入为普通有限十进制文本，不接受指数写法；数值绝对值≤10亿，长度界限为 0–512 整数，下界不得大于上界。类型切换时不适用的栏位禁用并不参与计算；例如 boolean 不用数值或长度界限。

### JSON 范围与 Unicode

自有递归 JSON 解析器在存入对象之前检查解码后的重复键，因此 `"age"` 与 `"a\u0067e"` 重复也会拒绝。每一层都拒绝三种原型字段。只接受标准双引号 JSON，拒绝多余尾部、NaN、Infinity、孤立代理项和任意代码。

样例≤4096 UTF-8 字节；顶层必须为对象，允许有界嵌套数据，但契约不递归检查字段。根深度为 0，子值深度最多 4；整个样例最多 128 个值，键不单独计入值数量。每对象≤16 字段、每数组≤32 元素、每字符串≤512 Unicode 码点；数值须有限且绝对值≤10亿。超限拒绝整个样例，不截断或部分计算。

`😀` 长度为 1，`e` 加组合重音 `́` 长度为 2；工具不做 Unicode 规范化。JSON 数字采用 JavaScript Number，这是契约判断教学模型，不提供十进制精确算术或全部数字表示误差分析。

### 预测与修订状态

“应用规则修订”先验证规则：有效且与最新应用规则不同才追加修订，相同规则不增加条目。草稿可以暂时含不完整 JSON 或未完成的界限编辑，此时允许有界保存，但不能提交预测。

提交预测须使用已应用的当前规则、合法 JSON、pass/fail 预测；产生包含修订号、独立规则快照、原样例文本与预测的轮次。此时 `result=null`，UI 与导出均不显示计算答案。为避免锁定后容量不足无法揭示，提交时内部计算结果所需的确切字节数并预留容量，但未揭示记录不保存或输出该答案。最多一个未揭示轮次，必须先揭示再提交下轮。

揭示只使用锁定快照，不使用当前编辑器内容；已揭示轮次不可再判定或改预测。草稿编辑会清掉当前观察选择，历史中的旧预测/结果保持不变；未揭示轮次可以通过“查看轮次N”继续揭示。修订不会回算旧轮。这里的不可覆盖是应用状态约束，不是防止用户手动篡改外部配置的安全/签名机制。

### 保存、容量、导出和生命周期

配置键为 `features.L027.state`，`schemaVersion:1`，保存当前草稿、全部规则修订和完整锁定轮次，包括已揭示结论。每次保存前用 `TextEncoder` 测整个 JSON 的 UTF-8 体积；恢复也先查整个原始对象的 64KiB 上限、版本与字段结构，再检查已揭示结果和锁定快照一致性、修订引用、未揭示顺序和未来结果容量。未知大字段不会绕过原始体积检查。

会话容量或记录条数超限时拒绝新增/编辑，不默默截断。超大草稿编辑会退回之前内容；记录历史保持。用户需先导出完整会话，再勾选“我已导出或同意清空本会话历史”，主动开始新会话。配置写入失败会显示提示，关闭后只能恢复较早状态，不能承诺最新记录已保存。

输入编辑后 250ms 合并保存；切走/销毁清理计时器并尝试保存，销毁清空组件。没有后台播放或网络操作；异步导出完成后不会向已销毁 DOM 写消息。

导出前检查 `saveTextSupportsCopyOnly===true`，生产桥接发送 `copyOnly:true`。仅 `response.ok===true` 宣布成功；取消、未确认成功和 EEXIST 分别反馈。基础主进程采用 `wx` 创建新文件，已有目标不会被覆盖。JSON 保存完整会话；Markdown列全部规则修订、原预测、样例、揭示状态、违反路径和误判，未揭示轮次不泄露计算结论。Markdown 对 HTML 特殊字符转义。

## 4. 使用步骤与可复现例子

### 核心验收：age=130 的误判与修订

1. 打开“功能工作台 → L027 数据契约反例训练”。默认契约为 age/number/必填/最小0/最大120，默认样例 `{"age":130}`，默认“预测通过”。
2. 点击“提交预测并锁定”。显示轮次1/修订1，尚未揭示；此时导出 JSON 的 `rounds[0].result` 为 null。
3. 点击“揭示锁定轮次”。显示真实失败、`$.age · range · 值130超界，闭区间[0, 120]`；统计“已揭示1轮 · 误判1条”。
4. 将“规则1最大值”改为 `150`。旧观察清空，历史保留；直接提交会提示先应用规则修订。
5. 点击“应用规则修订”，再“提交预测并锁定”，最后“揭示锁定轮次”。轮次2/修订2真实通过，累计仍为 1 条误判。
6. “查看轮次1”仍显示原上限120、原预测通过、原失败/误判；导出包含两条独立规则快照 `[120,150]`，不是把旧结果改成通过。

### 缺字段、类型与端点

用默认修订1分别载入缺字段 `{}`、null `{"age":null}`、错类型 `{"age":"20"}`：提交预测再揭示，分别报 required、type、type。`{"age":0}` 和 `{"age":120}` 均通过，`-1/121` 分别失败。若已修到150，则121通过，这正是规则快照与修订号需要明确的原因。

### Unicode 与数组训练

新增 name/string 规则，勾必填，最短/最长均为1，应用修订。样例 `{"age":20,"name":"😀"}` 通过；换为 `{"age":20,"name":"é"}`，预测失败后揭示 `$.name · stringLength · Unicode码点长度2超界`。

新增 tags/array，设置最短1/最长2；`{"age":20,"tags":[]}` 违反 arrayLength，`{"age":20,"tags":[null]}` 满足数组长度，元素 null 不会被额外校验。若 name 已被设为必填，样例还应补 name；工具不会自动忽略其他契约。

### 编辑未揭示轮次

提交默认130/预测通过后，将草稿预测改为失败并载入下界0。当前观察清空，不能提交新轮；从历史查看轮次1再揭示，仍判原130与原“通过”预测，记1条误判。当前草稿0/失败只是下一轮候选，不覆盖锁定记录。

## 5. 产出

界面产出包括锁定预测、样例与修订号，全部真实违反路径，逐轮误判/通过统计，历史轮次及每次有效规则修订。历史只按用户实际提交的轮次计数，不把重复点击揭示算成额外训练。

完整 JSON 包含 `feature/modelVersion/schemaVersion/exportedAt/session`。session 内含草稿、修订规则、锁定轮次；每轮结果为 null 或 `{passed,violations,misjudged}`。可复核旧轮时使用该轮规则与样例，不能使用最后一次编辑器规则代替。Markdown适合人工复盘；JSON保留原始样例文本，更适合独立复算。首版不提供文件导入、多用户成绩、标准 Schema 或业务正确性评分。
