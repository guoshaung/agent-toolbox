# E001 推箱子

## 1. 功能内容

20 个离线关卡，通过方向键、WASD 或四个方向按钮移动玩家，将全部箱子推到目标。提供移动/推箱、撤销一步、重开、关卡选择、下一关、当前棋盘续玩、各关最佳步数/推箱次数和精确最优总步数对比。20关全部可选，不要求先通关才能尝试后面的关卡。布局包含墙、单箱/双箱/三箱、转角、回廊和并排目标，不是同一图改颜色；关卡是本实现自制的有限布局。

棋盘用 ● 表示玩家、▣ 表示箱子、◎ 表示目标，已到目标的箱子为绿色 ✓；每格有行列与状态的无障碍标签。响应式棋盘最大宽480px、最大8列7行，点击棋盘获得键盘焦点。没有计时器、动画循环、网络、设备授权或运行时随机性。

## 2. 为什么需要

用一小局空间规划替代漫无目的切换窗口。前几关只需少量移动学习规则，后面需要绕到箱子背后、处理多个目标及通道。撤销和重开使错误推箱可以恢复；自动保存当前步迹，让退出后不必重新做已经完成的思考。

步数对比有明确口径和独立验证，避免把随意设置的难度数字叫作最优解，也避免把推箱次数和总移动次数混用。全部关卡直接可选，单局最多10000成功步，普通游玩不会被几十步的低上限截断。

## 3. 实现方式、规则与边界

`levels.mjs` 固定保存20个不同布局、标题与精确最优总步数；`model.mjs` 实现合法移动、推箱、撤销、结算、源步迹恢复及报告；`index.js` 用现有 `h()` 实现静态DOM棋盘和控件，不执行用户HTML。各关封闭矩形边界、一个玩家、1–3箱，箱子数等于目标数，初始未通关。规则如下：

- 每次成功移动玩家一格算一步；推箱也包含在这一步内。撞墙、箱子后方有墙/另一箱、无效方向不计步、不改坐标。每次只能推一个箱子，不能拉箱子。
- 全部箱子位于目标后，该局冻结方向和撤销，更新本机最佳记录并只结算一次。再次按方向键不会追加步数/重复保存结算。可以明确重开挑战，或切换下一关。未通关时撤销恢复玩家、全部箱子、总步数和推箱次数。
- 本机最佳先比较总步数，再在同总步数时比较推箱次数。已通关数量按有最佳记录的不同关卡数计算，重玩不重复增加。精确最优指成功移动总步数，不声称最少推箱数；多用步数=本机最佳总步数−该关精确最优。
- 键盘只在棋盘获得焦点时处理；方向键/WASD单次按下走一步，按住重复事件忽略，不拦截其他面板键盘。暂停/隐藏时禁用操作；返回保持当前棋盘，不自动走步。没有后台RAF或计时器，销毁释放全部棋盘、按钮、文件和可见性监听。
- 单局成功步迹最多10000字符（U/D/L/R），撤销最多回退该局全部已有步；到上限拒绝进一步成功移动，允许撤销或重开，不截断。内存只保留有界坐标撤销记录，配置只存源步迹。重开/切关清空本局步迹，保留各关最佳；只保存当前关卡一个未完成棋盘，不保留20个并行未完成局，界面明确切关将重开所选关卡。

自动进度位于 `ctx.config` 的 `featureLab.E001.progress`，schema1包含 `levelId/trace/best`，不接受来源文件直接提供玩家/箱子坐标或伪造渲染状态。恢复从内置初始布局逐步重放每一步，拒绝受阻步、通关后的追加步、未知关卡、未来版本、未知/缺失字段、超过10000步和无结算记录的通关步迹。最佳步数必须是该关最优至10000的整数，推箱数为1至最佳步数的整数；当前通关局的最佳不能比当前局更差。记录仍可被用户编辑，不是可信排行榜或防作弊认证。

JSON导入使用浏览器FileAPI、严格UTF-8及有限解析，最多65536字节、6层、每对象24字段，再按schema限制20个最佳记录；拒绝重复字段（包括转义后重复）、小数/指数/不安全整数。整个版本化存档/导出最多64KiB，不静默截断；最大10000步源迹往返已经实测。保存期间锁住新操作，失败明确提示临时保留、另存JSON或重试，公共配置的内存缓存不被当成成功落盘证明。无效自动进度保留原值，必须勾选确认重新建立，或明确确认导入有效备份才覆盖。

最优值在测试中以独立FIFO广度优先搜索核验：状态为玩家位置+排序后的全部箱子，每条合法移动边成本为1，逐层第一次到达完整目标即为最短总步数。该搜索不调用生产move/compile、也不读取硬编码解法作为答案；再将求出的路线应用到生产模型逐步核对。运行时不搜索，不用随机统计估计最优。

## 4. 如何使用与精确例子

1. 打开“娱乐 → 独立休闲游戏 → 推箱子”，默认L01。可点击方向按钮，或点击棋盘后使用方向键/WASD。
2. L01点“→ 右”两次（或按两次右键）：第一步走到箱子后，第二步推箱到目标，显示“2步 · 推箱1次 · 目标1/1”和通关提示；精确最优2步，多用0步。继续按方向不追加结算，方向和撤销按钮禁用。
3. 选择L04，向右两次，此时2步、推箱1次、未通关；点击“撤销一步”，恢复1步、推箱0次，以及玩家/箱子推前位置。按零起始ASCII列/行，玩家从(3,2)恢复(2,2)，箱子从(4,2)恢复(3,2)。退出再打开，可继续这个1步棋盘。
4. “重开当前关卡”清空本局步迹但保留最佳。切换其他关从其初始布局开始；“下一关”在L20后回到L01。
5. 另存续玩JSON新副本；下次通过文件输入选择JSON，仅展示待恢复关卡/步数/已通关数。勾选“确认替换全部续玩进度”再应用。取消或坏文件不覆盖当前棋盘。

L01布局（#墙，@玩家，$箱，.目标，空格地板）：

```text
######
#@ $.#
#    #
######
```

从同一初始布局，`DRULRR`（下右上左再右右）也是合法通关，6步、推箱1次，与精确最优2步差4步；随后重开用`RR`完成，最佳改为2步，已通关仍1/20。

可导入的未完成进度例：

```json
{"schema":1,"levelId":"L04","trace":"RR","best":{"L01":{"steps":2,"pushes":1}}}
```

恢复L04为2步/1推箱，保留L01最佳2步。将trace改为非法`UU`、未来schema2或未知关卡L99会拒绝。高级复现路线：L06 `LLLDRDRUUDDRUU` 共14步/5推箱；L20 `LDDLDDRUUUDDDRRUUULLLDLU` 共24步/10推箱，均实际Electron操作验证。

## 5. 使用后产出

自动进度与JSON副本包括完整当前源步迹和所有最佳记录，恢复时重新计算坐标、胜利状态和推箱次数。默认JSON文件 `sokoban-progress-copy.json`；Markdown `sokoban-records-copy.md` 包含当前状态、计步/结算口径、已通关数及全部20关的最优/最佳/推箱次数/多用步数，不截断关卡表。最优值依赖本schema1固定内置关卡版本，不把JSON当作任意外部关卡格式。

输出先检查 `saveTextSupportsCopyOnly===true`，调用 `files.saveText({content,extension,defaultName,copyOnly:true})`。仅 `ok===true` 成功；取消、异常、未确认结果如实显示，partialPath提示人工核对。已有文件拒绝，导入来源和旧副本不覆盖。导出等待期间锁输入，离开/销毁后旧回调不重新构建界面。未安装支持接口的旧版本禁用导出。
