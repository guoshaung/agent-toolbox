# T080 GPU 本地能力报告

## 1. 功能内容

只读采集当前 Electron/Chromium 报告的 GPU 适配器、原始驱动版本、字段来源、GL renderer 和 Chromium 图形/视频加速状态。输入目标任务、可选最低专用显存 GiB、精确驱动版本字符串与 Chromium 检查项，报告匹配、不同和待核项。完整 JSON/Markdown 先预览，再另存新副本。

设备字段读不到即 null/未知；专用显存始终明确未知，因为使用的公开 GPU 设备字段没有单位明确、可核验的专用显存字节数。不会以系统 RAM、共享显存、型号或 Chromium 的 native_gpu_memory_buffers 状态代替显存。当前浏览器加速与目标软件运行能力分别描述。

## 2. 为什么需要

同一台电脑可能同时报告集成显卡、独立显卡和软件适配器，也可能有各自不同的驱动字符串。把当前实际来源保留下来，能帮助用户准备后续视频、3D 或 AI 软件核验资料。一个 WebGL enabled 不能证明某个模型能使用 CUDA，未知的显存也不能被当作满足 8 GiB；报告明确留下这些待核项，避免把不完整信息变成运行保证。

## 3. 实现方式

固定 `host.cjs` 通过基础 PR #14 的可信功能 Host 桥接受 `collect({jobId})`，只调用 Electron 内置只读 API。`app.getGPUInfo('complete')` 提供设备/驱动信息；逐字段保留原始字符串和来源，vendorId/deviceId 为原始非负32位整数，active 是 Chromium 返回的布尔或未知。设备字符串缺失时不伪造名字；独立的 aux.glRenderer 仍可供人工观察，但不将它推断为每个非活动适配器型号。

本次采集监听 `gpu-info-update` 后才读取 `app.getGPUFeatureStatus()`；监听开始前发生的事件不冒充已观测。成功取得设备信息后最多等1秒 readiness，整个操作最多5秒；未观测到事件时 featureStatus unknown，不读取可能未就绪的状态。`isHardwareAccelerationEnabled()` 仅在版本实际提供且返回布尔时保留；当前项目 Electron33.4.11 未提供此 API，结果 null / api_unavailable_or_failed，与false有区别。

每 sender 最多1个在途作业，全模块最多32个 sender 作业；不可中断的底层GPU查询全模块最多1项。取消、窗口销毁或5秒超时释放等待及事件/计时器，不强制终止公开API；底层调用还未结束时新采集返回 `prior_underlying_gpu_query_still_pending` 的未知快照，不发起第二项查询或复用过时结果。真正settle后才允许新查询。没有后台轮询、shell、基准、目标任务、联网、驱动安装、加速开关修改或持久化设备报告。

采集范围：最多32适配器、每个允许字符串最多2048 UTF-8字节。非法/缺失/超限字符串字段为未知；设备结构不合法或条目超限时整个设备来源未知，未截断冒充完整。仅传回限定设备字段、3项GL字段及8项Chromium状态，其他原始GPU信息不输出。要求：任务三选一，显存留空或0–256 GiB最多3小数，驱动要求最多512 UTF-8字节，拒绝控制/孤立代理码元；驱动按完整原字符串精确比较，不按版本号猜测跨厂商新旧。

`model.mjs` 生成每适配器独立驱动对比、显存 unknown 和Chromium状态解释。enabled/enabled_on/enabled_force/enabled_force_on/enabled_readback表示Chromium报告加速，其中readback可能性能降低；六类disabled/unavailable状态报告当前非硬件加速，其他未来值未知且保留原值。即使全部匹配，`taskCompatibility=unknown_not_tested`，CUDA/ROCm/目标运行时、格式、空闲显存与实际任务仍待核。

renderer 使用文本节点显示，Markdown内JSON反引号编码为Unicode转义，用户字符串不执行。输入改变立即废弃旧报告/预览，面板隐藏、deactivate或destroy清空并请求取消，重新激活不自动查询。当前输入与设备报告不保存配置；工作台自身仅记录功能编号。保存使用生产 `files.saveText({content,extension,defaultName,copyOnly:true})`，只在 `ok===true` 后报成功，已有目标wx拒绝，取消/失败保留预览。

依据：[Electron app GPU API](https://www.electronjs.org/docs/latest/api/app#appgetgpuinfoinfotype)、[gpu-info-update 与状态就绪](https://www.electronjs.org/docs/latest/api/app#appgetgpufeaturestatus)、[GPUFeatureStatus原始值](https://www.electronjs.org/docs/latest/api/structures/gpu-feature-status)。最新文档的API不等于项目安装版本都支持；实际运行时版本进入每份报告。选择设备/驱动字段亦参照 Electron 官方链接的 [Chromium GPUInfo枚举源](https://chromium.googlesource.com/chromium/src/+/4178e190e9da409b055e5dff469911ec6f6b716f/gpu/config/gpu_info.cc)，不承诺跨版本全部字段存在。

## 4. 如何使用

1. 在工作台“工具 → 系统与本地环境”打开 T080，选 AI推理、视频处理或3D与浏览器图形。
2. 可输入最低显存 `8`、精确驱动版本 `31.0.12044.3` 和检查项 `webgl`；留空/不指定表示不检查该条件。
3. 点击“只读采集本机 GPU”，检查每个条目的 active、原始驱动、字段来源与aux.glRenderer。未知项需另外核验，Chromium列表不保证覆盖全部系统硬件。
4. 点击完整JSON或Markdown预览，核对型号/驱动等本机信息后另存新文件。已有目标会被拒绝，可重新选新目标；不修改来源或安装软件。
5. 改条件后须手动重新采集，旧报告不沿用。取消后若底层查询仍在处理，新报告明确未知，稍后再手动查询。

真实隐藏隔离 Electron33.4.11 / Node20.18.3生产catalog/workbench/preload/公共Host/原样singleton模块及文本writer，12组验收通过，证据 `work/electron-smoke-1790990995002/result.json`：

## 6. 具体使用例子

要准备一个要求8 GiB专用显存的AI推理项目，输入目标“AI推理”、显存 `8`、精确驱动 `31.0.12044.3`、检查项webgl，再手动采集。本次验收电脑的第0条驱动精确matched；其他驱动各自different或unknown。Chromium webgl显示enabled，GL renderer保留 AMD Radeon(TM) Graphics 原字符串，但专用显存unknown，任务兼容unknown_not_tested。用户由报告知道哪些驱动字符串实际可读，以及仍需在目标软件中核验显存和后端。

改为 `deliberately-different` 后旧报告立刻失效，重新采集各已读驱动different，不声称驱动过旧；改为 `1e2` 显存时直接拒绝，不发起采集。分别预览JSON/Markdown并保存新文件，得到同一份完整待核清单；向已存在的JSON文件保存被拒绝，原文件不变。
