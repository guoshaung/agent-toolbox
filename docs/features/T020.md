# T020 符号链接与断链巡检

## 1. 功能内容

选择一个允许巡检的实际普通目录，先核对完整根位置和限额，再确认只读遍历。读取普通目录条目、链接文本和目标路径元数据，不读取文件正文、不进入目录链接、不修改链接或修复文件。输出有效文件/目录/其他目标、断链、链接链循环、目录关系图循环、越界和未知状态，支持完整 JSON / Markdown 新副本。

## 2. 为什么需要

复制或移动项目后，普通文件列表不容易显示符号链接原始目标、断链与循环。盲目跟随目录链接还可能反复扫描或越出选定根目录。本工具保留原始链接、解析链和未知原因，帮助人工定位；没有把权限不足、超过跳数或未检查外部目标当成正常。

## 3. 实现方式

固定已打包 `host.cjs` 经公共 Host 桥调用 Node 内置 fs/path，不新增依赖。`select` 由主进程目录对话框选择根，lstat确认普通目录、realpath核对实际位置，返回当前sender私有随机selectionId及可见根路径。该步不遍历子目录。renderer传入任意path、其他窗口token、缺确认或已释放token都不能扫描。`scan` 必须当前token、唯一jobId、confirmed=true，每sender仅一个活动扫描，取消和dispose只处理自己的作业；最多32sender/每sender128个已用jobId，关闭窗口释放状态。

普通目录采用 `opendir` 流式条目和 `lstat`，不借递归readdir自动跟随链接。发现链接用 `readlink` 读取原始目标；按路径组件逐级lstat，只在所选根内解析链，保留尚未消费的尾部组件。遇重复的“链接位置+剩余尾部”是 symlink_chain循环；超过40次替换仅标unknown/hop limit，不能推断循环。越界路径立即outside，不检查其存在、权限或正文。目录链接不加入待遍历队列，因此有效alias不重复计入目标内文件。

此外建立已经遍历的普通目录父子边，加上解析到根内普通目录的链接边。若一个目录链接的目标沿这些关系能回到链接所在父目录，则标directory_graph循环。例如 `sub/back→根` 会形成根→sub→根；发现此关系无需实际进入back。互指目录可组成图循环；链接至一个没有回路的子目录仍为valid_directory。只有Node识别为symbolic link的符号链接/Windows junction采用此算法，不宣称覆盖全部Windows特殊reparse point、挂载点或硬链接。

最多10000条目、1000链接、32层普通目录、40次链替换、30秒检查期限和4MiB完整JSON报告；超限、取消或严重根/扫描目录改变整份失败，无截断成功报告。不可读取目录/条目保留path、operation、错误code，scanScopeComplete=false；ENOENT/ENOTDIR目标是broken，其他目标读取错误为unknown。根前后dev/ino/realpath核对，扫描普通目录进入前检查不为链接且实际仍在范围。它是一次非原子元数据观察，不能保证外部并发改动下的同一时刻快照，也不是对恶意并发替换的文件系统沙箱。

原始目标、解析位置及链条全部保留，最终链接按相对path排序，UI每页50条，导出不按页删减。JSON/MD不包含任何文件正文，但根、目标及链中绝对路径可能含私人信息。输入或报告不自动写配置；离开/隐藏/清空释放范围、取消等待、忽略晚回调，返回需重新选择确认。原生保存期间锁定操作，只 `ok===true` 报成功，取消/失败保持完整预览。

API参照 [Node fsPromises.lstat](https://nodejs.org/api/fs.html#fspromiseslstatpath-options)、[readlink](https://nodejs.org/api/fs.html#fspromisesreadlinkpath-options)、[opendir](https://nodejs.org/api/fs.html#fspromisesopendirpath-options)。实际验收运行时为Electron33.4.11 / Node20.18.3，不依赖文档新版本才提供的recursive/glob/disposable接口。

## 4. 如何使用

1. 工具工作台打开 T020，点击“选择允许巡检的目录”，选择项目普通根目录。需要公共Host桥 `features.callHostSupported===true`，缺失时禁用。
2. 核对“已选择巡检范围”的绝对根位置、限额和只读说明，此时尚未启动扫描。
3. 点击“确认以上目录并开始只读巡检”。查看分页状态及不可读项；不要将unknown或outside当成有效。可取消，取消后不显示部分报告。
4. 先“预览完整 JSON 报告”或“预览完整 Markdown 报告”，核对全部链条与未知项，再保存已预览报告新副本。文本接口需 `saveTextSupportsCopyOnly===true`，payload带copyOnly:true；已有目标拒绝，partialPath提示人工核对。
5. 清空、离开或隐藏释放根，返回后不会自动重新扫描。达到128次任务上限需关闭并重新打开窗口，防止永久增长任务历史。

## 5. 使用后产出与具体例子

产出 `symlink-audit-copy.json/.md`，含root/platform、普通文件/目录/链接数量、按状态计数、完整links及每个resolution链、errors、scanScopeComplete、限额和解释。Markdown保留完整结构化JSON，反引号编码避免用户路径破坏围栏；不会复制源文件正文或删除/修复任何链接。

在项目根放 `actual/sentinel.txt` 与 `cycle/` 两普通目录，以及 `valid→actual`、`broken→missing`、`loop-a→loop-b`、`loop-b→loop-a`、`cycle/back→根`、`outside→根外目录` 六个链接。Windows可用junction，POSIX用目录符号链接。扫描应得到普通目录3（含根）、普通文件1、条目9、链接6：valid_directory1、broken1、loop3、outside1。loop-a/b为symlink_chain，cycle/back为directory_graph；outside不检测根外目标是否存在。`actual/sentinel.txt` 只数一次，内容与mtime不变。

再添加51个指向不同不存在目标的链接，总57项，UI50+7两页，JSON仍完整57项。另存回已有第一份报告应拒绝，原字节不变。清空后确认按钮立刻禁用；重新选根才能再次确认。
