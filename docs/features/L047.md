# L047 压缩信息保真

## 1. 功能内容

学习工作台「语言与表达训练」中的本地人工事实核对工具。用户输入原文、压缩稿、来源名/出处、人工事实清单、必保标记和码点预算，为每条事实分别绑定原稿证据与压缩稿片段，直接点击「分析字数与人工绑定」得到长度预算、人工绑定覆盖率与完整事实证据表。catalog的AI可选在本MVP采用完整人工流程，无AI、联网或自动语义匹配依赖。

界面可以添加/删除事实、编辑说明、从两个真实文本框选择片段绑定，也可以输入0起算起止位置、查看当前区间预览后明确确认。表格包含每条事实ID、是否必保、事实修订、两稿位置/原片段/状态以及人工依据。未绑定显示未知/待核；原文证据缺失与压缩证据待核分别计数。可选事实仍完整展示和导出，原文出处空项明确未说明，不自动补写引文。

显示完整JSON与Markdown预览，可导出完整新副本。纯离线分析直接执行；只有「用三事实示例替换草稿」这类会替换两稿及人工记录的整体操作提供独立确认界面，「保留当前输入」取消替换。

## 2. 为什么需要

压缩文字可能保住了篇幅，却遗漏时间、数量或条件。用户需要先明确哪些事实必保，再逐项说明压缩稿中哪一段承载它，保留可复查的原文来源和未知项。自动出现相同词语不能替代人工核对事实是否完整、限定条件是否丢失。

本功能新增的是事实到两份稿件的人工证据绑定、绑定失效管理和字数预算对账。它不生成摘要、不评分语言或认知能力、不推断同义关系，也不把覆盖率当作语义保真度。多个事实允许绑定同一片段，含义是否一致或重复仍由用户判断；原文来源未知不被伪装成已有可靠出处。

## 3. 实现方式

### 明确计数口径

字数采用Unicode码点数（JavaScript字符串迭代），包括空白、标点、制表及换行。CRLF计2，LF或CR各计1，🙂计1，`e`加组合重音计2，家庭emoji序列`👩‍👩‍👧‍👦`计7。码点与用户感知字形/字素簇含义不同，参见[Unicode术语表：码点](https://www.unicode.org/glossary/#code_point)与[字素簇](https://www.unicode.org/glossary/#grapheme_cluster)。本计数只是一套明确的练习预算，不冒称投稿、考试或语言学通用字数标准。

`exceeded=max(0,压缩码点数−预算)`，`remaining=max(0,预算−压缩码点数)`；相等符合该长度预算。预算必须是0–16000整数，空输入拒绝，不隐式变成0。符合预算只说明长度合规。

### 证据位置、修订和未知

两稿片段采用0起算UTF-16码元半开`[start,end)`，当前有效锚提供1起算逻辑行/UTF-16列。区间非空、非纯空白、≤240码点，禁止拆分代理对；列不是UTF-8字节或屏幕字形列。使用[WHATWG HTML文本控制选区API](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#textFieldSelection)获取`selectionStart/selectionEnd`；textarea把CRLF/CR显示成LF时，模型将显示偏移映射回完整原稿换行偏移。恢复/JSON仍保留原换行；在文本框重新编辑得到的浏览器LF值成为新修订。

确认锚保存起止、当时quote、稿件修订和事实修订。更改某一稿只使该稿证据失效；更改某事实描述使该事实两稿证据失效，必保标记/来源说明/人工依据修改不改变片段位置。旧quote、区间和修订始终保留，即使位置越过缩短后的全文。工具不重新搜索同词、不插入位移或默默重新绑定。重新绑定必须人工核对当前预览并确认，选择同一位置也需重新确认当前修订。

覆盖率分母为全部必保事实数，分子为其中当前有效人工压缩绑定数。原稿证据是否完整独立显示待补，不改变这个人工绑定比例；没有必保事实时分数和比例为null，界面显示未定义。该比例既不证明原文来源可靠，也不证明压缩片段语义与人工事实相同。报告包含当前两稿全文及旧锚原句，不保存历次全文历史，不核验外部来源。

### 容量、持久化与生命周期

两稿各≤16000码点；来源名≤160、出处≤320；人工事实≤20，描述非空≤320、依据≤320；修订号1–1000000。非法控制字符/孤立代理字符、重复事实ID、未知schema字段、未来修订锚和非法预算整份拒绝，未截断成合格结果。完整输入JSON≤256KiB，完整JSON/MD各≤2MiB，报告在发布前同时验证两种产物容量。达到修订/事实上限需要先导出后新开练习。

配置只保存schemaVersion=1的两稿、事实、已确认锚和预算，TextEncoder计算整份JSON UTF-8≤64KiB；恢复同样验证版本、字段及体积。不保存派生报告、未确认区间数字或历史全文。非法/大输入仍可留在界面但明确提示未保存、关闭只能恢复较早合法输入；合法大稿可生成完整副本。超限不会自动丢事实/截旧quote。输入空预算或空事实描述修复前，完整分析与配置均不能成功。

分析复制完整已确认输入快照，在开始、每4条事实及结束让出任务队列，并在让出前后检查取消票据。取消、编辑、切走或destroy使旧任务失效，不发布部分表/迟到旧结果。配置采用每config一个写入队列（一个在途加最后待写快照），票据/所有权检查阻止旧回调覆盖新警告。未确认数字只留内存，并阻止分析/导出；切走忽略编辑，激活重建控件，销毁清空DOM、释放引用，不启动计时播放或外部进程。

导出冻结当时完整报告文本，通过`window.toolbox.files.saveText({content,extension,defaultName,copyOnly:true})`；桥接能力必须严格为true，响应`ok===true`才宣布保存成功。生产writer使用`wx`拒绝既有目标。导出失败/取消保留报告，销毁后的迟到IPC不能重建界面；Markdown包含完整结构化JSON，并使用动态代码围栏与HTML转义保留原始内容。不会写回原稿来源文件。

## 4. 使用步骤

1. 打开学习工作台中的L047，输入或粘贴两稿，填写来源/出处与码点预算。
2. 添加并编辑人工事实，标记必保或可选，填写人工依据/待核疑问；原文出处缺失保持未知。
3. 为事实选择原稿和压缩稿证据：选中文本后按对应绑定按钮，或者编辑起止位置、查看预览，再按确认。编辑数字尚未确认时不可生成报告。
4. 直接点击「分析字数与人工绑定」。核对超预算量、必保绑定分数及表格全部未知/失效记录。需要取消时按取消；更改文本后旧分析自动失效，再绑定当前片段并重新分析。
5. 预览完整JSON/Markdown，再导出新副本。报告包含两份全文及人工记录，请按原始资料范围管理保存位置。
6. 需要重置时先保留所需报告，再点击用示例替换草稿并明确确认；否则按保留当前输入。

## 5. 产出与可复现例子

示例原稿：`2025年，团队在广州招募了30名参与者，试验持续7天。`（28码点）。压缩稿：`广州招募30人；试验持续7天。`（15码点）。预算故意设5，因此超出10；用于验收长度运算，不推荐实际摘要长度。

| 事实 | 必保 | 原稿区间/原句 | 压缩绑定 |
| --- | --- | --- | --- |
| F1 地点为广州 | 是 | [9,11) 广州 | [0,2) 广州 |
| F2 招募30名参与者 | 是 | [14,17) 30名 | [4,7) 30人 |
| F3 试验持续7天 | 是 | [25,27) 7天 | 未绑定/待核 |

直接分析得到2/3（66.7%为显示近似）、必保待核1/F3、原稿出处待补0、超出10。F3即使有相同「7天」字样也不自动算绑定。选中压缩稿「7天」[12,14)按「用压缩稿选区绑定F3」，重新分析为3/3。再清除F1原稿证据，绑定比例仍3/3，原稿出处待补恰1/F1，避免把绑定比例误当来源可靠性。

在压缩稿开头依次输入「前」「缀」，稿件r1→r3，两个旧压缩锚保持[0,2)/[4,7)和quote，但失效；原稿锚仍当前有效。重新分析0/3。分别明确确认F1压缩[2,4)、F2[6,9)、F3[14,16)，再分析3/3、压缩17码点。把预算改17，超出0；将所有必保取消，三事实仍完整输出且覆盖率未定义。

完整JSON包含`feature/schemaVersion/modelVersion`、当前两稿及来源、预算、事实/证据/状态、pendingFactIds、sourceReviewFactIds、计数及解释；Markdown含预算与分数摘要、完整结构化记录。没有只导出可见行或伪造自动语义判断。
