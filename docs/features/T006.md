# T006 · 日志事件时间线

所属分组：工具 / 文本与结构化数据。规格对应 `docs/feature-planning/tools.json` 的 T006。

## 功能与必要性

不同进程可能按UTC或不同固定偏移写日志，直接按文本日期排序会把同一时刻误认为先后发生。源日志自身也可能乱序，堆栈续行或无效日期不能当作有效时间。本功能读取用户提供的多份本地日志，显式解释时间，统一到UTC毫秒后稳定排序，同时保留日志名称、来源编号、物理行号和原文。

它处理已有日志，不新增抓包或系统流量采集。原始文件只读，处理内容不上传、不写配置。每条未解析行保留明确原因，不能静默丢失或附着到前一事件。

## 实现方式

- `src/renderer/features/T006/meta.json` 提供工作台发现用分类、分组、标题和描述。
- `index.js` 使用现有 `h` 创建多文件浏览器输入、粘贴追加、逐来源格式/偏移控件、源内容片段、统计、事件/未解析行分页及导出按钮。同步 `create` 返回生命周期；切走取消未完成处理，销毁清空内存日志。
- `model.mjs` 提供严格时间戳解析、逐物理行遍历、UTC毫秒统一、可取消的稳定归并排序和有限额序列化。独立于其它功能路径，无新增依赖。
- 文件通过 `FileReader` 读取为字节，严格UTF-8解码，可保留开头BOM。如果一次选择的任意文件不能解码，整批不加入来源列表，已有来源保持。
- 日期时间先校验公历各分量，再使用 `Date.UTC` 加减明确偏移。不使用宽松 `Date.parse`，不依赖电脑本地时区，不猜测缺失年份、日期或时区。
- 等时刻按来源列表顺序及文件内原始物理行顺序排序；内部使用原始序号作为比较键，不依赖运行环境的默认排序稳定性。同名文件保留独立来源编号，不合并去重。
- 扫描每32,768字符或128行让出事件循环；归并排序每4,096次移动让出并检查取消；导出每128条检查取消。预览每页25条，源片段只显示前300字符，导出保留完整原始行。

## 使用方式

1. 选择“新增日志时间格式”。无行内时区的日志需要选择指定固定偏移格式，并明确填写 `Z` 或 `+08:00` 等值。
2. 选择一份或多份UTF-8本地日志文件，或填写日志名称并粘贴内容，点击“添加粘贴日志”。新增来源采用当前导入规则。
3. 在来源列表中分别核对每份日志的名称、格式和固定偏移。已添加来源不会随顶部新增规则改变。列表编号决定同刻事件的来源顺序。
4. 点击“生成统一时间线”。检查UTC时间、同刻组、来源编号、文件名、物理行和原文；再检查无法解析行及原因。
5. 核对后保存时间线CSV副本或完整JSON报告。CSV只含成功解析事件；JSON包含所有事件、无法解析行、来源解释规则和统计。
6. 修改来源名称、格式、偏移，或添加/移除来源后旧结果失效，必须重新生成；原文件不改变。空文件可添加并统计为来源，不生成虚构事件。

## 输入规则及具体示例

所有格式只识别**行首**完整时间，允许行首空白和 `[时间]` 包装。无方括号时，时间戳与消息之间必须有空白；方括号关闭后可紧接消息。原始行字符保留，行终止符不包含在 `raw` 字段中。

| 选择格式 | 明确支持的示例 | 时区语义 |
| --- | --- | --- |
| ISO日期时间＋行内时区 | `2026-07-01T12:00:00.123Z event`、`2026-07-01 20:00:00+08:00 event` | 必須行内 `Z` 或 `±HH:mm` |
| 日期时间＋指定固定偏移 | `2026-07-01 20:00:00.123 event` | 使用该来源填写的固定偏移 |
| Unix秒 | `1782907200.123 event` | UTC，允许0至3位小数 |
| Unix毫秒 | `1782907200123 event` | UTC，整数毫秒 |

支持 UTC 1970至2100年的时刻。日期分量必须是真实公历日期；时间使用00:00:00至23:59:59，不接受24:00、闰秒或秒值60。小数 `.1`、`.12`、`.123` 分别是100、120、123毫秒；四位以上小数报超精度，不截断。固定偏移范围为 -14:00 至 +14:00，14小时只能是整点。

本版固定偏移不包含夏令时规则。`Europe/London`、`PST`、城市名、缺失年份的syslog时间及仅 `HH:mm:ss` 时间都不推断。对于跨夏令时的来源，应使用每行带明确偏移的ISO日志；不能用一个固定偏移替代动态规则。消息里的时间字符串不被提取。

### UI可复现的跨时区验收

点击“载入跨时区示例”，来源列表为：

`utc.log` 选择ISO行内时区：

```text
2026-07-01T12:00:00.123Z API accepted
2026-07-01T11:59:59.999Z start
stack continuation
```

`east8.log` 选择日期时间＋指定固定偏移，填 `+08:00`：

```text
2026-07-01 20:00:00.123 UI received
2026-07-01 20:00:00.456 done
```

点击“生成统一时间线”。预期统计：2来源、5物理行、4事件、1未解析行、1同刻组。排序结果：

| UTC时刻 | 来源 | 物理行 | 消息 |
| --- | --- | --- | --- |
| 2026-07-01T11:59:59.999Z | utc.log | 2 | start |
| 2026-07-01T12:00:00.123Z | utc.log | 1 | API accepted |
| 2026-07-01T12:00:00.123Z | east8.log | 1 | UI received |
| 2026-07-01T12:00:00.456Z | east8.log | 2 | done |

UTC12点与东八区20点明确归同刻，`utc.log` 在同刻组中保持在前。`utc.log` 第3行保留在无法解析清单；不会猜测其属于哪次事件。

### 无效时间、跨日与空行

- `2026-02-29T12:00:00Z` 为无效日期，未解析原因明确显示。
- `2026-07-01T12:00:00.1234Z` 超过毫秒精度，不能按 `.123` 当成功。
- 选择ISO格式但输入 `2026-07-01 20:00:00 event`，原因是缺少行内偏移；可由用户切换该来源到固定偏移格式。
- 固定 `+08:00` 的 `2027-01-01 00:30:00` 输出 `2026-12-31T16:30:00.000Z`，保留真实UTC日期变化。
- 固定 `+05:45` 的 `2026-07-01 09:00:00` 输出 `2026-07-01T03:15:00.000Z`；分钟偏移不舍入成整小时。
- CRLF、LF、单独CR均作为物理行分隔。中间空行保留在未解析清单，单个文件尾行终止符不制造额外空行。

## 产出、保存和容量限制

- 界面统计来源数、物理行、成功事件、未解析行和同刻组。同刻组通过蓝色单元格识别；分页可查看全部成功和失败记录。
- UTF-8 BOM CSV：`source_index,source_name,source_line,utc,epoch_ms,source_offset,timestamp,message,raw`。逗号、双引号等按CSV规则转义；字段是日志字符串，电子表格可能解释公式形态内容，分享时应核对相应字段。
- 完整JSON：功能ID、来源格式/偏移/BOM/计数、总体统计、排序事件及未解析行原因。事件携带原始序号、物理行号、原时间、统一UTC、来源偏移和原文，可用于回溯。
- 保存调用 `files.saveText({ content, extension, defaultName, copyOnly: true })` 并要求 `saveTextSupportsCopyOnly === true`。基础层以 `wx` 拒绝已有目标。缺少此能力时结果可预览，导出禁用并说明原因。保存对话框阶段使用其取消按钮；已发送的保存IPC不支持AbortSignal撤回。
- 最多8份来源、每份2 MiB、合计8 MiB、50,000物理行、每行50,000字符。字节与总量在解析前检查；超限明确拒绝，不截断输入。单份及合计均按UTF-8字节计算。
- 输出上限12 MiB。JSON和CSV中的原文/消息可能扩大输出，序列化过程中检查限额，超过时建议拆分，不会生成部分副本。
- 无成功事件时CSV保存禁用；仍可保存包含全部未解析行的JSON。空文件与空物理行分别统计，不能混为一条事件。
