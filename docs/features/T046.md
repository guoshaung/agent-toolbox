# T046 字幕时间轴修复

## 1. 功能内容

本地读取或粘贴 SRT / 简单 WebVTT，按整数毫秒整体提前/后移，可选把过短字幕延长到指定展示时间。先生成逐条完整报告，列出每条原时间、新时间、延长量、重叠对象、重叠区间和越界；然后预览、保存 JSON 报告或修复字幕新副本。

输入最多1MiB、1000条、每条正文8KiB，重叠最多20000对；超过容量整份拒绝，不以截断结果冒充完整检查。最短展示0–60秒；时间范围00:00:00.000至99:59:59.999；媒体时长可选。没有音频上传、网络请求或自动草稿。

## 2. 为什么需要这个功能

字幕常因为片头长度或剪辑变化整体错位。直接手改时间容易漏改，延长短字幕又可能产生新重叠。本功能把修改规则和所有受影响条目同时显示，保留正文，用户确认后创建独立副本，可以核对修改而不覆盖来源。

重叠本身不直接意味着错误：WebVTT允许不同说话者的并行字幕。本功能提示全部重叠，要求确认后导出；不自动删除、裁剪、重新排列，也不声称与音频自动对齐。

## 3. 实现方式

model.mjs严格解析有限格式，转成统一结构{id,identifier,start,end,text}。时间以整数毫秒计算，避免浮点秒累积误差。整体偏移后，可选延长end至start+minMs；原始时间和延长量保留于报告。按开始时间排序的副本枚举所有相交半开区间，结束恰好等于另一条开始不算重叠；结果条目仍保持源顺序。每50条让出事件循环并检查取消，取消不发布部分报告。

负起点、超过99小时上限或所填媒体时长是导出阻断；JSON仍可查看和保存。短展示/重叠是提示，明确勾选确认才能生成字幕预览。输入和规则改变使旧报告及预览失效；隐藏/离开取消进行中的工作、废弃保存预览，返回不自动执行。正文和标识用textContent/value显示，标签不会在工具内执行；输出仍保留用户正文，不声称净化其内容。

SRT支持唯一正整数编号、HH:MM:SS,mmm、正文；导出连续重新编号1至n，原编号留在JSON。VTT支持仅WEBVTT头部、可选唯一标识、HH:MM:SS.mmm或MM:SS.mmm、正文。拒绝NOTE/STYLE/REGION、头部元数据、时间行定位设置及正文内时间戳，避免改变时间轴时悄悄丢失语义；不是完整VTT编辑器，不支持ASS。输入严格UTF-8、允许开头BOM和CRLF，导出LF。源相对顺序和正文内部行/空格保留，结尾分隔空行规范化。

格式依据已阅读[W3C WebVTT规范](https://www.w3.org/TR/webvtt1/)的cue时间、标识及重叠规则，并对照[FFmpeg 8.1 SubRip读取实现](https://www.ffmpeg.org/doxygen/8.1/libavformat_2srtdec_8c_source.html)。这里采用明确受限的解析契约，不宣称接受所有播放器方言。

保存先显示完整textarea预览，之后调用生产preload files.saveText，要求saveTextSupportsCopyOnly===true，payload含copyOnly:true，写入器用wx只创建新目标。只把ok===true视为成功；取消/拒绝/异常保留预览。另存对话框等待时禁改规则，不用普通覆盖接口降级。

## 4. 如何使用

1. 在新增功能工作台打开T046，选择SRT或简单VTT，粘贴文本或读取严格UTF-8字幕文件。
2. 填整体偏移秒，正数延后、负数提前，最多3位小数。填最短展示0–60秒；默认只报告不足，勾选“延长短字幕”才修改结束时间。可选填媒体时长用于边界检查。
3. 点击“生成完整时间轴报告”，阅读完整cue和overlaps列表。越界条目需要修正规则后重新分析，不自动裁剪。
4. 有重叠或短展示时，核对后勾选确认。JSON报告随时可预览，字幕副本在没有越界且提示已确认时可预览。
5. 检查完整导出预览，点“保存已预览的新副本”，选择新文件名。源字幕不会写回，已有文件拒绝覆盖。

## 5. 使用后产出和具体例子

产出T046-report.json含所有源编号、原/新时间、规则、逐条issues、全部重叠对及统计；T046-repaired.srt或.vtt是新时间轴副本。未填写媒体时长只检查格式范围，不表示已核验实际视频长度。

点“载入两条重叠示例”：第一条1.000–4.000秒、第二条3.000–5.000秒，偏移+2秒。报告应为3.000–6.000和5.000–7.000，重叠5.000–6.000共1000ms，两条均指向对方。未确认时字幕按钮禁用；确认后保存SRT首条为00:00:03,000 --> 00:00:06,000，第二条为00:00:05,000 --> 00:00:07,000，正文保持“第一条字幕”“第二条字幕”。改成偏移−2秒会使首条起点−1秒，报告保留错误但字幕导出阻止。

延长例：原第一条0–0.5秒，第二条0.7–2秒，最短1秒。不开延长时只报告第一条shortDisplay，无重叠；开启后第一条结束1秒，新增0.7–1秒的300ms重叠，需要确认。
