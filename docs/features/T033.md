# T033 照片隐私检查

## 1. 功能内容与适用范围

在本机选择一批静态 JPEG/PNG，先检查容器、EXIF 标签、GPS 和常见设备/拍摄字段，再明确选择整体隐私属性清理，生成前后图像预览。副本不重新压缩或调整尺寸，只有实际解码 RGBA 全图逐字节相同才允许另存。每张成功图单独另存新文件；完整 JSON 报告包含本批所有成功和失败项。

一次 1–10 张，每张 1 字节至 10MiB，总输入至 40MiB，编码宽/高各至 10000、至 4000 万像素。支持签名真实的 8 位顺序/渐进 DCT JPEG，以及静态 PNG（包含调色板、透明度、合法采样深度/交错字段，仍须当前解码器能读取）。文件扩展名不决定格式。HEIC、WebP、SVG、MPO、多图 JPEG、APNG、未知 PNG 关键块、尾随字节、结构/CRC/偏移错误整体拒绝，不抽取其中一帧凑作成功。

本版提供一个明确的整体属性组：EXIF 拍摄/GPS/设备/缩略图、XMP、IPTC、注释、PNG 文本、未知附加元数据。不能分别勾选“留设备但删GPS”，因为定位也可能复制在 XMP/IPTC 或不识别的附加容器中；界面说明整体删除的原因，用户先检查后选择该组。模式边界与 catalog 的“要清理的属性”对应整体清理组，不宣称通用 EXIF 标签编辑器。

## 2. 为什么需要

公开图片的可见画面之外，文件还可能含拍摄位置、相机型号、序列号或注释。在报告中隐藏某一字段并不会改变照片本身。这个功能从实际文件中移除相应容器，保持压缩图像数据、方向和显示色彩，并在导出前检查实际显示像素，方便用户交付保留画质的副本。

保留 JPEG JFIF 显示头（删除嵌入缩略图）、ICC_PROFILE 色彩配置和固定长度 Adobe 颜色变换头；保留 PNG 图像/调色板、透明、色彩以及显示相关块。ICC 自由文本未审查，可能仍含配置描述或制造商信息，因此不承诺“所有设备字节已消失”或“匿名化”。画面内地址、隐写、文件名和文件系统创建时间等不在清理范围。公开照片与公开检查报告是不同操作：报告仍含原 GPS、设备和源名，不应当作已清理照片直接公开。

## 3. 实现方式

`model.mjs` 为本功能独立的有限字节解析器，无第三方元数据包、用户代码或网络。格式依据：[W3C PNG 第三版](https://www.w3.org/TR/png-3/) 的块长度、CRC、eXIf 与文字容器定义；[CIPA 标准索引](https://www.cipa.jp/e/std/std-sec.html) 和 [CIPA Exif 3.0 概览](https://www.cipa.jp/std/documents/e/Exif3.0-Overview_E.pdf) 确认 Exif 的 GPS 目录用途。CIPA 完整规范下载入口在本次环境未取得 PDF 正文，不将该失败写成已全文核验；有限 TIFF 字节布局同时由独立夹具读取/写入及实际文件解码验证，不声称完整标准一致性认证。

JPEG 遍历标记和各扫描段，处理 FF00 转义与 restart 标记，保留扫描、帧和编码表原字节，删除 APP1（Exif/XMP）、APP13/IPTC、COM 及其他非显示 APP。EXIF 的 II/MM 字节序、标签长度、目录偏移、重复标签、循环和类型都校验；最多 1024 标签/目录、4096 标签/文件、4 层目录。只读取普通 ASCII 设备/日期字段（每字段显示至 512 字节并明确标记省略），GPS 三个无符号有理数及 N/S/E/W 参考；不识别的坐标显示 `gpsPresent=true, gps=null`，不猜测。方向须为明确的 1–8。整个原 EXIF 连缩略图删除，仅生成 26 字节 TIFF：一个 Orientation 标签、无子目录或尾随内容。

PNG 校验每块 CRC、IHDR 颜色/压缩/滤镜/交错、基本顺序、重复显示块、连续 IDAT、IEND 及无尾随数据；块数至 4000。移除 eXIf、tEXt/zTXt/iTXt、时间与其他未知附加块；如源有方向，IHDR 后重建最小 eXIf。文字/XMP 容器仅报告种类/大小与“可能含定位，内容未展开”，不将未解压文字误说成没有定位。保留 IHDR/PLTE/IDAT/IEND/tRNS/cHRM/gAMA/iCCP/sBIT/sRGB/cICP/mDCV/cLLI/bKGD/hIST/pHYs 的原字节。保留块不是全面的跨解码器 PNG 合规认证。

`worker.mjs` 在本地模块 Worker 中执行解析/清理，单次 15 秒超时终止，取消直接终止 Worker。候选副本二次解析，EXIF GPS 已无、设备字段为空；所有预期删除容器已无。主线程用 `createImageBitmap` 解码原件与候选件，64 行分块读取 Canvas RGBA 全图逐字节比较，各分块让出事件循环；不同尺寸、不同像素或解码失败整项拒绝。摘要为 WebCrypto SHA-256。图像解码及摘要调用不能底层中止，取消后只忽略返回值，并关闭位图、清空临时 Canvas。会话版本防止晚到回调重新生成旧报告。

隐藏/暂停/销毁会中止处理、清除预览 URL 和确认；回到可见页面只恢复操作界面，不继续原作业。销毁移除监听器、释放 URL、清空 File 输入和本批引用。没有 RAF、摄像头、权限请求或配置写入；切换功能后未保存本批不自动恢复。原生保存已开始后，切出/销毁不能撤销主进程实际保存，结果不会恢复旧界面；已有副本需用户管理。

## 4. 如何使用与具体例子

1. 选取 JPEG/PNG 集合，点击“检查照片”。下拉逐张选择，可查看完整原图、EXIF 标签清单、GPS 和设备字段；失败项保留文件名与原因。
2. 勾选“清理定位设备与文字整体属性”，点击“生成清理副本并验证像素”。处理结束后，下拉选择成功照片，查看左右完整原图/副本、清理后标签和全图像素一致结论。
3. 核对后勾选“已核对所选照片完整前后预览”，点击“另存所选照片新副本”。每次切换照片/隐藏/暂停都会重置这项确认。建议名为 `photo-01-privacy-copy.png` 或 `.jpg`；最终路径由原生保存对话框选择，已有目标不会覆盖。界面不能预先指定任意磁盘路径，也不会伪称建议名就是最终目标。
4. 依次保存其余成功照片，再按需要另存完整 JSON 报告。报告包含原定位信息，应由用户自行决定是否保留/分享。输入或属性改变会废弃旧报告；取消操作不产生成功状态；清空会释放当前本批。

可执行验收例：测试构造 EXIF II/MM GPS（N:22°30′00″、E:114°10′00″）、制造商 `ACME`、Orientation=6 的 JPEG，再加入 GPS XMP、APP13/IPTC、COM 和未知 APP5。检查得到纬度 22.5、经度 114.166666… 和方向 6。清理后 GPS 目录不存在、`gps=null`、设备 `{}`，APP1 只剩一个 Orientation=6 的最小 EXIF，APP13/COM/APP5 已无；压缩扫描段与源逐字节一致，实际全图像素一致。原 JPEG SHA 不变。

PNG 例：1024×768 RGB 坐标渐变图附加相同 GPS/设备 EXIF（方向 1）、tEXt、iTXt/XMP、zTXt 和 vpAg。清理后仅剩 IHDR/eXIf/IDAT/IEND，EXIF 只含方向 1，IDAT 与源完全相同；副本仍为 2360525 字节，超过目录接口 2MiB 单图限额，使用单图 Binary 10MiB 接口正常保存，尺寸没有暗中降低。损坏 PNG 与正常 JPEG 混批时报告保留两行，分别失败/成功，不漏项。

## 5. 使用后产出

- JPEG/PNG 新副本：真实清理后的文件字节，不是 Canvas 重编码。建议文件名不复用包含位置的源名，原件只通过 File API 读入，不写回。
- JSON 报告 schema=1：整体清理规则、精确限额/承诺边界、所有文件源名/字节数/SHA、成功/错误、前后块清单与 EXIF 标签、GPS/设备预览、实际 RGBA 比较口径与像素数、候选副本字节数/SHA/建议名。报告没有内嵌大图；不写配置。报告是检查结果，不能当项目重新导入恢复或替代照片验证。

先要求 `saveBinarySupportsCopyOnly===true` / `saveTextSupportsCopyOnly===true`，全部 payload `copyOnly:true`，只有回执 `ok===true` 显示成功。Binary 单文件上限 10MiB，与输入上限一致。没有调用每文件 2MiB 的 bundle 接口，没有声称一次生成完整大图目录。保存取消、非布尔 ok、失败、partialPath 都明确提示；保存期间锁输入/清空，销毁后的结果忽略。公共写入器验证 Base64/SHA 与独占 `wx`；原生对话框选择目标后不能覆盖已有文件。JSON 文本接口限 8MiB，本报告有界标签数/文件数保证在预算内。
