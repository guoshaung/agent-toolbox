# L025 异步顺序穷举

## 1. 功能内容

编辑最多六个有限回调事件与前置依赖，选择内置写入规则和结果约束，在模型内完整枚举依赖DAG的全部拓扑顺序。每行事件有ID、请求版本、固定结果文本和前置依赖ID，支持真实表格增删和编辑。提供旧覆盖新、依赖顺序、最新版守卫、逐次写约束四个模板。

产出包括全部合法顺序数量、通过/失败数量、最新请求、每个顺序的完整状态轨迹、最短首次检查失败前缀与原因。顺序清单和选择器可查看每条轨迹；失败筛选只改变列表，不截断统计或导出。完整JSON/Markdown副本保留全部模型记录。

## 2. 为什么需要

偶发异步覆盖问题的难点是两个请求先后发出，回调却以不同顺序到达。固定只试一次可能错过失败顺序，直接看最终文本也可能忽略它来自旧请求。

本功能通过小范围全穷举，训练用户把请求版本、回调顺序、前置依赖、写入守卫和结果约束分开。单调写入可能保证最终结果最新，却允许中途旧写；仅最新请求可写则满足更严格的逐次要求。这是有限事件调度验证，区别于共享内存锁实验，不连接真实网络或调试用户运行时。

## 3. 实现方式与模型边界

`model.mjs` 先校验事件及DAG，再用确定性深度优先枚举全部拓扑顺序，分别执行内置状态机；`index.js` 提供表格、规则/约束、全顺序列表和轨迹查看，`style.css` 使用实际主题变量。无eval、Function、用户脚本、外部依赖或真实异步执行。

- 所有请求已经在回调前发出。最高版本的请求是最新请求，版本不由输入末行或回调先后推断。每个回调原子执行一次，结果在开始前固定；不同事件即使结果文本相同，也仍按版本检查来源。
- 1–6事件，ID为1–12位ASCII字母/数字/_/-并以字母开头；请求版本为1–6整数且唯一。结果文本≤128 UTF-8字节，可为空；依赖文本≤256字节，用空格/英文或中文逗号分隔。重复ID/版本/依赖、未知依赖、自身依赖、循环和字段越界全部拒绝，不截断。改ID或删行后引用需手动修正，系统不偷偷删除依赖。
- 前置依赖表示该回调必须先执行，是严格偏序，不表示请求发出时间、延迟或等待机制。枚举优先顺序为输入行顺序；每次选择所有依赖已完成的事件，没有随机抽样。六个独立事件恰好6!=720顺序；上限防护超过720即报错。
- `naive`：每个回调都覆盖已写状态。`latest-request`：只有事件版本等于全局最高请求版本才写，其他回调跳过。`monotonic`：初次可写，其后只允许比已写版本更高的回调，旧回调跳过。这些是固定教学规则，不执行用户代码或推断应用意图。
- `final-latest` 只在全部事件结束时检查最终来源版本；中间旧值可能被后续新回调纠正，不能提前当成最终失败。`no-stale-writes` 每步检查，旧请求实际写入就失败；跳过旧写不失败，后续新写不能撤销已发生的违反。完整轨迹在首次失败后仍继续保留。
- 最短失败前缀指：**所有合法顺序中，到所选约束首次检查失败为止的最短前缀**；同长以枚举先出现者为准。最终结果约束只在全部结束检查，因此该约束的失败前缀就是完整顺序。逐次写约束可得到更短前缀。这不是删除事件后的因果最小反例，也不是实际运行时复现轨迹。

每次枚举结果、每条轨迹前后快照独立，修改查看位置不改变数据。最多720顺序×6步骤，全部同步有界计算；不模拟实际Promise、微任务/宏任务、重试、超时、取消、线程或事件循环。

## 4. 使用步骤与可复现例子

默认两个回调old/new，请求版本1/2、结果“旧请求结果”/“新请求结果”，均无依赖；规则每回调都写、约束全部结束必须最新。点击“枚举全部合法顺序”：

| 顺序 | 写入轨迹 | 最终状态 | 结论 |
| --- | --- | --- | --- |
| old → new | 未写入→版本1→版本2 | new，版本2，新结果 | 通过 |
| new → old | 未写入→版本2→版本1 | old，版本1，旧结果 | 失败 |

应看到合法2、通过1、失败1。点击“查看最短失败所在顺序”，看到顺序#2及前缀`new → old`（2步）；每步列出写入前、是否实际写入、写入后和检查时刻。失败来自来源版本，不仅比较文本。

“载入逐次写约束示例”后枚举：两顺序都含一次旧写，因此失败2，最短前缀为`old`（1步）。在`old → new`中最终状态虽然最新，仍违反每次写都最新的要求。改写入规则为monotonic：最终约束下两顺序都通过，逐次约束下只有`new → old`通过，因为old被跳过。

“载入最新版守卫示例”在两约束下都通过。依赖例给new添加old前置依赖，只有`old → new`，最终约束通过；逐次约束仍失败。反向依赖则只剩`new → old`并触发最终旧覆盖。输入互相依赖必须报循环，不能生成空的“成功”列表。

规模验收：默认例点击“增加事件”四次得到六个独立版本事件，枚举应为720个完整顺序，naive最终约束通过120、失败600（只有最高版本最后到达的5!=120顺序通过）。选择“只列失败顺序”后列表为600，但导出仍应有720条完整轨迹。33字符草稿ID、超过128字节结果文本或重复版本需清楚拒绝，旧结果在编辑时清空。

## 5. 产出与保存

JSON副本具有feature、schemaVersion、modelVersion、导出时间、完整草稿、当前选中索引，以及完整结果：解析后事件、最新请求、总/通过/失败数量、所有顺序、每步前后状态/是否写入/检查结果、各顺序首次失败前缀、全局最短前缀及其适用定义。Markdown逐个顺序列出同样完整记录，保留全部输入和最短前缀；没有有效枚举时明确没有顺序或结论，仍可导出草稿。用户文本安全渲染，Markdown中HTML字符转义。

导出能力必须 `files.saveTextSupportsCopyOnly===true`，参数含 `content`、`copyOnly:true` 和格式；只有返回 `ok===true` 才宣告成功。生产桥接独占创建，拒绝已有目标，取消/失败保留结果。过滤或当前选中顺序不影响完整导出。当前无报告导入，导出输入可重新计算。

全局配置仅存`schemaVersion:1`输入草稿，JSON测量UTF-8≤64KiB。另有更严草稿字段上限：ID/版本≤32字符、结果≤128字节、依赖≤256字节、规则/约束≤64字符及1–6行；允许有界但语法未完成的草稿，枚举时再严格校验。恢复先检查整个原始存储体积（含额外字段）、版本、字段类型/数量和容量，再提取已知字段。超限不写配置，明确提示关闭后只能恢复较早草稿，需导出完整JSON。顺序/轨迹/选中位置不保存，重进后重算；切走清保存计时器，销毁释放DOM，异步返回不重建界面。
