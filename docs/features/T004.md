# T004 正则抽取规则工坊

## 1. 功能与交付范围

对多份样本文本使用同一条 JavaScript 正则，输出每次匹配的原文、样本序号/名称、起止偏移、编号捕获、命名捕获及未匹配样本。样本可以粘贴或一次选择多个本地 UTF-8 文件；每个文件对应一份样本，可以编辑、移除和重新验证。

提供分页捕获表、选中匹配的完整原文/捕获详情、每样本失败列表，以及预览后的 JSON/CSV 副本导出。初版没有替换文本、运行 JavaScript、自定义脚本、联网或 AI 接口。

## 2. 必要性及与现有能力的关系

重复日志、标记文本等字段抽取，容易出现只验证一个成功样本、忽略未匹配样本、丢失原文位置的问题。本功能在同一页面验证多样本并保留来源及偏移，帮助确认抽取规则是否适用于整批输入。现有 webtools 主要嵌入网页；本功能为离线本地原生抽取、失败核查和结果副本提供完整闭环。它不修改源文件，也不把生成表格算作 CSV 清洗功能。

## 3. 实现方式与安全边界

`src/renderer/features/T004/meta.json` 提供分类和标题，`index.js` 实现同步 `create` 及 `activate/deactivate/destroy` 生命周期。`model.mjs` 负责输入限额、任务控制、结果表列及导出。`worker.mjs` 独立编译 `new RegExp(pattern, flags)` 和循环 `exec`；渲染主线程不会编译或试跑用户正则，不存在 `eval`/`Function` 执行用户代码。

每次验证都创建独立 module Worker，主线程设置含启动时间的整批计时器。成功、语法错误、Worker 错误、限额、超时和取消都会终止该 Worker 并清理监听器。超时/取消/限额整批中止，不生成可导出的半成品。失败列表区分此前已完成的样本和“未完成”样本；后者不会被当作“未匹配”。修改规则后新建 Worker 可继续验证。切走功能会取消操作，销毁会取消并清除 DOM。

Worker 使用真实 JavaScript 正则语义。重复匹配若命中空字符串，依据 [ECMAScript AdvanceStringIndex](https://tc39.es/ecma262/multipage/text-processing.html#sec-advancestringindex) 前进：u/v 模式遇合法代理对移动两个 UTF-16 单位，其他情况移动一个；字符串尾部再前进一步结束。终止方式参照 [HTML Worker terminate](https://html.spec.whatwg.org/multipage/workers.html#dom-worker-terminate)。这些机制限制正则回溯对界面响应的影响，不承诺某种正则能在指定时间完成。

没有增加 npm 依赖或公共 IPC。JSON/CSV 写入复用实际 `window.toolbox.files.saveText`，传入 `{content,extension,defaultName,copyOnly:true}`，且必须具有 `saveTextSupportsCopyOnly === true`。基础层以排他写入拒绝已有路径。缺少能力时导出按钮禁用，不调用旧写入接口。保存对话框供用户核对路径和新文件名；系统对话框打开后用其取消按钮关闭，面板取消只能中止生成阶段。

## 4. 使用步骤及输入规则

1. 点击“载入三条日志示例”，或填写名称/文本后点击“添加粘贴样本”，也可选择多份 UTF-8 文件。
2. 填写正则主体和 flags，再选择整批 Worker 超时：1、3（默认）或5秒。
3. 点击“验证并抽取”，核对捕获表、原文 `[起点,终点)` 和失败样本。点击“完整原文与捕获”查看未截断数据。输入改动会立即清除旧结果，必须重新验证。
4. 核对预览后保存完整 JSON 或匹配 CSV 副本，在原生对话框确认新目标路径。已存在文件会被拒绝。
5. 验证/文件读取/导出生成阶段可取消。超时后收紧规则或缩小样本再试。

正则输入不使用 `/.../flags` 包装，例如输入 `(?<level>INFO|ERROR) id=(?<id>\d+)`，flags 单独输入 `gu`。`(?<字段名>...)` 产生命名列，普通捕获产生 `capture:1` 等编号列；同一字段可同时在两类列出现。

| flags | 本功能语义 |
|---|---|
| g | 每样本全部非重叠匹配，每份样本重新从0开始 |
| 无g/y | 每样本最多首条匹配 |
| y（可同时带g） | 从位置0起连续粘连匹配；首次失败即停止，不扫描后续位置 |
| i / m / s | 忽略大小写 / 多行锚点 / 点可匹配换行 |
| u / v | Unicode语义，二者不可同时使用；未被运行时支持的语法报错 |
| d | 额外提供编号/命名捕获的真实区间，包括前置断言中处于匹配之前的捕获 |

flags 不可重复，仅接受 `dgimsuvy`。空规则、空样本是有效输入：空规则可产生零长度匹配。未参与捕获表示 `null`，参与但捕获零字符表示 `""`；界面用 `∅（未参与捕获）` 区分。

所有偏移都是整份样本文本的 **UTF-16单位**，起点包含、终点不包含；它们不是 UTF-8 字节偏移或 Unicode 码点计数。文件导入保留 BOM 与 CR/LF/CRLF，不以文件行作为独立样本。编辑文本框后按浏览器返回的换行重新计算。UTF-8 解码采用 `fatal:true`，遇非法编码本批文件一个也不添加；没有猜测编码或静默用替换字符。

## 5. 产出与客观输入输出示例

点击内置示例会载入三份独立样本：

```text
日志1: [12:00] INFO id=42 started
日志2: [12:01] ERROR id=7 failed
日志3: [12:02] DEBUG heartbeat
```

规则为 `(?<level>INFO|ERROR) id=(?<id>\d+)`，flags=`gu`。

| 样本 | 匹配区间 | 匹配原文 | named:level | named:id |
|---|---|---|---|---|
| 日志1 | [8,18) | INFO id=42 | INFO | 42 |
| 日志2 | [8,18) | ERROR id=7 | ERROR | 7 |

统计为“3份样本 · 2条匹配 · 1份未匹配”；日志3出现在未匹配列表。表格每页25条，长单元格仅在预览中缩略，完整详情和导出保留全文。

额外可验证输入：`(?:)` + `gu` 作用于 `😀X` 时，零长度区间依次为 `[0,0)`、`[2,2)`、`[3,3)`；去掉u则为0、1、2、3。规则 `(?<absent>a)?(?<empty>b*)` + `du` 作用于空文本时，absent为null、empty为空字符串，编号区间为 `[[0,0],null,[0,0]]`。

JSON 包含 `feature=T004`、`version=1`、`offsetUnit=UTF-16`、规则、所有原始样本/状态、匹配及统计。CSV只含匹配行，包括样本、起止偏移、原文和捕获列；字符串单元格存为 JSON 字面量后按 CSV 引号规则转义，空值为null、空字符串为`""`，避免字符串首字符被表格软件作为公式执行。读取这些列时先按CSV解码，再按JSON解码字符串值。失败详情和完整原始样本请使用JSON。

## 6. 验证结果、限额及剩余验证

验证命令：

```powershell
node --test --test-reporter=spec test/feature-T004.test.js
node --check src/renderer/features/T004/index.js
node --check src/renderer/features/T004/model.mjs
node --check src/renderer/features/T004/worker.mjs
git diff --cached --check
```

20项定向测试通过：17项模型/真实Node Worker测试及3项DOM契约测试。真实Worker测试使用 `node:worker_threads` 适配器；不把主线程的同步引擎或假定时器当作超时隔离证明。灾难回溯 `^(a+)+$` 对40个a加`!`在250ms超时后明确触发terminate，并再次成功提取`id=42`。覆盖样本偏移、首条/全局/粘连、多行、Unicode/孤立代理项空匹配、命名/可选捕获、d偏移、特殊字段名、语法错误、数量/大小限额、真实取消、成功/错误终止清理、导出编码/限额/取消、文件导入原子性及保护写入载荷。

首版限额：12份样本，每份100000、合计400000个UTF-16单位；单文件1 MiB、一次文件选择4 MiB；名称120字符；正则主体2048单位；1000条匹配（恰好1000可完成，第1001条中止）；每次匹配最多64个捕获组；累计匹配JSON表示不超过3 Mi个UTF-16单位；导出最多6 Mi个UTF-16单位。这些是防止过大输入/输出的边界，不代表大型日志处理能力。

本提交没有启动Electron或验证打包后的应用。DOM契约测试不等于真实浏览器交互。集成时应验证现有 `file://`、`script-src 'self'` 环境及打包资源下 module Worker 能加载、实际回溯超时后界面可继续输入、切走/销毁停止Worker，以及原生保存对话框与已有目标拒绝。若Worker被环境阻止，会明确报告隔离执行失败，不退回主线程执行正则。当前Node会提示项目未声明renderer `.js` 的ESM类型，该提示不影响20项测试，没有为消除提示而修改package。
