# L010 学习困难分解

## 1. 功能内容

对应 `docs/feature-planning/learning.json` 的 L010：输入卡点描述、具体例证、候选原因和验证动作，输出人工原因树及待执行的区分实验。MVP 手动拆分知识/表征/策略/执行候选，每个叶子可以绑定验证动作。核心全部离线，无 AI 必要依赖，也不运行 practice 的代码或诊断运行报错。

用户可编辑卡点标题/描述/例证/来源、单根树中每个候选描述/人工类别/依据/来源和父节点。固定 N1 是卡点根，箭头父→子表示用户进一步拆分。每非根节点至多一项动作，包括动作步骤、候选成立预期、替代解释预期、区分判据和人工出处。

结果含真实树图、逐叶路径和完整实验表、缺动作叶子、待执行实验、设计字段缺项、人工观察判断及全部历史。JSON/Markdown 预览和新副本完整导出；SVG 导出完整树及状态，动作/例证/观察全文见 JSON/Markdown。

默认三叶 N2 知识候选、N3 表征候选、N4 策略候选，N2/N3 有动作但尚未执行，N4 没有动作。报告准确标记一个“未验证（缺动作）叶子”N4，同时单列两个“待执行实验”，不声称其他两原因已经验证。

## 2. 为什么需要与人工判断边界

“不会做”包含多种可能卡点，直接重复练习未必能区分用户自己的候选解释。把卡点、例证、候选分支和区分实验写在同一报告里，可以发现某个叶子还没有具体动作，或成立预期/替代预期/判据尚未补充，便于用户下一步实际收集证据。

原因类别、拆分结构、动作设计、观察和支持/反驳/不确定判断均人工填写。工具不判断候选是否真实、实验是否有区分力、参考是否正确，也不将规则计数包装为学习效果。人工支持不证明真正原因；人工反驳不排除其他解释。没有自动诊断、语义评分、医学/心理判断、内容生成或外部来源认证。未填写描述或出处保持未知，不补造引文。

验收文字中的“未验证叶子”在界面和报告明确限定为**缺非空验证动作的叶子**；动作已绑定但未执行另列“待执行”。人工观察提交后才显示当前匹配的人工判断，仍不称为已证实原因。空成立预期、替代预期、区分判据逐项标待补，没有仅靠非空动作就宣称设计充分。

## 3. 实现方式、版本与有界模型

纯规则模型在 `model.mjs`，UI 在 `index.js`，生产 catalog 发现 `meta.json` 后工作台动态加载。模型版本 `L010-manual-cause-tree-experiments-v1`，真实项目样式变量 `--bg-raised`、`--bg-sunken`、`--line`、`--text`；未采用不存在的主题变量。

树必须恰有一个固定 N1 根，非根只能选知识/表征/策略/执行类别且父节点存在。每个节点沿父指针必须到达 N1，循环、自环、未知父级、多根和不可达根整份拒绝；根不能删除/换父/改类别。叶子按“非根且没有子节点”定义，只有根不算完成原因分解。每叶路径是 N1 到该叶的完整祖先序列。

非根节点最多一个动作；空动作对象或仅空白步骤仍计缺动作。非空动作无当前观察时待执行。用户把原叶子进一步拆为父节点后，原动作保留并单列“内部动作，不用于叶子验证”，不能用它覆盖新叶子的动作。内部动作的观察提交按钮禁用；需给新叶子分别绑定动作，不会自动复制/删除旧绑定。

观察通过用户明确提交追加，ID 递增，只读保留，包含非空观察原文、人工判断、出处、当时整个卡点/例证/原因树及动作设计完整快照。同叶有多条当前匹配观察时，以最后追加一条展示人工判断；全部观察原文仍保留，并非删除旧判断。观察没有可信外部时间戳、签名或真实性验证。

当前输入有总 `revision`，另有卡点/树 `contextVersion`；卡点/例证/来源、候选描述/依据/类别/来源、父子结构的每次合法修改都会提升上下文版本。动作任何设计/出处修改提升该动作 `designVersion`。观察只有上下文版本、完整卡点树内容、动作 ID/设计版本和完整动作内容都匹配，且仍是当前叶子，才用于当前判断；其余只历史。对象属性顺序无关，数组顺序保留。**文字改回旧值也不会恢复旧观察**，必须重新提交人工观察。单独修改 A1 设计不使同上下文的 A2 观察失效；改任一树/卡点字段则保守地使全部旧上下文观察只历史。

删除动作后旧观察保留；删除原因需先显式移走/删除子节点和动作绑定，工具不自动清引用。ID 不复用。删除/整体替换需确认，普通查看/本地分析直接执行。教学例整体替换会替换全部观察历史，需保留先归档。未提交观察表单仅当前页面内存，重载不恢复，界面明确说明。

最多 24 节点（含根）、23 动作、40 追加观察；标题80码点、卡点描述1000、例证1200、候选描述100、候选依据500、动作600、每种预期/判据500、观察1000、来源名120/位置240。拒绝非法控制字符和孤立 UTF16 代理项。长度预算按 Unicode 码点；实际浏览器 caret 按 UTF16，“甲😀”是偏移3。没有片段锚点，不猜测原句位置；textarea 依浏览器标准将 CRLF/CR 规范化为 LF，不宣称文件字节导入保真。

`schemaVersion:1` 完整卡点/树/动作/**所有观察快照** UTF8 JSON≤64KiB。每项修改、新观察、恢复均完整校验，超过数量或整体预算整份拒绝，旧历史不丢弃、不悄悄截断；大文本会比40条上限更早触及预算。完整 JSON/Markdown/SVG 各≤1MiB，超限整份失败。配置仅保存合法输入/已提交历史，不存派生状态/树图。

保存使用单通道队列、一个进行中写入和最新待写输入，旧回执不覆盖新提示。损坏或未来 schema/布尔旧草稿保留，编辑/切走/销毁都不自动覆盖；明确确认替换旧草稿后才恢复保存。分析完整取快照，每5节点让出一次，编辑/取消/隐藏/离开/销毁隔离迟到结果和 IPC 回执；返回不自动分析/执行动作，无计时器、网络、媒体资源或外部源扫描。

## 4. 使用步骤与可复现例子

1. 从功能工作台打开 L010，展开“卡点描述、例证与人工来源”，填具体卡点、至少能帮助自己回忆的例证和人工出处。
2. 展开“人工候选原因树编辑”，逐个写候选，选择知识/表征/策略/执行类别及父节点。用“新增子原因”继续拆分；父级循环会整项拒绝，原树保持。
3. 展开“逐叶验证动作与人工观察”，选择尚未绑定的叶子并点击“绑定验证动作”。填写明确动作、候选成立预期、替代预期和区分判据；空动作仍计缺动作，不自动补建议。
4. 直接点击“查看原因树与区分实验”，查树图、缺动作/待执行两项及完整逐叶表。实际执行区分实验后，再填写本次人工观察、判断和出处，点击“提交A…人工观察”，然后主动查看结果。
5. 修订卡点或实验设计后，旧观察只历史。需要当前判断就执行新设计、再提交新观察，不能靠文字改回复用旧判定。预览完整 JSON/Markdown，导出报告/图或完整输入归档。

默认例：N1“无法开始解题”；N2“概念定义不清楚”知识候选，A1“不用笔记写定义，并给一个反例”；N3“文字不能转为图式”表征候选，A2“只转换题目文字为图，不要求解答”；N4“第一步策略未选择”策略候选，无动作。叶子={N2,N3,N4}，未验证（缺动作）={N4}，待执行={N2,N3}，人工支持/反驳/不确定均0。三格式导出和逐叶表保持这一口径。

为 N4 绑定 A3，但步骤留空：仍恰1缺动作。填写“列出并尝试两种第一步，保留失败草稿”：缺动作变0、待执行3。只填步骤时三个区分设计字段显示待补，不会据此称原因已验证。

提交 A1 观察“无法独立解释定义”并人工选择支持，提交 A2 观察“可以画图，用户判定不是当前卡点”并选择反驳：人工支持1、反驳1、待执行1。改 A1 判据：支持变0，A1待执行，A2反驳仍1，原两观察不变。再给 A1 追加不确定观察后，更换卡点例证：所有原观察只历史，待执行3，完整报告仍含三条快照。

把 N2 拆成 N5“执行时漏掉一步”执行候选：N2成为内部节点，A1保留但不用于叶子验证；叶子={N3,N4,N5}，缺动作={N4,N5}。将 N2 父级改为 N5 会形成循环，整项拒绝，原结构保持。要删除 N2，先显式清理/移走 N5 和 A1；不会悄悄删除子树。

## 5. 产出与副本保护

JSON 含 feature/schema/model、总修订/上下文版本、全部当前卡点和例证/来源、所有树节点/类别/依据/来源、全部动作设计/版本/来源、**所有原观察快照和原文/人工判断/出处**、逐叶完整路径/缺动作/设计缺项/当前性、待执行实验、内部动作、未知项及计数/解释口径。Markdown 以安全 JSON 围栏给出同样完整内容，HTML字符转义、围栏长度超过用户反引号序列。图折叠或界面滚动不筛减导出。

SVG 包含全部当前树节点/连接、人工类别和叶子状态，短标签之外的完整候选/依据/来源放在节点 title；宽/高按整棵树自适应，没有按 viewport 截断。最多24节点星形树高2615像素，可滚动查看；最长链横向滚动。图表达人工拆分方向及状态，不声称真实因果或诊断结论。

合法输入归档无需分析通过也可导出，含全部当前输入和观察历史，标明不是分析结果。产物包含用户完整例证、原始观察和出处；未提交观察表单不在报告或配置中。

导出调用生产 `files.saveText({content,extension,defaultName,copyOnly:true})`，要求 `saveTextSupportsCopyOnly===true`；缺能力明确失败，只有 `ok===true` 才报成功。生产 writer 使用 `wx`，已存在目标拒绝且旧文件不改。取消/失败/字符串“true”等不明确回执不能报成功。已发起写盘不能切走撤回，只隔离迟到提示和 DOM 恢复。
