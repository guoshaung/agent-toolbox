# T060 源码可疑字符巡检

## 1. 功能内容

用户明确选择目录所提供的文件集合或若干独立文件，设置扩展名与完整目录段排除规则，再只读巡检严格 UTF-8 文本。提示固定19种双向/不可见格式字符与有限 Latin/Cyrillic/Greek 混用脚本候选，给出相对路径、行、码点列、UTF-16列与偏移、码位及Unicode名称。完整范围、排除列表和全部发现可预览并保存JSON/Markdown新副本。

目录入口实际范围是 HTML File API 提供的集合，不能声称包含浏览器没有列出的隐藏文件或整个磁盘。另一入口选择会替换旧集合；预览范围只读取文件元数据，点击巡检才读取正文。每页显示50发现，报告/导出保留全部。

## 2. 为什么需要

源码中不可见格式字符可能来自合法书写或复制，也可能干扰审阅。码位和明确行列能让开发者回到编辑器人工核对，不必执行文件或猜肉眼所见的顺序。开头BOM单独分类，混用脚本只标候选，不把合法Unicode、注释或国际化变量名判为恶意。没有发现也不代表安全。

## 3. 实现方式与支持范围

独立 `model.mjs` 先验证选择/规则/容量，再以64KiB块读取 File.slice().arrayBuffer()，严格fatal UTF-8流式解码，保留BOM并核对每块真实字节数。CRLF按一个换行，裸CR及LF也换行；行与column从1开始，column按Unicode码点，utf16Column按UTF-16码元，utf16Offset从0起。前方emoji会使两种列不同。报告不含源码正文、原token或上下文，仍含相对路径和变量片段位置，分享需核对路径范围。

依据为官方 [Unicode双向算法 UAX9](https://www.unicode.org/reports/tr9/)、[Unicode安全机制 UTS39](https://www.unicode.org/reports/tr39/) 及 [UnicodeData字符名称](https://www.unicode.org/Public/UCD/latest/ucd/UnicodeData.txt)。检测表固定为：

- 12种bidi：U+061C、200E、200F、202A、202B、202C、202D、202E、2066、2067、2068、2069。
- 7种invisible：U+200B、200C、200D、2060、FEFF、00AD、034F。起始U+FEFF单独记initial_bom；其后FEFF记invisible。名称为固定Unicode名称，合法用途也提示。

混用扫描以 `$`/`_`/ID_Start起始、ID_Continue及连接字符续接的标识符形态文本为单位，只收集Latin/Cyrillic/Greek脚本，出现两种才标mixed_script_candidate。不解析任何编程语言，因此注释、字符串也可提示；不检查同脚本形似字符、所有脚本、所有不可见字符，不实现完整UTS39混淆骨架或证明视觉形似。候选记录无单一字符码位/名称，改列脚本列表及片段码点数。

纳入扩展名大小写不敏感，最多40明确`.js`形式扩展名；目录排除大小写敏感、按完整段匹配，默认node_modules/.git/dist，不匹配not_node_modules，不支持glob/正则。所选最多100文件，纳入单个≤1MiB/合计≤4MiB；排除文件不读正文。连续标识符形态片段≤1024码点（纯Latin也遵守），全部发现≤10000，完整JSON≤4MiB。所有超限、读取长度不符、非法UTF8或孤立代理项整份拒绝，无部分成功报告，不静默截断。

相对路径验证拒绝绝对/驱动器/反斜杠/遍历/空段/控制符，目录选择去掉共同根名称；不归一化不同Unicode文件名。路径中固定所列格式字符转成可见`\uXXXX`，反斜杠也可见转义；不审计文件名本身或称其无可疑字符。UI用文本节点/textarea呈现，Markdown动态围栏并转义HTML，不执行源码/HTML。

异步读取及每约16KiB文本扫描让出事件循环并检查取消；取消、隐藏、暂停、销毁使票据失效，无残余报告。单段同步处理受预算限制，不承诺任意指令即时中断。没有网络、目录后台访问、Git读写、自动修复或自动草稿；当前文件引用仅面板内存。

导出完整预览后显式确认，通过生产 `saveTextSupportsCopyOnly===true`、`saveText({copyOnly:true,...})`。仅ok严格true提示成功；取消/false/undefined/throw保留预览并提示。已有文件由wx拒绝覆盖，不能改写源；已完成原生保存不能通过UI取消撤回。

## 4. 如何使用

1. 打开T060，选择目录或独立文件。按需要调整扩展名和完整目录段排除，勾选/关闭混用候选。
2. 点“预览所选范围”，核对纳入和排除相对路径/字节数；此时尚未读取正文。
3. 点“巡检完整所选集合”，等待完整结果；可取消，非法UTF8/超限需缩小明确选择后重试。
4. 按文件及行列回到编辑器人工确认。编辑器若按UTF16显示列，使用utf16Column；不要把发现数量当风险评分。
5. 预览完整JSON或Markdown，核对范围/路径后“保存已预览报告新副本”。规则或选择改变必须重新巡检；离开不会自动保存。

## 5. 使用后产出

新副本 `T060-source-audit.json` 或 `.md`，含feature/version、规则、所选数量、每个纳入文件字节数/发现数、全部排除及理由、各类别数量、全部发现和检测边界。JSON与Markdown均为完整记录，不只当前表页。无修复源码、执行日志或安全保证；报告无源码正文/token，但包含相对路径、码位/Unicode名称和片段位置。

## 6. 具体例子与验证

点击“载入四行码位示例”，在内存生成 `sample.js`（以下转义表示实际字符）：

```text
const ok = 1;
// 双向符：\u202E
const hidden\u200B = 2;
const p\u0430ypal = 3;
```

巡检应有3提示：第2行第8列U+202E RIGHT-TO-LEFT OVERRIDE；第3行第13列U+200B ZERO WIDTH SPACE；第4行第7列6码点片段Latin+Cyrillic混用候选。最后的Cyrillic小写а未包含在固定19格式字符中，仅触发混用候选。关闭混用再巡检仅剩2提示。`😀\u202E`在同一行中RLO码点列2、UTF16列3、偏移2；`\ufeff\u200B`第一项initial_bom列1，第二项列2，BOM没有偷偷删除。

`node --test test/feature-T060.test.js`：15项模型测试覆盖手算准确位置、19固定名字/BOM、CRLF/emoji、有限混用/关闭、目录段及扩展名、空文件、跨64KiB多字节、严格UTF8/孤立代理项/短读、100文件/单总字节/10000发现/1024片段边界、规则与路径/重复/Unicode区分、取消且源字节不变、400字符独立前缀换行/码点oracle。组件生产事件、原生写入与完整分页将在独立Electron验收后补充实际证据；模型测试不能代替它们。
