# L029 二分回归定位演练

## 1. 功能内容

在“学习 → 编程验证与调试训练”中，通过有限单调虚拟提交历史练习 bisect 决策。开局只给第1提交已知good、末端提交已知bad；用户选择未测提交或采用中点建议，工具返回该次good/bad，更新首坏候选区间，邻接边界唯一确定首坏后揭晓答案和统计。

支持固定演示、本地随机局、自定义单调序列三种模式。提交数2–256；所有局均good在前/bad在后且存在首坏，第1提交必须good。可视提交带只标已测试结果，不预先列完整好坏序列。纯本地，无AI、新依赖、真实Git命令或仓库操作。

## 2. 为什么需要

逐提交检查容易花费很多次构建/验证，但看到“二分”二字不等于知道应检查哪里、good/bad端点如何更新、首坏候选是否包含bad边界。本工具让每次选择的区间收缩可见，并把额外检查次数与理论最坏界比较。

默认16/9固定演示明确告诉学员首坏9，只用于操作说明；随机局在运行面板隐藏未定位答案，适合练习决策。自定义序列由作者输入首坏编号，作者当然知道答案，不能称未知答案挑战。三种模式均是教学抽象，不测试真实提交、真实代码或实际回归。

## 3. 实现方式与算法边界

`meta.json` 供公共工作台发现；`index.js` 实现同步create及生命周期；`model.mjs` 用闭包保留虚拟局答案，只暴露view/test两个方法；`style.css` 使用现有主题变量。用户输入经h/textContent/value显示，不执行代码。答案不放DOM属性、草稿设置或公开快照。

### 构造单调局

提交编号1…N，首坏F满足2≤F≤N，状态由确定规则 `commit < F ? good : bad` 定义。因此首端good、末端bad、首坏存在和单调性由构造保证。自定义只需N/F即可表示有限单调序列，不接受任意函数、非单调列表、真实Git提交或测试命令。

固定演示强制N=16/F=9，并明确披露它是已知答案演示。随机局使用crypto.getRandomValues取Uint32，拒绝超过最大整倍数区间的随机值后，在[2,N]均匀选择首坏；最多64次取样，超限/缺少能力报错不开新局，不退回Math.random。随机答案只在JS闭包内，开发者工具/内存仍可查，工具没有防作弊或隐藏安全保证。

自定义首坏输入在开局后清空变量并移除输入控件，不写配置、不放导出。点击“重置自定义局并输入新答案”先明确重置轨迹，重新提供输入栏；填新答案后开始新局。

### 区间与计数

维护good/bad两个已测试边界，首坏候选是(good,bad]，即[good+1,bad]，候选数bad−good。只能检查严格内部未测提交：good < commit < bad。good结果抬升good，bad结果降低bad。候选只剩1个时锁定首坏bad；这个提交可以是已知末端，未必需要额外检查首坏本身。

建议 `floor((good+bad)/2)`。初始候选数N−1，二元结果在最坏情况下区分首坏需要至少ceil(log2(N−1))次额外检查，平衡中点达到此界。当前剩余最坏界为ceil(log2(bad−good))。这是所有可能首坏位置的最坏情况界，不是每个特定答案的必需次数；例如4提交首坏2，检查2即可完成1次，而初始最坏界为2。

第1/末端是开局已知端点，不计额外检查；重复、已测试边界、区间外、非整数、完成后检查均拒绝，不增加计数或改动轨迹。每次合法检查严格收缩区间，最大N−2=254次，避免无限循环。轨迹完整保留选择、实际结果、检查前后good/bad、剩余候选、当时建议与是否采用。完成后列相对初始最优最坏界多出的检查数，这不是声称每局都必须达到该界。

### UI公开范围

开局显示两个已知结果、候选区间和中点建议。提交带显示所有编号，已測项标good/bad，区间内其他项标未测；区间外但未测的项明确标“区间外未测”，不提前标实际good/bad。进度来自已测试结果，未完成公开view/导出没有firstBad字段；完成才加入firstBad及完成统计。提交编号、建议或候选端点本身可能等于答案，这是公开算法推理，不是提前泄露完整好坏表。

固定演示模式的说明在开局前明确首坏9；随机模式不显示这条演示数字。自定义输入者已知答案，但开局面板也不继续保留答案输入。设置变更清空旧局和轨迹；选择待测编号不改变局，非法选择保留已有记录。数值字段在尚未开局时不会每个字符重建输入节点，支持连续编辑256等多位数。

### 保存、导出与生命周期

配置键 `features.L029.settings`，`schemaVersion:1`，只保存模式与提交数字符串。设置编辑可暂时不完整；开局才要求有效2–256整数。保存前TextEncoder测完整JSON≤64KiB UTF-8，恢复先检查整个原始体积/版本，再检查字段结构；未知大字段不能绕过限制。没有持久化运行局、首坏输入、随机数、待测选择、已测结果或轨迹；关闭/销毁后需新局。切走只清保存计时器，仍挂载的当前局保持；保存250ms合并，失败明确提示只能恢复较早设置。无后台任务。

JSON/Markdown导出调用生产saveText，检查saveTextSupportsCopyOnly===true并发送copyOnly:true，主进程wx拒绝任何已存在目标。只有response.ok===true才宣告成功；取消/未确认成功/错误分别提示。异步导出后组件已销毁时不回写DOM。进行中报告只含公开已知结果；完成报告含首坏与全部轨迹，导出不包含私有局数据。Markdown按当前模式说明教学边界并转义HTML。

## 4. 使用步骤与具体例子

### 16/9验收演示

1. 打开“功能工作台 → L029 二分回归定位演练”。默认固定演示明确说明16提交首坏9。
2. 点击“开始新局（重置轨迹）”。已知1good/16bad，候选[2,16]共15个，建议8，额外检查0。此时导出JSON没有round.firstBad。
3. 连续点击“测试建议中点”四次：8good→[9,16]；12bad→[9,12]；10bad→[9,10]；9bad→[9,9]。
4. 完成显示“首坏提交：9”，额外检查4，采用建议4，初始最优最坏界4。导出JSON/Markdown含首坏9和四条完整轨迹。

### 手动选择与线性比较

新开固定演示，使用待测编号输入和“测试所选提交”按2、3、4、5、6、7、8、9依次检查：前七个good，第9提交bad，合计8次，比初始最优最坏界4多4次。也可直接点击提交带的可用未测按钮。

输入1或16、重复8、8之后输入被排除的7，均拒绝且计数不变。已知端点和区间外按钮禁用，区间外未测显示该状态，不猜它的实际结果。

### 自定义、随机与端点案例

选择自定义模式，N=256/F=256；开局后答案输入消失，点击建议中点8次，最后已知255good/256bad，锁定首坏256，无需额外测试开局已知末端。256个提交按钮可滚动查看。N=2/F=2则两个端点立即唯一定位，额外检查0。

选择本地随机模式，输入16，开局；未知首坏直到邻接边界锁定，按建议中点最多4次完成。进行中可导出已知轨迹，之后完成可再导出不同文件名的报告。随机答案只作本地教学，不提供安全隐藏；自定义作者也不会忘记自己输入的答案。

任何模式修改设置会清旧局。想保留轨迹应先导出；运行局不存配置，重开应用会恢复设置并显示尚未开局。

## 5. 产出

界面包含当前已知good/bad边界、候选闭区间/数量、中点建议、额外检查/理论最坏界/剩余界/采用建议统计、256内有界提交带、全部已知结果与完整逐次检查表，完成后明确首坏及超出初始最优最坏界的次数。

JSON为 `{feature,schemaVersion,modelVersion,exportedAt,settings,round}`。round进行中不含firstBad，只含端点、known、interval、suggestion、公开trace和计数；完成加入firstBad。settings仅模式与数量，未开局round=null。Markdown保留同等公开记录与教学口径。不支持文件导入、真实bisect脚本、skip、波动测试、非单调回归或多次修复后的多坏区间。
