# T093 加密交付包

## 1. 功能内容

选择本地文件集合或目录，预览原相对路径和大小，用同一个用户口令生成认证加密包。恢复时选择/粘贴加密包、输入口令，只有完整认证、每份文件的大小/规范Base64/SHA-256以及全部路径验证通过才出现清单；用户核对预览后点击“已核对预览，恢复到新目录”，通过原生保存对话框选择尚不存在的新目录名称。

加密包JSON仅包含固定密码参数、随机salt、随机IV和密文，不暴露文件名、明文文件内容或清单。文件原相对路径、大小、哈希和字节数据全部在认证加密正文内。文件数量不写在外层，但密文长度仍能透露大致总体体积。

加密完成后可另存包JSON及源文件明文核验清单；恢复核验后也可另存已验证明文清单。独立清单明确包含文件名、大小和SHA-256，不自动生成磁盘文件，需用户明确点击，清单本身并不保密。没有密码找回、网络、账号、用户代码执行或口令上传。

## 2. 为什么需要

私密文件跨设备传递时，既要保密，也需要判断包是否被篡改和还原文件是否与源字节一致。单独压缩不提供这一完整流程；密码本保存口令、AI历史迁移和文件去重也没有认证文件包及新目录恢复能力。本模块把密钥派生、文件认证、逐文件哈希、预览和显式新目录写入连成一条可核验流程。

所有源文件只读。加密包保存使用新文件副本，解包写入使用新目录副本；已有目录或文件拒绝。错误口令或篡改在任何恢复请求之前失败，不创建文件或目录。

## 3. 实现方式与格式规则

`meta.json`使用工作台发现契约；`index.js`提供File API多文件/目录选择、两次口令确认、清单预览、包文件/JSON粘贴、认证解密、显式恢复和安全副本保存；纯`model.mjs`使用原生WebCrypto，无第三方运行时依赖。主进程的公共`files.exportBundle`接口属于基础层，本功能只调用，不修改。

| 规则 | 固定版本1口径 |
| --- | --- |
| 口令 | 8–256 Unicode码点，不trim、不Unicode归一化，首尾空白参与派生；拒绝孤立代理项。输入最多512 UTF-16单位。口令不写config或输出，只在本局内存；运行结束/暂停/清空/销毁清空密码框。 |
| 派生 | PBKDF2-HMAC-SHA256固定600000次；每次加密由`crypto.getRandomValues`产生新的16字节salt，派生AES256-GCM密钥，密钥不可导出。 |
| 加密 | 新的随机12字节IV，AES256-GCM，128bit认证标签，WebCrypto输出密文后接认证标签，作为一个规范Base64字段存储。 |
| 外层 | 精确字段`feature,version,kdf,hash,iterations,cipher,keyBits,tagBits,salt,iv,ciphertext`；固定值T093/1/PBKDF2/SHA-256/600000/AES-GCM/256/128。未知或缺失字段、不同参数/版本均拒绝，不能通过包声明降低工作因子。 |
| AAD | UTF-8编码的`JSON.stringify({...固定参数,salt,iv,payload:'T093-files-v1',encoding:'canonical-base64'})`，按固定参数上述顺序构建；salt/IV为规范Base64。绑定固定容器规则、参数和随机头信息，不依赖用户JSON的字段顺序或排版。 |
| 加密正文 | UTF-8 JSON精确字段`feature:'T093',version:1,files`，每项精确字段`path,size,sha256,base64`。文件名/相对路径/原大小/SHA-256/字节数据均在认证范围内。 |
| 文件集合 | 1–50个，每文件≤2 MiB，总原字节≤8 MiB；可含空文件，保持任意原始二进制字节，不把文档正文按文本重编码。目录输入保留`webkitRelativePath`，含顶层目录名；普通多文件只采用文件名。两种选择都替换当前集合，不自动合并。空目录不在File API文件集合中，不能重建。 |
| 路径 | 相对路径用`/`分隔，全路径≤500 UTF-16单位、每部分≤120；禁止空部分、`.`/`..`、绝对路径、反斜杠、控制字符、Windows非法字符及CON/PRN/AUX/NUL/COM1–9/LPT1–9保留名、末尾点或空格。大小写/NFC等价路径重复和文件/目录前缀冲突拒绝。与公共桥规则一致，不默默重命名。 |
| JSON/Base64 | 包≤16 MiB、解密正文≤12 MiB。规范标准Base64（`+/`字母表、有正确padding/零pad bits、无空白），解码后重编码必须一致。有界token扫描拒绝重复属性（含转义重复名）、深度>8、对象/数组节点>200、单对象字段>16，再由JSON.parse核验语法；精确字段/固定参数/安全整数大小检查不允许宽松格式。包文件严格UTF-8，可有BOM；解密正文也严格UTF-8。 |
| 解密顺序 | 检查外层规则和限额 → 派生密钥 → 对全部密文作GCM认证 → 解析正文 → 全部路径/大小/Base64验证 → 逐文件重新计算SHA-256。任一步失败不返回恢复清单；完成结果只读，并带本模块内部验证身份，复制/伪造对象不能调用`exportPayload`。 |

取消：File API读取和WebCrypto底层操作不能通过AbortSignal强行终止。本功能在每次异步返回、分段JSON扫描及文件校验点检查取消，取消后忽略结果，不进入预览或写入；密码运算返回前保持忙碌状态避免并发堆积。字节暂存使用后可置零，但不承诺擦除JS字符串、浏览器运行时副本、GC或系统交换空间。暂停清空口令和结果，回来需要重新输入口令/核验；切换具体功能/销毁移除监听、清理文件引用及界面，不自动保存。

写入：JSON另存前检查`saveTextSupportsCopyOnly===true`，发`saveText({content,extension:'json',defaultName,copyOnly:true})`；恢复目录前检查`exportBundleSupportsCopyOnly===true`，发`exportBundle({copyOnly:true,defaultName:'T093-恢复副本',files:[{path,base64,sha256}]})`。基础层在对话框前再次完整验证规范Base64和SHA-256，独占创建新目录，已有目标拒绝；正常写入错误尝试清理新目录，清理失败返回`partialPath`并要求人工核对。崩溃/断电不提供事务恢复保证。原生请求中应用取消按钮禁用，应在对话框取消；仅`ok===true`报告成功，严格取消/失败/异常/空响应均如实反馈。

参数依据：[W3C Web Cryptography API Recommendation](https://www.w3.org/TR/2017/REC-WebCryptoAPI-20170126/)、[MDN AES-GCM参数](https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams)、[MDN PBKDF2参数](https://developer.mozilla.org/en-US/docs/Web/API/Pbkdf2Params)和[MDN deriveKey](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/deriveKey)支持上述API与参数语义。[OWASP PBKDF2建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2)给出HMAC-SHA256的600000次工作因子；此来源讨论密码存储，作为本版本参数参考，不意味着本功能获得FIPS认证或可以抵御所有弱口令猜测。

## 4. 如何使用

1. 从“工具 → 隐私与数据迁移”打开“加密交付包”。用“多文件”选择一组文件，或用“目录”选择一个目录；检查预览的相对路径、每项大小和总量。
2. 输入和再次确认相同口令。口令首尾空白有效，请自行保留，不会写入配置或包。点击“认证加密已预览文件”，等待完成和核验清单出现。密码框自动清空。
3. 核对清单后点击“保存加密包JSON副本”，在另存对话框选择新的文件路径。要单独核验源文件可点“另存源文件明文核验清单”，注意这个清单含文件名称和哈希。
4. 接收方在恢复区选择包JSON文件或粘贴完整JSON，输入口令，点“完整认证解密并核验清单”。输入/口令改动会废弃旧恢复报告；尚未创建任何文件。
5. 全部验证通过后逐项核对清单，再点击“已核对预览，恢复到新目录”，在原生保存对话框选择一个不存在的新目录名称。已有目录拒绝。缺公共桥能力时按钮禁用并解释。
6. 可另存已验证明文清单，使用另一工具计算恢复文件SHA-256与清单比较。结束后点“清空文件、包、口令和报告”。读取/密码运算可请求取消；原生对话框阶段在对话框取消。

## 5. 产出与具体可重现例子

创建两个文件：`hello.txt`的原始字节为ASCII `hello`（5字节，不带换行/BOM），`empty.bin`为空文件（0字节）。多文件选择这两个，口令及确认都输入`test-pass-123`，加密。清单必须包含：

| 路径 | 原字节数 | SHA-256 |
| --- | --- | --- |
| hello.txt | 5 | 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824 |
| empty.bin | 0 | e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855 |

保存加密包到新文件`handoff-copy.json`。外层没有`hello.txt`或`empty.bin`；再对同样文件/口令加密，新salt/IV/密文应该不同，但源清单哈希不变。

恢复区选择`handoff-copy.json`，输入`test-pass-123`并认证，显示上述两个已验证文件和总5字节，尚未写目录。主动点击恢复并选择新的目录名`handoff-restored`，基础层返回成功后该目录含两个文件。独立清单JSON为`feature:T093,version:1,algorithm:SHA-256,totalBytes:5,files:[{path,size,sha256},...]`，每个恢复文件哈希与上述值一致。

反例：输入`test-pass-124`须显示“口令错误或加密包被篡改”，没有恢复清单，恢复按钮禁用，未调用exportBundle。把密文解码后只改一个字节再规范Base64编码同样失败；只更改外层iterations也拒绝，不降低工作因子。选择已有目录时保存失败，不报告成功或改写源文件；若底层返回清理失败的partialPath，界面提示人工核对该新目录。

定向命令`node --test test/feature-T093.test.js`，24项通过，模型使用真实Node WebCrypto且所有派生均固定600000次，无测试降级参数。覆盖：新随机salt/IV/密文；正确口令二进制/UTF8名字/空文件及哈希；外层不泄漏名称；错误口令和密文/认证标签/salt/IV改单字节；元数据/参数/版本拒降级；8–256码点和不trim口令；规范Base64；路径遍历/保留名/大小写/NFC/前缀冲突；重新认证封装的恶意正文哈希、大小、编码、结构、版本、路径与无效UTF-8；文件数量/单文件/总量上下限；最大8 MiB完整加密恢复与公共`validateBundle`兼容核对；JSON重复属性/语法/限额；异步取消结果；组件事件中的两次口令、文件/目录预览、完整验证后独立恢复、各类失败零导出调用、变更废弃旧报告、包File API读取、能力缺失、严格保存结果、partialPath、暂停/销毁及原生请求阶段的取消禁用。

另做model/test/renderer ESM语法和staged diff检查。Node加载现有renderer `.js`出现项目未声明module type警告，未改共享package文件。组件测试是DOM fixture和模拟IPC桥，不能替代真实浏览器或Electron原生安全/文件对话框/打包验收；独立worktree未安装依赖，不重复缺依赖全库检查。HEAD导入、全库检查、真实浏览器和原生恢复行为由集成方验证。

此格式是T093固定版本1的JSON容器，不兼容ZIP/7z/GPG或其它密码管理器，拒绝未知版本/参数。加密及Base64需要多份有界内存副本，适合小文件集合，限额不能按压缩后大小绕过。AES-GCM认证防止包在不知道口令时被修改，但持有口令的人可以生成新有效包；清单不能证明第三方作者身份。弱口令可能被离线猜测；丢失口令无法找回。路径规则为跨平台可移植集合，拒绝部分系统本来允许的文件名，不改变或扁平化名字。无硬件安全存储、密码擦除保证、断电事务保证、后台自动保存或网络传输。
