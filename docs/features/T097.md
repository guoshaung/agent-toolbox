# T097 个人数据导出包盘点

## 1. 功能内容

离线选择用户已经下载的ZIP导出包，或已解压目录的File API文件集合，生成类别、完整文件清单、大小口径与解析限制报告。不登录下载服务，不访问任何文件中的链接，不解压到磁盘，也不导出源文件内容。只允许另存JSON/Markdown盘点报告新副本。

所有类别均明确为路径/文件名/扩展名推测。账号/profile等路径推测为“账号资料”，photos/images及图片扩展名推测为“照片”；其它JSON和其它文件分开，名称编码未知则列为未知类别。不会通过个人值猜测服务商、账号或数据语义。

ZIP原文件压缩/未压缩大小来自头部声明，不等于实际解压或已核验的内容大小。首版不解码DEFLATE等压缩方法、不解密。只有少量未加密stored JSON或目录JSON做有界字节读取和结构抽检；每个条目单独注明是否抽检、失败原因、实际读取字节和CRC/大小核验状态。图片只记录路径/类型/大小，不解码、展示或执行图片内容。

## 2. 为什么需要

服务导出包可能包含账号资料、照片、其它文档和大量JSON，却缺少清晰清单。用户需要知道哪些目录和文件存在、体积如何、盘点过程实际检查了什么。直接把ZIP头部的未压缩大小称为已验证大小，或把按路径猜出的类别称为已确认内容，会给出错误安全感。

本模块保留所有条目并把未读取、未知编码、加密、不支持压缩、抽检预算耗尽、CRC或JSON失败逐条审计。报告只描述JSON字段名、类型和数量，避免复制个人字段值；字段名和文件名本身仍可能私密，由用户保存本地副本。

## 3. 实现方式与输入规则

`meta.json`符合工作台发现契约；`index.js`提供ZIP/目录实际文件控件、明确开始按钮、分页/状态筛选、完整报告保存及取消/清空；纯`model.mjs`提供有限ZIP32 reader、路径校验、CRC32、有界JSON结构摘要与报告导出。没有新增package依赖、隐式传递包或其它功能运行时依赖。

格式依据已核对PKWARE官方[APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)，使用4.3.7 local header、4.3.9 data descriptor、4.3.12 central header、4.3.16 EOCD及名称编码标记的字段定义。本实现为有限单磁盘ZIP32盘点器，并不声称兼容该规范全部扩展。

| 输入/校验 | 明确口径 |
| --- | --- |
| ZIP限额 | 整个实际读取容器22字节–20 MiB、最多2000中央目录条目（包含显式目录）。空ZIP可列0文件；目录条目不计为文件。声明未压缩大小允许很大但始终只作为声明，不据此分配解压缓冲。 |
| ZIP结构 | EOCD必须唯一且包含完整尾注释；单盘计数一致，central offset/size恰好对应EOCD之前的中央记录。拒绝ZIP64标记/extra、分盘、加密中央目录、缺签名、截断或未知中央记录。每项local与central的名称原字节、版本、方法、flags一致；非descriptor项CRC和大小声明一致。 |
| descriptor/区域 | bit3项校验12字节或带签名16字节descriptor与中央CRC/大小声明；无标记/带标记均支持，歧义拒绝。local区域不得重叠、留未知空洞、有自解压前缀或未索引数据。extra字段边界严格检查，内容只报告ID；注释只报告字节量。 |
| 文件名编码 | bit11按严格UTF-8（保留名称BOM字符）；未标bit11且无扩展编码声明的全ASCII名称可解码。其它编码、Unicode扩展路径或坏UTF-8不猜测，报告path:null、原始名称hex、pathVerified:false；不做JSON抽检或类别猜测。能直接识别的ASCII遍历/非法路径即使编码未知也阻止。 |
| 路径 | 已解码相对路径≤500 UTF-16单位、单部分≤120；拒绝绝对/drive/反斜杠/空部分/`.`/`..`/控制字符/Windows非法字符/保留名/末尾点空格。大小写/NFC重复、原始名称重复和文件/目录前缀冲突阻止整个报告。目录属性须与名称末尾斜杠一致；符号链接仅列元数据，不跟随读取。 |
| 目录File API | 1–2000文件，总File.size≤20 MiB；保留webkitRelativePath包括顶层目录。File.size称为File API文件大小，不是ZIP声明或已读取证明。File API不枚举空目录，清单也不声称它们不存在。两个来源控件互相替换，选择更改废弃旧报告。 |
| JSON抽检 | 最多尝试20文件，每文件≤256 KiB，实际读取总≤2 MiB。按输入顺序选择符合条件的.json，其余逐条注明未抽检原因。ZIP只读未加密method0/支持flags/版本的stored条目，先核对实际字节大小和CRC；method8及其它方法仅元数据，不调用解压API。目录只读取符合预算的JSON，图片arrayBuffer不调用。 |
| 结构摘要 | 严格UTF-8、可有BOM，拒绝重复字段（含转义重复键）、坏语法、孤立Unicode/非有限数、深度>20、节点>20000、不同字段名>200、字段名>80 UTF-16单位或控制字符。失败只报告通用原因，不把JSON.parse错误里的个人值写入报告。只输出rootType、类型节点计数、数组元素总数及各字段名出现次数/子值类型计数；不保存字段值、示例值或JSON原文。 |

大小字段分开：`source.actualContainerBytes`是实际ZIP容器读取大小；ZIP项的`declaredCompressedBytes/declaredUncompressedBytes/declaredCRC32`为声明；目录项的`fileAPIBytes`来自浏览器File元数据；`actualSampleReadBytes`才是该JSON实际读取字节。只有`storedSizeCRCVerified:true`明确表示该stored JSON的字节长度和CRC做过核对。即便它的JSON结构随后解析失败，这个CRC事实仍保留；它不是密码认证，整个包始终`fullyContentVerified:false`。不计算或宣称SHA/完整内容认证。

报告完整列出条目、推测类别依据、方法/flags/名称编码、大小口径、抽检状态/原因和预算。JSON成功只带结构摘要；失败、未抽检以及图片仍保留清单。每页50项显示，状态过滤不影响导出；完整报告≤8 MiB，超限拒绝，不截断。批量元数据、CRC、JSON扫描/遍历和报告生成都有异步检查点；取消后不发布半份报告或调用保存。底层File.arrayBuffer不能强行终止，等待返回后忽略取消结果。

暂停取消当前处理但已生成报告/来源仍留本模块内存，回来不自动读写；清空或销毁清理文件引用、报告、输入和监听，不写config。报告保存必须检查`saveTextSupportsCopyOnly===true`并传`copyOnly:true`，原生独占创建已有目标拒绝。仅`ok===true`成功；严格取消/false/字符串ok/空响应/异常不报成功。原生保存阶段在对话框取消，应用内取消按钮禁用。

## 4. 如何使用

1. 用户自行下载服务导出包，或先使用自己选择的解压工具解压。打开“工具 → 隐私与数据迁移 → 个人数据导出包盘点”。
2. 选择本地ZIP，或选择已解压目录。核对来源、File API大小及限额提示，点击“开始离线盘点”。输入改变会清除旧报告，避免把之前结果当成新包。
3. 核对文件数/显式目录数/清单总项数、类别推测、ZIP声明大小与目录实际File API大小。检查JSON尝试/成功数和实际抽检字节。未解码、加密、名称未知或超预算均能逐条看到原因。
4. 每页50条，用上一页/下一页和状态过滤看全部清单。成功JSON展开“仅字段/类型/数量结构”；不要把类别推测或抽检成功当作整包内容认证。
5. 点击保存完整JSON或Markdown报告副本，在另存对话框核对最终路径并选择一个不存在的新文件。分页/过滤不会缩减输出；本功能没有“解压/恢复源内容”按钮。
6. 完成后点击“清空来源与报告”。读取/盘点期间可取消；系统另存阶段在系统对话框取消。

## 5. 产出与可重现例子

准备目录export，含`account/profile.json`与`photos/pic.png`两文件。profile.json是以下UTF-8内容，不带换行/BOM（92字节）；测试照片文件只用6个二进制字节`89 50 4e 47 00 01`，本功能不解码它，因此无需有效图片正文：

```json
{"name":"PRIVATE_NAME","email":"PRIVATE_EMAIL","enabled":true,"friends":[{"id":7},{"id":8}]}
```

用ZIP工具以“存储/不压缩”方式建立export.zip，或直接选择已解压export目录。报告应是2文件、2推测类别（账号资料1、照片1），总原文件大小98字节。ZIP报`declaredZIPUncompressedBytes:98`、`declaredZIPCompressedBytes:98`，stored JSON抽检92实际字节、1份成功、1个stored文件CRC/长度通过；照片实际抽检0、CRC未核验。目录模式报`fileAPITotalBytes:98`，ZIP声明字段为null，照片也不读取内容。

JSON结构摘要包含name/email/enabled/friends/id字段及类型数量，id出现2次、number类型2次、friends为array；完整报告和DOM均不包含PRIVATE_NAME/PRIVATE_EMAIL个人值。`source.fullyContentVerified:false`、类别依据和解析限制始终保留。

若同样profile.json使用DEFLATE，文件和类别数量仍准确，ZIP大小仍是声明，但条目显示“压缩方法8不解码，仅元数据”，schema:null、实际抽检0、storedSizeCRCVerified:false。错误CRC的stored JSON显示抽检失败且schema:null，不输出原文。`../outside`路径、重复名称、分盘或ZIP64则阻止整个报告生成及保存。超过20份符合条件JSON后，其余仍在完整清单并注明预算，不能声称全部解析。
